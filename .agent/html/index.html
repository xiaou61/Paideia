架构导读

它是一个学编程的网站：看课程、做题、复习、问 AI、写笔记、改简历。这份导读不讲代码怎么写，只讲你点下去之后，系统里发生了什么。

十个专题，每页最前面都是一张「你做了什么 → 系统做了什么 → 你看到什么」的图，用大白话写，不需要任何背景知识。看不懂那张也没关系，往下翻「它内部是怎么做到的」，那一段才是给要改代码的人看的。

怎么读

如果只有十分钟，按 01 → 03 → 05 → 10 读：系统由什么组成、AI 这条主干怎么跑、内容怎么变成学习行为、谁能碰什么。其余六页是按需查的细节。

每页固定四段，从上到下越来越硬：

  • 先看一个具体场景——一张流程图，只有「你」、「系统」、「你看到的」。不出现任何代码名词。
  • 它内部是怎么做到的——同一件事换到代码视角，节点开始出现类名、表名、端点。
  • 读图要点——失败点、钱在哪一步动、权限在哪一步判。看懂等于知道边界，不是记住顺序。
  • 代码在哪——真要去改的时候从哪进。
这份导读是第二手材料。结构数字（模块、包、表、端点）来自 scripts/gen-arch-diagram.mjs 从 pom.xml / package.json / 迁移文件 / 控制器里抽出来的结果，权威副本在 docs/architecture/。这里如果和代码不一致，以代码为准，并跑一次生成脚本。

这份导读不画什么

写清楚是为了免得有人以为它完整：

  • 不画组件级 C4。在这个规模下，组件图会变成三十个框挤在一起，信息量低于直接读包结构。
  • 不画接口字段。请求与响应的具体结构在代码和契约测试里；要自动生成得引 springdoc，那是另一个决定。
  • 不画前端路由表。路由改得不频繁，一页一图的价值低于维护成本。
  • 不硬造状态机。会话与任务的状态都是枚举字段，没有真正的状态流转时画出来是假的。
  • 不含任何地址、端口映射到主机、凭据。这是公开仓库，图里一律只写服务名。

怎么改

页面是手写的 HTML，共用 style.css、nav.js、diagram.js 与本地 mermaid 副本，双击即可打开，不需要联网、不需要构建。改完跑一次 node .agent/html/render-check.mjs：它用 chromium 真打开每个页面，确认每张图都渲染出了 SVG、控制台没有报错。

结构性的数字如果有变化，先跑 node scripts/gen-arch-diagram.mjs 更新 docs/architecture/，再回来改这里的图与文字。
