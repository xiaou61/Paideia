十九页：14 页讲系统怎么跑（每块都讲到「真正难的是什么」），4 页讲代码怎么写。每页最前面是一张「你做了什么 → 系统做了什么 → 你看到什么」的图，不需要背景知识。

怎么读

如果只有十分钟，按 01 → 03 → 05 → 11 读：系统由什么组成、AI 这条主干怎么跑、内容怎么变成学习行为、谁能碰什么。其余按需查。

每页固定四段，从上到下越来越硬：

  • 先看一个具体场景——只有「你」「系统」「你看到的」，不出现代码名词。
  • 它内部是怎么做到的——同一件事换到代码视角，开始出现类名、表名、端点。
  • 设计取舍——为什么这么做、代价是什么、什么时候该改。
  • 读图要点 / 代码在哪——容易踩的点和入口文件。
图全部是手写的 HTML + CSS，没有用任何图表库。打开即渲染、不联网、没有几 MB 的脚本要下载，也不会有「等图慢慢画出来」的卡顿。

这份导读不画什么

  • 不画数据库集中页。表结构以迁移文件为准；只有解释一个设计时才提到表。
  • 不画组件级 C4。在这个规模下，组件图会变成三十个框挤在一起，信息量低于直接读包结构。
  • 不画接口字段。请求与响应的具体结构在代码和契约测试里；要自动生成得引 springdoc，那是另一个决定。
  • 不画前端路由表。路由改得不频繁，一页一图的价值低于维护成本。
  • 不含任何地址、端口映射到主机、凭据。这是公开仓库，图里一律只写服务名。

怎么改

页面是手写 HTML，图是 style.css 里的一组图元拼出来的：.flow（竖排流程）、.steps（谁对谁做了什么）、.layer（分层）、.rules（判定顺序）。没有 JS 负责画图，所以改一个框就是改一行 HTML。

改完跑 node .agent/html/render-check.mjs：它用 chromium 真打开每个页面，检查控制台没有报错、没有任何图横向溢出、侧栏 19 条导航齐全。--shots 可以把每页截图存到系统临时目录。

页面里的数字来自 scripts/gen-arch-diagram.mjs 对 pom.xml / package.json / 控制器的抽取，权威副本在 docs/architecture/。
