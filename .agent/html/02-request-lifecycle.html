02 / 请求链路

一次请求的一生

这张图回答：一个 HTTP 请求从浏览器到数据库，经过哪几道闸？被拒绝时，401、403、402、429 分别是哪一层拒绝的？

先看一个具体场景

你隔了一晚上再打开网页，页面正常刷新，屏幕上什么都没发生。但后台其实经历了一次「令牌过期 → 被拒绝 → 悄悄换一张 → 重试成功」，全程你无感。

理解这条链路只需要理解一件事：短的令牌容易过期，长的令牌不能天天拿出来用。短的用来干活，长的只用来换短的。

它内部是怎么做到的

鉴权只有一层，而且是无状态的：SecurityFilterChain 解析 JWT，不查数据库、不建会话。这意味着任何一次请求的鉴权成本是一次签名校验，与登录用户数无关。

四种「拒绝」的语义

状态谁拒的典型原因前端该怎么办
401Security 层没有令牌、令牌过期、签名不符用长期令牌换一张，重放原请求；换不到才跳登录
403Security 层已登录但角色不满足（例如不是管理员）不要重试，显示「没有权限」
402 / 业务码 40200Service 层积分不足引导去看积分面板，不要重复提交
429限流器 / 线程池登录失败过多；对话请求排队已满等一会儿再说，不要立即指数重试

规则按顺序判定，第一条匹配就停

下面就是真实顺序的缩略（管理端前缀全部排在宽规则之前）。顺序写反不会报错，只会越权——这是全项目最危险的一类错误。

1/actuator/health → 放行探活，只返回状态
2/actuator/prometheus → 只允许本机来源挂了反向代理就失效，必须改独立回环端口（见 09）
3/api/v1/auth/** → 放行登录注册发生在有身份之前
4/api/v1/knowledge/admin/** → 要求 ADMIN必须排在 /api/v1/knowledge/** 之前
5/api/v1/ai/admin/** → 要求 ADMIN必须排在 /api/v1/ai/** 之前，否则任何学习者能给自己发积分
6/api/v1/ai/** → 要求已登录显式写出来，是为了声明「它没有角色限制」
7/api/v1/sandbox/admin/** → 要求 ADMIN这里出过一次真缺陷：写在 /sandbox/** 之后，任何登录用户能下架别人的数据集
8GET /api/v1/knowledge/files/** → 放行UUID 即凭据，且只放行 GET（见 10）
9GET /assets/**、/sw.js、PWA 清单 → 放行登录前就要能加载；它们不含数据
10其余全部 → 要求已登录兜底。管理端接口绝不靠它保护

登录与刷新：一条链、一把锁

刷新令牌用家族组织：每次轮换签发新的、旧的立刻作废。如果旧的被再用一次，说明有第二个人拿着同一个令牌，于是整条家族链一起吊销。并发刷新也不会互踢——靠一条带 AND revoked_at IS NULL 的 UPDATE 决定「谁抢到了这次轮换」。

设计取舍：为什么是无状态 JWT

选它不是为了时髦，是为了让浏览器 SPA 和 Electron 桌面壳共用一套认证。会话（Cookie + 服务端存）在 Electron 里要处理跨域 Cookie 与写入权限，成本比 JWT 高得多。

代价写在明面上：

  • 登出不能立刻生效。登出只吊销 refresh 家族，已签发的 access 在剩余寿命内仍然可用。要立刻失效就得引入令牌黑名单——那就变回有状态了。
  • 任何「浏览器自己发起的请求」都拿不到凭据。<img>、iframe 导航、Service Worker 注册都不带 Authorization 头。为此有三处刻意的免鉴权（见 11），以及一处放弃的尝试（Grafana 面板，见 09）。
  • 令牌里的角色是签发时的快照。把某人从管理员改成学习者，他的旧令牌在过期前仍然是管理员。这是选择无状态的必然后果。

什么时候该改：如果真的需要「改权限立刻生效」或「封号立刻踢下线」，就必须引入短期黑名单或降到 5 分钟 access 寿命，并接受每次刷新多一次数据库往返。

读图要点

  • 业务码与 HTTP 状态是两个维度。BizException 带 ErrorCode，由 GlobalExceptionHandler 映射成 HTTP 状态，同时把业务码写进响应体。映射必须穷尽：历史缺陷是一个 switch 掉了 default，业务码 40200 正确而 HTTP 变成了 500。
  • 未知路由要显式 404。否则 @ExceptionHandler(Exception.class) 会把它兜成 500——「路径写错了」看起来像「服务端崩了」。
  • 响应体统一由 ApiResponseBodyAdvice 包一层，异常路径带 traceId，前端报错截图可以直接拿去查日志。
  • 前端守卫不是授权边界。路由守卫只决定「显示什么」，/api/** 上的规则才决定「能做什么」。静态资源放行也不等于数据放行。
  • CORS 必须显式接管。否则预检 OPTIONS 会先被兜底的「要求已登录」挡成 401，表现为「浏览器直接调通、跨域调用全挂」。

代码在哪

  • backend/paideia-security/…/SecurityConfiguration.java — 全部规则与顺序，注释里写了每条「必须排在谁之前」
  • backend/paideia-account/…/login/LoginService.java — 登录、失败限流
  • backend/paideia-account/…/token/TokenService.java — issueFor / rotate / revoke，家族与重用检测
  • backend/paideia-account/…/support/RateLimiter.java — 计数窗口
  • backend/paideia-web/…/GlobalExceptionHandler.java、ApiResponseBodyAdvice.java
