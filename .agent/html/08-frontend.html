一条增量怎么变成屏幕上的字

这张图回答：十六个前端包是怎么分工的？服务端推来的一段 SSE 文本，经过什么变成带代码块、带可点按钮的回答？

先看一个具体场景

你点了发送，屏幕上开始一个字一个字往外蹦。你已经读过的段落不会闪、代码块在你还没读完的时候不会来回变色，里面那些可点的按钮也是等那一段写完之后才出现的。

这三件事就是「流式渲染」的全部难点：每来一个字都重新画一遍，但不能让你看见重画。

它内部是怎么做到的

结构是「两层叶子 + 一堆领域包 + 两个可运行端」。@paideia/core（请求、鉴权状态、工具函数）与 @paideia/ui（组件、令牌、markdown 渲染）不依赖任何其它包；领域包（助手、知识库、简历、训练营……）只依赖这两个；apps/app 把十一个包组装成学习者端，apps/admin 用五个包组装成管理端。

流式回答走的是增量累加 + 逐前缀渲染：客户端只负责把 content 事件的片段拼起来，渲染交给 @paideia/ui 的同一个 MarkdownBody——知识库条目、简历预览、助手回答用的是同一个渲染器，不是三套。

从字节到按钮

读图要点

  • 流式渲染的口径是三条，缺一条都会「看着能用但会咬人」：逐前缀等价（任意时刻的渲染结果等于对当前完整前缀的渲染）、已完成的块零解析（不重复高亮、不重复挂交互）、安全（不信任模型输出的 HTML）。
  • 未完成的尾块要降级。半截的 ```、半截的表格、半截的链接都会让解析器吐出畸形结构。做法是切在最后一个完整 token 上、尾巴愈合为纯文本——别人（包括 opencode）也是这么做的，没有百分百优雅的解。
  • 渲染器是数据驱动的。新增一种交互块（比如新的题型）只需要：写一个组件 + 在注册表里登记语言名。不要改主渲染器的 if/else。
  • 助手面板停靠右侧，宽度写进根变量 --assistant-panel-w。主内容靠这个变量让位，而不是靠 margin 硬编码；窄屏退化成抽屉，Ctrl+J 开关。
  • 主题令牌只有一份，在 @paideia/ui。管理端与学习者端共用——这也是为什么改一次共享的 Table 能让整个管理端一起换代。
  • Tailwind 的 @source 指错目录会「静默缺样式」：页面能开、类名没生效，构建不报错。真踩过。改多包结构后第一件事是确认它指向了全部包。
  • 每一条用户可见路由都必须在导航栏或账号菜单里有入口。首页快捷卡不算——那排卡片要往下滚才看得见。曾经有三个页面（学习、图谱、SQL 练习）能直达 URL、内容齐全，但导航里一个都没有，用户以为内容少了一大半。

代码在哪

  • frontend/packages/assistant/src/sse.ts — 五种事件的客户端解析
  • frontend/packages/assistant/src/session-store.ts、conversation-panel.tsx — 会话状态与面板
  • frontend/packages/ui/src/markdown/markdown.tsx — MarkdownBody
  • frontend/packages/ui/src/markdown/renderers/ — 围栏块组件与 schema.ts 校验
  • frontend/apps/app/src/router.tsx — 学习者端路由；LearnerHeader 的 NAV 是导航入口清单
  • frontend/packages/identity — preferredNav 的联合字面量类型，加了新入口必须同步改
改了共享包就要跑三端 e2e。@paideia/ui / core / auth / knowledge 任何一处改动都可能同时影响学习者端、管理端与桌面壳。只改某一个应用时，按页面选一个 e2e 文件就够（十几秒到一分钟），别为了安心跑全量。
