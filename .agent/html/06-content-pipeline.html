06 / 内容线

内容生产线

这张图回答：平台上的内容从哪来？哪些是人写进去的，哪些每天自己长出来？为什么速递一天只允许调一次 AI？

先看一个具体场景

早上八点，你还没起床，系统自己出去转了一圈：Hacker News、几个技术 RSS、GitHub 趋势榜。抓回来几十条，它只调一次 AI，把这一堆压成摘要并逐条打分，然后按热度排好。

九点你打开「每日速递」，看到一屏今天的内容。另一条线是面经：抓完先进草稿箱，管理员看过才放出来——因为抓来的东西可能是垃圾。

它内部是怎么做到的

三条互不干扰的源，各自的「产物」和「把关人」都不一样。关键区别在最后两列：

源怎么进来频率落到哪谁把关
人工文稿scripts/import-course.mjs 走管理端接口，幂等导入人工触发knowledge_entries写稿的人 + code review
面经抓取EssayCollectionJob 每天抓牛客列表，抽成可读题目，再做相关性判定每天一次先草稿，发布后进 knowledge_entries管理员逐条过
每日速递HN / RSS / GitHub 三源汇总 → 一次 AI 摘要打分每天一次（cron）digest_items、digest_weeklies没有人工，靠打分与源筛选

三条源各自的关键动作

定时任务的三条纪律

1 用带时区的 cron，不用「每 24 小时」 fixedDelay=24h 的锚点是「上次跑完」，会随重启漂移；cron 的锚点是墙上时间。
2 异常必须自己吞掉并记录 @Scheduled 抛出的异常只会让 Spring 打一行错误，下一轮照旧。所以每个任务都自己记成功/失败，指标挂在 ScheduledTaskMetrics 上。
3 重启后要能补当天内容 换成 cron 后重启不再自动补，所以另有一个启动任务带「今天已有就跳过」的判断。少了它，部署完要等一整晚。

设计取舍：为什么一天只调一次 AI

抓回来的可能是 60 条，逐条调 AI 就是 60 次调用。压成一次，成本上限从「随源数量增长」变成「每天一次」——现在这条线的月成本是几分钱量级。

代价是：一次调用要处理几十条，单条精度不如逐条分析；某一条特别长的内容可能挤占预算。所以先做源内筛选（按热度、时间窗），再交给模型。

  • 为什么抓取必须先落草稿：面经是外部文本，抽取和判定都可能错。直接发布等于让垃圾上线，而且发布是有外链、有 SEO 的公开行为，撤回来成本更高。
  • 为什么 GitHub 是「页面优先 + Search 兜底」：生产机访问趋势页经常超时。兜底条件是「最近 3 天、≥ 50 星、最多 30 条」——不要以为那是主路径。
  • 为什么必须指纹去重：同一条内容今天抓到、明天还会抓到。指纹（标题 + 链接一类）靠唯一键覆盖；弄丢指纹的结果是每天多一批重复标题。

读图要点

  • 抓来的正文是不可信输入。它会被喂给模型做摘要——这是整条生产线唯一的安全风险面（提示注入）。读这一层先看它对输入做了什么，而不是看它画得多漂亮。
  • 速递的「今天」按北京时间算，与库里的 UTC 存储是两个概念。跨时区显示的 bug 十次有九次出在这里。
  • 速递不进知识库。它是独立的两张表，因为每天过期、也不属于学习路径。把它塞进 knowledge_entries 会让分类树和搜索被新闻淹没。
  • 没有人工审核不等于没有把关。速递的把关是「源 + 打分 + 排序」，面经的把关是「管理员」。两者风险等级不同，所以流程不同。

代码在哪

  • backend/paideia-ai/…/digest/DigestJob.java — 每日采集调度、启动补跑判断
  • backend/paideia-ai/…/digest/DigestCollectionService.java — 三源汇总、去重、调用摘要
  • backend/paideia-ai/…/digest/GithubTrendingSource.java、GithubStarHistory.java — 趋势页与兜底
  • backend/paideia-ai/…/essay/EssayCollectionJob.java、NowcoderEssaySource.java
  • backend/paideia-ai/…/decision/TechEssayFilter.java — 判定服务调用
  • scripts/import-course.mjs — 人工内容导入
  • backend/paideia-app/…/ops/ScheduledTaskMetrics.java — 定时任务的成败计数
改采集逻辑时先确认指纹还在。「重复采集」这条线最贵的错误不是抓不到，而是每天多一批重复条目——而且它不会报错，只会让速递页越来越像一锅粥。
