10 / 安全

谁能不登录访问什么

这张图回答：哪些端点不需要身份？「UUID 即凭据」这种做法的边界在哪？为什么规则的书写顺序比规则内容更容易出事？

先看一个具体场景

你把一篇笔记设成「可分享」，把链接发给朋友。他没登录，点开就能看——因为链接里那串随机 ID 就是你给出去的钥匙。

你把链接末尾改一个字符，立刻变成 404。这就是「UUID 即凭据」：没法猜、不用登录，但一旦泄露就等于把门打开了。

它内部是怎么做到的

免鉴权的端点只有六类，每一类都有明确的理由，而且每一类的「把关手段」不一样——有的是靠 id 不可枚举，有的是靠上游自己的登录，有的是靠「它本来就不含数据」。没有一类是「忘了配」。

这一层最危险的不是规则内容，是书写顺序：Spring Security 取第一条匹配的规则，写反了不报错、不告警、测试如果不覆盖就越权跑很久。已经出现过一次真缺陷，是契约测试抓到的。

规则按顺序判定，第一条匹配就停

免鉴权端点与它们各自的凭据

路径为什么必须免鉴权靠什么把关
/actuator/health探活只返回状态，不含数据
/api/v1/auth/**登录/注册发生在有身份之前图形验证码、失败限流、邮件验证码
GET /api/v1/knowledge/files/**<img> 不携带 Authorization 头，要求登录则图片全裂id 是 UUID，不可枚举即凭据；只放行 GET
GET /api/v1/public/shares/**分享给未登录的人看UUID；只含标题与正文，不含作者与学习痕迹
GET /、/assets/**、/admin/**、PWA 清单与 sw.js登录页要先能加载；Service Worker 注册是匿名请求纯静态文件，不含数据
/api/v1/ops/grafana/**iframe 导航拿不到 Bearer，Grafana 是 SPAGrafana 自己的登录（匿名已关闭）

读图要点

  • 「只允许回环」是第四种信任级别。/actuator/metrics/**、/actuator/prometheus、/api/v1/ops/hooks/** 不属于「免鉴权」，而是「只给本机」。前者排除公网探测，后者再加一道常量时间令牌比较。
  • 真缺陷长什么样：/api/v1/sandbox/admin/** 一度写在 /api/v1/sandbox/**（authenticated()）之后，于是任何登录用户都能下架别人的数据集、看全部举报。它不报错，是合并时由 ApiContractTest 抓到的。
  • 路径命名有纪律：管理端接口一律 /api/v1/<模块>/admin/**。/api/v1/admin/<模块> 这种写法不匹配任何既有规则，会直接落到 anyRequest()——看起来加了 admin 其实谁都能调。
  • 放行读 ≠ 放行写。两处免鉴权的读都限定了 GET；写入口（上传、建分享）走的是另一条要登录的路。把 POST 一起放行等于开了匿名写入口。
  • 积分闸不是授权。它判断的是「够不够钱」，位置在 Controller 之后、调用上游之前，返回 402。把它当权限写进 Security 配置会得到错误的语义（管理员也会没钱）。
  • MCP 走 PAT，不走 JWT。个人访问令牌由独立过滤器识别，权限按工具组切分——它是一条平行于登录态的信任通道，改工具清单时要同时想「这个令牌能不能调它」。
  • 前端守卫从来不是边界。路由守卫只决定显示什么；能不能做，只由 /api/** 上的规则决定。
