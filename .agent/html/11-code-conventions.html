11 / 工程规范

写代码时的硬规矩

这页回答：我要加一个接口，哪些写法会在构建期被挡住？哪些不会报错、但半年后才咬人？

先看一个具体场景

你要加一个「批量导出学习记录」的接口。大概三十行代码：控制器一个方法、服务里查两张表、返回一个 CSV。

但在这三十行里，有五件事不是「风格偏好」，而是写错了不会立刻报错的：SQL 写在哪儿、时间用什么时区、跨模块怎么取别人家的数据、异常怎么抛、这个接口该挂哪个前缀。下面按「多久之后才会发现」排序。

按「多久被发现」排序的规矩

规矩为什么违反了多久被发现
时间只存 UTC，由应用写MySQL 会话时区是 SYSTEM（+08:00）；DEFAULT CURRENT_TIMESTAMP 也按会话时区算8 小时后，而且没人会觉得是时区问题
SQL 只写在 mapper 里拼串就是把注入面写进代码；也让「这条 SQL 谁在用」无法检索注入要等出事；其它情况 code review 当天
跨模块只许用公开契约直接用别人的 internal 包，等于把两个模块焊死，改一个实现波及全仓ModularityTest 构建期就红
管理端接口挂 <模块>/admin/**只有这个形状能排在任何宽规则之前；换个写法会落到兜底，等于谁都能调永远不会，直到有人真去越权
前端每个页面必须有导航入口有 URL 没入口 = 没上线；首页快捷卡不算，那排要往下滚永远不会，只会表现为「内容少了一大半」

一、数据库：三条不能商量的

1 所有 SQL 只在 mapper 里 Java 里不拼 SQL，也不把 mapper 的语句挪到 Service。外键很少（见 07），所以「这张表谁在写」只能靠检索 mapper 来回答；语句一旦散落在 Java 里，这个问题就答不了了。
2 时间一律应用写 UTC，不用 NOW() / DEFAULT CURRENT_TIMESTAMP JDBC 连接串必须同时写 connectionTimeZone=UTC 与 forceConnectionTimeZoneToSession=true。少了后者就是「驱动按 UTC 解释、会话按本地时间写」，所有时间静默快 8 小时。
3 标识符小写 snake_case，主键自增 避开保留字；自增主键是既定选型，MyBatis 用 useGeneratedKeys 取值，不自己生成 id。

二、模块边界：构建期就挡住

模块之间只许通过公开契约接口说话（KnowledgeApi、AccountApi 这类）。实现类放在 internal 子包里，跨模块引用会被 ModularityTest 判红。

这条规矩的真实收益是改名不改调用方：把 EntryService 拆成两个，只要契约没变，别的模块一行都不用动。代价是多一层接口——但只有一层。

它挡不住的情况：你在同一个模块内部乱来，或者把契约接口写得跟实现一样宽（一个接口塞二十个方法）。边界靠构建守，接口的粒度靠 review 守。

三、错误与响应：HTTP 一个维度，业务码另一个维度

四、技术选型带来的硬约束

下面这几条不是偏好，是已经裁决过的选型，改它等于改架构：

  • 手写 MyBatis，禁止 MyBatis-Plus。要用它的便利，就等于把「SQL 只在 mapper」这条一起放弃。
  • 只用 MySQL，完全放开。可以用 upsert、JSON 算子、SKIP LOCKED、全文检索。代价是换库等于重写数据访问层——这是明知并接受的。
  • 不用 JDK 预览特性。结构化并发在 JDK 25 仍是预览；构建开了 --release 就会红。
  • 启动器名字变了。Boot 4 里是 spring-boot-starter-webmvc，@MockBean/@SpyBean 已移除——照旧写法抄示例会编译不过。
  • AI 只走 AgentScope，不叠加 Spring AI。且框架类型（Msg、ChatUsage）不得渗进业务代码，必须收在 ai 模块的端口之后。

五、前端：三条跟「别让用户找不到 / 别让样式分叉」有关

  • 每条用户可见路由都要有导航入口（导航栏或账号菜单），并同步给 @paideia/identity 的 preferredNav 补 key——那是联合字面量，不加会编译不过。这是唯一一处「让编译期帮你记住产品完整性」的地方。
  • 主题令牌只有一份，在 @paideia/ui。管理端与学习者端共用，否则两套颜色迟早分叉。
  • Tailwind 的 @source 要指向全部包。指错目录不会报错，只会静默缺样式——页面能开、类名没生效。

写注释的唯一判据

只写代码本身表达不出来的东西：为什么这么写、约束是什么、踩过什么坑。不要写「这里在做什么」——下一行代码已经说了。

反面例子在 SecurityConfiguration 里有一堆正面对照：每条 /admin/** 规则上面都写着「必须排在谁之前，写反会怎样」。那种注释是资产，因为它记录了一个不出现在类型系统里的约束。

自查清单（提交前三十秒）

  • 新表 / 新列 → 迁移是 14 位时间戳？只建结构？种子数据进 devdata？
  • 新端点 → 挂对了前缀？管理端是 <模块>/admin/**？
  • 新页面 → 导航里有入口？preferredNav 补了 key？
  • 新 SQL → 在 mapper 里？没有字符串拼接？
  • 新时间字段 → 应用写、UTC、两个 JDBC 参数都在？
  • 跨模块调用 → 走的是公开契约，不是 internal？
  • 改了模块边界 / 表 / 部署 → docs/architecture/ 的图在同一个提交里改了吗？
