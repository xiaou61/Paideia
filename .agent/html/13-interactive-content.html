13 / 内容即交互

文章里的代码块，为什么能点

这张图回答：一篇 markdown 文章里怎么放进去「可逐步走读的代码」「当场能跑的 SQL」「逐行回放的执行过程」？作者写错了会怎样？

先看一个具体场景

你读一篇源码解读，正文里有一段 Java 代码。代码下面有三个按钮：「上一步 / 下一步 / 重置」。点「下一步」，某一行高亮，右边的变量表跟着变，下面出现一句解释——这段讲解不在正文里，是块自己带的。

再往下，一道 SQL 题，你写完点「提交」，当场告诉你对错和差异。你翻到文章的 markdown 源文件，看到的只是几个围栏块。

六种块，各自解决一个具体问题

块你在页面上看到的难点在哪
code-tour代码 + 分步骤高亮 + 每步一句讲解步骤与行号绑定；代码改了行号就错位，所以要按内容锚定而不是写死行号
code-map一张「文件 → 职责」的导览图只做静态展示，不解析真实仓库——它是策展，不是索引
quiz选择题，当场判对错答案在正文里，判分要和服务端的题目身份（entry_id + block_key + question_key）对上
sql-challenge代码编辑器 + 运行 + 结果对比判定必须在服务端沙箱里真跑，不能信客户端
run-challenge写代码、执行、看输出同样走沙箱；执行失败要区分「编译错」和「超时」
trace-player逐行回放一次执行，变量表同步变回放的数据来自服务端录制（见 07），前端只负责播

上限是「内容侧天花板」，不是性能调优

1steps ≤ 20、codeLines ≤ 200、codeChars ≤ 20 000块是作者手写的。超过上限通常意味着这段应该拆成两篇，而不是「渲染器要支持更大的块」。
2上限集中在 schema.ts 一处作者指南与报错文案共用同一份数字，否则「文档说 20、代码允许 40」这种漂移一定会发生。
3校验是纯函数，可单测不需要挂载 React 就能验证契约——这是「坏内容降级」这类逻辑唯一能被稳定测到的形态。

可视化调试：录制在服务端，回放在前端

编辑器为什么是懒加载的

SQL / 代码挑战要用真正的编辑器（语法高亮、补全、快捷键），它实测 137 kB gzip——相当于整个主包的一大块。所以它只在页面上真的有挑战块时才去加载，门槛按 gzip 160 定。

懒加载这件事，写了守卫不等于守住了。这个仓库里的懒加载守卫自己被反向验证抓出过缺陷：它检测的是「构建产物里有没有这个模块名」，而模块名被内联进另一个 chunk 时守卫会误判。教训是——守卫必须做一次反向验证：把懒加载去掉，守卫要变红；没变红就说明它守的不是你以为的东西。

设计取舍

  • 为什么把校验集中在一个文件：几种块都会被同一个渲染器加载，作者写错时的报错口径必须一致。分散到各组件里，用户会看到五种不同措辞的「你写错了」。
  • 为什么校验失败是降级而不是抛错：一段坏内容不该让整篇文章白屏。降级成「提示 + 原始文本」之后，作者能自己看见问题，读者至少还能读到别的段落。
  • 为什么判定在服务端：客户端的判分等于把答案和标准一起发给用户。SQL 与代码挑战必须在沙箱里真跑，参考结果来自真实执行。
  • 为什么块里不写行号：代码一改，行号就错。步骤要按「内容锚点」绑定，行号在渲染时算出来。
  • 为什么不做「自动从仓库抓代码」：那会把内容与某个 commit 绑死，代码一改文章就过期。这里是策展：作者选一段贴进来，并负责它仍然成立。

读图要点

  • 新增一种块不用改主渲染器。写组件 + 在注册表登记语言名即可；改主渲染器的 if/else 是把协议退化成特例。
  • trace-player 的数据可能比界面上限大。服务端会截断，前端仍要按「可能不完整」渲染——最后一步之后没有 done 是正常情况（超时被杀）。
  • 移动端要降级。编辑器和三栏布局在窄屏上不可用，退化成「先看题、再展开编辑」比硬挤更好。
  • 块里的 JSON 是「内容」，不是「用户输入」。它由作者写进仓库，随文章一起 review——但它仍然是不可信输入，校验不能省。

代码在哪

  • frontend/packages/ui/src/markdown/renderers/ — 六种块与注册表
  • frontend/packages/ui/src/markdown/renderers/schema.ts — 数据契约与上限
  • frontend/packages/ui/src/markdown/renderers/trace-player.tsx — 回放
  • frontend/packages/sql-workbench/ — 编辑器、结果表、执行计划树
  • backend/paideia-sandbox/…/trace/SandboxTraceService.java — 录制与半截 JSON 处理
  • content/reading/、content/courses/ — 真正使用这些块的文章
