# 提案 · 书籍详解专题

## 摘要

平台现有 23 条内容线全部按主题切（想查 GC 点 GC）。本项加的是**第二个组织轴**：按书切，
一本书 = 一组有固定顺序的文章，顺序由作者决定。读者从"这本书在回答什么问题"读起，
一路跟到"它在哪里推不下去"。

交付三样东西：

1. **数据**：分类树从一层变两层（`书籍详解` → 每本书一条），导入脚本学会挂父分类。
2. **入口**：页头新增「书籍详解」，落到新页面 `/books`（书列表）与 `/books/:slug`（章节目录）。
3. **内容**：一本书的样章（《人月神话》，总览 + 4 篇正文），用来验证形态。

**不碰 schema，不新增后端接口。** 唯一的后端改动是给 `EntrySummary` 补一个已经存在于
数据库里的字段 `sortOrder`。

## 分期

**S1 · 数据侧**（不动前端，可独立验证）

- 导入脚本支持 `line_parent` / `line_parent_name`：父分类不存在就建，存在就复用。
- `EntrySummary` 补 `sortOrder`（Java 记录 + 查询 + 前端类型，共三处）。
- 建 `content/reading/books-man-month/` 骨架，用两篇占位内容先跑通导入。
- 验收点：库里出现 `books` → `books-man-month` 两层，子分类 `parent_id` 指对，
  第二次导入 `created 0 / updated 0`。

**S2 · 入口侧**（前端两个页面 + 导航）

- `/books`：取分类树找 `books`，取该根下全部条目（一次请求，后端本来就展开后代分类），
  按 `categoryId` 分组 → 每本书一张卡（书名 / 篇数 / 总览摘要）。
- `/books/:slug`：按 slug 从树里定位分类，取条目按 `sortOrder` 升序渲染章节目录。
- 导航项「书籍详解」进「知识」组，不参与身份排序（不写进 `preferredNav`）。
- 验收点：本地起前端，点击入口能一路走到章节目录。

**S3 · 内容侧**（人月神话 5 篇）

- 总览 + 「人月神话」「概念完整性」「第二系统效应」「没有银弹」。
- 每篇带出处头；至少一篇用 `code-map` 画论点图，至少一篇用 `quiz` 做"先猜后看"。
- 验收点：正文可读，概念图与出处头在窄屏不溢出。

**S4 · 验证**

- 新增 `frontend/apps/app/e2e/books.spec.ts`（导航入口 / 书卡 / 章节首条为总览）。
- 线上导入一次，写验收报告。

## 关键取舍

**一、书放在分类树里，不建新表。**
另一条路是给"书"建独立实体（书表 + 章节表），能自然存作者、出版社、ISBN。
放弃它是因为代价与收益不成比例：分类树已经提供层级、slug、排序，条目已经提供正文、
进度、AI 上下文、搜索、反向链接。新建一套表意味着这些全部要重写一遍，而本项的第一目标
是**验证形态值不值得做**，不是建一个书库系统。

代价是书没有结构化元信息（作者、版次、ISBN）。处理办法是把它们放进正文的出处头——
这也正是 REQ-006 已经要求的东西，不是额外发明。

**二、章节顺序用数据库已有的 `sort_order`，不用发布时间也不用 id。**
现有分类页按 `published_at DESC` 排，对"按顺序读"是反的；按 id 排则依赖"导入顺序等于
章节顺序"这条隐式前提，中途插一章就错位。`sort_order` 是导入脚本按 frontmatter 的
`order` 显式写入的，语义就是章节序号——补一个字段就能用，不引入任何新假设。

**三、书页另做一个，不复用 `/knowledge/categories/:id`。**
那个页面服务"浏览知识库"，排序是"最近更新优先"，也没有序号与章节语义。给它加一个排序开关
会让两条用途不同的路由共用同一个组件，下次谁想改浏览体验就会撞上书籍的约束。一个新的
章节页只做一件事，反而更短。

**四、导航入口指向固定路由 `/books`，不指向分类 id。**
分类页的地址要数字 id（`/knowledge/categories/:id`），写进导航就是换库即失效。
`/books` 与 `/books/:slug` 都按 slug 解析，slug 由内容源决定，重建数据库也不会变。

**五、第一期不新增任何围栏块。**
概念图用 `code-map`（它的代码字段全是可选的、标题可覆写），"先猜后看"用 `quiz`
（答完才出解释）。等 5 篇写完，缺什么会自己暴露；现在造一个"通用动画块"，很可能造出的
是只有一篇文章会用的东西。

## 风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 两个入口造成困惑 | 书籍同时出现在 `/knowledge` 与 `/books` | 已定 Q-002 选 A（与现有学习线一致）；真造成困惑再单独做一次过滤 |
| 内容产能 | 通识类书的讲解比技术文难写得多 | 一期只做一本，写完再决定第二本 |
| 版权 | 公开仓库 + 公开站点，书的缩写与翻译属演绎作品 | 只写自己的论证与举例；引一句必注出处；不整段翻译 |
| 顺序依赖导入 | `sort_order` 由 frontmatter 决定，写错序号不会报错 | 章节页显式显示序号，写错时肉眼可见 |
| 分类树变深 | 书籍根分类会出现在 `/knowledge` 首屏 | 一期只有一本书；若书变多需要给 `/knowledge` 加分组，那时单独评估 |
