# 书籍详解专题需求

> 2026-10-28 设计阶段查证后发现三处与实情不符（分类表没有元数据列、条目已有 `sort_order`
> 但读接口不返回、现有分类页按发布时间倒序），据此把状态改回 `draft` 并订正 REQ-002 /
> REQ-003 / REQ-007 与相关实现选择。旧签署记录保留作时间线。

## 目标

给平台加一条**以书为组织轴**的专题线，并与现有的主题轴区分开：

1. **现有 20 条阅读线与 3 门课程是按主题切的**：想查 GC 点 GC，想查 TCP 点 TCP。碎片随时可查，但它们不承担"跟着一个人的思路走一遍"这件事。
2. **书籍详解按书切**：一本书 = 一组有顺序的文章，顺序由作者决定而不是由知识点决定。读者从"这本书在回答什么问题"读起，一路跟到"它在哪里推不下去"。
3. **要有独立的导航入口**（用户 2026-10-28 明确要求）。它不是一个藏在知识库分类树里的角落，而是页头的一级入口。
4. 第一期做一本书作样章（《人月神话》），目的是验证形态，不是凑数量。

## 非目标

- **不做视频**。不引入 mp4 托管、不做 Manim 渲染、不做动画编辑器。理由：一条三分钟 1080p 约三十到八十 MB，托管与带宽是真金白银，且视频搜不到、复制不了、手机流量疼。
- **不做自由画布的动画**。不让作者在正文里写坐标、SVG 路径或逐帧元素位置——那会让一篇十分钟的文章变成两小时的版式调校，写不满二十篇就没人愿意写了。
- **第一期不新增围栏块**。视觉手段全部用现有块：概念图用 `code-map`（标题可覆写），"先猜后看"用小测（答题后才出解释）。等样章写完，缺什么再补，不预先造。
- **不做书籍原文的转载、翻译或改写**。详见「约束与依赖」的版权条。
- **不做书目导入**（从豆瓣/ISBN 自动抓简介）。书的元信息手写在 markdown 正文里。
- **不改学习轨道的通关规则**。书籍不是一条"要通关的线"，不引入关卡解锁、不做强制小测。
- **不改 schema**。分类表与条目表都不加列；缺的字段用现有数据或正文约定表达。

## 实现选择

Agent 依据已批准边界和仓库既有模式做出，不逐条回问用户：

- **书不建成学习轨道**。书籍分类不打 `line_kind`，因此不会出现在 `/learn`，也不需要凑小测去满足通关判定。进度沿用条目级既有进度，不新建关卡机制。
- **章节顺序用 `sort_order`**，不用 `learning-path` 块硬编码 `entryId`——`entryId` 换库即失效（WORK-040 已记录同一问题）。`sort_order` 已经由导入脚本按 `order` 写好，只差读接口把它带出来。
- **磁盘上一条书线仍是一级目录**：`content/reading/books-man-month/`，在 `00-总览.md` 的 frontmatter 里写 `line_parent: books`。不把 `books/` 做成容器目录——那会让导入脚本的「一个目录 = 一条线」扫描规则失效。
- **书籍根分类 slug `books`**，由导入脚本按需创建（`parentId: null`、不设 `line_kind`）。
- **不新增后端接口**：`/books` 与 `/books/:slug` 都基于已有的分类树与条目列表端点，只给 `EntrySummary` 补一个 `sortOrder` 字段。
- **点一本书落到 `/books/:slug`**，不用现有分类页：那个页面按发布时间倒序、也不显示序号，对"跟着顺序读"是错的。
- **概念图用 `code-map` 块并写 `title`**，不新增块、不改渲染器。围栏标签叫 `code-map` 只是源码里看着别扭，读者看不到。
- **"先猜后看"用小测块**：一个选项 + 答题后出的解释，已经能满足这个节奏。

## 功能需求

- **REQ-001** 页头新增一级入口「书籍详解」，点击落到 `/books`。入口在**桌面与移动端**都可达。
- **REQ-002** `/books` 列出全部书，每本至少显示：书名、一句话定位、已收录篇数。
  定位取自该书**总览条目**（`order` 为 0 的那篇）的摘要。**作者与版次不单独成字段**——分类表没有元数据列，它们写在每篇的出处头里，并在书页顶部呈现。
- **REQ-003** 点一本书进入章节列表，**按 `sort_order` 升序**，每篇显示序号与标题。
  （预计时长不显示：条目表没有这个列，写了也读不出来。）
- **REQ-004** 书籍分类**不得**作为学习线出现在 `/learn`。
- **REQ-005** 每本书的第一篇（`00-总览.md`）必须回答四件事：这本书想解决什么问题、作者怎么一步步推到答案、哪些结论有边界、它在跟谁争论。
- **REQ-006** 每篇正文第一段必须是出处头：作者、原版版次、中译本版次与译者、ISBN。
  这是"带出处的评论"与"没有出处的转述"的分界线。
- **REQ-007** 内容源在 `content/reading/books-<slug>/` 下（一条书线一个一级目录），改内容走 markdown + 导入脚本，不在管理端手抄。
- **REQ-008** 导入脚本支持**一级父分类**：从总览 frontmatter 读 `line_parent`（父分类 slug）与 `line_parent_name`（新建父分类时用的名字），父分类不存在就建，存在就复用；创建子分类时带上 `parentId`。
- **REQ-009** 首批交《人月神话》：1 篇总览 + 不少于 4 篇正文。每篇至少含一个可视块（概念图或小测）。

## 质量要求

- **出处可查**：每篇的结论都要能追到具体章节或页码。只写"书里说"不合格。
- **不复制原文**：不整段引用、不逐句翻译。可以引一句并注出处，其余用自己的话重讲。
- **详解必须有增量**：复述作者说了什么不算详解。增值来自三处——把论证补全、标出结论的边界、说明今天是否仍然成立。
- **口语优先**：沿用 `content/reading/README.md` 的文风口径（先结论后原因、术语用大白话解释、每节给具体例子）。
- **导入幂等**：连续两次导入同一批内容，第二次为 `created 0 / updated 0`。
- **不重复维护**：书里的内容不与现有主题线互相复制；需要引用时用普通链接。

## 约束与依赖

- **公开仓库 + 公开站点**：不得写入凭据、服务器地址。书籍内容必须是自己的讲解，不能是原书的缩写、改写或翻译——那是演绎作品，即使逐句换词也仍然是。
- 书名与作者可以标注（指明出处），但页面不得暗示官方授权或背书。
- 依赖 WORK-012 的 markdown 渲染与 WORK-014 的围栏块，两者均已完成。
- 依赖 WORK-020 的导入流水线；本项在其上增加一级父分类能力。
