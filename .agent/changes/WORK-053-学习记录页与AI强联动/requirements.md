# 学习记录页与 AI 强联动需求

## 目标

开一页**学习记录**：把"我学到哪、卡在哪、该复习什么"摆出来，并且这一页是"AI 与页面强联动"的**试点**——
不是页面上挂一个聊天框，而是三件事同时成立：

1. **上行**：点入口时，助手拿到的是这一屏的**结构化数据**（服务端组提示词，前端不拼自由文本）；
2. **反问**：助手先问清目标与卡点，再给建议，而不是一上来贴一段泛泛的学习方法；
3. **下行**：建议能**一键落成今天要做的事**，落库留痕，用户不点就不写；
4. **范式**：站点上所有"AI 生成"入口都改成这一种形态——**点按钮 → 助手打开并一轮轮问清楚 → 它调工具生成 → 结果回到页面**，
   而不是现在这种"按钮 → 一次请求 → 一段结果"。SQL 生成是第一个要改的样本。

用户的原话：「就要特别强的联动」「这个页面就作为我们跟 AI 强联动的试点页面」「在页面里加一些按钮，点击后自动打开我们的助手」。

## 非目标

- **不做完整的学习计划编辑器**：日历拖拽、跨周排期、批量改计划的都不做。一期只有"今天要做的事"这一层。
- **不让助手替用户改学习数据**：助手不能标某关为已通过、不能改掌握度、不能自己往计划里加条目。计划只能由用户在页面上点"采用"写入。
- **不新增模型调用**：所有 AI 能力复用现有对话链路（一次对话 = 公共行为 × 私有数据），不新增后台任务、不做自动定时调用。
- **不再加课程内容**：本项只做页面与联动，内容由内容线自己管。
- **不做成第二个 /learn**：岗位地图与关卡地图仍在 `/learn`，这一页只做汇总与对话入口。
- **不改后台任务型 AI**：每日速递、AIOps 诊断、记忆提取都不改成对话（前两个的纪律是"确定性/一天一次"，改了只会更贵更不稳）。

## 用户决定

- **2026-10-29**：要做这一页，并且是"特别强的联动"，不是"页面旁边挂个助手"。
- **2026-10-29**：联动入口用**按钮**——点了自动打开助手。

## 实现选择（待确认，见 Q-001…Q-003）

- **页面**：新路由 `/progress`，名字叫「学习记录」。四块数据：各线进度、最近失败的关卡、复习到期、掌握度最低的概念。
- **上行**：给 `PageContext` 加第二个变体 `kind: 'study-log'`，字段是这几块数据的**快照**（截断后），由 `serializePageContext` 统一拼进提示词——沿用 SQL 工作台那条路子，不新造通道。
- **反向**：加一个与 `applySql` 同形的 `pendingPlan` 通道：助手在回复里按约定格式给出候选计划项，页面渲染"采用"按钮，点了才写入。
- **场景**：新增 harness `planner`，提示词要求"先反问 2–3 个问题（目标 / 每周可投入时间 / 最近卡点）再给建议"。
- **入口只做三个**（见 REQ-003），不做"每块一个按钮"——按钮越多越像演示。

## 功能需求

- **REQ-001 页面与入口**：新增 `/progress`「学习记录」页；导航栏或账号菜单必须有入口。
- **REQ-002 汇总四块数据**：①每条线的进度（已过/总关数 + 下一关）；②最近失败过的关卡（带失败次数）；③复习到期条目；④掌握度最低的 5 个概念。**数字必须与 `/learn`、`/review` 一致**（同一来源，不在前端二次计算）。
- **REQ-003 三个 AI 入口**：
  1. **卡关处**：「问问为什么卡住」——上下文是那道关 + 最近几次作答；
  2. **复习**：「让 AI 出 5 道复习题」——上下文是到期条目；
  3. **推荐**：「为什么给我推这条线」——上下文是当前岗位与该线的进度。
  三个以外不再加。
- **REQ-004 上行上下文结构化**：页面把快照交给助手（`kind: 'study-log'`），服务端拼提示词；**前端不得自己拼自由文本当上下文**。快照要有长度上限，超长截断且标明被截断。
- **REQ-005 先反问再建议**：`planner` 场景的提示词要求先问目标/时间/卡点，再给建议；用户已回答过的问题不重复问（同一会话内）。
- **REQ-006 建议可落地**：助手回复里的候选计划项以约定结构出现（日期 + 目标 + 一句话理由），页面在对应位置渲染"采用"；采用后写入计划并刷新仍在。
- **REQ-007 写入只由用户触发**：助手不能直接写计划、不能改进度、不能改掌握度。它的输出只有"建议"，落库动作发生在用户点"采用"之后。
- **REQ-008 计费与配额不变**：沿用现有预扣-结算；新增页面不得产生额外模型调用（反问、建议都是同一轮对话）。
- **REQ-009 统一"AI 生成"范式**：站点上所有"AI 生成"入口统一为 **点按钮 → 助手打开（预填意图）→ 助手一轮轮问清楚 → 调工具生成 → 结果回到页面**。
  首个样本是 **SQL 工作台「让 AI 造」数据集**（#2）。
- **REQ-010 生成与写入的边界**：助手**可以**调工具产出内容并落库（生成数据集、出题、写提案都是用户要的产物），
  但**不得伪造学习结果**——不能标关卡通过、不能改掌握度、不能替用户交卷。"生成内容"与"代替用户学习"是两件事。

## 质量要求

- 页面在 360px 下不横向溢出（与 `layout.mobile` / `learn.spec` 同一口径）。
- 四块数据任一块为空时给明确空状态，不显示 0 与灰块。
- 上行快照里**不得包含**邮箱、令牌、密码等账号隐私字段（与 WORK-042 的脱敏同一条纪律）。
- 助手调用失败（余额不足 / 上游 5xx）时页面其余部分照常可用。

## 约束与依赖

- 依赖 `@paideia/assistant` 的上下文与反向通道——改动会影响**所有**用到助手的页面（知识库、SQL 工作台、训练营），必须保持既有行为不变。
- 依赖现有学习数据接口；若某块数据缺口（如"最近失败"没有现成接口），优先复用 `learning_progress`，不新造统计表。
- 新增计划表（若采纳 Q-001 的建议）要走 Flyway，文件名用 14 位时间戳。

## 关联工作项

- **WORK-005 / 006 / 011**：助手本体、记忆、面板与会话历史——本项只扩展上下文与入口，不改对话内核。
- **WORK-024 / 034**：学习轨道与复习——本项读它们的数据，不重写。
- **WORK-035**：`applySql` 反向通道的来源，照它的形态做计划回填。
- **WORK-047**：岗位与推荐，本项的"为什么推这条线"入口读它的结果。

## 验收标准

- **AC-001** 页面可打开，导航有入口；四块数据都能渲染，任一块为空时显示空状态而不是 0。
- **AC-002** 四块的数字与 `/learn`、`/review` 一致（同一条线上同一时刻取的数相同）。
- **AC-003** 点「问问为什么卡住」后助手面板打开，输入框已预填且包含该关标题；**不自动发送**。
- **AC-004** 上行快照真的到了服务端：断言请求体里的上下文包含 `study-log` 与该关标识；且快照里没有邮箱/令牌字段。
- **AC-005** 助手给出的候选计划项，点"采用"后出现在页面"今天要做的事"里；刷新后仍在。
- **AC-006** 助手回复里自称"已加入计划"但用户没点采用时，计划里**没有**这一条（写入只认用户动作）。
- **AC-007** 不点任何按钮、只浏览页面时，不产生任何模型调用（网络里没有对话请求）。
- **AC-008** 点 SQL 工作台的「让 AI 造」后**不再直接发一次生成请求**，而是打开助手并预填意图；助手问清主题/字段后调工具生成，
  产物仍走白名单 + 沙箱干跑（校验不能被对话链路绕开）。
- **AC-009** 助手在同一会话里连续生成两次，第二次不再重复问已经问过的问题（上下文里带着第一轮答案）。

## 假设

- 四块数据都能在 2–3 个既有接口内取到，不需要新的聚合接口。
- 计划项一期只需要"日期 + 目标（条目/关卡）+ 理由"，不需要优先级、时长、跨天顺延。

## 待确认问题

- **Q-001 计划存哪**：①新增一张最小表（日期 / 目标 / 来源会话 / 完成状态）；②复用训练营的每日计划；③只存 localStorage。
  **我建议 ①**：这一页的卖点是"留痕"，②会与训练营的计划语义打架，③换设备就没了。
- **Q-002 场景怎么加**：新增 harness `planner`，还是复用 `tutor` 靠页面上下文区分？
  **我建议新增**：提示词的"先反问"要求只属于这一页，塞进 `tutor` 会污染知识库里的答疑。
- **Q-004 一期改哪几个 AI 点**：盘点表里标"值得改"的有 1 / 2 / 3 / 4-5 / 7 / 10。
  **我建议一期只做 #2（SQL 造数据集）+ 本页三个入口**：#2 是用户点名的样本，能验证整条链路（工具、校验、回填），
  其余放在二期逐条迁移——一次改六个点，等于六个功能同时半成品。
- **Q-005 多轮引导的成本**：一次性调用是一次计费，对话引导是每轮一次。用户问得越细，积分花得越多。
  **我建议**：入口文案上标明"会消耗积分"，并在提示词里约束"不要为了追问而追问：能用默认值就用默认值，最多问三个问题"。
- **Q-003 助手能不能驱动页面**（例如它说"跳到第 12 关"页面就跳）：
  **我建议一期不做**——那是工具调用，与 REQ-007 的"不替用户动作"边界容易糊在一起；先让下行只走"建议 → 用户点采用"。
