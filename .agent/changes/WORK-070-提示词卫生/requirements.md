# 需求

## 目标

让提示词**可复用、不漂、看得见**三件事成立：同一句行为约束只有一个来源；每个提示词都有符合规范的
版本号且漏写会红；管理端能按提示词版本看调用分布——调优时先看得到"改了之后有没有变好"。

## 需求

- **REQ-001**：把五处逐字相同的输入侧围栏收成一份共享常量（`PromptFences.DATA_ONLY`），五处引用它。
- **REQ-002**：新增守卫测试——`*Prompt*.java` 必须有 `VERSION` 常量，且值符合 `<场景>-v<数字>`。
- **REQ-003**：`SummaryPrompt` 的裸 `"v2"` 改为 `"summary-card-v2"`，与其余 11 个提示词同一命名规则。
- **REQ-004**：`/api/v1/admin/ai-runs` 概览返回 `byPromptVersion`（与既有排行同一组筛选），
  管理端概览页出现「按提示词版本」排行卡。

## 验收标准

- **AC-001**：围栏那句话在 `src/main/java` 下只出现在 `PromptFences.java` 一处；五处引用编译通过。
- **AC-002**：守卫测试在「漏写 VERSION」或「命名走样」时失败，报出文件名与实际值；**反向验证**必须实测。
- **AC-003**：`SummaryPrompt.VERSION` 为 `summary-card-v2`。
- **AC-004**：概览接口返回 `byPromptVersion` 且带与其它排行相同的筛选；管理端类型检查通过。
- **AC-005**：`paideia-ai` 模块测试全绿（含 15 条需要真上游的 live 测试跳过）。

## 决策分层

### 已确认事实

- 12 个生产提示词类今天都已经带版本号（实测 12/12），但没有任何机制阻止第 13 个不带。
- 提示词是代码、不集中到配置或 `.md`：`HarnessPrompts` 的注释已写明理由（版本号、单测、穷尽 switch）。
- 管理端已有 4 个 AI 页面（概览 / 明细 / 大屏 / 反馈），`ai_runs.prompt_version` 早已落库；
  缺的只是"按版本"这一个分组维度。

### 用户决定（2026-11-04）

- 范围取 A（复用常量）+ B（版本守卫）+ 按版本排行卡；**不做** C（提示词正文挪到 `.md`），
  也**不做**后台在线编辑提示词。

### 实现选择

- `PromptFences` 放 `internal.prompt` 新包：跨 5 个包引用，必须 public。
- 守卫用**扫源码**而不是反射：提示词类多为包私有，反射要先硬编码类名，等于每加一个提示词都要改测试。
- `HarnessPrompts` 进白名单（它是注册表，版本在委托类里）。

### 待确认问题

- 概览页「按提示词版本」是否要和「错误类型」并排（当前放在第三行单独一张卡）。
- 是否要给排行卡加"该版本的失败率"——现在只显示调用次数，失败率要用 `status` 再分一次组。

## 不做

- 不把提示词正文挪到 `.md`：我们的提示词是带循环与占位符的拼接，挪出去要先造模板引擎；
  且 `.md` 的 BOM/CRLF 风险今天已经咬过一次（1.1MB 的 updates.md 打不开，只能用脚本改）。
- 不做后台在线编辑：那会让 code review、单测、`git` 回滚同时失效。
