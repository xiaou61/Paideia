# 重复代码收敛与共享工具提取需求

## 用户诉求（原话）

> 「然后是你看看代码里面是不是有很多地方 我们能抽成工具类之类的 统一优化 然后弄好后
> 然后最后需要你再进行一次自动化接口测试 就线上的 看看性能如何有没有特别慢的给我说一下」

两句：① 扫描并实施"抽共享工具/统一优化"；② 完成后对**线上**做一轮只读自动化接口测试，报告性能与"特别慢"的接口。②由同一会话在其后执行，证据另附（见本项测试报告的「线上冒烟」一节）。

## 已确认事实

三路并行扫描（后端主代码 / 后端测试 / 前端）逐条给过证据；候选全表与"必须保留的差异点"在 `design.md` 的对照表里，长期索引另落 `.agent/references/`。要点：

| 项 | 事实 |
| --- | --- |

## 目标

1. 后端 5 条：把逐字重复收敛到**唯一落点**（platform / security / 模块内 internal），行为等价或严格更正确（仅一处：伪造令牌的裸解析由 500 变 401，属修正）。
2. 测试 5 条：收敛 `body`、token、轮询、SSE、清理循环、用户播种；每处**保留承重差异**（超时值、清理顺序、UTC 变体、前缀数字），共享件只提供机制、不替调用方断言。
3. 前端 7 条：core 出纯函数（errorMessage / 时间格式化 / JSON 请求），ui 出三个哑组件与分页页脚，admin 出窗口查询串与 e2e session 辅助。
4. 全部改动**行为不变**；每一片用既有测试验证（后端切片 / 受影响模块 test；前端 typecheck + 单测 + 受影响 e2e，改共享包按规则跑两端相关全量）。
5. 完成后做**线上只读接口计时冒烟**（31 端点 ×3 轮 + 2 详情），flag ≥1s 与 ≥3s 的接口并单列报告。

## 非目标

- 不合并"有意为之"的重复（见上表）与低于阈值的两处重复。
- 不新增依赖、不建共享测试基类（`TestProfileConfiguration` 已解释会让 Spring 上下文按配置拆开、每份 15–25 秒）。
- 不改任何接口/响应/数据库结构；不动三处 multipart 上传。
- 不做 F8（38 处 API 工厂单例）——纯样板、收益是"装配只在一处"，留作下一轮；本项只做到 F7。
- 不部署、不推送（线上冒烟只读，不触发写库/计费/沙箱执行）。

## 功能需求

- **REQ-001** 后端 5 条共享件按 design 的签名与落点建立，全部调用点替换（条目见 design 对照表）。
- **REQ-002** 测试 5 条共享件建立并替换；`Await` 与 `TestTokens` 保持参数化，不引入默认值。
- **REQ-003** 前端 7 条共享件建立并替换（errorMessage、三件套、分页、e2e session、时间格式化、JSON 请求、admin 窗口查询串）。
- **REQ-004** 每片替换后：后端跑受影响模块 test + 守卫切片；前端跑 typecheck + 单测；改动 `@paideia/core`/`@paideia/ui` 后跑学习者端与管理端 e2e。
- **REQ-005** 完成后执行线上只读冒烟（脚本在临时目录、不提交）：31 端点 ×3 轮 + 2 条详情派生请求；输出中位/最大耗时、非 2xx；≥1s 与 ≥3s 单列。不触发写操作与计费端点。

## 质量要求

- 共享件不得引入行为差异；凡有差异（超时/顺序/变体）一律留在调用点，在代码注释里写明为什么。
- 前端共享件保持"哑"：`@paideia/ui` 不引 react-query，内部 2 行归一错误信息、不依赖 core。
- 每个新共享件至少被两处真实调用（防"为将来"造抽象）；写完即被替换点使用。
- 不改动被替换代码的测试期望；若某处测试被迫修改，必须在提交信息与报告里说明原因。
