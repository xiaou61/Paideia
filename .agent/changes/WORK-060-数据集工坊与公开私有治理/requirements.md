# 数据集工坊与公开私有治理需求

## 用户诉求（原话）

> 「他有能力 就是可以让我选择 是新建数据集还是什么，然后是可视化展示到底有多少个表格，
> 然后可以选择某个表格说 再加一点还是怎么样，反正就是联动效果好一点，每一步都需要用户来确认。」

> 「然后是这个数据应该分为公开和私有的，这个要记录好，公开或者私有的，然后个人也可以选择
> 公开还是私有，就是这个公开和私有，我希望就是能不能新开一个页面或者是弹窗，可以选择，
> 到底是谁上传的之类的。优化一下，开始吧。」

两条诉求是同一件事的两面：**数据集要成为用户可管理、可发现的一等对象**，而不是只能在下拉框里
看到名字、只能靠复制粘贴来造。

| 上传者 | 表里记录了 `owner_user_id`，但没有任何接口把它变成可显示的名字；管理端也只显示数字 id | `SqlDatasetMapper.Summary`、`AdminController.CommunityView` |

| 可视化 | 右侧表结构侧栏已能显示「共 N 张表 · M 列」，但和 AI 生成/保存流程没有连接 | `schema-views.tsx` |
| 数据集不可变 | 保存永远新建一个 key；没有原地编辑接口 | `SqlDatasetUploadService.upload` |

## 目标

1. **AI 数据集工坊**：用户能在 SQL 页选择「新建数据集」或「基于当前数据集改」；AI 负责问清表/列/行数并产出完整 SQL；页面把结果可视化（表数与表名）后再由用户确认保存。
2. **公开/私有是一等属性**：保存时用户明确选择「私有（仅自己）」或「公开（所有人可见）」；记录在 `source/status` 上；作者之后可以切换。
3. **数据集目录**：提供一个学习者端的目录弹窗，列出内置、公开社区、我的私有数据集，显示表数、行数、上传者与可见性；可以一键选用。
4. **每一步都由用户确认**：AI 只产出 SQL/方案，不写库、不执行 SQL；唯一的写库动作是用户点「确认保存」或「设为公开/私有」。

## 非目标

- **不做原地编辑**：数据集不可变；「基于当前数据集改」保存的是新数据集，原数据集不动。
- **不新增表、不改 `sql_datasets` 结构**：沿用现有 `source` / `status` / `owner_user_id`。
- **不做数据集搜索、分页、评分、评论、收藏**：目录一期只按「内置 / 公开 / 我的」分组，最多 200 条。
- **不做匿名访问**：目录与数据集仍只对已登录用户开放。
- **不给助手执行 SQL 的能力**：AI 不跑查询、不起容器；保存时的沙箱干跑仍由上传接口做。
- **不改管理端治理口径**：管理员仍只能下架/恢复，不能编辑内容；本项只补「上传者名字」。
- **不做公开数据集的使用统计/热度排序**。

## 实现选择

| 编号 | 选择 | 理由 |
| --- | --- | --- |
| I-01 | 目录入口做成 SQL 页的**弹窗**，不新开路由 | 用户说「页面或者是弹窗」；弹窗不新增导航入口、不改路由，先把联动跑通。将来要独立页可平移 |
| I-02 | 公开 = `source='community'` + `status='published'`；私有 = `source='private'` + `status='draft'` | 复用现有两列，不新增枚举/表；`taken_down` 仍是管理员专属状态 |
| I-03 | 上传接口增加 `visibility` 参数，默认 `private` | 保存时一次写入，不产生「先私有再发布」的中间态；AI 生成的默认仍是私有 |
| I-04 | 上传者名字通过**只读目录端口**解析，不在数据集表里冗余用户名 | `owner_user_id` 已经记录了归属；用户名不可改（无改用户名端点），但读时解析不会产生脏数据。端口只返回用户名，不返回邮箱/角色 |
| I-05 | AI 读现有数据集 SQL 用只读工具 `sql_read_dataset`，不把 SQL 塞进每条页面上下文 | 只有用户明确点「加」时才把数据行交给模型；避免普通提问也带出整份数据 |
| I-06 | 「存为数据集」按钮只把 SQL 送进面板，不直接保存 | 与「自主只建议不动作」一致；保存仍走白名单 + 沙箱干跑 + 配额 |

## 功能需求

### 数据集工坊

- **REQ-001**：SQL 页助手必须能调用 `planner_build_dataset`（新建）与 `sql_read_dataset`（读取现有数据集完整 SQL）；两者都是 `ToolScope.READ`，不写库。
- **REQ-002**：助手回答下在 SQL 工作台场景增加「存为数据集」按钮；点击后把回答里的第一个 SQL 代码块送进数据集面板，并打开面板。
- **REQ-003**：数据集面板提供「新建数据集 / 基于当前数据集改」两种模式；新建模式保留主题输入与「让 AI 设计」「直接生成并保存」；改现有模式显示当前数据集的表清单。
- **REQ-004**：改现有模式下，每张表提供「让 AI 加 N 行」动作（N 由用户输入，默认 5）；助手读取原 SQL 后产出完整的新 SQL，面板提示「会另存为新数据集，原数据集不变」。
- **REQ-005**：面板在保存前显示 SQL 的预计结构：至少显示「预计 N 张表」与表名；保存时以沙箱实际执行结果为准。
- **REQ-006**：面板保存时必须让用户填写/确认数据集名字，并选择公开或私有；默认私有。
- **REQ-007**：保存成功后自动选中新数据集，并刷新选择器与表结构侧栏。

### 公开/私有

- **REQ-008**：上传接口接受 `visibility`（`private` / `public`），默认 `private`；公开数据集立即对所有已登录用户可见。
- **REQ-009**：数据集作者可以在目录弹窗里把自己的数据集在公开/私有之间切换；切回私有时，其他用户立即看不到。
- **REQ-010**：内置数据集永远公开且不可切换；被管理员 `taken_down` 的社区数据集，作者不能自行重新公开。
- **REQ-011**：非作者不能切换别人的数据集可见性；接口返回与「不存在」同一句，不给出可枚举的差异。

### 数据集目录

- **REQ-012**：新增学习者端目录接口，返回内置公开集 + 所有已发布社区集 + 当前用户的私有集；每条包含 key、名字、可见性、来源、表数、行数、上传者名字、是否本人。
- **REQ-013**：目录不返回隐藏内置集、别人的私有集、已下架社区集。
- **REQ-014**：SQL 页数据集选择器旁增加「浏览数据集」入口；弹窗按「公开 / 我的」分组展示，支持「使用」与作者可见性切换。
- **REQ-015**：公开数据集显示上传者用户名；作者注销后显示「已注销用户」，不显示用户 id。
- **REQ-016**：管理端社区数据集列表增加「上传者」列，显示用户名而不是用户 id。

## 质量要求

- **安全**：所有可见性判断在服务端完成；目录与切换接口都必须按令牌主体判归属；前端隐藏不是权限。
- **隐私**：目录只暴露用户名，不暴露邮箱、角色、学习数据；AI 读取数据集 SQL 只在用户主动触发「加」时发生。
- **一致性**：公开/私有的判定只能有一处（`SqlDatasets.visible` 与目录查询共用同一口径），不能在控制器里另写一套。
- **可用性**：切换为私有时必须二次确认，并明确提示「其他人将不能再使用它」。
- **性能**：目录一次查询 + 一次用户名批量解析，不做 N+1；最多 200 条。
- **兼容**：现有 `/sandbox/status` 的 `datasets` 形状不变，避免破坏 e2e 与老客户端；目录是新端点。

## 约束与依赖

- 复用 `SqlDatasetUploadService` 的三道检查（大小 → 白名单 → 沙箱干跑 + 抓结构）与配额；不给 AI 或目录开更宽松的写路径。
- 不新增迁移；`source` / `status` 的现有语义保持不变。
- 上传者名字解析需要 account 模块提供只读目录能力；sandbox 只依赖端口，不直接依赖 account 内部。
- 依赖 WORK-035 已上线的数据集三源模型与上传校验；依赖 WORK-053 的「AI 提议、页面执行」范式。

## 验收标准

- **AC-001**：SQL 页助手的工具清单包含 `planner_build_dataset` 与 `sql_read_dataset`，且两者 `readOnly=true`；集成测试的「无写工具」哨兵仍通过。
- **AC-002**：在 SQL 页让助手造数据集，回答下出现「存为数据集」；点击后面板打开、SQL 填入、显示「预计 N 张表：…」。
- **AC-003**：保存时选「私有」，新数据集只出现在作者的选择器/目录「我的」里；另一个账号看不到。
- **AC-004**：保存时选「公开」，另一个账号的目录「公开」里能看到，且显示上传者用户名；`/sandbox/status` 的选项里也能选到它。
- **AC-005**：作者把自己的公开数据集切回私有后，另一个账号的目录与选择器里都不再出现；作者自己仍能看到。
- **AC-006**：非作者调用切换接口得到「没有这个数据集」；内置数据集调用切换得到明确拒绝；`taken_down` 的社区数据集作者不能自行重新公开。
- **AC-007**：目录不包含 `orders-hidden-a`、别人的私有集、`taken_down` 社区集。
- **AC-008**：对现有数据集执行「给某张表加 5 行」，助手产出完整 SQL；保存后生成新 key，原 key 仍可运行且内容不变。
- **AC-009**：从点击「让 AI 设计/加行」到保存前，数据库里不新增 `sql_datasets` 行；只有点「确认保存」才新增。
- **AC-010**：管理端数据集列表显示上传者用户名；注销作者的社区数据集显示「已注销用户」。
- **AC-011**：现有 SQL 练习 e2e 与数据集选择器不因新端点/新按钮而失败。

## 假设

- 用户名是唯一的公开身份；本项不引入昵称/头像。
- 「公开」意味着所有已登录用户可见，不意味着匿名可访问。
- 目录一期最多 200 条，不做分页；当前社区数据量远小于此。
- 作者切换公开/私有是即时生效的，不引入审核队列（与 WORK-035「先发布后审核」一致）。
