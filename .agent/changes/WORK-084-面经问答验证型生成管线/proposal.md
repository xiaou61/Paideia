# 面经问答验证型生成管线 提案

## 摘要

在 WORK-025 的「抓 → 过滤 → 抽题」之后、入库之前，插入一个**验证型 harness**（REQ-001~005）：每条「题目 + 草稿答案」先过一道便宜的**内部自检**；只有被判「有问题 / 不确定」的，才去**联网抓权威文档**做依据核验并**修订**；仍不确定的**进人工复核队列**，不自动入库。抽取契约、抓取环节、出库格式都不变，存量内容不回溯。

一句话：**便宜的先跑，可疑的才升级，拿不准的交给人**——这是生产上唯一同时满足"事实更准"和"成本可控"的形态。

## 推荐方案

**三级级联（cascade）**，全部落在 `backend/paideia-ai` 的 essay 包内：

1. **闸门（内部自检，1 次调用）**：模型只就「事实/机制是否有误」给出 `ok | issues | unsure` + `confidence` + 问题清单。**按用户口径（m00392）只判事实无误，不评覆盖度与可读性。**
2. **升级（依据核验 + 修订，仅对可疑项）**：确定性 Java 代码先去白名单官方站点检索并抓取**片段**（不是让模型自己上网），再把「题目 + 草稿 + 问题清单 + 片段」交给一次修订调用，输出 `accept | revise | reject` + 最终答案 + `confidence` + 用到的 URL。
3. **分流（REQ-003）**：`ok 且置信≥阈值` → 直接入库；`revise 且置信≥阈值` → 用修订稿入库；其余 → 写 `ai_essay_verifications` 表、状态 `pending_review`，**不入库**，等管理端复核。

核心机制的三条自限：
- 闸门是**便宜的**（1 次调用、温度 0、只看事实），保证典型成本约为现状的 **1.7 倍**，而不是全量 3~5 倍。
- 外部核验是**受控的**：域名白名单 + 复用 `UpstreamGuard`（https + 公网 IP，禁重定向）+ 单次总量封顶 + Redis 缓存 7 天；抓不到就**降级**为内部修订，绝不因为外部站点挂了而阻塞入库或放行未核验内容。
- 拿不准的**永不静默通过**：校验阶段自身报错，也进 `pending_review`，而不是回落成现状直接入库。

## 范围

**做**
- 校验编排与分流；内部自检 / 外部核验 / 修订三类提示与解析；判定与置信。
- 新表 `ai_essay_verifications`（只建结构，不插业务数据）与配套手写 MyBatis mapper。
- 外部依据检索器（白名单 + `UpstreamGuard` + Redis 缓存）。
- 管理端「面经复核」页面 + 采纳/驳回接口。
- 新 `RunKind` 记账、提示词版本、日志指标（REQ-004）。
- `paideia.ai.essay.verify.*` 配置与关闭回退（REQ-005）。

**不做**
- 不改抽取（`EssayExtractor`/`EssayQuestionParser`）与抓取（`NowcoderEssaySource`）。
- 不回填存量条目（用户决定：只对新抓取生效）。
- 不建向量库、不做语义检索；外部抓取只做**核验用途的只读取数**（`always.md` 第 29 行规则的受控例外，见风险）。
- 不把校验做成通用多轮聊天/工具 agent。

## 备选方案

| 方案 | 最有力的理由 | 为什么没选 / 放弃了什么 |
| --- | --- | --- |
| **A. 现状 + 提示词美化** | 零成本、零新代码、已经上线；对"格式/风格"确实够用 | 解决不了事实错误——提示词改的是措辞，不改模型参数记忆；用户已明确否定。放弃：无 |
| **B. 全量 Self-Consistency（N=5 投票）** | 实现最简单，无外部依赖；有唯一答案的题上确有效 | 每条都 5 倍成本；对"开放解释题"投票意义弱；**多个样本共享同一个错误先验**，把 5 条链都带错时投票反而放大自信。放弃：成本可控性、事实覆盖 |
| **C. 完整工具 agent（模型自主搜索）** | 最灵活，能追问、能多跳 | DeepSeek **工具调用与结构化输出不能同一次调用**，agent 运行时成本与不可控性高，出站面（SSRF/版权）最大；本期收益不成比例。放弃：可预测性、成本、安全面 |
| **D. 推荐：三级级联 + 人工复核** | 只对可疑项付贵成本；外部依据只在需要时取；拿不准交给人，符合"只要求事实无误" | 代价：多一个状态流与管理端页面；需要维护白名单与阈值 |

## 仓库影响

- **后端**：`paideia-ai/internal/essay` 新增验证编排、提示与检索；`EssayCollectionService.runOnce()` 入库循环改为"先判定再入库"；`EssayProperties` 增加 `verify` 配置；`RunKind` 增两个取值；`paideia-app` 增一条迁移。
- **数据库**：只增表 `ai_essay_verifications`，**不改** `knowledge_entries`（条目状态仍是 draft/published，复核队列不复用条目状态）。
- **前端**：仅管理端（`frontend/apps/admin`）增一页与一条路由/菜单；学习者端零改动。
- **对外行为**：开启 verify 后，部分答案会延迟入库或进复核；关闭时与现状逐条一致（REQ-005）。
- **计费**：仍不扣用户积分（平台行为），但新增的调用会计入 `ai_runs` 供部署侧统计。

## 风险与缓解

- **把对的改坏**（AC-002）：只在 `issues/unsure` 时才修订；修订提示要求"仅改错误处、保持原结构与事实正确的部分"；用 P0 样本回归，正向改坏率 >5% 即回退阈值。
- **外部站点不可用/被墙/改版**：Redis 缓存 + 抓取失败降级为内部修订 + 失败进复核；检索实现藏在 `ReferenceRetriever` 接口后，可无痛替换。
- **成本失控**：闸门只有 1 次调用；`verify.maxCallsPerRun` 硬封顶；外部最多 3 个 URL、每段 ≤1200 字；总预算与 `maxQuestionsPerRun` 共用。
- **版权/转载**：外部内容只以**片段**喂模型，修订要求用自己的话；条目里只存来源 URL，绝不整段抄入；记录只存 URL 与命中片段摘要（审计用）。
- **SSRF/内网探测**：每个外发 URL 过 `UpstreamGuard.assertAllowed`（https + 公网），禁重定向；域名白名单在检索与抓取两处都校验。
- **规则冲突**：外部抓取违反 `always.md`「本期不做向量化检索/语义检索/RAG」（第 29 行）。**这是受控例外**：仅"答案核验时只读抓取权威文档"，不建向量库、不建内容语义索引、不把抓取内容作为检索库。批准本提案/设计时需用户确认，并在 `always.md` 补记例外边界。
- **未核验内容静默通过**：校验自身异常 → `pending_review`（`reason=verify_error`），不回落成"直接入库"。
