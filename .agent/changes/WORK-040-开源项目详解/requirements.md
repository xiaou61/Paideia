# 开源项目详解需求

## 目标

给平台加一条"讲开源项目"的内容线，并把它分成两种**用途不同**的形态，各自放在合适的载体上：

1. **简讲 = 知识库条目**（`/knowledge`）。用途是**查阅**：这个项目是什么、解决什么问题、什么时候该用。五分钟读完就走，没有进度、没有小测、没有通关。
2. **精讲 = 学习轨道**（`/learn/:slug`）。用途是**学习**：一关一个机制，有进度、有小测或动手、通关后进复习队列。
3. 两者不要求成对出现。**大多数项目只配一张简讲卡**；只有"你想从它身上学一种设计手法，或你准备改它"的项目才值得精讲。
4. 两类之间的连接是一条普通链接，不是一个新机制。

## 非目标

- **不新增页面、不新增路由**。`/knowledge`、`/knowledge/categories/:id`、`/learn/:slug` 都已存在。
- **不新增围栏块**。`code-map` / `code-tour` / `code-challenge` / `quiz` 四个块已经能表达精讲需要的全部形态。
- **不做硬门禁**。不引入"上一关通过才解锁下一关"——与 2026-10-26 已上线的「关卡全部默认解锁」冲突。
- **不做项目源码的在线浏览/搜索**。精讲的代码片段随文章走，不做可交互的仓库浏览器。
- **不让简讲变成"课程的一句话版"**。简讲和精讲不共享正文，各自独立写作。

## 用户决定

- **2026-10-26**：同意把两种形态分开做——简讲放知识库、精讲放学习线，两者用链接相连，不合成一条轨道。
- **2026-10-26**：同意"大多数项目只配简讲"的比例，按简讲为主、精讲少量来规划。
- **2026-10-26**：先建工作项，**具体讲哪些项目稍后给出**（本项因此停在需求 draft）。

## 实现选择

Agent 依据已批准边界和仓库既有模式做出，不逐条回问用户：

- 简讲走 `content/reading/<slug>/` 同一套 markdown + 导入流水线，不手抄管理端。
- 简讲分类**不打 `line_kind`**，这样它不会以"一条线"的身份出现在 `/learn`。
- 给导入脚本加 `--no-track`，接到已有的 `options.track !== false` 判断上。这是本项唯一的代码改动。
- 简讲与精讲互链用纯 markdown 链接（`[标题](/learn/<slug>)`），**不使用 `learning-path` 块**——它的 `entryId` 换库就失效。
- 精讲每关的内容形态由作者按机制决定：允许纯文字 + 小测，不强制每关都有 `code-tour`。

## 功能需求

- **REQ-001** 内容分两种形态承载：简讲进知识库分类，精讲进学习轨道。同一项目可以两种都有，也可以只有简讲。
- **REQ-002** 简讲条目固定六段结构：一句话定位 / 解决什么问题 / 核心机制（三到五句）/ 什么时候该用、什么时候别用 / 替代品 / 许可证 + 仓库 + 对应版本。
- **REQ-003** 简讲**不得**作为学习线出现在 `/learn`。它没有通关概念。
- **REQ-004** 精讲每关聚焦一个机制。理论线每关至少一个带 `id` 的 `quiz`；实战线每关至少一个带 `id` 的 `code-challenge`。没有带 id 的块，这一关永远无法通关。
- **REQ-005** 内容源在 `content/` 下，改内容走 markdown + 导入脚本，不在管理端手抄。
- **REQ-006** 简讲条目末尾提供指向对应精讲轨道的链接；精讲第 0 关（总览）链回简讲条目。两者都可缺失，不强制成对。
- **REQ-007** 不新增页面与路由；两类内容都通过现有导航入口到达。

## 质量要求

- **出处可查**：每条简讲必须写明许可证、仓库地址、对应版本（tag 或 commit）。这是简讲唯一的质量闸——没有它，简讲会退化成"据说它性能很好"这类二手传言。
- **版本可追**：精讲正文的结论对应一个明确版本；行号用 permalink 固定到 commit。版本过期需要重审，本项只记录该义务，不建机制。
- **导入幂等**：重复运行导入脚本应为 `created 0 / updated 0`。
- **不重复维护**：同一项目的简讲与精讲各自独立写作，不互相复制正文。

## 约束与依赖

- 公开仓库：不得写入任何凭据、服务器地址。内容里引用的源码片段必须带许可证信息。
- 引用第三方源码需遵守其许可证；AGPL/GPL 项目不整段粘贴源码进公开内容。
- 依赖 WORK-014 的四个围栏块与 WORK-024 的轨道机制，两者均为已完成状态。

## 验收标准

- **AC-001** 导入简讲内容后，`GET /api/v1/learn/tracks` 中**不出现**简讲分类对应的轨道。
- **AC-002** 简讲条目在 `/knowledge` 对应分类下可见，正文正常渲染（含表格与链接）。
- **AC-003** 导入精讲内容后，`/learn` 出现对应轨道，关卡数与内容目录中的关卡文件数一致。
- **AC-004** 精讲理论线每关都有带 `id` 的 `quiz`，上报进度后该关可被判定为 `passed`。
- **AC-005** 简讲条目里的 `/learn/<slug>` 链接可点，落到对应轨道页。
- **AC-006** 连续两次导入同一批内容，第二次为 `created 0 / updated 0`。
- **AC-007** 每条简讲条目都含许可证、仓库链接、对应版本三项。
- **AC-008** 本项不新增路由：`git diff` 中不含 `router.tsx` 的改动。

## 假设

- 简讲与精讲共用同一套导入脚本，不需要新的导入通道。
- 内容分类按领域划分（如前端基建 / 数据层 / 中间件），而不是按知名度——此点待确认，见下。
- 精讲的首批内容规模在 3 条轨道以内，用于验证形态。
