# 开源项目详解方案

## 摘要

给平台加一条讲开源项目的内容线，分两种**用途不同**的形态：

- **简讲**进知识库（`open-source` 分类，**不打 `line_kind`**）——查阅用，五分钟判断"要不要用"。
- **精讲**进学习轨道（`sprig-deepdive`）——学习用，一关一个机制，有进度、能通关。

代码只改一处：`import-course.mjs` 增加 `--no-track`。其余全是内容。

## 推荐方案

### 为什么必须区分两种形态

它们的成本差一个数量级，混在一起会两头不讨好：

| | 简讲 | 精讲 |
| --- | --- | --- |
| 写作成本 | 1–2 小时 | 6–10 小时 |
| 目的 | 判断"要不要用" | 学会"它怎么做到的" |
| 有没有通关 | 没有 | 有，进复习队列 |
| 适合的项目 | 大多数 | 少数 |

如果把所有项目都做成精讲，成本会高到没人愿意写；如果都做成简讲，"想学设计手法"的需求没人接。**分开做，各自才能做完整。**

### 为什么简讲不能建轨道

`import-course.mjs` 目前**总是**建轨道——`options.track !== false` 这个判断存在，但 `parseArgs` 从来没设过 `track`。所以任何走它导入的内容都会出现在 `/learn`。

简讲没有通关概念，出现在 `/learn` 会让人以为"这条线要学完"，点进去却发现没有关卡、没有小测、进度永远是 0。这不是小瑕疵——它是**语义错误**。

修法有两处（都很小）：

1. `parseArgs` 认 `--no-track`，设 `options.track = false`。
2. `ensureCategory` 在该模式下传 `lineKind: null`。否则分类仍会被打上 `course`，`lineKind` 非空就会被当成一条线（`CategoryAdminService` 的 `normalizeLineKind` 语义）。

### 为什么首批是这四个项目

判据不是"知名度"，而是**本仓库是否真实用过**：

| 项目 | 与本仓库的关系 |
| --- | --- |
| Vite | 就是我们自己的前端构建器（WORK-045 实测启动瞬时、构建 11–49 秒） |
| Tailwind CSS | 就是我们自己的样式方案（`@paideia/ui` 基于它） |
| SQLGlot | 对应 SQL 沙箱的语句治理（为什么我们选了"执行结果比对"而不是解析判题） |
| SQLite | 作为"同类对照"——解释为什么我们的持久层选 MySQL 而不是它 |

讲自己在用的东西，才不会写成二手传言。这也是需求「质量要求」里"出处可查"能落地的前提：写的人真的踩过那些坑。

### 为什么精讲选 Sprig

Sprig 是 Helm 生态最广的模板函数库，而**"函数怎么注册进模板引擎"这件事在 Go 生态里到处都是**（Helm、Hugo、各种 codegen）。讲清一个，读者遇到同类库时就有判断力。

而且它小到能讲完：真正相关的只有一张 `FuncMap` 与三四个代表性函数，不需要读一个几万行的框架。

## 范围

**包含**：4 条简讲 + 1 条精讲（4 关）+ 两条线的总览；`--no-track` 代码改动；线上导入与验证。

**不包含**：新页面、新路由、新围栏块、硬门禁、源码在线浏览、AI 评分。

## 备选方案

| 方案 | 优点 | 为什么不选 |
| --- | --- | --- |
| **A. 全部做成知识库条目** | 最简单、不用改脚本 | 精讲的"通关 + 复习"没有任何承载；而且它会污染知识库——那 5 篇是"要学"的，不是"要查"的 |
| **B. 全部做成学习轨道** | 形态统一 | 简讲没有通关概念，被迫编造小测；而且每加一个项目就要写 4 关，成本高到没人写 |
| **C. 新开一个 `/open-source` 页面** | 形态可以完全自定义 | 违反"不新增页面"；且现有 `/knowledge` 与 `/learn` 已经能承载，新页面只是重复 |
| **D. 只写简讲，不做精讲** | 成本最低 | "想把设计手法学到手"的需求没人接；而精讲正是最能体现平台差异的部分 |
| **E. 本方案** | 两种用途各自完整、代码改动最小 | 需要维护两套写作模板 |

## 交付拆分（三个阶段）

- **P1 脚本**：`--no-track` + 分类 `lineKind` 置空；dry-run 验证两种模式输出不同。
- **P2 内容**：9 篇 markdown（4 简讲 + 4 精讲关 + 2 总览，其中两条线各 1 总览）。
- **P3 导入与验证**：线上导入 → 验证 `/learn` 不出现简讲、精讲有 4 关且能通关、幂等二次导入 0 变化、简讲含许可证/仓库/版本。

## 风险与缓解措施

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 简讲被建成轨道 | `/learn` 出现没有关卡的线 | `lineKind=null` + AC-001 用 `GET /learn/tracks` 断言不出现 |
| 精讲关卡缺带 id 的 `quiz` | 该关永远无法通关 | 每关都写了 `{"id":"sprig-0N-quiz",...}`；导入后上报一次进度验证判定 |
| 二次导入不是幂等 | 产生重复条目 | AC-006 连跑两次断言 `created 0 / updated 0` |
| 内容里的版本/许可证写错 | 简讲退化成传言 | 每篇都有「出处」一节；AC-007 断言三项齐全 |
| 引用了 GPL 项目源码 | 许可证风险 | 四篇简讲都没有整段粘贴源码，只讲机制 |
