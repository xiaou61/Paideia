# 从零开始分层：方案与取舍

## 摘要

把「从零开始」拆成两条同心轴上的路：**理论**（读完能解释）与**实战**（做完能验收）。分类用轨道上的一个字段，不做门禁；实战按"基础设施已有的先做"排序，四类形态分四期落地。

用户已定：四类实战与四块理论「全部都要弄」，限流都提到 1000，不设"理论完成才解锁实战"。

## 分期

| 期 | 内容 | 依赖 | 产出 |
| --- | --- | --- | --- |
| S1 | `mode` 字段、`/learn` 分两栏、导航入口、限流提到 1000 | 无 | 架子 |
| S2 | 通过判定按 mode 分支：理论只认小测 | S1 | 理论能"完成" |
| S3 | SQL 实战线（10 题） | S1+S2 | 第一条真能验收的实战 |
| S4 | 读代码实战 + 调试实战（各 1 条线） | S1+S2 | 零执行依赖的两类实战 |
| S5 | 项目式实战：沙箱多文件 + 预置测试 | S3+S4 | 最贵的一类，最后做 |
| S6 | 理论补四块（并发 / JVM / 数据库原理 / 系统设计） | S1 | 与实战配对的理论线 |

S3 先于 S4：它是唯一"不写基础设施就能判对错"的形态，能最快验证"实战 = 验收通过"这条闭环是否成立。

## 关键取舍

**1. 用字段，不用新表、不用两个顶级分类。**
`learning_tracks` 加 `mode`。理由：分类是轨道属性，不是目录结构；用户找的是"练 Spring"，不是"练所有实战"。层级会把同一主题拆到两个地方。

**2. 不做门禁。**
跨轨道依赖现有模型表达不了（`requires_entry_id` 只在轨道内部）。强行做要新增一套依赖语义，而 2026-10-26 刚把轨道内锁去掉（`ee5a074`）。配对只用"建议先看 X"的提示表达。

**3. 不改 `kind`。**
`kind` = course/reading，表达载体形态（有无可运行代码）；`mode` = theory/practice，表达目标（理解还是作品）。两个正交轴，合并会立刻失去区分能力——比如"实战也可以是一篇文章 + 一段可运行的查询"。

**4. 实战的"对错"必须可复现，不引入 AI 评分。**
SQL 用结果哈希，调试用输出比对，项目式用预置测试。AI 只用来生成内容与解释，不判定通过。

**5. 项目式放最后。**
它是唯一要放开多文件执行的一项，安全面（文件数、大小、依赖、超时）要单独定。先让前三类跑通，再决定要不要为了它改沙箱。

## 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 改通过判定影响既有 3 门课与已通过用户 | 进度被降级、复习排期错乱 | 先写回归测试：课程语义不变、已 passed 不降级；理论规则只对 `mode=theory` 生效 |
| 限流提到 1000 后沙箱被刷 | 容器数与 CPU 被占满 | 保留"每人并发 1"这道真正的容量闸；1000 只当熔断器 |
| 项目式多文件放开攻击面 | 容器内任意文件、依赖投毒 | 文件数/总大小/CPU/内存/输出全设上限；不允许运行时联网；镜像预装依赖 |
| 实战线内容会随技术演进过期 | 判题答案失效 | 每题带反模式与期望哈希，CI 里跑 `verify_sql_live.py` 复核 |
| 理论补四块与既有线重叠 | 用户看到两篇讲同一件事 | 写作前先对照既有 62 篇的标题与结论段，重叠的改写成"接续"而不是重讲 |
