# 提案 · 练习册与「测一测」入口

## 摘要

把 `quiz` 从"读到一半插一道题"改成"读完可以选择测一下"。

交付三件：

1. **抽取**：一个纯函数把正文里的 `quiz` 块摘出来，正文只留文字。
2. **入口**：条目页正文末尾出现「测一测 · N 题」，点开是面板，逐题作答。
3. **练习册**：`N 题` 这个数字就是"练习册"——它是既有内容的集合视图，没有新表。

## 分期

**S1 · 抽取与入口**（纯前端）

- `extractQuizzes(markdown)` 纯函数 + 单测（含"围栏在代码块里不能误摘"）。
- 条目页用抽取后的正文渲染，末尾挂入口卡。

**S2 · 面板**

- 复用 `Quiz` 的交互逻辑（逐题反馈、出分、重做），包进对话框。
- Esc 关闭、焦点陷阱、关闭即丢弃本次作答。

**S3 · 解析补齐与门禁**

- `parseQuiz` 的 `explain` 仍可缺省（老内容不能炸），但内容门禁脚本报出来。
- 页面为缺解析的题显示明确提示。

**S4 · 验证**

- e2e：正文无题卡、入口可点、面板可答可关。
- 动线检查：不点入口也能正常读完并上报进度。

## 关键取舍

**一、不建题目表。**
另一条路是建 `questions`，让题目成为一等实体（可搜索、可组卷、可统计正确率）。放弃它的理由：

- 题目的身份已经是 `(条目, 块, 题号) + 内容指纹`，`question_attempts` 一直在按这个记账，引入表等于把身份搬一次家。
- 建表就要导入管线、管理端、以及"markdown 与表谁是真相"的持续拉扯。而这个项目的内容纪律就是**内容即代码**。
- 收益（跨条目的智能组卷）一期用不上。

代价：题目不能脱离正文单独查询。所以"这条线共 N 题"要么服务端读正文（重），要么只显示条目的题数。一期选后者。

**二、在数据层摘，不在渲染层摘。**
可以做一个"只收集不渲染"的渲染器，但那需要在渲染期往共享状态里写东西，React 严格模式下会写两遍。
改成**先摘再渲染**：一个纯函数切开 markdown，正文交给现有渲染器，题目交给入口卡。可单测、无副作用。

**三、入口放正文末尾，不做悬浮按钮。**
悬浮按钮在 412px 的屏幕上会盖住正文最后两行，而这一期的全部意义是"别打断阅读"。

**四、解析由作者写，AI 不生成。**
AI 生成的解析要有地方存（新表）和生命周期（内容一改就过期）。而全仓 165 个 `quiz` 块的解析是一次性编辑工作，
作者写的还能保证与正文同一套口径。

## 风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 摘取误伤代码块 | 正文里的 ``` 示例里也可能出现 `quiz` 字样 | 行级状态机而不是正则；有专门用例 |
| 老内容没有解析 | 165 个块不可能一次补齐 | 页面显示明确提示，门禁只在**新内容**上强制 |
| 管理端预览也看不见题 | 若沿用同一条渲染路径，作者在预览里看不到自己的题 | 只改学习者阅读页；管理端预览保持内联 |
| 答题记录语义变化 | 原来边读边答，现在集中答；`recordAttempt` 的时序变了 | 不改接口，只改触发时机 |
