# 练习册与「测一测」入口需求

## 目标

1. **把题目从正文里请出来。** `quiz` 块现在是内联渲染的：读到一半突然出现一道题，答完再继续。对"边读边测"是有意义的，对绝大多数读者是打断——内容里 165 个 `quiz` 块，每一个都在截断一次阅读流。
2. **给它一个入口。** 正文末尾（或目录旁）出现「测一测 · N 题」，明确是"读完了可以自己验一下"，**不测也能读完**。
3. **确立"练习册"这个概念。** 一个条目有它的练习册（该条目所有题），一条线有它的练习册（该线所有条目的题）。这个概念**不建表**，是既有内容的一次集合视图。
4. **每题都要有解析。** 现在 `explain` 是可选字段，很多题答完只有"答对了/这题不对"。解析缺失时读者学不到东西。

## 非目标

- **不建题目表。** 题目继续长在 markdown 里，身份仍是 `(条目 id, 块 key, 题号)` + 内容指纹。理由见提案。
- **不做题目的编辑界面。** 改题仍然走"改 markdown → 导入"。
- **不做线级练习册的跨条目抽题。** 一期只做**条目级**；跨条目要先解决"服务端读正文抽题"的接口问题，单独一期。
- **不让 AI 出题。** 现有题目是作者写的，质量可控；AI 出题是另一件事。
- **不改尝试记录的数据结构。** `question_attempts` 原样复用。

## 已确认事实

| 项 | 事实 | 依据 |
| --- | --- | --- |
| 题目只存在于正文里 | 没有 `questions` 表；DB 里只有 `question_attempts` / `question_concepts` / `question_difficulty` | 迁移目录扫描 |
| 题目的身份是三元组 + 指纹 | `(entry_id, block_key, question_key)` + `fingerprint`（题干+选项+答案的 SHA-256） | `question_attempts` DDL |
| `quiz` 块的解析字段是**可选**的 | `explain?: string`，不写就不渲染解释 | `schema.ts` 的 `parseQuiz` |
| 内容里已有大量 `quiz` 块 | 全仓围栏统计 165 处 | 内容扫描 |
| 内联渲染是刻意的 | 组件注释与设计都把"答题后才出解释"当作教学节奏 | `quiz.tsx` 文件头 |
| 条目页已经在收答题事件 | `KnowledgeEntryPage` 传 `recordAttempt`，服务端按正文判定并记掌握度 | WORK-033 |
| 条目列表不返回正文 | 后端 `pagePublished` 只取 `LEFT(body,200)` | `EntryMapper` |

## 用户决定

- **2026-10-28**：内联的 `quiz` 太突兀，希望改成按钮形式，读完之后**可选**测与不测。
- **2026-10-28**：提出"题库"这个概念，并希望每个题库有解析。

## 实现选择

- **词不叫"题库"，叫「练习册」。** 本项目里"题库"已被 WORK-004 定义成"知识条目"（一行一个条目、无题型无答案），再复用会撞车。用户的口径保留在需求里，界面与代码统一用"练习册"。
- **`quiz` 块不再内联渲染**，改为收集后渲染一个入口卡。渲染器仍然解析每一块（复用现有 `parseQuiz`），只是换去处。
- **答题面板复用现有 `Quiz` 组件的交互**（逐题即时反馈、答完出分、重做），只是从"嵌在正文里"搬到"面板里"。
- **解析改为必填**：`parseQuiz` 允许缺省但内容门禁报错；页面对缺失的题显示"这道题还没有解析"而不是空白。
- **不上 AI 生成解析**（一期）：AI 写的解析需要缓存落库，等于加一张表；而全仓 165 个 `quiz` 块的解析是可以一次性补齐的编辑工作。

## 功能需求

- **REQ-001** 正文渲染时**不内联渲染** `quiz` 块，原位置不留占位。
- **REQ-002** 条目页出现「测一测」入口，显示题数与该条目的历史最好成绩（做过才显示）。**不点它也能正常读完正文。**
- **REQ-003** 点击入口打开面板，逐题作答、即时反馈、答完出总分；可关闭、可重做。
- **REQ-004** 交卷时沿用既有上报（`recordAttempt` + 本地 `quizzes` 进度），不新增接口。
- **REQ-005** 每道题都必须有解析；缺失时页面显示"这道题还没有解析"，且内容门禁（`check_seed_fences` 或等价脚本）把它报出来。
- **REQ-006** 练习册的集合概念在界面上可见：入口卡上写清"本条目 N 题"；条目所属的线在其地图页显示"这条线共 N 题"（只统计，不跨条目抽题）。
- **REQ-007** 不改数据库、不改迁移。

## 质量要求

- **可访问性**：面板是有焦点的对话框（Esc 关闭、焦点陷阱、`aria-modal`），不与页面滚动抢键盘。
- **不丢进度**：答到一半关闭，已答的题保留在本次会话里（不做持久化，重开即重做）。
- **阅读优先**：入口卡不能高于正文，不能遮挡正文，不能自动弹出。
- **解析质量**：解析要说清"为什么这个选项对、其他为什么错"，不是复述题干。

## 约束与依赖

- 依赖 WORK-014 的 `quiz` 块与渲染器契约、WORK-033 的作答与掌握度上报。
- 共享包 `@paideia/ui` 的改动会同时影响助手流式回答（那边不启用文档渲染器），必须保证流式路径不受影响。
- 内容侧要补解析，走 markdown + 导入脚本。

- **WORK-033**：作答、掌握度与概念关联，练习册的作答记录沿用。

## 验收标准

- **AC-001** 打开任意带 `quiz` 的条目，正文里**看不到**题目卡片；出现「测一测 · N 题」入口。
- **AC-002** 不点入口，正文正常读完并可上报进度。
- **AC-003** 点开面板能逐题作答，答完显示 `x / N` 分；Esc 可关。
- **AC-004** 关闭再打开，题目从头开始（不残留上次的作答）。
- **AC-005** 答完的题在 `question_attempts` 里有记录（沿用既有断言方式）。
- **AC-006** 缺解析的题显示明确提示，不渲染空白区。
- **AC-007** 助手流式回答里出现 ```quiz 仍是文本，不被当成组件（既有约束不回退）。
- **AC-008** 窄屏 412px 下面板不横向溢出，正文无溢出。

## 假设

- 入口卡放在正文**末尾**（读完再测），而不是目录旁。若用户希望"随时可测"，改成悬浮按钮即可，不影响数据契约。
- 一期的练习册只按条目聚合；线级只显示题数。

## 待确认问题

由 Agent 定案，**批准本需求即视为确认**：

- **Q-001 "题库"改名「练习册」**。理由：WORK-004 已把"题库"定义为知识条目（一行一个条目、无题型无答案无判分），
  再复用会让"题库"在两个意思之间漂移；而代码里 `questions` 相关的表名是 `question_*`，
  界面叫"练习册"不会与之冲突。
- **Q-002 解析由作者写，AI 不生成**。理由：AI 解析要有地方存（新表 + 生命周期），
  而 165 个块的解析是一次性的编辑工作；作者写的解析还能保证与正文口径一致。
- **Q-003 入口放正文末尾**。理由：这一期的诉求是"别打断阅读"，而末尾是唯一一个
  既不打断面、又不需要新增悬浮层的位置。做成悬浮按钮会在手机上挡住内容。
