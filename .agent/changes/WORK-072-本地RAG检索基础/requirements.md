# 需求

## 目标

为 AI 回答建立一套本地可运行的 RAG 基础：把已发布知识条目索引成可检索向量，用户提问时自动召回最相关的资料片段注入回答，并让回答能标注来源条目，降低“模型凭印象回答”的概率。

## 需求

- **REQ-001 本地 embedding 服务**：在 Paideia 服务器上用 Docker 部署 Ollama，加载本地 `bge-m3` 模型；服务只监听 `127.0.0.1:11434`，不对公网开放，Paideia 通过本机 HTTP 调用。
- **REQ-002 语料边界**：只索引**已发布知识条目**（含从零开始课程内容）；不索引用户笔记、个人记忆、简历、对话等私有数据。
- **REQ-003 切块与向量化**：按标题层级/段落把条目切成约 300–500 字的块，块间保留少量重叠；对每个块生成 embedding，并记录内容 hash 以支持增量更新。
- **REQ-004 索引存储**：在 MySQL 保存块文本、条目标识、内容 hash 与向量数据；当前规模不引入独立向量数据库。
- **REQ-005 检索与注入**：每次 AI 回答前自动用问题检索 Top-K（默认 6）相关块；把结果作为「参考资料」注入助手提示词。检索不到时明确说明没有找到资料，不强行编造。
- **REQ-006 来源引用**：回答里必须能标注「参考条目 #id」，前端渲染为可点击的条目链接；没有引用时不能伪装成有资料依据。
- **REQ-007 增量索引**：按 `knowledge_entries.updated_at` 定时做增量重建；条目更新或下架后，旧块必须失效或被删除。
- **REQ-008 降级**：本地 embedding 服务不可用时，AI 回答退回现有全文检索/普通回答路径，并向用户显示「检索增强暂不可用」，不能静默产生“没有资料的 RAG 回答”。
- **REQ-009 可评估**：建立一组中文技术问题的黄金集（问题 → 期望条目），记录 Top-K 召回率；上线前至少能对比“有 RAG / 无 RAG”的回答依据。

## 验收标准

- **AC-001**：本地 Ollama 服务健康，`bge-m3` 模型可加载；`127.0.0.1:11434` 可调用，公网端口不可达；容器重启后服务自动恢复。
- **AC-002**：索引覆盖全部已发布知识条目（含课程），索引块数与条目正文规模相符；用户笔记、记忆、简历、对话数据不入索引。
- **AC-003**：黄金集问题检索 Top-5 命中期望条目的比例达到约定阈值（首版目标 ≥ 70%），并记录基线。
- **AC-004**：AI 回答包含 `参考条目 #id` 链接；无命中时明确提示没有找到相关资料。
- **AC-005**：条目更新后增量索引能替换旧块；条目下架/删除后旧块不再出现在检索结果中。
- **AC-006**：embedding 服务关闭时，AI 回答仍能返回普通回答或现有全文检索结果，并显示降级提示；不会阻塞主流程。
- **AC-007**：索引与检索不读取或返回任何用户私有数据。

## 决策分层

## 已确认事实

- 当前 `knowledge_entries` 已有全文检索（MySQL `MATCH ... AGAINST`）与 `knowledge_search` 工具；没有 embedding 端点、向量列或向量索引。
- AI 助手已有 `knowledge_search` / `knowledge_get_entry` 等只读工具，回答可以在现有对话链路上注入参考上下文。
- Paideia 服务器为 4 核 CPU、15G 内存、36G 磁盘、已装 Docker、无 GPU；`bge-m3` 可在 CPU 上运行，模型约 2.2G 内存。
- 当前知识条目以已发布内容为主，个人笔记与记忆属于私有数据，已有严格归属校验。

## 用户决定

- 向量检索用于 **AI 回答的 RAG 基础**，不是先做独立搜索产品。
- 接受本地 embedding 服务与模型部署成本；使用服务器本地模型，不走外部 embedding API。
- 语料只包含已发布知识条目（含课程），不包含个人笔记/记忆。
- 每次 AI 回答自动检索 Top-K（默认 6），不要求用户手动点“检索”。
- 回答需要标注可点击的「参考条目 #id」。

## 实现选择

- 本地服务：Docker 运行 Ollama，模型 `bge-m3`；只绑定回环地址。
- 存储：MySQL 表保存块文本与向量 BLOB，Java 侧精确余弦检索；当前规模不上独立向量库。
- 索引：定时扫描 `updated_at` 增量重建，不依赖消息队列。
- 注入：在助手回答链路前置检索，注入「参考资料」；现有 `knowledge_search` 保留作兜底。
- 首版不做 rerank、不同 embedding 模型对比、个人数据索引。

## 待确认问题

- 首版黄金集的具体问题清单和召回阈值，等实现阶段与内容校对一起定。
- `bge-m3` 与 `bge-small-zh-v1.5` 的最终选择：先按 `bge-m3` 实现，若服务器内存/延迟不达标再降级。

## 不做

- 不引入 RabbitMQ/outbox：单实例继续沿用现有 `ai_memory_extraction_jobs` + `MemoryExtractionRelay`，邮件/统计也不纳入异步
- 不做独立向量数据库
- 不做 rerank / cross-encoder
- 不索引个人笔记、记忆、简历、对话
- 不做图片、音视频等多模态检索
- 不做自动改写知识库内容
