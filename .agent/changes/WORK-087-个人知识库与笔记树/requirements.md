# 个人知识库与笔记树需求

## 已确认事实

以下来自源码、已批准工件或已执行的检查，可复查。

1. **前置已完成（WORK-006）**：`backend/paideia-note` 已上线个人笔记的扁平 CRUD、只读分享（免登录、id 不可枚举、固定有效期、可撤回）、举报下架、注销级联硬删，全部按 `user_id` 隔离。
2. **现有笔记是扁平的**：`notes(id, user_id, entry_id NULL, title, body MEDIUMTEXT, created_at, updated_at)`（迁移 `V7__create_note_tables.sql`，仅 `KEY idx_note_user(user_id, updated_at)`）；**没有知识库、没有目录树、没有层级、没有全文索引**。`NoteService` 的产品上限是 `MAX_TITLE_CHARS=200`、`MAX_BODY_CHARS=20000`、`LIST_LIMIT=200`。
3. **MCP 已存在**：平台 MCP 网关 `paideia-mcp`（WORK-019/039/044），视图路由 `/mcp/x/{toolset}[/write]`，按 `ToolCatalog` 与 `ToolDescriptor.readOnly` 过滤只读/写；PAT 令牌有 scopes(READ/WRITE)、toolsets 白名单与每日调用上限。当前 `note` 工具集只有 `note_list / note_get / note_create / note_append`。已注册工具快照见 `backend/paideia-app/src/test/java/io/github/xiaou61/McpToolSnapshotTest.java`。
4. **全文检索范式现成**：项目已有 MySQL `FULLTEXT ... WITH PARSER ngram` 中文检索先例（`paideia-knowledge` 的 `EntryMapper`、`paideia-ops` 的 `PostmortemMapper`；`paideia-platform/SearchQuery.java` 构造 BOOLEAN 串，短查询退 `LIKE`）。
5. **迁移现状**：`db/migration` 里早期用 `V1`–`V24` 递增号，2026-10 起改用 14 位时间戳（最新 `V20261122210000__...`）。新迁移按时间戳命名，避免并发会话撞号。
6. **技术栈与纪律**：Spring Boot 4 + JDK 25；手写 MyBatis（禁 MyBatis-Plus）；仅 MySQL 且放开专有特性（可用 FULLTEXT/upsert/JSON）；Flyway；模块化单体 + Spring Modulith；公开仓库凭据不入库；用户数据按 `user_id` 隔离（见 `.agent/rules/always.md`）。
7. **本期不做向量检索**（既有否决，见 always.md）：内容检索用 MySQL 全文检索承担。
8. **免鉴权面**：全项目仅 `GET /files/{uuid}`（附件）与 WORK-006 的 `GET /share/{shareId}`（分享）两处；两处都靠「id/UUID 不可枚举即凭据」。

## 用户决定

以下由用户在 2026-11-24 的需求讨论中逐条裁决。

1. **结构形态 = 多个知识库 + 文档树**：用户可建**多个知识库**；每个知识库内是**目录/文档可无限嵌套**的树，最接近语雀。
2. **存储形态 = 内容存数据库 + 导入导出 .md**：正文以 markdown 文本存 MySQL；提供 `.md` 的**导入与导出**（单文档导出、整库打包）。**不**做真磁盘/对象存储上的 `.md` 文件，「核心是 .md」落在格式语义与导入导出上。
3. **索引三样全要**：**全文检索**（标题+正文，中文可搜）、**大纲 TOC**（按 markdown 标题生成、可跳转）、**双向链接/反链**（`[[]]` 引用、反链面板）。
4. **首版范围 = 一次性做完整语雀式前端**：知识库列表、文档树（可折叠/拖拽排序/右键菜单）、markdown 编辑器、大纲侧栏、反链面板、搜索、导入导出入口，一并交付。
5. **MCP 走现有网关**（2026-11-24 已确认）：沿用 `/mcp/x/note` 工具集与 PAT 令牌，把知识库/文档能力暴露给外部 AI 客户端，用于用户后续的学习笔记读写。
6. **MCP 写工具直写**：用户在外部客户端用 PAT 主动发起的写 = 等同本人操作，**直接写、不需二次交互确认**；但只作用于本人数据，PAT 的 scopes/toolsets/日限额继续生效。
7. **分享做两种**：**单篇文档分享**与**整库分享**首版都做。整库分享生成一个公开只读的知识库页面，可浏览整棵文档树；沿用 id 不可枚举、固定有效期、可撤回、过滤学习痕迹、下架即失效。

## 实现选择

以下由 Agent 在已确认边界内收口，影响数据或用户可见行为的逐条列出（有异议可在批准前推翻）。

- **目录与文档统一到一张 `notes` 表**：新增 `kind`（`doc` / `folder`）区分「目录」与「文档」；`parent_id` 表达父子（NULL=根），`sort_order` 表达同级顺序；目录无正文。理由：语雀里目录本身也是可展开的组织节点，统一表让「移动/排序/删除连带子树」只有一套代码。
- **新增两张表**：`note_books`（知识库）与 `note_links`（双链/反链关系）。
- **存量扁平笔记迁移**：为每个持有笔记的用户自动建一个默认知识库「我的笔记」，把现有 `notes` 行挂到该库根节点；不丢数据、不改 id。
- **双链语法**：`[[文档标题]]`（同知识库内按标题匹配）与 `[[id:123]]`（按 id 精确引用）；保存文档时解析正文、维护 `note_links`；目标改名/删除时反链侧显示为「悬空引用」，不自动改目标正文。
- **删除语义**：知识库与文档采用**软删**（`deleted_at`），删除文档连带其整棵子树；回收站/恢复留作后续，本周不做。
- **分享扩展为两种对象**：`note_shares` 增加「分享对象类型」（单篇文档 / 整个知识库）与目标 id；单篇与整库共用同一套「UUID 不可枚举 + 有效期 + 撤回 + 下架失效」纪律。整库分享的公开页按树遍历该库全部文档。
- **上限取值**：单文档正文上限、单知识库节点数上限、树最大深度、导入包大小上限**在设计里定**，取值原则是「够用且防滥用」（现存 `MAX_BODY_CHARS=20000` 明显偏小，拟放宽）。

## 背景

WORK-006 让平台第一次有了「个人笔记」——但它**只是一列平铺的卡片**：没有知识库、没有目录、不能嵌套、搜不了。用户真正需要的是一个**语雀式的个人知识库**：可以按主题建多个库，在一个库里把资料整理成层层目录与文档，写 markdown、按标题生成大纲、用 `[[]]` 互链并在反链里看到「谁引用了我」，还能整库导入导出一份 `.md` 快照。同时这套笔记要能通过 MCP 被外部 AI 客户端读写，成为用户「后续学习的笔记」的长期载体。

这不是给现有笔记页加个筛选框能达成的——它要动数据模型（层级与关系）、加检索与解析、扩 MCP 与前端。因此单独立项。

## 目标

- 用户可建**多个知识库**，每个库内是**目录/文档可无限嵌套**的树。
- 在树里**新建、重命名、移动、拖拽排序、删除（连带子树）**文档与目录。
- 写 markdown 文档并保存；可**可选挂靠**知识条目（沿用 `entry_id`）。
- **全文检索**本人知识库（标题+正文，中文可搜）；**大纲 TOC** 可跳转；**双链/反链**可用。
- **导入 / 导出 `.md`**：单文档导出、整库打包导出、`.md` 包导入成知识库树。
- 通过 **MCP** 让外部 AI 客户端读写本人的知识库/文档（只读+写工具）。
- 沿用并保持：**私有隔离、只读分享（单篇 + 整库）、举报下架、注销级联硬删**。
- 一次交付**完整语雀式前端**。

## 非目标

- **不做协作文档 / 多人实时编辑**（仍是单用户私有数据）。
- **不做版本历史 / 差异对比**（本周不做，未来可加）。
- **不做向量检索与语义检索**（既有否决）。
- **不做真 `.md` 文件存储或对象存储挂载**（决定第 2 条：存数据库 + 导入导出）。
- **不做跨用户协作共享**；分享是**只读传播**（单篇文档或整库），不提供共同编辑。
- 不做 AI 自动改写全文（保留现有「AI 提炼要点」这类单次能力即可）。

## 用户与工作流程

**学习者 · 组织与编辑**

1. 进入「我的笔记」→ 看到本人知识库列表，可新建 / 改名 / 删除 / 调整顺序。
2. 打开一个知识库 → 左栏是文档树；可新建文档或目录、拖拽排序、拖到别的节点下变成子节点。
3. 点一篇文档 → 右栏 markdown 编辑/预览；右侧大纲按标题列出、点击跳转。
4. 正文里写 `[[另一篇标题]]` → 保存后该篇的反链面板能看到「被本文引用」。

**学习者 · 查找与搬运**

5. 顶部搜索框输入关键词 → 命中本人知识库里标题或正文含该词的文档。
6. 对某篇点「导出」→ 下载 `标题.md`；对知识库点「导出」→ 下载整库 `.md` 压缩包。
7. 点「导入」上传 `.md` 或压缩包 → 生成/合并成一个知识库树。

**学习者 · 分享与治理（沿用并扩展）**

8. 对某篇文档点「分享」→ 得到免登录链接与固定有效期，可提前撤回。
9. 对整个知识库点「分享」→ 得到一个公开只读的知识库页面，访客可浏览整棵文档树。
10. 发现不当内容 → 举报；管理员在管理端下架，链接立即不可读。

**外部 AI 客户端 · MCP**

11. 在支持 MCP 的客户端里连入平台、用 PAT → 可列出知识库、读文档、检索、建/改文档、移动、删除本人内容。

**注销**

12. 注销 → 知识库、文档、链接、分享、举报记录全部删除，本人也不可再访问。

## 功能需求

- **REQ-001 多知识库管理**：创建、重命名、删除（软删）、排序本人知识库；每个库有名称（可含描述）。
- **REQ-002 文档树**：目录与文档可无限嵌套；新建、重命名、移动（含拖拽）、同级排序；**移动不得成环**（不能移到自身或子孙下）。
- **REQ-003 文档读写**：markdown 编辑/预览、保存；标题必填、正文可为空（目录）；可选挂靠知识条目 `entry_id`。
- **REQ-004 全文检索**：按关键词检索**本人**知识库，命中标题与正文，中文可搜；结果可定位到具体文档并高亮/摘要。
- **REQ-005 大纲 TOC**：由文档 markdown 的标题层级生成大纲，支持点击跳转。
- **REQ-006 双向链接与反链**：`[[]]` 引用语法；保存时解析维护链接关系；提供「本文引用了谁」与「谁引用了本文」两个方向；悬空引用可识别。
- **REQ-007 .md 导入导出**：单文档导出 `.md`；整库导出为含目录结构的压缩包；压缩包或单 `.md` 导入成知识库树。
- **REQ-008 私有隔离**：知识库、文档、链接、检索结果全部按 `user_id` 隔离；匿名 401、他人不可见、本人放行三态成立。
- **REQ-009 MCP 工具**：`note` 工具集扩展——只读（知识库列表、文档树、读文档、检索、反链）与写（建知识库、建/改/移动/删除文档），全部作用域限本人；PAT scopes/toolsets/日限额继续生效。
- **REQ-010 只读分享（单篇 + 整库）**：单篇文档可分享；整个知识库可分享为公开只读页面（可浏览整棵文档树）。两者均免登录可读、id 不可枚举、固定有效期、可撤回、内容不含学习痕迹。
- **REQ-011 举报与下架（沿用）**：举报入口与管理员下架对文档继续可用，下架后链接立即不可读。
- **REQ-012 注销级联硬删**：注销删除 `note_books`、`notes`、`note_links`、`note_shares`、`note_reports` 中该用户全部数据。
- **REQ-013 完整前端**：知识库列表 + 文档树 + 编辑器 + 大纲 + 反链面板 + 搜索 + 导入导出，一次性交付。

## 质量要求

- **越权防护是信任边界**：知识库、文档、链接、检索、导入导出、MCP 每一条读写路径都要校验归属；三态（匿名 401 / 他人 403 或空 / 本人放行）各有自动化用例。**不信任** MCP/前端传入的任何 id，一律在服务端按 `user_id` 复核。
- **树操作安全**：移动/排序必须校验「目标不是自身或子孙」，防成环；删除连带子树；节点数/深度/正文大小有上限。
- **导入包安全**：解析 `.md` / 压缩包时防 **zip slip**（路径穿越）、防 **zip bomb**（解压大小与条目数上限）、只接受 `.md`/文本、文件夹结构映射到目录节点；非法输入给出可见错误且不落半截数据（事务内完成）。
- **中文全文检索正确**：ngram 分词对中文可召回；短词/边界查询有回退策略；结果按 `user_id` 过滤。
- **存量迁移无损**：迁移把每条既有笔记放进「我的笔记」默认库根节点，id 与正文不变，分享/举报外键仍有效。
- **免鉴权面不扩张**：分享仍是唯一新增免登录读面（单篇 + 整库），纪律与 `GET /files/{uuid}` 一致（UUID 不可枚举、仅 GET、过滤痕迹、失效统一 404）；**整库分享只能遍历被分享库内该用户的文档**，不得泄漏其它库或用户数据。
- **失败可见不静默**：检索失败、导入失败、MCP 工具失败都要给出可见结果，不静默吞掉、不透出上游原始报文。
- **不作弊的完成**：测试要能证明「树移动真的防了成环」「检索真的按人过滤」「导入真的拒绝穿越路径」「注销真的删干净」。

## 约束与依赖

- **架构**：模块化单体 + Spring Modulith；`paideia-note` 扩展，跨模块只经 API 包（`NoteApi` 等）；`paideia-mcp` 从 `ToolCatalog` 取工具，不另起清单。
- **数据**：手写 MyBatis（SQL 只在 mapper）；Flyway 时间戳迁移；改 `notes` 表须**加法 + 回填**，不得破坏现有分享/举报/注销链路。
- **搜索**：仅 MySQL FULLTEXT（ngram），不引入向量库。
- **部署形态不变**：单实例、仅 8081 公网可达、无定时任务基设（软删回收、分享到期都不靠定时清理）。
- **公开仓库**：凭据与服务器信息不入库。
- **并发**：实施时若工作区不干净，按 Skill 规则开独立 worktree，避免与他人改动互相覆盖。
