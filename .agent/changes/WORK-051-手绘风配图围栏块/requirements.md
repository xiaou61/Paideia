# 手绘风配图（sketch 围栏块）需求

## 用户原始诉求

2026-10-28，用户拿一篇公众号技术文章（ReAct 模式讲解）提问：「有没有那种可以生成类似于手画的图的 skills？
比如说这个文章里面的，其实我们里面很多的讲解如果说多这样的图的话，会很好用的」。

同日调研完五条路线后，用户裁决：**选 B——rough.js + 小赖字体的浏览器内联方案**，并要求
「新开一个 work 慢慢实现」。

也就是说：要的不是"能把图画出来"，而是**课程讲解里能出现那种歪框、手写中文、手画箭头的插图**。

## 已确认事实

以下每条都在仓库或本机实测过（2026-10-28）：

1. **知识库正文里目前没有任何图片**：`content/` 下 217 篇 markdown，`![](...)` 出现 **0 次**，
   图片文件 0 个；`grep '```mermaid'` 只有 **11 处**。讲解主要靠文字和代码块。
2. **正文是纯 markdown 存进数据库的**：`scripts/import-course.mjs` 走管理端 API 导入，
   **没有图片资产管线**，也没有静态媒体目录。
3. **围栏块机制已经存在且成熟**：`frontend/packages/ui/src/markdown/renderers/index.ts` 导出
   `documentRenderers`（`code-tour`、`code-map`、`learning-path`、`code-challenge`、`quiz` 五种），
   统一用 `blocks.tsx` 的 `guard()` 包错误边界、`BlockFallback` 做降级（保留原始文本）。
4. **只在文档模式启用**：`markdown.tsx` 计算 plugins 时，`streaming` 为真则**不带** `documentRenderers`——
   模型在助手回答里输出的围栏块只当文本。这是有意为之的安全边界。
5. **数据契约集中在 `renderers/schema.ts`**：纯函数 `parseXxx(code): ParseResult<T>`，
   上限常量集中在 `LIMITS`，校验失败返回 `{ ok: false, error }`，**从不抛进渲染树**。
6. **mermaid 12.2.0 自带 `look: handDrawn`**（`config.type.d.ts:76`），且在我们的
   `securityLevel: 'strict'` 下 frontmatter 仍能改它（实测基准块 `path` 数 9 → 15）。
   但实测观感是"灰色积木 + 斜线填充"，中文仍是系统字体，达不到用户在文章里看到的观感。
7. **rough.js 4.6.6 体积很小**：`rough.esm.js` 27,748 字节，**gzip 8.7 KB**。
8. **小赖字体（Xiaolai）是 SIL OFL 1.1**，可商用；随附子集 343,500 字节（约 1000 字）。
   实测在浏览器里画 SVG 时中文字形**正常生效**；同样字体交给 mermaid 则不生效。
9. **Excalidraw 的 Excalifont 没有汉字**：实测 `fontFamily: 1` 下英文是手写体、**中文整段退回系统黑体**。
   这条排除了"用现成 Excalidraw skill"的路线。
10. **rough.js 的手绘抖动可做到确定性**：用由坐标/内容派生的固定 seed，同一份代码重跑两次
    PNG **md5 完全一致**（附件实现里已验证）。

## 实现选择

以下由 Agent 依仓库既有模式判定，不改变用户可见范围：

1. **复用现成的围栏块机制**，不新造第二套：新增语言标签 `sketch`，走 `documentRenderers` +
   `guard()` + `BlockFallback`。
2. **坐标不由作者写**：节点宽度按文字实测自动定、整行居中。手算坐标是作者侧最大的摩擦，
   而课程作者（人和 AI）只擅长写"谁连谁"。
3. **只在文档模式注册**，与 `code-tour` 等完全一致；助手流式回答里的 ```` ```sketch ```` 仍是文本。
4. **字体以子集形式入库**，并用脚本按内容重新生成；运行时只加载本地 woff2，不联网取字体。
5. **颜色走 CSS 变量**而不是 JS 判主题，深浅两套沿用站点令牌，避免第二套配色真相。
6. **抖动 seed 由内容派生**（节点 id + 序号），保证刷新、StrictMode 双渲染、重进页面结果一致。
7. **粗体依赖懒加载**：`roughjs` 走动态 `import`，不进入首屏主包。

## 目标

让课程/阅读线的长文里能写出一张**看起来像人手画**的插图：歪边框、手写中文标签、手画箭头，
并且这张图是**由文本生成的**——改文案只改 JSON，不用打开画图软件。

## 非目标

- **不做**图形化编辑器（作者写 JSON，不做拖拽）。
- **不做**图片资产管线（不引入图床、静态媒体目录、上传流程）。
- **不替换** mermaid：流程图、时序图仍用 mermaid；`sketch` 只负责"讲解用的示意图"。
- **不做**助手流式回答里的手绘图（那是模型输出文本，不该被执行）。
- **不做**导出 PNG/下载按钮（第一版只渲染，不导出）。
- **不做**任意路径/自由绘图 DSL（不提供 `path`、`polygon` 这类图元，避免变成第二个 SVG）。

## 用户与工作流程

作者（我/用户/管理端编辑）在 markdown 里写：

````markdown
```sketch
{
  "title": "agent 是怎么看代码的",
  "rows": [
    [{ "id": "a", "title": "上下文装不下", "sub": "整个仓库读不完", "tone": "gray" },
     { "id": "b", "title": "grep 定位", "sub": "只读那几百行", "tone": "blue" },
     { "id": "c", "title": "用完就丢", "sub": "需要时再检索", "tone": "amber" }]
  ],
  "arrows": [{ "from": "a", "to": "b" }, { "from": "b", "to": "c" }]
}
```
````

读者在知识库条目里看到一张手绘示意图，与正文同宽、跟随深浅主题。
作者写错时，页面显示"这块内容的数据格式有误：<原因>"加原始文本，正文其余部分照常。

## 功能需求

- **REQ-001** 支持 ```` ```sketch ```` 围栏块，内容是 JSON，渲染成手绘风格 SVG，
  包含标题、分行排列的节点（主标题 + 可选副标题）、节点之间的箭头。
- **REQ-002** 节点宽度由文字实测自动决定（有上下限），行内水平居中、行间垂直排列；
  作者**不需要也不允许**写坐标。
- **REQ-003** 中文标签使用手写字体；字体未覆盖的字符回退系统字体，**不得出现方框/豆腐块**。
- **REQ-004** 同一份 JSON 的渲染结果稳定：刷新、重进页面、React 双渲染下逐字节一致。
- **REQ-005** 非法 JSON、未知字段、未知箭头端点、超出上限时降级为「原因 + 原始文本」，
  不白屏、不抛异常到渲染树、不影响同页其它内容。
- **REQ-006** 只在文档模式（知识库条目、笔记预览、管理端预览）生效；流式回答里保持代码块形态。
- **REQ-007** 浅色与深色主题下都能读：文字与底色对比度达标，不出现浅底浅字。
- **REQ-008** 不增加首屏负担：`roughjs` 与字体都不进入首屏主包，只在页面真的出现 `sketch` 块时加载。
- **REQ-009** 作者契约可查：字段、上限、错误文案集中在一处，与解析器共用同一份常量。
- **REQ-010** 至少有一篇长文真实用上这张图（样例），并有自动化测试证明它被渲染。

## 质量要求

- 渲染吞吐：单块 ≤ 12 个节点时，首次绘制在普通笔记本上不超过 100 ms（不含字体下载）。
- 无障碍：SVG 带 `role="img"` 与 `aria-label`；标签是**真实 `<text>`**，可被选中与读屏。
- 视觉一致性：插图配色来自站点令牌（CSS 变量），不引入第二套调色板。

## 约束与依赖

- 新增运行时依赖 `roughjs`（MIT）。
- 新增字体资产：小赖字体子集（SIL OFL 1.1），**必须随仓库提供许可证说明**。
- 不改后端、不改数据库、不新增迁移——内容仍然是 markdown。
- 改动落在 `@paideia/ui`（共享包），按 AGENTS.md 需要跑该端 e2e；不跑三端全量。

## 验收标准

- **AC-001** 打开含 `sketch` 块的条目，出现 `data-testid="sketch-block"` 的 SVG；
  框的数量等于 JSON 节点数，箭头数量等于 `arrows` 条数。
- **AC-002** 中文标签在 SVG 中按手写字体族渲染；字体未覆盖的字符回退系统字体且**无方框**。
- **AC-003** 一行 3 个节点时，三个框的水平中心间距相等（误差 ≤ 1px），整行在外框内居中。
- **AC-004** 同一条目连续刷新两次，SVG 中每个 `path` 的 `d` 属性完全一致。
- **AC-005** 把 JSON 改坏（少一个 `]`）后，页面出现 `block-fallback` 并含原始文本；
  正文其它段落、其它围栏块不受影响。
- **AC-006** 助手流式回答里输出 ```` ```sketch ```` 时不渲染成图，保持代码块。
- **AC-007** 浅色与深色主题各截图一次，标签文字与框内底色对比度 ≥ 4.5:1。
- **AC-008** `pnpm --filter @paideia/app build` 后，入口 chunk 的 gzip 体积与本项实施前持平
  （sketch 相关代码全部在异步 chunk）。
- **AC-009** 单元测试覆盖：解析合法/非法、布局居中与宽度夹取、未知箭头端点报错。
- **AC-010** e2e（devdata，远程跳过）：种子条目里的 `sketch` 块被渲染成 SVG 且带 `<text>` 标签。

## 假设

- 一张图不超过 4 行、12 个节点；超过通常是"该拆成两张图"。
- 手写字体只用于图内标签，**不用于正文**——正文仍用站点字体，可读性不受影响。
- 作者愿意写 JSON；不做可视化编辑器。

## 待确认问题

无阻断性问题。

一条非阻断的观察，留给验收时判断：**手写中文在正文尺寸下的可读性没有经过读者检验**。
