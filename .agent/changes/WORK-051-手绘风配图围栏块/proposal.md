# 手绘风配图（sketch 围栏块）提案

## 摘要

在现有围栏块机制上加一种名为 `sketch` 的块：作者写一段 JSON（标题、分行节点、箭头），
运行时用 `rough.js` 在浏览器里画成手绘风格 SVG，标签用中文手写字体（小赖子集）。
不引入图片资产管线，不改后端，不替换 mermaid。

## 推荐方案

**B —— 浏览器内联渲染。**

核心机制：markdown 里的 `sketch` 围栏 → `parseSketch` 校验 → 用 canvas 实测文字宽度决定框宽、
整行居中 → `rough.js` 生成歪线条的框与箭头 → 我们自己的 `<text>` 摆手写标签。
产物是**内联 SVG**：可随主题变色、可被读屏、可被选中，不需要任何图片托管。

四条决定性理由：

1. **只有这条路能同时拿到"歪线条 + 手写中文"**。实测 Excalidraw 的中文整段退回黑体，
   mermaid 里的 webfont 不生效；rough.js 自己摆字，字体是普通的 CSS 字体，正常生效。
2. **它不需要图片资产管线**。正文存在数据库里，仓库没有静态媒体目录；内联渲染等于
   "图跟着文字走"，`import-course.mjs` 一行都不用改。
3. **它复用现成机制**。注册表、错误边界、降级外壳、校验范式全都已经在
   `renderers/` 里跑了一年多（WORK-014），新增的是"第五种块的画法"，不是新架构。
4. **代价透明**：依赖 gzip 8.7 KB，字体子集 343 KB（只在出现 `sketch` 块时下载）。

放弃的东西：作者要写 JSON 且**不能拖拽**；图形复杂度被限制在"分行节点 + 箭头"，
画不了自由构图（火柴人、任意曲线）——那类插图仍得靠 Excalidraw 手工画。

## 范围

**包含**：`sketch` 块的契约、解析、布局、绘制、字体、主题适配、降级、注册、一处内容样例、相应测试。

**不包含**：图形编辑器、图片托管、PNG 导出、自由图元（`path`/`polygon`）、mermaid 的替换或改写、
助手流式回答里的执行。

## 备选方案

### A 现状：mermaid 加 `look: handDrawn`

**最强的一面**：真的零成本——不加依赖、不改代码，作者在 frontmatter 里写一段配置就行，
而且在我们 `securityLevel: 'strict'` 下实测仍然生效。

**为什么没选**：观感不到位。实测在我们真实课程图上渲染出来是"灰色积木 + 斜线填充 + 极轻的抖动"，
中文仍是系统字体，整体仍是工程流程图而不是手绘插图。另外 `flowchart.wrappingWidth: 600`
（治中文折行的唯一办法）会**吞掉标签里的 `<br/>`**，与现有内容打架。

**它仍有位置**：流程图、时序图继续用它，本项不碰。

### C 构建期出图（rough.js 或 D2）→ 提交 PNG/SVG 资产

**最强的一面**：运行时零成本，观感与 B 相同甚至更好（D2 的自动排版最强），
而且出问题可以直接手工修那张图。

**为什么没选**：需要新建**一条图片资产管线**——内容在数据库里，仓库没有任何媒体目录，
今天 217 篇正文一张图都没有。要先决定图放哪（仓库？对象存储？`/files/{uuid}`？），
再给 `import-course.mjs` 加引用改写。相比之下 B 的"图随文字"根本不需要这一步。
另外改一个字就要重新出图、重新上传，作者循环比 B 长。

### D Excalidraw（`coleam00/excalidraw-diagram-skill` 一类）

**最强的一面**：手绘感最强，能画火柴人、自由构图，还有现成的 agent 工作流
（写 `.excalidraw` JSON → Playwright 渲染 → agent 看图自修）。

**为什么没选**：**中文整段退回系统黑体**（实测 `fontFamily: 1` 下英文手写、中文黑体）。
对一个中文站来说，图里最该"手写"的就是中文标签，这条直接出局。
附加代价：渲染链路要 8 MB 的包与 Playwright。

### E AI 生图

**最强的一面**：不受 DSL 限制，什么构图都能出。

**为什么没选**：中文文字与箭头指向不可控、同一提示词不可复现、每次调用要花钱；
课程内容需要的是**可审阅、可 diff、可修正**的图。

## 交付拆分

1. 契约与解析（`parseSketch` + 上限 + 单测）。
2. 布局（纯函数，注入量宽，单测）。
3. 渲染组件 + 注册 + 降级 + 懒加载。
4. 字体子集与生成脚本。
5. 内容样例与 e2e。

## 风险与缓解措施

| 风险 | 缓解 |
| --- | --- |
| 字体子集缺字（内容写了生僻字） | 缺字回退系统字体且不出现豆腐块；提供脚本按内容重生成，并在作者指南写清 |
| 中文手写在正文尺寸下可读性差 | 只在图内用；先做 2–3 篇样例，看过再铺开 |
| 字体加载与文字测量的竞态导致裁字 | 测量前 `await document.fonts.load(...)`；量宽函数可注入，测试用确定性桩 |
| 渲染不确定（StrictMode 双渲染、刷新） | 抖动 seed 由内容派生，不取随机数 |
| 作者把 JSON 写坏 | 走现成的 `BlockFallback`：原因 + 原始文本，页面其余部分不受影响 |
| 共享包变重 | `roughjs` 动态 import；构建后对比入口 chunk gzip 体积（AC-008） |
