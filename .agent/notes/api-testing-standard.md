# 接口自查标准

> 2026-10-18 重写。**这是一套手动跑的检查标准，不接 CI、不改部署脚本。**
> 什么时候想确认"接口整体还通不通"，跑一条命令，看一份报告。

## 一条命令

```bash
cd backend
source config/remote-db.local.env          # 测试库口令（被忽略的本地文件）
mvn -B -pl paideia-app test -Dtest=ApiWalkthroughTest
```

跑完会：

1. 在控制台打印一份逐条结果表；
2. 在 `.agent/testing/runs/` 下留一份同样内容的 Markdown（时间戳命名，追加不覆盖）。

约 13 秒。**不需要 Docker、不需要前端、不连上游 AI。**

## 它会做什么

**自己开一个账号，把每条接口都真走一遍，最后把自己注销掉。**

一条完整链路：

```
图形验证码 → 发邮箱验证码 → 注册 → 登录 → 刷新令牌
  → 读/写画像
  → 建分类、建两条条目、建关系、传附件（真 PNG 字节）
  → 分类树、条目列表/详情、附件读取
  → 自评标记/列表/取消
  → 建笔记 → 改 → 分享 → 公开读 → 举报 → 管理端处理
  → 撤回分享 → 删笔记
  → AI 凭据/积分/设置/记忆增删清/精简生成/会话/SSE 发消息/面试点评
  → 管理端积分审计与调分
  → 沙箱状态与运行
  → 登出 → 注销
```

当前共 **69 步**，覆盖运行时注册的**全部 62 个端点**（步数比端点多，是因为同一个端点在不同场景下测了多次，例如分享后撤回）。

## "全"是被断言的，不是被声称的

自查最后有一条覆盖检查：拿运行时注册的每条路由，与这一轮真正打到过的路由做差集，**非空就失败**。

这条断言第一次跑就抓出 5 条没被走到（其中 3 条是我用底层 API 直调、没走统一入口的记录；2 条是真的漏了）。这正是它存在的意义。

## 为什么它能"访问全接口"

之前那些跑不通的原因，逐条解决了：

| 之前的限制 | 现在怎么办 |
| --- | --- |
| 需要注册才能拿到令牌 | 自己走完整的注册链路（图形验证码用桩固定答案，验证码从内存信箱读） |
| 管理端接口没权限 | 用 `AuthPort` 直接签一个 admin 令牌，不依赖种子账号 |
| AI 接口会真花钱、真连上游 | 三个端口全部用桩：`EntrySummarizer`、`AssistantConversation`、`InterviewReviewer` |
| AI 接口余额不够返回 402 | 注册后直接给自己发积分（`CreditService.adjust`） |
| 沙箱要 Docker | 不要求：返回 503（未启用）也算接口可达，真跑代码由别的测试与线上验证 |
| 写接口会脏数据 | 全程用 `walk-<纳秒>` 前缀，结尾注销账号 + 删条目分类 |
| 附件只收图片/PDF | 上传真的 1×1 PNG 字节（服务端按字节嗅探，不是看扩展名） |
| 一条失败就中断 | 全部跑完再统一报，一次看到全貌 |

## 第四层：响应结构快照（2026-10-18 补）

前两层能证明"接口在"、"边界对"，前一轮的 69 步能证明"调用成功"——**但都证明不了"返回的东西还是原来那个形状"**。

实测确认过这一点：把 `NoteView.title` 改名成 `heading` 后，69 步**全过**，因为状态码没变。
而前端会静默拿不到标题。所以补了结构的快照。

**快照文件**：`backend/paideia-app/src/test/resources/api-shape.json`

每条端点记一串"字段路径: 类型"，不含任何值：

```json
"GET /api/v1/notes/{id}": [
  "code: number",
  "data.body: string",
  "data.createdAt: string",
  "data.id: number",
  "data.title: string",
  "data.updatedAt: string",
  "message: string",
  "traceId: string"
]
```

当前覆盖 **56 个端点**（其余是 SSE、二进制附件、302 跳转，没有稳定的 JSON 结构）。
数组只看第一个元素的结构，所以列表里加一条不会误报。

**字段改名、增删、类型变化都会红**，并且会精确列出：

```
+ GET /api/v1/notes/{id} -> data.heading: string
- GET /api/v1/notes/{id} -> data.title: string
```

**确认变更是有意的之后**：

```bash
mvn -B -pl paideia-app test -Dtest=ApiWalkthroughTest -Dapi.shape.update=true
```

然后 review `api-shape.json` 的 diff——那份 diff 就是"这次接口契约到底改了什么"的清单，
应当与前端改动一起提交。

## 新增接口时要做什么

1. 在控制器类或方法上标 `@ApiAccess(ApiAccess.Access.…)`。
2. 在 `ApiWalkthroughTest` 里给它加一段真实调用。

漏了任一步，三处断言会分别变红：

| 漏了什么 | 谁红 | 报什么 |
| --- | --- | --- |
| 没标 `@ApiAccess` | `ApiSurfaceTest` | 点名那条 `METHOD /path` |
| 标错访问级别 | `ApiContractTest` | "对学习者返回 403，但没有声明 ADMIN" |
| 没在自查里走一遍 | `ApiWalkthroughTest` 覆盖断言 | "这些端点这一轮没有被打到" |
| 改了响应字段名/增删字段/改类型 | `ApiWalkthroughTest` 结构快照 | 逐条列出 `+ data.heading` / `- data.title` |

三处都是构建失败，不靠记性。

## 三层各管什么

| 测试类 | 管什么 | 耗时 |
| --- | --- | --- |
| `ApiSurfaceTest` | 有没有端点没声明、有没有不限方法的映射、有没有越出 `/api/v1` 的接口 | 1s |
| `ApiContractTest` | 每条路由的拒绝路径：匿名 401、越权 403、畸形体 400/415、`X-Trace-Id` | 10s |
| `ApiWalkthroughTest` | **全部接口的正面路径** + 响应结构快照 | 20s |

只想确认"整体通不通"，跑第三条就够。

## 台账

`.agent/testing/runs/YYYY-MM-DDTHHmm-walkthrough-local.md`，每跑一次新增一份。

- 文件名按时间排序即时间线，不建"最新状态"汇总文件（汇总必漂移）。
- 每份含：合计步数、通过/失败数、覆盖端点数、逐条结果表。
- 脱敏：不写主机名、账号名、令牌、连接串。
- **常规运行只在台账留证，不另写项目时间线**，否则时间线会被跑测试刷满。

## 已知边界

- **只跑本地**（`target: local`）。日常自查就在本地跑。
- 沙箱只验接口可达，不验真的执行结果。
- AI 三处用桩，验的是"接口链路通"而不是"模型答得好"。
- 需要测试库口令；没给口令时整个类跳过而构建仍绿——**看结果先看 `Skipped` 列**。

## 和普通单测的分工

- **这套**回答"现在整体还通不通"，一次跑完全部。
- **各模块的 `*IntegrationTest`** 回答"这个业务规则对不对"，断言更细。
- 两者不替代：改了某个业务的语义，模块测试才是主场；改了一堆东西想确认没把别的弄坏，跑这套。
