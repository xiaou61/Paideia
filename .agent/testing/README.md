# 测试台账

本目录是**长期运行记录**：每次接口契约测试或线上冒烟跑完，追加一个文件，不修改旧文件。
它不是某个工作项的验收证据——工作项的验收在 `.agent/changes/WORK-*/testing/`；这里是跨工作项、跨时间的运行历史。

标准与分层定义在 [`.agent/notes/api-testing-standard.md`](../notes/api-testing-standard.md)（草案，待签署进 `rules/`）。

## 为什么单独有一个目录

- **工作项会结束，测试不会。** 把长期记录塞进 `WORK-*/testing/report.md` 的话，那些报告在代码一变就整体 `stale`，只能重写；而"上周三线上冒烟是什么结果"这个事实不该被覆盖。
- **追加不覆盖。** 每次运行一个新文件，历史天然可回溯，不做"最新状态"汇总文件（汇总会漂移，`ls` 就是索引）。

## 记什么、不记什么

| 记 | 不记 |
| --- | --- |
| 契约测试（L1 清单 + L2a 拒绝矩阵）的每次运行 | 每次本地单测、typecheck——那是内环，不入账 |
| 线上只读冒烟（L3）的每次运行 | 手工探索、临时 curl |
| 失败的具体用例与错误 | 令牌、口令、账号标识、主机名/IP/端口、连接串 |
| 运行时的 commit、是否 dirty、耗时、通过/失败/跳过数 | 完整的响应正文（可能含用户数据） |

**默认只记 `contract` 与 `smoke` 两层。** e2e 的回归结果若与本项相关（例如改动影响全部接口）可以记一条 `e2e` 记录，但不是每次必记——记录太勤会被当成噪音，最后没人写。

## 命名

```
runs/YYYY-MM-DDTHHmm-<layer>-<target>.md
例：runs/2026-10-18T1500-contract-local.md
    runs/2026-10-18T1530-smoke-online.md
```

`layer` ∈ `contract` | `smoke` | `e2e`；`target` ∈ `local` | `online`。
文件名按时间排序即时间线，不需要索引文件。

## 记录模板

```markdown
---
artifact: test-run
run_id: 2026-10-18T1500
layer: contract
target: local
commit: d694c14
workspace_dirty: false
status: passed
started: 2026-10-18 15:00:12 +0800
duration_s: 47
---

- 代码：`d694c14`，工作区干净
- 目标：本地（后端 `paideia_test`）
- 数据库口令：已提供

## 结果

| 层 | 用例 | 通过 | 失败 | 跳过 |
| --- | --- | --- | --- | --- |
| L1 路由清单 | 1 | 1 | 0 | 0 |
| L2a 拒绝矩阵 | 118 | 118 | 0 | 0 |

## 失败明细

无。

- 新增路由：2（`GET/PUT /api/v1/account/profile`）

```

`status` 只写 `passed` / `failed` / `partial`；`partial` 必须写明哪些没跑、为什么。

## 与项目时间线的分工

- **常规运行只落这里，不另写项目时间线。** 否则每跑一次测试就给时间线加一条，真实变更会被淹没。
- 台账/测试标准本身的结构变化、一次导致代码修改的失败、以及部署闸门的首次接入，用对应的 Git 提交信息说明。

## 脱敏（公开仓库）

本仓库是公开的，台账会被提交。写之前过一遍：

- 主机名、IP、端口一律写成 `online` / `local`，不写实际地址。
- 账号写成 `learner` / `admin`，不写用户名或邮箱。
- 令牌、Cookie、`Authorization` 头的值一律不出现；失败信息若带出这些，先删再提交。
- 服务器路径可以写（`/opt/paideia-app`），连接串不行。

## 保留

不删除旧记录。一年按每周两次 `contract` + 每次部署一条 `smoke` 估算约 150 个文件、几百 KB；超过约 200 个文件时按年份建子目录（`runs/2027/`），不做压缩或汇总。
