## 先把结论摆出来

`write()` 返回成功，只代表**数据交给了内核**，不代表已经写到磁盘。内核先把它放进页缓存，稍后由后台线程刷盘。

要真正落盘，必须 **fsync**（或 `O_SYNC`、或数据库自己的刷盘策略）。这也解释了三件事：

- 为什么断电会丢最近几秒的数据；
- 为什么"写文件"很快，但机器负载一高就突然卡；
- 为什么数据库要自己管理日志与刷盘顺序，而不是只靠文件系统。

## 一次读写的完整路径

读文件时：

1. 用户态调 `read()`；
2. 内核先查页缓存，命中就直接拷贝给用户（**不碰磁盘**）；
3. 没命中才向磁盘发请求，读上来后放进页缓存，再拷贝。

写文件时：

1. 用户态调 `write()`；
2. 内核写进页缓存，标记为"脏页"，立即返回；
3. 后台（或内存压力/`fsync` 触发）把脏页写到磁盘。

**所以"第二次读同一个文件很快"不是玄学**——第一次已经进了页缓存。这同样是"为什么测试环境快、生产环境慢"的常见原因：数据量和缓存命中率完全不同。

## 顺序 IO 与随机 IO

机械盘上，顺序读写比随机快一个数量级，因为省掉了磁头寻道。SSD 上差距小很多，但随机小 IO 仍有额外开销（每次请求的固定成本）。

这直接影响设计：

- **追加写日志**（顺序）比"改文件中间某处"（随机）快；
- **批量写**（攒够再写）比"一条一条写"快；
- 数据库的 WAL、消息队列的 commit log 都是顺序追加，不是巧合。

## 三个容易混淆的"写"

| 调用 | 保证 | 代价 |
| --- | --- | --- |
| `write()` | 数据进了内核页缓存 | 最小，可能丢数据 |
| `fsync()` | 数据与元数据落盘 | 一次真实磁盘往返 |
| `fdatasync()` | 只保证数据落盘 | 比 fsync 略快 |

**每次写都 fsync 会非常慢**：一条 100 字节的记录也要等一次磁盘。所以数据库用"组提交"：把多个事务的日志攒一起，一次 fsync 全部落盘。

## 为什么"写成功"后文件是空的

常见于两种写法：

```python
f = open("a.txt", "w")
f.write("hello")     # 还在用户态缓冲区里
# 程序崩溃 / 没 close
```

Python 的 `open` 默认还有一层用户态缓冲。`write` 只是写进这个缓冲，`close()` 或缓冲满了才交给内核。**用 `with` 保证 close**，需要更强保证时再 `f.flush(); os.fsync(f.fileno())`。

## 直接 IO 与零拷贝（知道有这回事就够）

- **Direct IO**：绕过页缓存，读写直达磁盘。数据库自己管理缓存时用，普通应用几乎不需要。
- **零拷贝**（`sendfile`）：把文件内容发到 socket 时，不让数据在用户态与内核态之间来回拷。静态文件服务、消息队列常用。

这两个概念的价值不在"自己实现"，而在**看懂中间件为什么那么设计**。

## 排查 IO 问题的三个数

```bash
iostat -x 1        # %util 接近 100% 说明设备忙；await 是平均等待
pidstat -d 1       # 哪个进程在读写在狂刷
vmstat 1           # bi/bo 每秒块读写
```

`%util` 高且 `await` 高 → 设备真的饱和；`%util` 不高但应用慢 → 可能在等锁、等网络，不是磁盘。

## 常见误区

### 误区：`f.write()` 之后文件里就有内容了

**你以为**：写一行就能被别的进程读到。
**其实**：可能在用户态缓冲里没交出去。要么 `close()`，要么 `flush()`；跨进程可见还要考虑内核缓存的时机。

### 误区：加了 `fsync` 就绝对不会丢数据

**你以为**：落盘等于万无一失。
**其实**：磁盘自身的写缓存也可能没落。真要抗断电，得看磁盘是否开启写缓存、是否支持屏障，以及文件系统与硬件的组合保证。工程上的做法是"接受一个很小的窗口 + 用副本兜底"。

### 误区：IO 慢就换 SSD

**你以为**：换硬件能解决。
**其实**：先确认瓶颈是磁盘、还是应用在一条一条地写、还是 `%util` 根本不高。批量、顺序、减少 fsync 往往比换盘更有效。

## 小结

写成功只到内核缓存，落盘要 fsync。页缓存解释"第二次快"。顺序 IO 优于随机 IO，批量提交优于逐条刷盘。排查先看 `%util` 与 `await`，别急着换硬件。下一篇从文件本身讲起：文件到底存在哪，inode、目录项与硬链接各管什么。
