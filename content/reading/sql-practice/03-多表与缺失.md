## 这一关要练什么

连接会把行变多；否定条件不要用 NOT IN。

下面每题都在同一套订单数据上跑。写完点「运行」看结果对不对；**写错不扣分，可以一直试**。

## 第 1 题 · 每个城市贡献了多少订单金额

**目标**：三张表连接后按城市聚合；理解「连接会把行变多」

```sql-challenge
{

 "kind": "sql-write",

 "goal": "三张表连接后按城市聚合；理解「连接会把行变多」",
 "dataset": [
  "orders-hidden-a",
  "orders-public"
 ],
 "starter": "SELECT c.city, ? AS total\nFROM customers c\nJOIN orders o ON ?\nJOIN order_items i ON ?\nGROUP BY ?\n",
 "normalize": {
  "rowOrder": "ignore",
  "columnOrder": "ignore"
 },
 "expectHash": {
  "orders-hidden-a": "0310519a8acc82d2bc995a8e7037a35b1b9b1687e368d8326ab63ce078f9a8da",
  "orders-public": "b2a742053900094b3f3788012198ddb863dc8a8ce0381bc5bd74372e02288cb8"
 },
 "explain": "订单金额挂在 order_items 上，城市挂在 customers 上，中间必须过 orders。少接一张表就会把「订单明细」错配到「客户」上——SQL 可能不报错，但数字全错。"

```

**为什么**：订单金额挂在 order_items 上，城市挂在 customers 上，中间必须过 orders。少接一张表就会把「订单明细」错配到「客户」上——SQL 可能不报错，但数字全错。

## 第 2 题 · 从没下过单的客户

**目标**：用 NOT EXISTS 表达「不存在」，比 LEFT JOIN + IS NULL 更难写错

```sql-challenge
{
 "id": "sql-p3-never",
 "kind": "sql-write",
 "title": "从没下过单的客户",
 "goal": "用 NOT EXISTS 表达「不存在」，比 LEFT JOIN + IS NULL 更难写错",
 "dataset": [
  "orders-hidden-a",
  "orders-public"
 ],
 "starter": "SELECT name\nFROM customers c\nWHERE ?\n",
 "normalize": {
  "rowOrder": "ignore",
  "columnOrder": "ignore"
 },
 "expectHash": {
  "orders-hidden-a": "18660860330ed2227481de0871db86aafda20d0e18d14d73825155ee9922a109",
  "orders-public": "f36c0a2c4282fe8e84bf06cee06c54a3b51f5629693692f29b58c75c424722b8"
 },
 "explain": "「没下过单」是一个否定条件：要找出在 orders 里找不到对应行的客户。NOT EXISTS 直接表达这一点，且不受 NULL 影响；NOT IN 的子查询一旦返回 NULL，整个条件会变成「未知」，结果为空——这是 SQL 里最经典的一个坑。"
}
```

**为什么**：「没下过单」是一个否定条件：要找出在 orders 里找不到对应行的客户。NOT EXISTS 直接表达这一点，且不受 NULL 影响；NOT IN 的子查询一旦返回 NULL，整个条件会变成「未知」，结果为空——这是 SQL 里最经典的一个坑。
