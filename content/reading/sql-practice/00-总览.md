## 这条线是干什么的

理论教你"这条 SQL 为什么这么写"，这条线只问一件事：**给你一份数据和一个业务问题，你能不能写出跑得出正确结果的查询。**

每一题都有参考答案在真实数据上跑出来的期望结果，写完点「运行」立刻知道对不对。**写错不扣分，可以一直试**——练习的价值在试，不在一次做对。

## 十道题怎么排

1. **从空值到分组**：`NULL` 与空字符串的区别；一单没下的客户怎么还能留在结果里；
2. **算钱**：金额是"单价 × 数量"再求和，不是把单价加起来；"卖得最多"是件数还是金额；
3. **多表与缺失**：三张表连接会把行变多；否定条件为什么不要用 `NOT IN`；
4. **聚合之外**：`WHERE` 与 `HAVING` 的分工；子查询给出的标量怎么用；
5. **窗口与时间**：排名怎么算；`DATETIME` 分组前为什么要先截到天。

## 练习之前

- 数据集是 `orders-public`（三张表：客户、订单、订单明细），课时里讲过结构；

## 常见误区

### 误区：能跑出结果的 SQL 就是对的

**你以为**：不报错、有数据，就说明写对了。
**其实**：最贵的错误是不报错的那种——少接一张表、漏乘数量、用 `WHERE` 过滤了本该 `HAVING` 的条件，结果都"看起来像"正确的。
**怎么验证**：拿一道题，把 `JOIN` 去掉一个条件再跑一遍，看它是否照样返回一堆行。

### 误区：练习就是做题，做对就完事

**你以为**：题目过了就学会了。
**其实**：每道题下面那段"为什么"才是重点——它讲的是这类错误在真实报表里长什么样、为什么难发现。
**怎么验证**：把一题的参考解改成一个你认为"等价"的写法，看结果是否真的相同。
