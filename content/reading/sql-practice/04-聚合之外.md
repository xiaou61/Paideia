## 这一关要练什么

WHERE 与 HAVING 的分工，以及子查询给出的标量。

下面每题都在同一套订单数据上跑。写完点「运行」看结果对不对；**写错不扣分，可以一直试**。

## 第 1 题 · 单价高于「所有商品平均单价」的明细

**目标**：聚合结果不能直接写在 WHERE 里：先用子查询算出平均值

```sql-challenge
 "explain": "WHERE 在分组之前执行，那时还看不到 AVG 这种聚合结果，所以直接写会报错。子查询先算出平均值（一个标量），外层再拿每行去比。这类题也常被写成「比平均贵」的直觉判断——一定要用数据算，别用眼睛看。"

```

**为什么**：WHERE 在分组之前执行，那时还看不到 AVG 这种聚合结果，所以直接写会报错。子查询先算出平均值（一个标量），外层再拿每行去比。这类题也常被写成「比平均贵」的直觉判断——一定要用数据算，别用眼睛看。

## 第 2 题 · 买了不止一种商品的订单

**目标**：分组后的筛选条件写在 HAVING，不是 WHERE

```sql-challenge
{
 "id": "sql-p4-multi",
 "kind": "sql-write",
 "title": "买了不止一种商品的订单",
 "goal": "分组后的筛选条件写在 HAVING，不是 WHERE",
 "dataset": [
  "orders-hidden-a",
  "orders-public"
 ],
 "starter": "SELECT order_id\nFROM order_items\nGROUP BY order_id\n? COUNT(*) > 1\n",
 "normalize": {
  "rowOrder": "ignore",
  "columnOrder": "ignore"
 },
 "expectHash": {
  "orders-hidden-a": "b789070ebd84236fd42e40c5b9065148e0239502abdaaa91f12ed9cad8857e04",
  "orders-public": "e4e73b6bc1771eaa9dd85d7d78e8c776e51a75135b46380ae42d721ac6b821ca"
 },
 "explain": "WHERE 过滤的是「行」，HAVING 过滤的是「组」。COUNT(*) 这类聚合只有在分组之后才有值，所以必须放 HAVING。`DISTINCT order_id` 会把所有下过单的订单都列出来，它答的是另一个问题。"
}
```

**为什么**：WHERE 过滤的是「行」，HAVING 过滤的是「组」。COUNT(*) 这类聚合只有在分组之后才有值，所以必须放 HAVING。`DISTINCT order_id` 会把所有下过单的订单都列出来，它答的是另一个问题。
