## 这条线是干什么的

大多数人用 Redis 的方式是把它当成一个"很快的 Map"：`SET` 存、`GET` 取、加个过期时间。这样用能跑，但一旦内存满了、主从延迟了、缓存突然全失效了，就只剩下重启和加机器两条路。

这条线反过来：**先讲清 Redis 为什么这样设计，再看它能干什么、不能干什么。** 你一旦知道"命令是一条线程串行执行的"，`KEYS` 为什么会拖垮实例、为什么不能用 `DEL` 删大 key、为什么锁的过期时间这么难定，就都不用背了。

## 六篇的走法

1. **Redis 是什么，为什么快**：内存 + IO 多路复用 + 无锁，以及单线程的边界在哪；
2. **五种基本类型与它们的真实用途**：每种类型解决什么问题，以及用 list 当队列会踩什么坑；
3. **过期与淘汰**：TTL 不是到点就删；内存满了八种策略各删谁；为什么不能当唯一存储；
4. **持久化**：RDB 和 AOF 各丢什么，混合持久化是什么，`fsync` 怎么选；
5. **缓存三大问题**：穿透、击穿、雪崩三者的区别（最容易被混为一谈）与各自的标准解法；
6. **分布式锁**：`SET NX PX`、误删别人的锁、Redlock 的争议、过期时间为什么最难。

## 常见误区

### 误区：Redis 就是个缓存，随便用

**你以为**：反正数据能从数据库重建，缓存怎么用都行。
**其实**：Redis 常被顺手用来做锁、做队列、做计数器、做排行榜——这些数据一旦丢，不是"重新查一次数据库"能补回来的。用之前先问一句：这份数据丢了会怎样。
**怎么验证**：翻一遍你的代码，找出所有 `redisTemplate.opsForValue().set` 的地方，标出哪些是"缓存"、哪些其实是"存储"。

### 误区：单线程是 Redis 的缺陷，迟早要改成多线程

**你以为**：单线程就是性能差，多线程一定更快。
**其实**：Redis 的瓶颈从来不是 CPU，而是内存和网络。单线程省掉了锁、省掉了线程切换，反而让每条命令的延迟更稳定、可预测。Redis 6 加的 IO 线程也只分担网络读写，命令执行仍然是单线程。
**怎么验证**：`redis-cli INFO commandstats` 看单条命令的平均耗时——通常是微秒级，说明 CPU 根本不是瓶颈。
