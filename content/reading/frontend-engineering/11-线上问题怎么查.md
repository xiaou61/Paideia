## 这一关在解决什么

用户发来一句"打不开了，白屏"，而你本地一切正常。这时候你手里有什么？

如果没有准备，答案是"什么都没有"——只能靠猜：让他刷新、让他清缓存、让他换浏览器，三招用完还没好，就只能让他截图。

这一关讲的是：**在你还没收到那条消息之前，就把证据留下来**。具体是四件事——白屏到底可能是什么、怎么把压缩后的报错映射回源码、错误该上报什么、以及怎么把一次次报错对到具体某次发布。

## 讲解

### 白屏的原因清单（按发生频率排序）

| 原因 | 表现 | 怎么确认 |
| --- | --- | --- |
| JS 报错中断了渲染 | 页面全白，Console 有红字 | 看 Console 第一条错误 |
| 资源 404 | 白屏或样式全丢 | Network 里筛选 404 |
| 路由没配 / 刷新 404 | 首页正常，某个深链接白 | 直接访问该 URL 看服务器返回 |
| 接口 401/403 | 骨架屏一直转，或直接跳登录 | Network 看接口状态码 |
| 缓存了旧 HTML + 新资源 | 偶发白屏，强刷就好 | 对比 HTML 与 assets 的版本 |
| 容器高度为 0 / CSS 全错 | 有内容但不可见 | Elements 里看根节点高度 |

前三条占绝大多数。**排查顺序就按 Console → Network → Elements 走一遍**，比任何猜测都快。

### 把压缩后的报错翻译回源码

生产代码是压缩加混淆的，堆栈长这样：

```text
TypeError: Cannot read properties of undefined (reading 'name')
    at t.value (index-8f3a2c.js:1:48213)
```

`index-8f3a2c.js:1:48213` 对一个 1MB 单行文件，等于没有信息。source map 就是那张翻译表：

```js
// vite.config.js
export default {
  build: {
    sourcemap: true,   // 生成 .map 文件，但不让浏览器自动加载
  },
}
```

关键的一条纪律：**source map 只能给内部用，不能公开部署**。它包含完整源码，公开等于把代码开源。做法是构建时生成、上传到错误监控平台（或私有存储），发布产物里删掉 `.map` 文件。

有了它，一条 `index-8f3a2c.js:1:48213` 能变成 `Cart.tsx 第 42 行`。

### 错误上报：三类必须接住

浏览器里没被接住的错误，用户看到白屏，你什么都收不到。三个入口：

```js
// 1. 同步错误与资源加载失败
window.addEventListener('error', (e) => {
  report({
    type: 'error',
    message: e.message,
    source: e.filename,
    line: e.lineno,
    col: e.colno,
    stack: e.error?.stack,
  })
}, true)   // 捕获阶段，才能收到资源加载失败的 error

// 2. Promise 里没人 catch 的拒绝
window.addEventListener('unhandledrejection', (e) => {
  report({ type: 'rejection', reason: String(e.reason) })
})

// 3. React 渲染期错误
class Boundary extends React.Component {
  componentDidCatch(error, info) {
    report({ type: 'react', message: error.message, componentStack: info.componentStack })
  }
  render() { return this.state.failed ? <Fallback /> : this.props.children }
}
```

这三类的分工很明确：`error` 管语法与运行时错误，`unhandledrejection` 管异步，`ErrorBoundary` 管渲染——前两者接不住 React 渲染期的错误（它被 React 自己吞掉并重抛），后者接不住事件处理函数里的错误（React 不管事件回调）。**都要**。

上报内容里，除了报错本身，必须带三样：

- **版本号**（发布时注入的 commit hash 或版本）；
- **路由**（哪个页面炸的）；
- **用户/环境标识**（谁的、什么浏览器、是否弱网）。

少了版本号，你会看到一堆分散的报错，却不知道是哪次发布带进来的。

### 从"有人在炸"到"哪次发布炸的"

有了版本号，监控平台的趋势图会变成这样：

```text
v1.20.3  错误率 0.02%   ← 正常
v1.20.4  错误率 3.1%    ← 发布后 10 分钟陡增
```

这时候判断就变成机械动作：对比这两个版本的 diff，重点看新引入的依赖与改动的路由。

**这就是"发一次版就盯十分钟"的价值**：错误率曲线是你发版后最便宜的回归测试，比任何测试套件都真实。

### 一个兜底：白屏也要能看见东西

```html
<div id="root"></div>
<script>
  // 8 秒还没挂上内容，说明入口挂了
  setTimeout(() => {
    var root = document.getElementById('root')
    if (root && root.children.length === 0) {
      root.innerHTML =
        '<p style="padding:24px;font:14px system-ui">页面加载失败，请刷新重试。<a href="/">回首页</a></p>'
    }
  }, 8000)
</script>
```

这段代码的作用不是修复问题，是**把"白屏"变成"有提示"**——用户知道该干什么，你也知道该查什么。成本几行，收益是所有白屏事故的用户体验下限。

## 常见误区

### 误区：用户说白屏，先让他清缓存

**你以为**：十有八九是缓存问题。
**其实**：清缓存确实偶尔有效（旧 HTML + 新资源），但如果你把它当成第一手段，就永远发现不了真正的原因——而真正的原因（某个接口 401、某个路由 404）会持续影响所有用户，只是他们没来反馈。
**怎么验证**：先要一张 Console 截图或问一句"按 F12 有没有红字"。这一个问题能砍掉 80% 的猜谜时间。

### 误区：source map 是开发用的，生产不该生成

**你以为**：生产开 source map 会暴露源码，关了更安全。
**其实**：不开的代价是**线上报错永远无法定位**，你只能看到压缩后的坐标。正确的做法是"生成但不公开"——构建时生成，上传到监控平台，产物里删掉。安全与可排查性可以同时拿到。
**怎么验证**：看发布产物里有没有 `.map` 文件（不该有），再看监控平台能否把堆栈还原到源码行（应该能）。

### 误区：接了 window.onerror 就全覆盖了

**你以为**：全局错误监听，什么都能抓到。
**其实**：三个盲区——Promise 拒绝走 `unhandledrejection`；React 渲染错误被框架吞掉，要 `ErrorBoundary`；跨域脚本的报错默认是 `Script error.`，不带任何细节（需要资源响应头加 `crossorigin` 并配置 CORS）。
**怎么验证**：故意在三个位置各造一个错误（同步、Promise、渲染），看监控能不能都收到。缺哪个就补哪个。
