## 这一关在解决什么

superpowers 的价值在**链路**——七个环节首尾相接，每一步都为下一步留下可检查的产物。只单独用其中某一个技能，效果会打折扣；连起来跑，才是一个完整的工作流。

> 版本同上：superpowers **v7.0.2**，commit `22f0b463`，核对于 2026-11-03，MIT。流程以该版本 README 的 "The Basic Workflow" 为准。

## 讲解

### 从"我想做个 X"到"合并分支"：七步

```text
① brainstorming        先问清楚要什么，把设计复述给你确认
② using-git-worktrees   拉独立分支/工作区，确认测试基线是绿的
③ writing-plans         拆成 2–5 分钟的小任务，写清路径/代码/怎么验
④ 执行                  subagent-driven-development 或 executing-plans
⑤ test-driven-development  每个任务先红后绿
⑥ requesting-code-review   对照计划审，critical 阻塞
⑦ finishing-a-development-branch  验测试、给选项、清理
```

逐步看每一步"留下了什么可检查的东西"：

1. **brainstorming**：产物是一份你签过字的设计（小改动就是聊天里确认的一段话）。**没有它，后面全在猜。**
2. **using-git-worktrees**：产物是一个干净的分支 + 一次跑绿的基线。**基线不绿，后面分不清是谁弄坏的。**
3. **writing-plans**：产物是任务清单。每个任务都小到"一个没耐心的初级工程师也能照着做完"——这是 README 的原话意思。
4. **执行**：两种模式。`subagent-driven-development` 派子智能体一个任务一个任务做，每做完一个就 review（最彻底）；`executing-plans` 在当前会话里逐个做，最后整体 review 一次（最省）。
5. **test-driven-development**：每个任务都走 RED→GREEN→REFACTOR。先写一个会失败的测试、看它真的红、再写最小代码让它绿。**在测试之前写的代码会被删掉重来。**
6. **requesting-code-review**：对照计划审，按严重度报问题，critical 的直接阻塞。
7. **finishing-a-development-branch**：跑测试、给你"合并 / 提 PR / 保留 / 丢弃"四个选项、清理工作区。

### 为什么非要强制 TDD

因为 TDD 是"**证据优于声明**"最直接的落地。

没有"先红后绿"，AI 说"我写好了、测试也过了"就只是一句话——你没法确认那个测试真的能测出问题。先红后绿至少证明了两件事：这个测试确实会因为 bug 而失败；修完之后它确实变绿了。**这两条，比一句"完成了"值钱得多。**

### 人在整条链路里的位置

这条链路看着像"AI 全自动"，其实每一步都有一个**人把关的门**：

- 设计确认（①之后）；
- 基线绿（②之后）；
- 计划批准（③之后，superpowers 明确要求执行前先把保存的计划给你看）；
- 每个任务的 review（④⑤⑥）；
- 最终合并决定（⑦）。

**门在，链路才可控；门没了，就退化成"让 AI 自己玩"。**

### 什么时候这套太重

小改动（改一行、修错别字）不必跑全链路。但里面有两样值得一直留着：**测试先行**，和**完成前验证**。这两件事的收益几乎在所有规模上都成立。

## 常见误区

### 误区：跑子智能体 = 让 AI 自己玩

**你以为**：派一屋子子智能体并行干，人就能躺着。
**其实**：关键在于每步之间的 review 门。没有门，子智能体越多，跑偏得越远、越难追。
**怎么验证**：对比"有 review 门"和"无 review 门"两组，看最后需要人工返工的量——差别很大。

### 误区：TDD 只是形式，写了测试就行

**你以为**：有测试文件就算 TDD。
**其实**：没先看它红，就不知道这个测试能不能抓到 bug。测试也可能是"永远绿"的摆设。
**怎么验证**：故意把被测代码改坏，看测试会不会红——不红，说明它不是有效测试。

### 误区：全链路等于高质量

**你以为**：七步全走一遍，结果一定好。
**其实**：流程保证"该做的都做了"，不保证"做对了"。规格本身错了，再规范的流程也只是把错误执行得更整齐。
**怎么验证**：回看一次失败交付，问题出在"流程没走"还是"第一步需求就错了"。

## 带走一句

**七步链路的本质是"每一步都为下一步留下可检查的产物"**——下一关就动手，把一个你反复做的流程，写成一个自己的 skill。
