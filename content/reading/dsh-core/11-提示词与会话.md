## 先把结论摆出来

**模型每次请求只看到两样东西：一份系统提示词，加上一段由会话日志投影出来的消息历史。** 两者都不是某个插件里写死的一坨字符串，而是很多插件"注册进来、按顺序拼起来"的。

而且有一条铁律：**模型能看到什么，就必须被记进会话日志。** 这样任何一次请求都能从日志重建、回放、审计。想给模型塞一点新东西，你得先让它变成一条会话事件。

## 系统提示词：很多段落，按 order 拼

`ctx.systemPrompt` 是一个注册表。每个插件可以贡献：

- **段落（section）**：一段提示词文本，按 `order` 升序排列。文本可以是静态的，也可以是"每次组装时求值"的函数。
- **工具 schema**：`defineTool` 注册的工具，会通过 `tools provider` 把 schema 贡献进提示词——所以工具描述本身就是提示词的一部分（第 6 关说过）。
- **运行上下文（context）**：每轮动态求值、作为一条"用户角色"快照进入历史，比如当前工作目录、时间、项目约定。
- **变量**：`{{name}}` 这种占位符，在渲染时插值。

注册一段自己的提示词，就是一句话：

```ts
ctx.systemPrompt.section({
  name: 'my-project-rules',
  order: 100,
  text: '本项目所有回复使用中文，代码示例用 TypeScript。',
})
```

组装时还有一个 `system-prompt/assemble` waterfall，专家插件可以在最后整体改写这次组装；注册了 `complete` 段落时，它会成为唯一的提示词段落。

## 会话日志：模型历史的唯一来源

模型看到的历史，不是"内存里攒出来的一串消息"，而是从**会话日志**投影出来的：

- 日志只追加（append-only），记录 `turn/start`、`step/start`、`system/message`、`user/message`、`assistant/message`、`tool/*` 这些事件。
- `deriveMessages()` 从日志里投影出"模型该看到的消息"。
- 所以 fork、恢复、回放、遥测，全都从这份持久日志派生，而不是各存一份。

这就是"**模型可见即已记录**"：如果某样东西没有对应的事件，它就不该出现在模型面前；反过来，凡是模型看到了，日志里一定查得到。

## 改提示词的正确姿势

- 加一条固定规则 → 注册一个 `section`。
- 加一个随环境变的值 → 注册一个 `context` 或 `variable`。
- 想让工具的描述出现在提示词里 → 它已经自动通过 `tools provider` 进去了，不用手拼。
- 想整体替换提示词 → 用一个 `complete` 段落（谨慎，它会盖掉别人）。

**不要**去 agent loop 里手拼字符串——那样既不可回放，也会跟别人注册的段落打架。

## 常见误区

### 误区：提示词就是某个文件里的一大段文字

**你以为**：系统提示词是一个 markdown 文件，改它等于改一个地方。

**实际上**：它是很多插件各自注册的段落 + 工具 schema + 运行上下文，按顺序拼出来的。你看到的"一段提示词"，背后可能是十几个贡献方。想让某段话出现/消失，应该去它所属的注册方，而不是找"那个提示词文件"。

**所以**：改提示词前先问"这段话是谁注册的"，动那个插件，别动总装。

### 误区：往上下文里塞点东西不用记日志

**你以为**：我在请求前临时给模型加一段背景，反正这一轮用完就没了，记不记无所谓。

**实际上**："模型可见即已记录"是硬约束。临时塞进去而不落日志，会让这次请求无法从日志重建——回放、审计、复现 bug 全部失真。

**所以**：要加模型可见的上下文，用 `agent.inject()` 或注册 context，让它进入被记录的历史；不要旁路硬塞。
