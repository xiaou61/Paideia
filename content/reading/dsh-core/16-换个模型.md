## 先把结论摆出来

**在 DSH 里"换模型"根本不用改代码**——模型是 `ctx.llm` 里注册的一个**适配器**，换模型/换提供方只是改配置；只有接入一个**全新 API 格式**的厂商时，才需要写一个新适配器。

按改动量从小到大，分三档：

1. **同提供方、换个模型 id**：只改配置里那一行。
2. **换提供方（已有适配器）**：改 `provider` + `model`，再配好对应的 API Key。
3. **接一个从没支持过的厂商**：写一个 `LlmAdapter`，实现 `stream()`。

## 第一档：只改一行配置

默认模型选择本身就是一个插件（`agent-default-model`），它的 `provider` 和 `model` 写在配置里。你在自己的 **patch 层**里覆盖它即可，别的配置一概不碰：

```yaml
# cordis.patch.yml —— 只覆盖这一条，其余保持框架默认
- id: agent-default-model
  config:
    provider: my-provider
    model: my-model-v1
```

这就是"换模型"最轻的形态：改一行，重启或热更新，选择器里换人。

## 第二档：换提供方（已经有适配器）

如果目标提供方已经有现成适配器（比如 `deepseek`、`pi-ai`），你要做的只是让它可路由：

- 在对应适配器插件的 `config.providers` 里包含这个 provider；
- 把 `agent-default-model` 的 `provider` / `model` 指过去；
- 配好 Key（密钥用环境变量，**不要写进仓库**）。

DSH 自带的两个完整适配器（`llm-deepseek` 与 `llm-pi-ai`）可以当范例，看同一套契约怎么落在两种不同的 API 格式上。

## 第三档：写一个新适配器

适配器就是一个继承 `LlmAdapter`、实现 `stream()` 的类：把 DSH 的"提供方无关请求"翻译成具体厂商的调用，再把响应翻译回 `StreamChunk`。

```ts
import { LlmAdapter, LlmError, attributionHeaders, type GenerateOptions, type StreamChunk } from '@deepseek-ai/dsh-llm'

class MyAdapter extends LlmAdapter {
  constructor(private apiKey: string) { super() }

  async *stream(options: GenerateOptions): AsyncIterable<StreamChunk> {
    const res = await fetch('https://api.example.com/v1/chat', {
      method: 'POST',
      headers: { 'content-type': 'application/json', ...attributionHeaders() },
      body: JSON.stringify({ model: options.model, messages: options.messages }),
      ...(options.signal ? { signal: options.signal } : {}),
    })
    if (!res.ok) throw new LlmError(`HTTP ${res.status}`, 'PROVIDER_HTTP_ERROR')
    // 真实适配器会解析响应，按下面的协议产出分片
    yield { type: 'finish', reason: { kind: 'stop' } }
  }
}

export const inject = ['llm']
export function apply(ctx, config) {
  ctx.llm.registerAdapter(['my-provider'], new MyAdapter(config.apiKey))
}
```

### StreamChunk 协议的三条硬规则

- 每个 `block-start` 都必须有配对的 `block-end`；`index` 从 0 递增。
- 文本用 `text-delta` 流式产出；工具调用用 `tool-call-delta`（`argumentsDelta` 是原始 JSON 文本的增量）。
- `usage` 必须在 `finish` 之前；`finish` 必须是最后一个分片。

另外两点：`stream()` 里**不能静默丢弃**不支持的字段——要抛带稳定 code 的 `LlmError`；每个 HTTP 请求都要带上 `attributionHeaders()` 并传递 `options.signal`（用于取消）。

## 常见误区

### 误区：换模型要改 agent loop

**你以为**：模型是主循环的一部分，换模型得动循环代码。

**实际上**：loop 只依赖 `ctx.llm` 这个 seam，具体是哪个适配器由配置决定。换模型是"换提供方"，不是"改循环"。

**所以**：任何时候要换模型，先找 `agent-default-model` 的配置和 `ctx.llm.registerAdapter`，别找 loop。

### 误区：适配器只要"能发出请求"就行

**你以为**：请求发出去、拿到文本，就算接好了。

**实际上**：必须严格遵守 `StreamChunk` 协议（start/end 配对、usage 在 finish 前、finish 最后），否则上层的历史、工具调用、计费都会错乱。还要正确处理取消（`options.signal`）和错误（带 code 的 `LlmError`）。

**所以**：适配器的难点不在"发请求"，在"把流式协议和错误语义翻译对"。照着仓库里两个现成适配器抄结构最稳。
