## 这条线讲什么

DSH（DeepSeek Harness）是一个**造 Agent 的底盘**：它自己不是一个写死的 Agent，而是把模型、工具、对话、系统提示词这些能力拆成一个个插件，再由一份配置把它们组装成一个能用的应用。

这条线不教你"怎么用 DSH"，也不教你"怎么写业务代码"。它只拆一件事：**为什么它能像搭积木一样，换掉模型、加一个工具、改一段提示词，而不用动其它任何一块代码？**

答案落在一个很小的插件框架上——**Cordis**。DSH 把它以 vendor 方式带在底层，所有能力（包括你会直接用到的大模型适配器、工具注册表、Agent 循环）都只是挂在这个框架上的插件。

## 一条主线

十七关其实在讲同一件事：**DSH 把"能力"和"装配"彻底分开了。**

- 插件只对自己负责：声明我要提供什么、我依赖什么、我监听了什么。
- 配置只对组合负责：这份应用装哪几个插件、每个插件给什么参数。

所以"换一个模型"不是改代码，而是改一行配置；"加一个工具"不是改主流程，而是多挂一个插件。理解了这条分工线，你再看 DSH 的任何一个子系统，都只是在问同一个问题：**它是靠哪个服务、哪个事件、哪个配置项接进来的？**

## 学完能得到什么

- 看到一个 DSH 插件，能说出它属于哪种形态、提供了什么、依赖了什么。
- 遇到"这个插件怎么没生效"，知道先去看它是不是卡在 PENDING、配置是不是没通过校验。
- 能判断一个能力该做成"服务"还是"事件"，以及拦截别人时该不该调用 `next()`。
- 能说清一次对话在 DSH 里是怎么变成一串 turn/step、模型与工具是怎么接上的。
- 知道改一个行为该挂到哪张表的哪一行，而不是一上来就想去改主循环。
- 能动手做几件真实的事：换个模型（改配置或写适配器）、写个子智能体委派、给对话加张自定义卡片。
- 对"插件化"这件事有手感：不是多抽象，而是把边界切在能替换的地方。

## 前置

- 会读一点 TypeScript（能看懂 `export function`、`class`、`interface` 就够）。
- 对"依赖注入""中间件"这类词有模糊印象更好，但没有也能读——第 2、4、7 关会用大白话补上。

## 不需要什么

- 不需要读完 Cordis 或 DSH 的全部源码。十七关挑的都是机制主干，代码片段是为了说明，不是为了逐行对着看。
- 不需要装环境、不需要跑起来。这条线是"读懂"，想真跑请按官方教程搭最小工程。

## 和「智能体」那条线的关系

「智能体」那条线讲的是**通用的 Agent 该怎么想**：下一步由谁决定、上下文怎么放、为什么要评测。

这条线讲的是**一个具体的 Agent 底盘是怎么搭起来的**：DSH 用什么机制把那些能力装到一起。两条线不重叠——一条教判断，一条拆实现。
