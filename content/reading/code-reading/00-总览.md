## 这条线是干什么的

会写自己的代码，和能读懂别人写好的代码，是两件事。这条线给的是**这个仓库自己的真实代码**，一条请求从 URL 到数据库的三层，每层只看十几行。

三关分别是：

1. **请求怎么落到方法上**：路由、路径变量，以及读路径为什么不强制登录；
2. **找不到就 404**：「不存在」与「是草稿」为什么故意回同一句话；
3. **过滤写在 SQL 里**：可见性判断为什么不该挪到 Java 代码里。

代码固定在提交 `93989e0` 上，点走读块里的链接能直接对到 GitHub 的原文与行号。**不用开沙箱**——这三关考的是读，不是跑。

## 常见误区

### 误区：读代码就是看懂语法

**你以为**：每行都认识，就算读懂了。
**其实**：读懂是能回答「为什么这么写、换个写法会怎样」。这三关每关都埋了一个"看似可以简化"的地方，简化了就出问题。
**怎么验证**：读完一关，试着回答「如果去掉这一行会怎样」，再看解释对不对。

### 误区：错误码越具体越好

**你以为**：找不到返回 404、没权限返回 403、是草稿返回 451，信息越全越好。
**其实**：区分「不存在」与「存在但你看不到」会给攻击者一个可枚举的探针——他能用状态码扫出哪些 id 真实存在。
**怎么验证**：拿一个不存在的 id 和一个未发布的 id，各请求一次，看返回是否完全一样。
