## 这一关在解决什么

前七关是分项，这一关是**一次上线前能照着做的检查**。它不能保证绝对安全，但能挡住绝大多数"上线后才发现"的低级问题。

用法：把清单贴进发布说明，逐项打勾或写明"不适用/有补偿措施"。

打个比方：上线检查单像飞机起飞前的检查表。老手也不会因为飞过一百次就跳过。真实机制是：多数事故不是不会做，而是当时漏做了一步；清单把“记得做”变成“必须回答”。

## 讲解

### 一、传输与域名

- [ ] 全站 HTTPS，HTTP 直接 301 到 HTTPS；
- [ ] 开 HSTS（`Strict-Transport-Security`），且确认没有仍需 HTTP 的子域；
- [ ] 证书链完整、未过期，域名与证书匹配；
- [ ] 管理端、接口、静态资源在同一套 HTTPS 策略下，没有"只保护首页"的漏洞。

### 二、安全响应头

```text
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Content-Security-Policy: default-src 'self'; object-src 'none'; base-uri 'self'
X-Frame-Options: DENY            （或 CSP 的 frame-ancestors 'none'）
```

- `nosniff` 防止浏览器把上传的文本当脚本执行；
- `Referrer-Policy` 避免 URL 里的敏感参数通过 Referer 泄漏到外站；
- `frame-ancestors` 防点击劫持；
- CSP 先观察（Report-Only）再强制，避免直接打断线上。

### 三、输入与输出

- [ ] 所有 SQL 用参数化；`ORDER BY`/表名走白名单；
- [ ] 所有用户内容输出按上下文转义；富文本走白名单净化；
- [ ] 上传限制类型、大小、文件名由服务端生成；
- [ ] 回调/跳转类参数做白名单，避免开放重定向。

### 四、认证与授权

- [ ] 登录、注册、重置、验证码接口有限流；
- [ ] 所有按 id 访问的接口校验归属（`WHERE user_id = current`）；
- [ ] 管理接口在服务端校验角色，不依赖前端隐藏；
- [ ] 401 与 403 语义正确；
- [ ] 登出/改密后旧会话或令牌失效。

### 五、密钥与配置

- [ ] 仓库、前端产物、日志里没有真实密钥；
- [ ] 生产密钥只从环境变量/密钥服务注入；
- [ ] `/actuator/env`、`/debug`、Swagger、目录列表未暴露公网；
- [ ] 错误页不返回堆栈与 SQL；
- [ ] 数据库账号最小权限，备份可恢复且加密。

### 六、可观测与响应

- [ ] 关键操作有审计日志（谁、何时、对哪条数据做了什么）；
- [ ] 登录失败、权限拒绝、异常高频请求有告警；
- [ ] 日志脱敏（手机号、邮箱、令牌）；
- [ ] 有安全事件联系人/流程，知道泄漏后先轮换。

### 七、依赖与构建

- [ ] 锁文件已提交，CI 用 frozen 安装；
- [ ] 高危依赖漏洞已修或有补偿措施；
- [ ] CI 令牌最小权限，第三方 action 固定到 commit；
- [ ] 有 SBOM 或依赖清单，出事后能定位影响范围。

### 上线后的第一小时

- [ ] 走一遍主流程（登录、核心写操作、退出）；
- [ ] 看错误率、401/403 比例、5xx；
- [ ] 用低权限账号试一次管理接口（应 403）；
- [ ] 确认日志里没有新出现的敏感字段。

## 常见误区

### 误区：检查单是形式主义

**你以为**：每次上线都填，没人看。
**其实**：它最值钱的地方是**把"记得做"变成"必须回答"**。漏配一个头、漏一个归属校验，通常不是不知道，而是当时没想到。
**怎么验证**：翻一次历史事故，看如果当时有这张单，哪一项能挡住。

### 误区：CSP 全站一把开最安全

**你以为**：直接 `default-src 'none'` 最稳。
**其实**：会把页面自己的脚本、样式、图片全挡掉，最后只能加 `unsafe-inline`，等于没开。应该先 Report-Only 收集，再逐步收紧。
**怎么验证**：上线前用 Report-Only 跑一周，看报告里有哪些被拦的资源。

### 误区：安全头配了就不用管业务校验

**你以为**：头都齐了，接口可以随便写。
**其实**：安全头防的是浏览器侧的一类攻击（XSS、点击劫持、降级），越权、注入、密钥泄漏完全不在它的覆盖范围。
**怎么验证**：拿低权限令牌调一个管理接口，看是否被业务层拦住。
