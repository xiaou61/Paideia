## 这一关在解决什么

泄漏密钥不需要被攻击——**提交一次、打一次日志、打进一次前端产物**就够了。而且密钥一旦进了公开仓库或日志系统，删文件也不等于处理完，只能轮换。

这一关讲三件事：密钥放哪、日志里该脱什么、泄漏之后怎么办。

## 讲解

### 前端没有秘密

```js
const key = import.meta.env.VITE_API_KEY
```

构建时这行会变成 `const key = "sk-..."`，任何人打开 DevTools 都能看到。**打包、混淆、加密 JS 都不能解决**——浏览器必须能读到它才能用。

规则：

- 前端只能持有**公开**信息（公开的 client id、公钥、统计站点 id）；
- 需要保密的调用一律走自己的后端，由后端持有密钥；
- 第三方密钥如果要"前端直连"，必须用它们的**公开可嵌入**模式（如地图的 referer 限制 key），并配置来源限制。

### 密钥放哪

| 方式 | 适用 | 注意 |
| --- | --- | --- |
| 环境变量 | 容器/进程注入 | 不要 `echo` 到构建日志；`ps` 可见的话要小心 |
| 密钥管理服务 | 生产（Vault/KMS/云 Secrets） | 启动时拉取，内存持有 |
| 本地未跟踪文件 | 开发（`.env.local`） | 加进 `.gitignore`，仓库只放 `.env.example` |
| 配置文件明文 | 不推荐 | 一旦进仓库就永久泄漏 |

**判断标准：这个文件会不会被 `git add` 到公开仓库？** 会，就绝不能放真实值。

### 配置错误也会泄漏

- `/actuator/env`、`/debug`、`/swagger` 暴露在公网；
- 错误页把堆栈、SQL、连接串返回给前端；
- 目录列表打开，`.git/`、`.env` 可下载；
- 备份文件 `app.yml.bak` 放在 web 根目录。

上线前把这些路径全部扫一遍，比读代码更快发现问题。

### 日志：既能查问题，也能泄密

```java
log.info("user login: {} / {}", username, password);          // 明文密码
log.info("request: {}", objectMapper.writeValueAsString(body)); // 可能含令牌、身份证
log.info("headers: {}", headers);                              // Authorization
```

三条纪律：

1. **不记录凭据**：密码、令牌、Cookie、验证码，一个都不进日志；
2. **脱敏后再记**：手机号 `138****1234`、邮箱 `a***@x.com`、身份证只留后四位；
3. **防日志注入**：用户输入里的换行会把一条日志拆成两条（伪造日志），记录前把 `\r\n` 转义。

结构化日志里用固定字段，不要拼接整段请求体：

```json
{"event":"login_failed","userId":42,"ip":"1.2.3.4","reason":"bad_password"}
```

### 泄漏之后：轮换，不是删除

如果密钥已经进了 Git 历史、日志、截图或第三方系统：

1. **立即在服务端轮换**（旧密钥失效）；
2. 检查使用记录，确认有没有被滥用；
3. 清理历史只是补救，不能替代轮换——历史、fork、缓存都可能还留着；
4. 复盘为什么会进，补上检查（pre-commit 扫描、Secret Scanning）。

### 最小权限

- 数据库账号只给需要的库与表权限，应用账号不要 `DROP`；
- 云 AK 按用途拆分，能只读就别给写；
- 第三方 token 只申请需要的 scope；
- 长期凭据能换短期就换短期。

一条凭据的爆炸半径，取决于它被授予了多少权限。

## 常见误区

### 误区：把密钥写进前端再加密就安全了

**你以为**：加密后浏览器能解，别人解不了。
**其实**：解密逻辑也在前端，任何人可以照做。加密只是增加了一点阅读成本。
**怎么验证**：在 DevTools 里下断点，看运行时变量里的明文。

### 误区：日志只有内部能看，不用脱敏

**你以为**：日志在服务器上，外人也看不到。
**其实**：日志会进集中平台、被导出、被截图、被第三方运维读取；一次误配就可能公开。
**怎么验证**：搜日志里的 `password`、`token`、`Authorization`，看有没有命中。

### 误区：从仓库删掉密钥就处理完了

**你以为**：`git rm` 之后就没了。
**其实**：历史、fork、CI 缓存、别人的本地克隆都还留着。唯一可靠的处理是**轮换**。
**怎么验证**：在 GitHub 搜一次旧密钥的前缀（只搜前缀，不要贴完整值）。

## 带走一句

**前端没有秘密、日志不记凭据、泄漏先轮换**——密钥安全的关键是"假设它一定会泄漏，然后限制影响"。
