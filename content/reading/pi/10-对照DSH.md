## 现在的坑

九讲读完，你大概能画出 pi 的循环、事件、工具、扩展、provider 和 TUI。但真正会困扰你的问题还没回答：

**下次要造一个 agent，我该从 pi 抄，还是从 DSH 抄？**

这不是"哪个更好"的问题。pi 和 DSH 解决的是同一件事的两个不同阶段：一个帮你**写一个 agent**，一个帮你**造一个能装配很多 agent 能力的平台**。分不清这两件事，你会抄错层。

## 一页地图

| 维度 | pi | DSH |
| --- | --- | --- |
| 定位 | 最小 agent harness（库 + CLI） | 造 Agent 的平台底盘 |
| 内核 | `agent-loop.ts` 的一千行循环 + `pi-ai` | Cordis 插件内核 + 各类能力插件 |
| 装配方式 | 代码：`new Agent()`、扩展模块 | 配置：`cordis.yml` + patch，可热更新 |
| 扩展单位 | 扩展（事件 / 工具 / 命令 / UI）+ npm 包 | 插件（提供能力）+ 服务 + seam |
| 生命周期 | 有 `agent_start` / `agent_settled`，无撤销式注册 | 每个注册都是可撤销的 effect |
| 权限 | **无内置**，靠 gate + 容器 | 沙箱与权限**内建** |
| 子智能体 | **不内置**，示例里用扩展实现 | **内建**（子智能体与多智能体） |
| 持久化 | `pi-durable`（会话 / 任务 / 文档） | 一切状态从会话日志派生 |
| 界面 | TUI 差分渲染 | 插件化的 UI 卡 |

这张表里最值得盯的是**"无内置"那两行**。pi 的 README 第 19 行写得很直白：它 skips "features like sub-agents and plan mode"；第 90 行写着没有权限系统。这不是没做完——**是它把这三件事留给了你**：沙箱外置、子智能体做成扩展、计划模式做成扩展（官方示例里就有 `plan-mode/`）。

DSH 的选择相反：权限、子智能体、日志派生，全部内建，代价是你必须接受它的插件模型和配置方式。

## 三个判据

**一、你要交付的是"一个东西"还是"一个底盘"。**
只交付一个 agent（哪怕要给团队用），pi 的"代码即配置"更省事：没有 yml、没有 patch、没有热更新，出问题看堆栈就行。要让别人在你不改代码的前提下装配出新形态，DSH 的插件 + 配置才是对的层。

**二、权限是不是产品需求。**
如果只是"防手滑"，pi + 30 行 gate + 容器足够（第 08 讲）。如果是多租户、要给别人跑不可信代码、要审计"谁在什么时候动了什么"，那权限必须是内核的一部分——这时候 pi 的留白会变成你的工作量。

**三、谁能改它。**
只有你和你的团队改 → pi。有外部贡献者、有多个下游产品、需要热更新 → DSH。热更新不是性能优化，是**协作模式**：谁能改配置，谁就能改行为。

## 该抄什么

**从 pi 抄四个具体的东西**（都能直接落到你的代码里）：

- **事件契约**：`agent_start / turn_start / tool_execution_* / turn_end / agent_end / agent_settled` 这套顺序语义，比"回调 + 状态机"清楚得多。
- **`convertToLlm` 的闸门**：会话层可以宽，模型层必须窄；这道转换是唯一出口。
- **"并发执行、串行叙述"**：执行可以乱序，落盘必须按源序——否则模型下一轮推理会被自己的工具结果搞乱。
- **整批 `terminate`**：提前结束要看整批，不能一个工具说了算。

**从 DSH 抄三个**（这是 pi 没有的）：

- **可撤销的注册**：每个注册返回 disposer，热更新与测试都好做。
- **seam 的三角色**：一个能力拆成"定义 / 实现 / 使用"，换实现不动调用方。
- **日志派生状态**：会话是事实，状态是投影，重放能重建。

## 和真实现的差异

- **pi 的"不做"是有意识的减法，不是遗漏。** 它连权限系统的替代品都没给（只有一句"containerize it"），因为它假设你会用容器。DSH 把沙箱做进内核，因为它假设你会跑别人的代码。
- **两条线的"扩展"不是一回事。** pi 的扩展是**代码模块**（TypeScript 文件，能注册工具、拦事件、画界面）；DSH 的插件是**配置里的一个条目**（提供能力、依赖服务、可被 patch）。前者灵活，后者可运维。
- **版本提醒**：pi 的扩展 API 在 `v1.5.0` 之后仍在变（第 01 讲提过，`extensions/types.ts` 到 main 已改三十多行）；DSH 侧的结构以本站十七讲为准，那批内容也需要按 DSH 的实际版本复核后再引用具体行号。

## 小结

pi 是"把循环写干净"的答案，DSH 是"把能力装起来"的答案。抄 pi 抄**契约与顺序**，抄 DSH 抄**边界与装配**；两者都抄，你得到的是一个内核干净、边界清楚、还能被配置驱动的 agent 平台。
