## 现在的坑

读源码时你会撞见两个"消息"类型：`AgentMessage` 和 `Message`。第一反应通常是"多此一举"——为什么不直接用一个数组，发给模型就完了？

等你写扩展时会发现不对劲：你想加一种"通知"消息给界面看，它不该进上下文；你想在压缩后重建历史，又得保证模型看到的和会话里存的一样。**这两件事用同一套消息就做不到。**

pi 的答案是分成两层：**会话层可以很宽，模型层必须很窄**。中间那道闸叫 `convertToLlm`。

对应的类型和位置：

- `AgentMessage = Message | CustomAgentMessages[keyof CustomAgentMessages]`（`packages/agent/src/types.ts:374`），自定义消息靠**声明合并**加进去（`:358-365`）。
- `transformContext?: (messages, signal) => Promise<AgentMessage[]>`（`:244`），可选。
- `convertToLlm: (messages) => Message[] | Promise<Message[]>`（`:222`），**必填**。
- 两者在每轮请求前依次执行：`agent-loop.ts:399`（transform）→ `:404`（convert）→ `:406`（normalize）→ `:412`（发请求）。

为什么 `convertToLlm` 必填、`transformContext` 可选？因为**不转换就一定错**，不剪枝只是可能超长。前者是正确性问题，后者是体验问题。

## 一个具体例子：工具清单也住在系统消息里

这是 pi 最反直觉的一处设计。

你大概以为"模型知道有哪些工具"是请求参数里带了一份 schema。pi 不是：**工具清单写在 transcript 的第一条 system 消息里**，`agent.ts:86` 用 `createInitialSystemMessage` 建首条消息时就把工具声明拼了进去（`packages/ai/src/utils/transcript.ts:10`）。

那运行中换工具怎么办？`declareToolChanges`（`agent-loop.ts:342`）会在每次请求前比较"对话里声明的工具"和"当前能执行的工具"，差量写进一条新的 system 消息：

```ts
// 大意：把 toolsAdded / toolsRemoved 记进 system 消息
const update = withToolChanges({ role: "system", content: "", timestamp: Date.now() }, changes)
```

所以对模型来说，**换工具不是换参数，是"系统提示词变了"**。这解释了两件事：为什么扩展能在会话中途注册工具，模型下一轮就知道；以及为什么工具描述写得含糊会直接影响模型选不选它——它和提示词是同一层东西。

## 和真实现的差异

- **`convertToLlm` 每轮只调一次。** 源码注释写得很直白（`agent-loop.ts:77-78`）：它没法在这里校验"每条自定义消息都被转换了"，只能假设你的 `convertToLlm` 覆盖了所有类型。漏掉的类型会在 provider 那里报错，而不是在 pi 里报错。
- **系统消息是只读的回放。** `agent.state.systemPrompt` 不是可变字段，它每次从 transcript 头部重放（`getCurrentSystemMessage`，`transcript.ts:73`）。想改提示词，就追加一条 system 消息——`sections` 还能替换其中某一段（skills 就是这么做的）。
- **`message_*` 事件覆盖所有消息，不只是助手的。** 用户消息、工具结果、自定义消息都会发 `message_start` / `message_end`；只有助手消息会有 `message_update`（流式增量，`types.ts:538`）。第 01 讲没订这三个，是因为它们太吵——但做 UI 时必须用。
- **UI 消息不是"不发给模型的空壳"。** 它默认也不会被发出去，但前提是你的 `convertToLlm` 把它过滤掉。不写过滤，它就真的会进请求。

## 小结

两层消息的分工是：`AgentMessage` 负责"会话里发生过什么"（可以很宽），`Message` 负责"模型这次要看什么"（必须很窄），`convertToLlm` 是唯一的闸门。

如果重来一次，我会先写一个自定义消息类型 + 三行 `convertToLlm`，跑一次，看它被过滤掉——比读十遍类型定义更快理解"为什么要两层"。
