## 这条线讲什么

pi 是 [earendil-works/pi](https://github.com/earendil-works/pi)（原来的 `badlogic/pi-mono`，MIT）。它自称 **minimal, extensible agent harness**——不是一个开箱即用的产品，而是一套让你自己拼出 agent 的零件：

| 包 | 管什么 |
| --- | --- |
| `pi-agent-core` | agent 循环、工具调用、事件流 |
| `pi-ai` | 多 provider 的统一 LLM 接口 |
| `pi-coding-agent` | 命令行、扩展、技能、会话 |
| `pi-tui` | 终端界面（差分渲染） |
| `pi-durable` | 会话与任务持久化 |
| `chord` / `pi-telemetry` | 进程内对象运行时 / 遥测契约 |

这条线只拆一件事：**一个 agent 从"收到一句话"到"把活干完"，中间到底发生了什么。** 不教 prompt 怎么写，也不教 RAG 怎么搭。

它和我们已经写过的「从0带你了解 DSH 核心」是互补的：DSH 那 18 讲读的是「一个产品怎么用插件把几十种能力装起来」，这条线读的是「一个循环怎么写得干净、边界怎么切」。两条线对照着看，你会更清楚哪些东西该进内核、哪些该留给扩展。

## 读之前先对版本

> 本线十讲对应 **pi v1.5.0**，commit `f9a2636`（2026-11-09 核对）。下文所有文件路径与行号都以这个 tag 为准。

开源项目的源码解析，最怕的不是讲错道理，是**版本对不上**：`main` 每天都在动，你照着一周前的文章去翻第 495 行，翻到的是别的东西，然后开始怀疑自己。所以这条线把版本钉死，并且给你三条核对路径：

- **装同版本**：`npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.5.0`（需要 Node 22.19+）
- **对源码**：`git clone https://github.com/earendil-works/pi.git && git checkout f9a2636`
- **查单点**：把文中路径贴到 GitHub 上，在 `v1.5.0` 这个 tag 下看

如果你装的是最新版，发现行号偏了——**先怀疑版本，不要怀疑自己**。凡是 `v1.5.0` 到 `main` 已经有差异的地方，文中会单独标出来。

## 十讲路线

- **01** 把黑盒打开：一次 prompt 的事件序列
- **02** 一页地图：七个包各管什么
- **03** agentLoop：一次请求怎么变成一个 turn
- **04** 消息分层：`AgentMessage` 与 `convertToLlm`
- **05** 工具执行：并行、顺序与 `terminate`
- **06** steering 与 follow-up：两条队列
- **07** pi-ai：多 provider 的真难题
- **08** 写一个 30 行的 permission gate
- **09** TUI 差分渲染：终端为什么能画界面
- **10** 对照 DSH：两种 harness 的边界选择

## 三种走法

- **只读**：按顺序看，每讲 15–20 分钟，不敲代码也能跟上。
- **跟着写**：每讲都有一个能在本机跑起来的最小例子（只要 Node，不要 API Key 也能跑到"发请求"那一步）。
- **改造**：看完 05 讲的执行顺序和 08 讲的 gate，把 gate 换成你自己的规则，再回头看 05——这是理解"扩展点在哪"最快的路。

## 这条线不教你什么

- 不教你怎么写 prompt、怎么搭 RAG、怎么评测模型输出。
- 不追 `main` 的新特性；想看最新代码，先回到 01 讲把版本对齐。
- 不替你选 harness。看完第 10 讲，你应该能自己说出 pi 和 DSH 各自适合什么。
