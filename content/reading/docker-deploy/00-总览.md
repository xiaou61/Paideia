## 这条线是什么

四道**动手改文件**的部署题：给你一个应用目录，你写出或修好 `Dockerfile` / `docker-compose.yml`，判定脚本检查**结构与关键指令**。

**重要前提**：本平台的判题容器里没有 Docker（`command -v docker` 为空），所以判定**不做真实构建与启动**，只检查：

- 阶段数量与命名、构建产物是否从 builder 阶段复制；
- 基础镜像是否固定、运行用户是否非 root；
- 是否有健康检查、端口声明；
- 清理与安装是否合并、是否有不该出现的指令；
- Compose 里服务、依赖条件、卷与健康检查是否齐全。

这意味着它验证的是"你知不知道一个能上线的 Dockerfile 该长什么样"，不验证"这个镜像真的能跑"。真机构建请在自己的 Docker 环境里做。

## 怎么交

每题给一段可编辑的 shell 脚本（通常是 `cat > Dockerfile <<'EOF' ... EOF` 模板或 `sed` 提示），你改它、点运行，判定会在同一容器里检查生成的文件。

## 四关在练什么

1. **多阶段 Dockerfile**：builder 用 Maven、运行用 JRE、产物 `COPY --from`、非 root、健康检查；
2. **修安全问题**：`latest`、明文密钥、root 用户、`apt-get upgrade`——四处各修一次；
3. **镜像瘦身**：合并 `RUN`、`--no-install-recommends`、清理 apt 缓存；
4. **Compose 编排**：app + MySQL、`service_healthy` 依赖、数据卷、健康检查。
