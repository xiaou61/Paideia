## 这一关在解决什么

拿到一张表后，下一步几乎总是"只看某个子集"和"加一列算出来的值"。这一关讲三件事：

- 多条件筛选为什么必须加括号；
- 为什么赋值经常"没生效"或"改到了原表"；
- 逐行循环为什么该改成向量化。

打个比方：整列运算像流水线一次冲压，逐行循环是拿锤子一个个敲。真实机制是：向量化把计算交给底层 C 循环，快且不受索引影响。

## 讲解

### 布尔索引：每个条件都要括号

```python
result = df[(df['status'] == 'paid') & (df['amount'] > 100)]
```

`&` 的优先级比 `==` 高，不写括号会先算 `'paid' & df['amount']`，直接报错或得到意外结果。`|`、`~` 同理：

```python
df[(df['city'] == '北京') | (df['city'] == '上海')]
df[~(df['status'] == 'cancelled')]
```

`and`/`or` 不能用在这里——它们是对单个布尔值做运算，而列是整列布尔序列。

更可读的写法是 `isin` / `between` / `query`：

```python
df[df['city'].isin(['北京', '上海'])]
df[df['amount'].between(100, 1000, inclusive='left')]
df.query("status == 'paid' and amount > 100")
```

`query` 里可以用 `@变量` 引用 Python 变量，适合条件长的场景。

### 派生列：一次算整列

```python
df['amount_yuan'] = df['amount_cent'] / 100
df['is_large'] = df['amount'] > 1000
df['discount'] = (df['origin_price'] - df['pay_price']) / df['origin_price']
```

这就是向量化：表达式作用在整列上，pandas 内部用 C 循环。**不要写 `for` 逐行加值**：

```python
# 慢，而且容易在索引上出错
for i in range(len(df)):
    df.loc[i, 'amount_yuan'] = df.loc[i, 'amount_cent'] / 100

# 快，且与索引无关
df['amount_yuan'] = df['amount_cent'] / 100
```

数据量到十万行以上，逐行写法通常慢两个数量级。

### 条件分支：`np.where` 与 `np.select`

```python
import numpy as np

df['level'] = np.where(df['amount'] >= 1000, '大单', '普通单')

conditions = [df['amount'] >= 1000, df['amount'] >= 100]
df['level'] = np.select(conditions, ['大单', '中单'], default='小单')
```

`np.select` 按顺序匹配，第一个命中的生效——顺序错了，后面的规则永远进不去。

### 赋值没生效？看 `.loc` 与链式索引

```python
# 可能没有改到原表（链式索引）
df[df['city'] == '北京']['level'] = '一线'

# 明确改原表
df.loc[df['city'] == '北京', 'level'] = '一线'
```

链式索引先 `df[...]` 得到一个中间对象，再对它赋值。pandas 无法保证这个中间对象是视图还是副本。结果就是"有时生效、有时不生效"，还常伴随 `SettingWithCopyWarning`。

规则很简单：**要修改，就用 `.loc[行条件, 列名]` 一次写完**。

### 字符串与日期也是列

```python
df['email_domain'] = df['email'].str.split('@').str[-1]
df['city'] = df['city'].str.strip().str.replace('市', '', regex=False)
df['month'] = df['created_at'].dt.to_period('M')
df['weekday'] = df['created_at'].dt.dayofweek
```

`.str` 与 `.dt` 是整列操作；遇到 `NaN` 时它们默认返回 `NaN`，不会中断。做完记得数一下空值有没有变多：

```python
df[['city', 'email_domain']].isna().sum()
```

### 分箱：把连续值变分类

```python
bins = [0, 100, 500, 1000, float('inf')]
labels = ['0-100', '100-500', '500-1000', '1000+']
df['bucket'] = pd.cut(df['amount'], bins=bins, labels=labels, right=False)
```

`right=False` 表示左闭右开，避免 100 同时落进两个桶。分箱边界要按业务含义定，不要默认等宽——等宽分箱经常让 90% 的样本挤在第一个桶里。

## 常见误区

### 误区：多条件筛选不加括号也能跑

**你以为**：`df[df.a == 1 & df.b == 2]` 只是写法问题。
**其实**：位运算符优先级导致表达式先结合成 `1 & df.b`，轻则报错，重则静默得到错误子集。
**怎么验证**：加括号前后各数一次行数；不一样就说明之前算错了。

### 误区：`df[condition]['col'] = x` 是标准写法

**你以为**：先筛再赋值，很直观。
**其实**：这是链式索引，作用在临时对象上，原表可能不变。pandas 未来版本会明确禁止这种写法。
**怎么验证**：赋值后打印原表对应行，看是否真的变了。

### 误区：逐行循环更"可控"

**你以为**：一行一行处理，逻辑清楚、不会错。
**其实**：慢只是其一；更大的问题是索引——`df.loc[i]` 里的 `i` 是标签不是位置，经过筛选或排序后很容易错位。
**怎么验证**：对比向量化与循环的耗时（`%timeit`），十万行通常差 100 倍以上。
