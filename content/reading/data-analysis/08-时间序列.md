## 这一关在解决什么

时间是最容易"看起来没问题"的维度：按天聚合、画条折线、算个环比，数字都出得来。但下面三件事只要有一样没处理，结论就会系统性偏：

- **粒度**：按自然日还是滚动 24 小时；
- **时区**：跨零点的记录算哪一天；
- **不完整周期**：今天才过到一半，和上周同一天比当然低。

## 讲解

### 粒度：先定"一天"从哪开始

```python
df['date'] = df['created_at'].dt.date                    # 自然日（按 UTC）
df['date_bj'] = df['created_at'].dt.tz_convert('Asia/Shanghai').dt.date
```

同一笔 UTC `2026-11-03 16:30` 的记录：

- 按 UTC 是 11 月 3 日；
- 按北京时间是 11 月 4 日 00:30，属于 4 日。

如果数据源是 UTC、报表按北京时间看，不转时区就会让"每天 0–8 点的数据"整体错位一天。**先确定业务口径用哪个时区，再统一转换，不要在查询、聚合、展示三处各转一次。**

### 重采样：把细粒度汇总到粗粒度

```python
ts = df.set_index('created_at')['amount'].resample('D').sum()
ts_week = df.set_index('created_at')['amount'].resample('W-MON').sum()
```

`resample` 要求索引是时间类型。`'D'` 是自然日，`'W-MON'` 是"到周一为一周"——周的定义也要写清楚，否则"周环比"两边不是同一个窗口。

**重采样只会聚合，不会补空**：

```python
ts.asfreq('D', fill_value=0)   # 没有数据的日期补 0
```

不补 0 的话，折线图会把两个有数据的日子直接连起来，看起来"一直很平稳"，实际中间断了好几天。

### 滚动窗口：平滑而不是对齐日历

```python
ts.rolling(7).mean()            # 最近 7 天均值（含当天）
ts.rolling('7D').sum()          # 按时间跨度，不按行数
```

`rolling(7)` 按**行数**算，缺天时会跨过空缺；`rolling('7D')` 按**时间**算，更符合"最近七天"的直觉。

7 日滚动均值适合看趋势，但它有滞后：真正的拐点会在几天后才显现。**做异常检测时不要把平滑后的曲线当成实时值。**

### 同比与环比：先对齐周期

```python
daily = df.set_index('created_at')['amount'].resample('D').sum()
daily['wow'] = daily / daily.shift(7) - 1
```

`shift(7)` 是"七天前同一位置"。如果中间缺天，位置会错位——所以要先 `asfreq('D', fill_value=0)` 把日期补全，再 shift。

更稳的写法是按日期对齐：

```python
daily = daily.asfreq('D', fill_value=0)
daily['last_week'] = daily.shift(7, freq='D')
```

### 不完整周期：必须截断

"今天"通常只过了一半。把今天和上周同一天的全天数据比，必然偏低。

两种处理：

1. 比较时**截到同一时刻**（今天到 12:00，上周同日也只取到 12:00）；
2. **排除当天**，用完整日做趋势，当天只做实时监控。

同理，月初、季初的"环比"都要检查两个周期长度是否一致——2 月比 1 月少 3 天，直接比总量会得出错误结论。**比日均或比同长度窗口**。

### 分群看时间：留存与 cohort

"整体留存没变"可能掩盖两个相反的趋势。按注册周分组（cohort），看每一批用户在第 N 天的留存：

```python
cohort = df.groupby(['signup_week', 'day_n'])['user_id'].nunique().unstack()
```

这样能看出"新用户越来越差，但老用户补上了"这类结构变化。整体指标是平均，平均会骗人。

## 常见误区

### 误区：按 `created_at` 直接 `dt.date` 就是业务日

**你以为**：日期取出来就是那天。
**其实**：数据库存 UTC 时，`dt.date` 得到的是 UTC 日期；对北京时间用户，0–8 点的记录会算到前一天。
**怎么验证**：取一条 UTC 16:30 的记录，转与不转时区各算一次所属日期。

### 误区：重采样没数据就是 0

**你以为**：`resample('D').sum()` 会把没数据的日期算 0。
**其实**：它只输出有数据的桶（或输出 NaN，取决于版本与参数），中间的空档会消失。
**怎么验证**：`ts.index` 是否连续；不连续就 `asfreq` 补。

### 误区：同比就是"去年同期"

**你以为**：`shift(365)` 就是同比。
**其实**：闰年、促销日错位（去年双十一在周三，今年在周四）、口径变更都会让"同期"失真。同比要同时看**日期对齐**与**业务事件对齐**。
**怎么验证**：把两个周期的日序列并排画出来，看峰谷是否对得上。
