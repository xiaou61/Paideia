## 这条线写给谁

写给**会用 Excel 或 SQL、但每次做分析都像在试**的人：

- 拿到一张表，先 `df.head()`，然后不知道下一步该干嘛；
- 算出来的数和运营对不上，双方都说自己是对的；
- 图很好看，但没人因为这张图改变决定；
- 被问「这个结论可靠吗」，只能回答「数据就是这样」。

## 为什么数据分析值得单独学

因为它的产出不是代码，是**决定**。同一份数据可以得出两个相反的结论，差别通常不在工具，而在三件事：**问题怎么定义、口径怎么定、边界在哪**。

工具（pandas、SQL、BI）都会过时，这三件事不会。这条线把工具当例子，重点放在"为什么这样算"和"算出来能说明什么"。

## 一个前提

需要 Python 与 pandas：

```text
python -c "import pandas; print(pandas.__version__)"
```

装不上也不影响读：每一关的 SQL 与结论部分不依赖 pandas。示例数据都在文内，可以直接复制到 Jupyter、`python -i` 或任何 Notebook 里跑。

## 常见误区

### 误区：分析就是算指标

**你以为**：把 DAU、留存、转化率算出来就是分析。
**其实**：指标是原料。分析要回答的是"**所以呢**"——这个数说明什么、和谁比、要不要改。没有比较对象与决定的指标，只是一串数字。
**怎么验证**：写完一个数，逼自己补一句"所以我们应该……"；补不出来，说明这个数还没有分析价值。

### 误区：数据不会骗人

**你以为**：只要口径一致，结论就是客观的。
**其实**：口径是人定的。统计"活跃用户"用登录、用打开、还是用产生行为，会得到三个不同的数，而且都"没错"。选择哪一种，取决于要回答的问题。
**怎么验证**：同一个指标问三个人"怎么算的"，答案不一致就说明口径没写下来。
