## 这一关在解决什么

分组聚合是分析里最常用的一步：按城市看销量、按渠道看转化、按用户看首单时间。它的模型只有一句话：

**split → apply → combine**（按某个键拆成若干组，每组算一个值，再拼回一张表）。

理解这句话，`groupby` 的绝大多数行为都能推出来；不理解，就会写出"总数对、分组加起来不对"的查询。

## 讲解

### 最小用法

```python
by_city = df.groupby('city')['amount'].sum()
```

拆开看：

1. **split**：按 `city` 的每个不同值，把行分成若干组；
2. **apply**：对每组取 `amount` 列，求和；
3. **combine**：把"组名 → 结果"拼成一个 Series。

多个指标用 `agg`：

```python
by_city = df.groupby('city').agg(
    orders=('order_id', 'count'),
    users=('user_id', 'nunique'),
    revenue=('amount', 'sum'),
    avg_amount=('amount', 'mean'),
)
```

这种"命名聚合"写法比 `agg(['sum', 'mean'])` 更好读，列名也直接是你要的名字。

### `count` 与 `size` 不是一回事

```python
df.groupby('city')['amount'].count()  # 非空值个数
df.groupby('city').size()             # 行数（含空值）
```

如果 `amount` 有缺失，`count` 会小于 `size`。用 `count` 当"订单数"时，缺金额的订单被悄悄排除，结果会比实际少。

**数订单用 `order_id` 的 `nunique` 或 `size`，不要用金额列的 `count`。**

### 分组键里有空值

默认 `groupby` 会**丢掉**键为 `NaN` 的行：

```python
df.groupby('city')['amount'].sum().sum()  # 可能小于 df['amount'].sum()
```

差的那部分就是 `city` 缺失的行。要保留就把空值当一类：

```python
df.groupby('city', dropna=False)['amount'].sum()
```

这是一个非常隐蔽的坑：分组结果看起来正常，但各组合计与总数对不上。

### 占比：分母是谁

"各渠道订单占比"至少有两种算法：

```python
by_channel = df.groupby('channel').size()
share = by_channel / by_channel.sum()        # 占全部订单
share_per_city = df.groupby(['city', 'channel']).size() / df.groupby('city').size()
```

第二种是"每个城市内部各渠道占比"，分母不再是全量。报告里写"占比"时必须说明分母，否则读者会按自己的理解算。

### `transform`：把组内统计值贴回原表

```python
df['city_avg'] = df.groupby('city')['amount'].transform('mean')
df['amount_vs_city'] = df['amount'] - df['city_avg']
```

`agg` 把数据压缩成"一组一行"，`transform` 保持原行数、把组内算出的值广播回每一行。做"与组均值比较""组内排名"时用它。

组内排名：

```python
df['rank_in_city'] = df.groupby('city')['amount'].rank(ascending=False, method='dense')
```

### 多键分组与结果形状

```python
df.groupby(['city', 'channel'])['amount'].sum()
```

结果是**多层索引**（MultiIndex）。做后续处理时通常要拉平：

```python
result = (df.groupby(['city', 'channel'], as_index=False)
            .agg(revenue=('amount', 'sum')))
```

`as_index=False` 让分组键变回普通列，后面 `merge`、`sort_values` 都省事。

### SQL 的同一件事

```sql
SELECT city,
       COUNT(DISTINCT order_id) AS orders,
       COUNT(DISTINCT user_id)  AS users,
       SUM(amount)              AS revenue
FROM orders
WHERE status = 'paid'
GROUP BY city;
```

两条纪律和 pandas 一样：

1. **`WHERE` 在分组前过滤，`HAVING` 在分组后过滤**——把"金额大于 100"写进 `HAVING` 会先聚合再筛，语义完全不同；
2. `COUNT(*)` 与 `COUNT(amount)` 不同，`COUNT(DISTINCT ...)` 才是去重计数。

## 常见误区

### 误区：分组求和加起来应该等于总和

**你以为**：各城市之和 = 全表之和。
**其实**：键为 `NULL` 的行默认不进任何组；`WHERE` 条件也可能在分组前过滤掉一部分。对不上时先查这两个。
**怎么验证**：`df['amount'].sum()` 与 `groupby(...).sum().sum()` 各算一次。

### 误区：`count()` 就是行数

**你以为**：`count` 数的是组里有几行。
**其实**：它数的是该列非空值的个数。金额缺失的订单不算，但订单本身是存在的。
**怎么验证**：`size()` 与 `count()` 对比，差值就是该列缺失的行数。

### 误区：占比只有一种算法

**你以为**：`value / total` 天经地义。
**其实**：分母可以是全量、可以是某个筛选后子集、也可以是"每个分组内部"。三种都合理，但含义不同。
**怎么验证**：在报告里把分母写成一句话；写不出来就说明还没定义清楚。
