## 这一关在解决什么

清洗是最容易被当成"体力活"的一步，但它决定了后面所有数字的上限。这一关不列函数清单，只讲三个判断：

- 缺失值该删、该补，还是该单独当一类？
- "重复"是按什么定义的重复？
- 异常值是错误，还是最有价值的样本？

打个比方：清洗像择菜，先分清是烂叶还是好叶。真实机制也一样：缺失看机制、重复看口径、异常看真假，每一步都要说得出理由。

## 讲解

### 缺失：先问为什么缺

同样是 `null`，背后原因决定处理方式：

| 缺失原因 | 例子 | 处理 |
| --- | --- | --- |
| 随机缺失 | 用户没填可选字段 | 删行或补众数，影响小 |
| 与某个群体相关 | 老年用户不爱填年龄 | 直接删会让样本偏年轻 |
| 缺失本身有含义 | 没提交过订单，所以 `first_order_at` 为空 | 不要补，应该单独算"未下单" |

第三种最常见也最容易被错补：把"没有订单"补成 0 元，会把"从未购买"和"买了 0 元"混成一类。

判断方法：**把缺失单独做一类，和整体比一比**。

```python
df['has_age'] = df['age'].notna()
df.groupby('has_age')['converted'].mean()
```

如果两组转化率明显不同，说明缺失不是随机的，删之前要三思。

删行之前还要看**删掉多少**：

```python
missing = df.isna().sum()
print((missing / len(df)).sort_values(ascending=False).head())
```

一列缺 60%，删行等于把大部分数据删了；这时候要么放弃这一列，要么把它当"有/无"来用。

### 重复：先定义"什么算同一条"

`df.duplicated()` 默认比较**所有列**。但业务上的重复往往是"同一个用户同一天下了两单相同的商品"，而不是整行一模一样。

```python
# 整行重复
df.duplicated().sum()

# 业务主键重复
df.duplicated(subset=['order_id']).sum()

# 业务组合重复（同用户同商品同时间）
df.duplicated(subset=['user_id', 'sku_id', 'created_at']).sum()
```

三种口径会给出三个不同的数。**先说清楚"重复"指哪一种，再决定删哪一条**。删除时保留哪条也有讲究：`keep='last'` 通常对应"最新状态"，`keep='first'` 对应"首次记录"。

### 异常值：先分成两类

看到 `amount = 9,999,999`，先别急着删。问三个问题：

1. **是录入/单位错误吗？**（分转元、多打了一个 0）
2. **是真实但极端的业务吗？**（企业客户、批发单）
3. **是测试/内部账号吗？**（`user_id = 1`）

三类处理方式完全不同：

- 第 1 类：修正或置空，并在报告里说明；
- 第 2 类：**保留**，但用中位数、分位数而不是均值做汇总，或者单独分组；
- 第 3 类：过滤掉，且口径里要写明"排除内部账号"。

一律删掉最大值，会让结论变成"我们的客户都很小"，这是最危险的清洗。

### 用分位数看，不用均值

```python
df['amount'].describe(percentiles=[.5, .9, .99, .999])
```

均值被极端值拉动，分位数不会。看 `P99` 与 `P999` 的差距，通常就能判断"长尾有多长"。

箱线图的 1.5 倍 IQR 规则可以当参考，但不要机械套用。它假设分布近似对称，而收入、订单额这类数据天然右偏。

### 清洗要留下痕迹

每一次修改都应该是**可追溯的**：

```python
df = raw.copy()
df['amount_fixed'] = df['amount'].where(df['amount'] < 1_000_000)
cleaning_log = {
    'rows_in': len(raw),
    'rows_dropped_missing_user': int(raw['user_id'].isna().sum()),
    'amount_over_1m': int((raw['amount'] >= 1_000_000).sum()),
}
```

报告里写清"从多少行到多少行、因为什么去掉的"。别人无法复现的清洗，等于没有清洗。

## 常见误区

### 误区：缺失值一律用均值/中位数补

**你以为**：补上就完整了。
**其实**：补值会**缩小方差**，让数据看起来比实际更集中；如果缺失与目标相关，补值还会引入偏差。补之前先确认缺失机制，能删就删，不能删就单独编码。
**怎么验证**：补值前后各算一次标准差与分组均值，看差异有多大。

### 误区：去重就是 `drop_duplicates()`

**你以为**：一行代码搞定。
**其实**：默认按整行去重，业务上的"重复提交"往往整行并不相同（时间差几秒、状态不同）。要用业务主键或组合键定义重复。
**怎么验证**：分别按整行、按 `order_id`、按组合键数一次重复量，看差多少。

### 误区：异常值就是脏数据

**你以为**：超出 3 倍标准差的都该删。
**其实**：真实业务的长尾往往就是价值所在（大客户、爆款）。删掉它们，等于把最重要的样本清理掉了。
**怎么验证**：把"异常"那几行单独拉出来看用户与商品，判断是错误还是真实极端。
