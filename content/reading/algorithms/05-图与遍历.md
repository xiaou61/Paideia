## 32×32 全是陆地时，递归 DFS 崩了

我在练手项目里画了一张 40×40 的地图（随机种子固定，1 是陆地、0 是水）。下面所有数字都出自这一张，以及它的几个放大版。先用最顺手的写法数连通块——递归 DFS：

```python
def dfs(r, c, seen, d):
    seen.add((r, c))
    for dr, dc in ((-1, 0), (0, 1), (1, 0), (0, -1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < 40 and 0 <= nc < 40 and (nr, nc) not in seen:
            dfs(nr, nc, seen, d + 1)
```

把地图换成一张同样 40×40、但全是陆地的，它直接崩：

```text
  File "map.py", line 6, in dfs
    dfs(nr, nc, seen, d + 1)
RecursionError: maximum recursion depth exceeded while calling a Python object
```

我原来的判断是「40×40 才 1600 个格子，递归能有多深」。量出来是这样：

```text
[1] 31x31 全陆地: ok 最深 961 层 访问 961/961 格
[1] 32x32 全陆地: RecursionError 最深 996 层 访问 996/1024 格
[1] 同一份 40x40 带水地图: 最深 262 层
```

三点。

**深度不是边长。** 32×32 的边长是 32，崩在第 996 层。深度等于这条路径上一共走过多少个格子——全陆地时 DFS 一路不回头，把走过的整条路都压在栈上。

**崩不崩跟格子总数关系不大。** 同样 40×40，带水那张 1002 格陆地，最深只有 262 层；全陆地那张 1600 格，跑到第 996 次递归就撞上 `sys.getrecursionlimit()`。上限是 1000（这台机器上的值），这里 996 就崩，是因为这个数算的是**所有** Python 帧，`dfs` 之外还有解释器自己的几层；所以能用的深度总是比上限少一点，具体少几层别当成常量。31×31 能走完，深度 961，恰好等于格子数 961，说明它真的把整张图铺满了。

**决定这条线的是最长链**，也就是这张图里最长的无重复路径。这个数不看点数，看形状：一条蛇形走廊比一块 40×40 的空地深得多。我项目里那张图只有一条 262 层的链，所以没崩——是运气，不是写法对。

## 换成显式栈，不崩了，但顺序变了

显式栈版本：

```python
seen, stack = {(0, 0)}, [(0, 0)]
while stack:
    r, c = stack.pop()
    for dr, dc in ((-1, 0), (0, 1), (1, 0), (0, -1)):
        nr, nc = r + dr, c + dc
        if 0 <= nr < 40 and 0 <= nc < 40 and (nr, nc) not in seen:
            seen.add((nr, nc))
            stack.append((nr, nc))
```

40×40 全陆地跑完，栈里最多同时压 780 个。注意这个数**小于**递归版的 996：两个「栈」装的不是同一种东西。递归栈装的是从起点到当前格子的整条路径；显式栈装的是「已经登记、还没展开」的边界。边界可以远小于最长路径。

```text
[2] 显式栈 10x10: 栈峰值 45 访问 100 格
[2] 显式栈 40x40: 栈峰值 780 访问 1600 格
```

代价是访问顺序会变。4×4 全陆地上，两种写法我各打了一遍（邻居顺序都是上、右、下、左）：

```text
[2] 4x4 递归   00 01 02 03 13 23 33 32 22 12 11 21 31 30 20 10
[2] 4x4 显式栈 00 10 20 30 31 32 33 23 13 12 02 03 22 21 11 01
```

递归版先往右走（01、02、03），显式栈版先往下走（10、20、30）。原因在那句 `stack.append` 上：邻居按上、右、下、左压进去，出栈是**反序**，于是实际展开顺序变成左、下、右、上，第一个有效邻居成了「下」。

顺便把上面两段代码摆在一起看：它们只差一个容器。一个 `seen`、一个容器、一个循环体，其余全一样——容器从哪一头取，就决定了是往深里钻还是往外铺。BFS 换成队列、从头取，就是这样；DFS 换成栈、从尾取，也是这样。差别只有取出顺序这一件事。

所以「把递归改成显式栈」不是等价变形。它们在「能不能走完」上等价，在「按什么顺序走」上不等价。如果你有东西依赖这个顺序——比对两份输出、按访问次序编号、给结果做稳定 diff——换写法会让它变，得连输出一起改。

## 同一个起点终点：BFS 97 步，DFS 175 步

回到那张带水的地图。按四邻接找连通块，它分成 34 块，最大一块 756 格，前 5 大是 756、152、21、11、10，另外有 15 块单格岛。

在最大那块上，从 (0, 3) 走到最远格 (39, 39)：

```text
[3] (0, 3) -> (39, 39): BFS 97 步
[3] 每层格数 [1, 1, 1, 1, 2, 2, 3, 1, 3, 2, 3, 2]
[3] 同一起终点: 递归 DFS 175 步 显式栈 DFS 121 步
```

三个读法：

1. BFS 的 97 就是最短步数，也等于层数——`dist[t]` 的定义就是「走过多少条边」。这里每条边算 1。
2. 递归 DFS 走 175 步到达，显式栈 DFS 走 121 步。三个数互不相同：DFS 保证「能到」，不保证「最短」，连两个 DFS 版本之间都不保证一样。
3. 「每层格数」那行是我原以为会单调增长的地方。实际是 1、1、1、1、2、2、3、1、3、2、3、2（前 12 层）——这张图是细长蛇形，一层常常只有一两格，这 12 层里最宽的一层也只有 3 格。BFS 的队列宽度取决于层的形状，不取决于图有多大：这张 40×40 的图上，队列一直是几个元素的事。

权重只要不是全 1，BFS 的「第一次到达即最短」就不成立。处理那套（优先级队列）不在这篇里。

## visited 写在哪一行：结果一样，代价差 4 倍

BFS 里最容易写错位置的就是 visited。把它放在出队之后，逻辑上仍然对：出队的点如果已经访问过就跳过。实测：

```text
[4] 40x40 入队标记 入队   1600 峰值   40 | 出队标记 入队   6241 峰值  158 | 都访问 1600/1600
[4] 240x240 入队标记 入队  57600 峰值  240 | 出队标记 入队 229441 峰值  958 | 都访问 57600/57600
```

两边访问的格子数一模一样（1600 和 57600），所以它不是「错」，是「浪费」：同一个格子被反复入队，次数约等于它的度数。40×40 上 6241/1600 ≈ 3.9，240×240 上 229441/57600 ≈ 4.0——四邻接，每个格子最多被四个邻居各推进来一次。队列峰值也跟着从 240 涨到 958。

这是我想强调的分界：**正确性和代价是两件事**。出队标记的 BFS 结果完全正确，只是入队次数多了 4 倍。而完全不标 visited 是另一回事——我给它加了 20 万步上限：

```text
[6] 从 (0, 3) 出发不标 visited: 跑满 200000 步仍未结束，栈里还有 200000 个待展开
```

跑满上限也没结束，而且栈只增不减（每弹一个格子，压回两到四个）。没有上限就是死循环加内存一路涨。图有环，这一条不是优化建议，是正确性要求。

## deque 在网格上不比 list.pop(0) 快

关于 BFS 用 `deque` 的说法，我原来的预期是「换一下能快一个数量级」。先量同一批网格：

```text
[5] 网格 BFS 40x40 (  1600 格): deque   0.94 ms | list.pop(0)   0.81 ms |  0.87x
[5] 网格 BFS 120x120 ( 14400 格): deque   9.85 ms | list.pop(0)   8.82 ms |  0.89x
[5] 网格 BFS 240x240 ( 57600 格): deque  40.72 ms | list.pop(0)  33.74 ms |  0.83x
```

`list.pop(0)` 反而略快。原因在下一组测量里：把容器直接从头取空，不做任何 BFS。

```text
[5] n=   1000: list.pop(0)    0.078 ms | deque.popleft   0.029 ms |     2.6x
[5] n=  10000: list.pop(0)   16.615 ms | deque.popleft   0.271 ms |    61.2x
[5] n= 100000: list.pop(0) 3694.355 ms | deque.popleft   3.300 ms |  1119.4x
```

差距跟着「队列同时有多长」走，不是跟着 n 走。240×240 的网格 BFS 队列峰值只有 240，每次 `pop(0)` 只搬 240 个指针，memmove 一小段的成本比 `deque.popleft` 的调用开销还低；而纯出队那组，容器一开始就有 10 万长。

为了让队列真的堆起来，我造了一张宽图（起点直连 100/200/400 个枢纽，每个枢纽再连 100 个叶子）：

```text
[5]   10101 个点: deque    1.15 ms | list.pop(0)    98.17 ms |   85.1x
[5]   20201 个点: deque    2.70 ms | list.pop(0)   391.14 ms |  144.9x
[5]   40401 个点: deque    4.80 ms | list.pop(0)   605.61 ms |  126.2x
```

同样是 BFS、同样是邻接表，差 85–145 倍。三个倍数不单调（85、145、126），这行别当精确数看：时间主要花在队列最满的那一段，样本越大越受内存与缓存抖动影响，量级是「几十到一百多倍」。

所以判据是「你的队列峰值有多宽」，不是「你用了哪种容器」。网格、树、层数少的图上，峰值就是最宽那层的格数，两者没有区别；一层几万点的图，换 `deque` 是必须的。

还得说清这些性质属于谁。`list.pop(0)` 要搬动全部剩余元素，是 CPython 当前的实现——list 是连续数组，从头弹一个就要把后面所有元素往前挪一格。`deque` 两端操作 O(1) 是文档写明的；`list.pop(0)` 的复杂度文档没承诺。换个实现（PyPy、别的版本）具体差多少我没量。

## 症状 → 先看哪

这张表是入口，不是总结：

| 症状 | 先看哪 | 依据 |
| --- | --- | --- |
| `RecursionError`，图并不大 | 最长链，不看点数 | 32×32 崩在 996 层；同一份 40×40 只到 262 层 |
| 结果对，但入队次数远大于点数 | visited 是不是写在出队之后 | 240×240：229441 vs 57600 |
| 程序不结束、内存一直涨 | 有没有标 visited | 20 万步还在跑，栈只增不减 |
| 同一张图、两种写法输出不同 | 邻居压栈顺序 | 4×4 上递归先 01、显式栈先 10 |
| 找到的路径比最短的长 | 用的是 DFS | 同一起终点 97 / 121 / 175 |
| n 大了内存爆 | 是不是邻接矩阵 | 1600 点矩阵 2.44 MB，有边的格子 0.24% |
| BFS 慢 | 队列峰值有多宽 | 240 宽的网格无差别，1 万宽的图差 100 倍 |

## 改哪个参数，动的是什么

| 改这个 | 变的是什么 | 实测 |
| --- | --- | --- |
| visited 从出队挪到入队 | 结果不变，入队次数降到约 1/4 | 229441 → 57600 |
| 递归改显式栈 | 不再撞递归上限，访问顺序变 | 40×40 栈峰值 780（递归那版要 996 层以上） |
| 队列 list 改 deque | 窄队列没差，宽队列差 1–2 个数量级 | 0.83x / 126x |
| 邻接表改矩阵 | 空间 n²，换来 O(1) 查两点是否有边 | 397 KB → 2.44 MB（1600 点） |

## 跑一遍

一段脚本，上面每个数字都能重放：

```python
import sys, time, random, platform
from collections import deque

ORD = ((-1, 0), (0, 1), (1, 0), (0, -1))
print('python', sys.version.split()[0], '| recursionlimit', sys.getrecursionlimit(),
      '|', platform.platform())

# [1] 递归 DFS 第一次崩在多大的全陆地地图
def rec_dfs(K):
    sys.setrecursionlimit(1000)
    seen, deepest = set(), 0
    def dfs(r, c, d):
        nonlocal deepest
        deepest = max(deepest, d)
        seen.add((r, c))
        for dr, dc in ORD:
            nr, nc = r + dr, c + dc
            if 0 <= nr < K and 0 <= nc < K and (nr, nc) not in seen:
                dfs(nr, nc, d + 1)
    try:
        dfs(0, 0, 1)
        return 'ok', deepest, len(seen)
    except RecursionError:
        return 'RecursionError', deepest, len(seen)

for K in (31, 32):
    r, d, v = rec_dfs(K)
    print(f'[1] {K}x{K} 全陆地: {r} 最深 {d} 层 访问 {v}/{K*K} 格')

N = 40
random.seed(20261119)
grid = [[1 if random.random() < 0.62 else 0 for _ in range(N)] for _ in range(N)]
print(f'[1] 带水的地图 {N}x{N}: 陆地 {sum(map(sum, grid))} 格')

def longest(g):
    sys.setrecursionlimit(100000)
    R, C, seen, best = len(g), len(g[0]), set(), 0
    def dfs(r, c, d):
        nonlocal best
        best = max(best, d)
        seen.add((r, c))
        for dr, dc in ORD:
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C and g[nr][nc] == 1 and (nr, nc) not in seen:
                dfs(nr, nc, d + 1)
    for r in range(R):
        for c in range(C):
            if g[r][c] == 1 and (r, c) not in seen:
                dfs(r, c, 1)
    return best

print(f'[1] 同一份 40x40 带水地图: 最深 {longest(grid)} 层')

# [2] 显式栈：深度与访问顺序
def stack_dfs(K):
    seen, stack, peak = {(0, 0)}, [(0, 0)], 1
    while stack:
        peak = max(peak, len(stack))
        r, c = stack.pop()
        for dr, dc in ORD:
            nr, nc = r + dr, c + dc
            if 0 <= nr < K and 0 <= nc < K and (nr, nc) not in seen:
                seen.add((nr, nc)); stack.append((nr, nc))
    return peak, len(seen)

for K in (10, 40):
    print(f'[2] 显式栈 {K}x{K}: 栈峰值 {stack_dfs(K)[0]} 访问 {stack_dfs(K)[1]} 格')

def order(M, use_stack):
    out, seen = [], {(0, 0)}
    if use_stack:
        stack = [(0, 0)]
        while stack:
            r, c = stack.pop(); out.append((r, c))
            for dr, dc in ORD:
                nr, nc = r + dr, c + dc
                if 0 <= nr < M and 0 <= nc < M and (nr, nc) not in seen:
                    seen.add((nr, nc)); stack.append((nr, nc))
    else:
        def go(r, c):
            out.append((r, c)); seen.add((r, c))
            for dr, dc in ORD:
                nr, nc = r + dr, c + dc
                if 0 <= nr < M and 0 <= nc < M and (nr, nc) not in seen:
                    go(nr, nc)
        go(0, 0)
    return out

print('[2] 4x4 递归  ', ' '.join(f'{r}{c}' for r, c in order(4, False)))
print('[2] 4x4 显式栈', ' '.join(f'{r}{c}' for r, c in order(4, True)))

# [3] 同一张图：岛屿、层数、BFS vs DFS
R, C = N, N
def flood(s):
    q, seen, cells = deque([s]), {s}, []
    while q:
        y, x = q.popleft(); cells.append((y, x))
        for dr, dc in ORD:
            ny, nx = y + dr, x + dc
            if 0 <= ny < R and 0 <= nx < C and grid[ny][nx] == 1 and (ny, nx) not in seen:
                seen.add((ny, nx)); q.append((ny, nx))
    return cells

parts, seen_all = [], set()
for r in range(R):
    for c in range(C):
        if grid[r][c] == 1 and (r, c) not in seen_all:
            cells = flood((r, c)); seen_all |= set(cells); parts.append(cells)

sizes = sorted((len(x) for x in parts), reverse=True)
print(f'[3] 岛屿 {len(parts)} 块 最大 {sizes[0]} 格 前 5 大 {sizes[:5]} 单格岛 {sizes.count(1)} 块')

big = max(parts, key=len)
start = min(big)
dist, q = {start: 0}, deque([start])
while q:
    y, x = q.popleft()
    for dr, dc in ORD:
        ny, nx = y + dr, x + dc
        if 0 <= ny < R and 0 <= nx < C and grid[ny][nx] == 1 and (ny, nx) not in dist:
            dist[(ny, nx)] = dist[(y, x)] + 1; q.append((ny, nx))
far = max(dist, key=dist.get)
layer = {}
for d in dist.values():
    layer[d] = layer.get(d, 0) + 1
print(f'[3] {start} -> {far}: BFS {dist[far]} 步')
print('[3] 每层格数', [layer.get(i, 0) for i in range(12)])

def path(s, t, use_stack):
    if use_stack:
        seen, st = {s}, [(s, [s])]
        while st:
            (y, x), p = st.pop()
            if (y, x) == t:
                return p
            for dr, dc in ORD:
                ny, nx = y + dr, x + dc
                if 0 <= ny < R and 0 <= nx < C and grid[ny][nx] == 1 and (ny, nx) not in seen:
                    seen.add((ny, nx)); st.append(((ny, nx), p + [(ny, nx)]))
        return []
    sys.setrecursionlimit(100000)
    found = []
    def dfs(y, x, seen, cur):
        seen.add((y, x)); cur.append((y, x))
        if (y, x) == t:
            found.extend(cur); return True
        for dr, dc in ORD:
            ny, nx = y + dr, x + dc
            if 0 <= ny < R and 0 <= nx < C and grid[ny][nx] == 1 and (ny, nx) not in seen:
                if dfs(ny, nx, seen, cur):
                    return True
        cur.pop(); return False
    dfs(s[0], s[1], set(), [])
    return found

print(f'[3] 同一起终点: 递归 DFS {len(path(start, far, False))-1} 步 '
      f'显式栈 DFS {len(path(start, far, True))-1} 步')

# [4] visited 标在入队还是出队
def bfs_enq(K):
    seen, q, enq, peak = {(0, 0)}, deque([(0, 0)]), 1, 1
    while q:
        peak = max(peak, len(q)); r, c = q.popleft()
        for dr, dc in ORD:
            nr, nc = r + dr, c + dc
            if 0 <= nr < K and 0 <= nc < K and (nr, nc) not in seen:
                seen.add((nr, nc)); q.append((nr, nc)); enq += 1
    return enq, peak, len(seen)

def bfs_deq(K):
    seen, q, enq, peak = set(), deque([(0, 0)]), 1, 1
    while q:
        peak = max(peak, len(q)); r, c = q.popleft()
        if (r, c) in seen:
            continue
        seen.add((r, c))
        for dr, dc in ORD:
            nr, nc = r + dr, c + dc
            if 0 <= nr < K and 0 <= nc < K:
                q.append((nr, nc)); enq += 1
    return enq, peak, len(seen)

for K in (40, 240):
    a, b = bfs_enq(K), bfs_deq(K)
    print(f'[4] {K}x{K} 入队标记 入队{a[0]:7d} 峰值{a[1]:5d} | '
          f'出队标记 入队{b[0]:7d} 峰值{b[1]:5d} | 都访问 {a[2]}/{b[2]}')

# [5] deque vs list.pop(0)
def bfs_list(K):
    seen, q = {(0, 0)}, [(0, 0)]
    while q:
        r, c = q.pop(0)
        for dr, dc in ORD:
            nr, nc = r + dr, c + dc
            if 0 <= nr < K and 0 <= nc < K and (nr, nc) not in seen:
                seen.add((nr, nc)); q.append((nr, nc))
    return len(seen)

def best(fn, *a):
    ts = []
    for _ in range(5):
        t = time.perf_counter(); fn(*a); ts.append(time.perf_counter() - t)
    return min(ts) * 1000

for K in (40, 120, 240):
    d, l = best(bfs_enq, K), best(bfs_list, K)
    print(f'[5] 网格 BFS {K}x{K} ({K*K:6d} 格): deque {d:6.2f} ms | list.pop(0) {l:6.2f} ms | {l/d:5.2f}x')

def wide(n_hub, per):
    g = {0: list(range(1, n_hub + 1))}
    nid = n_hub + 1
    for h in range(1, n_hub + 1):
        kids = list(range(nid, nid + per)); nid += per
        g[h] = kids
        for k in kids:
            g[k] = []
    return g, nid

def bfs_graph(g, use_deque):
    seen, q = {0}, (deque([0]) if use_deque else [0])
    while q:
        u = q.popleft() if use_deque else q.pop(0)
        for v in g[u]:
            if v not in seen:
                seen.add(v); q.append(v)

# [7] 邻接矩阵 vs 邻接表

def deep_size(x, seen=None):
    seen = set() if seen is None else seen
    if id(x) in seen:
        return 0
    seen.add(id(x))
    s = sys.getsizeof(x)
    if isinstance(x, dict):
        for k, v in x.items():
            s += deep_size(k, seen) + deep_size(v, seen)
    elif isinstance(x, (list, tuple, set)):
        for v in x:
            s += deep_size(v, seen)
    return s
```

## 动手

1. 给你手上的递归 DFS 加一个深度参数，记住最大值。超过 900 就换显式栈——不是因为递归慢，是因为你离那个 1000 只剩几十层，图稍微变个形状就崩。别用调大 `setrecursionlimit` 糊过去：调大之后会不会撞穿 C 栈，我在 3.11.5 上没试，不知道在哪一步变成段错误。
2. 把 BFS 的 visited 挪到入队那行，同时打印「入队次数」和 `len(queue)` 的峰值。入队次数接近点数的 4 倍（四邻接）或 8 倍（八邻接），就说明你在为同一个点重复付费。
3. 量你那个 BFS 的队列峰值。峰值只有几十，换 `deque` 不会快；峰值上万，不换就是上面那 100 倍。

## 还差的

- 只测了 Python。Java 的 `ArrayList.remove(0)`、C++ 的 `vector.erase(begin())` 在同形状图上差多少，我没量；结论「看队列宽度」应该成立，但具体倍数不能拿这篇的数去套。
- 有向图的环检测和拓扑排序一句没写。原文有一段「包管理器按依赖顺序安装、循环依赖报错」，那是另一张图上的另一套代码，我没跑过，就整段删了——所以这篇对「循环依赖」没有任何本机证据。
- 加权图只留了一句话。Dijkstra、0-1 权重的双端队列 BFS、A* 都没碰，「第一次到达即最短」在有权图上的正确反例也没构造。
- 递归上限只量到「32×32 崩」。调大 `sys.setrecursionlimit` 之后 3.11 会不会真撞穿 C 栈、在哪一步变段错误，我没试，也不敢替它下结论。
- 内存那行是估算。`deep_size` 是我自己写的递归求和，把 dict/list 对象的 `sys.getsizeof` 加起来；没做进程 RSS 对比，也没算分配器碎片，2.44 MB 与 397 KB 只能当量级看。
