## 先把结论摆出来

图和树的区别只有一条：**图可以有环，且任意两个点之间可能有多条路**。所以图遍历必须记录"访问过没有"，否则会无限打转。

两种遍历方式，差别只在"先扩展谁"：

- **BFS（广度优先）**：用**队列**，一层一层往外扩。无权图上第一次到达某点，走的就是最短路径。
- **DFS（深度优先）**：用**栈**（或递归），一条路走到黑，不行再回退。

代码骨架几乎一样，只换一个容器。**先想清楚你要"最短"还是"走完"，再选。**

## 图的两种存法

| 存法 | 空间 | 适合 |
| --- | --- | --- |
| 邻接矩阵 | O(n²) | 点少、边密、要 O(1) 判断两点是否相连 |
| 邻接表 | O(n + m) | 点多样稀（绝大多数真实场景） |

社交关系、依赖关系、路由表都是稀疏图，用邻接表。矩阵只在点数几百、且频繁查"两点之间有没有边"时才划算。

## BFS：最短路径与"层"

```text
queue = [起点]
visited = {起点}
while queue 非空:
    取队头 node
    for 每个邻居 next:
        if next 未访问:
            标记 visited
            queue 入队 next
```

三个要点：

1. **入队时就标记 visited**。如果出队才标记，同一个点可能被重复入队，队列膨胀；
2. 无权图的最短路径 = BFS 的层数；
3. 有权图（边有不同代价）不能直接用 BFS，要用 Dijkstra（本质是优先队列版的 BFS）。

**"层"这个概念特别好用**：社交网络的几度人脉、依赖的传递层数、文件系统的层级，都是 BFS 的层。

## DFS：连通性、拓扑、回溯

```text
stack = [起点]
visited = {起点}
while stack 非空:
    node = stack.pop()
    for 每个邻居 next:
        if next 未访问:
            visited 加入 next
            stack 入栈 next
```

DFS 的典型用途：

- **连通分量**：从每个未访问点出发做一次 DFS，能数出有几块；
- **环检测**：DFS 时若遇到"正在访问中"的节点，说明有环；
- **拓扑排序**：有向无环图上，按 DFS 完成顺序逆序输出；或反复取入度为 0 的点（Kahn 算法）；
- **回溯搜索**：路径、组合、数独，本质是带撤销的 DFS。

**递归写 DFS 最直观，但图深时会栈溢出**。线上代码更安全的写法是显式栈。

## 复杂度

邻接表上，BFS/DFS 都是 **O(n + m)**（n 个点、m 条边）：每个点进一次，每条边看一次。

邻接矩阵上则是 O(n²)，因为每个点都要扫一整行。

## 一个真实场景：依赖解析

包管理器要按依赖顺序安装，本质是**拓扑排序**：

1. 每个包是点，"A 依赖 B"是 B → A 的有向边；
2. 反复取入度为 0 的点输出（Kahn）；
3. 如果最后还有点没输出，说明有循环依赖——报错，而不是死循环。

这解释了为什么"循环依赖"是构建系统必须处理的错误，而不是能绕过去的警告。

## 常见误区

### 误区：DFS 能找到最短路径

**你以为**：都是遍历，应该差不多。
**其实**：DFS 只保证"能到"，不保证"最短"。无权图最短用 BFS，有权图用 Dijkstra。

### 误区：图遍历不用记录访问

**你以为**：和树一样往下走就行。
**其实**：图有环，不记录就会无限循环。访问标记不是优化，是正确性要求。

### 误区：邻接矩阵更"完整"所以更好

**你以为**：矩阵直观。
**其实**：n 个点要 n² 空间。一万个点的稀疏图要一亿个格，很多是空的。真实场景几乎都是邻接表。

## 小结

图遍历必须记录访问；BFS 用队列求最短与层数，DFS 用栈做连通性、环检测、拓扑与回溯。邻接表是默认选择，复杂度 O(n + m)。循环依赖检测就是拓扑排序的副产品。下一课：排序怎么选。
