## 第 997 条任务：RecursionError

我手上是一份任务表，两个需求：按 `id` 范围取一批（比如 1000–2000 号），和每次取 deadline 最早的那条。我先做第一个——按 `id` 建一棵二叉搜索树当有序索引。任务从 CSV 里读进来，`id` 是 0、1、2……递增的，我就照着文件顺序一条条插：

```python
class Node:
    __slots__ = ('v', 'l', 'r')

    def __init__(self, v):
        self.v, self.l, self.r = v, None, None


def insert(root, v):
    if root is None:
        return Node(v)
    if v < root.v:
        root.l = insert(root.l, v)
    else:
        root.r = insert(root.r, v)
    return root


root = None
for i in range(997):
    root = insert(root, i)
```

```text
RecursionError: maximum recursion depth exceeded
```

这台机器上 `sys.getrecursionlimit()` 是 1000。996 条能过，第 997 条崩。

这个数还会动：把同样的循环套进一个函数里再调，能过的上限就变成 995。限制数的是**当时栈有多深**，不是数据量——所以「数据量不到 1000 就安全」是错的，你在一层调用里建树，栈底早就垫了几层。我一开始以为它和 n=1000 这个整数有关，白白多试了几轮。

我更早的预期是「树会自己长成两边差不多」。实际是按递增顺序插入时，每个新值都比根大，于是一路往右走，最后长成一条 `0 → 1 → 2 → …` 的链，递归深度等于节点个数。

## 换成循环，只是不再报错

```python
def insert(root, v):
    if root is None:
        return Node(v)
    cur = root
    while True:
        if v < cur.v:
            if cur.l is None:
                cur.l = Node(v)
                return root
            cur = cur.l
        else:
            if cur.r is None:
                cur.r = Node(v)
                return root
            cur = cur.r
```

不崩了。量一下形状：

```text
n=  1000  顺序插入 depth=  1000  随机插入 depth= 19  查不存在的值比较次数: 链=  1000  随机树=  8
n= 10000  顺序插入 depth= 10000  随机插入 depth= 31  查不存在的值比较次数: 链= 10000  随机树= 11
```

「查不存在的值」是最坏情况：它要走完整条路径才能确定没有。10000 条数据在链上一次查 10000 次比较，和遍历一个 list 一样；同样 10000 条随机插入，深度 31，11 次比较。

所以递归不是病根。同一份数据，如果 CSV 里的顺序是随机的，递归版插 10000 条一点都不崩；把同样形状的链交给一个递归查最大值的函数，照样崩。变的一直是数据的形状，不是写法。

要真 O(log n)，得是**平衡**的搜索树，而平衡不会从插入顺序里自己长出来。

## 标准库里没有平衡树，我找了很久

我最先以为「找现成的」这一步就是 `TreeMap`，查了一圈才发现：`TreeMap` 是 Java 的；`sortedcontainers` 是第三方库，这台机器上 `import sortedcontainers` 直接 `ModuleNotFoundError`；Redis 的 zset 是另一个进程里的东西，不是 Python 的类型。CPython 3.11.5 的标准库里没有一个「按键有序的映射」——`OrderedDict` 保的是插入顺序，`heapq` 只保证堆顶。

能用的替身是「排好序的 list + `bisect`」：查是二分，插入要 `insort` 把后面所有元素搬一格。

```text
n=  2000  insort    0.58 ms   heappush   0.12 ms
n= 10000  insort    8.48 ms   heappush   1.02 ms
n= 20000  insort   26.62 ms   heappush   1.23 ms
```

n 从 10000 到 20000 翻一倍，`insort` 的总耗时涨了 3 倍多（平方量级），`heappush` 那列几乎没动——那一列是堆，堆不维护全序，插入时基本不用搬东西。贵的那部分正是「有序」这两个字买来的。

这决定了它的用法：**建好再查**可以。10 万条有序 list 上取一个区间，`bisect_left` 加 `bisect_right` 一共 10.4 us，一次返回 9861 条。**边插边查**不行，每插一条都在搬数据。

## 第二个需求：不要全序，只要最急的那条

id 区间那个查询我其实用不上；天天跑的是开头说的第二个需求——每次取 deadline 最早的那个任务。这里不需要全序，只要极值，堆就够。

`heapq` 是小顶堆，`h[0]` 是最小值。我拿一个在 `__lt__` 里计数的包装类，把「一次操作到底比较了多少次」数了出来：

```text
n=  1000  heapify     1638 (1.64/元素)  逐个 push     2226 (2.23/次)  全部 pop     8678 (8.68/次)
n= 10000  heapify    16401 (1.64/元素)  逐个 push    22861 (2.29/次)  全部 pop   120143 (12.01/次)
n=100000  heapify   165082 (1.65/元素)  逐个 push   228002 (2.28/次)  全部 pop  1534794 (15.35/次)
```

三列得分开读：

- **`heapify`**：1.64 次/元素，n 翻 100 倍几乎不变。它是从最后一个非叶节点往前下沉，总代价线性。
- **全部 `pop`**：8.68 / 12.01 / 15.35，对应 log₂n = 10 / 13 / 17，差不多 0.9×log₂n。每次都要从根沉到叶子，这是真的 O(log n)。
- **逐个 `push`**：2.23 / 2.29 / 2.28，一点都不涨。随机数据插进去，上浮一两层就停了。上限呢？我把「每次插入的都比现有最小值还小」这种最坏顺序也跑了一遍：7.99 / 11.36 / 14.69 次，也就是 0.9×log₂n。

所以「插入 O(log n)」得说全：**上限是 O(log n)，随机数据下平均两次多点**。这个区别在判断「要不要用堆」时有用——它不是每插一条就掏 log n 的代价。

「取顶 O(1)」也得说清是哪个动作：

```text
堆大小 1e5，各做 1e5 次
heap[0]        4.12 ms   ≈ 41 ns/次
heapq.heappop  40.06 ms  ≈ 401 ns/次
```

看一眼是 O(1)；取走一个要把末尾搬到根再沉下去，是 O(log n)，秒表上差十倍——堆里 1e5 个元素，log₂n 是 17 层，每层一次比较加一次交换，摊下来正好这个量级。

## heapq 上会真报错的两处

第一处，平手时比较不下去：

```python
h = []
heapq.heappush(h, (1, {'id': 'a'}))
heapq.heappush(h, (1, {'id': 'b'}))
```

```text
TypeError: '<' not supported between instances of 'dict' and 'dict'
```

元组比大小是逐项比的：第一项相等，就去比第二项；第二项是 dict，没有 `<`。任务队列里「优先级相同」不是边角情况，是常态。修法是塞一个永不相等的第二项：

```python
import itertools

seq = itertools.count()
heapq.heappush(h, (deadline, next(seq), task))
```

顺手拿到第二个好处：同 deadline 的任务按入队先后出队。要是省掉 `seq`、直接塞 `(deadline, task_id)`，而 id 又是字符串，平手时就改按字典序比——`'10'` 排在 `'9'` 前面。

第二处，`heapq` 只有小顶堆。要最大堆，得把值取负，或者给元素自定义一个反过来的 `__lt__`。取负的坑是 `h[0]` 里存的是 `-max`，忘了取回来就会看到「最大的那个是 -5」。

还有一件不算错但很容易用错：**堆的数组不是有序数组**。

```text
依次 push 5 3 8 1 9 2  -> [1, 3, 2, 5, 9, 8]
sorted(...)            -> [1, 2, 3, 5, 8, 9]
```

`[1, 3, 2, 5, 9, 8]` 里 3 排在 2 前面、9 排在 8 前面。只保证父节点不大于子节点，同一层之间没有任何关系。要全有序只能一条条 pop，而那就是排序，还比 `sorted()` 慢：

```text
n=100000   heapify 5.24 + 全部 pop 40.14 = 45.4 ms
           sorted()                        17.02 ms
```

同数据、同机器，用 `heapq` 手动做一次排序比内置 `sorted()` 慢一倍多。

## 建堆和取前 k：两个参数决定该用谁

**已有数据建堆，别循环 push。** 1.64 对 2.28 次/元素，n=1e5 时 5.24 ms 对 6.67 ms。

**取前 k 个，`nlargest` 和 `sorted` 的选择取决于 k。** n = 200000 个随机整数，5 次中位数：

| k | `heapq.nlargest(k, data)` | `sorted(data)[-k:]` | 差多少 |
| --- | --- | --- | --- |
| 1 | 1.42 ms | 37.56 ms | 26 倍 |
| 10 | 3.02 ms | 40.12 ms | 13 倍 |
| 100 | 3.56 ms | 37.64 ms | 11 倍 |
| 10000 | 29.36 ms | 40.40 ms | 1.4 倍 |
| 200000 | 47.74 ms | 45.80 ms | 慢 4% |

k 接近总数时 `nlargest` 反而慢一点，这不是 bug：3.11 的文档把 `nlargest` 写成「等价于 `sorted(iterable, key=key, reverse=True)[:n]`」，k 不小于长度时它就直接排一遍再切，多拷了一次切片。**结果等价是文档写明的，代价不是**——别默认它内部是个堆。

并列时结果还取决于传没传 key：

```python
rows = [('b', 1), ('a', 1), ('c', 1), ('d', 0)]

heapq.nlargest(3, rows)                      # [('d', 0), ('c', 1), ('b', 1)]
heapq.nlargest(3, rows, key=lambda t: t[1])  # [('b', 1), ('a', 1), ('c', 1)]
sorted(rows, key=lambda t: t[1], reverse=True)[:3]   # [('b', 1), ('a', 1), ('c', 1)]
```

不传 key 是整元组比较，字符串序也参与进来，所以数字最小的 `('d', 0)` 排到了最前面。传了 key，并列的保持原来的相对顺序，和 `sorted` 的稳定性一致。

## 一张排查表

| 症状 | 先看哪 |
| --- | --- |
| 越跑越慢，数据量涨得没那么多 | 插入顺序是不是已经有序（自增 id、时间戳、排好序的文件）；量深度 ÷ 元素数 |
| 递归版本报 `RecursionError`，数据量看着不大 | `sys.getrecursionlimit()` 和当时的栈深；先确认是不是退化成了链 |
| `TypeError: '<' not supported between instances of ...` | 堆里放的是元组或对象，平手时第二项不可比较；加递增计数器或写 `__lt__` |
| 从堆里按顺序取，结果不是有序的 | 把 `heap` 当有序数组用了；只有 `h[0]` 有意义 |
| 大顶堆取出来的值是负的 | 用取负实现的大顶堆，忘了取回来 |
| 边插边查，几万条之后卡住 | 是不是在有序 list 上 `insort`；改成先收集再排序，或换堆 |
| 要按区间/前缀读，用堆怎么都不对 | 堆里没有范围信息，这个需求它做不到；换有序结构或交给数据库索引 |

## 跑一遍

上面每一个数都能用这个脚本复现（`heapq` 的比较次数靠 `__lt__` 计数，时间和内存另算）：

```python
import heapq
import random
import sys

sys.setrecursionlimit(1000)          # 3.11 默认就是 1000，显式写出来免得误读


class Node:
    __slots__ = ('v', 'l', 'r')

    def __init__(self, v):
        self.v, self.l, self.r = v, None, None


def insert(root, v):                  # 递归版
    if root is None:
        return Node(v)
    if v < root.v:
        root.l = insert(root.l, v)
    else:
        root.r = insert(root.r, v)
    return root


def build(n):
    root = None
    for i in range(n):
        root = insert(root, i)
    return root


def first_crash(nested):
    for n in range(900, 1200):
        try:
            if nested:
                def wrapper():
                    build(n)
                wrapper()
            else:
                build(n)
        except RecursionError:
            return n
    return None


print('recursionlimit =', sys.getrecursionlimit())
print('顺序插入，模块顶层第一个崩掉的 n =', first_crash(False))
print('顺序插入，外面套一层函数第一个崩掉的 n =', first_crash(True))


def insert_iter(root, v):
    if root is None:
        return Node(v)
    cur = root
    while True:
        if v < cur.v:
            if cur.l is None:
                cur.l = Node(v)
                return root
            cur = cur.l
        else:
            if cur.r is None:
                cur.r = Node(v)
                return root
            cur = cur.r


def depth(root):
    best, stack = 0, [(root, 1)]
    while stack:
        nd, d = stack.pop()
        best = max(best, d)
        if nd.l:
            stack.append((nd.l, d + 1))
        if nd.r:
            stack.append((nd.r, d + 1))
    return best


def probes(root, key):
    cur, c = root, 0
    while cur is not None:
        c += 1
        if key == cur.v:
            return c
        cur = cur.l if key < cur.v else cur.r
    return c


random.seed(20261119)
for n in (1000, 10000):
    seq = None
    for i in range(n):
        seq = insert_iter(seq, i)
    vals = list(range(n))
    random.shuffle(vals)
    rnd = None
    for v in vals:
        rnd = insert_iter(rnd, v)
    print(f'n={n:6d}  顺序插入 depth={depth(seq):6d}  随机插入 depth={depth(rnd):3d}  '
          f'查不存在的值比较次数: 链={probes(seq, n - 0.5):6d}  随机树={probes(rnd, n - 0.5):3d}')


class Cnt:
    __slots__ = ('v',)
    cmp = 0

    def __init__(self, v):
        self.v = v

    def __lt__(self, o):
        Cnt.cmp += 1
        return self.v < o.v


print('heapq 比较次数（用 __lt__ 计数）')
for n in (1000, 10000, 100000):
    random.seed(n)
    Cnt.cmp = 0
    h = [Cnt(random.randrange(10 ** 9)) for _ in range(n)]
    heapq.heapify(h)
    c_heapify = Cnt.cmp

    Cnt.cmp = 0
    h = []
    for x in (Cnt(random.randrange(10 ** 9)) for _ in range(n)):
        heapq.heappush(h, x)
    c_push = Cnt.cmp

    Cnt.cmp = 0
    while h:
        heapq.heappop(h)
    c_pop = Cnt.cmp
    print(f'n={n:6d}  heapify {c_heapify:8d} ({c_heapify / n:.2f}/元素)  '
          f'逐个 push {c_push:8d} ({c_push / n:.2f}/次)  '
          f'全部 pop {c_pop:8d} ({c_pop / n:.2f}/次)')

h = []
for x in [5, 3, 8, 1, 9, 2]:
    heapq.heappush(h, x)
print('push 5 3 8 1 9 2 ->', h, '| sorted ->', sorted(h))

h = []
heapq.heappush(h, (1, {'id': 'a'}))
try:
    heapq.heappush(h, (1, {'id': 'b'}))
except TypeError as e:
    print('平手不可比较 ->', type(e).__name__, ':', e)

data = [random.randrange(10 ** 9) for _ in range(200000)]
print('nlargest(200000, data) == sorted(data, reverse=True) ->',
      heapq.nlargest(200000, data) == sorted(data, reverse=True))
print('nlargest(5, data) == sorted(data, reverse=True)[:5] ->',
      heapq.nlargest(5, data) == sorted(data, reverse=True)[:5])

rows = [('b', 1), ('a', 1), ('c', 1), ('d', 0)]
print('无 key ->', heapq.nlargest(3, rows))
print('有 key ->', heapq.nlargest(3, rows, key=lambda t: t[1]))
```

## 动手

1. 把手上的 `insert` 换成迭代版，写个 `depth()` 量你那棵树。深度接近元素数，说明问题在插入顺序（自增 id、时间戳、已排序的文件），不在递归——这时候调 `sys.setrecursionlimit` 只是把崩溃点往后挪，查询还是线性。
2. 把任务堆从 `(deadline, task)` 改成 `(deadline, next(seq), task)`，重跑一遍，确认同 deadline 的任务按入队顺序出队了。如果你之前见过「优先级相同就随机换顺序」的测试偶发失败，八成就是这里。
3. 找出你代码里最大的一次「取前 k」，记下 k 和 n。k 比 n 小两个数量级就换 `nlargest`；k 接近 n 就留着 `sorted`，换过去只是多拷一次切片。

## 还差的

- 所有数字只在一台机器、一个进程里量过：CPython 3.11.5，`platform.platform()` 报 `Windows-10-10.0.22000-SP0`，单线程。毫秒数是 5 次中位数，同一台机器上再跑一遍能差几十个百分点（「全部 pop」那列我两次分别量到 27.90 和 40.14 ms）；比较次数和深度那几列是稳定的。
- 平衡树一个都没实测。红黑树、AVL、跳表在本文只出现名字；`sortedcontainers` 没装（`ModuleNotFoundError`），它的插入和区间成本我没量过，所以没推荐它。
- 递归那条线只量到「它崩」。`sys.setrecursionlimit` 调到 10000 之后会不会真的撞穿 C 栈，我没试——调大限制不是解决方案，但具体在哪里变成段错误我不知道。
- 没测并发和内存。堆和有序 list 在几十万条时的实际内存占用、以及多线程下 `heapq` 的行为，都没量。
- B+ 树和磁盘 IO 一句没写。原来那段「三四层就能索引上亿行」我找不到本机可复现的出处，页大小、键宽、树高之间怎么换算也没验，就整段删了。
