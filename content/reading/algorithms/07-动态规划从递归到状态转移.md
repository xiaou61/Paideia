## 先把结论摆出来

动态规划不是一种新算法，它是**给递归加一本账**：同一个子问题只算一次，把答案记下来。能这么做的前提有两个：**最优子结构**（大问题的最优解能由小问题的最优解拼出来）和**重叠子问题**（递归树里同一个节点被反复访问）。缺一个，就不该硬套 DP。


落地时永远走同一条路：

1. 先写**暴力递归**，把"每个位置有哪些选择"写清楚；
2. 发现重复调用后加**记忆化**，复杂度通常立刻降到"状态数 × 每个状态的转移代价"；
3. 如果需要更低常数、或者递归太深，再改**自底向上**的表格；
4. 表格能省空间时再省，但**先写对二维版**，别一上来就压成一维。

写 DP 只有五件事要定：状态含义、转移方程、base case、遍历顺序、答案位置。**状态定义错了，后面全错**；转移方程只是把"最后一步的选择"翻译成代码。

## 从爬楼梯开始：三种写法差在哪

题目：一次可以走 1 级或 2 级，走到第 n 级有多少种走法。

暴力递归直接按定义写：

```python
def climb(n):
    if n <= 2:
        return n          # n=1 一种，n=2 两种
    return climb(n - 1) + climb(n - 2)
```

`climb(5)` 会算两次 `climb(3)`、三次 `climb(2)`。递归树是一棵二叉树，时间 O(2^n)，空间是递归深度 O(n)。n=40 就要等几秒，n=100 基本出不来。

加一本账，也就是记忆化：

```python
def climb(n, memo=None):
    if memo is None:
        memo = {}
    if n <= 2:
        return n
    if n in memo:
        return memo[n]
    memo[n] = climb(n - 1, memo) + climb(n - 2, memo)
    return memo[n]
```

每个 n 只算一次，时间 O(n)，空间 O(n)（表加栈）。

自底向上：

```python
def climb(n):
    if n <= 2:
        return n
    a, b = 1, 2                 # f(1), f(2)
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b
```

时间 O(n)，额外空间 O(1)。

三种写法共用同一个转移方程 `f(n) = f(n-1) + f(n-2)`，区别只在"答案从哪来、什么时候算"。**记忆化是递归加缓存，自底向上是把递归顺序倒过来填表**，不是两个不同的问题。

| 写法 | 时间 | 空间 | 什么时候用 |
| --- | --- | --- | --- |
| 暴力递归 | O(2^n) | O(n) 栈 | 只用来想清楚选择，不交付 |
| 记忆化 | O(n) | O(n) | 状态依赖复杂、不好定顺序时 |
| 自底向上 | O(n) | O(1) 可压缩 | 依赖方向清楚、调用量大时 |

## 五件套：状态、方程、初始值、顺序、答案

这五件事是 DP 的检查清单。少定一件，代码通常能跑，但答案会在某个边界上错。

**状态定义**要能用一句人话读出来："`dp[i]` 表示……"。读不出来，说明还没想清楚。爬楼梯的 `dp[i]` 是"走到第 i 级的方法数"，一句话就够。

**转移方程**看最后一步。走到第 i 级，最后一步只能跨 1 级或 2 级，所以方法数等于"到 i-1 的方法数"加"到 i-2 的方法数"。这就是把选择翻译成加法。

转移有两种方向：**拉**（用已知的过去算现在）和**推**（用现在更新未来）。爬楼梯两种写法都对：`dp[i] = dp[i-1] + dp[i-2]` 是拉，`dp[i+1] += dp[i]; dp[i+2] += dp[i]` 是推。拉的形式更容易检查依赖，推的形式在"一个状态影响多个后继"时更自然，比如图上路径计数。初学时统一用拉，别在同一段代码里混着写。

**base case** 是最小规模直接给出的答案。爬楼梯是 `dp[1]=1`、`dp[2]=2`。别小看它：求最小值时初始值填 0，会把"不可达"当成"代价为零"，这是 DP 最常见的错。

**遍历顺序**由依赖决定。`dp[i]` 依赖 `dp[i-1]` 和 `dp[i-2]`，i 就必须从小到大。二维表同理：先算被依赖的格子。顺序反了不是慢，是读到还没算的 0 或初始值。

**答案位置**是最后一个容易漏的点。爬楼梯是 `dp[n]`；LIS 是 `max(dp)` 而不是 `dp[n-1]`；背包是 `dp[n][W]`。写之前先问"我定义的状态里，哪一个代表了题目要的东西"。

| 要素 | 爬楼梯 | 0-1 背包 | 编辑距离 |
| --- | --- | --- | --- |
| 状态 | `dp[i]` 走到 i 的方法数 | `dp[i][w]` 前 i 件、容量 w 的最大价值 | `dp[i][j]` 前 i 个字符变成前 j 个字符的最少操作 |
| 转移 | `dp[i-1] + dp[i-2]` | 不拿或拿，取较大值 | 相等则跳过；否则删、插、换取最小 |
| base | `dp[1]=1, dp[2]=2` | `dp[0][*]=0` | `dp[0][j]=j, dp[i][0]=i` |
| 顺序 | i 从小到大 | i 从小到大，一维时 w 从大到小 | i、j 都从小到大 |
| 答案 | `dp[n]` | `dp[n][W]` | `dp[m][n]` |

## 0-1 背包：状态多一维，世界不一样

题目：n 件物品，第 i 件重 `w_i`、价值 `v_i`，背包容量 W，每件最多拿一次，求能装下的最大价值。

状态定义成 `dp[i][w]`：**只考虑前 i 件物品、容量不超过 w 时的最大价值**。转移只有两个选择：

- 不拿第 i 件：`dp[i-1][w]`；
- 拿第 i 件（前提 `w >= w_i`）：`dp[i-1][w-w_i] + v_i`。

```python
def knapsack(weights, values, W):
    n = len(weights)
    dp = [[0] * (W + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        wi, vi = weights[i - 1], values[i - 1]
        for w in range(W + 1):
            dp[i][w] = dp[i - 1][w]
            if w >= wi:
                dp[i][w] = max(dp[i][w], dp[i - 1][w - wi] + vi)
    return dp[n][W]
```

时间 O(nW)，空间 O(nW)。这个复杂度叫**伪多项式**：它看起来是多项式，但 W 是数值不是输入长度。W 给到 10 亿，这个算法就跑不动——DP 不是万能的，状态规模本身就是天花板。

压成一维：

```python
def knapsack(weights, values, W):
    dp = [0] * (W + 1)
    for wi, vi in zip(weights, values):
        for w in range(W, wi - 1, -1):     # 必须倒序
            dp[w] = max(dp[w], dp[w - wi] + vi)
    return dp[W]
```

**为什么倒序**：`dp[w-wi]` 必须来自"还没考虑当前物品"的旧值。正序遍历时，下标小的格子已经在本轮被更新过，等于同一件物品被拿了第二次，0-1 背包就变成了完全背包。这一条既是考点，也是线上算错钱的经典来源。

## 最长递增子序列：状态定义决定成败

最容易写错的定义是：`dp[i]` 表示"前 i 个元素里的最长递增子序列长度"。这个定义没法转移——你不知道前 i 个的 LIS 结尾是谁，就无法判断 `nums[i]` 能不能接上去。

正确的定义是：`dp[i]` 表示**以 `nums[i]` 结尾**的最长递增子序列长度。

```python
def lis(nums):
    if not nums:
        return 0
    dp = [1] * len(nums)
    for i in range(1, len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp)
```

时间 O(n²)，空间 O(n)。答案是 `max(dp)`，因为最长的那个不一定以最后一个元素结尾。

如果只需要长度，可以做到 O(n log n)：维护一个 `tails` 数组，`tails[k]` 表示"长度为 k+1 的递增子序列，能用的最小结尾"。

```python
import bisect

def lis_fast(nums):
    tails = []
    for x in nums:
        i = bisect.bisect_left(tails, x)   # 严格递增用 left
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
```

每来一个数，二分找第一个大于等于它的位置并替换。`tails` 的长度就是答案。

**注意**：`tails` 本身不一定是合法的子序列。比如 `[2, 5, 3, 4]` 走完得到 `[2, 3, 4]`，但原数组里 3 在 5 后面，取不出 2、3、4。只有长度有意义，别把 `tails` 当答案输出。

## 编辑距离：二维字符串 DP 的模板

题目：把 `word1` 变成 `word2`，每次可以插入、删除、替换一个字符，求最少操作数。

状态 `dp[i][j]`：把 `word1` 的前 i 个字符变成 `word2` 的前 j 个字符，最少要几步。

- 两个末尾字符相同：不用操作，`dp[i][j] = dp[i-1][j-1]`；
- 不同：三种操作取最小，再各加 1。

```python
def edit_distance(a, b):
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1):
        dp[i][0] = i              # 删光
    for j in range(n + 1):
        dp[0][j] = j              # 全插入
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1]
            else:
                dp[i][j] = 1 + min(
                    dp[i - 1][j],       # 删除 a[i-1]
                    dp[i][j - 1],       # 插入 b[j-1]
                    dp[i - 1][j - 1],   # 替换
                )
    return dp[m][n]
```

时间 O(mn)，空间 O(mn)。以 `horse` 变 `ros` 为例，填表结果：

```text
        ""   r   o   s
  ""     0   1   2   3
  h      1   1   2   3
  o      2   2   1   2
  r      3   2   2   2
  s      4   3   3   2
  e      5   4   4   3
```

右下角 3 就是答案：`h→r` 替换、删掉一个 `r`、删掉 `e`。同一套骨架换成"最长公共子序列"，只是把三种操作改成"跳过或匹配"，可见二维字符串 DP 的形态是固定的。

## 空间压缩：能压的只有"用完就扔"的维度

DP 的空间压缩不是技巧，是观察依赖关系：**某一维算完就再也不用了，才能扔掉**。

- 爬楼梯只依赖前两个状态，两个变量就够；
- 0-1 背包的 `dp[i][*]` 只依赖 `dp[i-1][*]`，可以压成一维，但必须倒序遍历；
- 完全背包（每件物品无限次）一维要**正序**，因为本层更新后的值就是要被重复使用的；
- 编辑距离依赖上、左、左上三个格子，可以压成一行，但要把左上角先存进临时变量，否则会被覆盖；
- LIS 的 O(n²) 版本依赖前面所有 `dp[j]`，压不到 O(1)，能压到 O(n) 已经到底；
- 需要输出具体方案时，整张表（或父指针）不能扔，否则回溯不出路径。

| 问题 | 依赖 | 能否压缩 | 做法 |
| --- | --- | --- | --- |
| 爬楼梯 | 前两个状态 | 能到 O(1) | 两个变量滚动 |
| 0-1 背包 | 上一层 | 能到 O(W) | 一维倒序 |
| 完全背包 | 本层左侧 | 能到 O(W) | 一维正序 |
| 编辑距离 | 上、左、左上 | 能到 O(n) | 一行加对角线临时变量 |
| LIS O(n²) | 前面所有状态 | 只能到 O(n) | 保留 dp 数组 |
| 需要输出方案 | 整张表 | 不能 | 存选择或父指针 |

**顺序**：先把二维版写对、跑通小数据，再压缩。压缩只改空间，不改转移；如果压完答案变了，几乎一定是遍历方向或临时变量的问题。

## 复杂度怎么估：状态数乘转移代价

DP 的时间几乎总是两个数相乘：**有多少个状态**，**每个状态要看多少个前置状态**。

- 爬楼梯：n 个状态，每个看 2 个，O(n)；
- 0-1 背包：n × W 个状态，每个看 2 个，O(nW)；
- LIS 的 O(n²) 版：n 个状态，每个看前面 n 个，O(n²)；
- 编辑距离：m × n 个状态，每个看 3 个，O(mn)。

所以优化 DP 只有两条路：**减少状态数**（换定义、去掉无用维度、用性质压缩状态），或者**减少每个状态的转移代价**（前缀最大值、二分、单调队列）。LIS 从 O(n²) 降到 O(n log n)，走的就是第二条：不再回头看所有 j，而是二分找位置。

估复杂度时先数状态，再数转移。状态数超过 10^7 就要警惕内存；转移里再套一层循环，通常就是超时的来源。先估一遍再写代码，比写完跑挂了再回头找要省事。

## 什么时候不该用 DP

DP 有明确的适用边界，越界硬套只会得到又慢又难懂的代码。

- **没有重叠子问题**：归并排序、二叉树遍历、二分查找，每个子问题只出现一次，记忆化没有收益，反而多一张表。
- **状态爆炸**：旅行商问题的状态是"已访问集合 + 当前位置"，规模 2^n × n；n=30 就已经不现实。状态数本身就是算法上限。
- **贪心可证明最优**：区间调度、霍夫曼编码、部分找零问题。能证明贪心对，就别写 DP。
- **要列出所有方案**：DP 擅长算"最优值"或"方案数"，把每一种具体方案都输出，输出本身就可能是指数级，应该用回溯。
- **状态有后效性**：当前状态不足以决定未来。比如只记"最大利润"却不知道手里有没有股票，后续买卖就没法判断；这时要补维度（持有/不持有），而不是硬套一维。
- **数据规模按数值增长**：背包容量 10 亿、金额精确到分且范围极大，O(nW) 直接不可行，要考虑贪心近似、数学方法或换问题建模。
- **需要在线回答**：数据一条条到达，必须立刻给出当前最优，而 DP 往往要等整个输入读完才能填表。这类问题要用增量算法或近似，不能套离线 DP。
- **业务代码里的绝大多数需求**：排序、去重、连接、Top K、分页，用排序、哈希表、堆和数据库索引就够了。DP 出现在路径规划、文本相似度、资源分配、序列对齐这类"选择组合"问题上，不是日常默认工具。

## 一个具体例子

用四件物品、容量 5 的 0-1 背包走一遍。物品如下：

| 物品 | 重量 | 价值 |
| --- | --- | --- |
| A | 2 | 3 |
| B | 3 | 4 |
| C | 4 | 5 |
| D | 5 | 6 |

二维表 `dp[i][w]`（行是前 i 件，列是容量 0 到 5）：

```text
i\w   0   1   2   3   4   5
0     0   0   0   0   0   0
A     0   0   3   3   3   3
B     0   0   3   4   4   7
C     0   0   3   4   5   7
D     0   0   3   4   5   7
```

看几个关键格子：

- `dp[2][5]`：不拿 B 是 3，拿 B 则是 `dp[1][2] + 4 = 3 + 4 = 7`，取 7；
- `dp[3][4]`：不拿 C 是 4，拿 C 是 `dp[2][0] + 5 = 5`，取 5；
- `dp[4][5]`：不拿 D 是 7，拿 D 是 `dp[3][0] + 6 = 6`，仍然取 7。

答案是 7。反推拿了哪些：`dp[4][5] == dp[3][5]`，说明没拿 D；`dp[3][5] == dp[2][5]`，没拿 C；`dp[2][5] != dp[1][5]`，说明拿了 B，回到 `dp[1][5-3] = dp[1][2]`；`dp[1][2] != dp[0][2]`，说明拿了 A，回到 `dp[0][0]`。最终是 A + B，重量 5，价值 7。

再用一维数组验证倒序的必要性。处理 A（重 2、价值 3）时：

- 倒序 `w=5,4,3,2`：每个格子读到的 `dp[w-2]` 都还是 0，结果是容量 2 到 5 各为 3，A 只用了一次；
- 正序 `w=2,3,4,5`：`dp[2]=3`，到 `w=4` 时读 `dp[2]` 已经是 3，于是 `dp[4]=6`，等于把 A 拿了两次。

这就是"遍历顺序反了"最直观的后果：代码不报错，答案偏大，而且只有小数据手算才能发现。

一维数组每轮结束后的值（下标 0 到 5）：

```text
初始     0  0  0  0  0  0
处理 A   0  0  3  3  3  3
处理 B   0  0  3  4  4  7
处理 C   0  0  3  4  5  7
处理 D   0  0  3  4  5  7
```

最后一行和二维表的最后一行完全一致。一维版不是另一种算法，只是把用过的行覆盖掉。

## 常见误区

### 误区：状态定义少一维也能凑合

**你以为**：`dp[i]` 表示"前 i 个元素的最优值"就够了，省一维更简单。
**其实**：很多问题的"能不能接上"取决于结尾的具体值或当前是否持有，不是只看前 i 个的最优值。LIS 需要"以 i 结尾"，股票买卖需要"持有/不持有"，编辑距离需要两个字符串的下标。
**怎么验证**：用一个小反例手算。比如 `[2, 5, 3, 4]`，如果按"前 i 个的 LIS"定义，`dp[2]=2`（2、5），到 3 时你不知道前面的结尾是 5，就会错误地认为接不上；正确做法是分别看以 2 和以 5 结尾的两个状态。

### 误区：初始值都填 0 就行

**你以为**：base case 无非是 0，数组初始化成 0 最省事。
**其实**：求最小值时 0 会把"不可达"伪装成"代价为零"；求最大值时 0 可能压过合法的负值；背包用"恰好装满"定义时，只有 `dp[0]=0`，其余必须是负无穷。初始值代表"这个状态是否合法"，不是随便填的占位符。
**怎么验证**：打印第 0 行和第 0 列，逐个问"在没有物品、容量为 0、字符串为空时，这个状态合法吗、值应该是多少"。再构造一个无解的小用例，看程序返回的是"无解"还是一个看似合理的 0。

### 误区：二维表随便按什么顺序填都行

**你以为**：只要每个格子都算一遍，顺序无所谓。
**其实**：`dp[i][j]` 依赖谁，谁就必须先算。0-1 背包一维必须倒序，完全背包必须正序；编辑距离如果压成一行，左上角必须先保存再覆盖。顺序错了不会报错，只会读到初始值。
**怎么验证**：在转移里临时打印依赖的坐标和值，检查每个依赖是否已经是"本轮之前算好的"。更稳的办法是写一个暴力递归做对拍，随机生成几十组小数据比较结果。

### 误区：DP 一定比递归快，所以能用就用

**你以为**：只要把递归改成 DP，性能就会提升。
**其实**：没有重叠子问题时，DP 只是把每个子问题算一遍再存起来，白费空间，还可能因为要填满整张表而比递归多算很多无用状态。记忆化还有哈希查找和递归调用的常数开销。
**怎么验证**：先数一数递归树里有没有重复节点。没有重复，直接用分治或普通递归；有重复，再比较记忆化和自底向上的实际耗时，别只看复杂度。

## 小结

动态规划的核心不是背题型，而是四步：把选择写成递归、发现重复、给状态下定义、按依赖填表。状态定义要能用一句话读出来，转移方程看最后一步，base case 决定哪些状态合法，遍历顺序由依赖方向决定，答案位置要回到题目问的那个量。空间压缩是最后一步，先写对二维版。没有重叠子问题、状态爆炸、贪心可证或需要枚举所有方案时，不要用 DP。下一课：当你要列出所有方案而不是只求一个最优值时，该怎么系统地枚举、去重和剪枝。
