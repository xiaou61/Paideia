## 先把结论摆出来

回溯就是**带撤销的深度优先搜索**。它不聪明，但它穷举得有纪律：

```text
做选择 → 递归下一层 → 撤销选择
```

能解决问题的关键不在模板，而在**每一层有哪些选择、什么时候可以提前放弃**。前者决定搜索树长什么样，后者决定你是秒出还是超时。

三个判断：

- 问题要求**列出所有方案**（排列、组合、子集、棋盘）→ 优先想到回溯；
- 只要求**最优值**，且子问题重叠 → 先看动态规划（上一篇）；
- 搜索树大到无法穷举 → 必须有**剪枝**，否则换什么写法都救不了。

## 回溯的模板只有四行

```python
def backtrack(path, choices):
    if 满足结束条件:
        result.append(path.copy())   # 必须拷贝：path 后面还会被改
        return
    for choice in choices:
        if not 可行(choice):
            continue
        path.append(choice)          # 做选择
        backtrack(path, 下一层的 choices)
        path.pop()                   # 撤销选择
```

四处最容易写错：

1. **忘记撤销**：`path.pop()` 漏掉，后面的分支会带着上一条路径继续走；
2. **忘记拷贝**：`result.append(path)` 存的是引用，最后全是空列表或同一条路径；
3. **结束条件位置错**：放在循环里还是循环外，决定会不会重复收集；
4. **下一层的 choices 没变**：组合问题要从 `start` 往后选，排列问题每层都可重头选（但要跳过已用）。

## 排列、组合、子集：三棵不同的树

### 子集

每个元素只有"选 / 不选"两种选择，搜索树是一棵二叉树：

```python
def subsets(nums):
    result = []
    def dfs(start, path):
        result.append(path.copy())
        for i in range(start, len(nums)):
            path.append(nums[i])
            dfs(i + 1, path)
            path.pop()
    dfs(0, [])
    return result
```

`start` 保证不会回头选，所以 `[1,2]` 和 `[2,1]` 不会同时出现。

### 组合

和子集几乎一样，只是**到长度 k 就停**：

```python
def combine(n, k):
    result = []
    def dfs(start, path):
        if len(path) == k:
            result.append(path.copy())
            return
        for i in range(start, n + 1):
            path.append(i)
            dfs(i + 1, path)
            path.pop()
    dfs(1, [])
    return result
```

### 排列

每一层都可以选任意一个没选过的元素，所以要一个 `used` 数组：

```python
def permute(nums):
    result, used = [], [False] * len(nums)
    def dfs(path):
        if len(path) == len(nums):
            result.append(path.copy())
            return
        for i, value in enumerate(nums):
            if used[i]:
                continue
            used[i] = True
            path.append(value)
            dfs(path)
            path.pop()
            used[i] = False
    dfs([])
    return result
```

**三者的区别只在"下一层能选谁"**：子集/组合用 `start` 往后走，排列用 `used` 全范围走。模板是同一个。

## 去重：排序之后跳过同层重复

有重复元素时（比如 `[1,1,2]` 求子集），不处理会得到重复结果。标准做法是**先排序**，然后在同一层跳过相同的值：

```python
for i in range(start, len(nums)):
    if i > start and nums[i] == nums[i - 1]:
        continue          # 同一层里，相同的值只选第一个
    ...
```

注意判断是 `i > start`（同一层）而不是 `i > 0`。后者会把"不同层但值相同"也跳过，导致漏解。

## 剪枝：提前承认"这条路没戏"

剪枝就是在进入递归之前判断：**当前状态下，还有没有可能得到合法解/更优解**。没有就返回。

### 可行性剪枝

组合求和：从 `[2,3,6,7]` 里找和为 7 的组合。如果当前和已经超过目标，再往下加只会更大：

```python
if current_sum > target:
    return
```

更狠一点：先把候选排序，循环里一旦 `current_sum + nums[i] > target` 就 `break`，因为后面的更大。

### 最优性剪枝

求"最少需要几个数"时，如果当前步数已经不小于已知最优解，就没必要继续：

```python
if steps >= best:
    return
```

### 搜索顺序剪枝

先试"更可能成功"的分支，能更早拿到一个好答案，从而让最优性剪枝更早生效。比如找零钱时先试大面额。

**剪枝不是玄学**：每一刀都要能说清"为什么剩下的分支不可能更好"。说不清就先别剪，剪错了会漏解，而且很难测出来。

## 一个具体例子：N 皇后

在 n×n 棋盘上放 n 个皇后，任意两个不能同行、同列、同对角线。

```python
def solve_n_queens(n):
    result = []
    cols, diag1, diag2 = set(), set(), set()

    def dfs(row, board):
        if row == n:
            result.append(["".join(r) for r in board])
            return
        for col in range(n):
            if col in cols or (row - col) in diag1 or (row + col) in diag2:
                continue
            cols.add(col); diag1.add(row - col); diag2.add(row + col)
            board[row][col] = "Q"
            dfs(row + 1, board)
            board[row][col] = "."
            cols.remove(col); diag1.remove(row - col); diag2.remove(row + col)

    dfs(0, [["."] * n for _ in range(n)])
    return result
```

三个集合就是三把剪枝刀：同列、主对角线（`row - col` 相同）、副对角线（`row + col` 相同）。不加它们，8 皇后要试 8^8 种摆法；加上之后，搜索树小到可以瞬间跑完。

**注意 `row` 是递增的**，所以"同行"天然不可能重复，不需要第四个集合。

## 复杂度怎么估

回溯的时间复杂度 = **搜索树的节点数 × 每个节点的处理代价**。

- 子集：2^n 个节点；
- 排列：n! 个节点；
- 组合：C(n,k) 个节点；
- N 皇后：上界 n!，剪枝后远小于它。

空间复杂度 = **递归深度 × 每层保存的状态**，通常 O(n)。`path`、`used`、棋盘这些都要算进去。

面试里说"回溯是指数级"是对的，但更重要的是说清**指数底数是什么、剪枝把哪些分支砍掉了**。

## 什么时候不该用回溯

- **只要最优值，且子问题重叠**：用 DP。比如爬楼梯、背包，回溯会重复算大量子问题；
- **数据规模大到指数级不可接受**：先想有没有贪心、二分、图算法等多项式解法；
- **需要"所有方案"但方案数量本身是指数级**：先确认业务真的需要全部，而不是只要前 k 个或计数。

## 常见误区

### 误区：回溯就是递归，会递归就会回溯

**你以为**：只要函数自己调自己，就是回溯。
**其实**：回溯的关键是**做选择与撤销选择成对出现**，以及每层枚举候选。普通递归（比如求阶乘）没有"撤销"这一步。
**怎么验证**：在 `path.append` 后打印 path、在 `pop` 后再打印一次，两次输出必须对称回到上一层。

### 误区：结果不对就加个 Set 去重

**你以为**：重复结果用 `Set` 包一层最省事。
**其实**：`Set` 只能去掉完全相同的最终结果，不能阻止搜索树里重复的分支。输入一变大，重复分支仍然指数级增长，只是最后被 Set 吞掉。
**怎么验证**：在递归入口打印当前 path，看同一个中间状态是否被访问了多次；是的话该在"选谁"这一层剪，而不是在结果层去重。

### 误区：剪枝越多越快，能剪就剪

**你以为**：多写几个 `if` 提前 return，总不会错。
**其实**：剪枝条件写错会**漏掉合法解**，而且测试用例往往发现不了——它只是少返回几个结果，不报错。
**怎么验证**：先写无剪枝版本，用小规模随机输入对比两版结果集合；完全一致再加下一个剪枝。

### 误区：回溯和 DP 可以随便互换

**你以为**：都能解决"从多个选择里找答案"的问题，用哪个都行。
**其实**：回溯枚举所有方案，DP 利用重叠子问题求最优值。把 DP 题写成回溯通常直接超时；把"列出所有方案"的题写成 DP 又表达不了方案本身。
**怎么验证**：看题目要的是"所有方案"还是"一个最优值"；再看递归树里同一个子问题是否被反复访问。

## 小结

回溯的骨架是"做选择 → 递归 → 撤销"，排列/组合/子集的差别只在下一层能选谁。去重靠排序 + 同层跳过相同值；剪枝靠能说清理由的可行性/最优性判断。复杂度要按搜索树节点数和每层代价估，指数级问题先确认有没有多项式解法，再决定要不要穷举。
