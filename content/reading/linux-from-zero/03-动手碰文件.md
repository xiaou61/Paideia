## 这一关在解决什么

`ls`、`cp`、`mv`、`rm` 这四个命令你大概都敲过，但 `ls -l` 那七列每一列是什么意思、`cp` 什么时候会**默默覆盖**你的文件、`rm` 为什么连回收站都没有——这些不清楚，就会在某个下午丢掉不该丢的东西。

这一关的目标是：**看一行 `ls -l` 就能判断"这个文件谁能改、上次什么时候被动过"，并且删东西之前知道自己在删什么。**

## 为什么没有回收站

因为 Linux 的目录项就是"名字 → inode 编号"的映射，文件内容在 inode 里。`rm` 做的是**删掉这条映射并减一次链接计数**，计数归零时空间才被释放。中间没有任何"暂存区"这一层。

这不是设计缺陷而是选择：服务器上大量文件是程序产生的临时数据，"删了还能恢复"意味着要一直占着空间。代价是**删除不可逆**，只能靠备份和习惯来防。

## 讲解

### `ls -l` 的七列，逐列读

```text
$ ls -l /etc/hostname /etc/nginx /usr/bin/python3
-rw-r--r--  1 root root     12 Oct 12 09:30 /etc/hostname
drwxr-xr-x  2 root root   4096 Oct 20 11:02 /etc/nginx
lrwxrwxrwx  1 root root      9 Sep 30 10:15 /usr/bin/python3 -> python3.12
```

从左到右：

| 列 | 例子 | 含义 |
| --- | --- | --- |
| 类型+权限 | `-rw-r--r--` | 第一位是类型：`-` 普通文件、`d` 目录、`l` 软链接、`s` socket、`p` 管道 |
| 链接数 | `1` | 硬链接数量；目录这一列是子目录个数 + 2 |
| 属主 | `root` | 这个文件归谁 |
| 属组 | `root` | 归哪个组 |
| 大小 | `12` | 字节数；目录显示的是**目录项本身**的大小，不是里面文件总和 |
| 修改时间 | `Oct 12 09:30` | 默认显示 mtime；超过半年会显示年份 |
| 名字 | `/etc/hostname` | 软链接会带 `-> 目标` |

权限位第 04 关专门讲。这里先记住一件事：**目录的大小不是它占的空间**，看目录多大要用 `du -sh 目录`。

`ls` 的常用组合：

| 命令 | 用途 |
| --- | --- |
| `ls -lh` | 人类可读的大小（`12K`、`1.2M`） |
| `ls -la` | 含隐藏文件，看清有没有 `.env` |
| `ls -lt` | 按修改时间倒序——**看"刚改了什么"最有用** |
| `ls -lS` | 按大小倒序 |
| `ls -ld 目录` | 只看目录本身，不列内容 |
| `ls -lR` | 递归列出（大目录别用） |

### 建目录：`mkdir -p`

```text
$ mkdir -p /data/app/logs /data/app/conf
```

`-p` 做两件事：**缺的父目录一起建**，以及**目录已存在时不报错**。所以脚本里建目录一律带 `-p`，可以放心重复执行（幂等）。

### 复制：`cp` 的三个前提

```text
$ cp app.conf app.conf.bak          # 目标不存在 → 复制成新文件
$ cp app.conf /etc/myapp/           # 目标是已存在的目录 → 放进去，叫 /etc/myapp/app.conf
$ cp -r conf/ /etc/myapp/conf/      # 目录要 -r
$ cp -a /data/app /backup/          # -a：连权限、属主、时间一起保留
```

三条最容易踩的：

- **`cp` 默认静默覆盖。** `cp a b` 里 `b` 已存在时不会问一句，内容直接没了。加 `-i` 会问，加 `-n` 会跳过已存在的。建议在自己的 `.bashrc` 里给 `cp`、`mv`、`rm` 加别名（第 17 关有写法）。
- **目录结尾有没有 `/` 影响结果**：`cp -r src /backup`（`/backup` 不存在）会把 `src` 复制**成** `/backup`；`cp -r src /backup/`（`/backup` 已存在）会在里面建 `/backup/src`。前者常见于"本想备份到目录，结果把目录本身覆盖了"。
- **不带 `-a` 时属主会变成你自己。** 用 `sudo cp` 备份系统文件，备份出来的文件属主是 root——以后普通用户改不了它。

### 移动与改名：`mv`

`mv` 同时干两件事：换路径、换名字。没有单独的 `rename`。

```text
$ mv app.log app.log.2026-10-29     # 改名
$ mv *.log /data/logs/              # 移动一批
$ mv -i a b                         # 已存在时先问
```

一个必须知道的行为：**同一块磁盘内 `mv` 是瞬时的**（只改目录项，文件内容一个字节都不动）；**跨磁盘 `mv` 会变成"复制 + 删源"**，大文件会很慢，而且中途断电可能出现半个文件。想判断是不是跨盘：`df /源路径 /目标路径` 对比设备名。

### 删除：`rm`

```text
$ rm a.txt
$ rm -r build/          # 目录要 -r
$ rm -rf build/         # -f 不提示、不存在也不报错
$ rm -i important.txt   # 逐个确认
```

三条纪律，都是从事故里换来的：

1. **先 `ls` 再 `rm`。** 把命令里的 `rm -rf` 换成 `ls -ld` 先跑一遍，看清匹配到哪几个路径，再删。
2. **变量一定加引号。** `rm -rf $DIR/` 在 `DIR` 为空时会变成 `rm -rf /` 附近的东西。正确写法是 `rm -rf "${DIR:?}"`——`${VAR:?}` 在变量为空时报错退出。
3. **文件名以 `-` 开头**时，会被当成参数。用 `./` 或 `--`：`rm -- -weird.txt`。

`-f` 是个容易被滥用的小开关：它的作用是"不提示、不存在也当成功"。**批量删除时它反而危险**，因为它让"路径拼错"和"删成功"看起来一模一样。删之前不确定就先去 `-f`。

### 软链接与硬链接：`ln`

```text
$ ln -s /opt/app/current/bin/run /usr/local/bin/run    # 软链接（-s）
$ ln /data/a /data/b                                    # 硬链接（少用）
```

- **软链接（symbolic link）**是一个独立的小文件，内容是"目标路径字符串"。目标删了它就断（`ls -l` 里显示红色）。可以跨文件系统、可以指向目录。
- **硬链接（hard link）**是给同一个 inode 起第二个名字。它和原文件完全平级，删一个另一个还在，**不能跨文件系统、不能指向目录**。

判断自己该用哪种：想"给一个长路径起个短名字"，用 `ln -s`；想"同一份内容有两个名字"，才用硬链接。

读软链接的目标有三个办法，各有用途：

```text
$ ls -l /usr/local/bin/run         # 显示 -> /opt/app/current/bin/run
$ readlink /usr/local/bin/run      # 只打印目标
$ readlink -f /usr/local/bin/run   # 一路解析到底的真实路径，脚本里最实用
```

`readlink -f` 会把中间所有软链接都解开。判断"这个链接到底指向哪"时用它，不会看错一层。

### 找文件：`find`

`find` 和通配符不是一回事：**通配符由 shell 展开当前目录，`find` 自己递归遍历**。找深层文件必须用 `find`。

```text
$ find /var/log -name "*.log"                 # 按名字
$ find / -type f -size +100M                  # 大于 100MB 的普通文件
$ find /data -mtime -1 -type f                # 最近 1 天内改过的文件
$ find /data -name "*.tmp" -delete            # 找到就删（先不加 -delete 跑一遍）
$ find /data -name "*.log" -exec gzip {} \;   # 对每个结果执行一条命令
```

四个参数够日常用：

| 参数 | 含义 |
| --- | --- |
| `-name` / `-iname` | 名字匹配（`-iname` 忽略大小写） |
| `-type f` / `-type d` / `-type l` | 只要文件 / 目录 / 软链接 |
| `-size +100M` | 大于；`-size -1k` 小于；单位 `k`、`M`、`G` |
| `-mtime -1` | 1 天内改过；`+30` 是 30 天前；`-mmin -30` 按分钟 |

`-exec ... \;` 里的 `{}` 是当前找到的路径，`\;` 是这条命令的结束。也可以用 `-exec ... +` 把结果一次性传给命令（更快），或者用管道交给 `xargs`（第 06 关讲）。

**一个纪律**：`find /` 从头扫全盘，在有几十万文件的机器上要跑几十秒并且很吃 IO。能限定目录就限定，能用 `-maxdepth` 就加：

```text
$ find /var/log -maxdepth 2 -name "*.log"
```

### 看时间戳：`stat`

`ls -l` 只显示 mtime。`stat` 给三个时间：

```text
$ stat app.conf | head -6
  File: app.conf
  Size: 214       Blocks: 8          IO Block: 4096   regular file
Access: 2026-10-29 09:12:40.123456789 +0800
Modify: 2026-10-28 22:03:17.000000000 +0800
Change: 2026-10-29 09:10:02.555555555 +0800
```

| 时间 | 含义 | 什么时候变 |
| --- | --- | --- |
| `Access` (atime) | 最后一次被读 | 读一次变一次（很多系统用 `relatime` 减少写盘） |
| `Modify` (mtime) | 最后一次内容被改 | 写文件时变 |
| `Change` (ctime) | 最后一次 inode 元信息被改 | 改内容、改权限、改属主**都会**变 |

排查"这个文件是不是被人动过"要看 ctime，不是 mtime——`chmod` 只改 ctime，mtime 一点没变，这正是"内容没变但权限被改了"的盲区。

## 常见误区

### 误区：`mv` 一定比 `cp` 快

**你以为**：`mv` 只是改个位置，所以永远很快。
**其实**：同一块磁盘内，`mv` 确实只改目录项，瞬间完成。**跨文件系统时 `mv` 是"完整复制 + 删源"**，和 `cp` 再加 `rm` 是一样的开销，甚至更慢（少了 `cp` 的选项）。把 `/data`（一块盘）的东西 `mv` 到 `/home`（另一块盘）时，几百 G 的数据要跑很久。
**怎么验证**：`df /data /home` 看两个路径的 `Filesystem` 是否相同；不同就是跨盘。

### 误区：`rm` 之后还能用工具恢复

**你以为**：文件级的恢复工具（类似 Windows 的恢复软件）总能捞回来。
**其实**：`rm` 只删目录项，内容块会被标记为可复用；**一旦有新数据写进去，块就被覆盖**，恢复概率随写入量快速下降。在 SSD 上因为 TRIM 的存在，往往是立刻不可恢复。生产环境的正确做法是备份与快照，不是"删错了再救"。
**怎么验证**：在一个临时目录建文件、`rm` 掉、立刻 `dd if=/dev/zero of=fill bs=1M count=200`，再试着用 `grep -a 关键词 /dev/sdX` 找——基本找不回来。

### 误区：软链接占空间，删源文件能省回它的大小

**你以为**：软链接复制了目标的内容。
**其实**：软链接只存一个路径字符串（`ls -l` 的大小就是字符串长度），改目标内容它跟着变，删了目标它就断。真正占空间的是目标本身。反过来，**删掉软链接不会影响目标**——这是新手最担心的一件事，可以放心删。
**怎么验证**：`ln -s /var/log/syslog /tmp/s; ls -l /tmp/s` 显示大小是路径长度；`rm /tmp/s; ls /var/log/syslog` 目标还在。
