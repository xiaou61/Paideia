## 这条线写给谁

写给**会用电脑、但没正经用过 Linux** 的人：命令只会 `cd` 和 `ls`，一看报错就搜，搜到就粘，粘完不知道为什么好了。

也写给**已经天天用 Linux、但只记住了几条命令**的人：`chmod 777` 到底放开了什么、进程为什么 `kill -9` 也杀不掉、`df` 和 `du` 为什么对不上、`sudo` 和 `su` 的区别——这些都在下面讲清楚。

## 和「Linux 排查」是怎么分工的

站点里还有一条「Linux 排查」线，讲的是**机器已经出问题**时按 CPU、内存、磁盘、网络四条线定位。

那条线假设你懂基本命令。这条线反过来：**先把地基讲完，再谈排查**。顺序上建议先看这条，再去看排查；两条不重复，排查线不会重讲 `ls -l` 的每一列。

## 十九关怎么排

分五段，每段解决一类问题：

- **地基（01–05）**：命令行长什么样、文件放在哪、怎么碰文件、权限和用户。这五关决定你后面所有命令是不是"照着背"。
- **组合（06–07）**：管道、重定向、`grep`/`sed`/`awk`。学会把几个小命令拼成一条能解决真问题的命令，这是 Linux 和图形界面最大的差别。
- **运行时（08–10）**：进程、信号、环境变量。程序"启动了但没在跑""换成 systemd 就找不到命令"这类事都归这一段。
- **运维（11–14）**：装软件、把程序变成服务、看日志、磁盘满没满。这一段是你把东西放到服务器上以后每天要用的。
- **联网与自动化（15–19）**：端口与防火墙、SSH、Shell 脚本、定时任务，最后一关把前面全部串起来做一次。

## 一个前提：你需要一台 Linux

不需要买服务器，三种都行：

- **本机 Docker**：`docker run -it --rm ubuntu:24.04 bash`，秒开一个干净环境，练完直接删。
- **WSL2**（Windows）：`wsl --install`，得到一个完整的 Ubuntu。
- **云服务器**：最接近真实，但记得别在上面 `rm -rf` 练手。

**唯一要注意的是**：01–04 关里的"练习破坏性命令"（比如删文件、改权限）请在容器或虚拟机里做。本机要是就是你的开发环境，别拿它练 `chmod -R`。

## 常见误区

### 误区：Linux 命令靠背

**你以为**：学会 Linux 就是记住几百条命令和参数。
**其实**：日常真正常用的命令不到 30 个，参数靠 `--help` 和 `man` 现查。真正要理解的是**几套模型**：一切皆文件、权限三组、进程有父子、输入输出是一条流。模型对了，新命令看一眼就知道大概怎么用。
**怎么验证**：随便挑一个没用过的命令（比如 `stat`），先猜它的参数风格（`-h` 是不是人性化、`-f` 是不是指定格式），再用 `stat --help` 对照。猜对率会随模型建立明显上升。

### 误区：出问题就 `sudo` 一下

**你以为**：报"Permission denied"就是权限不够，加 `sudo` 就对了。
**其实**：`sudo` 是以 root 身份执行，等于把系统所有门都打开。用它掩盖问题会留下两种后患：① 你产生的文件属主变成 root，以后普通用户改不了；② 一个本该被权限挡住的操作（比如误删 `/etc`）真的被执行了。
**怎么验证**：`sudo touch /tmp/x && ls -l /tmp/x` 看属主是 root；再 `sudo -i` 进去，`echo $HOME` 也会变成 `/root`。这就是"在 root 环境里干活"和"用 sudo 干一件事"的区别。

### 误区：容器里的 Linux 和真机一样

**你以为**：在 Docker 里练会了，服务器上照搬就行。
**其实**：容器共享宿主内核，没有 systemd（默认）、没有真实的开机流程、很多内核参数只读、`/proc` 内容也不完整。**权限、管道、进程、文件系统这些完全一样**；systemd、网络配置、磁盘挂载这几关必须上真机（或虚拟机）才算练过。
**怎么验证**：在 Ubuntu 容器里跑 `systemctl status` 会直接报 `System has not been booted with systemd`。这不是你敲错，是容器里没这个进程。
