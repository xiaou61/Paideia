Linux 服务器没有桌面、没有鼠标。你面前的整个系统就是**一个提示符加一行输入**。这一关把"这行提示符在告诉你什么""命令由哪几部分组成""忘了参数去哪查"讲清楚——后面十八关都建立在这上面。

## 为什么是命令行

因为**命令行可以组合**。图形界面里，"找出所有大于 100MB 且昨天之后改过的日志"要靠某个软件的勾选框；命令行里，这是两条命令拼起来，而且同样的拼法可以套到任何条件上。

代价是它不告诉你下一步该点哪。所以要先学会三件事：看提示符、拆命令、查帮助。

## 讲解

### 提示符在说什么

登录后你会看到类似这样一行，光标在末尾等输入：

```text
lzf@web-01:~$
```

它由四段拼起来，每段都有信息：

| 片段 | 含义 | 从哪查 |
| --- | --- | --- |
| `lzf` | 当前用户名 | `whoami` |
| `web-01` | 主机名 | `hostname` 或 `hostnamectl` |
| `~` | 当前目录，`~` 是家目录的缩写 | `pwd` |
| `$` | 普通用户；**`#` 表示你是 root** | `id -u`（0 就是 root） |

最后那个符号值得单独记：看到 `#` 就说明你现在的每条命令都会以最高权限执行。很多"一失手把系统弄坏了"的事故，第一现场都是提示符是 `#` 而人没注意。

### 一条命令由什么组成

```text
命令名  [短选项]  [长选项]  [参数]
ls      -l         --all     /etc
```

三条规则覆盖了 90% 的情况：

- **短选项**是一个减号加一个字母，可以合起来写：`ls -lh` 等于 `-l -h`。
- **长选项**是两个减号加一个单词：`--help`、`--color=auto`。长选项更好读，也更好搜。
- **参数**是要操作的对象，通常是路径或名字。参数里的空格必须用引号包起来：`mkdir "my notes"`。

### 先把这台机器看清楚

四条命令，登录后第一件事就该跑：

```text
$ whoami; id; hostname; date
lzf
uid=1000(lzf) gid=1000(lzf) groups=1000(lzf),27(sudo)
web-01
Wed Oct 29 15:04:11 CST 2026
```

`id` 那行信息量最大：`uid=1000` 是用户编号（root 固定是 0），`gid` 是主组，`groups` 是加入的所有组——`sudo` 就在里面，说明这个账号能提权。

再看系统和跑了多久：

```text
$ uname -a
Linux web-01 6.8.0-45-generic #45-Ubuntu SMP PREEMPT_DYNAMIC ... x86_64 GNU/Linux
$ uptime
 15:05:02 up 12 days,  3:41,  2 users,  load average: 0.08, 0.12, 0.09
```

`uname -a` 依次是：内核名、主机名、内核版本、构建信息、架构。`uptime` 的 `load average` 三个数字是 1、5、15 分钟的平均负载，第 08 关会细讲。

### 忘了参数怎么办

**先 `--help`，再 `man`，最后才是搜。** 这两个都是本机自带的，比搜索快，而且版本一定对得上。

```text
$ ls --help | head -5
Usage: ls [OPTION]... [FILE]...
List information about the FILEs (the current directory by default).

$ man ls
```

`man` 打开的是完整手册，里面按固定的几段写：`NAME`（一句话说明）、`SYNOPSIS`（用法格式）、`DESCRIPTION`（每个参数什么意思）、`EXAMPLES`（例子，最有用的一段）、`SEE ALSO`（相关命令）。

`man` 里的操作和 `less` 一样：空格翻页、`/关键词` 搜索、`q` 退出。第一次进去出不来是正常现象，按 `q`。

手册分了 8 卷，同名的东西可能在不同卷里：

| 卷 | 内容 | 例子 |
| --- | --- | --- |
| 1 | 普通命令 | `man 1 printf` |
| 2 | 系统调用 | `man 2 open` |
| 3 | 库函数 | `man 3 printf` |
| 5 | 文件格式 | `man 5 passwd` |
| 8 | 管理命令 | `man 8 mount` |

比如 `printf` 在 1 卷和 3 卷都有，直接 `man printf` 给你的是 1 卷（shell 命令）。想看 C 函数要写 `man 3 printf`。

不确定命令叫什么时，用 `man -k` 按关键词搜所有手册的一句话说明：

```text
$ man -k "copy files"
cp (1)               - copy files and directories
```

### 快捷键：这五个能省掉大量时间

| 按键 | 作用 |
| --- | --- |
| `Tab` | 补全命令名、路径、参数。按两下列出所有候选 |
| `↑` / `↓` | 翻历史命令 |
| `Ctrl+R` | 反向搜索历史，输几个字母就找回上次那条长命令 |
| `Ctrl+C` | 中断当前命令 |
| `Ctrl+L` | 清屏（等于 `clear`，但不清历史） |

`Tab` 补全是其中最值钱的一个：它不仅省打字，还**帮你确认路径拼对了**——补不出来就说明这个文件不存在。

### 读懂三类最常见的报错

新手期 90% 的错误就这三种，认出来就不用搜：

| 报错 | 真正含义 | 先查什么 |
| --- | --- | --- |
| `command not found` | 这个命令不在 `PATH` 里的任何目录 | 拼写；是否装了；`which 命令名` |
| `No such file or directory` | 路径不存在（可能是文件名大小写不同） | `ls` 一下上一级目录 |
| `Permission denied` | 文件在，但你没这个权限 | `ls -l` 看属主与权限；是不是要 `sudo` |

注意第一种和第二种的区别：`bash: nginx: command not found` 是**程序没找到**；`cat: /etc/ngnix.conf: No such file or directory` 是**文件没找到**。前者查安装，后者查路径。

## 常见误区

### 误区：提示符里的 `~` 就是根目录

**你以为**：`~` 看着像"最顶层"，应该等于 `/`。
**其实**：`~` 是**当前用户的家目录**，普通用户是 `/home/用户名`，root 是 `/root`。切用户后 `~` 会指向不同地方——这正是 `sudo -i` 之后"文件怎么跑到 `/root` 下了"的原因。
**怎么验证**：`echo ~` 和 `pwd` 对比；`sudo -i` 之后再 `echo ~`，会变成 `/root`。

### 误区：`Ctrl+C` 会把系统停掉

**你以为**：`Ctrl+C` 是关机或重启。
**其实**：它只是给**当前前台命令**发一个中断信号（`SIGINT`），等于告诉程序"停下来"。它不影响系统，也不影响后台进程。关掉终端窗口才可能连带杀掉该终端里起的进程（这也正是 `nohup` 存在的原因）。
**怎么验证**：跑 `sleep 100`，按 `Ctrl+C`，提示符立刻回来；再跑 `sleep 100 &` 放后台，按 `Ctrl+C` 按不掉它，要用 `jobs` 看到它再用 `kill`。

### 误区：命令拼错会有提示，不会真执行

**你以为**：打错了系统会拦住。
**其实**：`rm -rf /tmp/bulid` 这种拼写错误不会报错——它只会"找不到/tmp/bulid"，什么也不删，看起来像成功。危险的是反向情况：**参数里多一个空格**，`rm -rf /tmp /build` 就从"删一个目录"变成"删两个"。执行破坏性命令前，先去掉 `-f` 跑一遍看它要动什么。
**怎么验证**：`rm -rf /tmp/不存在的目录` 退出码是 0（成功）；`rm -r /tmp/不存在的目录`（去掉 -f）才会报 `No such file or directory`。
