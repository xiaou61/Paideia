## 这一关在解决什么

Windows 有 C 盘、D 盘，Linux 只有**一棵树**，最上面是 `/`。这一关把"东西都放在哪"和"怎么描述一个位置"讲清楚。不然后面每次看到 `/var/lib/docker`、`/etc/systemd/system` 都只是死记路径。

## 为什么是一棵树

因为**挂载**。Linux 的磁盘不是 C/D/E 各自一棵树，而是把一块磁盘"挂"到这棵树的某个目录上。插一块新盘到 `/data`，之后往 `/data` 里写文件就写到了那块盘上——对程序来说路径永远是 `/data/x`，换盘不用改代码。

这条设计带来一个后果，也是新手最容易懵的地方：**同一块空间可能出现在两个路径下**，或者"看起来有文件却访问不到"（被挂载覆盖了）。第 14 关讲磁盘时会碰到。

## 讲解

### 每个目录装什么（FHS）

这不是约定俗成，是 **FHS**（Filesystem Hierarchy Standard）标准，发行版都照它放东西：

| 目录 | 装什么 | 你要不要动 |
| --- | --- | --- |
| `/` | 树根 | 不动 |
| `/bin`、`/sbin` | 基本命令、管理命令。现代发行版里是指向 `/usr/bin` 的软链接 | 不动 |
| `/etc` | **配置文件**，几乎全是纯文本 | 要改，改前先备份 |
| `/home/用户名` | 普通用户的家目录 | 你的地盘 |
| `/root` | root 的家目录 | 只在 `sudo -i` 后在里面 |
| `/var` | **会变大的数据**：日志 `/var/log`、数据库文件、缓存、队列 | 要监控大小 |
| `/tmp` | 临时文件，**重启会被清空** | 随手用 |
| `/usr` | 已安装的程序与库：`/usr/bin` 命令、`/usr/lib` 库、`/usr/local` 自己装的 | 装软件会写 |
| `/opt` | 第三方整套软件（一个目录装一个产品） | 可选 |
| `/proc` | **内核的虚拟文件系统**，不占磁盘 | 只看 |
| `/sys` | 内核与设备的虚拟文件，同理 | 只看 |
| `/dev` | 设备文件，如 `/dev/sda`、`/dev/null` | 一般不动 |
| `/boot` | 内核与引导文件 | 不动 |
| `/srv`、`/mnt`、`/media` | 服务数据、临时挂载点、可移动介质 | 视情况 |

两条最实用的推论：

- **配置在 `/etc`，数据在 `/var`。** 所以"备份一台服务器"通常是备份 `/etc` 加 `/var` 里指定的业务目录，而不是整盘。
- **`/proc` 和 `/sys` 不占磁盘。** `df` 统计不到它们，删不掉，读出来的都是内核实时状态（第 08、14 关会用到）。

### 绝对路径与相对路径

- **绝对路径**从 `/` 开始：`/etc/nginx/nginx.conf`。不管你现在在哪，它指向同一个文件。
- **相对路径**不从 `/` 开始：`nginx/nginx.conf`。它相对**当前目录**解释。

脚本里、配置文件里、定时任务里，**一律用绝对路径**。因为这些东西运行时的工作目录不受你控制（第 10、18 关都会踩）。

三个特殊符号：

| 符号 | 含义 |
| --- | --- |
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `~` | 当前用户的家目录 |

于是 `cd ../../etc` 是"上两级，再进 etc"。`.` 的用处比看上去大：`cp a.txt ./` 是"复制到当前目录"，`./run.sh` 是"执行当前目录下的 run.sh"（第 10 关解释为什么必须写 `./`）。

### 走路的四条命令

```text
$ pwd
/home/lzf
$ cd /var/log
$ pwd
/var/log
$ cd nginx           # 相对路径：/var/log/nginx
$ cd ..              # 回到 /var/log
$ cd -               # 回到上一次所在的目录
/etc/systemd/system
```

`cd` 不带参数等于 `cd ~`。`cd -` 在两个目录之间来回跳，改配置时很好用（在 `/etc/nginx` 和日志目录之间来回）。

`pwd` 有两个容易忽略的点：`pwd` 给的是**逻辑路径**，`pwd -P` 给的是**解析掉软链接后的真实路径**。如果你 `cd` 进了一个软链接目录，两者会不一样：

```text
$ ln -s /var/log /tmp/loglink
$ cd /tmp/loglink && pwd
/tmp/loglink
$ pwd -P
/var/log
```

排查"我明明在这个目录，怎么改的不是那个文件"时，`pwd -P` 是第一个要跑的。

### 通配符：一次选中一批

`*`、`?`、`[]`、`{}` 由 **shell**（不是命令）展开，所以对任何命令都有效：

| 写法 | 匹配 | 例子 |
| --- | --- | --- |
| `*` | 任意长度任意字符（不含 `/`） | `*.log` 所有日志 |
| `?` | 恰好一个字符 | `app?.log` → `app1.log`、`app2.log` |
| `[abc]` | 其中一个字符 | `app[12].log` |
| `[0-9]` | 一个范围 | `access.log.[0-9]` |
| `{a,b}` | 两个备选（逗号隔开，**展开成两条**） | `cp a.txt{,.bak}` |

最后那条是常用技巧：`cp a.conf{,.bak}` 等价于 `cp a.conf a.conf.bak`。

两个坑：

- `*` **不匹配以点开头的隐藏文件**。`ls *` 看不到 `.env`，`ls -a` 才看得到。
- 匹配不到时，多数 shell 会把 `*.log` **原样**传给命令，于是报 `No such file or directory: '*.log'`。看到路径里带着 `*` 出现在报错里，就是这个原因，不是命令不支持通配符。

### 隐藏文件与 `ls -a`

Linux 里"隐藏"不是属性，只是**文件名以 `.` 开头**。所以 `.bashrc`、`.ssh`、`.env` 都是隐藏文件。

`ls -a` 会连 `.` 和 `..` 一起列出来；`ls -A` 列出隐藏文件但不含这两个。日常用 `ls -la` 看得最全。

## 常见误区

### 误区：`/proc` 里有一堆文件，得清一清

**你以为**：`ls /proc` 看到几百个数字目录和一堆文件，可能占了不少空间。
**其实**：`/proc` 和 `/sys` 是**内核在内存里现编的**，不占磁盘。里面的数字是进程号，读文件等于问内核当前状态，写文件等于改内核参数。`df -h` 里根本不会列它们。
**怎么验证**：`cd /proc && ls`；再 `df -h /proc` 会提示 `proc` 文件系统总大小 0。

### 误区：路径里的 `..` 会先"跳到真实目录"再退回

**你以为**：`cd /a/link/..` 里的 `..` 指的是 `/a`。
**其实**：如果 `link` 是指向 `/x/y` 的软链接，`cd /a/link` 之后你的逻辑位置是 `/a/link`，`..` 就到 `/a`；而 `pwd -P` 显示的真实位置是 `/x/y`，那里的 `..` 是 `/x`。**两种"上一级"不是同一个目录**，这就是"改错文件"的经典成因。
**怎么验证**：`ln -s /var/log /tmp/ll; cd /tmp/ll; pwd; pwd -P; cd ..; pwd`，最后一步会回到 `/tmp`。

### 误区：`/tmp` 可以当长期存储

**你以为**：把上传的临时文件、数据库 socket 放 `/tmp` 没问题。
**其实**：多数发行版用 `systemd-tmpfiles` 定期清理 `/tmp`（默认 10 天，Debian 系更短），重启也会清空。放在那里的东西随时可能消失。
**怎么验证**：`ls /usr/lib/tmpfiles.d/` 看清理策略；`systemctl status systemd-tmpfiles-clean.timer` 看清理任务下次什么时候跑。
