## `cd ..` 和 `cd -` 差的不是一级

```text
$ cd ~/Downloads
$ pwd
/home/lzf/Downloads
$ cd ..
$ pwd
/home/lzf
$ cd -
/home/lzf/Downloads
$ pwd
/home/lzf/Downloads
```

这是 bash 的标准形态。这台机器是 Windows，没有 Linux 环境，下面不是本机输出。重点在 `cd -` 打印的那一行：它不是「上一级」，是「上一次所在目录」。`..` 是路径里的父目录，`-` 是 shell 记在 `OLDPWD` 里的旧位置。两者只有在刚 `cd ..` 完时看起来一样，再走几步就会分叉。

第一次用就报 `cd: OLDPWD not set`，不是命令坏了，是这个 shell 还没有上一个目录。

后面就按一台装了 nginx 的机器走：下载目录是 `~/Downloads`，配置在 `/etc/nginx`，日志在 `/var/log/nginx`。

## 一棵树，和挂在树上的盘

Linux 没有 C:、D:。所有路径从 `/` 开始，磁盘是挂到这棵树上的。`/data` 可以是根盘上的普通目录，也可以是一块单独硬盘的挂载点；对程序来说都只是 `/data`。

```text
$ ls /
bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
```

这是常见的顶层布局，具体条目会随发行版和容器镜像变。`/bin`、`/sbin`、`/lib` 在很多现代发行版上只是指向 `/usr` 的软链接；用 `ls -ld /bin /sbin` 看本机是不是这样，不要背。

挂载有一个容易忽略的后果：挂载点原来的内容会被遮住。你往 `/data` 里放的文件，如果后来在 `/data` 上挂了另一块盘，看到的就是新盘的内容；旧文件还在根盘的那个目录里，但通过 `/data` 已经看不到了。第 14 篇讲 `findmnt` 和 `df` 时会再碰到。

## 每个目录装什么

FHS（Filesystem Hierarchy Standard）是大多数发行版遵循的布局约定，不是内核强制。下面这些位置够你读懂常见的报错和文档：

| 目录 | 放什么 | 你要不要动 |
| --- | --- | --- |
| `/` | 树根 | 不动 |
| `/bin`、`/sbin` | 基本命令、管理命令；很多现代发行版合并到 `/usr/bin`、`/usr/sbin` | 不动 |
| `/etc` | 本机配置，几乎都是纯文本 | 要改，改前备份 |
| `/home/用户名` | 普通用户家目录 | 你的地盘 |
| `/root` | root 的家目录；常见 700 | 普通用户没有 x 时进不去 |
| `/var` | 会增长的数据：`/var/log` 日志、`/var/lib` 状态、`/var/cache` 缓存、`/var/spool` 队列 | 监控大小 |
| `/tmp` | 临时文件；很多发行版是 1777（人人可写 + sticky） | 随手用，别长期存 |
| `/run` | 本次启动以来的运行时数据，常见 PID 文件和 socket | 只看 |
| `/usr` | 包管理器安装的程序、库、头文件；`/usr/local` 给本地安装 | 装软件会写 |
| `/opt` | 整套第三方软件，一个产品一个目录 | 视情况 |
| `/proc`、`/sys` | 内核和设备的虚拟文件系统，不占磁盘 | 只看 |
| `/dev` | 设备文件，如 `/dev/null`、`/dev/sda` | 一般不动 |
| `/boot` | 内核、initramfs、引导配置 | 不动 |
| `/srv`、`/mnt`、`/media` | 服务数据、临时挂载点、可移动介质 | 视情况 |

两条实用推论：

- 配置在 `/etc`，会变的数据在 `/var`。很多服务器的备份清单就是 `/etc` 加上业务自己的数据目录，而不是整盘。
- `/proc`、`/sys` 不是磁盘上的文件。`df -h` 默认会略过不少虚拟文件系统，`df -a` 才列全；里面的数字是进程号，读文件是在问内核状态。

## 绝对路径、相对路径，以及 `..` 的真实身份

绝对路径从 `/` 开始：`/etc/nginx/nginx.conf`。相对路径从当前目录算：`nginx/nginx.conf`。cron、systemd、CI 脚本启动时的工作目录各不相同，所以脚本里写绝对路径最稳。

三个符号：

| 符号 | 含义 |
| --- | --- |
| `.` | 当前目录 |
| `..` | 上一级目录 |
| `~` | 当前用户的家目录，由 shell 展开 |

`~` 只在 shell 里展开；写在引号里、或者传给不经过 shell 的程序，它就是一个普通字符。`./run.sh` 里的 `./` 也不是装饰：当前目录默认不在 `PATH` 里，不写 `./` 就找不到脚本（第 10 篇讲 `PATH`）。

从 `/var/log/nginx` 回 `/etc` 要上三级：

```text
$ cd /var/log/nginx
$ cd ../../../etc
$ pwd
/etc
```

少一个 `..` 会到 `/var/etc`，不是 `/etc`。这类错误不会报「路径写错」，只会报后面那个文件不存在。

`..` 还有一个更隐蔽的分叉。bash 的 `cd` 默认按逻辑路径处理，`cd /a/link` 之后 `cd ..` 回 `/a`；但 `pwd -P` 会告诉你 `link` 实际指向 `/x/y`。如果你用 `cd -P /a/link` 进去，shell 记的是 `/x/y`，再 `cd ..` 就去 `/x`。两个「上一级」不是同一个目录。

更要注意：普通程序不是 bash。`cat /a/link/../note.txt` 由内核解析路径：先跟 `link` 到 `/x/y`，再把 `..` 解析成 `/x`，读的是 `/x/note.txt`，不是 `/a/note.txt`。脚本里别用带软链接的 `..` 猜路径；先 `readlink -f` 或 `realpath` 看真实目标。

`pwd` 和 `pwd -P` 的差别也在这里：

```text
$ ln -s /var/log /tmp/loglink
$ cd /tmp/loglink
$ pwd
/tmp/loglink
$ pwd -P
/var/log
```

`pwd` 是 bash 内建，默认报逻辑路径；`pwd -P` 报解析软链接后的物理路径。排查「我明明在这个目录，怎么改的不是那个文件」时，先跑 `pwd -P`。

## 一次选中一批，但别把隐藏文件漏了

`*`、`?`、`[]`、`{}` 由 shell 展开，不是由 `ls` 或 `cp` 展开。`*` 不跨 `/`，也不匹配以 `.` 开头的名字：

```text
$ ls *
app.conf  logs  run.sh
$ ls -a
.  ..  .env  app.conf  logs  run.sh
```

`ls -a` 连 `.` 和 `..` 一起列；`ls -A` 列隐藏文件但不含这两个。日常 `ls -la` 看得最全。

| 写法 | 匹配 | 例子 |
| --- | --- | --- |
| `*` | 任意长度，不含 `/` | `*.log` |
| `?` | 恰好一个字符 | `app?.log` 匹配 `app1.log` |
| `[abc]` | 其中一个字符 | `app[12].log` |
| `[0-9]` | 一个范围 | `access.log.[0-9]` |
| `{a,b}` | 两个备选，展开成两个词 | `cp app.conf{,.bak}` |

`{}` 是 bash/zsh 的 brace expansion，不是 POSIX `sh` 的语法；`cp app.conf{,.bak}` 等价于 `cp app.conf app.conf.bak`，目标存在时照样静默覆盖。

bash 默认在通配符匹配不到时把 `*.log` 原样传给命令，于是报 `No such file or directory: '*.log'`。看到报错里带着 `*`，先想「当前目录没有匹配」，不是命令不支持通配符。zsh 默认会直接报 `no matches found`，行为不一样。

## 还差的

- 这台机器没有 Linux 环境，`cd -`、`pwd -P`、`..` 的行为是按 bash 手册写的；zsh、fish、`sh` 的细节可能不同。
- 挂载只讲了「会遮住原目录」这一层，bind mount、overlay、mount namespace 没展开，`/proc/self/mountinfo` 也没读。
- `/tmp` 的清理策略没在具体发行版上核对。不同发行版可能不同：有的用 systemd-tmpfiles 按年龄清，有的把 `/tmp` 挂成 tmpfs，重启就没；用 `findmnt /tmp` 和 `/usr/lib/tmpfiles.d/tmp.conf` 确认自己的机器。
- FHS 对容器镜像不总成立，精简镜像可能没有 `/sbin`、`/lib` 这些目录。
