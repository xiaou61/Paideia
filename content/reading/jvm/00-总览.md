## 这条线是什么

Java 课里那篇《JVM 内存与 GC》讲的是**概念**：堆/栈放什么、GC 是什么。这条线接着往下走，只讲**出事时怎么看**：

- 进程被 OOM Killer 杀了，怎么区分是堆满还是堆外；
- GC 频繁但堆不大，问题出在哪；
- `jstat` 输出里哪几个数字是真正该看的；
- 内存"泄漏"在 Java 里到底长什么样。

## 四篇的走法

1. **内存结构：堆之外还有三块**：堆、元空间、线程栈、直接内存——OOM 有四种，报错文本能直接告诉你是哪一种；
2. **GC 怎么选**：分代假设、G1 / ZGC 的取舍，以及"该不该调"；
3. **GC 日志怎么读**：从一次 Full GC 倒推是"对象太多"还是"回收太慢"；
4. **泄漏与类加载**：`jmap` / `jstat` / `jstack` 的分工，以及最常见的三种泄漏。

## 一个前提

假设你写过 Java、知道对象在堆上分配。不要求读过收集器源码，也不要求会调 JVM 参数——真正常用的参数就那五六个，第四篇会列。

**对着自己的服务读**：先跑一次 `jstat -gcutil <pid> 1000`，看能不能读懂那几列。

## 常见误区

### 误区：OOM 就是堆内存不够，加 `-Xmx`

**你以为**：`OutOfMemoryError` 一律是堆太小。
**其实**：报错文本会告诉你是哪一种——`Java heap space` 是堆，`Metaspace` 是类元数据，`unable to create native thread` 是线程栈，`Direct buffer memory` 是堆外。加堆对后三种完全无效，甚至更糟。
**怎么验证**：出事时先抄下异常信息的第一行，再对照自己的启动参数。

### 误区：GC 调优是必须做的事

**你以为**：上线前要把 JVM 参数调好。
**其实**：现代收集器（G1/ZGC）的默认值已经很好。绝大多数服务只需要设 `-Xmx`/`-Xms` 相等、开 GC 日志。为了"优化"去改一堆参数，通常是在给一个别处的问题（比如对象分配太频繁）打补丁。
**怎么验证**：先看 GC 日志里停顿是否真的影响到了业务指标，再决定动不动。
