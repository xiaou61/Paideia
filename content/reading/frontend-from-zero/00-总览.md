## 这条线写给谁

写给**能照着教程拼出一个页面、但说不清每一步为什么**的人。

如果你有过下面这些时刻，这条线就是为你排的：

- 改了 CSS 没反应，只能靠 `!important` 碰运气；
- 从接口拿到数据后不知道该放在哪，于是满页面找 `innerHTML`；
- 别人说「这个要用状态驱动」，你听懂了字，但不知道和直接改 DOM 差在哪；
- 本地 `npm run dev` 一切正常，部署上去白屏。

## 为什么前端值得单独学

因为前端的难点从来不是"写页面"，而是**两套东西同时在动**：浏览器有一套自己的渲染与事件模型，你的应用有一套自己的数据与状态。所有"玄学 bug"都出在这两套模型的接缝上——事件绑在了会被替换掉的节点上、状态改了但视图没重画、CSS 优先级算错了层。

把这两套模型分开看清楚，前端就变成一件很确定的事：**数据变了，让界面跟着变**。

## 十二关怎么排

- **看懂（01–05）**：浏览器从地址栏到像素做了什么（01）、HTML 表达结构（02）、CSS 的盒模型与层叠（03）、Flex/Grid 怎么排版（04）、响应式与移动端（05）。这一段决定你后面所有"为什么没生效"能不能自己解释。

## 一个前提

需要三样东西：

```text
node -v      # 20 以上
npm -v       # 跟着 node 一起来
```

外加一个现代浏览器（Chrome / Edge / Firefox）和任意编辑器。**不需要**先学框架、不需要买课程、不需要装一堆插件。

每一关的示例都可以直接在浏览器里跑：新建一个 `index.html`，双击打开就是你的实验台。

## 常见误区

### 误区：前端就是 HTML + CSS，JavaScript 是附加的

**你以为**：页面是写出来的，JavaScript 只是加点特效。
**其实**：今天的前端应用里，**结构往往由数据决定**。列表有几行、按钮是禁用还是可点、加载时显示什么，都是 JavaScript 算出来的；HTML 只提供容器与语义。
**怎么验证**：随便打开一个你常用的网站，DevTools 里禁用 JavaScript 再刷新——大部分应用会变成空白或"请启用 JavaScript"。

### 误区：框架是必学的第一步

**你以为**：先学 React，再回头补基础。
**其实**：框架只是把"数据变 → 界面变"这件事自动化。不懂 DOM 与事件，你无法判断问题出在框架还是浏览器；不懂 CSS 层叠，`className` 写了不生效你只能猜。这条线先把浏览器那套讲清楚，第 10 关才引入组件。

### 误区：样式写了没生效，是浏览器有 bug

**你以为**：`color: red` 写上了，页面不变，肯定是缓存。
**其实**：九成是**选择器没选中**、**被更高优先级覆盖**、或者**样式表没加载**。这三件事在 DevTools 的 Elements → Styles 面板里都有确定答案：被划掉的规则、命中的选择器、404 的请求，一眼能看出来。
**怎么验证**：选中元素，看右侧 Styles：划掉的规则前面会显示是谁覆盖的；如果你的规则根本没出现，说明选择器没匹配上。
