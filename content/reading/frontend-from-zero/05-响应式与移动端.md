## 这一关在解决什么

"手机上打开全乱了"通常不是某一个样式写错，而是三个前提没设对：

1. 没有 viewport，手机按 980px 的桌面宽度渲染；
2. 用了固定宽度，屏幕窄了就横向滚动；
3. 字号、点击目标、间距按鼠标设计，手指点不中。

这一关把这三件事一次讲清，并给出"先流式、再断点"的顺序——大部分页面不需要写很多媒体查询。

## 讲解

### 第一件事：viewport

```html
<meta name="viewport" content="width=device-width, initial-scale=1" />
```

没有它，移动浏览器会假装自己有 980px 宽，把整个页面缩小塞进屏幕：字变得极小、点什么都点不中。加上之后，`width: 100%` 才真的是屏幕宽度，`@media (max-width: ...)` 才会按设备宽度触发。

### 第二件事：让宽度自己流

优先用相对单位与自动分配：

```css
.container { width: min(100% - 32px, 1120px); margin-inline: auto; }
.grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(240px, 1fr)); gap: 16px; }
.title { font-size: clamp(1.25rem, 2.5vw, 1.75rem); }
```

- `min(100% - 32px, 1120px)`：小屏留 16px 边距，大屏最宽 1120px；
- `auto-fill + minmax`：列数跟着容器走；
- `clamp(最小, 理想, 最大)`：字号随视口缩放，但有上下限。

这三样覆盖了大多数"响应式"需求，**一行媒体查询都不用写**。

### 第三件事：断点只处理"结构变化"

媒体查询留给"布局结构真的需要换"的地方，而不是每个尺寸都调一遍：

```css
@media (min-width: 768px) {
  .nav { display: flex; }      /* 小屏是纵向菜单，大屏才横向 */
}
```

常用断点（不是标准，只是惯例）：

| 宽度 | 大致对应 |
| --- | --- |
| `< 640px` | 手机 |
| `640–1024px` | 平板 / 小笔记本 |
| `> 1024px` | 桌面 |

写 `min-width` 从小到大叠加（mobile-first），比写一堆 `max-width` 更好维护：基础样式是手机，宽屏只做加法。

### 触控目标与字号

- 可点区域至少 **44×44px**（Apple HIG）或 48×48px（Material）。图标按钮要加 padding，不能只靠图标本身；
- 正文至少 16px，输入框字号小于 16px 时 iOS 会自动放大页面；
- 间距留够，手指比鼠标粗得多。

这些是可用性底线，不是"优化"。

### 图片与溢出

```css
img { max-width: 100%; height: auto; display: block; }
```

`max-width: 100%` 防止图片撑破容器；`height: auto` 保持比例。表格、代码块、长 URL 是三大溢出源，给容器加 `overflow-x: auto` 比让整页横向滚动好。

### 怎么验证

不要只拖浏览器窗口——DevTools 的设备模拟（Toggle device toolbar）会同时改 viewport 与触控，更接近真机。重点看三件事：

1. 有没有横向滚动条；
2. 文字是否小于 16px；
3. 按钮是否点得中（用鼠标在模拟器里点，别用真实鼠标的精度去判断）。

## 常见误区

### 误区：响应式就是多写几个媒体查询

**你以为**：每个屏幕尺寸写一套样式。
**其实**：大部分适配靠流式布局完成；媒体查询只处理"结构要变"的少数点。堆媒体查询会让样式成倍增长，而且总有没覆盖到的宽度。
**怎么验证**：把浏览器从 320px 慢慢拖到 1600px，如果中间某些宽度明显错位，说明基础布局不是流式的。

### 误区：`width: 100vw` 等于屏幕宽度

**你以为**：`100vw` 就是可视宽度，最准。
**其实**：在有纵向滚动条时，`100vw` 包含滚动条宽度，会比可用宽度大，导致横向滚动。用 `width: 100%` 或 `min(100%, ...)` 更稳。
**怎么验证**：页面出现横向滚动条时，检查是否有元素用了 `100vw` 或固定宽度。

### 误区：小屏就是把大屏缩小

**你以为**：桌面版等比缩小就是移动版。
**其实**：缩小后字太小、按钮太密、悬浮菜单没法悬停。移动端常常要改变结构（侧栏变抽屉、表格变卡片），这是媒体查询真正该做的事。
**怎么验证**：在 360px 宽度下只用拇指操作一遍主流程——能不能点到、看不看得清。

## 带走一句

**先让布局流起来（min/clamp/auto-fill），再用断点处理结构变化**——响应式是布局方式的后果，不是媒体查询的数量。
