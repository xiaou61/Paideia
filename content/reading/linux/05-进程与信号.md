## 先把结论摆出来

`kill -9` 不是"强一点"，而是**完全不同的语义**：

| 信号 | 行为 | 什么时候用 |
| --- | --- | --- |
| `SIGTERM`（15） | 请求退出，进程可以清理、保存、关闭连接 | **默认首选** |
| `SIGKILL`（9） | 内核直接终止，进程没有任何机会 | 15 无效时 |
| `SIGHUP`（1） | 传统上表示"重载配置" | 多数守护进程支持 |
| `SIGINT`（2） | 等价于 Ctrl+C | 前台调试 |

`-9` 的代价：临时文件不删、正在写的文件留半截、数据库事务不回滚、连接没有 FIN、消息队列的正在处理消息没有 ack。**这些后果往往比"进程没退"更麻烦。**

## 进程状态：先看它在干什么

```text
$ ps -eo pid,ppid,stat,%cpu,%mem,cmd --sort=-%cpu | head
```

`STAT` 列第一位是关键：

| 状态 | 含义 | 能杀吗 |
| --- | --- | --- |
| `R` | 正在运行 | 能 |
| `S` | 可中断睡眠（等事件） | 能 |
| `D` | **不可中断睡眠**（等 IO） | **不能**，连 -9 也没用 |
| `Z` | 僵尸 | 已经死了，等父进程回收 |
| `T` | 被暂停 | 需要先 `-CONT` |

**`D` 状态是最容易踩的坑**：磁盘坏了、NFS 挂了，进程会卡在 `D`，`kill -9` 毫无效果，只能等 IO 超时或重启机器。此时 `ps` 看到它还在，`top` 看到它占着 CPU 的等待时间。

## 僵尸进程：死不掉的是父进程的锅

```text
$ ps -eo pid,ppid,stat,cmd | awk '$3 ~ /Z/'
```

僵尸进程（`Z`）已经执行完、只留一个进程表条目等父进程读退出码。它**不占 CPU、不占内存**，只占一个 PID。

**为什么杀不掉**：它已经死了，没有东西可杀。真正要处理的是**父进程**——父进程不调 `wait()` 回收，僵尸就一直在。

- 父进程正常时：它应该自己回收；
- 父进程有 bug：僵尸越积越多，最终耗尽 PID；
- **解法**：修父进程，或重启父进程（僵尸随之被 init 接管并回收）。

## 找出谁在占着端口

```text
$ ss -lntp | grep :8080
LISTEN 0 128 0.0.0.0:8080 0.0.0.0:* users:(("java",pid=1234,fd=45))
```

或者：

```text
$ lsof -i :8080
$ fuser 8080/tcp
```

**注意**：`ss -p` 需要 root 或有权限的用户，否则看不到进程名。

## 优雅停机的正确做法

对一个 Java 服务：

```text
$ kill -15 <pid>      # 发 SIGTERM
# 观察日志，等它自己退
$ ps -p <pid>         # 还在？
$ kill -9 <pid>       # 等够了再强杀
```

Spring Boot 支持优雅停机：

```yaml
server:
  shutdown: graceful
spring:
  lifecycle:
    timeout-per-shutdown-phase: 30s
```

它会停止接收新请求、等手上的请求处理完再退出。**没有这个配置时，`-15` 也可能直接切断正在处理的请求。**

## 一个具体的排查

```text
# 现象：重启服务报 "Address already in use"
$ ss -lntp | grep :8080
LISTEN 0 128 *:8080 *:* users:(("java",pid=9876,fd=45))

# 确认是老进程
$ ps -p 9876 -o pid,etime,cmd
  PID     ELAPSED CMD
 9876       02:15:33 java -jar app.jar

# 优雅停
$ kill -15 9876
$ sleep 5
$ ss -lntp | grep :8080 || echo "已释放"
```

**不要上来就 `kill -9`**：如果是数据库连接池，强杀会让连接留在服务端的 `Sleep` 状态，占用连接数直到超时。

## 常见误区

### 误区：kill -9 是最保险的停服务方式

**你以为**：反正要重启，-9 一步到位。
**其实**：它会跳过所有清理：临时文件残留、连接未关闭、正在写的文件损坏、消息未 ack。用 `-15` 等一会儿通常就退了。
**怎么验证**：给一个写文件的服务发 `-9`，检查文件是否留下半截内容。

### 误区：进程还在就说明它活着

**你以为**：`ps` 能看到就是正常运行。
**其实**：`Z`（僵尸）和 `D`（卡在 IO）都在 `ps` 里，但都不干活。要看 `STAT` 列。
**怎么验证**：`ps -eo stat` 过滤出 Z 与 D 状态的进程。

### 误区：端口占用一定是老进程没退

**你以为**：`Address already in use` 就是上一个实例还在跑。
**其实**：也可能是别的程序占了这个端口，或者是 TIME_WAIT 的连接（虽然 TIME_WAIT 通常不影响新监听）。先 `ss -lntp` 看清是谁。
**怎么验证**：`lsof -i :<port>` 看进程名与启动时间。
