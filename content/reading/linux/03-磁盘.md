## 先把结论摆出来

`df` 说磁盘满了，但 `du` 加起来远远没到——**这是三种真实故障，不是工具错了**：

1. **有文件被删了，但进程还开着它**：空间要等进程关闭才释放；
2. **inode 用完了**：文件很小但数量极多，块还有空但建不了新文件；
3. **挂载点遮蔽**：一个目录被别的文件系统挂载盖住，原来的文件还在但看不见。

按这三条依次排，九成的问题能定位。

## df 与 du 统计的东西不同

| 命令 | 统计什么 |
| --- | --- |
| `df -h` | 文件系统**已分配的块**（从超级块读） |
| `du -sh` | 目录里**可见文件**的实际大小（遍历目录算） |

`df` 是"账本上花了多少"，`du` 是"我能看见的东西加起来多少"。两者对不上，说明有"账上有、看不见"的东西——正好对应上面三种情况。

## 情况一：被删除但仍被打开的文件

```text
$ df -h /
Filesystem  Size  Used Avail Use%
/dev/vda1    40G   39G  1.0G  98%

$ du -sh /var/log
120M    /var/log
```

差了几个 GB。找元凶：

```text
lsof +L1
```

输出里 `NLINK` 为 0 的条目就是"链接数为 0（已删除）但仍被打开"的文件。常见于：

- 日志文件被 `rm` 了，但应用还开着文件描述符（`logrotate` 配置不对的典型后果）；
- 大量写入的临时文件被删了但进程没关。

**解法**：重启那个进程，或者用 `: > /proc/<pid>/fd/<n>` 清空（不是删除）。

**预防**：日志用 `logrotate` 的 `copytruncate`，或者让应用自己按大小滚动。

## 情况二：inode 用完

```text
$ df -i /
Filesystem   Inodes    IUsed   IFree IUse%
/dev/vda1   2621440  2621440      0  100%
```

块还有空间，但 inode 没了——**建不了任何新文件**。表现是"磁盘没满却写不进去"，报 `No space left on device`。

找哪个目录文件最多：

```text
for d in /var/* /tmp /home/*; do
  echo "$(find $d -xdev 2>/dev/null | wc -l) $d"
done | sort -nr | head
```

典型成因：

- 会话文件、缓存小文件（比如 PHP 的 session、大量缩略图）；
- 邮件队列堆积；
- 某个程序疯狂建临时文件没清。

**解法**：清掉那些小文件；长期方案是调整目录结构或改用对象存储。

## 情况三：挂载点遮蔽

```text
mount | grep /data
/dev/vdb1 on /data type ext4
```

如果先把文件写进 `/data`，之后才把 `/dev/vdb1` 挂到 `/data`，原来的文件就被"盖住"了——`du /data` 看不到它们，但空间仍被占用。

判断方法：`df /data` 和 `df /data/..` 的 `Used` 差异，或者把挂载卸掉看空间是否回来（**生产上别随便卸载**）。

**预防**：挂载写进 `/etc/fstab`，开机就挂上，避免"先写后挂"。

## 一个排查的顺序

```text
1. df -h           → 哪个分区满了
2. df -i           → inode 是否耗尽
3. du -sh /* 2>/dev/null | sort -h | tail   → 哪个目录大
4. lsof +L1        → 有没有被删除但仍打开的文件
5. 对比 df 与 du   → 差得大就回到第 4 步
```

**先看 inode 再看块**：`df` 报满但 `du` 正常时，`df -i` 往往一眼就看出问题。

## 常见误区

### 误区：rm 了文件空间就回来了

**你以为**：删文件就释放磁盘。
**其实**：只要还有进程开着那个文件，块就不会释放。日志文件被删了但应用没重启，是线上磁盘涨满的最常见原因之一。
**怎么验证**：`rm` 一个大文件前后对比 `df -h`；若没变，`lsof +L1` 找持有者。

### 误区：磁盘满一定是文件太多太大

**你以为**：清掉大文件就好。
**其实**：可能是 inode 耗尽——几百万个小文件把 inode 用完了。
**怎么验证**：`df -i` 看 IUse% 是否 100%。

### 误区：`du -sh /` 和 `df` 应该相等

**你以为**：两者不一致说明有 bug。
**其实**：它们统计的对象不同（可见文件 vs 已分配块），不一致是常态——差异本身就是排查线索。
**怎么验证**：在一个干净目录 `touch` 一个文件再删掉，观察两者是否都无变化。
