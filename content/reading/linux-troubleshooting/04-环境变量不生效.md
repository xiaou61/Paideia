## 场景

`start.sh` 读取 `$APP_PORT` 写启动信息，但执行后 `out.txt` 里是：

```text
port=
```

`config/.env` 明明写着 `APP_PORT=8080`。原因是：**`.env` 不会自动加载**。文件里的一行 `KEY=VALUE` 只是文本，除非有人把它读进当前 shell。

## 先想清楚

两种正解：

**一、运行前加载（不改脚本）**

```text
set -a
. config/.env
set +a
sh start.sh
```

`set -a` 让加载进来的变量自动 export，子进程（`sh start.sh`）才能看到。

**二、在脚本里加载（更稳）**

```sh
#!/bin/sh
set -a
. "$(dirname "$0")/../config/.env"
set +a
echo "port=$APP_PORT" > out.txt
```

第二种更适合部署：谁调用脚本都不用先记得 source。

注意 `export APP_PORT=8080` 只对**当前 shell 及其子进程**有效；在命令行里 export 完再开一个新终端，就没有了。

## 常见误区

### 误区：`source .env` 之后子进程一定看得到

**你以为**：变量已经在 shell 里了。
**其实**：`source` 只设置当前 shell 的变量；不 `export`，子进程看不到。`set -a` 就是"接下来的赋值都自动 export"。
**怎么验证**：`X=1; sh -c 'echo $X'` 输出空；`export X=1` 后同样命令输出 1。

### 误区：在 `.bashrc` 里写了就全局生效

**你以为**：所有脚本都能读到。
**其实**：`.bashrc` 只对交互式 bash 生效；systemd、cron、CI 启动的进程不读它。部署脚本应该自己显式加载配置。
**怎么验证**：用 `cron` 跑一个依赖 `.bashrc` 变量的脚本，看变量是否为空。

### 误区：`.env` 里的引号与空格随便写

**你以为**：`APP_PORT = 8080` 也能用。
**其实**：`KEY=VALUE` 的等号两边不能有空格（否则会被当成命令）；值里有空格或特殊字符要加引号。不同工具的解析规则还不完全一样。
**怎么验证**：写一行带空格的赋值，`source` 看是否报 `command not found`。

## 带走一句

**`.env` 是文本，不是环境变量**——要么运行前 `set -a` 加载，要么让脚本自己 source，二者都要 export 才能传给子进程。
