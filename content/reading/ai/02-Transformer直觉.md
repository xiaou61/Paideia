## 不除 √d_k，五个候选的平均最大权重是 0.93

我照论文写了 `softmax(Q @ K.T) @ V`，第一次跑忘了除 `√d_k`。当时的假设是「这会导致 exp 溢出，得加个减 max 的写法」。量了一下不是：`d_k=64` 的单个样本里最大 logit 才 15.4，最大的 `exp` 是 4.7e6，float64 要到 1.8e308 才溢出，差着约 300 个数量级。减 max 那两句（下面代码里已经写了）本来就该有，但它在 `d_k=64` 时什么都救不了——它避的是溢出，我遇到的不是溢出。

塌的是分布：

```python
import numpy as np

rng = np.random.default_rng(20261119)


def softmax(z):
    z = z - z.max(axis=-1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=-1, keepdims=True)


for d in (8, 16, 32, 64, 128):
    raw, sc, st = [], [], []
    for _ in range(200):
        q, k = rng.standard_normal((5, d)), rng.standard_normal((5, d))
        S = q @ k.T
        st.append(S.std())
        raw.append(softmax(S).max(axis=1).mean())
        sc.append(softmax(S / np.sqrt(d)).max(axis=1).mean())
    print(f"d_k={d:<3} std(q.k) {np.mean(st):5.2f}   maxP raw {np.mean(raw):.3f}   scaled {np.mean(sc):.3f}")

S64 = rng.standard_normal((5, 64)) @ rng.standard_normal((64, 5))
print("d_k=64 单个样本：max logit %.1f  max exp %.1e" % (S64.max(), np.exp(S64).max()))
```

```text
d_k=8   std(q.k)  2.77   maxP raw 0.723   scaled 0.457
d_k=16  std(q.k)  3.94   maxP raw 0.805   scaled 0.464
d_k=32  std(q.k)  5.53   maxP raw 0.859   scaled 0.463
d_k=64  std(q.k)  7.64   maxP raw 0.897   scaled 0.459
d_k=128 std(q.k) 10.96   maxP raw 0.929   scaled 0.463
d_k=64 单个样本：max logit 15.4  max exp 4.7e+06
```

Python 3.11.5 / numpy 2.4.6，本机跑出来的。`q`、`k` 的每个分量取独立标准正态，每次 5 个候选、跑 200 次取平均。

`raw` 那一列随着 `d_k` 变大一路爬到 0.929，`scaled` 那一列停在 0.46 附近不动。这就是 `1/√d_k` 干的事：**把 logits 的尺度从 `d_k` 里摘出去**，让 softmax 的陡峭程度不随维度变。

为什么是 `√d_k` 不是 `d_k`：`q·k = Σ q_i k_i`，`d` 个独立乘积相加，方差是 `d`、标准差是 `√d`。上面 `std(q.k)` 那一列实测 2.77 → 10.96，理论 `√8=2.83`、`√128=11.31`，偏低是每次只取 25 个样本再平均的抽样误差。除完标准差回到 1 附近，一行里 5 个候选的 logits 差个 ±1，softmax 才落在「有偏好但不极端」的地方。换成乘 `1/d` 会跑到另一头：每行都接近均匀，谁跟谁都一样，注意力等于没做。

顺带把两个旋钮对上：`softmax(S/√d_k)` 和 `softmax(S/T)` 是同一个式子，`1/√d_k` 等于给每层注意力写死一个温度 `√d_k`（`d_k=64` 时是 8）。API 上那个 `temperature` 除的也是 logits，只是发生在输出层而不再每层做一遍。「温度低更确定、温度高更发散」在注意力的尺度上是同一件事，只是你没得调——它是写死在结构里的。

至于 `temperature=0` 时服务商内部是不是严格取 argmax，那是实现，我没核过任何一家的代码或文档。能确定的是：从 `softmax(S/T)` 这个式子推不出「同一个请求两次调用逐字节相同」——批大小、GPU 上的归约顺序、fp16 累加顺序都能让并列的两个候选换位。要可复现，去查有没有 seed 参数，然后自己跑两次比对。

## 第 1 行把 0.9999 给了最后一个 token

先把三个字母对上号再往下看：`q` 是这个位置在问什么，`k` 是每个位置能提供的线索，`q·k` 大表示这条线索对得上；那一行 softmax 出来的是权重；输出是 `Σ p_j v_j`，`v` 是每个位置提供的内容。`Wq/Wk/Wv` 三个 `d×d` 矩阵做的是把同一个输入向量投进三个不同的空间。

还是那 5 个 token：`他 说 他 不 来`。第 0 和第 2 个是同一个字，这一节故意不加位置编码，所以它们拿到的东西完全相同。

```python
D = 64
IDS = [0, 1, 0, 2, 3]                  # 他 说 他 不 来：第 0、2 个位置是同一个字
rng = np.random.default_rng(2)


def ln(x):                             # 每行 LayerNorm，模仿进 attention 之前的归一化
    return (x - x.mean(axis=1, keepdims=True)) / (x.std(axis=1, keepdims=True) + 1e-5)


def ent(p):
    return -(p * np.log(p + 1e-30)).sum(axis=-1)


def qkv(x, seed=7, d=D):
    r = np.random.default_rng(20261119 + seed)
    Wq, Wk, Wv = (r.standard_normal((d, d)) / np.sqrt(d) for _ in range(3))
    return x @ Wq, x @ Wk, x @ Wv


E = ln(rng.standard_normal((4, D)))    # 4 个不同的字，每个字一个向量
X = E[IDS]
Q, K, V = qkv(X)                       # 还没有位置编码：Q/K/V 只由字本身决定
S = Q @ K.T
P_raw, P_sc = softmax(S), softmax(S / np.sqrt(D))

print("raw    P[1]", np.round(P_raw[1], 4))
print("scaled P[1]", np.round(P_sc[1], 4))
print("raw    maxP", np.round(P_raw.max(axis=1), 4), " H", np.round(ent(P_raw), 3))
print("scaled maxP", np.round(P_sc.max(axis=1), 4), " H", np.round(ent(P_sc), 3))

j = int(np.argmin(P_raw[1]))           # 第 1 行权重最小的那个位置
Vp = V.copy()
Vp[j] += 1.0                           # 把这个位置的 V 整体挪一个单位
print("poke V[%d]: raw %.2e  scaled %.2e" % (
    j,
    np.linalg.norm((P_raw @ Vp)[1] - (P_raw @ V)[1]),
    np.linalg.norm((P_sc @ Vp)[1] - (P_sc @ V)[1])))
```

```text
raw    P[1] [0.     0.     0.     0.     0.9999]
scaled P[1] [0.1259 0.078  0.1259 0.1458 0.5244]
raw    maxP [0.6038 0.9999 0.6038 0.4997 0.9526]  H [0.785 0.001 0.785 0.698 0.198]
scaled maxP [0.2858 0.5244 0.2858 0.3562 0.4045]  H [1.543 1.34  1.543 1.383 1.397]
poke V[1]: raw 1.92e-06  scaled 6.24e-01
```

三件事能直接读出来：

- `raw` 的 `P[1]` 是 `[0. 0. 0. 0. 0.9999]`。第 1 个位置（「说」）把全部重量压在最后一个 token 上，它这一行的输出几乎就是 `V[4]` 本身，前四个 `V` 一点都没读进来。`scaled` 把同一行摊成 `[0.126 0.078 0.126 0.146 0.524]`，五个 `V` 都进来了一点。
- 同一张矩阵里 `raw` 的 `maxP` 是 `[0.6038 0.9999 0.6038 0.4997 0.9526]`，**不是每行都塌**。塌不塌看那一行的 logits 跨度，所以「漏了缩放」不会五行一起报警：有一行已经 0.9999，另两行还在 0.5 附近，你可能就这么上线了。
- 把第 1 行权重最小的位置（`V[1]`）整体挪 1.0，`raw` 下输出只动 `1.92e-06`，`scaled` 下动 `0.624`，差 32 万倍。这不是「权重小一点」，是这个位置的 `V` 对输出没有贡献。反传时它的梯度也按同一个权重缩，`1e-6` 的系数基本学不动。**「softmax 太尖」的实际后果是某些位置白给**——这句话在这里有一个能复现的数字。

必须说清的一点：这个玩具里第 1 行偏偏看最后一个 token，**没有任何语义**。`Wq/Wk/Wv` 是固定种子的随机矩阵，这个偏好是随机数算出来的，不是模型认为「说」和「来」有关系。这篇文章能给你机制和可复现的数字，给不了「注意力学到了什么」——那个得拿真模型的权重和探针来看。

## 两个「他」的输出一模一样

先给一个不靠直觉的测法：把 5 个 token 打乱成 `[4, 0, 2, 3, 1]` 再算一遍，跟「先算完再打乱」比，最大差 `6.7e-16`——浮点误差。输入换顺序，输出只是跟着换顺序，数值一个不差。

所以「他 说 他 不 来」里的两个「他」，`q/k/v` 三组向量完全相同，两行的权重也完全相同，输出距离是 `0.0e+00`。模型手里没有「第一个他」和「第三个他」，只有一个「他」。要让它知道谁在前谁在后，得把位置信息塞进去：

```python
def pe(npos, d):
    pos = np.arange(npos)[:, None]
    i = np.arange(d // 2)[None, :]
    w = 1.0 / (10000.0 ** (2 * i / d))
    out = np.zeros((npos, d))
    out[:, 0::2] = np.sin(pos * w)      # 偶数维 sin
    out[:, 1::2] = np.cos(pos * w)      # 奇数维 cos，与前一维共享 w
    return out, w.ravel()


PE, W = pe(5, D)
print(np.round(PE[:5, :6], 4))
print("cycle/pos  w0 %.2f  w1 %.2f  w31 %.0f" % (2 * np.pi / W[0], 2 * np.pi / W[1], 2 * np.pi / W[31]))
print("cos(PE[0]d01,PE[1]d01)=%.6f  cos(w0*1)=%.6f" % (PE[0, :2] @ PE[1, :2], np.cos(W[0])))
```

这张表里有四个能当判据用的数：

- **pos 0 在每一对维度上都是 `[0, 1]`**（`sin 0=0`、`cos 0=1`），64 维上是同一张脸。位置 0 的编码不含任何「第几」的信息，它是个特例。
- **`w(0)=1`，一个周期只要 6.28 个位置**；`w(1)=0.7499`，周期 8.38；`w(31)=1.334e-04`，周期 47,117。同一个向量里，前几对维度每个位置转一大圈，最后几对维度慢到 4096 个位置才走完它周期的 8.7%（4096/47117）。
- **旋转**：`cos(PE[0]d01, PE[1]d01) = 0.540302`，正好等于 `cos(1)`；换成 `PE[3]` 和 `PE[4]`，差值 1 个位置，还是 `0.540302`。这一对维度的相似度只取决于「差几个位置」，不取决于「在第几个位置」。
- 但**这只对单独一对维度成立**。每一对有自己的 `w`，整条 64 维向量的内积并不只由距离决定。把「正弦编码天生表示相对位置」当成整条向量的性质，是很容易顺手写下去的一句过度概括。

把它加上去，再看那两个「他」：

```python
def attn(x):
    q, k, v = qkv(x, seed=8)
    return softmax(q @ k.T / np.sqrt(D)) @ v


perm = [4, 0, 2, 3, 1]
print("max|perm(out)-attn(perm(X))| = %.1e" % np.abs(attn(X[perm]) - attn(X)[perm]).max())
print("||out0-out2||  no PE %.1e   with PE %.4f" % (
    np.linalg.norm(attn(X)[0] - attn(X)[2]),
    np.linalg.norm(attn(ln(X + PE))[0] - attn(ln(X + PE))[2])))
print("row norm  token %.2f  PE %.2f" % (np.linalg.norm(X[0]), np.linalg.norm(PE[0])))

q, k, v = qkv(X, seed=8)
S_c = np.where(np.triu(np.ones((5, 5)), 1) > 0, -1e30, q @ k.T / np.sqrt(D))
P_c = softmax(S_c)
print("causal P[0]:", np.round(P_c[0], 4), " nnz:", (P_c > 1e-12).sum(axis=1),
      " ||out0-V0||: %.1e" % np.linalg.norm((P_c @ v)[0] - v[0]))

Qh, Kh = q.reshape(5, 4, 16), k.reshape(5, 4, 16)
for h in range(4):
    Ph = softmax(Qh[:, h] @ Kh[:, h].T / 4)[0]
    print("head %d argmax %d maxP %.3f  row %s" % (h, Ph.argmax(), Ph.max(), np.round(Ph, 3)))
```

`no PE` 是 `0.0e+00`，加完变 `0.4220`——同一个字的两个位置终于不是同一个东西了。顺带一行数字值得记住：词向量这一行的范数 8.00，位置编码 5.66。**位置编码不是「附带一个序号」，它注入的能量和词向量同一个量级**，这也是原论文直接把它加到词向量上就能工作的原因。

## 因果掩码：第 0 行只有一个合法位置

上面那段输出里有两行是掩码的：

- `causal P[0]: [1. 0. 0. 0. 0.]`，每行合法位置数是 `[1 2 3 4 5]`。
- 第 0 行的输出和 `V[0]` 的差是 `0.0e+00`。第一个位置的输出完全没混合，就是它自己的 `V`。

这里有一句被讲歪的话要掰正：**注意力本身不分方向**。「每个 token 去看它前面所有的 token」有两处不准。

一是**含自己**：因果掩码下第 `i` 个位置能看的是 `0..i`，所以第 0 行有 1 个合法位置而不是 0 个。按「只看前面」理解，会以为它看不到自己，读第 0 行输出等于 `V[0]` 时会以为出了 bug。

二是**双向是合法的**：BERT 那类编码器两侧都看，差的就是这个掩码。方向是 decoder 为了「不许从未来抄答案」做的配置，不是注意力机制的性质。判断一个实现属于哪种有个笨办法：数每行的合法位置数，`1,2,3,4,5` 是因果，`5,5,5,5,5` 是双向。

最后四行是 4 个头、每个 16 维。第 0 行的 `maxP` 是 `0.255 / 0.327 / 0.410 / 0.385`，四个头里三个 argmax 在第 0 位、一个在第 3 位——形状确实不一样。但得老实说：**从权重里读不出「这个头管指代、那个头管语法」**。你能观察到的只有「头与头不同、尖度不同」。要把头和功能连起来，得做消融（剪掉一个头看指标掉多少）或者探针分类器，这篇没做。

还有一件顺手能看见的事：每个头里第 0 和第 2 个位置的权重完全相等（`0.255/0.255`、`0.327/0.327`……），因为这里喂进去的 `X` 还是没加位置编码的那份。上一节那个 `0.0e+00` 在这张表里又出现了一次。

## 症状 → 先看哪

| 症状 | 先量什么 | 判据 |
| --- | --- | --- |
| 每行权重几乎均匀，等于 1/长度 | logits 的标准差 | 缩放后应在 1 附近；接近 0 说明 Q/K 被 LN 压平，或者把「除以 √d」写成了「乘 √d」 |
| 每行几乎 one-hot，熵接近 0 | 有没有漏 1/√d_k，以及 d_k 多大 | d_k=128、5 个候选、漏缩放时平均最大权重 0.929，不漏时 0.463 |
| 同一个字出现两次，两行输出完全一样 | 位置编码有没有进到 Q/K/V 的输入里 | 距离 0.0e+00 就是没进去（正弦 PE 加进去后本文测到 0.4220） |
| 某个位置的 V 改了，输出几乎不动 | 那一行的权重分布 | 权重 0.9999 时把 V 整体挪 1.0，输出只动 1.92e-06 |
| 第 0 行输出跟上下文无关 | 数每行合法位置数 | 因果掩码应为 1,2,3,4,5；第 0 行输出 == V[0] 是正确行为，不是 bug |

这五行没有一行需要「换个更大的模型」。五件事都在你手边三十行 numpy 里能复现。

## 动手

1. 换句子。把 `IDS` 改成 8–10 个 token、其中一个字出现两次，重跑上面那段。`no PE` 那一项应该还是 `0.0e+00`（理论上必然是），然后把 `with PE` 的数记下来——它有多大，决定了位置信息在你这个句子上够不够用。
2. 换候选数。把 `block A` 里的 `(5, d)` 改成 `(20, d)` 再跑，看 `raw` 和 `scaled` 两列的差距是拉大还是缩小。我猜是拉大，但这只是猜，你自己跑出来的才算。
3. 换位置编码。把 `pe()` 换掉，改成对 `q`、`k` 按维度对旋转（RoPE 的做法，不往输入上加），看「同距离的两行 cos 相等」还成不成立。这篇没做这个实验，所以上面所有关于 PE 的结论只覆盖「加在输入上」这一种。

## 还差的

- **玩具的权重没有语义。** 第 1 行看最后一个 token，是随机矩阵算出来的结果。真模型里「他」跟谁绑定，要看真权重，这篇没有。
- **没测训练好的模型。** 全文的推导前提是「`q`、`k` 分量是独立标准正态」——那是初始化的假设，不是训练后的样子。真实模型的 logits 尺度由训练决定，LN 之后 `q/k` 分量的 std 未必是 1，所以「训练好的模型 softmax 有多尖」这篇没量。`1/√d_k` 那套是「按这个假设会发生什么」的机制，不是对现成模型的测量。
- **只有前向敏感度，没有反传梯度。** poke 那个实验是把 `V` 挪 1.0 看输出动多少，属于有限差分。说「梯度被饿死」严格讲要看不含梯度的 Jacobian 或者真反传，我这里只给了「输出对它的敏感度」。
- **只测了 5 个 token、1 层、4 个头、正弦编码。** 层数叠起来之后权重怎么变、8k 上下文里远距离的权重是不是更小，一个都没测。所以这篇文章没有写「远距离关联变弱」——那句话只能靠测量，而我这里没有数据。
- **没装 torch（按要求）。** 所有数字来自 numpy 2.4.6 手写的三十行，没跟任何库的实现对照过，公式按原论文的 3.2.1（缩放点积注意力）和 3.5（位置编码）手抄。库里的实现可能带 `scale` 参数、可能有 bias、可能用别的数值写法，那些都没验。
