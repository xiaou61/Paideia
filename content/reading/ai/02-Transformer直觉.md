## 先把结论摆出来

不推公式，只记住三句：

1. 每个 token 都会被变成一个向量，表示"它在这个语境里的意思"；
2. **注意力**让每个 token 去看它前面所有的 token，按相关程度加权，更新自己的表示；
3. 模型最后做的是一个极其朴素的事：**预测下一个 token**。重复这个过程，就得到整段回答。

"预测下一个 token"听起来简单，但它意味着模型的目标是"最像的续写"，不是"最正确的结论"——这是理解幻觉的起点。

考虑这句话：

> 小明把书放进背包，因为它太重了。

"它"指的是书还是背包？人靠上下文判断。注意力机制就是让"它"这个位置的表示，能按权重读取前面"书"和"背包"的信息，从而带出"重"更可能指书。

具体做法（直觉版）：

- 每个 token 生成三个向量：**查询（Q）、键（K）、值（V）**；
- 用 Q 和所有 K 算相似度，得到权重；
- 按权重把 V 加权求和，作为这个 token 的新表示。

**"多头"** 就是同时用几组 Q/K/V，各自关注不同类型的关系（语法、指代、位置等），再把结果拼起来。

## 为什么需要位置信息

注意力本身对顺序不敏感：把词打乱，权重计算看不出区别。所以要把位置信息注入进去（位置编码），让模型知道"谁在前谁在后"。

这解释了一个常见现象：**长文本里，距离很远的两段信息关联会变弱**，即使窗口放得下。

## 训练与推理是两件不同的事

- **训练**：用海量文本，让"预测下一个词"的错误变小。参数在这一步确定。
- **推理**：参数冻结，只做前向计算。你调 API 时发生的是推理。

所以：

- 你没法通过对话"教"模型新知识（它不会更新参数）；
- 你能改变的只有**上下文**（提示词、资料、历史）；
- "记忆"功能本质上是把信息存起来，下次再塞回上下文。

## 温度与采样：为什么同样的问题答案不同

模型输出的是一个概率分布，不是唯一答案。采样时：

- **温度低**（接近 0）：更倾向高概率 token，稳定、保守、可能重复；
- **温度高**：更愿意选低概率 token，多样、有创意、也更容易跑偏。

**产品上的默认建议**：

- 抽取、分类、结构化输出：温度 0 或很低；
- 写作、头脑风暴：温度 0.7 左右；
- 代码生成：低温度。

## 为什么它会"自信地编"

模型的训练目标是"生成合理的续写"，不是"只生成有依据的内容"。当上下文里没有答案时，最合理的续写往往是一个**看起来像答案的句子**。

这就是幻觉的机制层解释：

- 它没有"我不知道"的默认动作；
- 它会把相似但不同的东西拼在一起；
- 流畅度与正确性无关。

对策不在模型内部，而在系统设计：给资料（RAG）、要求引用来源、允许回答"不知道"、关键结论做校验。这些是下一篇的内容。

## 常见误区

### 误区：模型"理解"了内容

**你以为**：它像人一样有概念。
**其实**：它建模的是 token 之间的统计关系。表现上很像理解，但边界在于：没有依据时它不会自动停下。

### 误区：上下文里说一遍它就记住了

**你以为**：对话中告诉它一次，之后永远知道。
**其实**：只在本次上下文有效。超出窗口、或新开会话，就没了。

### 误区：温度设 0 就完全确定

**你以为**：0 温度 = 每次一样。
**其实**：多数实现仍有浮点与并行带来的微小差异；需要严格可复现时要看服务商是否支持种子参数。

## 小结

注意力让每个 token 按相关度读取上下文；模型靠"预测下一个 token"训练出来，因此目标是合理而非正确。参数在推理时冻结，能改的只有上下文。幻觉是"合理续写"的必然副产品。下一课：用检索把"依据"补上。
