## 这条线是什么

这条线是**项目式**的实战：给你一个方法签名和一个**只读的测试入口**，你只改自己那个文件，把测试跑绿。

和前面三类实战的区别：

| 形态 | 你交什么 |
| --- | --- |
| SQL 实战 | 一条查询 |
| 调试实战 | 修好的单文件 |
| 读代码实战 | 填空 |
| **项目实战** | **一个可以编译运行的小项目（多文件）** |

测试入口是只读的，所以你没法"改测试让它通过"——它跑的是服务端固定的入口，测试文件与你自己的文件一起编译。

**你的文件固定叫 `Main.java`，类名必须是 `Main`。** 换成别的类名会直接编译失败（这曾是这条线的一个真 bug）。

## 先修理论（不构成门槛）

| 关卡 | 默认先掌握 |
| --- | --- |
| 1 取前 k 个最大的 | 第 3–4 课（循环、数组） |
| 2 解析并报平均 | 第 4、9、13 课（字符串、异常） |
| 3 词频统计 | 第 8、11、12、20 课（Map、hashCode、集合选型、排序） |
| 4 分组求平均 | 第 8、12、13、19 课（Map、集合、异常、数值舍入） |

没上过也能做：测试会一条条告诉你哪种情况没过。先修只是让你少花时间在语法上。

## 四关在练什么

1. **取前 k 个最大的**：把一个看起来简单的需求按边界拆开——空数组、k 超长、k 为 0、重复值；
2. **解析并报平均**：真实输入永远不干净——空串、空白、非数字项、以及"分母为 0"；
3. **词频统计**：`Map` 计数与**两条排序规则的主次**——次数相同时按字母，不能只按次数；
4. **分组求平均**：先过滤非法行，再分组求和计数，最后处理舍入与除零。

四关都用了同一个判据：**先列边界，再写实现**。

## 常见误区

### 误区：能跑通一个正常例子就算写完了

**你以为**：输入 `[5,1,9]`、k=2 跑对了，就完成。
**其实**：测试会打空数组、k 超过长度、k 为 0、有重复值。面试真正在问的是"你想到了几种情况"。
**怎么验证**：写完实现，先不看测试结果，自己把四类边界各列一遍。

### 误区：失败了就改到输出一样

**你以为**：只要能过测试就行。
**其实**：测试打印的是 `fail: <用例名>`，那个名字在告诉你"哪种情况没考虑"。为了过测试而写特判只在这组数据上对。
**怎么验证**：过测试后，自己再加一个边界值跑一遍看是否仍然正确。

### 误区：测试用例名为什么是英文的

**你以为**：作者偷懒没写中文。
**其实**：期望输出要与程序输出**逐字比较**，中文在不同容器/编码下可能出现差异；用例名用 ASCII，判题才稳定。正文该讲清楚的，一个字都没省。
