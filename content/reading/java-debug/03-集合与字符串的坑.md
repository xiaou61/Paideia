## 这一关要练什么

集合的重载陷阱：想按值删元素，却删掉了那个下标上的元素；字符串用 `==` 比内容；边遍历边删同一个集合。

每题给一段**能跑但结果是错的**代码与它应有的输出。改到输出一致就算过，改坏了可以接着改。

## 第 1 题 · 删掉了 id=2，它却还在

**目标**：`List<Integer>` 的 `remove` 有两个重载，传 `int` 删的是下标，按值删要传对象

```code-challenge
{
 "id": "dbg-05",
 "kind": "run",
 "title": "删掉了 id=2，它却还在",
 "language": "java",
 "starter": "import java.util.ArrayList;\nimport java.util.Arrays;\nimport java.util.List;\n\npublic class Main {\n    public static void main(String[] args) {\n        List<Integer> ids = new ArrayList<>(Arrays.asList(5, 2, 9));\n        ids.remove(2);\n        System.out.println(\"size=\" + ids.size());\n        System.out.println(\"ids=\" + ids);\n    }\n}\n",
 "cases": [
  {
   "name": "正确输出",
   "expected": "size=2\nids=[5, 9]\n"
  }
 ],
 "explain": "`ids` 是 `List<Integer>`，它的 `remove` 有两个重载：`remove(int index)` 和 `remove(Object o)`。实参写成 `2` 是 `int`，编译器在**不做装箱就能匹配**的那一步就选中了 `remove(int)`，于是删掉的是下标 2 上的 `9`。想按值删，必须让它匹配 `Object`：`remove(Integer.valueOf(2))`（或 `remove((Object) 2)`）。同样的坑在 `List<String>` 上反过来：`list.remove(0)` 删的是下标 0，想删字符串 `\"0\"` 得写 `remove(\"0\")`。**症状是\"删了，但删错了\"**——数量对得上、内容不对，比抛异常难查得多。"
}
```

**为什么**：`ids` 是 `List<Integer>`，它的 `remove` 有两个重载：`remove(int index)` 和 `remove(Object o)`。实参写成 `2` 是 `int`，编译器在**不做装箱就能匹配**的那一步就选中了 `remove(int)`，于是删掉的是下标 2 上的 `9`。想按值删，必须让它匹配 `Object`：`remove(Integer.valueOf(2))`（或 `remove((Object) 2)`）。同样的坑在 `List<String>` 上反过来：`list.remove(0)` 删的是下标 0，想删字符串 `"0"` 得写 `remove("0")`。**症状是"删了，但删错了"**——数量对得上、内容不对，比抛异常难查得多。

## 第 2 题 · 密码明明是对的，却被拒绝

**目标**：`==` 比引用，`equals` 比内容；`new String(...)` 造出来的字符串和字面量一定不是同一个对象

```code-challenge
{
 "id": "dbg-06",
 "kind": "run",
 "title": "密码明明是对的，却被拒绝",
 "language": "java",
 "starter": "public class Main {\n    public static void main(String[] args) {\n        char[] input = {'a', 'd', 'm', 'i', 'n'};\n        String password = new String(input);\n        if (password == \"admin\") {\n            System.out.println(\"welcome\");\n        } else {\n            System.out.println(\"denied\");\n        }\n    }\n}\n",
 "cases": [
  {
   "name": "正确输出",
   "expected": "welcome\n"
  }
 ],
 "explain": "`new String(input)` 每次都在堆上新造一个对象，`\"admin\"` 这个字面量则来自字符串常量池，`==` 比的是\"是不是同一个对象\"，所以永远不等。这类 bug 有个讨厌的特性：**两边都写成字面量时（`\"admin\" == \"admin\"`）它又是 true**——测试里刚好能过，换成真实输入就挂。所以规则不能记成\"== 有时候行\"，只能记成\"比内容一律用 `equals`\"；并且把常量放前面（`\"admin\".equals(password)`），变量为 null 时也不会抛空指针。顺带一提，密码用 `char[]` 接（用完可以擦掉）本来就是安全实践，这里转成 `String` 只是为了演示比较——**为了比较而转换，就要用 `equals`**。"
}
```

**为什么**：`new String(input)` 每次都在堆上新造一个对象，`"admin"` 这个字面量则来自字符串常量池，`==` 比的是"是不是同一个对象"，所以永远不等。这类 bug 有个讨厌的特性：**两边都写成字面量时（`"admin" == "admin"`）它又是 true**——测试里刚好能过，换成真实输入就挂。所以规则不能记成"== 有时候行"，只能记成"比内容一律用 `equals`"；并且把常量放前面（`"admin".equals(password)`），变量为 null 时也不会抛空指针。顺带一提，密码用 `char[]` 接（用完可以擦掉）本来就是安全实践，这里转成 `String` 只是为了演示比较——**为了比较而转换，就要用 `equals`**。

## 第 3 题 · 一边遍历一边删，程序直接崩了

**目标**：for-each 背后是迭代器，遍历期间改集合会让它抛 `ConcurrentModificationException`

```code-challenge
{
 "id": "dbg-07",
 "kind": "run",
 "title": "一边遍历一边删，程序直接崩了",
 "language": "java",
 "starter": "import java.util.ArrayList;\nimport java.util.Arrays;\nimport java.util.List;\n\npublic class Main {\n    public static void main(String[] args) {\n        List<String> tags = new ArrayList<>(Arrays.asList(\"java\", \"sql\", \"java\", \"git\"));\n        for (String tag : tags) {\n            if (tag.equals(\"java\")) {\n                tags.remove(tag);\n            }\n        }\n        System.out.println(\"tags=\" + tags);\n    }\n}\n",
 "cases": [
  {
   "name": "正确输出",
   "expected": "tags=[sql, git]\n"
  }
 ],
 "explain": "for-each 会被编译成迭代器，`next()` 每次都会检查集合的 `modCount` 有没有变；`tags.remove(tag)` 改的正是这个计数，于是下一轮 `next()` 抛出 `ConcurrentModificationException`。**这个异常名有误导性**：它跟多线程没关系，单线程边遍历边改一样触发。正解是 `tags.removeIf(...)`（内部走迭代器的 `remove`），或者在显式 `Iterator` 上调用 `iterator.remove()`。如果改成下标 `for` 循环，不会抛异常，但删掉一个元素后后面的元素整体前移，`i++` 会跳过紧挨着的那一个——**相邻的重复元素只删掉一个**，那就是\"能跑但结果错\"的版本，比崩溃更难发现。"
}
```

**为什么**：for-each 会被编译成迭代器，`next()` 每次都会检查集合的 `modCount` 有没有变；`tags.remove(tag)` 改的正是这个计数，于是下一轮 `next()` 抛出 `ConcurrentModificationException`。**这个异常名有误导性**：它跟多线程没关系，单线程边遍历边改一样触发。正解是 `tags.removeIf(...)`（内部走迭代器的 `remove`），或者在显式 `Iterator` 上调用 `iterator.remove()`。如果改成下标 `for` 循环，不会抛异常，但删掉一个元素后后面的元素整体前移，`i++` 会跳过紧挨着的那一个——**相邻的重复元素只删掉一个**，那就是"能跑但结果错"的版本，比崩溃更难发现。
