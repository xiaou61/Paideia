# 32 · 文本块

## 一个在 Windows 上永远为 false 的断言

我在 Windows 上写过一个测试，断言一段 JSON 里带 CRLF：

```java
String s = "A\r\nB";
System.out.println(s.contains("\r"));   // true
```

然后我把同一个 JSON 换成了文本块，断言没改，测试红了：

```java
String t = """
        A
        B
        """;
System.out.println(t.contains("\r"));   // false
```

同样的内容、同样的平台，换个写法 `\r` 就没了。

原因是文本块在编译期就把行尾统一成 `\n`，**与源文件的换行符、与操作系统都无关**。这件事有两面：

- 好的一面：文本块里的内容在任何平台上都一样，测试不会因为同事用 macOS 就红。
- 坑的一面：如果你的协议或文件格式要求 CRLF（某些 Windows 配置、HTTP 头、旧的 CSV 工具），文本块**给不了你** `\r\n`，得自己 `replace("\n", "\r\n")`。

同一段内容，用 `+` 拼接会保留平台差异，用文本块会被抹平。这个差别不报错，只在断言或字节比对时才现形。

## 三个引号，内容原样

<!-- run -->
```java
public class Main {
    public static void main(String[] args) {
        String json = """
                {
                  "id": 1024,
                  "name": "小林"
                }
                """;

        System.out.println(json);
        System.out.println(json.contains("\"id\": 1024"));
    }
}
```
```text
{
  "id": 1024,
  "name": "小林"
}

true
```

注意两件事：

- 里面写 `"id"` 不用转义；只有内容里出现连续三个引号时才需要（写成 `\"""`）。
- 输出里 `{` 顶格、`"id"` 缩进两格——**不是**源码里的八格。文本块会剥掉公共缩进。

## 缩进：取最小缩进，统一剥掉

规则是：把**所有非空行**和**结尾那个 `"""` 所在行**的缩进放在一起，取最小值，再从每行开头去掉这么多空格。

结尾 `"""` 的位置因此决定了一切：

```java
String a = """
    SELECT *
    FROM users
""";          // 结尾顶格 → 最小缩进 0 → 四个空格全保留

String b = """
    SELECT *
    FROM users
    """;      // 结尾缩进 4 → 最小缩进 4 → 全部剥掉
```

`a` 不报错，只是每行前面多了四个空格。这种东西肉眼看输出几乎发现不了，要靠把换行替换成可见字符：

```java
System.out.println("[" + a.replace("\n", "|") + "]");
// [    SELECT *|    FROM users|]
```

**多缩进的部分会被保留**，这正好用来写嵌套结构——文本块里贴一段 YAML 或代码，内层缩进是内容的一部分，不会被吃掉。

## 三个只在细节里出现的坑

**一、行尾空格会被删掉。** 文本块会去掉每行末尾的空白（编辑器里看不见，diff 里也难看）。要保住，在行尾写 `\s`：

```java
String t = """
        hello\s
        """;
System.out.println("[" + t.replace("\n", "|") + "]");
// [hello |]
```

`\s` 表示一个空格，且它不是一个「末尾空白」，所以不会被剥。

**二、行末一个 `\` 会把下一行接上来。**

```java
String t = """
        one \
        two
        """;
System.out.println(t.replace("\n", "|"));
// one two|
```

这在写很长的单行命令时有用，但它**吃掉的是换行本身**，所以两行之间连空格都没有——`one` 和 `two` 之间那个空格是我在 `\` 前手动留的。

**三、内容里有连续三个引号要转义。** 否则它提前结束文本块：

```java
String t = """
        he said \"""hi\""" to me
        """;
System.out.println(t.trim());
// he said """hi""" to me
```

## 它不能插值

文本块只是字符串字面量的另一种写法，没有 `${name}`。要拼变量还是 `+` 或 `formatted`：

```java
String sql = """
        SELECT * FROM users WHERE id = %d
        """.formatted(id);
```

`%d` 里塞错了类型会在运行时抛 `IllegalFormatConversionException`，所以它比 `+` 更容易在运行时翻车——这也是为什么文本块**不适合到处拼变量的长文本**：一堆 `%s` 比 `+` 更难读，还失去了编译期类型检查。

（字符串模板 `STR."..."` 在 Java 21 是预览特性，后续被撤回，别在生产代码里依赖。）

## 什么时候该用

适合：SQL、JSON、HTML/XML 片段、测试里的期望输出、带格式的报错信息——共同点是**内容是死的**。

不适合：一段到处要插变量的文本；需要精确控制 CRLF 的协议内容（要自己替换回来）；超长的构建脚本（还是放在文件里读，别写进代码）。

## 还差的

- **只用 JDK 25 单平台验过**。我说的「与平台无关」是规范行为，但我没有在 Linux/macOS 上真编过同一份源码去比对字节。
- **`\s` 与编辑器自动去尾随空格的关系没测**。IDE 保存时把行尾空格删掉的话，`\s` 之前的空格会先少一批，这个组合我没踩过。
- **`String.stripIndent()` 与文本块缩进规则的差异**只看了文档，没写实验对比两者在同一段文本上的结果。
