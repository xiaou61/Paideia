# 28 · 日志：程序出事了怎么查

## 这一课你要会

- 用日志框架分级输出，而不是到处 `System.out.println`；
- 写出一条能定位问题的日志：谁、做了什么、结果、可查的 id；
- 知道哪些东西**绝对不能**写进日志。

## 为什么

程序在用户的机器上、在服务器上出错了。你不在现场，唯一能看的就是日志。

`println` 也能打印，但它缺三样东西：**时间、级别、线程**。出事时你需要的恰好是这三样——"几点开始的"、"是错误还是普通信息"、"哪个线程卡住了"。更麻烦的是，`println` 关不掉：上线后想调日志量，得改代码重新发版。

日志框架把"打不打、打到哪、什么格式"变成配置，代码里只表达"这件事有多重要"。

## 讲解

### 日志有级别，按重要性分

| 级别 | 什么时候用 | 例子 |
| --- | --- | --- |
| `SEVERE` / `ERROR` | 功能失败了，需要人处理 | 支付回调验签失败 |
| `WARNING` / `WARN` | 还能继续，但明显不对 | 重试第 2 次、缓存没命中 |
| `INFO` | 关键业务节点 | 订单创建成功、用户登录 |
| `FINE` / `DEBUG` | 排查细节 | 入参、SQL、分支走向 |

默认只输出 `INFO` 及以上。`DEBUG` 平时关着，出问题时在配置里打开——**不用改代码、不用重新编译**，这就是框架相对 `println` 的最大价值。

### 一条好日志长什么样

```text
SEVERE pay failed orderId=1024 userId=7 reason=timeout
```

它回答了四个问题：

1. **谁**：`userId=7`
2. **做了什么**：`pay failed`
3. **对哪个对象**：`orderId=1024`
4. **为什么**：`reason=timeout`

`key=value` 的写法比"用户 7 的订单 1024 支付失败了，因为超时"更好搜：日志系统里直接搜 `orderId=1024` 就能把这条链路全捞出来。

### JDK 自带的日志

JDK 里有两层：`System.Logger` 是门面，`java.util.logging` 是默认实现。框架（Spring 等）通常用 SLF4J，写法几乎一样。下面用 JDK 自带的实现，不引入任何依赖：

<!-- run -->
```java
import java.util.logging.Handler;
import java.util.logging.Level;
import java.util.logging.LogRecord;
import java.util.logging.Logger;

public class Main {
    public static void main(String[] args) {
        Logger logger = Logger.getLogger("demo");
        logger.setUseParentHandlers(false);
        logger.setLevel(Level.ALL);

        Handler out = new Handler() {
            @Override
            public void publish(LogRecord record) {
                System.out.println(record.getLevel() + " " + record.getMessage());
            }

            @Override
            public void flush() {
            }

            @Override
            public void close() {
            }
        };
        out.setLevel(Level.ALL);
        logger.addHandler(out);

        logger.info("order created orderId=1024");
        logger.warning("retry 2/3 orderId=1024");
        logger.severe("pay failed orderId=1024 userId=7 reason=timeout");
    }
}
```
```text
INFO order created orderId=1024
WARNING retry 2/3 orderId=1024
SEVERE pay failed orderId=1024 userId=7 reason=timeout
```

真实项目里这个 `Handler` 由配置提供（输出到控制台还是文件、什么格式）。业务代码只写 `logger.warning(...)`，不关心落到哪。

### 绝对不要写进日志的东西

- 密码、验证码、token、Cookie；
- 完整的身份证号、银行卡号、手机号（需要的话打码：`138****1234`）；
- 用户的完整请求体——里面可能什么都有。

日志会被收集、转发、长期保存，权限往往比数据库松。**一条密钥进了日志，等于把它公开了**，删日志也未必删得干净。

## 常见误区

### 误区：`println` 就是日志

**你以为**：反正都能打印，为什么还要引框架。
**其实**：`println` 没有时间、级别、线程，也不能按配置开关。出问题时你需要的是"可筛选、可关闭、能落到文件"的东西。

### 误区：日志打得越多越好

**你以为**：都打上，出事总能查到。
**其实**：日志量太大会淹没关键信息、增加存储成本，还可能拖慢程序。打**关键节点 + 失败原因 + 可查 id**，细节用 DEBUG 级别按需打开。

### 误区：日志只有开发看

**你以为**：上线后就没人看了。
**其实**：线上排障、审计、安全事件回溯都依赖日志。写日志时假设"半年后的自己只能看到这一行"。

## 小结

日志要回答"谁、做了什么、结果、为什么"。用级别控制详略，用 `key=value` 方便搜索，密码与 token 绝不入日志。JDK 自带 `java.util.logging`，框架里常见的是 SLF4J，写法一致。
