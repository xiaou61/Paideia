# 14 · 文件 I/O

## 同一段「你好」，两个 API 写出两种字节

把同一个字符串分别交给 `Files.writeString` 和 `FileWriter`，都不传编码，在 `-Dfile.encoding=GBK` 下跑：

```java
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;
import java.io.Reader;
import java.nio.charset.Charset;
import java.nio.charset.MalformedInputException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.HexFormat;

public class Main {
    public static void main(String[] args) throws IOException {
        String text = "你好";
        Path dir = Files.createTempDirectory("enc-");
        Path a = dir.resolve("files.txt");
        Path b = dir.resolve("writer.txt");

        Files.writeString(a, text);
        try (FileWriter writer = new FileWriter(b.toFile())) {
            writer.write(text);
        }

        System.out.println("defaultCharset=" + Charset.defaultCharset());
        System.out.println("Files.writeString=" + HexFormat.of().formatHex(Files.readAllBytes(a)));
        System.out.println("FileWriter=" + HexFormat.of().formatHex(Files.readAllBytes(b)));
        System.out.println("Files.readString=" + Files.readString(a));
        System.out.println("readAllLines=" + Files.readAllLines(a).get(0));

        try {
            System.out.println("Files.readString(b)=" + Files.readString(b));
        } catch (MalformedInputException error) {
            System.out.println("Files.readString(b)=" + error.getClass().getSimpleName());
        }

        try (Reader reader = new FileReader(a.toFile())) {
            char[] buffer = new char[16];
            int count = reader.read(buffer);
            System.out.println("FileReader=" + new String(buffer, 0, count));
        }

        Files.deleteIfExists(a);
        Files.deleteIfExists(b);
        Files.deleteIfExists(dir);
    }
}
```
```text
defaultCharset=GBK
Files.writeString=e4bda0e5a5bd
FileWriter=c4e3bac3
Files.readString=你好
readAllLines=你好
Files.readString(b)=MalformedInputException
FileReader=浣犲ソ
```

命令：

```text
javac --release 21 -encoding UTF-8 Main.java
java "-Dfile.encoding=GBK" "-Dstdout.encoding=UTF-8" Main
```

在 PowerShell 里把每个 `-D` 参数用引号包住，否则它可能被拆成两个参数。

我原来的判断是「不写编码就跟着平台走」，所以两个文件应该都是 GBK。实际只有 `FileWriter` 是：它写出 `c4 e3 ba c3`，正是「你好」的 GBK；`Files.writeString` 写出的 `e4 bd a0 e5 a5 bd` 是 UTF-8，和默认字符集设成 GBK 没有关系。

更直接的对照：`Files.readString(b)` 用 UTF-8 去解 GBK 字节，抛 `MalformedInputException`；`FileReader` 用 GBK 去解 UTF-8 字节，读出 `浣犲ソ`。同一段字节，换一种解码规则就换一个结果。

`HexFormat` 只是把字节打成十六进制，Java 17 起才有；这里用它看文件里到底是什么，不影响文件 API 本身。

### 为什么

`Files` 这一组字符串方法默认就是 UTF-8，和平台默认无关。`readString` / `writeString` 是 Java 11 加的；`readAllLines` / `lines` / `newBufferedReader` 这些更早的无 charset 重载也规定 UTF-8：

- `Files.readString(path)`、`Files.writeString(path, text)`；
- `Files.readAllLines(path)`、`Files.write(path, lines)`；
- `Files.lines(path)`、`Files.newBufferedReader(path)`、`Files.newBufferedWriter(path)`。

这些**不带 charset 参数的重载**不会去读 `Charset.defaultCharset()`；API 文档对每一个都写明了 UTF-8。

`FileReader` / `FileWriter` / `new InputStreamReader(stream)` 是另一套：它们不带 charset 时用 `Charset.defaultCharset()`。这个值在 Java 18 起默认是 UTF-8（JEP 400），但可以被 `-Dfile.encoding=GBK` 改回去；Java 17 及更早则由系统区域和 JDK 实现决定。所以「`FileWriter` 不写编码」在 Java 21 的默认配置下可能刚好没事，换一台机器或加一个启动参数就变。

**结论**：只要文件本身是 UTF-8，`Files` 的方法不写 charset 不会因为平台默认而乱码；`FileWriter` 那一套才必须显式指定。`Files` 上写 `StandardCharsets.UTF_8` 仍然值得写——它让读代码的人一眼知道协议是 UTF-8，也防止你以后换成 `FileWriter` 时忘了补。

验证方法：把上面的程序分别在 `-Dfile.encoding=GBK` 和 `-Dfile.encoding=UTF-8` 下跑。`Files.writeString` 的十六进制不变；`FileWriter` 那行会从 `c4e3bac3` 变成 `e4bda0e5a5bd`。

`Files.lines(a)` 同样按 UTF-8 解码，只是返回流；它必须关闭，后面会讲。

### 还有一个坑：`getBytes()` 仍看默认编码

`Files.write(path, bytes)` 收的是字节，不涉及字符编码。下面两行看起来都「写字符串」，实际不一样：

```java
Files.write(path, text.getBytes());                       // 默认字符集
Files.write(path, text.getBytes(StandardCharsets.UTF_8)); // UTF-8
```

`new String(bytes)` 同理，解码时也用默认字符集。要解码已知是 UTF-8 的文件，用 `new String(bytes, StandardCharsets.UTF_8)`，或者直接用 `Files.readString`。

验证方法：在 `-Dfile.encoding=GBK` 下打印 `text.getBytes()` 的十六进制，再打印 `text.getBytes(StandardCharsets.UTF_8)` 的十六进制，前者是 GBK，后者是 UTF-8。

## 覆盖、追加与「打开即截断」

`Files.writeString` 不传选项时，默认是 `CREATE + TRUNCATE_EXISTING + WRITE`：

```java
Files.writeString(path, "新内容"); // 文件不存在就建；存在就清空再写
```

追加要显式传 `APPEND`：

```java
Files.writeString(path, "下一行\n",
        StandardOpenOption.CREATE, StandardOpenOption.APPEND);
```

`CREATE` 可以省吗？文件不存在时，只传 `APPEND` 会抛 `NoSuchFileException`；所以第一次写要带上 `CREATE`。

`TRUNCATE_EXISTING` 在打开文件时就执行，不是写到第一个字符才清空。写失败也救不回旧内容——这也是为什么覆盖写之前先备份，或者先写临时文件再 `move`（带 `REPLACE_EXISTING`）替换。

验证方法：先写 `"旧内容"`，再调用 `Files.writeString(path, "")`，然后 `Files.size(path)`；结果是 `0`，旧内容已经没了。再写一次并传 `APPEND`，`Files.size(path)` 会变大。

`Files.write` 的字节版本默认选项一样。区别只是它收 `byte[]`，不处理字符编码。

## 路径相对的是当前工作目录

```java
Path base = Path.of("data");
Path file = base.resolve("notes.txt");
```

`Path.of("data.txt")` 是相对路径，基准是**当前工作目录**（`System.getProperty("user.dir")`），不是 `.java` 文件所在目录，也不是项目根，更不是脚本目录。命令行里跑，工作目录就是你敲命令时所在的目录；IDE 里跑，工作目录由运行配置决定，可能是项目根，也可能是模块目录。同一句 `Path.of("data.txt")` 在两个地方可能指向两个文件。

验证方法：

```java
System.out.println(Path.of(".").toAbsolutePath().normalize());
System.out.println(System.getProperty("user.dir"));
```

在 IDE 和命令行各跑一次，对比输出。要固定位置，用绝对路径，或者用 `Path.of(System.getProperty("user.dir"), "data", "notes.txt")` 显式拼。

`Path.of` 和 `Paths.get` 是同一件事：`Path.of` 是 Java 11 加的，`Paths.get` 更老；普通字符串两者结果相等。新代码用 `Path.of`。

旧 `File` 还能互转：

```java
File file = path.toFile();
Path back = file.toPath();
```

验证方法：在默认文件系统上，`path.toFile().toPath().equals(path)` 为 `true`。

路径不要用字符串 `+ "/"` 拼：Windows 和 Unix 分隔符不同，`..` 也不会被规范化。用 `resolve` 拼子路径；需要消掉 `..` 时再调用 `normalize()`。

## 建目录前先处理 null

```java
Files.createDirectories(path.getParent());
```

上面这行对 `Path.of("data.txt")` 会抛 `NullPointerException`：单段相对路径没有父目录，`getParent()` 返回 `null`，而 `Files.createDirectories(null)` 不接受 null。

两种写法：

```java
Path parent = path.getParent();
if (parent != null) {
    Files.createDirectories(parent);
}
```

或者：

```java
Path parent = path.toAbsolutePath().getParent();
if (parent != null) {
    Files.createDirectories(parent);
}
```

第二种对普通文件名能拿到父目录；对文件系统根路径（如 `C:\`、`/`）`getParent()` 仍是 `null`，所以 `if` 还是要留。

验证方法：打印 `Path.of("data.txt").getParent()`，看到 `null`；再调用 `Files.createDirectories(null)`，看到 `NullPointerException`。

`Files.createDirectories` 会连同上层一起建，目录已存在也不报错；`Files.createDirectory`（单数）只建一层，父目录不存在就抛 `NoSuchFileException`。

验证：在空目录里对 `a/b` 调 `createDirectory`，会抛 `NoSuchFileException`；换成 `createDirectories` 就成功。

`Files.delete(path)` 不存在时抛 `NoSuchFileException`；`Files.deleteIfExists(path)` 返回 boolean，适合清理。验证：对同一个不存在的路径各调一次，前者抛异常，后者返回 `false`。

## copy / move：目标存在不是覆盖，是异常

```java
Path source = Path.of("notes.txt");
Path target = Path.of("notes-copy.txt");

Files.copy(source, target); // 目标存在：FileAlreadyExistsException
```

要覆盖，显式传 `REPLACE_EXISTING`：

```java
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
Files.move(source, target, StandardCopyOption.REPLACE_EXISTING);
```

`Files.move` 不传 `REPLACE_EXISTING` 时，目标存在同样抛 `FileAlreadyExistsException`。

选项表：

| 选项 | 用在哪 | 作用 | 不注意会怎样 |
| --- | --- | --- | --- |
| `REPLACE_EXISTING` | copy / move | 目标存在时替换 | 不传就抛 `FileAlreadyExistsException`；传了但目标是**非空目录**，仍抛 `DirectoryNotEmptyException` |
| `COPY_ATTRIBUTES` | copy | 尽量把属性一起复制 | 不传时规范**不保证**属性跟着走；传了也不是所有属性都能复制 |
| `ATOMIC_MOVE` | move | 要求原子移动 | 文件系统不支持时抛 `AtomicMoveNotSupportedException`；它和别的选项一起用时，其它选项会被忽略 |

`COPY_ATTRIBUTES` 这条要特别小心「在我机器上是好的」。我在 Windows 上做过对照：源文件时间改成固定值，普通 `Files.copy` 也保留了修改时间，和 `COPY_ATTRIBUTES` 的结果一样。但 API 文档只说「不要求复制属性」，没保证普通 copy 不会复制。换文件系统、换属性（ACL、所有者）就可能不同。要可预期，就显式写 `COPY_ATTRIBUTES`，并在复制后自己检查关键属性。

验证方法：先复制到已存在的目标，不传 `REPLACE_EXISTING` 看 `FileAlreadyExistsException`，再传了看内容被替换；然后把源文件的 `lastModifiedTime` 设成一个固定的旧时间，分别普通复制和带 `COPY_ATTRIBUTES` 复制，比较目标文件的 `Files.getLastModifiedTime`。如果你的文件系统和我的 Windows 一样两条都相等，别据此认为默认会复制——这只说明当前实现复制了，不是契约。`ATOMIC_MOVE` 要在目标文件系统上试，不支持时会抛 `AtomicMoveNotSupportedException`。

`Files.copy` 复制目录时只建一个空目录，不会递归复制里面的内容；要递归得自己走 `Files.walk` 或用 `Files.walkFileTree`。这一课不展开。

## 必须关闭的流不止 `Files.lines`

`Files.lines` 返回的 `Stream<String>` 持有一个打开的文件：

```java
try (Stream<String> lines = Files.lines(Path.of("data.txt"))) {
    lines.forEach(line -> System.out.println(line)); // Stream 第 20 课、lambda 第 21 课再讲
}
```

`Files.walk`、`Files.list`、`Files.find` 返回的 `Stream<Path>` 也一样，它们持有目录句柄：

```java
try (Stream<Path> paths = Files.walk(Path.of("data"))) {
    paths.forEach(path -> System.out.println(path)); // Stream 第 20 课、lambda 第 21 课
}
```

不关不一定当场报错：目录句柄会一直占着，直到流被关闭或进程退出；Windows 上还可能让删除失败，Linux 上就是 fd 泄漏。跑久了或者递归打开很多目录，才会看到 `Too many open files` 一类的问题。**不能靠「没报错」判断没泄漏。**

验证方法：在 Windows 上开一个 `Files.walk` 不关，然后尝试删除那个目录；或者在循环里反复打开流，观察进程句柄数（PowerShell：`Get-Process java | Select-Object Id, Handles`）是否一直涨。Linux 上看 `/proc/<pid>/fd` 的数量。

如果只是逐行读文件，`Files.newBufferedReader` 更容易看清关闭边界：

```java
try (BufferedReader reader = Files.newBufferedReader(path)) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
}
```

`Files.readAllLines` 返回 `List<String>`，内部已经读完并关闭，不需要你再关；代价是一次性把整个文件放进内存。

## `main` 上写 `throws IOException`，不要写 `throws Exception`

文件操作的受检异常都在 `java.io.IOException` 这一支：`NoSuchFileException`、`FileAlreadyExistsException`、`MalformedInputException` 都是它的子类。方法签名写 `throws IOException`，调用方知道要处理的是 I/O 失败；写 `throws Exception` 能编译，但把类型信息抹掉了，调用方只能按 `Exception` 处理，也分不清是文件不存在还是权限不够。

验证：把 `throws IOException` 删掉再编译，javac 会报 `unreported exception IOException; must be caught or declared to be thrown`；改成 `throws Exception` 能过编译，但签名不再说明失败类型。

## 跑一遍

下面这段故意不写 charset：`Files.writeString` / `readAllLines` / `readString` 都按 UTF-8，输出里的第一行就是「第一行」的 UTF-8 字节。

<!-- run -->
```java
import java.io.IOException;
import java.nio.file.FileAlreadyExistsException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardCopyOption;
import java.nio.file.StandardOpenOption;
import java.util.HexFormat;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Path folder = Files.createTempDirectory("paideia-io-");
        Path notes = folder.resolve("notes.txt");

        Files.writeString(notes, "第一行\n");
        System.out.println(HexFormat.of().formatHex(Files.readAllBytes(notes)));

        Files.writeString(notes, "第二行\n",
                StandardOpenOption.CREATE, StandardOpenOption.APPEND);
        List<String> lines = Files.readAllLines(notes);
        System.out.println(lines.size());
        System.out.println(Files.readString(notes).strip());

        Files.writeString(notes, "覆盖了\n");
        System.out.println(Files.readString(notes).strip());

        Path source = folder.resolve("source.txt");
        Path target = folder.resolve("target.txt");
        Files.writeString(source, "source");
        Files.writeString(target, "old");
        try {
            Files.copy(source, target);
        } catch (FileAlreadyExistsException error) {
            System.out.println(error.getClass().getSimpleName());
        }
        Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
        System.out.println(Files.readString(target));

        Files.deleteIfExists(target);
        Files.deleteIfExists(source);
        Files.deleteIfExists(notes);
        Files.deleteIfExists(folder);
    }
}
```

## 还差的

- 没讲 `FileChannel`、`RandomAccessFile` 和内存映射文件。要处理断点续传、超大文件或并发读写，这一课的 `Files` 包装不够。
- 没讲文件锁、原子替换的完整方案。`ATOMIC_MOVE` 只在文件系统支持时成立，临时文件 + `move` 的崩溃恢复也只是一笔带过。
- 没讲权限、ACL、符号链接、硬链接在不同系统上的差异。`Files.copy` 的 `COPY_ATTRIBUTES` 到底复制了哪些属性，得按目标文件系统单独查。
- 没讲 `WatchService`、磁盘满、只读文件系统、编码检测这些运行期问题。真要做「监听目录并导入」时，需要另开一课。
