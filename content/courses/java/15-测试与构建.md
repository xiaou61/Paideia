# 15 · 测试与构建

## 一条测试都没跑，构建却是 SUCCESS

这是我第一次对自己的记账小工程跑 `mvn -o -B clean test` 时，和测试有关的**全部**输出：

```text
[INFO] --- surefire:3.5.6:test (default-test) @ ledger ---
[INFO] ------------------------------------------------------------------------
[INFO] BUILD SUCCESS
[INFO] ------------------------------------------------------------------------
```

没有 `T E S T S`，没有 `Tests run`，连「几条通过、几条失败」都没有。我当时的判断是「绿了，说明 4 条断言都过了」；实际是**一条都没跑**——因为我把测试类命名成了 `AmountCheck`。

工程很小，先把能粘贴跑的东西放全。目录：

└── src/

`Amount` 只有一个方法：把「元」解析成「分」。这一课从头到尾只用它一个对象：

```java
package ledger;

public final class Amount {

    private Amount() {
    }

    public static long parse(String text) {
        if (text == null || text.isBlank()) {
            throw new NumberFormatException("金额不能为空");
        }
        String[] parts = text.strip().split("\\.");
        if (parts.length > 2) {
            throw new NumberFormatException("不是合法金额：" + text);
        }
        String frac = parts.length == 2 ? parts[1] : "";
        if (frac.length() > 2) {
            throw new NumberFormatException("最多两位小数：" + text);
        }
        long fracValue = frac.isEmpty() ? 0 : Long.parseLong(frac);
        return Long.parseLong(parts[0]) * 100 + fracValue;
    }
}
```

`long` 存分只是为了让断言短。金额本身能不能用 `long`、利息和分摊怎么舍入，是另一个话题（要 `BigDecimal` 加显式舍入模式），本课不碰。记住这里藏着一个 bug，等会儿让测试去抓。

四条测试，一条问一件事：

```java
package ledger;

import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

import org.junit.jupiter.api.Test;

class AmountTest {

    @Test
    void parsesWholeYuan() {
        assertEquals(1200, Amount.parse("12"));
    }

    @Test
    void keepsTwoDecimalPlaces() {
        assertEquals(105, Amount.parse("1.05"));
    }

    @Test
    void padsOneDecimalPlace() {
        assertEquals(150, Amount.parse("1.5"));
    }

    @Test
    void rejectsThreeDecimalPlaces() {
        assertThrows(NumberFormatException.class, () -> Amount.parse("1.005"));
    }
}
```

`assertThrows` 第二个参数是个函数，`() -> ...` 的箭头语法第 21 课才讲，这里先照抄：它的意思是「把这段调用交给 assertThrows 去执行」。

第一次跑时这个类叫 `AmountCheck`，就有了开头那段「什么都没跑」的输出。

### surefire 为什么把 AmountCheck 当成不存在

surefire 3.5.6 的插件描述（`META-INF/maven/plugin.xml`）里，默认 `includes` 是四条模式：

```text
**/Test*.java
**/*Test.java
**/*Tests.java
**/*TestCase.java
```

`AmountCheck` 一条都不匹配。**「没找到测试」不是错误**，所以 surefire 什么都不说，构建照样 SUCCESS。

反证：显式点名，叫什么都跑。

```text
mvn -o -B test "-Dtest=AmountCheck"
[INFO] Running ledger.AmountCheck
[ERROR] Tests run: 4, Failures: 1, Errors: 0, Skipped: 0, Time elapsed: 0.057 s <<< FAILURE! -- in ledger.AmountCheck
[INFO] BUILD FAILURE
```

同一个类、同一套断言，换个参数就红了。测试一直在，只是默认扫描没叫它。

### 看到什么，先看哪

| 输出里的样子 | 先看哪 | 怎么确认 |
| --- | --- | --- |
| `BUILD SUCCESS`，但完全没有 `Tests run` 行 | 测试类名是否匹配上面四条 includes | `mvn -o -B test "-Dtest=类名"` 点名跑一次 |
| `Tests run: 1`，可类里写了两个 `@Test` | 那个方法是不是 `private` | 本机实测：`private` 的 `@Test` 被静默跳过，不报错，构建仍 SUCCESS |
| `Failures: 1` | 断言的期望值/实际值有没有写反 | 看 `expected: <A> but was: <B>`，A 是 `assertEquals` 的第一个参数 |
| `Errors: 1` | 测试方法自己抛了异常，根本没走到断言 | 看第一条异常类名和消息 |
| `COMPILATION ERROR` + `testCompile` | 测试代码编译不过，跟断言无关 | `-DskipTests` 挡不住它，见参数表 |

第一行是我踩到的；第二行也实测过：一个普通 `@Test` 加一个 `private @Test`，结果是 `Tests run: 1`，没有任何提示。

读法就三条：

- **哪条**：`padsOneDecimalPlace`，`AmountTest.java:22`，就是 `assertEquals(150, Amount.parse("1.5"))` 那一行。测试方法写得短，行号才有这种用处。
- **期望与实际**：`expected: <150> but was: <105>` 里，`150` 是 `assertEquals` 的第一个参数（我写的期望），`105` 是 `parse` 真返回的值。方向别记反：先 `expected`，后 `was`。
- **异常类**：`org.opentest4j.AssertionFailedError`，JUnit 5 的断言失败抛它。实测它的父类是 `java.lang.AssertionError`，`instanceof AssertionError` 为 `true`——所以既有的 `catch (AssertionError e)` 也能抓到它。但类名属于 JUnit 的实现，别拿它写业务判断。

`105` 说明 `"1.5"` 被算成了 1.05 元的分：小数点后只有一位 `5`，`Long.parseLong("5")` 得到 5，`100 + 5 = 105`。少了一步补零。

### `Failures` 和 `Errors` 不是同一个东西

另建一个故意抛异常、不写断言的测试（`throw new IllegalStateException("数据库连不上")`），跑出来是：

```text
[INFO] Running ledger.ThrowTest
[ERROR] Tests run: 1, Failures: 0, Errors: 1, Skipped: 0, Time elapsed: 0.008 s <<< FAILURE! -- in ledger.ThrowTest
java.lang.IllegalStateException: 数据库连不上
[ERROR] Tests run: 5, Failures: 0, Errors: 1, Skipped: 0
```

断言判定为假 → `Failures`；测试方法自己炸了、压根没走到断言 → `Errors`。两种都让构建失败，但要修的东西不同：前者先怀疑期望值或被测代码算错，后者先读那条异常的堆栈。

## `test` / `package` / `verify` 各走到了哪一步

`mvn package` 会把测试再跑一遍（输出里又出现一次 `Tests run: 4`），然后才打包：

```text
[INFO] --- maven-jar-plugin:3.5.1:jar (default-jar) @ ledger ---
[INFO] Building jar: C:\Users\Lenovo\AppData\Local\Temp\paideia-j15\ledger\target\ledger-1.0.0.jar
```

看看 jar 里到底有什么：

```text
C:\...\ledger> jar tf target\ledger-1.0.0.jar
META-INF/
META-INF/MANIFEST.MF
ledger/
META-INF/maven/
META-INF/maven/paideia/
META-INF/maven/paideia/ledger/
ledger/Amount.class
META-INF/maven/paideia/ledger/pom.xml
META-INF/maven/paideia/ledger/pom.properties
```

没有 JUnit，也没有 `AmountTest.class`。`junit-jupiter` 声明的 `scope` 是 `test`，它只在编译和运行测试时可见。

`mvn verify` 呢？在这个 pom 下，它执行的目标列表和 `package` **完全一样**（`clean`、`resources`、`compiler:compile`、`resources:testResources`、`compiler:testCompile`、`surefire:test`、`jar:jar`）。`verify` 是生命周期的最后一个阶段，它不是「自动跑集成测试」的开关——要跑集成测试，得把 failsafe 插件绑到 `integration-test` 阶段上。所以「`mvn verify` 会跑集成测试」这句话，条件是这个 pom 里已经绑了那套东西。

### 为什么 pom 里要钉插件版本

Maven 3.9.0 自带的默认绑定（打包在 `lib/maven-core-3.9.0.jar` 的 `META-INF/plexus/default-bindings.xml` 里）是：maven-compiler-plugin **3.10.1**、maven-surefire-plugin **3.0.0-M8**、maven-jar-plugin **3.3.0**。默认绑定跟着 Maven 版本走，换台机器换个 Maven，插件版本跟着换、测试行为也跟着变。钉住版本，结果才可复现——本机 m2 里就躺着 surefire 3.5.4 和 3.5.6 两个版本。

### 参数 → 影响

| 命令 / 参数 | 实测结果 |
| --- | --- |
| `mvn -o -B test` | 编译主代码和测试代码，跑 surefire；本机 4 条约 0.05 秒 |
| `mvn -o -B package` | 上一步 + 再跑一遍测试 + `jar:jar` 产出 `target/ledger-1.0.0.jar` |
| `mvn -o -B verify` | 这个 pom 下目标列表与 `package` 相同；没有 failsafe 时它不多做任何事 |
| `-DskipTests` | 只跳过执行；测试代码照样编译。测试编译不过时仍是 `BUILD FAILURE` |
| `-Dmaven.test.skip=true` | 连测试代码都不编译：`Not compiling test sources`，`target/test-classes` 不生成 |
| `-o` | 离线，只查本机 `~/.m2` |

两个跳过参数的差别不是措辞问题。我故意往 `src/test/java` 里放一个编译不过的文件（`int x = ;`），`-DskipTests` 报 `COMPILATION ERROR` 并失败，`-Dmaven.test.skip=true` 直接 SUCCESS：

```text
[ERROR] /C:/Users/Lenovo/AppData/Local/Temp/paideia-j15/ledger-scratch/src/test/java/ledger/BrokenTest.java:[4,27] 非法的表达式开始
[INFO] BUILD FAILURE
```

命令行注意两点：

- `-Dmaven.test.skip=true` 在 PowerShell 里要用引号包住（`"-Dmaven.test.skip=true"`），否则被拆成两段，报 `[ERROR] Unknown lifecycle phase ".test.skip=true"`。
- 本文全程加 `-o` 是因为这台机器的 m2 里已经有 junit-jupiter 5.12.2、surefire 3.5.6、jar-plugin 3.5.1。你的 m2 里没有的话，去掉 `-o` 让它下载；离线环境会卡在找不到依赖。

## 跑一遍

JUnit 只是把「比两个值、失败时打出期望与实际」这件事包了一层。下面这段没有 Maven、没有 JUnit，把两版 `parse` 放进同一个 `Main`，用手写的 `check` 打出 JUnit 那样的结果：

<!-- run -->
```java
public class Main {

    static long parseBroken(String text) {
        if (text == null || text.isBlank()) {
            throw new NumberFormatException("金额不能为空");
        }
        String[] parts = text.strip().split("\\.");
        if (parts.length > 2) {
            throw new NumberFormatException("不是合法金额：" + text);
        }
        String frac = parts.length == 2 ? parts[1] : "";
        if (frac.length() > 2) {
            throw new NumberFormatException("最多两位小数：" + text);
        }
        long fracValue = frac.isEmpty() ? 0 : Long.parseLong(frac);
        return Long.parseLong(parts[0]) * 100 + fracValue;
    }

    static long parseFixed(String text) {
        if (text == null || text.isBlank()) {
            throw new NumberFormatException("金额不能为空");
        }
        String[] parts = text.strip().split("\\.");
        if (parts.length > 2) {
            throw new NumberFormatException("不是合法金额：" + text);
        }
        String frac = parts.length == 2 ? parts[1] : "";
        if (frac.length() > 2) {
            throw new NumberFormatException("最多两位小数：" + text);
        }
        while (frac.length() < 2) {
            frac = frac + "0";
        }
        return Long.parseLong(parts[0]) * 100 + Long.parseLong(frac);
    }

    static void check(String label, long expected, long actual) {
        if (expected == actual) {
            System.out.println(label + " -> ok");
        } else {
            System.out.println(label + " -> expected: <" + expected + "> but was: <" + actual + ">");
        }
    }

    static String rejection(String text) {
        try {
            parseFixed(text);
            return "没抛异常";
        } catch (NumberFormatException error) {
            return error.getMessage();
        }
    }

    public static void main(String[] args) {
        check("broken 1.5", 150, parseBroken("1.5"));
        check("fixed 1.5", 150, parseFixed("1.5"));
        check("fixed 12", 1200, parseFixed("12"));
        check("fixed 1.05", 105, parseFixed("1.05"));
        check("fixed 0.05", 5, parseFixed("0.05"));
        System.out.println("fixed 1.005 -> " + rejection("1.005"));
        System.out.println("fixed 空白 -> " + rejection("  "));
    }
}
```
```text
broken 1.5 -> expected: <150> but was: <105>
fixed 1.5 -> ok
fixed 12 -> ok
fixed 1.05 -> ok
fixed 0.05 -> ok
fixed 1.005 -> 最多两位小数：1.005
fixed 空白 -> 金额不能为空
```

命令：

```text
javac -encoding UTF-8 Main.java
java "-Dfile.encoding=UTF-8" "-Dstdout.encoding=UTF-8" Main
```

第一行是全文那个 bug 的最小复现：只有一位小数时错，两位小数 `1.05` 反而对，所以拿 `12` 和 `1.05` 两条当验收，抓不到它。`fixed 0.05 -> ok` 也是真的：`Long.parseLong("05")` 等于 5，正好是要的 5 分。

## 还差的

- **没有 CI**：全文都是本机 `mvn -o` 跑（m2 里已有 junit-jupiter 5.12.2、surefire 3.5.6、jar-plugin 3.5.1）。接一条流水线要另外解决依赖下载与缓存、JDK 版本矩阵、失败归档，这些命令本身给不了。
- **没有可执行 jar**：`jar tf` 里只有 `ledger/Amount.class`，MANIFEST 只有四行、没有 `Main-Class`，`java -jar` 跑不起来。要产出能直接 `java -jar` 运行的包，得上 shade/assembly 或 Spring Boot 那种重打 jar。
- **没有覆盖率与它的边界**：本课没装 JaCoCo，也没定义「测到什么程度算够」。它记的是「这行执行过没有」，不记「断言够不够」——`rejectsThreeDecimalPlaces` 只验了异常类型、没验消息，一样算覆盖过。
- **没有依赖隔离**：`Amount` 是纯函数，能直接 `new` 出来断言。碰到数据库、HTTP、时间、随机数，得先有 Mock 或 Testcontainers，那一步这课没碰。
- **没有集成测试的那一半**：本课的 `verify` 和 `package` 目标列表一样，因为 pom 里没有 failsafe。把 `*IT` 挂到 `verify` 上、让它和单测分两段跑，是另一套配置。
