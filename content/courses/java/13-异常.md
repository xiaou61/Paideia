# 13 · 异常

## 这一课你要会

- 分清**受检异常**与**非受检异常**，知道为什么只有前者必须处理；
- 用 `try / catch / finally` 与 try-with-resources；
- 知道什么时候该 `throw`，什么时候该让它冒到上层。

## 为什么

Java 的异常体系比 Python 多一条分界线：有些异常编译器**强制**你处理，有些不强制。

这条线是 Java 的设计选择，代价是代码里到处 `throws`；好处是"可能失败"写在方法签名上，调用方跑不掉。

## 讲解

### 两大家族

```text
Throwable
├── Error                     （一般不该捕获：OutOfMemoryError 等）
└── Exception
    ├── RuntimeException      （非受检：NullPointerException、IllegalArgumentException…）
    └── 其它                  （受检：IOException、SQLException…）
```

规则：

- **受检异常**必须 `catch` 或在方法签名上 `throws`，否则编译失败；
- **非受检异常**（`RuntimeException` 及其子类）不强制，通常是编程错误。

判断口径：**"调用方能不能合理地恢复？"** 能（文件不存在可以换一个）就是受检；不能（参数传错是 bug）就是非受检。

### 基本形状

```text
try {
    int value = Integer.parseInt(text);
    System.out.println(value);
} catch (NumberFormatException error) {
    System.out.println("不是数字：" + text);
} finally {
    System.out.println("收尾");
}
```

**按从具体到宽泛的顺序排 catch**：先 `NumberFormatException` 再 `Exception`。顺序反了编译器直接拒绝（后面的分支永远到不了）。

### try-with-resources

有资源的对象（文件、连接）实现了 `AutoCloseable`，可以这样写：

```text
try (BufferedReader reader = Files.newBufferedReader(path)) {
    return reader.readLine();
}
```

退出时自动 `close()`，哪怕抛异常。**比手写 finally 更不容易漏**，也更短。

### 主动抛

```text
if (amount < 0) {
    throw new IllegalArgumentException("金额不能为负：" + amount);
}
```

三条习惯：

- 抛**最具体**的类型（`IllegalArgumentException` 而不是 `Exception`）；
- 消息里带**收到的值**——这是唯一能救排错的信息；
- 不要用异常表达正常的控制流。

### 自定义异常

```text
class InsufficientBalanceException extends RuntimeException {
    InsufficientBalanceException(String message) {
        super(message);
    }
}
```

业务失败通常继承 `RuntimeException`（不强求调用方处理）；如果调用方**必须**处理，才继承 `Exception`。

```java
public class Main {

    static int parseAge(String text) {
        try {
            int age = Integer.parseInt(text);
            if (age < 0) {
                throw new IllegalArgumentException("年龄不能为负：" + text);
            }
            return age;
        } catch (NumberFormatException error) {
            throw new IllegalArgumentException("年龄必须是数字，收到：" + text, error);
        }
    }

    public static void main(String[] args) {
        for (String raw : new String[]{"18", "abc", "-3"}) {
            try {
                System.out.println("解析成功：" + parseAge(raw));
            } catch (IllegalArgumentException error) {
                System.out.println("解析失败：" + error.getMessage());
            }
        }

        try {
            System.out.println(1 / 0);
        } catch (ArithmeticException error) {
            System.out.println("不能除以 0");
        } finally {
            System.out.println("收尾总是执行");
        }

        System.out.println("程序继续走到这里");
    }
}
```


## 常见误区

### 误区：所有异常都必须 try/catch

**你以为**：只要可能有异常就得包起来。
**其实**：只有受检异常强制。`RuntimeException`（空指针、越界、参数错）不强制，通常说明代码有 bug。

### 误区：catch Exception 更稳妥

**你以为**：宽一点总没坏处。
**其实**：会把"不该恢复的错误"也一起吞掉，而且日志里丢失具体类型。catch 你要处理的那一种。

### 误区：异常消息随便写

**你以为**：反正只是给开发看的。
**其实**：它就是唯一的现场。至少写清收到了什么、期望什么。

## 小结

受检异常强制处理，非受检通常是 bug。catch 从具体到宽泛。有资源就 try-with-resources。抛异常带收到的值。
