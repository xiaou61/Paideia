# 05 · 类与对象

## 一个 -1000 分的学生

我给自己的练习项目写了个记分的小程序，第一版长这样：

```java
class Student {
    public String name;
    public int score;
}
```

```java
Student s = new Student();
s.name = "小林";
s.score = 90;
s.score = -1000;      // 这行也没人拦
```

跑完打印 `小林 -1000`，程序一声不响。当时我的想法很朴素：反正是我自己的代码，谁会往里塞负数。

后来把这段拿去给同学跑，他一句"那我直接把分改大点不就行了"，我才意识到问题不是"谁会不会使坏"，而是**`score` 这份数据的合法性，没有任何一处代码在负责**。谁都能改，就没人真的管。

## 把字段藏起来，问题会跑到构造器去

第一反应是加 `private`：

```java
class Student {
    private String name;
    private int score;

    public Student(String name, int score) {
        this.name = name;
        this.score = score;        // 这里其实还是个缺口
    }

    public int getScore() {
        return score;
    }
}
```

这下 `s.score = -1000` 编译不过了。但 `new Student("小林", -1000)` 照样能进去——**构造器是公开的第二个入口，很多人只封了字段，忘了构造器也在这里打破规则**。

所以第 05 课真正要处理的是三件事：

1. 字段都能藏起来（`private`），外部只能通过方法读写；
2. 所有写入口——包括构造器——都走同一处校验；
3. 搞清楚 `final` 到底保证了什么（它不保证你以为的那些）。

## 校验收在一处，才叫封装

```java
public class Student {
    private final String name;
    private int score;

    public Student(String name, int score) {
        this.name = name;
        setScore(score);
    }

    public void setScore(int score) {
        if (score < 0) {
            throw new IllegalArgumentException("分数不能为负：" + score);
        }
        this.score = score;
    }

    public void addScore(int delta) {
        if (delta < 0) {
            throw new IllegalArgumentException("加分不能为负：" + delta);
        }
        setScore(this.score + delta);
    }

    public int getScore() {
        return score;
    }
}
```

三个写入口（构造器、`setScore`、`addScore`）最后都落到 `setScore` 这一个判断上。以后规则变了——比如还要限制最高 100 分——只改一个地方。

这就是 `private` 的全部意义：**不是"不让别人看"，是"让合法性只有一个地方负责"**。所以只写 `private` 再加一对什么都不校验的 getter/setter，等于把公开字段换个写法而已。

## 跑一遍

<!-- run -->
```java
public class Main {

    static class Student {
        private final String name;
        private int score;

        Student(String name, int score) {
            this.name = name;
            setScore(score);
        }

        void setScore(int score) {
            if (score < 0) {
                throw new IllegalArgumentException("分数不能为负：" + score);
            }
            this.score = score;
        }

        void addScore(int delta) {
            if (delta < 0) {
                throw new IllegalArgumentException("加分不能为负：" + delta);
            }
            setScore(this.score + delta);
        }

        int getScore() {
            return score;
        }

        String getName() {
            return name;
        }
    }

    public static void main(String[] args) {
        Student a = new Student("小林", 90);
        System.out.println("入学分数：" + a.getScore());

        try {
            new Student("小周", -1000);
        } catch (IllegalArgumentException error) {
            System.out.println("构造器拦住：" + error.getMessage());
        }

        try {
            a.addScore(-5);
        } catch (IllegalArgumentException error) {
            System.out.println("加分拦住：" + error.getMessage());
        }

        System.out.println("分数没变：" + a.getScore());

        a.addScore(10);
        System.out.println("加分后：" + a.getScore());
    }
}
```
```text
入学分数：90
构造器拦住：分数不能为负：-1000
加分拦住：加分不能为负：-5
分数没变：90
加分后：100
```

注意最后两行：`addScore(-5)` 抛出异常之后，`a.getScore()` 还是 90。被拒绝的操作**没有留下半个改动**，这才是"校验在写之前"的意思。

## `final` 只锁引用，不锁内容

```java
private final java.util.List<String> tags = new java.util.ArrayList<>();
```

`final` 保证的是"`tags` 这个字段不会再指向另一个 List"。下面这行完全合法：

```java
tags.add("java");   // 内容是能改的
```

想要内容也不可变，得换成 `List.of(...)` 这类不可变实现，或者干脆不暴露修改方法。这两条我一开始搞混过，写成了"`final` 对象不可变"，面试被问到时卡了半天。

## `equals` 和 `hashCode` 先记一句

默认的 `equals` 比的是"是不是同一个对象"：

```java
Student a = new Student("小林", 90);
Student b = new Student("小林", 90);
System.out.println(a.equals(b));   // false
System.out.println(a == b);        // false
```

想按内容比较就得自己重写 `equals`；重写 `equals` 就必须连 `hashCode` 一起重写，否则放进 `HashSet` 会"放进去却查不到"。为什么是这个机制，第 11 课专门拆——现在只要知道"这两个必须成对出现"，别单独重写一个。

另外，不重写 `toString` 时打印对象看到的是 `Student@6d06d69c`。`@` 后面是对象的哈希码十六进制，**每次运行都不一样**，所以别把它当固定输出抄进文档或断言里。

## 带走三句话

- 字段 `private` 不是为了藏，是为了让"什么值合法"只有一处负责。
- 构造器、setter、加分类方法，三个写入口必须落到同一个校验上。
- `final` 只锁引用；`equals` 和 `hashCode` 必须成对重写。
