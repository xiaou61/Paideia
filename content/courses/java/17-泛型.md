# 17 · 泛型：类型参数与通配符

## 这一课你要会

- 读懂 `List<String>`、`Map<K, V>`、`<T extends Comparable<T>>` 这些写法；
- 知道**类型擦除**是什么，以及它带来哪三条限制；
- 用通配符（`? extends` / `? super`）解决"传不进去"的编译错误；
- 判断什么时候该写泛型方法，什么时候直接用具体类型。

## 为什么

泛型是 Java 里"看懂了就再也不会写错、一直看不懂就一直绕着走"的东西。

它要解决的是**类型安全**：没有泛型时，`List` 里什么都存，取出来必须强转，转错了在运行时才炸。

```java
List raw = new ArrayList();
raw.add("hello");
raw.add(42);
String first = (String) raw.get(0);
int second = (int) raw.get(1);      // 这行编译过，运行炸
```

泛型把这类错误提前到编译期。代价是它有一层"擦除"机制，导致几条反直觉的限制。

## 讲解

### 基础：类型参数

```java
List<String> names = new ArrayList<>();
names.add("a");
// names.add(42);          // 编译错误，正是我们要的

Map<String, Integer> ages = new HashMap<>();
ages.put("alice", 30);
int age = ages.get("alice");   // 不需要强转
```

`<String>` 就是一个**类型参数**。它不是"运行时检查"，而是编译器替你插好了强转、并且禁止写错类型。

### 自己写泛型类

```java
class Box<T> {
    private T value;

    void set(T value) { this.value = value; }
    T get() { return value; }
}

Box<String> box = new Box<>();
box.set("hi");
String text = box.get();
```

`T` 只是一个名字，习惯用 `T`（Type）、`E`（Element）、`K`/`V`（Key/Value）、`R`（Result）。叫什么都行，含义靠约定。

### 泛型方法

```java
static <T> T firstOf(List<T> items) {
    return items.isEmpty() ? null : items.get(0);
}
```

`<T>` 写在返回类型前面，表示"这个方法是泛型的"。调用时类型自动推断：

```java
String s = firstOf(List.of("a", "b"));     // T 推断为 String
Integer n = firstOf(List.of(1, 2));         // T 推断为 Integer
```

### 有界泛型：`extends`

```java
static <T extends Comparable<T>> T max(List<T> items) {
    T best = items.get(0);
    for (T item : items) {
        if (item.compareTo(best) > 0) {
            best = item;
        }
    }
    return best;
}
```

`T extends Comparable<T>` 表示"T 必须是可比较的"。没有这个约束，`item.compareTo(...)` 编译不过——编译器不知道 `T` 有没有这个方法。

注意：**泛型的 `extends` 可以约束类，也可以约束接口**，统一写 `extends`。多个约束用 `&`：

```java
static <T extends Number & Comparable<T>> T maxNumber(List<T> items) { ... }
```

### 类型擦除：最关键的一条

**泛型只存在于编译期。运行时 `List<String>` 和 `List<Integer>` 是同一个类。**

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());   // true
```

编译器把 `List<String>` 里的 `String` **擦掉了**，运行时它只是 `List`。所以：


**限制一：不能 `new T()`。**

```java
class Box<T> {
    // T value = new T();     // 编译错误：运行时不知道 T 是什么
}
```

需要创建实例时，得把 `Class<T>` 传进来：

```java
static <T> T create(Class<T> type) throws Exception {
    return type.getDeclaredConstructor().newInstance();
}
```

**限制二：不能 `instanceof T`，也不能 `T[]`。**

```java
// if (obj instanceof T) {}       // 编译错误
// T[] array = new T[10];         // 编译错误
```

**限制三：基本类型不能当类型参数。**

```java
// List<int> numbers;             // 编译错误
List<Integer> numbers = new ArrayList<>();   // 必须用包装类
```

这就是为什么集合里只能用 `Integer` 不能用 `int`——上一课讲过装箱的代价，泛型是它的主要来源。

### 通配符：`? extends` 与 `? super`

先看这个场景：

```java
static void printAll(List<Object> items) {
    for (Object item : items) {
        System.out.println(item);
    }
}

List<String> names = List.of("a", "b");
printAll(names);   // 编译错误！
```

直觉上"`List<String>` 是 `List<Object>` 的一种"是错的——泛型**不支持这种协变**，因为如果可以，`printAll` 里就能往 `names` 里 `add(42)`。

解法是通配符：

```java
static void printAll(List<?> items) {      // 任意类型的 List
    for (Object item : items) {
        System.out.println(item);
    }
}
```

`List<?>` 表示"某种未知类型的 List"。你只能读（读出来是 `Object`），不能写（除了 `null`）。

### `? extends` 与 `? super` 的选择

这两个通配符有明确的用途，记住一句口诀：**PECS**（Producer Extends, Consumer Super）。

| 写法 | 含义 | 你能做什么 |
| --- | --- | --- |
| `List<? extends Number>` | "某个 Number 的子类型" | **读**：读出来当 `Number` 用；**不能写** |
| `List<? super Integer>` | "某个 Integer 的父类型" | **写**：能 `add(Integer)`；**读出来是 `Object`** |

```java
// 只读：接受 List<Integer>、List<Double>...
static double sum(List<? extends Number> items) {
    double total = 0;
    for (Number item : items) {
        total += item.doubleValue();
    }
    return total;
}

// 只写：接受 List<Integer>、List<Number>、List<Object>
static void fill(List<? super Integer> items, int count) {
    for (int i = 0; i < count; i++) {
        items.add(i);
    }
}
```

**为什么 `? extends` 不能写**：如果 `items` 实际是 `List<Double>`，你 `add(1)`（一个 `Integer`）就会破坏它的类型约束。编译器直接禁止。

**为什么 `? super` 读出来是 `Object`**：你不知道这个列表的准确类型，只知道它至少能装 `Integer`。往里放安全，往外拿只能当 `Object`。

**如果既要读又要写**：不要用通配符，直接写 `<T>`：

```java
static <T> void copy(List<T> from, List<T> to) {
    for (T item : from) {
        to.add(item);
    }
}
```

### 一个常见编译错误的翻译

```text
List<String> cannot be converted to List<Object>
```

意思是"泛型没有协变"。修法看你要干什么：只读用 `? extends`，只写用 `? super`，都干用 `<T>`。

### 泛型该不该用

**用**：写工具方法（`firstOf`、`max`、`copy`）、写容器类（`Box`、`Pair`）、写通用的转换函数。

**不该用**：业务代码里绝大多数类不需要泛型。给一个只会装 `User` 的 `UserRepository` 加个 `<T>` 是纯负担——类型参数只有在**真的会被多种类型复用**时才有价值。

## 动手

这段代码演示三件事：泛型方法的类型推断、类型擦除的证据、以及 `extends` / `super` 的实际差别。

<!-- run -->
```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    /** 泛型方法：T 由调用方推断。 */
    static <T> T firstOf(List<T> items) {
        return items.isEmpty() ? null : items.get(0);
    }

    /** 有界泛型：T 必须可比较。 */
    static <T extends Comparable<T>> T max(List<T> items) {
        T best = items.get(0);
        for (T item : items) {
            if (item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }

    /** ? extends：只读，接受任意 Number 子类型的列表。 */
    static double sum(List<? extends Number> items) {
        double total = 0;
        for (Number item : items) {
            total += item.doubleValue();
        }
        return total;
    }

    /** ? super：只写，接受 Integer 的任意父类型列表。 */
    static void fill(List<? super Integer> items, int count) {
        for (int i = 0; i < count; i++) {
            items.add(i);
        }
    }

    public static void main(String[] args) {
        System.out.println("firstOf: " + firstOf(List.of("a", "b")));
        System.out.println("max: " + max(List.of(3, 9, 2)));
        System.out.println("sum ints: " + sum(List.of(1, 2, 3)));
        System.out.println("sum doubles: " + sum(List.of(1.5, 2.5)));

        // 类型擦除的证据：两个不同泛型参数的 List 运行时是同一个类
        List<String> strings = new ArrayList<>();
        List<Integer> integers = new ArrayList<>();
        System.out.println("擦除后同类: " + (strings.getClass() == integers.getClass()));

        // ? super 可以写
        List<Object> sink = new ArrayList<>();
        fill(sink, 3);
        System.out.println("fill 结果: " + sink);
    }
}
```

```text
firstOf: a
max: 9
sum ints: 6.0
sum doubles: 4.0
擦除后同类: true
fill 结果: [0, 1, 2]
```

最后两行是关键：**擦除后两者是同一个类**（`java.util.ArrayList`），而 `List<Object>` 能接收 `fill` 的写入是因为 `Object` 是 `Integer` 的父类型。

## 常见误区

### 误区：`List<String>` 可以赋给 `List<Object>`

不能，编译错误。泛型不支持协变——如果能，就能通过 `List<Object>` 往里面塞 `Integer`，破坏 `List<String>` 的约束。要表达"某种类型的列表"用 `List<?>`。

### 误区：类型擦除后泛型就没用了

擦除只影响**运行时**。编译期的类型检查全部保留，而这正是泛型 99% 的价值：把强转写错这类错误从"上线后炸"变成"编译不通过"。

### 误区：通配符越多越好

`List<? extends Comparable<? super T>>` 这种能写出来，但可读性极差。除非你在写公共库，否则**先考虑用普通类型参数 `<T>`**，实在需要放宽才加通配符。

### 误区：泛型数组可以 `new T[]`

不行。擦除后运行时不知道 `T` 是什么，没法分配。要"泛型数组"的语义，用 `List<T>`，或者传 `Class<T>` 再用 `Array.newInstance(type, size)`。

## 小结

- `<T>` 是类型参数；泛型把类型错误从运行时提前到编译期。
- 有界泛型写 `<T extends Comparable<T>>`，类与接口都用 `extends` 约束。
- 类型擦除带来三条限制：不能 `new T()`、不能 `instanceof T`、不能用基本类型。
- 通配符口诀 PECS：**读用 `? extends`，写用 `? super`，都干用 `<T>`**。
- 业务代码里泛型要克制：只有真的会被多种类型复用时才值得加。
