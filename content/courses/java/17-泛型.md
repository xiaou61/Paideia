# 17 · 泛型：类型参数与通配符

## 这行 `(int)` 编译时只给警告，运行时才炸

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List raw = new ArrayList();
        raw.add("hello");
        raw.add(42);
        int first = (int) raw.get(0);
        int second = (int) raw.get(1);
        System.out.println(first);
        System.out.println(second);
    }
}
```

`javac --release 21 -Xlint:unchecked Main.java` 只给警告：

```text
Main.java:7: warning: [unchecked] unchecked call to add(E) as a member of the raw type List
        raw.add("hello");
               ^
  where E is a type-variable:
    E extends Object declared in interface List
Main.java:8: warning: [unchecked] unchecked call to add(E) as a member of the raw type List
        raw.add(42);
               ^
  where E is a type-variable:
    E extends Object declared in interface List
2 warnings
```

这两条都是 raw type 的 unchecked 调用：编译器不知道 `List` 里装什么，只能警告你。编译通过不等于安全。

`java Main` 才炸：

```text
Exception in thread "main" java.lang.ClassCastException: class java.lang.String cannot be cast to class java.lang.Integer (java.lang.String and java.lang.Integer are in module java.base of loader 'bootstrap')
	at Main.main(Main.java:9)
```

我原来以为 `(int) raw.get(0)` 会死在 `get` 里面。实际 `get` 只返回 `Object`；`(int)` 先检查这个 `Object` 是不是 `Integer`，再拆箱。`raw.get(0)` 是 `String`，所以异常抛在 `Main.main`。反过来，`int second = (int) raw.get(1);` 不会炸——`raw.get(1)` 本来就是 `Integer 42`，`(int)` 只是拆箱。把两行调换，炸的就是第二行。

同一类错误，`List<String>` 在编译期就拦：

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> names = new ArrayList<>();
        names.add("a");
        names.add(42);
    }
}
```

```text
Main.java:8: error: incompatible types: int cannot be converted to String
        names.add(42);
                  ^
1 error
```

`names.add(42)` 连运行机会都没有。泛型把 `ClassCastException` 提前成 `incompatible types`；代价是运行期还有一层擦除。

以上输出来自 Temurin 25.0.4：编译用 `javac --release 21`，运行用 `java`；英文报错用 `-Duser.language=en -Duser.country=US`（设置该变量后 `java`/`javac` 会多打一行 `Picked up JAVA_TOOL_OPTIONS`，上面的输出省略了它）。

## 先分清类型参数和类型实参

```java
class Box<T> {
    private T value;

    void set(T value) { this.value = value; }
    T get() { return value; }
}

public class Main {
    public static void main(String[] args) {
        Box<String> box = new Box<>();
        box.set("hi");
        String text = box.get();
        System.out.println(text);
    }
}
```

`T` 是**类型参数**（type parameter），是声明里的占位符；`String` 是**类型实参**（type argument），是调用时填进去的真实类型；`<String>` 是参数化类型 `Box<String>` 的实参列表。

中文资料常把两者都叫「类型参数」，但看到「`<String>` 是类型参数」这种说法要警惕：`String` 自己不是参数，它只是被填进 `T` 的实参。后文说 `<T>` 时，指的是左边那个声明。

`T` 只是个名字，习惯用 `T`（Type）、`E`（Element）、`K`/`V`（Key/Value）、`R`（Result）。叫什么都行，含义靠约定。

## `firstOf`：从参数推断 `T`

```java
static <T> T firstOf(List<T> items) {
    return items.isEmpty() ? null : items.get(0);
}
```

`<T>` 写在返回类型前面，表示这个方法自己声明类型参数。调用时类型从实参推断：

```java
String s = firstOf(List.of("a", "b"));   // T 推断为 String
Integer n = firstOf(List.of(1, 2));      // T 推断为 Integer
```

空列表返回 `null`；`firstOf` 不要求列表非空。

## `max`：`Comparable<T>` 太窄

先写一个看起来合理的版本：

```java
import java.util.List;

class Base implements Comparable<Base> {
    public int compareTo(Base other) { return 0; }
}

class Sub extends Base {}

public class Main {
    static <T extends Comparable<T>> T max(List<T> items) {
        T best = items.get(0);
        for (T item : items) {
            if (item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }

    public static void main(String[] args) {
        List<Sub> subs = List.of(new Sub());
        Sub result = max(subs);
    }
}
```

编译失败：

```text
error: method max in class Main cannot be applied to given types;
  required: List<T>
  found:    List<Sub>
  reason: inference variable T has incompatible equality constraints Base,Sub
  where T is a type-variable:
    T extends Comparable<T> declared in method <T>max(List<T>)
```

`Sub` 从 `Base` 继承了 `Comparable<Base>`，但 `Comparable<T>` 要求 `T` 能和自己比。`LocalDate` 也一样：它实现的是 `Comparable<ChronoLocalDate>`，不是 `Comparable<LocalDate>`。把 `List<LocalDate>` 先装进变量再传给旧版 `max`，会看到：

```text
reason: inference variable T has incompatible equality constraints ChronoLocalDate,LocalDate
```

要放宽成「T 的超类型实现了 Comparable 即可」，把边界改成 `Comparable<? super T>`：

```java
static <T extends Comparable<? super T>> T max(List<T> items) {
    T best = items.get(0);
    for (T item : items) {
        if (item.compareTo(best) > 0) {
            best = item;
        }
    }
    return best;
}
```

这样 `List<Sub>` 和 `List<LocalDate>` 都能过。`LocalDate` 的例子：

```java
List<LocalDate> dates = List.of(
        LocalDate.of(2026, 1, 1),
        LocalDate.of(2026, 2, 1));
System.out.println(max(dates));
```

```text
2026-02-01
```

注意 `List.of(...)` 直接写在 `max(...)` 里面时，`List.of` 会跟着目标类型一起推断；要复现上面的编译错误，先把列表声明成 `List<LocalDate> dates`。这类目标类型推断会让「看起来是 `List<LocalDate>`」的表达式实际变成 `List<ChronoLocalDate>`，别被它骗了。

`max` 要求 `items` 非空。`List<Integer> empty = List.of(); max(empty);` 会在 `items.get(0)` 抛 `ArrayIndexOutOfBoundsException: Index 0 out of bounds for length 0`（`List.of` 的不可变空列表实现；`ArrayList` 抛 `IndexOutOfBoundsException`）。直接写 `max(List.of())` 时，编译器先因为推断不出满足边界的 `T` 而报错，轮不到运行期。

多个上界用 `&` 连接。规则是：**类最多一个，且必须写在最前面，其余必须是接口**。合法写法：

```java
static <T extends Number & Comparable<T>> T maxNumber(List<T> items) {
    T best = items.get(0);
    for (T item : items) {
        if (item.compareTo(best) > 0) {
            best = item;
        }
    }
    return best;
}
```

反过来写 `T extends Comparable<T> & Number`，`javac` 报 `interface expected here`。`Number` 是类，不能跟在接口后面。

## 擦除：只剩最左边界

**泛型检查只存在于编译期。运行时 `List<String>` 和 `List<Integer>` 是同一个类。**

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());   // true
```

编译器把类型实参擦掉；字节码里只有 `List`，取元素时在调用点插入强转。但擦除不是一律擦成 `Object`。写四个方法放进 `Erasure.java`：

```java
public class Erasure {
    static <T> T unbounded(T value) { return value; }
    static <T extends Number> T boundedNumber(T value) { return value; }
    static <T extends Comparable<T>> T boundedComparable(T value) { return value; }
    static <T extends Number & Comparable<T>> T multi(T value) { return value; }
}
```

`javap -p -s Erasure` 的 descriptor：

```text
static <T> T unbounded(T);
  descriptor: (Ljava/lang/Object;)Ljava/lang/Object;

static <T extends java.lang.Number> T boundedNumber(T);
  descriptor: (Ljava/lang/Number;)Ljava/lang/Number;

static <T extends java.lang.Comparable<T>> T boundedComparable(T);
  descriptor: (Ljava/lang/Comparable;)Ljava/lang/Comparable;

static <T extends java.lang.Number & java.lang.Comparable<T>> T multi(T);
  descriptor: (Ljava/lang/Number;)Ljava/lang/Number;
```

无界 `T` 擦成 `Object`；`T extends Number` 擦成 `Number`；`T extends Comparable<T>` 擦成 `Comparable`；多边界擦成最左边的 `Number`。所以 `max` 里的 `item.compareTo(best)` 在擦除后还能调——`T` 的上界本来就是 `Comparable`，不是 `Object`。

## 三条限制，加一条独立的

擦除带来三条限制。

**限制一：不能 `new T()`。**

```java
class Box<T> {
    T value = new T();   // 编译错误：unexpected type
}
```

编译器报 `required: class`、`found: type parameter T`。要按类型创建实例，得让调用方传一个创建方法（工厂）；反射第 27 课再讲，这里先跳过。

**限制二：不能 `instanceof T`。**

```java
static <T> boolean isType(Object value) {
    return value instanceof T;   // 编译错误：Object cannot be safely cast to T
}
```

**限制三：不能 `new T[10]`。**

```java
static <T> T[] make() {
    return new T[10];   // 编译错误：generic array creation
}
```

这三条都来自同一件事：运行时不知道 `T` 是什么。

但要说清楚：**`T[]` 作为参数、返回值、局部变量的类型是合法的**。非法的只是 `new T[10]`：

```java
public class Main {
    static <T> void take(T[] items) {
        System.out.println(items.length);
    }

    public static void main(String[] args) {
        take(new String[]{"a", "b"});
    }
}
```

```text
2
```

数组在运行时由调用方给的数组决定组件类型，方法签名里的 `T[]` 不需要自己分配。真要自己造数组，得传 `Class<T>` 再用 `Array.newInstance`（会有 unchecked 警告），那还是反射，第 27 课再说。

另一条限制不是擦除带来的：**基本类型不能作类型实参**。

```java
List<int> numbers = new ArrayList<>();   // 编译错误：required: reference, found: int
List<Integer> boxed = new ArrayList<>(); // 必须用包装类
```

第 10 课讲过装箱的代价，集合里只能用 `Integer` 不能用 `int`，泛型集合会频繁装箱。这个限制来自「泛型只接受引用类型」，和运行期擦除到哪个边界无关。

## `List<Object>` 不是 `List<String>` 的父类型

```java
static void printAll(List<Object> items) {
    for (Object item : items) {
        System.out.println(item);
    }
}

List<String> names = List.of("a", "b");
printAll(names);
```

```text
error: incompatible types: List<String> cannot be converted to List<Object>
```

直觉上「`List<String>` 是 `List<Object>` 的一种」是错的。泛型不支持这种协变；如果支持，`printAll` 里就能往 `names` 里 `add(42)`。

解法是通配符：

```java
static void printAll(List<?> items) {
    for (Object item : items) {
        System.out.println(item);
    }
}
```

`List<?>` 表示「某种未知类型的 List」。它**不是只能读**：

```java
List<?> items = new ArrayList<>(List.of("a", "b"));
items.remove(0);        // 能编译
items.remove("b");      // 能编译
items.add(null);        // 能编译
System.out.println(items);   // [null]
items.clear();          // 能编译
System.out.println(items.size());   // 0
```

`remove(int)`、`remove(Object)`、`clear()` 不依赖元素的具体类型；`add(null)` 对任何引用类型都成立。在这几个操作里，只有 `add(非 null)` 被禁；`set` 非 null 同样不行。

```text
error: incompatible types: String cannot be converted to CAP#1
  where CAP#1 is a fresh type-variable:
    CAP#1 extends Object from capture of ?
```

所以准确说法是「不能 `add` 非 null」，不是「只能读」。

## PECS：一个列表和两个列表

`? extends` 和 `? super` 的用途记一句：**PECS**（Producer Extends, Consumer Super）。

| 写法 | 读出来 | 写进去 |
| --- | --- | --- |
| `List<? extends Number>` | 能当 `Number` 用 | 不能 `add` 非 null |
| `List<? super Integer>` | 只能当 `Object` 用 | 能 `add(Integer)` |

```java
// 只读：接受 List<Integer>、List<Double>...
static double sum(List<? extends Number> items) {
    double total = 0;
    for (Number item : items) {
        total += item.doubleValue();
    }
    return total;
}

// 只写：接受 List<Integer>、List<Number>、List<Object>
static void fill(List<? super Integer> items, int count) {
    for (int i = 0; i < count; i++) {
        items.add(i);
    }
}
```

**为什么 `? extends` 不能写**：如果 `items` 实际是 `List<Double>`，你 `add(1)`（一个 `Integer`）就会破坏它的类型约束。`add(null)` 能过，但没有实际意义。

**为什么 `? super` 读出来是 `Object`**：你不知道列表的准确类型，只知道它至少能装 `Integer`。往里放安全，往外拿只能当 `Object`。

### 同一个列表：`<T>` 就够

```java
static <T> void swap(List<T> items, int i, int j) {
    T tmp = items.get(i);
    items.set(i, items.get(j));
    items.set(j, tmp);
}
```

一个列表同时读和写，取出来的 `T` 要能原样放回去，所以元素类型必须一致。`<T>` 正好；`List<? extends T>` 读得到但写不进，`List<? super T>` 写得进但读出来只是 `Object`。

### 两个列表：`copy(List<T>, List<T>)` 只适合同类型

```java
static <T> void copy(List<T> from, List<T> to) {
    for (T item : from) {
        to.add(item);
    }
}
```

这个签名只能复制元素类型完全相同的两个列表。`List<Integer>` 复制到 `List<Number>` 编译失败：

```text
error: method copy in class Main cannot be applied to given types;
  required: List<T>,List<T>
  found:    List<Integer>,List<Number>
  reason: inference variable T has incompatible equality constraints Number,Integer
```

JDK 的 `Collections.copy` 不是这个签名。`javap java.util.Collections`：

```text
public static <T> void copy(java.util.List<? super T>, java.util.List<? extends T>);
```

目标列表是消费者，用 `? super T`；源列表是生产者，用 `? extends T`：

```java
static <T> void copy(List<? super T> to, List<? extends T> from) {
    for (T item : from) {
        to.add(item);
    }
}

List<Integer> src = List.of(1, 2, 3);
List<Number> dst = new ArrayList<Number>();
copy(dst, src);
System.out.println(dst);   // [1, 2, 3]
```

参数顺序是 `copy(目标, 源)`，和 `Collections.copy` 一致；别把 `to`/`from` 写反。注意 JDK 的 `Collections.copy` 是按索引覆盖，目标列表必须先有至少 `src.size()` 个位置；上面这个 `copy` 用 `add`，所以从空列表开始。名字像，行为不一样。

这就是「同一个列表」和「两个列表」要分开讲的原因：一个列表时 `<T>` 够；两个列表有子类型关系时，必须双通配符。

## 泛型该不该用

**用**：写工具方法（`firstOf`、`max`）、容器类（`Box`）、通用的转换函数。

**不该用**：业务类只为一种类型服务时，不要加类型参数。一个只装 `User` 的 `UserRepository` 写成 `UserRepository<T>` 没有收益，调用方还得多写一个类型实参。类型参数只有在真的会被多种类型复用时才值回票价。

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    static <T> T firstOf(List<T> items) {
        return items.isEmpty() ? null : items.get(0);
    }

    static <T extends Comparable<? super T>> T max(List<T> items) {
        T best = items.get(0);   // 要求 items 非空
        for (T item : items) {
            if (item.compareTo(best) > 0) {
                best = item;
            }
        }
        return best;
    }

    static double sum(List<? extends Number> items) {
        double total = 0;
        for (Number item : items) {
            total += item.doubleValue();
        }
        return total;
    }

    static void fill(List<? super Integer> items, int count) {
        for (int i = 0; i < count; i++) {
            items.add(i);
        }
    }

    public static void main(String[] args) {
        System.out.println("firstOf: " + firstOf(List.of("a", "b")));
        System.out.println("max: " + max(List.of(3, 9, 2)));
        System.out.println("sum ints: " + sum(List.of(1, 2, 3)));
        System.out.println("sum doubles: " + sum(List.of(1.5, 2.5)));

        List<String> strings = new ArrayList<>();
        List<Integer> integers = new ArrayList<>();
        System.out.println("擦除后同类: " + (strings.getClass() == integers.getClass()));

        List<Object> sink = new ArrayList<>();
        fill(sink, 3);
        System.out.println("fill 结果: " + sink);
    }
}
```

```text
firstOf: a
max: 9
sum ints: 6.0
sum doubles: 4.0
擦除后同类: true
fill 结果: [0, 1, 2]
```

`擦除后同类: true` 是因为两个空 `ArrayList` 运行期都是 `java.util.ArrayList`；`fill 结果` 能写进 `List<Object>`，是因为 `Object` 是 `Integer` 的父类型，正好符合 `? super Integer`。

## 还差的

- 泛型可变参数 `T...` 与 `@SafeVarargs` 没讲；它和 `new T[]` 是同一个擦除问题，但处理方式不同。
- 桥方法（bridge method）没展开；继承泛型类并重写方法时，编译器会生成额外方法，`javap` 能看到。
- 通配符捕获（`CAP#1`）只提到了报错文本，没讲怎么用辅助方法把 `?` 捕获成 `T`。
- 反射创建泛型实例、`Array.newInstance` 造数组没写，留到第 27 课。
