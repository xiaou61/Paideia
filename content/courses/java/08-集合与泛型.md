# 08 · 集合与泛型

## 三个学号相同的人，`HashSet` 说他们是三个人

选修课报名表收上来，我先想到 `Set`：同一个学号不该进两次。下面这段能直接粘进 `Main.java` 跑：

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

class Student {
    final String id;
    final String name;

    Student(String id, String name) {
        this.id = id;
        this.name = name;
    }
}

public class Main {
    public static void main(String[] args) {
        List<Student> roster = new ArrayList<>();
        roster.add(new Student("2024001", "小林"));
        roster.add(new Student("2024002", "小周"));
        roster.add(new Student("2024001", "小林"));

        Set<Student> unique = new HashSet<>(roster);
        System.out.println(unique.size());
        System.out.println(unique.contains(new Student("2024001", "小林")));
    }
}
```

JDK 25 上（`javac --release 21`）跑出来是这两行：

```text
3
false
```

我原来的判断是「`Set` 自动去重，同一个学号只会留一条」。错的是我。`HashSet` 判两样东西是不是同一个，走两步：先 `hashCode()` 决定丢进哪个桶，再在该桶里用 `equals()` 逐个比。两步都调用对象自己的实现。`Student` 没写这两个方法，继承来的 `equals` 比的是「是不是同一个对象」，而 `new` 出来的是三个不同对象——内容一字不差，也不算同一个人。

这个坑的完整版（重写了 `equals` 却忘了 `hashCode`，`contains` 直接给 `false`）在第 11 课，整篇都在拆它。这一课只取一条结论：**自定义对象要按内容去重，`equals` 和 `hashCode` 得自己写**。

不写这两个方法也有路走。报名表里真正唯一的键是学号，那就别让 `Set` 猜，自己建索引：

```java
Map<String, Student> byId = new HashMap<>();
for (Student student : roster) {
    byId.put(student.id, student);
}
System.out.println(byId.size());           // 2
System.out.println(byId.get("2024009"));   // null，不抛异常
```

同一份名单，换个容器从 3 条变 2 条。不是玄学：`Map` 的键是 `String`，而 `String` 自带「内容相等」的定义。把 `HashSet` 里的元素换成学号字符串，结果立刻不一样：

```text
只装学号字符串时：2
```

`Set` 能按内容去重，前提是装的类型知道什么叫「相等」。`Map.get` 找不到键返回 `null`，而 `List` 接口约定的越界行为是抛 `IndexOutOfBoundsException`（`List.get` 的 Javadoc 写明了这一点）——两种「没有」，一种给 `null`，一种给异常，后面写判空代码时会反复撞上。

## 编译期拦下的那句，和运行期才炸的那句

名单里还挂着一列昵称 `List<String> nicknames`。有一次我把学号当昵称塞了进去（`Integer` 这个包装类第 10 课细讲，这里只要知道它不是 `String`）：

```java
Integer id = 2024001;
nicknames.add(id);
```

JDK 25 的 javac 配 `--release 21`，原话是：

```text
Main.java:8: error: incompatible types: Integer cannot be converted to String
        nicknames.add(id);
                      ^
Note: Some messages have been simplified; recompile with -Xdiags:verbose to get full output
1 error
```

这就是泛型买到的东西：元素类型在编译期检查，检查点就是这次调用。编译器认的是 `List<String>` 这个声明，`Integer` 进不去。

那绕过编译器呢？原始类型 `List` 就是那个后门——它让编译器闭嘴，只留一条 unchecked 警告：

```java
List raw = nicknames;
raw.add(Integer.valueOf(42));      // 只有警告，编译通过，运行时也不报错
String name = nicknames.get(0);    // 这一行才炸
```

```text
塞进 Integer 之后 size = 1
get 的时候：class java.lang.Integer cannot be cast to class java.lang.String (java.lang.Integer and java.lang.String are in module java.base of loader 'bootstrap')
```

`add` 那一刻什么都没发生，`size` 从 0 变 1，连 `System.out.println(nicknames)` 都会老老实实把 `42` 打出来。异常出现在**取出来赋给 `String`** 的那一行：擦除之后，编译器把类型转换插在 `get` 的调用点上，`Integer` 过不去。

我以为 `add` 会当场拒绝，实际它接受得干干净净，账记在 `get` 上。换成自己写的类型，消息只是把 `String` 换成 `Student`，还多一段加载器信息：

```text
取出来才炸：class java.lang.Integer cannot be cast to class Student (java.lang.Integer is in module java.base of loader 'bootstrap'; Student is in unnamed module of loader 'app')
```

所以擦除的代价不只是「拿不到类型」，还包括**错误位置离写错的地方很远**：`add` 在 A 方法里，异常在 B 方法的 `get` 上。栈顶看起来跟你改的代码毫无关系，排查时先找「这个集合有没有跨过泛型边界」。

顺手记一条：泛型不协变。`List<String>` 不能当 `List<Object>` 用。

```text
Main.java:6: error: incompatible types: List<String> cannot be converted to List<Object>
        List<Object> objects = nicknames;
                               ^
1 error
```

「那怎么把子类型列表传进只读参数」属于通配符，第 17 课。

## 擦除擦掉的到底是什么

把两个列表的运行时类拿出来比：

```text
两个列表的运行时类相同：true
运行时类名：java.util.ArrayList
```

`List<String>` 和 `List<Integer>` 在运行期是同一个类，`String`、`Integer` 都不在里面。三个直接后果，报错我一个个跑过。

不能 `new T()`：

```text
Main.java:4: error: unexpected type
            return new T();
                       ^
  required: class
  found:    type parameter T
  where T is a type-variable:
    T extends Object declared in class Box
1 error
```

不能对带类型实参的类型做 `instanceof`：

```text
Main.java:6: error: Object cannot be safely cast to List<String>
        if (value instanceof List<String>) {
            ^
1 error
```

不能创建泛型数组：

```text
Main.java:5: error: generic array creation
        List<String>[] buckets = new List<String>[3];
                                 ^
1 error
```

（`instanceof` 那句的措辞随 javac 版本变过，别拿整句当搜索关键词，用 `instanceof` 加泛型更稳。）

**但「擦除」不等于「声明处的泛型也没了」。** 反射读一个字段，类型实参还在（反射那套 API 后面有单独一课，这里只借它验证一件事）：

```text
字段声明处：java.util.List<java.lang.String>
类型实参：java.lang.String
对象上只剩：E
```

class 文件里留着泛型签名（`Signature` 属性），所以字段、方法参数、返回值上写的 `List<String>`，反射读得到；而一个 `ArrayList` 实例上，只剩它自己声明时用的那个符号 `E`，`String` 无处可寻。

准确的说法是**类型实参不进运行期**，不是「泛型在运行期完全不存在」。这个区别在写框架代码时是分水岭：序列化、依赖注入那些库正是靠读声明处的签名工作的，它们读不到的是「这个具体实例里装的是什么」。

## 名单是从数组来的：改列表会不会改到数组

报名名单最初是 `String[]`（从 CSV 拆出来的），我拿 `Arrays.asList` 转成 `List`：

```text
改了视图，数组变成：[林, 小周]
视图 add：java.lang.UnsupportedOperationException
```

`set` 改到了原数组，`add` 抛 `UnsupportedOperationException`。`Arrays.asList` 返回的是原数组的**视图**：定长，能改元素，不能增删。`Arrays.asList("小林", null)` 也照收，`size` 是 2——它不检查元素。

`List.of` 是另一回事，它真不可变，连 `set` 都不行：

```text
List.of set：java.lang.UnsupportedOperationException
包一层再改：[小林, 小周]
```

还有一条容易漏的差别：`List.of` 不接受 `null` 元素。这不是编译错误，是运行时异常：

```text
List.of 带 null：java.lang.NullPointerException
```

要能增删就用 `new ArrayList<>(…)` 包一层。这个包装是拷贝，之后改列表不会影响原数组。

到这里可以把几种症状收成一张速查表——看到现象，先查那一格：

| 看到的现象 | 先查哪里 |
| --- | --- |
| `add` 抛 `UnsupportedOperationException` | 这个 `List` 哪来的：`Arrays.asList` 定长，`List.of` / `List.copyOf` 不可变 |
| 往 `Set` 放两次同一个业务对象，`size` 还是 2 | 这个类有没有写 `equals` 与 `hashCode`（第 11 课） |
| `add` 顺利，取出来赋值时 `ClassCastException` | 中间有没有用原始类型、反射，或把集合跨泛型边界传过 |
| `for` 里删元素，有时抛 CME，有时元素凭空少一个 | 删完之后还有没有下一次 `next()`；直接换 `removeIf` |
| `HashMap` / `HashSet` 遍历顺序和插入顺序对不上 | 顺序不是语言保证；要顺序用 `LinkedHashMap`（第 12 课） |

## 循环里删元素，抛不抛看删完还有没有下一次 `next()`

同一个增强 `for` 循环，只改列表长度和删哪个位置，结果不一样（JDK 25，`ArrayList`）：

| 起点 | 结果 |
| --- | --- |
| 3 个元素，删第 1 个 | `ConcurrentModificationException`，只访问到 1 个元素 |
| 3 个元素，删中间那个 | 不抛，最后一个元素被静默跳过 |
| 2 个元素，删第 1 个 | 不抛，第 2 个元素被静默跳过 |
| 2 个元素，删最后 1 个 | `ConcurrentModificationException` |
| 1 个元素，删它自己 | `ConcurrentModificationException` |

「遍历时删除一定抛 CME」这句话是错的。CME 只是 fail-fast 的**尽力而为**（`ArrayList` 的 Javadoc 写的是 fail-fast 行为无法保证、只在 best-effort 的意义上抛），抛不抛取决于删完之后迭代器还会不会调 `next()`：

- 删完 `hasNext()` 变回 `false`，循环提前收工，异常不出现，代价是被删元素后面的元素整体前移一格、**没被检查就出局**；
- 删完 `hasNext()` 仍为 `true`，下一次 `next()` 发现 `modCount` 对不上，抛 CME。

`ArrayList.Itr.hasNext()` 在当前实现里就是 `cursor != size` 这一句比较——实现细节，不是规范。能依赖的只有一条：**边遍历边改，结果不保证**。

要删就三条路，都不用你猜 `modCount`：

```java
waiting.removeIf("小林"::equals);        // 按条件批量删，首选

// 或者用迭代器自己删
Iterator<String> it = waiting.iterator();  // import java.util.Iterator;
while (it.hasNext()) {
    if (it.next().equals("小林")) {
        it.remove();
    }
}

// 或者干脆重建一个新列表
List<String> kept = new ArrayList<>();
for (String name : waiting) {
    if (!name.equals("小林")) {
        kept.add(name);
    }
}
```

`removeIf` 那条的实测输出：

```text
removeIf 之后：[小周]
```

## 跑一遍

上面每一段拼在一起，就是这份名单的完整走一遍。注意 `Student` 这次补了 `toString`，否则打印出来是 `Student@...` 这种带身份哈希的东西，每次运行都不一样。

<!-- run -->
```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

class Student {
    final String id;
    final String name;

    Student(String id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public String toString() {
        return id + " " + name;
    }
}

public class Main {
    public static void main(String[] args) {
        List<Student> roster = new ArrayList<>();
        roster.add(new Student("2024001", "小林"));
        roster.add(new Student("2024002", "小周"));
        roster.add(new Student("2024001", "小林"));
        System.out.println("名单条数：" + roster.size());

        Set<Student> unique = new HashSet<>(roster);
        System.out.println("丢进 HashSet 之后：" + unique.size());
        System.out.println("同一个学号认不认：" + unique.contains(new Student("2024001", "小林")));

        Set<String> ids = new HashSet<>(List.of("2024001", "2024002", "2024001"));
        System.out.println("只装学号字符串时：" + ids.size());

        Map<String, Student> byId = new HashMap<>();
        for (Student student : roster) {
            byId.put(student.id, student);
        }
        System.out.println("按学号建索引：" + byId.size());
        System.out.println("2024002 是：" + byId.get("2024002"));
        System.out.println("2024009 是：" + byId.get("2024009"));

        String[] array = {"小林", "小周"};
        List<String> view = Arrays.asList(array);
        view.set(0, "林");
        System.out.println("改了视图，数组变成：" + Arrays.toString(array));
        try {
            view.add("小吴");
        } catch (UnsupportedOperationException error) {
            System.out.println("视图 add：" + error);
        }

        List<String> fixed = List.of("小林", "小周");
        try {
            fixed.set(0, "林");
        } catch (UnsupportedOperationException error) {
            System.out.println("List.of set：" + error);
        }
        System.out.println("包一层再改：" + new ArrayList<>(fixed));

        List<String> waiting = new ArrayList<>(List.of("小林", "小周", "小吴"));
        try {
            for (String name : waiting) {
                if (name.equals("小林")) {
                    waiting.remove(name);
                }
            }
        } catch (RuntimeException error) {
            System.out.println("三个元素删第一个：" + error);
        }

        List<String> waiting2 = new ArrayList<>(List.of("小林", "小周"));
        try {
            for (String name : waiting2) {
                if (name.equals("小林")) {
                    waiting2.remove(name);
                }
            }
            System.out.println("两个元素删第一个没抛，剩下：" + waiting2);
        } catch (RuntimeException error) {
            System.out.println("两个元素删第一个抛了：" + error);
        }

        List raw = roster;
        raw.add(Integer.valueOf(42));
        System.out.println("绕过泛型之后条数：" + roster.size());
        try {
            Student last = roster.get(3);
            System.out.println(last);
        } catch (ClassCastException error) {
            System.out.println("取出来才炸：" + error.getMessage());
        }
    }
}
```

丢进 HashSet 之后：3
同一个学号认不认：false

按学号建索引：2
2024002 是：2024002 小周
2024009 是：null
改了视图，数组变成：[林, 小周]
视图 add：java.lang.UnsupportedOperationException
List.of set：java.lang.UnsupportedOperationException
包一层再改：[小林, 小周]
三个元素删第一个：java.util.ConcurrentModificationException
两个元素删第一个没抛，剩下：[小周]

## 还差的

1. `equals` / `hashCode` 只到「必须写」这一步。怎么写、五条契约、`hashCode` 冲突之后链表怎么退化，都在第 11 课；这篇没有给你验证「我写对了」的手段。
2. 通配符（`? extends` / `? super`）与 PECS 一个字没提，那是第 17 课。所以文中「`List<String>` 不能当 `List<Object>`」只说了不行，没说「怎么把子类型列表传给只读参数」。
3. 集合选型没做：`ArrayList` 与 `LinkedList` 的增删差距、`HashMap` 与 `TreeMap` 的成本，这篇一个数都没测，留到第 12 课。
4. 表格里「遍历顺序不是语言保证」这句我是按 `HashMap` 文档写的，没有跨 JDK 版本对比过实际遍历顺序——它是提醒，不是实测结论。
5. 这篇用到的集合实现都不是线程安全的，多线程同时改同一个 `List` 会以什么形式坏掉，完全没测，第 22 课再补。
