# 19 · 日期时间：LocalDate、Instant 与跨时区

## 这一课你要会

- 分清 `LocalDate` / `LocalTime` / `LocalDateTime` / `Instant` / `ZonedDateTime` 各自代表什么；
- 知道**什么时候必须用 `Instant`**，什么时候用 `LocalDate` 就够；
- 做日期加减、格式化与解析，不用 `SimpleDateFormat`；
- 认出"存本地时间还是存 UTC"这个决定带来的后果。

## 为什么

老的 `Date` + `Calendar` + `SimpleDateFormat` 有三个硬伤：可变（能被人改）、月份从 0 开始（一月是 0）、`SimpleDateFormat` 不是线程安全的（多线程共用会给出错乱结果）。

Java 8 起有了 `java.time` 包，全部不可变、线程安全、语义清晰。**新代码不要再用 `Date`**。

真正难的不是 API，是**"这个时间点该用哪个类型"**。选错了，跨时区就出问题。

## 讲解

### 五种类型，各代表什么

| 类型 | 含义 | 例子 | 什么时候用 |
| --- | --- | --- | --- |
| `LocalDate` | 只有日期 | `2026-10-20` | 生日、账期、到期日 |
| `LocalTime` | 只有时间 | `14:30:00` | 每天几点开门 |
| `LocalDateTime` | 日期 + 时间，**没有时区** | `2026-10-20T14:30` | 本地日历上的一个刻度 |
| `Instant` | **时间轴上的一个点**（UTC） | `2026-10-20T06:30:00Z` | 记录"事情发生的时刻" |
| `ZonedDateTime` | 时间点 + 具体时区 | `2026-10-20T14:30+08:00[Asia/Shanghai]` | 要按时区算规则 |

**最容易搞错的一对**：`LocalDateTime` 与 `Instant`。

`LocalDateTime` 说"2026-10-20 14:30"，但它**不知道自己属于哪个时区**。同样写 `14:30`，在北京和伦敦是两个不同的时刻。

`Instant` 说的是"距离 1970-01-01 00:00:00 UTC 过了多少纳秒"——它唯一确定一个时刻，与时区无关。

### 一条实用规则

> **记录"什么时候发生的"用 `Instant`；记录"日历上的哪一天"用 `LocalDate`。**

例如：

```java
Instant createdAt = Instant.now();      // 用户注册时刻
LocalDate birthday = LocalDate.of(1995, 3, 8);   // 生日：没有"时刻"这回事
```

**为什么 `createdAt` 不能用 `LocalDateTime`**：如果服务器在东京、用户在北京，同一行 `2026-10-20T14:30` 到底是哪个时刻？换个部署区域，历史数据的含义就变了。

### 创建与解析

```java
// 现在
LocalDate today = LocalDate.now();                    // 用系统默认时区
LocalDate todayInTokyo = LocalDate.now(ZoneId.of("Asia/Tokyo"));
Instant now = Instant.now();                          // UTC，永远可用

// 指定值
LocalDate date = LocalDate.of(2026, 10, 20);          // 月份是 1..12，不是 0..11
LocalTime time = LocalTime.of(14, 30);
LocalDateTime dateTime = LocalDateTime.of(date, time);

// 解析
LocalDate parsed = LocalDate.parse("2026-10-20");               // ISO 格式
LocalDate custom = LocalDate.parse("2026/10/20",
        DateTimeFormatter.ofPattern("yyyy/MM/dd"));
```

`LocalDate.of(2026, 10, 20)` 里十月就是 `10`——这是相对 `Calendar` 的一大改进（老 API 里十月是 `9`）。

### 加减：返回新对象

`java.time` 的类**全部不可变**，所有"修改"都返回新对象：

```java
LocalDate today = LocalDate.of(2026, 10, 20);
LocalDate nextWeek = today.plusWeeks(1);      // 新对象
LocalDate lastMonth = today.minusMonths(1);

System.out.println(today);      // 2026-10-20，没变
System.out.println(nextWeek);   // 2026-10-27
```

`plusMonths(1)` 遇到月末有特殊处理：`2026-01-31` 加一个月得 `2026-02-28`（不是 3 月 3 日），这是"月末对齐"规则，比手工算靠谱。

### 时区转换

```java
Instant instant = Instant.parse("2026-10-20T06:30:00Z");

// Instant → 某时区的时间
ZonedDateTime beijing = instant.atZone(ZoneId.of("Asia/Shanghai"));
System.out.println(beijing);    // 2026-10-20T14:30+08:00[Asia/Shanghai]

// 某时区的时间 → Instant
Instant back = beijing.toInstant();   // 回到 06:30Z

// 需要 LocalDateTime 时显式给时区
LocalDateTime local = LocalDateTime.ofInstant(instant, ZoneId.of("Asia/Shanghai"));
```

关键点：**`LocalDateTime` 与 `Instant` 之间互转必须给时区**，这是编译器在提醒你"这里有歧义"。

### 格式化：用 `DateTimeFormatter`

```java
DateTimeFormatter format = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");

String text = LocalDateTime.now().format(format);
LocalDateTime parsed = LocalDateTime.parse("2026-10-20 14:30:00", format);
```

**`DateTimeFormatter` 是不可变且线程安全的**，可以做成常量反复用：

```java
private static final DateTimeFormatter FORMAT =
        DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
```

这和 `SimpleDateFormat`（有状态、必须每次新建或加锁）是本质区别。

### 与时间戳互转

```java
// Instant ↔ 毫秒时间戳
long epochMilli = System.currentTimeMillis();
Instant fromMilli = Instant.ofEpochMilli(epochMilli);

// Instant → 秒
long epochSecond = fromMilli.getEpochSecond();
```

数据库里存 `BIGINT` 时间戳、或者和前端 JS 交互（JS 的 `Date` 就是毫秒数）时用这套。

### 两个高频陷阱

**陷阱一：`Duration` 与 `Period` 别混。**

```java
Duration.between(t1, t2)   // 两个 Instant 之间的"时长"，按秒/纳秒
Period.between(d1, d2)     // 两个 LocalDate 之间的"日期间隔"，按年/月/日
```

`Duration` 用于时刻差（"这个请求花了 230ms"）；`Period` 用于日期差（"入职 3 年 2 个月"）。

**陷阱二：不要对 `LocalDateTime` 做"跨时区"运算。**

```java
// 错：东京的 9:00 与北京的 9:00 差了 1 小时
LocalDateTime tokyoNine = LocalDateTime.of(2026, 10, 20, 9, 0);
LocalDateTime beijingNine = LocalDateTime.of(2026, 10, 20, 9, 0);
// 这两个"看起来同时"，实际相差一小时
```

要表达"同一时刻"，用 `Instant` 或 `ZonedDateTime`；`LocalDateTime` 只适合"本地日历上的刻度"。

## 动手

这段代码演示同一时刻在三个时区下的表示，以及不可变与格式化的行为。

<!-- run -->
```java
import java.time.Duration;
import java.time.Instant;
import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.ZoneId;
import java.time.ZonedDateTime;
import java.time.format.DateTimeFormatter;

public class Main {
    public static void main(String[] args) {
        // 1) 同一时刻，不同时区
        Instant instant = Instant.parse("2026-10-20T06:30:00Z");
        System.out.println("UTC     : " + instant);
        System.out.println("北京    : " + instant.atZone(ZoneId.of("Asia/Shanghai")));
        System.out.println("东京    : " + instant.atZone(ZoneId.of("Asia/Tokyo")));

        // 2) 不可变：加减返回新对象
        LocalDate base = LocalDate.of(2026, 1, 31);
        LocalDate plusMonth = base.plusMonths(1);
        System.out.println("原值    : " + base);
        System.out.println("加一个月: " + plusMonth);

        // 3) 格式化与解析
        DateTimeFormatter format = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
        LocalDateTime moment = LocalDateTime.of(2026, 10, 20, 14, 30, 5);
        String text = moment.format(format);
        System.out.println("格式化  : " + text);
        System.out.println("解析回来: " + LocalDateTime.parse(text, format));

        // 4) 时长：Duration 按秒算，不是按日历
        Instant start = Instant.parse("2026-10-20T06:30:00Z");
        Instant end = Instant.parse("2026-10-20T06:30:02Z");
        Duration spent = Duration.between(start, end);
        System.out.println("耗时毫秒: " + spent.toMillis());

        // 5) LocalDateTime 与 Instant 互转必须给时区
        ZonedDateTime beijing = instant.atZone(ZoneId.of("Asia/Shanghai"));
        LocalDateTime local = LocalDateTime.ofInstant(instant, ZoneId.of("Asia/Shanghai"));
        System.out.println("本地时间: " + local);
        System.out.println("回到 UTC: " + beijing.toInstant());
    }
}
```

```text
UTC     : 2026-10-20T06:30:00Z
北京    : 2026-10-20T14:30+08:00[Asia/Shanghai]
东京    : 2026-10-20T15:30+09:00[Asia/Tokyo]
原值    : 2026-01-31
加一个月: 2026-02-28
格式化  : 2026-10-20 14:30:05
解析回来: 2026-10-20T14:30:05
耗时毫秒: 2000
本地时间: 2026-10-20T14:30
回到 UTC: 2026-10-20T06:30:00Z
```

注意第三行「加一个月」：`1 月 31 日 + 1 个月` 得到 `2 月 28 日`，不是 `3 月 3 日`。这是"月末对齐"：目标月份没有 31 号时取该月最后一天。

## 常见误区

### 误区：`LocalDateTime` 就是"时间"，可以随便存

它没有时区。存进库里之后，同一行数据在不同部署区域的解释不同。**要记录时刻就用 `Instant`（数据库里通常存 UTC 的 `DATETIME` 或时间戳）**。

### 误区：时区直接用 `ZoneId.of("GMT+8")`

偏移量不是时区。`GMT+8` 没有夏令时规则，而真实时区（`Asia/Shanghai`）有完整规则。**用地区名，不用偏移量**。

### 误区：`Duration.between` 能算"相差几个月"

不能，它按秒算。日历上的"几个月"要用 `Period`，而且"一个月"的天数本身不固定。

### 误区：月份、星期可以直接用数字

`LocalDate.getMonthValue()` 返回 1..12（符合直觉），但 `DayOfWeek` 是枚举，`getValue()` 返回 1..7（周一是 1）。想可读就用 `Month.OCTOBER`、`DayOfWeek.MONDAY` 这些常量，别写裸数字。

## 小结

- `LocalDate` / `LocalTime` / `LocalDateTime` 是**本地日历**上的刻度，没有时区。
- `Instant` 是**时间轴上的点**，用于记录"何时发生"。
- `ZonedDateTime` = 时刻 + 时区规则，用于按时区计算。
- 所有 `java.time` 类**不可变**，加减返回新对象。
- `DateTimeFormatter` 线程安全可复用；`SimpleDateFormat` 有状态，新代码不要用。
- 时刻差用 `Duration`，日期间隔用 `Period`。
