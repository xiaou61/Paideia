# 12 · 集合选型：ArrayList、LinkedList、HashMap、TreeMap

## 这一课你要会

- 按"要不要顺序、要不要去重、要不要排序、要不要按 key 查"四问选对集合；
- 说清 `ArrayList` 与 `LinkedList` 各自慢在哪里；
- 知道 `HashMap` 的查询为什么是 O(1)、什么时候退化成 O(n)；
- 认出"在循环里 `list.contains(...)`"这种隐形 O(n²)。

## 为什么

Java 的集合有十几种，新手常见两种极端：**全用 `ArrayList`**（该去重不去重、该排序不排序），或者**记不住就随便挑**（在链表上做随机访问，慢几百倍还找不到原因）。

选型只有四个问题，问完就有答案。

## 讲解

### 四问选型法

| 问题 | 答"是" | 答"否" |
| --- | --- | --- |
| 1. 需要按 key 快速查值？ | `Map` 家族 | 往下问 |
| 2. 需要去重？ | `Set` 家族 | 往下问 |
| 3. 需要保持插入顺序？ | `ArrayList` / `LinkedHashSet` | 往下问 |
| 4. 需要自动排序？ | `TreeSet` / `TreeMap` | `ArrayList` / `HashMap` |

几张常用表：

**List（有序、可重复、按下标访问）**

| 类 | 底层 | 适合 |
| --- | --- | --- |
| `ArrayList` | 动态数组 | **默认选它**：随机访问快、尾部追加快 |
| `LinkedList` | 双向链表 | 频繁在头部/中间插入删除（实际很少见） |

**Set（不重复）**

| 类 | 底层 | 适合 |
| --- | --- | --- |
| `HashSet` | 哈希表 | **默认选它**：O(1) 查询，顺序不保证 |
| `LinkedHashSet` | 哈希表 + 链表 | 要保留插入顺序 |
| `TreeSet` | 红黑树 | 要自动排序、要范围查询 |

**Map（键值对）**

| 类 | 底层 | 适合 |
| --- | --- | --- |
| `HashMap` | 哈希表 | **默认选它**：O(1) 查询 |
| `LinkedHashMap` | 哈希表 + 链表 | 要保留插入顺序（或做 LRU 缓存） |
| `TreeMap` | 红黑树 | 要按 key 排序、要范围查询 |

### `ArrayList` vs `LinkedList`

```java
List<Integer> array = new ArrayList<>();
array.get(500000);         // O(1)：直接算下标

List<Integer> linked = new LinkedList<>();
linked.get(500000);        // O(n)：从头部一个一个走
```

**`LinkedList` 的随机访问是线性时间**。所以：

```java
// 反面：在 LinkedList 上用 for 循环按下标遍历
for (int i = 0; i < list.size(); i++) {
    System.out.println(list.get(i));    // 每次 O(n)，总共 O(n²)
}
```

**遍历一律用 for-each**（它走迭代器，链表上是 O(n) 总代价）：

```java
for (Integer value : list) {
    System.out.println(value);
}
```

**实践结论**：`LinkedList` 几乎总是被误用。它只在"频繁在中间插入/删除且已经握着那个位置的迭代器"时才有优势。**默认用 `ArrayList`**。

### `HashMap` 为什么是 O(1)

`HashMap` 内部是一个数组 + 链表（或红黑树）：

1. 用 `getKey()` 的 `hashCode()` 算出桶下标；
2. 到那个桶里用 `equals()` 找目标。

桶数够多时平均每个桶只有一两个元素，所以是 O(1)。

**什么时候退化成 O(n)**：

- **大量 key 的 `hashCode` 相同**（哈希碰撞）：全挤在一个桶里，退化成链表；
- **`equals` / `hashCode` 写错**：上一课讲过，直接导致找不到；
- **桶太少而元素太多**：`HashMap` 会自动扩容（默认装到 75% 时翻倍），所以正常使用不会遇到。

**容量预设**：如果能预估元素个数，构造时就给容量，避免反复扩容。

```java
// 预计放 1000 个，给 1000 / 0.75 ≈ 1334，向上取到 2 的幂
Map<String, Integer> map = new HashMap<>(2048);
```

### `HashMap` 允许 null，`TreeMap` 不允许

```java
Map<String, String> hash = new HashMap<>();
hash.put(null, "x");       // 可以（key 为 null 放第一个桶）

Map<String, String> tree = new TreeMap<>();
tree.put(null, "x");       // NullPointerException：排序时要比 null
```

`HashSet` 基于 `HashMap`，所以同样允许一个 `null` 元素；`TreeSet` 不允许。

### `List.of()` 是不可变的

```java
List<String> fixed = List.of("a", "b");
fixed.add("c");      // UnsupportedOperationException
```

`List.of(...)`、`Set.of(...)`、`Map.of(...)` 返回的集合**不可变**。要可变得用构造器包一层：

```java
List<String> mutable = new ArrayList<>(List.of("a", "b"));
```

`List.of` 还有个"优点"值得知道：它**不允许 null 元素**（`List.of(null)` 直接抛 NPE）。这让"集合里混进 null"这类问题提前暴露。

### 隐形 O(n²)：循环里的 `contains`

```java
// 反面：n 次 contains，每次 O(n)，总共 O(n²)
for (String name : names) {
    if (!allowedList.contains(name)) {
        System.out.println("不允许：" + name);
    }
}
```

`ArrayList.contains` 是线性扫描。数据量一万时，这就是一亿次比较。

**修法**：把查找集合换成 `HashSet`。

```java
Set<String> allowed = new HashSet<>(allowedList);   // 一次转换 O(n)
for (String name : names) {
    if (!allowed.contains(name)) {                  // 每次 O(1)
        System.out.println("不允许：" + name);
    }
}
```

**这是最常见的性能问题之一**，而且数据量小的时候完全看不出来。

### `Map` 的常用便利方法

```java
Map<String, Integer> counts = new HashMap<>();

// 没有就取默认值（不写进 map）
int value = counts.getOrDefault("a", 0);

// 有就加，没有就设为初始值（原子地一步完成）
counts.merge("a", 1, Integer::sum);

// 有值就计算新值
counts.computeIfPresent("a", (key, old) -> old + 1);

// 没有就创建
counts.computeIfAbsent("b", key -> 0);

// 遍历
counts.forEach((key, value2) -> System.out.println(key + "=" + value2));
```

`merge` 是**统计频次的标准写法**：`counts.merge(word, 1, Integer::sum)`。比 `if (containsKey) ... else ...` 短且不容易错。

### 三种集合的推荐默认值

| 需求 | 用它 |
| --- | --- |
| 要一个列表 | `new ArrayList<>()` |
| 要一个去重集合 | `new HashSet<>()` |
| 要一个键值表 | `new HashMap<>()` |
| 需要一个**常量**集合（不打算改） | `List.of(...)` / `Set.of(...)` / `Map.of(...)` |

这四条覆盖 95% 的日常场景。

## 动手

这段代码演示三种集合的行为差异：顺序、去重、排序，以及 `HashMap` 的便利方法。

<!-- run -->
```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        List<String> words = List.of("banana", "apple", "banana", "cherry", "apple");

        // 1) List：保留全部，含重复
        List<String> asList = new ArrayList<>(words);
        System.out.println("List     : " + asList + "（" + asList.size() + " 个）");

        // 2) HashSet：去重，顺序不保证
        Set<String> asSet = new HashSet<>(words);
        System.out.println("HashSet  : 共 " + asSet.size() + " 个不同元素");

        // 3) LinkedHashSet：去重 + 保留首次出现顺序
        Set<String> ordered = new LinkedHashSet<>(words);
        System.out.println("LinkedSet: " + ordered);

        // 4) TreeSet：去重 + 自动排序
        Set<String> sorted = new TreeSet<>(words);
        System.out.println("TreeSet  : " + sorted);

        // 5) HashMap 统计频次：merge 是标准写法
        Map<String, Integer> counts = new HashMap<>();
        for (String word : words) {
            counts.merge(word, 1, Integer::sum);
        }
        // HashMap 的迭代顺序不保证，要稳定输出用 TreeMap 排一下
        System.out.println("频次     : " + new java.util.TreeMap<>(counts));

        // 6) 容量预设：避免反复扩容
        Map<String, Integer> sized = new HashMap<>(16);
        sized.put("a", 1);
        System.out.println("预设容量 : " + sized);

        // 7) 不可变集合：写入会抛异常
        List<String> fixed = List.of("x", "y");
        try {
            fixed.add("z");
        } catch (UnsupportedOperationException failure) {
            System.out.println("List.of 不可变：写入被拒绝");
        }
    }
}
```

```text
List     : [banana, apple, banana, cherry, apple]（5 个）
HashSet  : 共 3 个不同元素
LinkedSet: [banana, apple, cherry]
TreeSet  : [apple, banana, cherry]
频次     : {apple=2, banana=2, cherry=1}
预设容量 : {a=1}
List.of 不可变：写入被拒绝
```

注意 `HashSet` 那行只打印个数不打印内容——**它的顺序不保证**，打印出来可能是任意顺序。这是刻意的：不要写出依赖 `HashSet` 顺序的代码。

## 常见误区

### 误区：`LinkedList` 插入删除比 `ArrayList` 快，所以更好

只在"已经在那个位置、握着迭代器"时才成立。按 `get(i)` 定位再插入，定位本身就是 O(n)。**默认用 `ArrayList`。**

### 误区：`HashSet` 保持顺序

不保证。要插入顺序用 `LinkedHashSet`，要排序用 `TreeSet`。写代码时不要依赖 `HashSet` 的迭代顺序。

### 误区：`Map.get` 返回 `null` 就是 key 不存在

`HashMap` 允许 value 为 `null`，所以 `get` 返回 `null` 有两种可能："没有这个 key" 或 "这个 key 的 value 就是 null"。要区分用 `containsKey`。

### 误区：`List.of()` 返回的列表操作和 `ArrayList` 一样

不可变。`add`、`remove`、`set` 都会抛 `UnsupportedOperationException`。要可变必须 `new ArrayList<>(List.of(...))`。

### 误区：`HashMap` 的遍历顺序稳定

不保证，而且扩容后顺序会变。要顺序用 `LinkedHashMap`（插入序）或 `TreeMap`（排序）。

## 小结

- 四问选型：按 key 查 → Map；去重 → Set；保留顺序 → ArrayList / LinkedHashSet；自动排序 → TreeSet / TreeMap。
- 默认值：`ArrayList`、`HashSet`、`HashMap`；常量用 `List.of` / `Set.of` / `Map.of`。
- `LinkedList` 的随机访问是 O(n)，**几乎总该用 `ArrayList`**。
- 循环里的 `contains` 是隐形 O(n²)，把参照集合换成 `HashSet`。
- `Map.merge(key, 1, Integer::sum)` 是统计频次的标准写法。
- 预估容量时给 `HashMap` 构造器传初始容量，避免反复扩容。
