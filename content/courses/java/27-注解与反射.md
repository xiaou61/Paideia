# 25 · 注解与反射

## 这一课你要会

- 说清注解和反射的分工：注解只是标签，读标签的代码才是逻辑；
- 用 `@Retention(RUNTIME)` 让注解活到运行时，并知道不加会怎样；
- 用反射读类/方法上的注解、按名字取方法并调用；
- 知道反射的代价，以及业务代码里为什么应该直接调用。

## 为什么

你会在 Spring 里看到 `@Service`、`@Transactional`，在 JUnit 里看到 `@Test`。它们看起来像"给方法加了魔法"：加了 `@Test`，这个方法就会被测试框架跑起来。

真实的机制只有两步：

1. **注解**是贴在代码上的标签，本身不执行任何逻辑；
2. **框架**在启动时用**反射**扫描这些标签，读到 `@Test` 就把对应方法找出来调用。

不理解这两步，就会把注解当咒语：不生效时不知道查哪里，也不知道什么时候该自己写一个。

## 讲解

### 注解就是一个特殊的接口

```text
@interface Label {
    String value();
}
```

`@interface` 是定义注解的语法。用的时候写 `@Label("demo")`，因为成员叫 `value`，可以省略名字。注解可以带默认值、可以标在类/方法/字段/参数上（`@Target` 决定）。

### 不加 `@Retention`，编译器会把它丢掉

注解的保留策略有三种：

| 策略 | 活到哪一步 | 常见用途 |
| --- | --- | --- |
| `SOURCE` | 只在源码里，编译后消失 | `@Override`、代码检查 |
| `CLASS` | 进了 `.class`，但运行时读不到（默认） | 某些编译期工具 |
| `RUNTIME` | 运行时还能通过反射读到 | 框架、测试、序列化 |

**默认是 `CLASS`**。很多人写了一个自定义注解，反射里却永远读到 `null`，原因就是漏了 `@Retention(RetentionPolicy.RUNTIME)`。

### 反射把类拆开看

反射允许你在运行时拿到 `Class` 对象，再问它：有哪些方法、哪些字段、带了什么注解、能不能调用。

<!-- run -->
```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.Method;

public class Main {

    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.TYPE)
    @interface Label {
        String value();
    }

    @Label("demo")
    static class Service {
    }

    static String greet(String name) {
        return "hello, " + name;
    }

    public static void main(String[] args) throws Exception {
        Label label = Service.class.getAnnotation(Label.class);
        System.out.println(label.value());

        Method method = Main.class.getDeclaredMethod("greet", String.class);
        System.out.println(method.getName() + "/" + method.getParameterCount());
        System.out.println(method.invoke(null, "小林"));
    }
}
```
```text
demo
greet/1
hello, 小林
```

三个细节：

- `getDeclaredMethod("greet", String.class)` 要同时给**方法名和参数类型**——Java 允许重载，只给名字不够；
- `invoke(null, ...)` 的第一个参数是"在哪个对象上调用"，静态方法是 `null`；
- 方法名和参数类型是**字符串**，写错时编译器不知道，只有运行时抛 `NoSuchMethodException`。

### 反射的代价

- **失去编译期检查**：方法改名后，字符串不会跟着改，测试跑起来才发现；
- **可读性下降**：IDE 的"查找引用"找不到通过反射发起的调用；
- **封装限制**：JDK 17 以后强封装，反射访问别的模块的私有成员可能被拒绝。

所以业务代码里优先直接调用。反射最适合三类地方：框架、通用工具（序列化、参数校验）、测试。

## 常见误区

### 误区：加了注解就自动生效

**你以为**：`@Label("demo")` 一写，程序就会按 `demo` 做点什么。
**其实**：注解只是标签，没有读取它的代码就什么都不会发生。注解不生效时，先确认"有没有人读它"，再确认"读的时候它还在不在"（保留策略）。

### 误区：反射一定很慢，所以完全不能用

**你以为**：反射是性能杀手，任何地方都不该出现。
**其实**：现代 JVM 会做调用点优化，普通业务量级下反射不是瓶颈。真正的问题是它绕过了编译期检查，改代码时容易漏。框架用反射是合理的；业务代码为了"灵活"用反射通常得不偿失。

### 误区：`getDeclaredMethods()` 会包含父类的方法

**你以为**：拿到的是"这个对象所有能调的方法"。
**其实**：`getDeclaredMethods()` 只给本类声明的；`getMethods()` 才包含继承来的 public 方法。两个名字很像，行为差很多。

## 小结

注解是标签，反射是读标签的手。默认保留策略是 `CLASS`，要运行时读到必须写 `@Retention(RUNTIME)`。反射靠字符串找方法，失去编译期检查，所以留给框架与工具，业务代码直接调用。
