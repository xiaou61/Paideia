# 27 · 注解与反射

我给练手项目的价格表写了个自查小工具：方法上贴 `@Check`，主程序扫一遍，把贴了标签的方法挨个跑。第一版只做了「读到标签里的名字」这一步：

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Target;
import java.lang.reflect.Method;

public class Main {
    @Target(ElementType.METHOD)
    @interface Check {
        String value() default "";
    }

    static class PriceBook {
        @Check("reject negative count")
        static void negativeCount() {
        }
    }

    public static void main(String[] args) throws Exception {
        Method m = PriceBook.class.getDeclaredMethods()[0];
        System.out.println(m.getAnnotation(Check.class).value());
    }
}
```

```text
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "Main$Check.value()" because the return value of "java.lang.reflect.Method.getAnnotation(java.lang.Class)" is null
	at Main.main(Main.java:19)
```

我第一反应是「反射被 JDK 25 挡了」——猜错了。`getAnnotation` 没拒绝我，它如实报告了它看到的东西：什么都看不到。这条 NPE 也把话说全了，返回 null 的是 `Method.getAnnotation(java.lang.Class)` 这个调用，不是 `value()` 写错了。

下面所有输出都出自本机 Temurin 25.0.4。正文里的完整程序和 `run` 块用 `javac --release 21` 编（沙箱基线是 21），一次性探针用默认 target；为了读英文报错我设了 `JAVA_TOOL_OPTIONS=-Duser.language=en -Duser.country=US`，报错原文照抄。栈里 `Method.java:565` 这类行号是本机 JDK 的，换个版本会变。

## 标签压根没进 class 文件

把同一段代码编两次，一次不写 `@Retention`，一次在 `@interface Check` 上加 `@Retention(RetentionPolicy.RUNTIME)`，再用 `javap -v -p 'Main$PriceBook'` 看 `negativeCount` 那一节。两次输出只差一个词：

```text
      RuntimeInvisibleAnnotations:
        0: #13(#14=s#15)
          Main$Check(
            value="reject negative count"
          )
```

```text
      RuntimeVisibleAnnotations:
        0: #13(#14=s#15)
          Main$Check(
            value="reject negative count"
          )
```

注解确实写进了 class 文件，只是第一次写进了 Invisible 那一栏。反射只在 Visible 那一栏里找，所以报「没有」。`@Retention` 的默认值决定的是「活到哪一步」，不是「写没写」：

| `@Retention` | javap 里在哪 | 运行时 `getAnnotation` |
| --- | --- | --- |
| `SOURCE` | 方法上什么都不剩 | 返回 `null` |
| `CLASS`（不写就是这个） | `RuntimeInvisibleAnnotations` | 返回 `null` |
| `RUNTIME` | `RuntimeVisibleAnnotations` | 返回注解实例 |

`SOURCE` 那一行我也验了：给注解加上 `@Retention(RetentionPolicy.SOURCE)` 再标到方法上，`javap -v` 里那个方法连 Annotations 段都没有，常量池里也搜不到注解名。

顺带把另一条容易混的判断摆清：`@Target` 管的是「能贴在哪儿」，贴错了是**编译期**报错，不会让你运行时读到 null。把 `@Target(ElementType.METHOD)` 的 `@Check` 贴到 `PriceBook` 的 `taxRatePercent` 字段上，javac 直接给（另写的 `Src.java` 探针）：

```text
Src.java:11: error: annotation interface not applicable to this kind of declaration
        @Check
        ^
1 error
```

### 更难受的不是 NPE，是「0 个用例全绿」

我第二版把读标签换成 `isAnnotationPresent` 过滤，漏 `@Retention` 也不抛异常：

```java
int found = 0;
for (Method m : PriceBook.class.getDeclaredMethods()) {
    if (!m.isAnnotationPresent(Check.class)) {
        continue;
    }
    found++;
}
System.out.println("found " + found + " checks, 0 failed");
```

```text
found 0 checks, 0 failed
```

方法体里明明贴了 `@Check`，抛异常的用例也在，工具却报告「0 个用例、0 个失败」。所以看到自查工具打出 0 个用例，先怀疑「找到没找到」，别当成「都通过」——这两件事在输出上长得一模一样。

## 找方法：declared 和继承来的不是一回事

注解能读到了，下一步是「把贴了标签的方法全找出来」。`Class` 上两个名字很像的调用，返回的东西差得很远。我写了个几行的探针，在一个什么都不写的子类上量了一遍（`Parent` 有一个 `public void shown()` 和一个 `private void hidden()`，`Child extends Parent`）：

```text
Child getMethods: 10
Child declared: 0
Object getMethods: 9
```

10 是继承来的 `shown` 加上 `Object` 的 9 个（`equals`、`hashCode`、`toString`、`getClass`、`notify`、`notifyAll`、三个 `wait`；`clone` 是 protected，不算）。父类那个 private `hidden` 两边都看不到：`getMethods()` 只给 public，`getDeclaredMethods()` 只给本类声明的。

| 调用 | 你拿到什么 |
| --- | --- |
| `getDeclaredMethods()` | 只有本类声明的，含 private；不含继承来的 |
| `getMethods()` | 本类 + 继承来的 public，`Object` 那 9 个也在里面 |
| `getDeclaredMethod("total", int.class)` | 名字和参数类型都得对上，只在本类找 |
| `getMethod("total", int.class)` | 同上，但只找 public，且包含继承 |

第三行那个「参数类型也得对上」很容易踩。`PriceBook` 里真实的方法是 `total(int cents, int count)`，我只给了 `int.class`（探针里这个类已经有 `total` 和两个标了 `@Check` 的方法）：

```text
Exception in thread "main" java.lang.NoSuchMethodException: Main$PriceBook.total(int)
	at java.base/java.lang.Class.getDeclaredMethod(Class.java:2422)
	at Main.main(Main.java:22)
```

这条消息容易看反：`total(int)` 是**我请求的**签名，不是类里真实存在的签名。它只告诉你「没有这个」，不告诉你「有哪些」——要么 `javap` 看一遍，要么自己遍历把名字打出来。

还有一条不写在报错里、只在 javadoc 里的：`getDeclaredMethods()` 返回的数组「不排序，也不保证任何顺序」。我这次跑出来恰好是声明顺序，于是「先跑谁」看起来稳定；但这个顺序不是契约，换台机器或换次编译都可能变。依赖它的自查工具会在某次重构后突然「只跑了一部分」，而且不报错。所以正文里的 runner 先按方法名排一遍再跑。

## invoke：静态传 null，异常还会被包一层

`Method.invoke` 的第一个参数是「在哪个对象上调用」。静态方法传 `null` 就行；实例方法传 `null`，抛的是：

```text
target=null -> java.lang.NullPointerException: Cannot invoke "Object.getClass()" because "obj" is null
```

注意消息里点的是 `obj`——`Method.invoke` 自己的参数名。这说明 NPE 出在反射调用内部，不是你方法体开头那行。

第二件事更坑：被调方法抛出的异常不会原样冒出来，先被装进 `InvocationTargetException`。我第一版 runner 只 `catch (RuntimeException)`，于是：

```text
Exception in thread "main" java.lang.reflect.InvocationTargetException
	at java.base/jdk.internal.reflect.DirectMethodHandleAccessor.invoke(DirectMethodHandleAccessor.java:119)
	at java.base/java.lang.reflect.Method.invoke(Method.java:565)
	at Main.main(Main.java:32)
Caused by: java.lang.IllegalStateException: tax table is empty
	at Main$PriceBook.taxTableLoaded(Main.java:16)
	at java.base/jdk.internal.reflect.DirectMethodHandleAccessor.invoke(DirectMethodHandleAccessor.java:104)
	... 2 more
```

这段里没有 `PASS shippingIsFree`，也没有末尾那行统计：第一个失败用例就把整个 runner 打断了，后面的用例再没跑。`InvocationTargetException` 不是 `RuntimeException` 的子类，那个 catch 一点用都没有。

正确写法是把 cause 取出来：

```java
} catch (InvocationTargetException e) {
    Throwable cause = e.getCause();
    System.out.println("FAIL " + name + " -> " + cause.getClass().getSimpleName());
}
```

这也是为什么测试框架的失败报告里总有一长串 `Caused by`——它们干的正是这件事。

## 强封装：别人的私有字段不一定给你读

最后一道墙在自己代码之外。想读 `String` 的私有字段：

```text
java.lang.reflect.InaccessibleObjectException: Unable to make field private final byte[] java.lang.String.value accessible: module java.base does not "opens java.lang" to unnamed module @8bcc55f
	at java.base/java.lang.reflect.AccessibleObject.throwInaccessibleObjectException(AccessibleObject.java:353)
	at java.base/java.lang.reflect.AccessibleObject.checkCanSetAccessible(AccessibleObject.java:329)
	at java.base/java.lang.reflect.Field.setAccessible(Field.java:173)
	at Open.main(Open.java:6)
```

（`@` 后面那串是模块对象的哈希，每次运行不同。）

三个具体判断：

- 这条限制的起点是 **JDK 16**（JEP 396 把强封装变成默认），不是 17 才有的。17 拆的是放开的口子：本机 25 上跑 `java --illegal-access=permit -version`，回的是 `Ignoring option --illegal-access=permit; support was removed in 17.0`。
- 它只拦**别的模块**的私有成员。你自己 class 文件里的私有成员，反射照读，不用加任何参数。
- 真要放开，是启动时加 `--add-opens java.base/java.lang=ALL-UNNAMED`；我加上之后同一个程序打印 `ok: byte[]`。但这是给框架和工具的最后手段。业务代码需要它的那天，说明你在依赖一个别人没打算给你看的字段。

## 跑一遍

把上面几处拼起来，是能跑的最小版本：注解带 RUNTIME、按方法名排序再跑、失败取 cause、最后一行给统计。

<!-- run -->
```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Method;
import java.util.Arrays;

public class Main {

    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.METHOD)
    @interface Check {
        String value() default "";
    }

    static class PriceBook {
        static int total(int cents, int count) {
            return cents * count;
        }

        @Check("reject negative count")
        static void negativeCount() {
            if (total(100, -1) >= 0) {
                throw new AssertionError("negative count accepted");
            }
        }

        @Check
        static void taxTableLoaded() {
            throw new IllegalStateException("tax table is empty");
        }
    }

    public static void main(String[] args) {
        Method[] methods = PriceBook.class.getDeclaredMethods();
        Arrays.sort(methods, (a, b) -> a.getName().compareTo(b.getName()));
        int pass = 0;
        int fail = 0;
        for (Method m : methods) {
            Check check = m.getAnnotation(Check.class);
            if (check == null) {
                continue;
            }
            String name = check.value().isEmpty() ? m.getName() : check.value();
            try {
                m.invoke(null);
                System.out.println("PASS " + name);
                pass++;
            } catch (InvocationTargetException e) {
                Throwable cause = e.getCause();
                System.out.println("FAIL " + name + " -> " + cause.getClass().getSimpleName());
                System.out.println("     " + cause.getMessage());
                fail++;
            } catch (ReflectiveOperationException e) {
                System.out.println("ERROR " + name + " -> " + e.getClass().getSimpleName());
                fail++;
            }
        }
        System.out.println(pass + " passed, " + fail + " failed");
    }
}
```
```text
PASS reject negative count
FAIL taxTableLoaded -> IllegalStateException
     tax table is empty
1 passed, 1 failed
```

`total` 那个方法没贴标签，被 `check == null` 跳过了；`negativeCount` 用注解里的名字当报告名，`taxTableLoaded` 没写名字就用方法名——这就是 `value()` 带默认值的用法。

## 还差的

- 反射的性能我一个字没写数字。手写循环测这个（预热、逃逸分析、调用点内联都得专门设计）我拿不出自己信的结果，就不编毫秒数。我不用反射的理由是编译期检查和重构，不是速度——`Method.invoke` 慢不慢，这篇没回答。
- 编译期那条链路（`@Retention(SOURCE)` + 注解处理器、`javac -processor`）完全没碰。本文只讲运行时读注解。
- `@Inherited`、`@Repeatable`、`@Target({ElementType.TYPE_USE})`、`getAnnotationsByType` 都没做实验，不替它们下结论。
- 强封装我只验了 unnamed module 读 `java.base` 私有字段这一种；`--add-opens` 我只试了「加上就能过」，没试它失效的边界（比如目标模块没 opens 包时会报什么）。
- 沙箱基线是 Java 21，我跑的是 25。`run` 块和正文开头那段完整程序都用 `javac --release 21` 编过，保证没用 21 之后的语法与 API；但 `java` 是 25 跑的，运行时行为仍然是 25 的。
