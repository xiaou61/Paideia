# 26 · 正则表达式

## 这一课你要会

- 分清"整串匹配"（`matches`）和"找一段"（`find`）；
- 用分组把日期拆成三段；
- 知道 `.`、反斜杠在 Java 字符串里要写两遍；
- 判断什么时候**不该**用正则。

## 为什么

校验手机号、从日志里抠出订单号、按分隔符拆一行配置——这些事用 `split` 和 `if` 写会越写越长，正则一行就够。

但正则也是出了名的"写完三天自己也看不懂"。这一课的目标不是背语法，而是掌握最常用的四件事：**字符类、数量词、分组、锚定**，然后知道边界在哪。

## 讲解

### 两个完全不同的方法

| 方法 | 含义 | 例子 |
| --- | --- | --- |
| `matches()` | **整串**必须完全匹配 | `"abc".matches("b")` → false |
| `find()` | 只要能找到**一段**就算 | `Matcher.find()` → true |
| `replaceAll()` | 把找到的每一段都换掉 | 手机号打码 |

这三个混用是新手最常见的 bug：想校验格式却用了 `find`，于是 `"x2026-10-26y"` 也能通过。

### 分组：把匹配到的内容拆开

括号 `(...)` 是分组，`group(1)`、`group(2)` 按左括号的位置取：

<!-- run -->
```java
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class Main {
    public static void main(String[] args) {
        Pattern date = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
        Matcher matcher = date.matcher("发布于 2026-10-26，更新于 2026-11-02");

        while (matcher.find()) {
            System.out.println(matcher.group(1) + "/" + matcher.group(2) + "/" + matcher.group(3));
        }

        System.out.println("2026-10-26".matches("\\d{4}-\\d{2}-\\d{2}"));
        System.out.println("订单 A-1024".matches("\\d{4}"));
        System.out.println("订单 A-1024".replaceAll("\\d+", "#"));
    }
}
```
```text
2026/10/26
2026/11/02
true
false
订单 A-#
```

### 转义要写两遍

正则本身用 `\d` 表示"一个数字"，但 Java 字符串里反斜杠也是转义字符，所以要写 `"\\d"`。这是第二个高频 bug：

```text
错误：Pattern.compile("\d+")     // 编译期就报 illegal escape character
正确：Pattern.compile("\\d+")
```

同理，想匹配一个**字面量点号**（比如版本号 `1.2.3`），正则是 `\.`，Java 字符串要写 `"\\."`。只写 `.` 表示"任意一个字符"，会把 `1x2y3` 也放过去。

### 常用语法速查

| 写法 | 含义 |
| --- | --- |
| `\d` / `\D` | 数字 / 非数字 |
| `\w` / `\W` | 字母数字下划线 / 非 |
| `\s` / `\S` | 空白 / 非空白 |
| `a*` / `a+` / `a?` | 0 次以上 / 1 次以上 / 0 或 1 次 |
| `a{2,4}` | 2 到 4 次 |
| `[abc]` / `[^abc]` | 其中任一 / 不在其中 |
| `^` / `$` | 开头 / 结尾 |
| `.*?` | 非贪婪（尽可能少） |

### 贪婪是最容易踩的坑

`<.*>` 匹配 `<a><b>` 时会一口气吃到最后一个 `>`，得到 `<a><b>`；`<.*?>` 才会分别得到 `<a>` 和 `<b>`。**默认是贪婪的**，加 `?` 才变成"尽快结束"。

### 什么时候别用正则

- 解析 HTML、JSON、SQL 这类**嵌套结构**：正则没有栈，处理不了任意深度；
- 业务规则复杂到需要注释：先拆成几个小判断，比一条 200 字符的正则可维护；
- 有现成解析器：日期用 `LocalDate.parse`，URL 用 `URI`，别自己写。

## 常见误区

### 误区：`matches` 和 `find` 差不多

**你以为**：都是"能不能匹配上"。
**其实**：`matches` 要求整串完全匹配，`find` 只要求存在一段。校验格式用 `matches`，提取内容用 `find`。

### 误区：`.` 就是点号

**你以为**：写 `1.2` 就是匹配 `1.2`。
**其实**：`.` 匹配任意字符，`1x2`、`1 2` 都算。要字面量点号必须转义成 `\.`，Java 字符串里写 `"\\."`。

### 误区：正则能解析 HTML

**你以为**：`<div>(.*?)</div>` 就能取内容。
**其实**：遇到嵌套的 `div`、属性里的 `>`、注释里的标签就会错。HTML/JSON 用专门的解析器，正则只适合结构简单、边界清楚的文本。

## 小结

校验用 `matches`（整串），提取用 `find`（找一段），替换用 `replaceAll`。括号是分组，`\d` 写进 Java 字符串要变 `"\\d"`，字面量点号是 `"\\."`。默认贪婪，`.*?` 才是非贪婪。嵌套结构不要用正则硬啃。
