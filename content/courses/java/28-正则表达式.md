# 28 · 正则表达式

## 它不是版本号，为什么通过了

线上校验版本号，我写的是这个：

```java
String pattern = "\\d+.\\d+.\\d+";
System.out.println("1x2y3".matches(pattern));
```

```text
true
```

`1x2y3` 不是版本号，`1.2.3` 才是，可它通过了。

原因只有一个字：正则里 `.` 是「任意一个字符」，不是「点号」。`1x2y3` 正好是「数字 + 任意字符 + 数字 + 任意字符 + 数字」，完全符合。

要匹配真正的点号，得先把它转义成 `\.`；而反斜杠在 Java 字符串里又有特殊含义，所以要写成 `"\\."`。**正则是 `\.`，Java 字符串是 `"\\."`——两层转义，这课一半的坑都在这里。**

```text
loose dot  : true      "1x2y3".matches("\\d+.\\d+.\\d+")
escaped dot: true      "1.2.3".matches("\\d+\\.\\d+\\.\\d+")
escaped dot: false     "1x2y3".matches("\\d+\\.\\d+\\.\\d+")
```

最后一行才是我们想要的。这类 bug 不报错、不抛异常，只是让脏数据静默进来。

## 转义写错，编译就过不去

把 `\d` 直接写进 Java 字符串，编译器当场拒绝：

```text
E.java:2: error: illegal escape character
Pattern.compile("\d");
                   ^
```

因为 `\d` 在 Java 字符串里不是合法转义序列。正确写 `"\\d"`。

所以有一张必须记住的对照：

| 你想匹配的 | 正则写法 | Java 字符串写法 |
| --- | --- | --- |
| 一个数字 | `\d` | `"\\d"` |
| 一个字面量点号 | `\.` | `"\\."` |
| 一个反斜杠 | `\\` | `"\\\\"` |
| 一个数字（字符类） | `[0-9]` | `"[0-9]"` |

右列才是你敲进代码的样子，左列只存在于正则的语法里。

## matches 与 find：两个完全不同的方法

| 方法 | 含义 | 说明 |
| --- | --- | --- |
| `String.matches(regex)` | **整串**完全匹配 | 等价于 `Pattern.matches`，每次重新编译正则 |
| `Matcher.find()` | 只要**存在一段**匹配就为真 | 可以循环调用，逐段前进 |
| `Matcher.matches()` | 整串匹配，但可复用已编译的 `Pattern` | 和 `String.matches` 语义相同 |
| `replaceAll(regex, repl)` | 把找到的每一段都替换 | 内部就是 `find` 循环 |

差别有多大，跑一遍最清楚：

```text
anchored find : false     Pattern("^\\d{4}-\\d{2}-\\d{2}$") 对 "x2026-10-26y"
loose find    : true      同上但去掉 ^ 和 $
loose matches : false     同一个 loose 模式用 matches
```

三条连起来看，能解释两个常见误解：

1. **find 并不会让 `^` `$` 失效。** 上面第一行写了锚定，`find` 依然返回 `false`。所以「用了 find 所以 `x2026-10-26y` 也能通过」这句话只在**模式没写锚定**时成立——真正的原因是没写 `^...$`。
2. **`matches` 对同样的模式返回 `false`**，因为它要求整串匹配，而 `x` 开头就不满足。

结论：校验格式用 `matches`（或带 `^...$` 的 `find`），提取内容用 `find`。

## 贪婪与非贪婪：必须用 find 循环才看得见

```text
greedy matches: true      "<a><b>".matches("<.*>")
lazy matches  : true      "<a><b>".matches("<.*?>")

lazy find loop: [<a>][<b>]
greedy loop   : [<a><b>]
```

注意前两行**都是 `true`**——`matches` 要求整串匹配，`<.*?>` 只是「尽快结束」，碰到整串匹配的要求它一样能把整串吃掉。

真正体现区别的是 `find` 循环：贪婪版一次吃掉整串，非贪婪版给你两段。这也说明一件事：**讨论「贪婪/非贪婪」时，必须说清用的是 `matches` 还是 `find` 循环**，否则结论是反的。

```java
Matcher m = Pattern.compile("<.*?>").matcher("<a><b>");
while (m.find()) {
    System.out.println(m.group());
}
```

## `\d` `\w` `\s` 默认只认 ASCII

这条对中文项目特别重要：

```text
中\w      : false     "中".matches("\\w")
中(?U)\w  : true      "中".matches("(?U)\\w")
中\p{L}   : true      "中".matches("\\p{L}")
٣\d      : false     "٣".matches("\\d")        （阿拉伯-印度数字）
٣(?U)\d  : true      "٣".matches("(?U)\\d")
```

`\w`、`\d`、`\s` 的**默认**语义是 ASCII 字符类，中文不算「字母数字下划线」，全角数字也不算数字。

三条出路：

- 在模式前加内联标志 `(?U)`——等价于 `Pattern.UNICODE_CHARACTER_CLASS`；
- 编译时传标志：`Pattern.compile("\\w+", Pattern.UNICODE_CHARACTER_CLASS)`；
- 显式写 Unicode 类别：`\p{L}`（字母）、`\p{Nd}`（十进制数字）。

需要按「中文也算字母」处理用户输入（比如姓名、地名校验）时，一定要选其中一条，否则用户名字里带中文就被判为非法。

## 常用语法速查

| 正则写法 | Java 字符串 | 含义 |
| --- | --- | --- |
| `\d` / `\D` | `"\\d"` / `"\\D"` | 数字 / 非数字（默认 ASCII） |
| `\w` / `\W` | `"\\w"` / `"\\W"` | 字母数字下划线 / 非（默认 ASCII） |
| `\s` / `\S` | `"\\s"` / `"\\S"` | 空白 / 非空白 |
| `a*` / `a+` / `a?` | 同左 | 0 次以上 / 1 次以上 / 0 或 1 次 |
| `a{2,4}` | 同左 | 2 到 4 次 |
| `[abc]` / `[^abc]` | 同左 | 其中任一 / 不在其中 |
| `^` / `$` | 同左 | 开头 / 结尾 |
| `.*?` | 同左 | 非贪婪（尽可能少） |
| `(...)` | 同左 | 捕获分组 |

## 分组：把匹配到的内容拆开

括号是分组，`group(1)`、`group(2)` 按左括号出现的顺序取。

<!-- run -->
```java
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class Main {
    public static void main(String[] args) {
        Pattern date = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
        Matcher matcher = date.matcher("发布于 2026-10-26，更新于 2026-11-02");

        while (matcher.find()) {
            System.out.println(matcher.group(1) + "/" + matcher.group(2) + "/" + matcher.group(3));
        }

        System.out.println("2026-10-26".matches("\\d{4}-\\d{2}-\\d{2}"));
        System.out.println("订单 A-1024".matches("\\d{4}"));
        System.out.println("订单 A-1024".replaceAll("\\d+", "#"));
    }
}
```
```text
2026/10/26
2026/11/02
true
false
订单 A-#
```

三行输出分别对应：`find` 循环拿到两段日期；`matches` 对整串成立；`matches` 对「一串里含四位数字」不成立（因为不是整串）；`replaceAll` 把 `1024` 换成一个 `#`。

## 什么时候别用正则

- **嵌套结构**：HTML、JSON、SQL 这些有任意深度的结构，正则没有栈，处理不了。`<div>(.*?)</div>` 遇到嵌套 `<div>`、属性里的 `>`、注释里的标签就会错。
- **有现成解析器**：日期用 `LocalDate.parse`，URL 用 `URI`，别自己写。
- **业务规则复杂到需要注释**：拆成几个小判断，比一条 200 字符的正则可维护。
- **按分隔符拆字符串**：`String.split` 本身就吃正则，不必先 `Pattern.compile`。

## 还差的

- **只验了 JDK 25 上的行为（`javac --release 21` 编译）**。更老的 JDK 在 `\p{...}` 支持范围、Unicode 版本上有差异，我没逐条对照。
- **`(?U)` 与 `Pattern.UNICODE_CASE` 的交互没测**。大小写不敏感匹配中文、土耳其语 `i` 这类边界我没碰。
- **回溯造成的性能问题没量化**。只知道「嵌套量词容易灾难性回溯」，说不出具体在什么输入规模上会炸。
