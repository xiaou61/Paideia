# 25 · 常见编译与运行错误速查

## 这一课你要会

- 分清编译期错误与运行时异常，知道该在哪一步找；
- 认出最常见的几类报错，从原文说出原因和修法；
- 读堆栈时先找到**自己代码**的那一帧，而不是从头逐行看；
- 说清 `==`/`equals`、整数除法、文件编码、classpath 这四个"不报错但结果不对"的坑。

## 为什么

报错不是敌人。编译器把文件名、行号、甚至出错的那个字符都用 `^` 标出来了；JVM 的堆栈也标出了调用链。新手常见的两种反应——把整段报错贴进搜索框，或者先怀疑 JDK 装坏了——都会浪费最多的时间。

这一课是一张**速查表**：看到哪行字，就知道往哪查。不需要背，遇到时回来对照。

## 讲解

### 先分清两种错误

| | 编译期错误 | 运行时异常 |
| --- | --- | --- |
| 谁报的 | `javac` | `java`（JVM） |
| 典型 | `cannot find symbol`、`incompatible types`、`missing return` | `NullPointerException`、越界、类型转换、并发修改 |
| 长什么样 | `Main.java:5: error: ...` + 插入符 `^` | `Exception in thread "main" ...` + `at` 栈帧 |
| 说明什么 | 名字、类型或语法不对，`.class` 根本没生成 | 程序跑起来了，某个值或状态不对 |

**编译不过就先修编译错误**，不要试图运行。编译器的报错通常比运行时的更精确，因为它看到的是完整的类型信息。

### cannot find symbol

```text
Main.java:5: error: cannot find symbol
        System.out.println(total);
                           ^
  symbol:   variable total
  location: class Main
```

**原因**：编译器从没见过这个名字。常见四种：

- 拼错（`total` 写成 `totol`）；
- 声明在别的方法或代码块里，出了作用域就不可见；
- 用了别的包的类却忘了 `import`；
- 类在另一个模块/目录，classpath 没带上。

**修法**：把报错里的 `symbol` 和你的声明逐字对一遍；检查声明是否在同一个方法/块内；补 `import`；跨模块的类检查构建配置。

```java
int sum = 0;
System.out.println(total);   // total 从未声明，或拼错了 sum
```

### incompatible types

```text
Main.java:4: error: incompatible types: possible lossy conversion from double to int
    int price = 9.9;
                ^
```

```text
Main.java:4: error: incompatible types: String cannot be converted to int
    int age = "18";
```

**原因**：Java 是静态类型语言，赋值两边的类型必须兼容。`double` 转 `int` 会丢小数，编译器不让你**隐式**做；`String` 和 `int` 是两种完全不同的类型，更不会自动转换。

**修法**：

- 想清楚这个变量到底该是什么类型，改声明；
- 确实要截断小数：显式 `(int) 9.9`，它**截断**而不是四舍五入；
- 把字符串转数字：`Integer.parseInt("18")`，并用 `try/catch` 处理格式错误；
- 金额别用 `double`，用 `BigDecimal`（第 24 课）。

### missing return

```text
Main.java:7: error: missing return statement
    }
    ^
```

**原因**：方法声明了返回类型，但存在一条走到方法末尾还没 `return` 的路径。典型是 `if` 没有 `else`、`switch` 没有覆盖所有分支、循环可能一次都不执行。

**修法**：保证所有路径都有返回值，或者在走不到的分支抛异常。

```java
static int sign(int value) {
    if (value > 0) {
        return 1;
    } else if (value < 0) {
        return -1;
    }
    return 0;      // 别漏掉 0 这一支
}
```

### NullPointerException

```text
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "name" is null
	at Main.main(Main.java:6)
```

**原因**：变量里是 `null`，却当成对象用了。`null` 不是空字符串，也不是 0。常见来源：

- 对象字段没初始化（字段默认值是 `null`）；
- `map.get(key)` 的 key 不存在，返回 `null`；
- 方法在某个分支返回了 `null`；
- 对象数组 `new String[3]` 里每个元素初始都是 `null`。

**修法**：先找"这个 null 从哪来"，而不是在出错行随手加个判断。确定允许缺失时：

```java
if (name != null) {
    System.out.println(name.length());
}
// 或者
Objects.requireNonNull(name, "name 不能为空");
```

JDK 14 之后 NPE 消息会指出具体是哪个变量为 null，先读它。

### ArrayIndexOutOfBoundsException

```text
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at Main.main(Main.java:4)
```

**原因**：长度为 3 的数组，合法下标是 `0、1、2`。写成 `<=`、硬编码了一个过大的下标、或者集合在中途被删短了，都会越界。`List` 的对应异常叫 `IndexOutOfBoundsException`，消息类似。

**修法**：

```java
for (int i = 0; i < values.length; i++) {   // 不是 <=
    ...
}
```

不需要下标时用增强 `for`；需要按位置访问时，先确认 `0 <= index && index < length`。调试时先把 `length` 打出来，比盯着循环猜快。

### ClassCastException

```text
Exception in thread "main" java.lang.ClassCastException: class java.lang.String cannot be cast to class java.lang.Integer
	at Main.main(Main.java:5)
```

**原因**：对象实际是 `String`，却强行当成 `Integer`。泛型擦除后，`List` 在运行时并不检查元素类型，类型转换发生在取值的地方，所以错误可能离"放进集合"很远。

**修法**：不要用原始类型（`List` 而不是 `List<String>`）；转换前用 `instanceof` 判断：

```java
if (value instanceof Integer number) {
    System.out.println(number + 1);
}
```

更好的修法是让数据模型从一开始就说清类型，而不是靠运行时强转。

### ConcurrentModificationException

```text
Exception in thread "main" java.util.ConcurrentModificationException
	at java.base/java.util.ArrayList$Itr.checkForComodification(ArrayList.java:1013)
	at java.base/java.util.ArrayList$Itr.next(ArrayList.java:967)
	at Main.main(Main.java:8)
```

**原因**：用 `for-each`（内部是迭代器）遍历集合时，直接对集合做了结构性修改（`add`/`remove`）。**单线程也会抛**，名字里的 "concurrent" 容易误导。

**修法**：

```java
Iterator<String> iterator = names.iterator();
while (iterator.hasNext()) {
    if (iterator.next().equals("b")) {
        iterator.remove();          // 通过迭代器删
    }
}

names.removeIf(name -> name.equals("b"));   // 更短
```

或者先收集要删的元素，遍历结束后再统一删。

### == 与 equals

这一类不抛异常，只是结果"看起来不对"。

```java
String a = new String("hi");
String b = new String("hi");
System.out.println(a == b);        // false：两个不同对象
System.out.println(a.equals(b));   // true：内容相同

Integer x = 128;
Integer y = 128;
System.out.println(x == y);        // false：缓存只覆盖 -128..127
```

**原因**：`==` 比较的是**引用**（是不是同一个对象）或基本类型的值；`equals` 默认也是引用比较，但 `String`、`Integer` 等类重写了它，比较内容。字符串字面量会被常量池复用，所以有时 `==` 又碰巧是 `true`——规律不统一，不能依赖。

**修法**：对象内容比较一律 `.equals`；可能为 null 时用 `Objects.equals(a, b)`；枚举用 `==`（身份就是语义）。`Integer` 只在缓存区间内 `==` 为 true，别拿它当数值比较。

### 整数除法

```java
System.out.println(7 / 2);      // 3
System.out.println(7 / 2.0);    // 3.5
System.out.println(7 % 2);      // 1
```

**原因**：两个 `int` 相除，先做整数除法、直接截断，再赋值。`double b = 7 / 2;` 仍然是 `3.0`，因为除法在赋值之前就完成了。负数向零截断：`-7 / 2` 是 `-3`。

**修法**：至少让一个操作数是 `double`，或者用 `BigDecimal` 并指定精度与舍入：

```java
double average = sum / 2.0;
BigDecimal average = total.divide(BigDecimal.valueOf(count), 2, RoundingMode.HALF_UP);
```

顺带一个相关的坑：`int millis = 30 * 24 * 3600 * 1000;` 会溢出，因为右边全是 `int`。写成 `30L * 24 * 3600 * 1000`。

### 文件编码

```text
Exception in thread "main" java.nio.charset.MalformedInputException: Input length = 1
	at java.base/java.nio.charset.CharsetDecoder.decode(...)
```

或者没有异常，只是中文变成 `æ˜¯` 这样的乱码。

**原因**：写入时用一种编码，读取时用另一种。JDK 18 起默认字符集是 UTF-8，但老项目、容器参数或其他工具仍可能用 GBK/ANSI；只要两边不一致，就会乱码或抛 `MalformedInputException`。

**修法**：读写两端都显式指定 `StandardCharsets.UTF_8`：

```java
Files.writeString(path, text, StandardCharsets.UTF_8);
String text = Files.readString(path, StandardCharsets.UTF_8);
```

不要靠 `-Dfile.encoding=UTF-8` 兜底——它只改默认值，改不了别人写文件时用的编码。Excel 导出的 UTF-8 CSV 还常带 BOM，第一行会多一个不可见字符，读取时要单独处理。

### javac 与 java 的 classpath

```text
Error: Could not find or load main class Main
Caused by: java.lang.ClassNotFoundException: Main
```

**原因**：`java` 找不到 `Main.class`。常见情况：

- 编译时用了 `-d out`，运行时却没加 `-cp out`；
- 类名大小写写错（Java 区分大小写）；
- 类在包里，比如 `com.example.Main`，运行时必须用全名 `com.example.Main`；
- 运行时少了依赖 jar，报 `NoClassDefFoundError`（注意：是**运行期**找不到类，和编译期的 `cannot find symbol` 不同）。

**修法**：

```bash
javac -d out src/Main.java
java -cp out Main

# 有包名时
java -cp out com.example.Main

# 同时带依赖目录（Windows 用分号分隔）
java -cp "out;libs/*" com.example.Main
```

`javac` 的 `-d` 决定 `.class` 放到哪里，`java` 的 `-cp` 决定去哪里找。这两个目录要对上。`java Main.java` 是 JDK 11+ 的单文件源码启动方式，只适合单文件小程序，不要和 `java Main` 混用。

### 如何从堆栈第一行定位

```text
Exception in thread "main" java.lang.NumberFormatException: For input string: "12a"
	at java.base/java.lang.Integer.parseInt(Integer.java:652)
	at java.base/java.lang.Integer.parseInt(Integer.java:770)
	at Main.main(Main.java:7)
```

按这个顺序读：

1. **第一行**：异常类型 + 消息。`NumberFormatException: For input string: "12a"` 已经告诉你"`12a` 不是数字"。
2. **找第一条属于自己代码的 `at`**：这里是 `Main.main(Main.java:7)`。JDK 的 `Integer.parseInt` 帧只说明异常在哪抛出，不是你的 bug 所在。
3. **有多个 `Caused by` 时，先从最后一个读起**：它是最底层的原因，再往上找是谁触发的。
4. **`... 23 more`** 只是省略了重复的公共栈帧，不影响定位。

```sketch

```

编译错误的格式不同：`Main.java:7: error: ...`，行号已经在第一行，下面的 `^` 指向具体字符。

### 一张速查表

| 看到 | 先查 |
| --- | --- |
| `cannot find symbol` | 拼写、作用域、`import`、classpath |
| `incompatible types` | 两边类型是否一致，是否需要 `parse` 或显式转换 |
| `missing return` | 是否所有分支都返回 |
| `NullPointerException` | 这个变量为什么是 null |
| `Index ... out of bounds` | 下标边界，`<` 还是 `<=` |
| `ClassCastException` | 对象的真实类型，是否有原始类型 |
| `ConcurrentModificationException` | 遍历时是否直接增删 |
| 结果差一点 / 比较为 false | `==`、整数除法、`BigDecimal` 精度 |
| 中文乱码 / `MalformedInputException` | 读写两端编码是否一致 |
| `Could not find or load main class` | `-cp` 与包名 |

### 跑一遍：捕获异常，而不是让它终止程序

下面故意制造两个常见异常，并在原地捕获、打印类型。输出是固定的。

<!-- run -->
```java
import java.util.ArrayList;
import java.util.ConcurrentModificationException;
import java.util.List;

public class Main {

    public static void main(String[] args) {
        List<String> names = new ArrayList<>(List.of("a", "b", "c", "d"));

        try {
            for (String name : names) {
                if (name.equals("b")) {
                    names.remove(name);       // 遍历时直接删
                }
            }
        } catch (ConcurrentModificationException error) {
            System.out.println("捕获：" + error.getClass().getSimpleName());
        }

        try {
            String text = null;
            System.out.println(text.length());
        } catch (NullPointerException error) {
            System.out.println("捕获：" + error.getClass().getSimpleName());
        }

        System.out.println("程序继续运行");
    }
}
```

```text
捕获：ConcurrentModificationException
捕获：NullPointerException
程序继续运行
```

两点说明：

- 删 `"b"` 之后集合里还有元素，迭代器的下一次 `next()` 会发现 `modCount` 变了，于是抛 `ConcurrentModificationException`。这是**必然复现**的，不是偶发。
- 捕获只适合"这个错误可以就地恢复"的场景。真实程序里，输入格式错误可以恢复；数组越界通常说明逻辑写错了，应该修代码，而不是 catch 掉继续跑。

## 常见误区

### 误区：报错先怪环境

**你以为**：编译不过或运行报错，是 JDK 装坏了、IDE 有 bug。
**其实**：绝大多数错误第一行就写明了类型和位置。`cannot find symbol` 是名字问题，`NullPointerException` 是值问题，都能直接对应到代码。环境问题通常表现为"同一个命令，所有程序都失败"。
**怎么验证**：把第一行和第一条自己的 `at` 帧抄出来，对照本课速查表；再编译一个五行的 `Hello.java`，如果它也失败，才去查环境。

### 误区：`==` 和 `equals` 可以混用

**你以为**：两个字符串内容一样，`==` 就是 `true`。
**其实**：`==` 比的是引用。`new String` 一定为 `false`；字面量因为常量池可能为 `true`；`Integer` 在 -128..127 的缓存区间内也可能为 `true`。规律不统一，所以对象内容比较一律用 `equals`。
**怎么验证**：打印 `new String("hi") == new String("hi")`，以及 `Integer a = 128, b = 128;` 后的 `a == b`。

### 误区：编译通过就没问题

**你以为**：`javac` 不报错，程序就是对的。
**其实**：编译只检查语法和类型。空指针、数组越界、并发修改、整数截断、编码错误都在运行时才出现，有的甚至不报错、只是结果不对。
**怎么验证**：`String s = null; s.length();` 编译完全通过，运行抛 `NullPointerException`。

### 误区：整数除法会自动四舍五入

**你以为**：`7 / 2` 得 3.5，或者至少得 4。
**其实**：两个 `int` 相除直接截断小数，得 3；`7 / 2.0` 才是 3.5。要四舍五入得显式用 `Math.round` 或 `BigDecimal` 的舍入模式。
**怎么验证**：分别打印 `7 / 2`、`7 / 2.0`、`7 % 2`，再看 `-7 / 2` 的结果。

## 小结

- 先分编译期还是运行期：`javac` 的错看 `文件:行号`，JVM 的错看第一行 + 第一条自己的 `at` 帧。
- `cannot find symbol` 查名字与作用域，`incompatible types` 查类型，`missing return` 查分支。
- NPE 查 null 的来源，越界查 `<` 与 `<=`，`ClassCastException` 查真实类型，CME 查遍历时的增删。
- `==` 比引用，`equals` 比内容；整数除法会截断；金额用 `BigDecimal`。
- 读写文件显式用 UTF-8；`-d` 与 `-cp` 的目录要对上，包名要写全。
- 读堆栈的顺序：异常类型和消息 → 自己代码的第一帧 → 最后一个 `Caused by`。

报错读得多了，你会发现它其实是在替你指出下一行该看哪里。**先读第一行，再读自己的那一帧**，绝大多数问题在三十秒内就能定位。
