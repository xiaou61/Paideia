# 03 · 循环与方法

## 从 3 开始倒数，它停不下来

我想打印 3、2、1，写了这个：

```java
public class Main {
    public static void main(String[] args) {
        int countdown = 3;
        while (countdown > 0) {
            System.out.println(countdown);
        }
    }
}
```

存成 `Main.java`，`javac --release 21 Main.java`，再 `java Main`。它不会停：

```text
3
3
3
3
3
3
3
3
```

上面只截了前 8 行。在我这台 Temurin 25 上，我把进程跑了 1.2 秒后杀掉，一共 9214 行，全是 `3`。条件 `countdown > 0` 没错，错的是循环体里没人改 `countdown`——它永远是 3，条件永远成立。

补上 `countdown--` 就正常了：

```java
while (countdown > 0) {
    System.out.println(countdown);
    countdown--;
}
```

```text
3
2
1
```

现在它能停下来，是因为每一轮都把 `countdown` 改小了。可如果我不想等它自然结束，而是想在某个条件满足时立刻走人呢？`countdown--` 解决不了这个。

## 提前退出：break、continue 和标签

`break` 结束当前这一层循环；`continue` 跳过本轮剩下的语句，直接进入下一轮。只有一层循环时，这两个词就够。两层嵌套时，它们默认只作用于最近的那一层。

下面的程序有两段。第一段想在外层 `i` 的每一轮里只打印 `j <= i` 的组合，`j > i` 时用 `continue outer` 直接跳到外层下一轮。第二段从 `1-1` 开始找 `i * j == 4`，找到就用 `break search` 一次跳出两层：

<!-- run -->
```java
public class Main {
    public static void main(String[] args) {
        outer:
        for (int i = 1; i <= 3; i++) {
            for (int j = 1; j <= 3; j++) {
                if (j > i) {
                    continue outer;
                }
                System.out.println(i + "-" + j);
            }
        }

        System.out.println("---");

        search:
        for (int i = 1; i <= 3; i++) {
            for (int j = 1; j <= 3; j++) {
                if (i * j == 4) {
                    break search;
                }
                System.out.println(i + "-" + j);
            }
        }
        System.out.println("已跳出");
    }
}
```
```text
1-1
2-1
2-2
3-1
3-2
3-3
---
1-1
1-2
1-3
2-1
已跳出
```

标签就是循环前面的一行 `名字:`，冒号不能省。`continue outer` 不是「跳到 `outer` 那一行重新开始」，而是结束外层这一轮，接着执行外层的 `i++` 和条件判断；`break search` 则直接到 `search` 标记的整个循环之后，也就是打印 `已跳出` 的那一行。

没有标签时，`break` 在两层循环里只跳出内层。想跳出外层，要么加标签，要么在外层维护一个布尔标志。标签只能标在语句前面；这一课示范的是标在 `for` 上，`while` 同样可以标。

## 数组最小预览（先照抄，第 04 课再讲）

后面要讲的 `for-each` 需要遍历数组；最后的 `join` 也收 `String[]`。这一课只需要看懂这 5 行：

```java
String[] names = {"小林", "小周", "小陈"};  // 类型[] 变量 = {元素...}
int n = names.length;                      // 3；length 是字段，没有括号
String first = names[0];                   // 下标 0 是第一个
for (String name : names) System.out.println(name);  // for-each：依次取出
String[] empty = new String[3];            // 先开长度 3 的数组，元素是 null
```

`String[]` 读作「String 数组」，是一串长度固定的 String。`parts.length` 是元素个数，`parts[i]` 是第 i 个（从 0 数）。数组怎么创建、越界会抛什么、为什么 `Object[]` 能接 `String[]` 却在运行时炸，都是第 04 课的内容。这里先照抄，不要停下来研究。

## 四种循环：for、for-each、while、do-while

```text
for (int i = 0; i < 3; i++) { ... }   // 三段式：初始化; 条件; 每轮之后
for (String name : names) { ... }      // for-each：遍历数组/集合
while (condition) { ... }              // 先判断，再执行
do { ... } while (condition);          // 先执行一次，再判断
```

`for` 的三段分别是「初始化; 条件; 每轮之后做什么」。`for (int i = 0; i < 3; i++)` 里 `i` 取 0、1、2，共 3 次；这里没有数组，`< 3` 只是让 `i` 从 0 数到 2，不是「下标从 0 开始的通行写法」——下标是下一课的事。

`i` 声明在 `for` 的括号里，作用域就到循环结束为止。出了循环再写 `System.out.println(i);`，编译不过：

```text
Main.java:6: error: cannot find symbol
        System.out.println(i);
                           ^
  symbol:   variable i
  location: class Main
1 error
```

这不是坏事：一个已经过期的计数不该在循环外还能用。

`while` 先判断后执行，可能一次都不执行。`do-while` 先执行一次再判断，所以循环体至少跑一次：

```java
int attempts = 0;
do {
    attempts++;
} while (attempts < 2);
```

`attempts` 从 0 开始，第一轮先加到 1，判断 `1 < 2` 成立；第二轮加到 2，判断 `2 < 2` 不成立，退出，最后是 2。

`for-each` 不给你下标，适合「每个元素都做一遍」；需要索引时还是用三段式 `for`。

`while (true)` 和 `for (;;)` 是同一个意思：条件恒真。两者没有语言层面的性能差异，别为了「快一点」写 `for (;;)`。这种循环只能靠 `break`、`return` 或 `throw` 结束——下一节讲方法时会用到这一点。

## 方法写在类里，调用顺序不重要

Java 没有 Python 那种顶层函数。方法必须写在类里；这里都写成 `static`，意思是「不用先 new 一个对象就能调用」，`static` 本身第 06 课再展开。

我原来记的是「方法必须先声明再使用」。同一类里并不是这样：下面的 `a()` 调用了后面才声明的 `b()`，照样编译、照样打印 2（输出和后面的返回规则示例在一起）。编译器先收集类里所有方法签名，再按名字和参数类型解析调用，跟它们在文件里的先后顺序无关。

声明方法时，参数类型和返回类型都要写。没有返回值写 `void`。参数传进方法之后到底发生了什么（值传递）第 06 课讲，这里先会用。

方法还能自己调自己，叫递归。这一课只讲调用别人；递归后面再讲，别以为方法只有重载这一种花样。

### 非 void 方法不能正常走完

「所有路径都要 return」不准确。准确的规则是：非 void 方法不能正常执行到方法末尾。满足它的方式不止 `return`：

- `return 值;` 直接返回；
- `throw ...;` 抛出异常，也不会正常走完；
- 条件恒真的无限循环，比如 `while (true) {}` 或 `for (;;) {}`，永远到不了末尾。

下面这些方法都能编译。`checked` 在 `ok` 为 false 时抛异常；两个无限循环方法压根不会返回，所以不用写 `return`（但也不能调用，调了就卡住）：

<!-- run -->
```java
public class Main {
    static int a() {
        return b() + 1;
    }

    static int b() {
        return 1;
    }

    static int checked(boolean ok) {
        if (ok) {
            return 1;
        }
        throw new IllegalStateException("not ok");
    }

    static int loopWithReturn() {
        while (true) {
            return 1;
        }
    }

    static int neverEndsWhile() {
        while (true) {
        }
    }

    static int neverEndsFor() {
        for (;;) {
        }
    }

    public static void main(String[] args) {
        System.out.println(a());
        System.out.println(checked(true));
        System.out.println(loopWithReturn());
        System.out.println("两个无限循环方法编译通过，但不调用");
    }
}
```
```text
2
1
1
两个无限循环方法编译通过，但不调用
```

但无限循环里有 `break` 就不行了——循环可能退出，方法就可能走到末尾：

```java
public class Main {
    static int f(int x) {
        while (true) {
            if (x > 0) {
                break;
            }
            return 1;
        }
    }
}
```

```text
Main.java:9: error: missing return statement
    }
    ^
1 error
```

`break` 让 `while (true)` 不再「恒真地走不完」：`x > 0` 时会跳出循环，直接落到方法结尾。补一个 `return`（或 `throw`）才行。`if (x > 0) return 1;` 单独一个 `if` 也不够：`x <= 0` 时没有分支可走，仍然会到末尾。

（报错是在英文 locale 下截的；你本机若是中文，`error:` 会变成「错误:」，行号一样。）

## 重载：同名方法，编译器按参数挑

同名、参数列表不同，就是重载。参数个数或类型必须不同；只改返回类型不算。下面两个 `f()` 只差返回类型，编译直接报「已经定义过」：

```java
public class Main {
    static int f() {
        return 1;
    }

    static double f() {
        return 1.0;
    }
}
```

```text
Main.java:6: error: method f() is already defined in class Main
    static double f() {
                  ^
1 error
```

参数列表不同就能共存。`add(1, 2)` 两个都是 `int`，选 `add(int, int)`；`add(1, 2.0)` 第二个是 `double`，选 `add(double, double)`，结果也从 `3` 变成 `3.0`：

<!-- run -->
```java
public class Main {
    static int add(int a, int b) {
        return a + b;
    }

    static double add(double a, double b) {
        return a + b;
    }

    static String pick(String value) {
        return "String";
    }

    static String pick(Integer value) {
        return "Integer";
    }

    public static void main(String[] args) {
        System.out.println(add(1, 2));
        System.out.println(add(1, 2.0));
        System.out.println(pick("x"));
    }
}
```
```text
3
3.0
String
```

`pick("x")` 选 `pick(String)`。但 `pick(null)` 编译不过：`null` 既能当 `String`，也能当 `Integer`，编译器没有理由偏向任何一个。

```java
public class Main {
    static String pick(String value) {
        return "String";
    }

    static String pick(Integer value) {
        return "Integer";
    }

    public static void main(String[] args) {
        pick(null);
    }
}
```

```text
Main.java:11: error: reference to pick is ambiguous
        pick(null);
        ^
  both method pick(String) in Main and method pick(Integer) in Main match
1 error
```

`Integer` 是包装类，第 10 课讲；这里只要知道它是另一种引用类型，和 `String` 平级。`null` 没有类型，两个重载都能接，所以编译期选不出来。真要传 `null`，就写 `pick((String) null)` 把类型说死；能避免就避免这种两个重载都能接 `null` 的写法。

## 循环里拼字符串，javac 生成了什么

`String` 不可变。`s = s + i` 不是改原来的串，而是造一个新的 String 再让 `s` 指过去；循环 N 次就有 N 个中间串，前面的都没人引用，等 GC 收。

我原来以为 `javac` 会把 `+` 编译成 `StringBuilder`。实际用 `javac --release 21` 编译后，`javap -c` 看到的是 `invokedynamic` + `makeConcatWithConstants`：

```java
public class Main {
    static String concat(String s, int i) {
        return s + i;
    }

    public static void main(String[] args) {
        String s = "";
        for (int i = 0; i < 3; i++) {
            s = s + i;
        }
        System.out.println(s);
    }
}
```

`javac --release 21 Main.java` 之后 `javap -c Main` 的相关输出（省略了构造器和常量池）：

```text
  static java.lang.String concat(java.lang.String, int);
    Code:
         0: aload_0
         1: iload_1
         2: invokedynamic #7,  0              // InvokeDynamic #0:makeConcatWithConstants:(Ljava/lang/String;I)Ljava/lang/String;
         7: areturn

  public static void main(java.lang.String[]);
    Code:
...
        10: aload_1
        11: iload_2
        12: invokedynamic #7,  0              // InvokeDynamic #0:makeConcatWithConstants:(Ljava/lang/String;I)Ljava/lang/String;
        17: astore_1
        18: iinc          2, 1
        21: goto          5
...
```

这是我这台机器上 Temurin 25.0.4 的输出；你机器上的常量池编号可能不是 `#7`，`invokedynamic` 和 `makeConcatWithConstants` 不会变。

`main` 里 `12: invokedynamic` 在循环体内部（`21: goto 5` 跳回条件判断），每转一圈就调一次拼接方法，生成一个新 String。`javac` 没有在循环外建一个 `StringBuilder` 反复复用；它只是把每个 `+` 变成一个拼接调用点。

所以结论没变：循环里拼大量字符串，手动用 `StringBuilder`。它内部是一块可扩容的缓冲区，`append` 改的是同一个对象，最后 `toString()` 才生成一个 String：

```java
StringBuilder builder = new StringBuilder();
builder.append("a").append("b");
String result = builder.toString();
```

如果一轮只拼三五个串，`+` 更清楚，没必要为了「优化」把代码写复杂。规模大时才换；具体快多少我没在这里做基准，不编数字。

## 跑一遍

本机 Temurin 25，示例统一按 `javac --release 21` 编译。把这一课的东西放进一个类：`sumTo` 用 `for`，`join` 用 `StringBuilder` 和数组下标，`countdown` 用 `while`，`attempts` 用 `do-while`，名字用 `for-each` 打印。

<!-- run -->
```java
public class Main {
    static int sumTo(int limit) {
        int total = 0;
        for (int i = 1; i <= limit; i++) {
            total += i;
        }
        return total;
    }

    static String join(String[] parts, String separator) {
        StringBuilder builder = new StringBuilder();
        for (int i = 0; i < parts.length; i++) {
            if (i > 0) {
                builder.append(separator);
            }
            builder.append(parts[i]);
        }
        return builder.toString();
    }

    public static void main(String[] args) {
        System.out.println(sumTo(4));

        String[] names = {"小林", "小周", "小陈"};
        for (String name : names) {
            System.out.println(name);
        }

        System.out.println(join(names, "、"));

        int countdown = 3;
        while (countdown > 0) {
            System.out.println(countdown);
            countdown--;
        }

        int attempts = 0;
        do {
            attempts++;
        } while (attempts < 2);
        System.out.println("尝试次数：" + attempts);
    }
}
```
```text
10
小林
小周
小陈
小林、小周、小陈
3
2
1
尝试次数：2
```

## 还差的

- 数组只给了最小预览。怎么 `new`、越界时抛什么、`String[]` 赋给 `Object[]` 为什么能编译却在运行时炸，都在第 04 课。
- 值传递只提了一句。参数是基本类型还是引用类型、方法里改参数会不会影响外面，第 06 课讲。
- 递归只说了「后面再讲」。递归的终止条件、调用栈多深会 `StackOverflowError`，这一课没展开。
- `StringBuilder` 的初始容量、`StringBuffer` 的线程安全、`String.join` 这些都没讲；这一课只回答「循环里为什么别一直用 `+`」。
- 标签只演示了嵌套循环。`break 标签;` 也能跳出带标签的普通语句块，这一课没给例子；这一课只演示循环上的用法。
- 拼接性能没有基准数字。要比较就自己写 JMH，别拿一段 `System.nanoTime()` 当结论。
