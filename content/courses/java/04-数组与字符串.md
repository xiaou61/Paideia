# 04 · 数组与字符串

## 排完序，「小林 62」

我拿两个数组存这张三人的成绩单：`names` 放名字，`scores` 放分数，同一个人在两边下标相同。想按分数从小到大看，我就排了 `scores`：

```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        String[] names = {"小林", "小周", "小陈"};
        int[] scores = {90, 62, 78};

        Arrays.sort(scores);

        for (int i = 0; i < scores.length; i++) {
            System.out.println(names[i] + " " + scores[i]);
        }
    }
}
```

本机 JDK 25（Temurin 25.0.4+7），`javac --release 21 Main.java` 之后 `java Main`：

```text
小林 62
小周 78
小陈 90
```

小林是 90 分的那位。我原来以为「排一张表，行会整行跟着动」，像电子表格里选中两列一起排。实际 `Arrays.sort(scores)` 只拿到 `scores` 这一块内存，它不知道旁边还有个 `names`；它做的唯一一件事，是把这个 `int[]` 里的数字在原地调成升序。名字一个都没动，于是「下标相同就是同一个人」这条对应关系被排没了。

错不在 `sort`，在我拿两个数组拼一张表——那层对应关系只活在我脑子里。

## 对齐活在两个数组的下标里

数组能装的元素只有一种类型。这张成绩单有两列：名字是 `String`、分数是 `int`，一个数组装不下，所以我拆成两个，用「下标相同」连起来。这条连接没有任何代码在维护，`Arrays.sort` 一动手它就作废。

要让它真的连在一起，得换成能一起动的容器：第 05 课的类，或者第 08 课的 `List`。数组的本分先把规矩看清：

- 长度在 `new` 那一刻定死，之后只能读 `length`——它是字段，不带括号；
- 下标从 0 开始，最后一个元素是 `length - 1`；
- `new int[3]` 的元素是 `0`，`new String[3]` 的元素是 `null`（不是空串）；
- 越界不在编译期查，跑到那一行才抛。

第 03 课只用过在声明处直接给元素的那种写法，这里补上另外两种：

```text
int[] scores = new int[3];                     // 三个 0
int[] fixed = {90, 62, 78};                    // 声明处就给元素
String[] names = new String[]{"小林", "小周"};  // 完整写法，等价于上一种
```

`new String[3]` 打印出来是 `[null, null, null]`。对其中一个元素调 `length()`：

```text
Exception in thread "main" java.lang.NullPointerException: Cannot invoke "String.length()" because "<local1>[0]" is null
	at N.main(N.java:4)
```

后半句「谁调用了什么、哪个元素是 null」是 JDK 14（JEP 358）才加进消息里的，老版本只给一个类名。引用类型不指向任何对象时读它的成员，就是 `NullPointerException`；怎么接住第 13 课讲。

## 越界要跑到那一行才报

给成绩单求平均分，我把循环条件写成了 `<=`：

```java
public class Main {
    public static void main(String[] args) {
        int[] scores = {90, 62, 78};
        for (int i = 0; i <= scores.length; i++) {
            System.out.println(i + " " + scores[i]);
        }
    }
}
```

`javac --release 21 Main.java` 一句提示都没有；`java Main` 打到第四轮停下：

```text
0 90
1 62
2 78
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 3 out of bounds for length 3
	at Main.main(Main.java:5)
```

消息里两个数都给全了：要访问下标 3，长度只有 3，合法下标是 0、1、2。`<=` 改成 `<` 就对了。

`javac` 不是没看见这个 `<=`，是它根本没往下算：下标是运行时才算出来的值，编译器只检查 `scores` 是不是 `int[]`、`scores[i]` 里的 `i` 是不是 `int`。`scores[3]` 这种写死的越界，它也不查。

## `Object[]` 能接 `String[]`，写进去才炸

`Object` 是引用类型的顶部类型（第 07 课讲继承时会解释为什么）。数组这条规则跟着变：`String` 是 `Object` 的子类型，`String[]` 也就能赋给 `Object[]`。

```java
public class Main {
    public static void main(String[] args) {
        Object[] box = new String[]{"a"};
        box[0] = 1;
        System.out.println("没报错");
    }
}
```

`javac --release 21 Main.java` 通过，`java Main` 在赋值那一行停住：

```text
Exception in thread "main" java.lang.ArrayStoreException: java.lang.Integer
	at Main.main(Main.java:4)
```

`box` 的声明类型是 `Object[]`，编译器只能看声明；`1` 会被自动装成 `Integer`，对 `Object` 来说是合法的。但 `box` 指向的那个对象，运行时知道自己是被 `new String[]{...}` 造出来的 `String[]`，写入前要做一次元素类型检查，`Integer` 不是 `String`，于是抛。

反方向连编译都过不了：

```text
Main.java:3: error: incompatible types: int[] cannot be converted to Object[]
        Object[] box = new int[]{1};
                       ^
1 error
```

基本类型的数组不参与这条协变：`int[]` 是 `Object`，但不是 `Object[]`。

所以数组的「能赋值」和「能写入」是两件事，闸门被挪到了运行期。`Object[] box` 这个名字看着像「什么都能装」，实际能装什么由它此刻指向谁决定。想在声明时就把元素类型定死、又不想等运行期才发现，那是泛型的方向，正好和数组相反——第 08 课讲。

## 打印出来是 `[I@6b95977`

想先看一眼数组里存了什么，直觉上写 `System.out.println(scores)`：

```java
public class Main {
    public static void main(String[] args) {
        int[] scores = {90, 62, 78};
        String[] names = {"小林", "小周"};
        System.out.println(scores);
        System.out.println(names);
    }
}
```

```text
[I@6b95977
[Ljava.lang.String;@7e9e5f8a
```

这不是 bug，是 `Object.toString()` 的形状：`类名@十六进制`。数组没有重写 `toString`，走的就是继承来的那一版。`[I` 是 `int[]` 在 JVM 里的内部名字（`[` 表示数组、`I` 表示 `int`），`[Ljava.lang.String;` 同理。

`@` 后面那串来自 `Object.hashCode()`，规范只规定了 `toString` 长这样，没规定哈希值怎么算。我连着跑两次，两次都是 `6b95977`——同一台机器、同一个 JDK、同一个分配顺序，它稳定；换台机器或换个 JDK 版本就未必。所以它不是你程序的行为，是这一次运行给对象编的号，别抄进断言里。

要打印内容用 `Arrays.toString`，比较内容用 `Arrays.equals`（第 02 课说过 `==` 比身份，数组也一样，`scores == scores` 当然是 `true`，换成另一个内容相同的数组就是 `false`）。

`Arrays` 里这一课要用的几个：

| 调用 | 拿到什么 | 什么时候会踩坑 |
| --- | --- | --- |
| `Arrays.toString(a)` | `[90, 62, 78]` 这样的字符串 | 以为 `println(a)` 也能这样 |
| `Arrays.equals(a, b)` | 逐元素比较的布尔值 | 用 `==` 比内容 |
| `Arrays.sort(a)` | 没有返回值，原地改 `a` | 以为它会返回排好的新数组，于是 `a` 已经被改乱 |
| `Arrays.copyOf(a, n)` | 长度 n 的新数组，原数组不动 | 调完没接住，然后以为数组能变长 |

最后一行牵着「数组定长」这条规矩：想多放一个人，只能造一个更长的数组，把旧的抄过去。`Arrays.copyOf(names, 4)` 把「造新的 + 抄」包成一次调用，返回的是新数组，`names` 还是 3 格；要留住它得写 `names = Arrays.copyOf(names, 4)`。另外两条路是手写 `for` 逐个赋值和 `System.arraycopy`，这一课不铺开。

## 这行成绩单是从一段文本里切出来的

前面那张成绩单不是手写的，它来自一行文本：

```java
String line = "小林:90,小周:62,小陈:78";
```

切第一刀用 `split`，它返回 `String[]`：

```text
String[] rows = line.split(",");   // {"小林:90", "小周:62", "小陈:78"}
rows.length                        // 3：数组的 length，不带括号
rows[0].length()                   // 5：String 的 length()，带括号
```

两个 `length` 长得像、写法不同，混了就编译不过。集合还有第三个 `size()`，第 08 课。

`split` 的参数是**正则表达式**，不是普通字符串。这条区别咬人的地方是按点号切：`"a.b".split(".")` 得到的是长度 0 的数组——点号在正则里匹配任意字符，整串每个字符都被当成分隔符，剩下的一串空串又在尾部被清掉。要按字面点切，写 `split("\\.")`，得到 2 个元素。尾部空串怎么算的细节，第 09 课有一张对照表。

每一行还要再切一刀：名字和分数之间夹着冒号。用 `indexOf` 找位置，用 `substring` 切：

```text
String row = "小林:90";
int colon = row.indexOf(':');   // 2
row.substring(0, colon)         // "小林"，下标 0、1
row.substring(colon + 1)        // "90"，从冒号后一位到结尾
```

`substring(a, b)` 左闭右开，`b` 那个位置取不到。所以名字那头写 `0, colon`（不含冒号），分数那头写 `colon + 1`（跳过冒号）。

问题出在有人抄漏了冒号，那一行只有 `"小陈"`。这时 `indexOf` 返回 `-1`——它用 `-1` 表示「没找到」，不抛异常。这个 `-1` 被直接喂给 `substring`：

```java
public class Main {
    public static void main(String[] args) {
        String row = "小陈";
        int colon = row.indexOf(':');
        System.out.println(row.substring(0, colon));
    }
}
```

```text
Exception in thread "main" java.lang.StringIndexOutOfBoundsException: Range [0, -1) out of bounds for length 2
	at java.base/java.lang.String.checkBoundsBeginEnd(String.java:4937)
	...
	at Main.main(Main.java:5)
```

中间几帧是 JDK 内部的检查方法，我省略了；`at Main.main(Main.java:5)` 是唯一属于你代码的那一帧——也就是说，栈指着 `substring`，真正「没找到」的其实是上一行的 `indexOf`。把返回值交给 `substring` 之前先判一次：

```text
int colon = row.indexOf(':');
if (colon < 0) {
    System.out.println("这一行没有冒号：" + row);
} else {
    String name = row.substring(0, colon);
    String score = row.substring(colon + 1);
}
```

`indexOf` 把错误当值返回、`substring` 拿到值才炸，这两件事凑在一起，就让崩溃点离出错点隔了一行。

## 跑一遍

把上面几节拼成一个程序：从一行文本还原成两个数组、打印内容、排序但只排副本、再给数组扩一格。

<!-- run -->
```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        String line = "小林:90,小周:62,小陈:78";
        String[] rows = line.split(",");

        String[] names = new String[rows.length];
        int[] scores = new int[rows.length];
        for (int i = 0; i < rows.length; i++) {
            int colon = rows[i].indexOf(':');
            names[i] = rows[i].substring(0, colon);
            scores[i] = Integer.parseInt(rows[i].substring(colon + 1));
        }

        System.out.println(Arrays.toString(names));
        System.out.println(Arrays.toString(scores));
        System.out.println(names.length + " " + names[0].length());

        int[] sorted = Arrays.copyOf(scores, scores.length);
        Arrays.sort(sorted);
        System.out.println(Arrays.toString(sorted));
        System.out.println(Arrays.toString(scores));
        System.out.println(Arrays.equals(scores, sorted));

        String[] grown = Arrays.copyOf(names, names.length + 1);
        grown[grown.length - 1] = "小赵";
        System.out.println(grown.length + " " + Arrays.toString(grown));
    }
}
```
```text
[小林, 小周, 小陈]
[90, 62, 78]
3 2
[62, 78, 90]
[90, 62, 78]
false
4 [小林, 小周, 小陈, 小赵]
```

几行对着看：

- `3 2` 是两个 `length` 的写法差异，`names` 是 3 格，小林这个名字 2 个字符；
- `[62, 78, 90]` 和 `[90, 62, 78]` 都在，说明 `sort` 排的是副本，`scores` 原样；
- `Arrays.equals(scores, sorted)` 是 `false`，内容不同就是不同，和 `==` 是两回事；
- `4 [小林, 小周, 小陈, 小赵]` 是新数组，`names` 依然是 3 格。

`Integer.parseInt` 负责把 `"90"` 变成 `90`，碰到非数字抛 `NumberFormatException`；它和包装类的关系第 10 课讲，怎么接住异常第 13 课讲，这里先照抄。

「排在副本上」不是排序的标准姿势，只是这张表只有分数一列时我能做的一件不出错的事：名字和分数还靠下标对齐，我不去动它们。要真的按分数排名字，得先把「两个数组」这个结构换掉——第 05 课和第 08 课之后才有正常写法。

这一段见过了四类停下来的地方，下次遇到先对这张表：

| 你看到的 | 它在说什么 | 该动哪里 |
| --- | --- | --- |
| `[I@6b95977` | 打印的是对象编号，不是元素 | `println(a)` 换成 `Arrays.toString(a)` |
| `Index 3 out of bounds for length 3` | 要访问的下标等于 `length` | 循环条件 `<=` 改 `<` |
| `ArrayStoreException: java.lang.Integer` | 父类型数组里写进了它不认的元素 | 别用 `Object[]` 变量接 `String[]` |
| `Range [0, -1) out of bounds for length 2` | `indexOf` 返回的 `-1` 被喂给了 `substring` | 传下去之前判 `< 0` |
| `split` 结果长度是 0 | 分隔符按正则解释，点号是任意字符 | 写 `split("\\.")` |

## 还差的

- 「按分数排名字」的正式写法没给。这一课只做到「排副本」，因为手上还没有能把两列绑在一起的东西；第 05 课有自己的类，第 08 课有 `List`，那之后才能整条记录一起排。
- 数组协变只验了 `String[]` 和 `int[]` 两种。`String[][]` 之类的多维数组怎么协变、`Object[][]` 里塞 `String[]` 会不会抛、泛型数组为什么 `new List<String>[3]` 编译不过，都没碰。
- `Integer.parseInt` 只走了正常路径。`" 90"`（带空格）、空串、`"9O"`（字母 O）各自抛什么没跑，`NumberFormatException` 怎么接住第 13 课。
- 字符数只数了 BMP 内的中文：`"小林".length()` 是 2。`length()` 数的是 UTF-16 code unit，emoji 算 2、代理对与 `codePointCount` 第 29 课，这篇所有例子都在 BMP 内。
- 性能一个数没测。`Arrays.copyOf` 扩一次容的开销、手写 `for` 抄一段和 `System.arraycopy` 差多少，我都没跑基准，所以不给数字。
