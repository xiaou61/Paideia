# 07 · 继承、多态与接口

## 这一课你要会

- 写子类、用 `super()` 调父类构造器、重写方法；
- 说清多态在"换一种实现"时省掉了什么；
- 分清抽象类与接口，知道该选哪个。

## 为什么

Java 的两大复用手段都在这一课：`extends`（继承）和 `implements`（接口）。它们解决的其实是同一个问题——**让调用方只依赖行为，不依赖具体类**。

分不清两者会让类型层级越来越怪：要么该用接口的地方硬套继承，要么把一堆无关的类塞进同一条继承链。

## 讲解

### 继承的最短形状

```text
class Animal {
    protected final String name;

    Animal(String name) {
        this.name = name;
    }

    String speak() {
        return "...";
    }
}

class Dog extends Animal {
    Dog(String name) {
        super(name);
    }

    @Override
    String speak() {
        return "汪";
    }
}
```

要点：

- **子类构造器必须先调父类构造器**（`super(...)`）。不写时编译器会插入一个无参的 `super()`，父类没有无参构造器就编译失败；
- **`@Override` 注解不是必须，但一定写**：它让编译器帮你检查"确实重写到了"，拼错方法名会立刻报错；
- **`protected`** 表示"子类可见"，比 `private` 宽、比 `public` 窄。

### 多态

```text
List<Animal> animals = List.of(new Dog("旺财"), new Cat("咪咪"));
for (Animal animal : animals) {
    System.out.println(animal.speak());
}
```

循环里写的是 `Animal`，实际执行的是各自的 `speak()`。这就是多态：**调用方按父类型写，运行期按真实类型分派**。

加一种新动物，这个循环一个字都不用改——这就是它省下的东西。

### 抽象类 vs 接口

| | 抽象类 `abstract class` | 接口 `interface` |
| --- | --- | --- |
| 能写字段 | 能（含实例字段） | 只能常量（`static final`） |
| 能写构造器 | 能 | 不能 |
| 能写方法实现 | 能 | 能（`default` 方法） |
| 一个类能继承/实现几个 | **1 个** | **多个** |
| 表达什么 | "是一种"，且共享部分实现 | "具备某种能力" |

选法：**需要共享状态或部分实现 → 抽象类；只需要约定行为 → 接口**。绝大多数情况下接口更合适，因为 Java 只能单继承。

### 接口的现代写法

```text
interface Shape {
    double area();

    default String describe() {
        return "面积是 " + area();
    }
}
```

`default` 方法提供默认实现，实现类可以覆盖也可以不覆盖。这让"给接口加方法"不必强制所有实现类都改——这是 Java 8 之后接口能演进的原因。

### 跑一遍

<!-- run -->
```java
import java.util.List;

public class Main {

    interface Shape {
        double area();

        default String describe() {
            return String.format("面积 %.1f", area());
        }
    }

    abstract static class Animal {
        protected final String name;

        Animal(String name) {
            this.name = name;
        }

        abstract String speak();
    }

    static class Dog extends Animal {
        Dog(String name) {
            super(name);
        }

        @Override
        String speak() {
            return name + "：汪";
        }
    }

    static class Cat extends Animal {
        Cat(String name) {
            super(name);
        }

        @Override
        String speak() {
            return name + "：喵";
        }
    }

    record Circle(double radius) implements Shape {
        @Override
        public double area() {
            return Math.PI * radius * radius;
        }
    }

    record Square(double side) implements Shape {
        @Override
        public double area() {
            return side * side;
        }
    }

    public static void main(String[] args) {
        List<Animal> animals = List.of(new Dog("旺财"), new Cat("咪咪"));
        for (Animal animal : animals) {
            System.out.println(animal.speak());
        }

        List<Shape> shapes = List.of(new Circle(1), new Square(2));
        for (Shape shape : shapes) {
            System.out.println(shape.describe());
        }
    }
}
```
```text
旺财：汪
咪咪：喵
面积 3.1
面积 4.0
```

`record` 是 Java 16 起的语法糖：一行声明不可变数据类，自动生成构造器、`equals`、`hashCode`、`toString`。课程里只用到它表达"这就是一组值"，不展开。

## 常见误区

### 误区：子类会自动调用父类的构造器

**你以为**：继承之后父类的初始化自动跑。
**其实**：子类构造器第一句必须是 `super(...)`；不写时编译器插一个无参 `super()`。
**怎么验证**：父类只有一个带参构造器、子类不写 super，看编译错误。

### 误区：`@Override` 只是注释，写不写都一样

**你以为**：没有功能。
**其实**：它让"我以为重写了其实没有"变成编译错误。

### 误区：继承用来复用代码

**你以为**：有共同代码就抽个父类。
**其实**：继承表达"是一种"。只为复用代码而继承会让类型层级失真——用组合或接口。

## 小结

子类构造器先 `super(...)`。多态让调用方只依赖父类型。`@Override` 一定要写。共享状态用抽象类，只约定行为用接口。
