# 07 · 继承、多态与接口

## 编译器的两句错，我当时都没看懂

给 `Animal` 加一个子类 `Bird`，我以为 `name` 是 `protected`，子类里当然能赋值：

```java
class Animal {
    protected final String name;

    Animal(String name) {
        this.name = name;
    }
}

class Bird extends Animal {
    Bird(String name) {
        this.name = name;
    }
}
```

`javac` 给了两句错（这是真实输出，JDK 21 起文字一样）：

```text
Main.java:7: error: constructor Animal in class Animal cannot be applied to given types;
    Bird(String name) {
                      ^
  required: String
  found:    no arguments
  reason: actual and formal argument lists differ in length
Main.java:8: error: cannot assign a value to final variable name
        this.name = name;
            ^
2 errors
```

第 7 行那句我没看懂——我明明没写"无参调用"。第 8 行更怪：`protected` 不是"子类可见"吗？

这两句话其实在说两条不同的规则，一次撞上了。

## 第一句：子类构造器的第一句必须是 super(...)

Java 规定：**每个构造器的第一句如果不是 `this(...)` 或 `super(...)`，编译器就替你插一个无参的 `super()`**。

我什么都没写，于是被插成了：

```java
Bird(String name) {
    super();            // 编译器自动加的
    this.name = name;
}
```

而 `Animal` 只有一个 `Animal(String)`，没有无参构造器，于是 `super()` 找不到目标——这就是"required: String, found: no arguments"的真实含义：它在抱怨那个被自动插入的无参调用。

改对很直接：

```java
class Bird extends Animal {
    Bird(String name) {
        super(name);
    }
}
```

有一条经验值得记住：**父类一旦只提供了带参构造器，所有子类都必须显式调 `super(...)`**。所以设计父类时如果不确定，就别急着把无参构造器删掉。

## 第二句：final 字段不能"再赋一次值"

`protected final String name` 里，`final` 的意思是"这个字段只能被赋值一次"，赋值地点只有两处：声明处，或它所属类的构造器里。

`Bird` 的构造器不是 `Animal` 的构造器，所以 `this.name = name` 在那里是**第二次赋值**，编译不过。`protected` 管的是可见性，`final` 管的是可写性——两个维度，我当年混在一起理解了。

想让子类能设这个值，正确做法是让父类的构造器去设（即上面的 `super(name)`），而不是绕过去直接赋值。

## 多态：真正省事的地方在"加一种新的"那一刻

把行为收进父类，让子类各自实现：

```java
abstract class Animal {
    protected final String name;

    Animal(String name) {
        this.name = name;
    }

    abstract String speak();
}
```

调用方只写父类型：

```java
List<Animal> animals = List.of(new Dog("旺财"), new Cat("咪咪"));
for (Animal animal : animals) {
    System.out.println(animal.speak());
}
```

循环里没有一处提到 `Dog`、`Cat`。以后加 `Bird`，这个循环一个字都不用改——**这才是多态省下的东西：不是少写代码，是调用方不需要知道新增了谁**。

如果这里写成 `if (animal instanceof Dog)` 再强转，那多态就白用了：每加一种动物都得回来改这个 `if`。

## 跑一遍

<!-- run -->
```java
import java.util.List;

public class Main {

    abstract static class Animal {
        protected final String name;

        Animal(String name) {
            this.name = name;
        }

        abstract String speak();
    }

    static class Dog extends Animal {
        Dog(String name) {
            super(name);
        }

        @Override
        String speak() {
            return name + "：汪";
        }
    }

    static class Cat extends Animal {
        Cat(String name) {
            super(name);
        }

        @Override
        String speak() {
            return name + "：喵";
        }
    }

    interface Shape {
        double area();

        default String describe() {
            return String.format("面积 %.1f", area());
        }
    }

    static class Circle implements Shape {
        private final double radius;

        Circle(double radius) {
            this.radius = radius;
        }

        @Override
        public double area() {
            return Math.PI * radius * radius;
        }
    }

    static class Square implements Shape {
        private final double side;

        Square(double side) {
            this.side = side;
        }

        @Override
        public double area() {
            return side * side;
        }
    }

    public static void main(String[] args) {
        List<Animal> animals = List.of(new Dog("旺财"), new Cat("咪咪"));
        for (Animal animal : animals) {
            System.out.println(animal.speak());
        }

        List<Shape> shapes = List.of(new Circle(1), new Square(2));
        for (Shape shape : shapes) {
            System.out.println(shape.describe());
        }
    }
}
```
```text
旺财：汪
咪咪：喵
面积 3.1
面积 4.0
```

两点顺带说：

- `Circle`/`Square` 这两个类写起来有点长。Java 16 起可以用 `record Circle(double radius) implements Shape` 一行搞定，第 35 课讲 `record`，这里先不用，免得你以为是新语法。
- `@Override` 不写也能跑，但一定写。它让"我以为重写了、其实只是新加了一个方法"这种错误在编译期就暴露——尤其是方法名拼错一个字母的时候。

## 抽象类还是接口：一条判据

| | 抽象类 `abstract class` | 接口 `interface` |
| --- | --- | --- |
| 实例字段 | 有 | 没有（只能 `static final` 常量） |
| 构造器 | 有 | 没有 |
| 方法实现 | 有 | 有（`default` / `static` / `private` 方法，Java 8/9 起） |
| 一个类能用几个 | 继承 1 个 | 实现多个 |
| 表达 | "是一种"，且共享部分状态与实现 | "具备某种能力" |

判据（按顺序问自己）：

1. 这些实现类**需要共享字段或共享一段实现**吗？需要 → 抽象类。不需要 → 接口。
2. **这些类本质上是同一类东西吗**（`Dog` 是一种 `Animal`）？是 → 可以继承。不是（`Circle` 和 `FileOutputStream` 都能"关闭"）→ 接口。
3. 拿不准 → 接口。因为 Java 只能单继承，选错继承会锁死在一条链上，而接口可以后补、可以实现多个。

## 接口的 default 到底解决什么

```java
interface Shape {
    double area();

    default String describe() {
        return String.format("面积 %.1f", area());
    }
}
```

`default` 方法带实现，实现类可以不覆盖。它真正解决的问题是**给已发布的接口加方法**：没有 `default` 时，给接口加一个方法会让所有实现类编译失败；有了 `default`，老实现类不用动就能继续编译。

这也是为什么 `List` 在 Java 8 之后能加 `stream()` 而不破坏任何人的代码。

## 带走三句话

- 子类构造器第一句是 `super(...)`；父类没有无参构造器时，这一句不能省。
- `protected` 管可见，`final` 管可写——子类能看见父类的 final 字段，但不能替它赋值。
- 拿不准继承还是接口就选接口：Java 只能单继承，选错了改不回来。
