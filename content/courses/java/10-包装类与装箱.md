# 10 · 包装类与自动装箱

## 这一课你要会

- 说清八种基本类型对应的包装类，以及为什么要有它们；
- 解释 `Integer a = 1000; Integer b = 1000; a == b` 为什么是 `false` 而 `100` 时是 `true`；
- 认出自动拆箱导致的 `NullPointerException`；
- 知道 `Integer` 缓存范围是 `-128..127`，以及为什么不该依赖它。

## 为什么

Java 有两套数字：基本类型（`int`、`double`）和包装类（`Integer`、`Double`）。

基本类型快、不占对象、不能为 `null`；包装类是对象，能进集合、能为 `null`、能参与泛型。

问题出在**两者会自动互转**（自动装箱/拆箱），而转换过程里有两个坑：**缓存**和 **`null`**。这两个坑都不报错，只给你错误的结果或一个奇怪的 NPE。

## 讲解

### 八种基本类型与它们的包装类

| 基本类型 | 包装类 | 默认值（字段/数组） |
| --- | --- | --- |
| `byte` | `Byte` | `0` |
| `short` | `Short` | `0` |
| `int` | `Integer` | `0` |
| `long` | `Long` | `0L` |
| `float` | `Float` | `0.0f` |
| `double` | `Double` | `0.0d` |
| `char` | `Character` | `'\u0000'` |
| `boolean` | `Boolean` | `false` |

注意 `int` → `Integer`、`char` → `Character`，其余都是首字母大写。**包装类都是对象**，没有无参构造之外的"轻量"形式（`Integer` 内部只有一个 `int` 字段，但整个对象有对象头）。

### 什么时候必须用包装类

三个场景，基本类型做不到：

```java
// 1) 泛型不能是基本类型
List<Integer> numbers = new ArrayList<>();   // List<int> 编译不过
Map<String, Long> counts = new HashMap<>();

// 2) 需要表达"没有值"
Integer score = null;   // int 不能是 null

// 3) 反射与框架（Spring、Jackson）大量依赖包装类
```

**其余情况用基本类型**。局部变量、方法参数、返回值——只要确定有值，就用 `int` 而不是 `Integer`：少一次对象分配，也没有 NPE 风险。

### 自动装箱与拆箱

```java
Integer boxed = 42;    // 自动装箱：Integer.valueOf(42)
int unboxed = boxed;   // 自动拆箱：boxed.intValue()
```

编译器自动插了这两次调用。方便，但每次装箱都可能分配对象——在循环里累积起来就是垃圾。

### 坑一：`Integer` 缓存 -128..127

```java
Integer a = 100;
Integer b = 100;
System.out.println(a == b);   // true

Integer c = 1000;
Integer d = 1000;
System.out.println(c == d);   // false
```

原因：`Integer.valueOf(int)` 对 `-128..127` 直接返回**缓存里的同一个对象**，超出范围才 `new`。所以 `a` 和 `b` 是同一个对象（`==` 为真），`c` 和 `d` 是两个不同对象（`==` 为假）。

**这个缓存是 JLS 规定的**（`-128..127` 必须缓存），加大值是 HotSpot 的可选行为（`-XX:AutoBoxCacheMax`）。所以：

> **绝不依赖 `==` 比较包装类。** 一律用 `equals`，或者先拆箱成基本类型再比。

缓存本身是好东西（小整数太常用），坏的只是"用 `==` 比它"。

### 坑二：拆箱时的 `NullPointerException`

```java
Integer total = null;
int value = total;        // NPE！拆箱调 total.intValue()
```

更隐蔽的是**混合运算**：

```java
Integer a = null;
if (a > 0) { ... }        // NPE：a > 0 会先拆箱
```

以及**三元表达式**：

```java
Integer maybe = null;
Integer result = true ? 0 : maybe;    // 拆箱，NPE
```

最后一个特别容易漏——看起来只是"取一个值"，实际上三元运算符在一边是 `int`、另一边是 `Integer` 时，会把 `Integer` 拆箱统一成 `int`。

**防御写法**：明确给默认值。

```java
int value = total == null ? 0 : total;
Integer safe = (Integer) (flag ? Integer.valueOf(0) : maybe);  // 显式保持包装类型
```

更实用的做法是：**别让包装类出现在算术里**。从 `null` 可能的来源（数据库、JSON）取到值之后，立刻判空转成基本类型，之后的逻辑全用 `int`。

### 包装类做 `HashMap` 的 key：能行，但要小心

```java
Map<Integer, String> byId = new HashMap<>();
byId.put(1, "a");
System.out.println(byId.get(1));    // a
```

`HashMap` 用 `equals` + `hashCode` 找 key，所以 `Integer` 作为 key 是正确的（`get(1)` 会对 `1` 装箱再比较 `equals`）。

**但 `Long` 和 `Integer` 不能混用**：`map.put(1L, ...)` 与 `map.get(1)` 是两个不同的 key。

### 数值比较：`compare` 与 `compareTo`

```java
Integer a = 1000;
Integer b = 1000;
System.out.println(a == b);              // false
System.out.println(a.equals(b));         // true
System.out.println(a.compareTo(b) == 0); // true
```

`compareTo` 返回负数/0/正数，适合排序。`Integer.compare(a, b)` 是静态版本，不用管 null（会 NPE，所以要先判）。

### `parseInt` 与 `valueOf` 的区别

```java
int a = Integer.parseInt("42");        // 基本类型 int
Integer b = Integer.valueOf("42");     // 包装类（走缓存）
Integer c = Integer.valueOf(42);       // 同上
```

`parseInt` 直接给 `int`，不产生对象；`valueOf` 给 `Integer`，可能走缓存。**能用 `parseInt` 就用它**——省一次装箱。

## 动手

这段代码把两个坑都演出来：先看缓存边界，再看拆箱 NPE 的触发点。

<!-- run -->
```java
public class Main {
    public static void main(String[] args) {
        // 1) 缓存边界：127 与 128 是分水岭
        Integer small1 = 127;
        Integer small2 = 127;
        Integer big1 = 128;
        Integer big2 = 128;
        System.out.println("127 == 127 : " + (small1 == small2));
        System.out.println("128 == 128 : " + (big1 == big2));
        System.out.println("128 equals : " + big1.equals(big2));

        // 2) 拆箱 NPE：混合运算会先拆箱
        Integer missing = null;
        try {
            if (missing > 0) {
                System.out.println("不会到这里");
            }
        } catch (NullPointerException failure) {
            System.out.println("拆箱 NPE 被捕获");
        }

        // 3) 正确写法：先判空再转基本类型
        int safe = missing == null ? 0 : missing;
        System.out.println("安全取值：" + safe);

        // 4) parseInt 不产生对象，valueOf 走缓存
        int primitive = Integer.parseInt("42");
        Integer boxed = Integer.valueOf(42);
        System.out.println("parseInt=" + primitive + " valueOf=" + boxed);
    }
}
```

```text
127 == 127 : true
128 == 128 : false
128 equals : true
拆箱 NPE 被捕获
安全取值：0
parseInt=42 valueOf=42
```

注意第三、四行：**`==` 说不同，`equals` 说相同**。这就是为什么包装类不能用 `==` 比。

## 常见误区

### 误区：`Integer` 和 `int` 差不多，随手用哪个都行

差别有三个：`Integer` 是对象（有对象头、可能为 null、需要分配）、`int` 是值。默认用 `int`，只在需要 `null` 或进集合时用 `Integer`。

### 误区：小数字用 `==` 没问题，因为缓存让它相等

它"碰巧"相等，但这是实现细节。同一个人写下一段类似的代码遇到 `1000` 就变成 `false`。**别建立这种依赖。**

### 误区：`Objects.equals` 也要判空

不用。

```java
Objects.equals(null, null);        // true
Objects.equals(null, "x");         // false
Objects.equals("x", "x");          // true
```

它是 null 安全的比较工具，两个参数都可以是 null。比较两个可能为 null 的包装类时，用它比手写 `a != null && a.equals(b)` 干净。

### 误区：`Integer` 的 `+` 不会出问题

`a + b`（两个 `Integer`）会**先各自拆箱、相加、再装箱**。三步里任何一步遇到 `null` 都 NPE。而且结果是新对象，`==` 又不可靠。

## 小结

- 八种基本类型各有包装类；`int`→`Integer`、`char`→`Character`。
- 只有需要 `null`、进集合、参与泛型时才用包装类，其余用基本类型。
- `Integer` 缓存 `-128..127`：**包装类一律用 `equals` 比，不用 `==`**。
- 拆箱遇到 `null` 抛 NPE，混合运算与三元表达式都会触发拆箱。
- `Objects.equals` 是 null 安全的比较工具；`parseInt` 比 `valueOf` 少一次装箱。
