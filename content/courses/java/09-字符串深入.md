# 09 · 字符串：不可变、池与拼接

## 这一课你要会

- 说清 `String` 为什么不可变，以及"不可变"到底省了你什么事；
- 分清 `==`、`equals`、`equalsIgnoreCase` 各自比什么；
- 知道字符串常量池什么时候帮你省对象、什么时候不省；
- 判断一段拼接代码会不会在循环里偷偷造出成千上万个对象。

## 为什么

Java 里最常被写错的类型不是 `int`，是 `String`。

三个高频错误：用 `==` 比内容、在循环里用 `+` 拼字符串、以为 `trim()` 会改自己。它们都不会报错，只会安静地给出错的结果或者慢十倍。

这一课把这三件事一次讲透。

## 讲解

### 不可变：`String` 一旦造出来就改不了

```java
String a = "hi";
a.toUpperCase();      // 返回值是 "HI"，但 a 还是 "hi"
System.out.println(a); // hi
```

`toUpperCase()` 不会修改 `a`，它**造了一个新字符串返回**。这就是"不可变"：所有看似修改的方法，实际都返回新对象。

**不可变换来了三件事**：

1. **可以安全共享**：同一个 `"hi"` 被一千个变量引用也没问题，没人能改它；
2. **可以缓存哈希**：`String` 第一次算完 `hashCode` 之后缓存起来，所以它当 `HashMap` 的 key 特别快；
3. **线程安全**：不可变对象天然没有并发问题，不需要加锁。

**代价**：每次"修改"都要复制。所以频繁改内容时不能用 `String`，要用 `StringBuilder`（下面讲）。

### `==` 比地址，`equals` 比内容

```java
String a = "java";
String b = "java";
String c = new String("java");

System.out.println(a == b);         // true  —— 同一个池里的对象
System.out.println(a == c);         // false —— c 是新建的对象
System.out.println(a.equals(c));    // true  —— 内容相同
```

`==` 比的是"是不是同一个对象"（引用相等），`equals` 比的是"内容是否相同"。

**规则**：比较字符串内容**永远用 `equals`**。用 `==` 有时对有时不对——`a == b` 之所以是 `true`，是常量池在帮你省对象，换个写法就变成 `false`。这种"大部分时候对"的 bug 最难查。

`s.equals(x)` 与 `x.equals(s)` 的区别：前者在 `s` 为 `null` 时会抛 `NullPointerException`，后者会。所以**常量写在前面**更安全：

```java
if ("yes".equals(answer)) { ... }   // answer 为 null 也安全
```

### 字符串常量池：省对象的地方

```java
String a = "java";              // 进池
String b = "java";              // 复用池里那个，a 和 b 是同一个对象
String c = new String("java");  // 强制新建，不进池（内容相同但是不同对象）
String d = c.intern();          // 手工入池：如果池里已有 "java"，返回池里那个
```

**什么时候用 `new String(...)`**：几乎不用。它唯一明确的用途是"我确实需要一个新的、与池里那个不同身份的对象"——那种场景极少。

**`intern()` 的意义**：把运行时拼出来的字符串丢进池里，之后同样的内容可以共享。适合"大量重复的固定值"（比如从文件里读出来的一批状态名）。**不适合**千变万化的值——池也会占内存。

### 拼接：`+` 在循环里是陷阱

```java
// 反面例子：循环 1 万次，造出 1 万个中间字符串
String result = "";
for (int i = 0; i < 10000; i++) {
    result += i;   // 每次都是"复制旧内容 + 追加"，第 n 次复制 n 个字符
}
```

`result += i` 等价于 `result = result + i`：每次都造一个全新的字符串，把旧内容整个复制一遍。总量是 1+2+3+…+10000 个字符，约 5000 万个字符的复制。

**正确写法**：用 `StringBuilder`。

```java
StringBuilder builder = new StringBuilder();
for (int i = 0; i < 10000; i++) {
    builder.append(i);   // 内部是可扩容的数组，追加是均摊 O(1)
}
String result = builder.toString();
```

**一条实用判据**：**循环里的拼接一律用 `StringBuilder`**。循环外的少量拼接（`a + " " + b`）编译器会自动优化成 `StringBuilder`，不必手写。

### 常用方法里最容易搞错的几个

| 方法 | 做什么 | 陷阱 |
| --- | --- | --- |
| `trim()` | 去掉首尾空白 | **不改自己**，返回新串；它只认 ≤ 空格（U+0020）的字符，全角空格去不掉 |
| `strip()` | 去掉首尾空白（Unicode 版） | Java 11 起才有；中文全角空格用这个 |
| `split(",")` | 按分隔符切开 | 结尾的空串会被丢掉：`"a,b,".split(",")` 只有 2 个元素 |
| `substring(a, b)` | 取 `[a, b)` | **b 不含**；`substring(0, 0)` 是空串不是第一个字符 |
| `replace` vs `replaceAll` | 前者按字面替换，后者按正则 | `replaceAll(".", "")` 会删掉**全部字符**，因为 `.` 是正则"任意字符" |

`replaceAll` 那个坑值得单独记：**只要用到 `replaceAll`，第一个参数就是正则**。想替换字面量里的 `.`，要写 `replaceAll("\\.", "")` 或者干脆用 `replace(".", "")`。

### 字符串与数字的互转

```java
int n = Integer.parseInt("42");        // 42
String s = String.valueOf(42);         // "42"
String t = 42 + "";                    // 也能转，但不推荐：可读性差，且可能有性能问题
```

**`parseInt` 遇到非数字会抛 `NumberFormatException`**，它是 `RuntimeException`，不强制捕获。所以解析用户输入时必须自己判：

```java
static Integer tryParse(String text) {
    try {
        return Integer.parseInt(text.trim());
    } catch (NumberFormatException failure) {
        return null;   // 用 null 表示"不是数字"，比抛异常给调用方更省事
    }
}
```

## 动手

先看一遍完整示例：它演示不可变、池、以及循环拼接的两种写法。

<!-- run -->
```java
public class Main {
    public static void main(String[] args) {
        // 1) 不可变：方法返回新串，原串不动
        String original = "  Hello  ";
        String trimmed = original.trim();
        System.out.println("原始=[" + original + "]");
        System.out.println("trim后=[" + trimmed + "]");
        System.out.println("长度变化：" + original.length() + " -> " + trimmed.length());

        // 2) == 与 equals
        String a = "java";
        String b = "java";
        String c = new String("java");
        System.out.println("a == b : " + (a == b));
        System.out.println("a == c : " + (a == c));
        System.out.println("a.equals(c) : " + a.equals(c));

        // 3) 循环拼接：StringBuilder 版
        StringBuilder builder = new StringBuilder();
        for (int i = 0; i < 5; i++) {
            if (i > 0) {
                builder.append('-');
            }
            builder.append(i);
        }
        System.out.println("拼接结果：" + builder.toString());

        // 4) split 的结尾空串会被丢掉
        String[] parts = "a,b,".split(",");
        System.out.println("split 元素个数：" + parts.length);
    }
}
```

```text
原始=[  Hello  ]
trim后=[Hello]
长度变化：9 -> 5
a == b : true
a == c : false
a.equals(c) : true
拼接结果：0-1-2-3-4
split 元素个数：2
```

注意最后一行：`"a,b,"` 按逗号切只有 **2** 个元素，不是 3。结尾那个空串被 `split` 默认丢掉了。要保留它得写 `split(",", -1)`。

## 常见误区

### 误区：`trim()` 会改掉原字符串

不会。所有 `String` 的方法都不改自己。`original.trim()` 只是"算了一下"，结果丢了就丢了——必须接住返回值。

### 误区：`==` 能比字符串，反正简单测试里都对

只在小范围里对。`"a" == "a"` 为真，是因为两个都是编译期常量、指向池里同一个对象。一旦有一边来自 `new`、`substring`、`StringBuilder.toString()`、或者从网络/文件读进来的内容，`==` 就变成 `false`。**用 `equals`，不要赌。**

### 误区：`replaceAll` 就是"全部替换"的意思

它的意思是"按**正则**全部替换"。要替换字面量尽量用 `replace`（它按字面、且不解析正则）。必须用 `replaceAll` 时，把正则里所有元字符都转义：`.` `*` `+` `?` `(` `)` `[` `]` `{` `}` `\` `^` `$` `|`。

### 误区：`StringBuilder` 和 `StringBuffer` 随便选

`StringBuilder` 不是线程安全的，`StringBuffer` 是（方法上加了 `synchronized`）。**单线程里用 `StringBuilder`**；需要跨线程共享同一个缓冲区才考虑 `StringBuffer`——而那种需求本身很少见。

## 小结

- `String` 不可变：所有"修改"都返回新串，必须接住返回值。
- 比内容用 `equals`，常量写在前面避免 NPE。
- 常量池让相同字面量共享对象；`new String` 绕开它，`intern()` 主动入池。
- 循环拼接用 `StringBuilder`，`+` 在循环里是平方级代价。
- `replaceAll` 走正则，`trim` 只认半角空白，`split` 默认丢结尾空串。
