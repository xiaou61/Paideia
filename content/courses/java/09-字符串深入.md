# 09 · 字符串：不可变、池与拼接

## 传进来的 `admin`，`==` 说是 false

```java
public class RoleCheck {
    public static void main(String[] args) {
        String role = args.length > 0 ? args[0] : "guest";
        System.out.println("role = " + role);
        System.out.println("role == \"admin\"      : " + (role == "admin"));
        System.out.println("role.equals(\"admin\") : " + role.equals("admin"));
        System.out.println("\"admin\" == \"admin\"   : " + ("admin" == "admin"));
    }
}
```

本机 JDK 25（Temurin 25.0.4+7），`javac --release 21 -encoding UTF-8 RoleCheck.java`，再 `java RoleCheck admin`：

```text
role = admin
role == "admin"      : false
role.equals("admin") : true
"admin" == "admin"   : true
```

我先在 `main` 里写死 `String role = "admin"` 跑过一遍，`role == "admin"` 是 true，就以为这个判断没问题。改成从 `args[0]` 取之后，同一个 `if` 永远走 else：值一模一样，`==` 说不等。

差别不在值，在这两个引用指向的是不是同一个对象。`==` 比身份，`equals` 比内容——这句话熟到可以不过脑子地背出来，但背下来回答不了「`==` 什么时候才为真」。

## 哪几种写法会撞上同一个对象

下面这些变量的内容都是 `admin`，`==` 的结果却分成两派：

```java
public class Pool {
    public static void main(String[] args) {
        String a = "admin";
        String b = "admin";
        String c = new String("admin");
        String folded = "ad" + "min";
        String part = "ad";
        String joined = part + "min";
        String built = new StringBuilder("admin").toString();
        String sliced = "adminx".substring(0, 5);

        System.out.println("a == b（两处字面量）: " + (a == b));
        System.out.println("a == folded（\"ad\" + \"min\"）: " + (a == folded));
        System.out.println("a == c（new String）: " + (a == c));
        System.out.println("a == c.intern(): " + (a == c.intern()));
        System.out.println("a == joined（变量 + 字面量）: " + (a == joined));
        System.out.println("a == built（StringBuilder）: " + (a == built));
        System.out.println("a == sliced（substring）: " + (a == sliced));
    }
}
```

```text
a == b（两处字面量）: true
a == folded（"ad" + "min"）: true
a == c（new String）: false
a == c.intern(): true
a == joined（变量 + 字面量）: false
a == built（StringBuilder）: false
a == sliced（substring）: false
```

- **字面量**。JLS §3.10.5 规定字符串字面量和常量表达式的值会被 intern，共享同一个实例。所以同一程序里两处 `"admin"` 是同一个对象——这是规范给的，不是 HotSpot 恰好如此。
- **常量表达式**。`"ad" + "min"` 两边都是常量，编译期就折叠成一个 `"admin"` 常量，进的还是池里那个。
- **`new String("admin")`**。一定新建一个对象。参数里的字面量 `"admin"` 本身仍在池里，只是返回的对象不在池里——所以 `c.intern()` 能把池里那个捞回来。
- **运行期造出来的串**。变量参与的 `+`、`StringBuilder.toString()`、`substring()` 都返回新对象，不进池。

字节码里能直接看到这个分界（`javap -c -p Pool`，行尾的箭头是我加的注释）：

```text
  0: ldc           #7   // String admin    ← a
  3: ldc           #7   // String admin    ← b
 10: ldc           #7   // String admin    ← new String 的参数
 16: ldc           #7   // String admin    ← "ad" + "min" 已折叠
 20: ldc           #14  // String ad       ← 变量 part
 26: invokedynamic #16,  0  // InvokeDynamic #0:makeConcatWithConstants:(Ljava/lang/String;)Ljava/lang/String;
```

所以 `==` 的结果取决于「这个引用是从哪来的」：同一份代码换个取值方式就翻脸。比内容用 `equals`，并且把常量写在左边：

```java
if ("admin".equals(role)) { ... }   // role 为 null 时返回 false，不抛
```

但这只保护「右边那个操作数为 null」这一种情况。想先去掉空白再比，`"admin".equals(role.strip())` 在 `role` 为 null 时照样抛 NPE，因为先求值的是 `role.strip()`：

```java
String normalized = role == null ? "" : role.strip();
if ("admin".equals(normalized)) { ... }
```

两边都可能为 null 时用 `java.util.Objects.equals(x, y)`。另外，我原来写成「`s.equals(x)` 在 `x` 为 null 时会抛 NPE」——方向反了。实际是谁调用谁负责：`s` 为 null，`s.equals(x)` 抛；`x` 为 null，`x.equals(s)` 抛。

## `trim()` 与 `strip()`：改的是返回值，不是那个变量

`typed` 是「全角空格 + admin + 全角空格」，全角空格是 U+3000：

```java
String typed = "\u3000admin\u3000";
System.out.println(typed.length());                 // 7
System.out.println(typed.trim().length());          // 7：没去掉
System.out.println(typed.strip().length());         // 5
System.out.println(typed.strip().equals("admin"));  // true
```

`trim()` 确实去空白，但它认的空白是 `<= ' '`（U+0020）的字符，全角空格 U+3000 不在里面，长度还是 7。`strip()` 按 `Character.isWhitespace` 判断，才把它去掉；这是 Java 11 起才有的方法。我原来的猜测是「`trim()` 去掉所有空白」，长度 7 就是反证。

第二个坑是返回值。`String` 的「修改」方法都不改自己：

```java
String input = "  admin  ";
input.trim();
System.out.println("[" + input + "]");   // [  admin  ]
```

`input` 长度还是 9。`trim()` 算出了结果，没人接住就丢了，得写 `input = input.trim();`。`toUpperCase()`、`replace()`、`substring()` 全是这个模式。

「不可变」说的是这个对象的内容不能改，不是变量不能改：变量可以指向另一个对象，原来那个原样待着。换来的好处是可以安全共享，一千个变量指着同一个 `"admin"` 也没人能改它；`hashCode` 在当前 OpenJDK 里算完会存进 `private int hash` 字段（`javap -p java.lang.String` 能看到），当 `HashMap` 的键时省一次计算——后半句是这一版实现的行为，不是 JLS 保证，别拿它做性能承诺。代价是每次「修改」都要复制一份。

## 循环里 `+=`：75 毫秒和 0.96 毫秒

```java
int n = 10000;

long copied = 0;
long startPlus = System.nanoTime();
String result = "";
for (int i = 0; i < n; i++) {
    copied += result.length() + String.valueOf(i).length();
    result += i;
}
long endPlus = System.nanoTime();

long startBuilder = System.nanoTime();
StringBuilder builder = new StringBuilder();
for (int i = 0; i < n; i++) {
    builder.append(i);
}
String built = builder.toString();
long endBuilder = System.nanoTime();

System.out.println("n                    : " + n);
System.out.println("结果长度              : " + result.length());
System.out.println("+ 版累计复制的字符数   : " + copied);
System.out.println("+ 版耗时 ms           : " + (endPlus - startPlus) / 1_000_000.0);
System.out.println("StringBuilder 耗时 ms: " + (endBuilder - startBuilder) / 1_000_000.0);
System.out.println("两版结果一致          : " + result.equals(built));
```

同机跑一次：

```text
n                    : 10000
结果长度              : 38890
+ 版累计复制的字符数   : 189424495
+ 版耗时 ms           : 75.5302
StringBuilder 耗时 ms: 0.96
两版结果一致          : true
```

同一程序又跑两次，`+` 版是 82.58 和 62.38 ms，`StringBuilder` 是 0.92 和 0.86 ms。没预热、没开 GC 日志，这几个数只够说明量级（这里差七十到九十倍），不是基准测试。

为什么是平方级：`result += i` 等于 `result = result + i`，每轮造一个新串、把旧内容整个复制一遍，累计复制的字符数随轮数平方增长，程序自己数出来是 189,424,495 个。我原来写「总量 1+2+…+10000，约 5000 万个字符」——那是按「每轮只追加 1 个字符」估的，而 `i` 从 1 位涨到 4 位，实际差了将近 4 倍。估量级可以，别把估算标成实测。

再看 `+` 编成了什么（`javap -c -p Concat`，类里是 `part = "ad"`、`joined = part + "min"`、`folded = "ad" + "min"`）：

```text
  4: invokedynamic #9,  0   // InvokeDynamic #0:makeConcatWithConstants:(Ljava/lang/String;)Ljava/lang/String;
 10: ldc           #13      // String admin
```

Java 9 起 javac 把 `+` 编成 `invokedynamic` 的 `makeConcatWithConstants`，不再显式 `new StringBuilder`。每轮仍然要新建一个 `String`，平方级代价不变；但「编译器会把 `+` 优化成 `StringBuilder`」是 Java 8 时代的说法，照抄进设计文档就过期了。具体编成什么是 javac 的实现，不是语言保证，我这里用的是 JDK 25。

正确写法：

```java
StringBuilder builder = new StringBuilder();
for (int i = 0; i < 10000; i++) {
    builder.append(i);   // 内部是数组，扩容按倍数复制，均摊下来每次追加接近 O(1)
}
String result = builder.toString();
```

「循环里的拼接一律用 `StringBuilder`」也不够准。慢的不是「在循环里」，是「把结果累积到同一个 `String` 上」：

```java
List<String> ids = new ArrayList<>();
for (int i = 0; i < 10000; i++) {
    ids.add("id-" + i);   // 每轮一个短串，不累积，不构成平方级
}
```

自问一句：这个变量在循环里是不是被自己 `+=`？是，才需要 `StringBuilder`。

## 调用 → 结果

下表每一行的结果都是本机 JDK 25 跑出来的，可以直接对照：

| 调用 | 本机结果 | 该记住的 |
| --- | --- | --- |
| `"a,b,".split(",")` | 长度 2，结尾空串没了 | 默认 limit 为 0，丢掉结尾空串 |
| `"a,b,".split(",", -1)` | 长度 3 | `-1` 保留结尾空串 |
| `"a,,b".split(",")` | 长度 3，中间是个空串 | 只丢结尾的 |
| `" abc ".trim()` | `"abc"` | 只认 `<= ' '` 的字符 |
| `"\u3000admin\u3000".trim()` | 长度 7，原样 | 全角空格 U+3000 不动 |
| `"\u3000admin\u3000".strip()` | 长度 5 | Java 11 起，按 `isWhitespace` |
| `"a.b".replaceAll(".", "")` | 空串 | 第一个参数是正则，`.` 是任意字符 |
| `"a.b".replace(".", "")` | `"ab"` | 按字面替换 |
| `"abc".substring(0, 0)` | 空串 | 右端不含 |
| `Integer.parseInt("42")` | `42` | 非数字抛 `NumberFormatException` |
| `Integer.parseInt(" 42 ")` | 抛 `NumberFormatException` | 不会自动去空白，先 `strip()` |
| `"admin".equals(null)` | `false` | 常量在左边才安全 |
| `String.valueOf(42)` | `"42"` | 转字符串，比 `42 + ""` 表达清楚 |

`parseInt` 抛的 `NumberFormatException` 不是受检异常，编译器不强制你接。用命令行参数做运算时它抛出来就直接终止，怎么接住见第 13 课。

## 跑一遍

下面这段不需要参数，跑一遍就能看到上面几节的结论：

<!-- run -->
```java
public class Main {
    public static void main(String[] args) {
        // 1) 运行期拼出来的串：内容相同，身份不同
        String literal = "admin";
        String role = String.join("", "ad", "min");
        System.out.println("role: " + role);
        System.out.println("role == admin: " + (role == literal));
        System.out.println("role.intern() == admin: " + (role.intern() == literal));
        System.out.println("role.equals(admin): " + role.equals(literal));

        // 2) trim 与 strip 的分界：全角空格 U+3000
        String typed = "\u3000admin\u3000";
        System.out.println("typed.length(): " + typed.length());
        System.out.println("typed.trim().length(): " + typed.trim().length());
        System.out.println("typed.strip().length(): " + typed.strip().length());
        System.out.println("strip 后等于 admin: " + typed.strip().equals(literal));

        // 3) String 的方法返回新串，不改自己
        String greeting = "hi";
        greeting.toUpperCase();
        System.out.println("greeting 仍是: " + greeting);

        // 4) 累积拼接用 StringBuilder
        StringBuilder builder = new StringBuilder();
        for (int i = 0; i < 5; i++) {
            if (i > 0) {
                builder.append('-');
            }
            builder.append(i);
        }
        System.out.println("builder: " + builder);

        // 5) split 与正则
        System.out.println("a,b,.split(\",\").length: " + "a,b,".split(",").length);
        System.out.println("a,b,.split(\",\", -1).length: " + "a,b,".split(",", -1).length);
        System.out.println("a.b.replaceAll(\".\", \"\"): [" + "a.b".replaceAll(".", "") + "]");
        System.out.println("a.b.replace(\".\", \"\"): [" + "a.b".replace(".", "") + "]");
    }
}
```

```text
role: admin
role == admin: false
role.intern() == admin: true
role.equals(admin): true
typed.length(): 7
typed.trim().length(): 7
typed.strip().length(): 5
strip 后等于 admin: true
greeting 仍是: hi
builder: 0-1-2-3-4
a,b,.split(",").length: 2
a,b,.split(",", -1).length: 3
a.b.replaceAll(".", ""): []
a.b.replace(".", ""): [ab]
```

`role` 用 `String.join` 造，和 `args[0]` 属于同一类：运行期创建、不进池，所以 `==` 是 false，`intern()` 之后再比才是 true。7、7、5 三个数就是 `trim` 与 `strip` 的分界。

## 还差的

- `NumberFormatException` 怎么接住（受检还是非受检、try/catch 与 finally 的执行顺序）第 13 课才讲，这篇只到「它会抛」。
- 正则本身没写：`replaceAll` 只演示了第一个参数是正则这一点，分组引用、替换串里 `$` 与 `\` 的转义、`split` 的 limit 语义都留着，第 28 课。
- 计时只有墙钟时间，没有堆占用、没有 GC 数据、也没预热，所以「75 ms 对 0.96 ms」只说明这台机器上的量级；要下结论得用 JMH。
- 编码没碰：`length()` 数的是 UTF-16 code unit，一个 emoji 算 2，本文所有例子都在 BMP 内，代理对与 `codePointCount` 都没验，第 29 课。
- `StringBuilder` 的扩容阈值、`StringBuffer` 的同步开销、几十万个运行期字符串下 `intern()` 是否划算，都没有测；`intern` 的实现还与 JDK 版本有关。
