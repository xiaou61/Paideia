# 26 · 枚举与常量

## 界面上写着「已付款」，`valueOf` 却说没这个常量

订单状态在页面上显示中文。我把显示文案交给 `toString()`，读配置时又想反过来用这段文案找回常量：

<!-- run -->
```java
public class Main {
    enum OrderState {
        PENDING("待付款"),
        PAID("已付款"),
        SHIPPED("已发货");

        private final String label;

        OrderState(String label) {
            this.label = label;
        }

        @Override
        public String toString() {
            return label;
        }
    }

    static void show(String raw) {
        try {
            System.out.println("valueOf(" + raw + ") -> " + OrderState.valueOf(raw).name());
        } catch (RuntimeException e) {
            System.out.println("valueOf(" + raw + ") -> " + e);
        }
    }

    public static void main(String[] args) {
        System.out.println("name() = " + OrderState.PAID.name());
        System.out.println("toString() = " + OrderState.PAID);
        show("PAID");
        show("已付款");
        show("paid");
        show(null);
    }
}
```
```text
name() = PAID
toString() = 已付款
valueOf(PAID) -> PAID
valueOf(已付款) -> java.lang.IllegalArgumentException: No enum constant Main.OrderState.已付款
valueOf(paid) -> java.lang.IllegalArgumentException: No enum constant Main.OrderState.paid
valueOf(null) -> java.lang.NullPointerException: Name is null
```

六行输出里有三个判断，我改代码前猜错了前两个：

- `valueOf` 只查 `name()`，不查 `toString()`。`name()` 在 `java.lang.Enum` 上是 `final` 的（`javap -p java.lang.Enum` 能看到 `public final java.lang.String name();`），`toString()` 才是留给你改的那个。
- 查名字大小写敏感：`paid` 和 `PAID` 是两个不同的字符串，配置里写成小写就读不回来。
- 传 `null` 抛的是 `NullPointerException`（消息 `Name is null`），不是 `IllegalArgumentException`。两类错都塞进同一个 `catch (RuntimeException e)` 时，至少要把消息带出来，否则「没传参数」会被当成「名字写错」。

（本文输出都是本机 `javac 25.0.4` 加 `--release 21` 跑出来的；课程沙箱的编译基线也是 21，见 `scripts/verify_course.py` 里的 `SANDBOX_JAVA_MAJOR`。）

## 常量本身是 `static final` 字段，构造器由编译器调用

把上面那个类编出来，用 `javap -p` 看 `OrderState` 变成了什么（这里摘掉了 `$VALUES` 字段、`$values()` 和 `static {}` 三行）：

```text
final class Main$OrderState extends java.lang.Enum<Main$OrderState> {
  public static final Main$OrderState PENDING;
  public static final Main$OrderState PAID;
  public static final Main$OrderState SHIPPED;
  private final java.lang.String label;
  public static Main$OrderState[] values();
  public static Main$OrderState valueOf(java.lang.String);
  private Main$OrderState(java.lang.String);
  public java.lang.String toString();
}
```

三个常量就是三个 `public static final` 字段，构造器是 `private` 的——源码里我一个修饰符都没写，`javap` 显示的却是 `private`：它读的是字节码里的修饰符，不是从源码猜的。所以外部 `new OrderState("x")` 不可能编过：实例只在类初始化时由编译器创建，你要的几个值就是全部的值。

想在构造器前面加 `public` 会直接编译失败：

```text
Main.java:9: error: modifier public not allowed here
        public OrderState(String label) {
               ^
1 error
```

`values()` 和 `valueOf(String)` 也是编译器给每个枚举单独生成的静态方法，不属于 `java.lang.Enum`（那里只有一个双参数的 `public static <T extends Enum<T>> T valueOf(Class<T>, String)`）。所以把变量声明成 `Enum<?>` 之后，连 `values()` 都调不到：

```java
public class Main {
    enum OrderState { PENDING, PAID }

    public static void main(String[] args) {
        Enum<?> e = OrderState.PAID;
        System.out.println(e.values().length);
    }
}
```
```text
Main.java:6: error: cannot find symbol
        System.out.println(e.values().length);
                            ^
  symbol:   method values()
  location: variable e of type Enum<?>
1 error
```

因为这些常量是单例（`private` 构造器 + 每个常量一个静态字段），身份判断和顺序操作的结果很固定：

<!-- run -->
```java
import java.util.Arrays;

public class Main {
    enum OrderState { PENDING, PAID, SHIPPED, CANCELLED }

    public static void main(String[] args) {
        System.out.println("==: " + (OrderState.PAID == OrderState.valueOf("PAID")));
        System.out.println("equals: " + OrderState.PAID.equals(OrderState.valueOf("PAID")));
        System.out.println("compareTo: " + OrderState.SHIPPED.compareTo(OrderState.PENDING));
        System.out.println("values: " + Arrays.toString(OrderState.values()));
        System.out.println("ordinal: " + OrderState.CANCELLED.ordinal());
    }
}
```
```text
==: true
equals: true
compareTo: 2
values: [PENDING, PAID, SHIPPED, CANCELLED]
ordinal: 3
```

`Enum.equals` 是 `final` 的 `this == other`，所以 `==` 和 `equals` 的结论永远一样，`==` 还少一层空指针风险。`compareTo` 返回的是两个 `ordinal()` 相减，`values()` 是声明顺序——这两条只对「位置」负责，对业务优先级一无所知。

## 存数据库：`name()` 读得回来，`ordinal()` 会错位

| 想做的事 | 写法 | 实测结果 |
| --- | --- | --- |
| 判断两个常量是不是同一个 | `a == b` | `true`；`Enum.equals` 是 `final` 的 `this == other`，两种写法结论永远一致 |
| 按名字反查 | `OrderState.valueOf("PAID")` | 拿到 `PAID`；大小写敏感；传 `null` 抛 `NullPointerException` |
| 按页面文案反查 | `OrderState.valueOf("已付款")` | `IllegalArgumentException: No enum constant ...`，名字只认 `name()` |
| 比大小 | `SHIPPED.compareTo(PENDING)` | `2`，等于两个 `ordinal()` 相减，与业务优先级无关 |
| 取全部常量 | `OrderState.values()` | `[PENDING, PAID, SHIPPED]`，按声明顺序 |
| 存进数据库 | `ordinal()` | 声明顺序一变，旧数字就指向别的状态，而且不报错 |
| 存进数据库 | `name()` 或自定义 `code` | 顺序变了也读得回；常量改名会断 |

`ordinal()` 和 `compareTo` 都直接绑定声明位置，拿它们做持久化或排序依据，等于把「代码里的第几行」写进了数据。同一个下标，两版各编译一次：

```java
// v1: enum OrderState { PENDING, PAID, SHIPPED }
System.out.println(OrderState.values()[1].name());   // PAID

// v2: enum OrderState { PENDING, CANCELLED, PAID, SHIPPED }
System.out.println(OrderState.values()[1].name());   // CANCELLED
```

没有异常，没有警告，只有数据含义变了。所以这一列存 `name()`。如果连常量改名都不能影响数据（外部协议、跨服务对接），再加自己的 `code`，让数字和声明顺序彻底脱钩：

```java
enum OrderState {
    PENDING(10), PAID(20), SHIPPED(30);

    private final int code;

    OrderState(int code) {
        this.code = code;
    }

    int code() {
        return code;
    }

    static OrderState fromCode(int code) {
        for (OrderState s : OrderState.values()) {
            if (s.code == code) {
                return s;
            }
        }
        throw new IllegalArgumentException("unknown code " + code);
    }
}
```

中间插常量、重排都不影响已经存下的 `code`。代价是同一个语义维护两份，所以能存 `name()` 就别加 `code`。

## 加一个常量，`switch` 不报错，悄悄返回 null

<!-- run -->
```java
public class Main {
    enum OrderState { PENDING, PAID, SHIPPED, CANCELLED }

    static String label(OrderState s) {
        String text = null;
        switch (s) {
            case PENDING -> text = "等付款";
            case PAID -> text = "可以发货";
            case SHIPPED -> text = "已发出";
        }
        return text;
    }

    public static void main(String[] args) {
        for (OrderState s : OrderState.values()) {
            System.out.println(s + ": " + label(s));
        }
    }
}
```
```text
PENDING: 等付款
PAID: 可以发货
SHIPPED: 已发出
CANCELLED: null
```

`CANCELLED` 那一行就是 bug：`switch` 语句不要求覆盖全部常量，漏一个分支是合法代码，什么也不做，`text` 保持初始的 `null`，一路传到页面上——已付款显示正常，新状态显示空白。往枚举里加一个状态时不会有任何提示。

两种改法，选一个：

1. 初始值不要 `null`，改成 `throw new IllegalStateException("unhandled state: " + s)`，漏掉的分支立刻在运行时炸出来；
2. 把 `switch` 写成表达式（`return switch (s) { ... };`），漏常量是编译错误：`error: the switch expression does not cover all possible input values`。这种写法第 33 课细讲。

顺带纠正一句常被说反的话：编译器替你检查穷尽性，靠的是「`switch` 表达式」，不是「`switch` 语句」。语句漏分支只会在运行时表现为「什么都没发生」，不会编译报错。

## 还差的

- 只在 JDK 25.0.4 加 `--release 21` 上跑过。课程沙箱脚本编译时不带 `--release`，直接用本机 `javac`；JDK 25 下这条路径本文没单独验。
- 没连真数据库。`ordinal()` 错位是构造两版枚举、各编译一次跑出来的结果，不是线上回滚案例。
- 没测跨 `ClassLoader` 的场景：同一个枚举被两个加载器各加载一次时，两边的常量是不同的对象，`==` 会是 `false`（`equals` 也一样，它就是 `==`）。这个边界本文只推理，没实测。
- `EnumSet` / `EnumMap` 没讲。需要「一组状态」或「以枚举为键查表」时它们才是标准做法，等有具体用例再补。
- 反射能不能造出枚举实例没验，留到第 27 课注解与反射一起试。
