# 24 · 枚举与常量

## 这一课你要会

- 用 `enum` 表达"只有这几种"的值，而不是散落的 `String` 或 `int` 常量；
- 给枚举加字段、构造器与方法；
- 说清 `==`、`values()`、`valueOf()` 在枚举上怎么用；
- 知道 `ordinal()` 为什么不能存进数据库。

## 为什么

假设订单状态只有"待付款 / 已付款 / 已发货"三种。用字符串表示，方法签名是 `void ship(String status)`，那么调用的人可以传 `"已付宽"`（拼错）、`"已取消"`（不存在）、或者 `null`。编译器一个都挡不住，错误要等运行到某个分支才暴露。

枚举把可选值收成一个**类型**：参数写成 `Status`，编译器就只允许传那三个常量，拼错直接编译不过。它还能带字段和方法，把"状态 → 能不能发货"这种规则写在值自己身上，而不是散落在 `if` 里。

## 讲解

### 枚举是类，不是三个整数

```text
enum Status { UNPAID, PAID, SHIPPED }
```

括号里的每一项都是一个**单例对象**：整个程序里 `Status.PAID` 只有一个实例。所以：

- 用 `==` 比较是对的，而且比 `equals` 更直接（不会空指针）；
- 不能 `new Status()`；
- 可以给枚举加字段、构造器、普通方法，甚至实现接口。

`values()` 返回全部常量（按定义顺序），`valueOf("PAID")` 把名字转回常量，名字**大小写敏感**，找不到会抛 `IllegalArgumentException`——不是返回 `null`。

### 带字段与方法的枚举

"等级越高权重越大"这种映射，最合适的写法是让每个常量自己带权重：

<!-- run -->
```java
public class Main {
    enum Level {
        LOW(1), MEDIUM(2), HIGH(3);

        private final int weight;

        Level(int weight) {
            this.weight = weight;
        }

        int weight() {
            return weight;
        }

        boolean atLeast(Level other) {
            return weight >= other.weight;
        }
    }

    public static void main(String[] args) {
        Level a = Level.LOW;
        Level b = Level.HIGH;

        System.out.println(a + "=" + a.weight());
        System.out.println(b.atLeast(a));
        System.out.println(a.atLeast(b));
        System.out.println(Level.valueOf("MEDIUM").weight());
        System.out.println(Level.values().length);
    }
}
```
```text
LOW=1
true
false
2
3
```

要点：

- 枚举的构造器**只能是 private（或包级私有）**，写 `public` 编译不过——常量是编译器替你创建的，不该由外部 `new`；
- 每个常量后面的 `(1)`、`(2)` 就是在调构造器；
- `toString()` 默认返回常量名，所以 `System.out.println(a)` 打印 `LOW`。

### `switch` 是枚举最顺手的用法

```text
switch (status) {
    case UNPAID -> System.out.println("等付款");
    case PAID -> System.out.println("可以发货");
    case SHIPPED -> System.out.println("已发出");
}
```

箭头写法不穿透，也不需要 `break`（第 33 课细讲）。枚举还有一个好处：**少写一个分支，编译器可能直接报错**（`switch` 表达式要求覆盖全部常量），漏处理的状态不会悄悄走 `default`。

### `ordinal()` 是位置，不是身份

`ordinal()` 返回常量在 `enum` 里的下标：`UNPAID` 是 0、`PAID` 是 1。看起来很适合存数据库，**但不要这么做**。哪天有人在中间插了一个 `CANCELLED`，所有旧数据的含义就整体错位了——而且没有任何报错。

要持久化，存 `name()`（`"PAID"`）或者自己定义的 `code` 字段。名字是稳定的标识，顺序不是。

## 常见误区

### 误区：枚举就是几个 `static final int` 的语法糖

**你以为**：它只是省得写常量，没有额外能力。
**其实**：枚举是完整的类，可以带字段、方法、实现接口，还能被 `switch` 做穷尽性检查。`static final int` 做不到"只能传这几个值"。

### 误区：`valueOf` 找不到会返回 `null`

**你以为**：像 `Map.get` 一样，没有就返回空，判一下就行。
**其实**：它抛 `IllegalArgumentException`。外部输入（配置、请求参数）转枚举时，要么先校验，要么接住异常给出人话提示。

### 误区：`ordinal()` 可以安全地当数字存起来

**你以为**：0、1、2 就是固定的编号。
**其实**：它只是"定义在第几位"。重排或插入常量后，旧数据的 1 可能已经变成另一个状态了。存 `name()` 或自定义 `code`。

## 小结

枚举是"封闭集合"的表达方式：只有这几个值，编译器替你把住入口。它可以带字段和方法，`==` 比较是惯用法，`valueOf` 大小写敏感且会抛异常，`ordinal` 只表示位置、不要持久化。
