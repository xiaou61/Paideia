# 03 · 循环

## 1、2、3，没有 4

```python
for i in range(1, 4):
    print(i)
```
```text
1
2
3
```

我原来以为 `range(1, 4)` 会数到 4。实际最后一个是 3：**右端不包含**。

换一个起点和步长，右端仍然不包含：

| 写法 | 实际产出 |
| --- | --- |
| `range(3)` | `0, 1, 2` |
| `range(1, 4)` | `1, 2, 3` |
| `range(0, 10, 3)` | `0, 3, 6, 9` |

`range(0, 10, 3)` 从 0 开始，每次加 3，到 9 为止；10 不取。记住「左闭右开」，第 05 课的切片也用同一套边界。下面的输出都在本机 CPython 3.11.5 上跑过。

## 条件一次都不成立，循环体一次也不跑

再看一个更容易猜反的：

```python
countdown = 0
while countdown > 0:
    print('body')
print('loop skipped, program continues')
```
```text
loop skipped, program continues
```

`countdown > 0` 一开始就是假，所以 `while` 的循环体一次都没执行，程序直接走到下一行。**条件永远不成立不会卡死**，它只是跳过。

真正会卡死的是另一种：条件一直成立，循环体里又没有让它变假的动作，也没有 `break`。

```python
n = 3
while n > 0:
    print(n)
```
```text
3
3
3
3
3
3
```

上面只截了前 6 行；后面还是 3。我在终端里按了 Ctrl+C，解释器才停下来，打印 `KeyboardInterrupt`。原因是循环体里只有 `print(n)`，没有任何一行改变 `n`；`n > 0` 永远为真。

所以写 `while` 时先问一句：**哪个动作会让条件最终变假？** 上面的例子缺的就是 `n = n - 1`。没有这个动作，也没有 `break`，条件再简单也会变成死循环。

## for 和 while 怎么选

- 次数确定，或者有一串值要逐个处理：用 `for`。例如 `range(1, 4)`、`range(0, 10, 3)`。
- 次数不确定，靠条件停：用 `while`。例如倒计时到 0、等某个条件成立。

倒计时是 `while` 的典型写法：

```python
countdown = 3
while countdown > 0:
    print(countdown)
    countdown = countdown - 1
print('结束')
```
```text
3
2
1
结束
```

`countdown = countdown - 1` 每轮都把条件往假的方向推一步。没有它，就是上一节的死循环。

`continue` 放进 `while` 时也要看这一点：如果 `continue` 跳过了让条件变小的那条语句，循环同样停不下来。

## break 和 continue

| 语句 | 作用 | 本轮剩下的语句 |
| --- | --- | --- |
| `break` | 立刻结束整个循环 | 不执行 |
| `continue` | 结束本轮，进入下一轮 | 不执行 |

先看 `continue`：

```python
for i in range(1, 6):
    if i == 3:
        continue
    print(i)
print('跳过 3')
```
```text
1
2
4
5
跳过 3
```

`i == 3` 时，`continue` 把本轮剩下的 `print(i)` 跳过去，直接进入 `i == 4`。

`break` 则是整个循环都不再继续：

```python
for number in range(1, 6):
    if number > 2:
        print('第一个大于 2 的是', number)
        break
```
```text
第一个大于 2 的是 3
```

找到 3 就退出，后面的 4、5 不会再检查。

### 不用 break 的 flag 写法

下面这段用 `found` 记住「已经遇到 3」。它也能打印 1、2：

```python
found = False
for i in range(1, 5):
    if i == 3:
        found = True
    if not found:
        print(i)
```
```text
1
2
```

flag 版是 6 行。循环遇到 3 之后并没有退出，只是从那一刻起不再打印；它还会把 4 走完，每轮都要再看一次 `found`。同样的结果用 `break` 是 4 行：

```python
for i in range(1, 5):
    if i == 3:
        break
    print(i)
```
```text
1
2
```

这就是一组 6 行对 4 行的前后对照：flag 版要额外维护 `found`，`break` 版把「遇到 3 就停」直接写出来。flag 适合「循环结束后还要知道有没有找到」；如果只是「遇到就停」，`break` 更直接。

### 用 if 包住剩余语句，还是用 continue

不想让某条路径执行后面的语句，可以把剩余语句整段包进 `if`。下面两段输出完全一样，`continue` 版多一行控制语句：

```python
for i in range(1, 5):
    if i % 2 == 0:
        print(i)
        print('偶数')
print('结束')
```
```text
2
偶数
4
偶数
结束
```

```python
for i in range(1, 5):
    if i % 2 != 0:
        continue
    print(i)
    print('偶数')
print('结束')
```
```text
2
偶数
4
偶数
结束
```

第一种把「偶数时才做」写成 `if` 包住两行；第二种先排除奇数，再让后面的两行默认执行。剩余语句只有一两行时，`if` 更好读；剩余语句很长、缩进会堆很多层时，`continue` 能把它们拉回一层。两种都对，选让读者少往回翻的那种。

## 边遍历边删，-2 会被跳过

列表第 05 课讲。这里先照抄三件事：`numbers = [-1, -2, 3]` 是一个列表，`numbers.remove(x)` 删掉第一个等于 `x` 的元素，`numbers[index]` 按下标取元素；下标从 0 开始。你只需要看下面下标怎么走。

```python
numbers = [-1, -2, 3]
for number in numbers:
    if number < 0:
        numbers.remove(number)
print(numbers)
```
```text
[-2, 3]
```

两个负数，只删掉了 `-1`。`-2` 留下来了，而且没有报错。

在 CPython 3.11.5 里，列表迭代器按位置往后走，也就是「索引推进」；删除会让「元素前移」：

1. 先看下标 0，值是 `-1`，删掉。列表变成 `[-2, 3]`。
2. 迭代器接着看下标 1，此时下标 1 是 `3`；`-2` 已经前移到下标 0，不会再被检查。索引走到 1，元素却已经前移到 0，两个动作错开了。

```sketch

      { "id": "before", "title": "[-1, -2, 3]", "sub": "下标 0 是 -1，删掉", "tone": "gray" }

  ],
  "arrows": [
    { "from": "before", "to": "after", "label": "删下标 0" },
    { "from": "after", "to": "missed", "label": "下一个下标 1 是 3" }
  ]

```

这是 CPython 3.11.5 的实测行为；语言层面不保证你边遍历边改列表时会怎样，所以正确做法是别这么写。

正确写法：不要一边遍历一边删，改成手动控制下标。删了元素就不要加 `index`，因为下一个元素已经移到当前位置；没删才加：

```python
numbers = [-1, -2, 3]
index = 0
while index < len(numbers):
    if numbers[index] < 0:
        del numbers[index]
    else:
        index = index + 1
print(numbers)
```
```text
[3]
```

如果只是想留下非负数，也可以新建一个列表，或者遍历副本；前者要等第 05 课讲列表的 `append`，后者要等第 05 课讲切片 `numbers[:]`。这一课先把「下标什么时候前进」讲清楚。

那 `for i in range(len(items))` 呢？需要下标时它是对的方向，但**在循环里删元素时也不安全**：

```python
numbers = [-1, -2, 3]
for index in range(len(numbers)):
    if numbers[index] < 0:
        del numbers[index]
print(numbers)
```
```text
IndexError: list index out of range
```

`range(len(numbers))` 在循环开始时就已经把终点定成 3。删掉两个元素后列表只剩一个，下标 2 就不存在了。前面实际上还有一段 `Traceback`，最后一行是上面这个。不是 `range` 算错了，是循环体改变了列表长度。

只读元素时，直接 `for number in numbers:` 最省事；需要位置、又要边删边改时，用 `while` 手动控制下标，或者换成一个新列表。不要用「先拿长度、再从头删」这种写法。

## 缩进不是排版

Python 用缩进表示「哪些语句属于同一个块」。但「少一格一定报错」是错的。下面这段循环体只有一条语句，用了 3 个空格，照样能跑：

```python
for i in range(1, 4):
   print(i)
```
```text
1
2
3
```

3 个空格能跑，不代表应该这么写。这里真正会报错的是同一个块里的缩进不一致。比如第一行 4 个空格、第二行 3 个空格，最后一行是：

```python
for i in range(1, 4):
    print('第一行')
   print('第二行')
```
```text
IndentationError: unindent does not match any outer indentation level
```

反过来，把第二行退到最左边，不会报错，但它的身份变了：它不再属于循环体，循环结束后只执行一次：

```python
for i in range(1, 4):
    print('循环内')
print('循环外')
```
```text
循环内
循环内
循环内
循环外
```

Tab 和空格混在同一个块里，还可能得到：

```text
TabError: inconsistent use of tabs and spaces in indentation
```

所以不要靠「少缩进一格看它报不报错」来检查。统一用 4 个空格，编辑器里把 Tab 设成插入 4 个空格；要检查的是同一块里的两行有没有对齐。

## 还差的

- 列表的 `remove`、`del` 和下标规则第 05 课才系统讲；这一课只用了复现漏删所需的最小部分。
- 这一课没讲切片复制（第 05 课）、列表推导式（第 18 课），也没讲 `enumerate`、`zip` 这类带下标的遍历工具。需要下标时这一课只用了 `range(len(...))` 和手动 `while`。
- 没讲嵌套循环里 `break` 只退出最近一层，也没讲怎么跳出多层循环。
- 没做性能测试；`while` 手动下标和 `for` 直接遍历在真实数据上差多少，这一课没有数字。
