# 18 · 小项目

## 这一课你要会

- 把一个脚本拆成"数据层 / 逻辑层 / 入口"，知道为什么这么拆；
- 建虚拟环境并理解它解决的问题；
- 给纯逻辑写第一个 `assert` 测试，并让它在出错时红。

## 为什么

前十一课都是"一个文件跑一段"。真实项目不是这样：它要能装依赖、能被人接手、能在改动后确认没坏。

这一课不教你新语法，只教**把已有的东西摆好**。学完你应该能自己写一个"读文件 → 处理 → 写文件"的完整小工具，并且敢改它。

## 讲解

### 分三层

```text
todo/
  storage.py    读写数据（只有它碰文件）
  service.py    业务规则（纯函数，不碰文件）
  main.py       入口（解析参数、调前两层、打印结果）
```

为什么这么拆：

- **`service.py` 是纯的**：给它一组数据，它返回结果，不碰文件、不打印。所以能直接测。
- **`storage.py` 只负责"从哪来、到哪去"**。以后换成数据库只改这里。
- **`main.py` 最薄**：只做参数解析与串接。

一开始会觉得"一个脚本就够，为什么要三个文件"。等到你要改"存到数据库"，或者想测"排序对不对"，就知道这层拆分省了什么。

### 虚拟环境

不同项目依赖的包版本会冲突。虚拟环境给每个项目一个独立的包目录：

```text
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate
pip install requests
pip freeze > requirements.txt
```

**为什么必须用**：不用的结果是全局包版本被多个项目互相覆盖，最后谁也跑不起来。

### 第一个测试

```text
def test_filter_keeps_only_unfinished():
    items = [{"title": "a", "done": False}, {"title": "b", "done": True}]
    assert [item["title"] for item in filter_unfinished(items)] == ["a"]
```

`assert` 失败时 Python 直接抛 `AssertionError`。测试框架（pytest / unittest）做的事就是在每个测试里跑这些断言，汇总结果。

不必一开始就用 pytest：把 `assert` 写在一个 `if __name__ == "__main__":` 块里也能验证。**关键是有断言，而不是"我看了一眼输出是对的"**。

### 一个完整的小例子

下面把三层压成一个文件，但仍然能看出边界：`filter_unfinished` 是纯函数，`run` 负责输入输出，`__main__` 只负责调。

<!-- run -->
```python
def filter_unfinished(items):
    return [item for item in items if not item["done"]]


def summarize(items):
    total = len(items)
    done = sum(1 for item in items if item["done"])
    return f"{done}/{total} 已完成"


def run(raw_items):
    remaining = filter_unfinished(raw_items)
    print(summarize(raw_items))
    for item in remaining:
        print("- " + item["title"])


items = [
    {"title": "写地址解析", "done": True},
    {"title": "补单元测试", "done": False},
    {"title": "写 README", "done": False},
]

run(items)

assert [item["title"] for item in filter_unfinished(items)] == ["补单元测试", "写 README"]
assert summarize([]) == "0/0 已完成"
print("断言全部通过")
```
```text
1/3 已完成
- 补单元测试
- 写 README
断言全部通过
```

## 常见误区

### 误区：小项目不用拆文件，一个脚本就行

**你以为**：拆文件是"大项目才需要"的讲究。
**其实**：拆的不是规模，是**边界**。规模小的时候边界更清楚，正是练手的时候。

### 误区：虚拟环境会让程序更稳定

**你以为**：装了 venv 就不会出依赖问题。
**其实**：它只做隔离。依赖是否会崩取决于版本是否兼容——所以还要 `requirements.txt` 锁住版本。

### 误区：测试就是打印出来看一眼

**你以为**：跑一遍看输出对就行。
**其实**：那不是测试，是手工检查。断言能让你在改了十行之后立刻知道坏没坏。

## 小结

三层：纯逻辑、存储、入口。用 venv 隔离依赖。测试的本质是断言，不是眼睛。

到这里十二课就完了。你还不会写大型系统，但已经能把一个想法变成能跑、能改、能验证的小工具——这已经是多数人学编程真正想达到的位置。

下一步建议：找一个自己会用的小工具（批量改名、整理文件、统计文本），从头写一遍。**写不完也没关系，卡住的地方就是下一个要补的知识点。**
