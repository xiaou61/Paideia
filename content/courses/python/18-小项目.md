# 18 · 小项目

## `import todo`，先打印了三行

最初的 `todo.py` 长这样：

```python
def filter_unfinished(items):
    return [item for item in items if not item["done"]]


def summarize(items):
    total = len(items)
    done = sum(1 for item in items if item["done"])
    return f"{done}/{total} 已完成"


def run(raw_items):
    remaining = filter_unfinished(raw_items)
    print(summarize(raw_items))
    for item in remaining:
        print("- " + item["title"])


items = [
    {"title": "写地址解析", "done": True},
    {"title": "补单元测试", "done": False},
    {"title": "写 README", "done": False},
]

run(items)

assert [item["title"] for item in filter_unfinished(items)] == ["补单元测试", "写 README"]
assert summarize([]) == "0/0 已完成"
print("断言全部通过")
```

我只想拿 `filter_unfinished`，在同一个目录里 import：

```text
PS> python -c "import todo"
1/3 已完成
- 补单元测试
- 写 README
断言全部通过
```

我以为 `import` 只把函数名拿过来；它把整个 demo 跑了一遍，还替我做了断言。

第二件事更直接。我把 `main.py` 单独放到另一个目录，`cd` 过去再跑（路径我省成 `...`）：

```text
PS> python main.py
Traceback (most recent call last):
  File "...\main.py", line 1, in <module>
    import storage
ModuleNotFoundError: No module named 'storage'
```

我以为把 `main.py` 拷到哪都能跑；它只在自己的目录里找得到 `storage.py`。

两件事都不在业务逻辑里：一件是 import 时执行了模块顶层的入口代码，另一件是文件边界没摆好，`main.py` 去找一个不在它旁边的 `storage.py`。前十七课的主线都是把一个脚本跑通；这一课把文件摆成一个能 import、能跑、能存盘的小项目。

## 入口：只让直接运行的那一次干活

`import` 不是「只把函数名拿过来」。第 12 课已经验证过：它会执行模块顶层的每一行。上面 `run(items)`、两个 `assert` 和 `print` 都在顶层，所以 import 一次就全跑一次。

把入口缩进到守卫里：

```python
# todo.py（末尾）
if __name__ == "__main__":
    items = [
        {"title": "写地址解析", "done": True},
        {"title": "补单元测试", "done": False},
        {"title": "写 README", "done": False},
    ]

    run(items)

    assert [item["title"] for item in filter_unfinished(items)] == ["补单元测试", "写 README"]
    assert summarize([]) == "0/0 已完成"
    print("断言全部通过")
```

再试：

```text
PS> python -c "import todo; print('import 结束')"
import 结束
PS> python todo.py
1/3 已完成
- 补单元测试
- 写 README
断言全部通过
```

import 那一行没有报表了。守卫保护的是缩进内的入口代码；函数定义和常量仍在顶层执行，否则你 import 不到它们。这是第 12 课说的 import 副作用，不是新规则。

## service.py：只收列表，不碰文件

`service.py` 只做业务判断：

```python
def filter_unfinished(items):
    return [item for item in items if not item["done"]]


def summarize(items):
    total = len(items)
    done = sum(1 for item in items if item["done"])
    return f"{done}/{total} 已完成"
```

它不 `open`、不 `print`、不读命令行。给它一个列表，它返回另一个列表或一个字符串。这样测试时不用造文件，也不用清空数据库。

`assert` 只有一条规则：后面的表达式为假，就抛 `AssertionError`；为真，什么都不打印。它不是给人看的日志，是让程序自己判对错。

`[item["title"] for item in filter_unfinished(items)]` 是列表推导式：对筛选后的每个 `item` 取 `title`，拼成新列表。把它和 `["补单元测试"]` 比，比逐行 print 更容易看出差在哪。

测试文件长这样：

```python
from service import filter_unfinished, summarize


def test_filter_keeps_only_unfinished():
    items = [
        {"title": "写地址解析", "done": True},
        {"title": "补单元测试", "done": False},
    ]
    assert [item["title"] for item in filter_unfinished(items)] == ["补单元测试"]


def test_summary_counts_empty_list():
    assert summarize([]) == "0/0 已完成"


if __name__ == "__main__":
    test_filter_keeps_only_unfinished()
    test_summary_counts_empty_list()
    print("2 passed")
```

为了确认测试真的会红，我先把 `service.py` 里的 `not` 删掉，在 Python 3.11.5 / Windows 上跑 `python test_service.py`：

```text
Traceback (most recent call last):
  File "...\test_service.py", line 17, in <module>
    test_filter_keeps_only_unfinished()
  File "...\test_service.py", line 9, in test_filter_keeps_only_unfinished
    assert [item["title"] for item in filter_unfinished(items)] == ["补单元测试"]
           ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
AssertionError
```

路径是临时目录，我省成了 `...`；行号和断言内容没动。

**测试函数定义了不等于跑了。** `def test_...` 只是把函数挂到名字上，Python 不会自动调用。必须有人在 `if __name__ == "__main__":` 里调用，或者由 pytest 收集。上面这版至少保证直接运行时会真的执行两条断言。

把 `not` 加回来，再跑同一份测试，输出只有一行：

## storage.py：只有这个文件碰 `open`

现在把文件放进同一个目录：

```text
todo/
  data/tasks.json
  service.py       纯函数
  storage.py       只有它碰文件
  main.py          入口
  test_service.py
```

`storage.py` 负责「数据从哪来、到哪去」。本课用 JSON，两个函数：

```python
import json
from pathlib import Path

DATA_FILE = Path(__file__).parent / "data" / "tasks.json"


def load_tasks():
    if not DATA_FILE.exists():
        return []
    with open(DATA_FILE, encoding="utf-8") as file:
        return json.load(file)


def save_tasks(tasks):
    DATA_FILE.parent.mkdir(exist_ok=True)
    with open(DATA_FILE, "w", encoding="utf-8") as file:
        json.dump(tasks, file, ensure_ascii=False, indent=2)
```

`Path(__file__).parent` 把路径钉在 `storage.py` 旁边，不钉在你敲命令时所在的目录。第 8 课说过相对路径相对的是当前工作目录；这里用 `__file__` 避免那个坑。

`load_tasks` 在文件不存在时返回空列表，第一次运行不会因为 `tasks.json` 还没建就崩。`save_tasks` 用 `"w"` 重写整个文件——JSON 是一个整体，不能像日志那样追加；代价是它没有并发保护，两个进程同时写会互相覆盖，这一点放在「还差的」。

数据长这样：

```json
[
  {"title": "写地址解析", "done": true},
  {"title": "补单元测试", "done": false},
  {"title": "写 README", "done": false}
]
```

## main.py：取数据、调纯函数、交回 storage

依赖方向是 `main` 同时依赖两边，`service` 不依赖 `storage`：

```sketch
{
  "title": "main 同时依赖 service 和 storage",
  "rows": [
    [
      { "id": "main", "title": "main.py", "sub": "取数据、调用、保存", "tone": "gray" }
    ],
    [
      { "id": "svc", "title": "service.py", "sub": "纯函数，不碰文件", "tone": "green" },
      { "id": "sto", "title": "storage.py", "sub": "load / save JSON", "tone": "blue" }
    ]
  ],
  "arrows": [
    { "from": "main", "to": "svc", "label": "传列表" },
    { "from": "main", "to": "sto", "label": "读 / 存" }
  ]
}
```

`main.py` 同时 import 两边；`service.py` 不 import `storage`，`storage.py` 也不 import `service`。

`main` 先从 `storage.load_tasks()` 取数据，把列表交给 `service.filter_unfinished` / `summarize`，最后把改过的 `tasks` 交回 `storage.save_tasks()`。

```python
import service
import storage


def main():
    tasks = storage.load_tasks()
    left = service.filter_unfinished(tasks)

    print(service.summarize(tasks))
    for task in left:
        print(f"- {task['title']}")

    if not left:
        print("没有未完成的任务")
        return

    left[0]["done"] = True
    storage.save_tasks(tasks)
    print(f"已把「{left[0]['title']}」标成完成")
    print(service.summarize(tasks))


if __name__ == "__main__":
    main()
```

`left` 里的 dict 和 `tasks` 里的是同一批对象，改 `left[0]["done"]` 就是改 `tasks`，所以 `save_tasks` 写回去的是改过的列表。第一次跑：

```text
PS> python main.py
1/3 已完成
- 补单元测试
- 写 README
已把「补单元测试」标成完成
2/3 已完成
```

再跑一次：

```text
PS> python main.py
2/3 已完成
- 写 README
已把「写 README」标成完成
3/3 已完成
```

第三次就没有未完成了。这个「每次标一条」是玩具行为，不是通用待办工具；它存在的目的只是让 `save_tasks` 真的被调用，而不是只展示一个没接上的函数。

`main.py` 的入口也在守卫里：

```text
PS> python -c "import main; print('import 结束')"
import 结束
```

没有报表，也没有改文件。把 `main.py`、`service.py`、`storage.py` 放在同一个目录，从上一层跑 `python todo\main.py` 也能工作，因为 Python 把脚本所在目录放进 `sys.path`，而数据路径用 `__file__` 钉住了。开头那个 `ModuleNotFoundError` 的修法不是 `sys.path.append`，是别把 `main.py` 单独拷走。

## 虚拟环境：命令要跟 shell 对上

第 12 课已经建过 `.venv`，这里只补一个最容易抄错的点：PowerShell 里不能照抄 `.venv\Scripts\activate` 这个不带扩展名的写法。

```text
python -m venv .venv

# PowerShell
.\.venv\Scripts\Activate.ps1

# cmd.exe
.venv\Scripts\activate.bat
```

PowerShell 被执行策略挡住时，报错会写 `... cannot be loaded because running scripts is disabled on this system`。只对当前窗口放开：

```text
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

`.venv\Scripts\activate` 不会把 `VIRTUAL_ENV` 设到当前 PowerShell 会话；后面的 `pip install` 仍然装进全局 Python。这就是「看起来没报错，实际没生效」的那类坑。

生效后提示符前面会出现 `(.venv)`。提示符只是提示，确认解释器是哪一只：

```text
PS> python -c "import sys; print(sys.executable)"
C:\...\todo\.venv\Scripts\python.exe
```

不想激活也行，直接用 venv 里的解释器：

```text
.\.venv\Scripts\python.exe -m pip install 包名
.\.venv\Scripts\python.exe main.py
```

本课的项目只用到 `json` 和 `pathlib` 这两个标准库模块，所以没有要装的包，也不需要 `requirements.txt`。等你真的 import 了第三方包，再考虑依赖文件。`requirements.txt` 只写项目真正 import 的第三方包；没 import 的包不要写。`pip freeze` 会把当前环境里安装的包（包括传递依赖）都列出来，在干净的 venv 里可以当起点，但它不是「项目 import 了什么」的精确清单。

## 还差的

- `main.py` 没有命令行参数，只能按顺序标完成；要按标题标某一条，得加 `sys.argv` 或 `argparse`。
- `load_tasks` 遇到坏 JSON 会直接抛 `JSONDecodeError`，没有提示是哪一行、也没有备份。
- `save_tasks` 直接覆盖整个文件，两个进程同时写会丢更新；真要多人用，需要临时文件加原子替换或文件锁。
- 测试只覆盖了 `service.py` 的两个纯函数；`storage.py` 的读写在临时目录里还没测，`main.py` 的串接也没测。
- 没有 pytest 配置、没有覆盖率、没有打包；现在靠 `python test_service.py` 手动跑。
- 只支持本地 JSON；换 SQLite 或数据库要重写 `storage.py`，但 `service.py` 不用动——这正是分层想换来的东西。
