# 15 · 装饰器

## 这一课你要会

- 解释"函数也是对象"，并把它当参数传、当返回值用；
- 写一个最小装饰器，理解它相当于 `fn = wrapper(fn)`；
- 用 `*args, **kwargs` 让装饰器不破坏原函数的签名；
- 用 `functools.wraps` 保住原函数的名字，并知道不保住会坏什么；
- 看懂带参数的装饰器（三层函数）。

## 为什么

装饰器是框架里最密集出现的语法：Flask 的 `@app.route`、pytest 的 `@pytest.fixture`、FastAPI 的依赖注入、Django 的 `@login_required`，全是它。

它解决一个具体问题：**想给很多函数加同一段前后逻辑（计时、日志、鉴权、重试），但不想在每个函数里复制**。装饰器让你写一次，然后一行 `@xxx` 套上去。

## 讲解

### 函数是对象

```python
def greet(name):
    return f"hi {name}"

say = greet          # 不加括号：把函数本身赋给变量
print(say("小明"))   # hi 小明
print(greet)         # <function greet at 0x...>
```

函数可以赋给变量、放进列表、当参数传、当返回值。这就是装饰器成立的全部前提。

### 最小装饰器

```python
def logged(fn):
    def wrapper(*args, **kwargs):
        print(f"调用 {fn.__name__}")
        return fn(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(1, 2))
```

`@logged` 放在 `def add` 上面，等价于：

```python
def add(a, b):
    return a + b
add = logged(add)
```

所以 `add` 这个名字最终指向的是 `wrapper`，不是原来的函数。`wrapper` 内部再调用原来的 `fn`。

### `*args, **kwargs` 为什么必须写

```python
def logged(fn):
    def wrapper(*args, **kwargs):   # 原函数要什么参数，这里原样转发
        return fn(*args, **kwargs)
    return wrapper
```

如果写成 `def wrapper():`，那么被装饰的 `add(1, 2)` 会报"wrapper 不接受参数"。`*args` 收位置参数、`**kwargs` 收关键字参数，再原样转给 `fn`——这样装饰器对任何签名的函数都通用。

### `functools.wraps`：不写会坏什么

```python
import functools

def logged(fn):
    @functools.wraps(fn)          # 把 __name__、__doc__ 等复制到 wrapper 上
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper
```

不写 `@functools.wraps(fn)` 时，`add.__name__` 会变成 `"wrapper"`，`help(add)` 显示的是 wrapper 的文档。这会直接坏掉三件事：

- 日志里全是 `wrapper`，看不出是哪个函数；
- 自动生成文档（Sphinx、FastAPI 的 OpenAPI）里接口名都错了；
- pytest、Flask 这类按函数名注册的东西可能冲突。

**结论：写装饰器一律加 `@functools.wraps(fn)`。**

### 跑一遍

<!-- run -->
```python
import functools


def logged(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        print(f"调用 {fn.__name__}")
        return fn(*args, **kwargs)
    return wrapper


def bare(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


@logged
def add(a, b):
    "两个数相加"
    return a + b


@bare
def sub(a, b):
    return a - b


print(add(1, 2))
print(add.__name__, add.__doc__)
print(sub.__name__)
```
```text
调用 add
3
add 两个数相加
wrapper
```

`logged` 只加了一行日志，结果原样返回；`add.__name__` 与 `add.__doc__` 都被 `functools.wraps` 保住了。对比 `sub`：没写 `functools.wraps`，名字直接变成 `wrapper`，日志和自动文档里就再也认不出它。

### 带参数的装饰器：多一层

```python
def retry(times):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except Exception:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator

@retry(3)
def fetch():
    ...
```

读法是三层：最外层收**装饰器参数**（`3`），中间层收**被装饰的函数**，最内层是真正替换上去的函数。`@retry(3)` 先执行 `retry(3)` 得到一个装饰器，再用它装饰 `fetch`。

### 装饰器不该做的事

- **不要偷偷改返回值类型**：`@logged` 只该加日志，不该把 `int` 变成字符串；
- **不要吞异常**：除非它就是"重试/降级"装饰器，否则让异常原样冒出去；
- **不要在装饰器里做耗时初始化**：装饰发生在 import 时，一次性的连接可以，每次调用都建连接不行。

## 常见误区

### 误区：装饰器会改变原函数

**你以为**：原函数还在，只是"多了一层"。
**其实**：原名指向的是 wrapper。原函数只有 wrapper 内部还引用着，外部已经拿不到。
**怎么验证**：装饰后 `print(add)`，看到的是 wrapper 的地址；不写 `functools.wraps` 时连名字都不是 add。

### 误区：装饰器越薄越好，不用管签名

**你以为**：反正 `*args, **kwargs` 万能。
**其实**：它能转发，但 IDE 与类型检查器看不到真实参数，补全和类型提示会失效。需要精确签名时，可以用 `typing.ParamSpec`（进阶写法），或者干脆少用装饰器。

### 误区：什么都能用装饰器解决

**你以为**：横切逻辑都该抽成装饰器。
**其实**：装饰器适合"进入前/退出后"的短逻辑。要在函数执行中途插入步骤、或者要共享大量状态，写显式的辅助函数更好读。

## 小结

装饰器 = 接收函数、返回新函数的高阶函数，`@` 只是语法糖。写它必须用 `*args, **kwargs` 转发参数，并加 `@functools.wraps` 保住元数据。带参数的装饰器是三层函数。它适合日志、计时、鉴权、重试这类前后逻辑。
