# 15 · 装饰器

## 计时器报 0.000s，可这段代码明明等了 0.2 秒

想找出哪个函数慢，先写了个 `@timed`，套在一个读数据的函数上：

```python
import functools
import time


def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__}: {time.perf_counter() - start:.3f}s")
    return wrapper


@timed
def rows(n):
    for i in range(n):
        time.sleep(0.01)
        yield i


print(sum(rows(20)))
```

```text
rows: 0.000s
190
```

`rows: 0.000s` 是在 `rows(20)` 那一刻打出来的——那时一个元素都还没生成。`190` 是之后 `sum` 把生成器走完才拿到的。这 20 次 `sleep(0.01)` 是真花了时间的，同一台机器、Python 3.11.5，把 `perf_counter` 套在循环外面量到 0.207–0.210 秒：

```text
190 0.209s
```

那 0.2 秒一秒都没进计时器。原因不在装饰器写错，在我把「调用」当成了「执行」：14 课讲过，调用生成器函数只返回一个生成器对象，函数体一行都不跑。`wrapper` 里那句 `return fn(*args, **kwargs)` 量到的，只是「拿到这个对象」的那一下。

我前后看了三遍才承认这件事：装饰器包住的是函数**被调用**这个动作，不是函数**做完**这件事。这篇剩下的部分，都是从这个错认里长出来的。

## @ 只做了一件事：把名字换成新函数

`@timed` 放在 `def rows` 上面，等价于先定义函数、再重新绑定这个名字：

```python
def rows(n):
    for i in range(n):
        time.sleep(0.01)
        yield i


rows = timed(rows)
```

所以执行到 `def` 结束的那一刻，`rows` 已经指向 `timed` 返回的 `wrapper` 了，原来的函数只剩 `wrapper` 内部还引用着。`rows.__wrapped__ is 原函数` 是 `True`——那是 `functools.wraps` 留的入口，下一节说。

叠两个装饰器时，顺序按这个赋值推。`@tag("外")` 在上面、`@tag("内")` 在下面，等价于 `work = tag("外")(tag("内")(work))`：「内」先包，「外」最后包，调用时「外」先进。

```python
def tag(name):
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            print("进", name)
            result = fn(*args, **kwargs)
            print("出", name)
            return result
        return wrapper
    return deco


@tag("外")
@tag("内")
def work():
    print("干活")


work()
```

```text
进 外
进 内
干活
出 内
出 外
```

`wrapper` 的形参表必须写 `*args, **kwargs`。写成空括号，被装饰的函数一带参数就炸：

```python
def broken(fn):
    def wrapper():
        return fn()
    return wrapper


@broken
def add(a, b):
    return a + b


add(1, 2)
```

```text
TypeError: broken.<locals>.wrapper() takes 0 positional arguments but 2 were given
```

这是 3.11.5 的原文，消息里 `broken.<locals>.` 那段是限定名，别的版本字样不完全一样，别拿整句去 grep 自己的报错。位置参数进 `args`、关键字参数进 `kwargs`，再原样转给 `fn`，`wrapper` 才能适配任何签名——代价是静态类型看不见参数，第 4 节会说。

## wrapper 里的 fn 是从哪来的

04 课讲循环里的函数时留了一句「闭包第 15 课才讲」。就是这里。

`wrapper` 的形参表里没有 `fn`，可它用得上 `fn`：`fn` 是 `timed` 的局部变量，`wrapper` 定义在 `timed` 内部，编译器会把这个名字记成自由变量，运行时存在一个 cell 里。

```python
def timed(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


w = timed(len)
print(w.__code__.co_freevars)
print("fn" in w.__code__.co_varnames)
print(w.__closure__[0].cell_contents is len)
```

```text
('fn',)
False
True
```

`co_varnames` 是 `wrapper` 自己的局部名字，里面没有 `fn`；`co_freevars` 才是它从外层借的那几个。`__closure__` 是真正装这些借来东西的格子，掏出来一比就是 `len` 本人。

这里要跟 04 课那个 bug 分清楚。那个 bug 是循环里定义好几个函数、共用一个外层变量 `i`，最后都读到 `i` 的终值；装饰器不会，每调用一次 `timed(fn)` 就新建一个 cell，两个被装饰的函数各持自己那一格。

## functools.wraps 保住了什么，又顺手改了什么

`functools.wraps(fn)` 做的事可以逐条数：把原函数上 `functools.WRAPPER_ASSIGNMENTS` 列的那几个名字抄给 `wrapper`（3.11.5 打出来是 `('__module__', '__name__', '__qualname__', '__doc__', '__annotations__')`），把原函数的 `__dict__` 更新过去，最后挂一个 `__wrapped__` 指回原函数。

不写它，名字和文档就没了：

```python
import functools
import inspect


def no_wraps(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


def with_wraps(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


def add(a: int, b: int = 2) -> int:
    "两数相加"
    return a + b


plain = no_wraps(add)
kept = with_wraps(add)
print("plain:", plain.__name__, "|", repr(plain.__doc__), "|", inspect.signature(plain))
print("kept: ", kept.__name__, "|", repr(kept.__doc__), "|", inspect.signature(kept))
```

```text
plain: wrapper | None | (*args, **kwargs)
kept:  add | '两数相加' | (a: int, b: int = 2) -> int
```

第二行值得多看一会儿。我原来的笔记里写的是「不写 wraps，签名就丢了」——这半句只在两个位置成立：没写 wraps 时运行时确实丢了（就是 `plain` 那行），以及交给静态检查器时（下一段）。**运行时**的 `inspect.signature` 会顺着 `__wrapped__` 往下找，写了 wraps 就能把原参数表原样拿回来，`help()`、文档生成、调试器都吃这一口。

静态那侧不吃。同一份代码交给 mypy，被装饰过的函数直接变成 `Any`，参数写错也不报：

```python
import functools


def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


def plain(a: int, b: int) -> int:
    return a + b


@timed
def decorated(a: int, b: int) -> int:
    return a + b


plain(1, "x")
decorated(1, "x")
```

```text
$ python -m mypy demo.py
demo.py:20: error: Argument 2 to "plain" has incompatible type "str"; expected "int"  [arg-type]
Found 1 error in 1 file (checked 1 source file)
```

第 20 行报了，第 21 行的 `decorated(1, "x")` 一声不吭（本机 `mypy 2.4.1`）。这就是 `ParamSpec` 存在的原因，本篇不展开。

`wraps` 还顺带改了一件事，跟这篇开头那个 bug 直接相关：`inspect.isgeneratorfunction` **不跟着** `__wrapped__` 走。一个生成器函数被包一层之后，从外面看它就不是生成器函数了：

```text
原函数是生成器函数: True
包一层之后: False
```

（这两行是本篇「跑一遍」里的实测输出。）所以「判断它是不是生成器函数」这件事，必须在装饰器里对传进来的 `fn` 做，不能对外面那个装饰过的名字做。

还有一处我原先写错的：说过「原函数只有 wrapper 内部还引用着，外部拿不到」。写了 wraps 就有公开入口 `__wrapped__`；没写也能从 `__closure__[0].cell_contents` 掏出来。准确的说法是**外部没有公开名字，但引用一直在**。

## 症状对不上时，先看哪

| 症状 | 先看哪 |
| --- | --- |
| 日志里每一行都写着 `wrapper` | 装饰器没加 `@functools.wraps(fn)`，`__name__` 被 wrapper 的覆盖了 |
| `TypeError: ...wrapper() takes 0 positional arguments but 2 were given` | wrapper 的形参表没写 `*args, **kwargs` |
| `inspect.signature(f)` 得到 `(*args, **kwargs)` | 同上，缺 wraps：没有 `__wrapped__`，signature 无处可跟 |
| 给函数加了装饰器，mypy 就不管它的参数了 | 装饰器没类型标注，返回值退化成 `Any`；要 `Callable[P, R]` 配 `ParamSpec` |
| 装饰过的生成器函数 `isgeneratorfunction` 变成 `False` | 它在外部已经是普通函数；判断要挪到装饰器内部、对原函数做 |
| 计时器对含 `yield` 的函数报 0.000s | 量的是「拿到生成器」那一下，不是迭代过程 |
| `@retry(N)` 里后来改了 `N` 却不起作用 | `N` 在装饰那一行就求值完了；要可变就读运行时状态，别从实参传 |

## 带参数的装饰器：那个 3 在 def 那行就算完了

```python
import functools

ATTEMPTS = 3


def retry(times):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            for attempt in range(times):
                try:
                    return fn(*args, **kwargs)
                except ValueError:
                    if attempt == times - 1:
                        raise
        return wrapper
    return decorator


calls = 0


@retry(ATTEMPTS)
def flaky():
    global calls
    calls += 1
    if calls < 3:
        raise ValueError("这次失败")
    return "ok"


ATTEMPTS = 1
print(flaky(), calls)
```

```text
ok 3
```

三层怎么读：最外层收装饰器的参数（`3`），中间层收被装饰的函数，最内层是替换上去的 `wrapper`。`@retry(ATTEMPTS)` 这一行在 `def` 之后就执行完了，当时 `ATTEMPTS` 是 3，后面再改成 1 也没用——`times` 已经在闭包里了。

`@retry(0)` 更安静：`range(0)` 一次都不跑，函数直接返回 `None`，不报任何错。

```text
None
```

这不是语言的问题，是代码没写「一次都没试」那条分支。重试次数要能改，就让它读运行时状态（配置对象、环境变量），别从装饰器实参传。

## 把计时器改对

拿 `inspect.isgeneratorfunction(fn)` 在装饰时分流，生成器函数换一个「边迭代边计时」的 wrapper：

```python
import functools
import inspect
import time


def timed(fn):
    if inspect.isgeneratorfunction(fn):
        @functools.wraps(fn)
        def gen_wrapper(*args, **kwargs):
            start = time.perf_counter()
            try:
                yield from fn(*args, **kwargs)
            finally:
                print(f"{fn.__name__}: {time.perf_counter() - start:.3f}s")
        return gen_wrapper

    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            print(f"{fn.__name__}: {time.perf_counter() - start:.3f}s")
    return wrapper
```

同一句 `sum(rows(20))`，现在的输出是：

```text
rows: 0.210s
190
```

（一次运行的实际输出；5 次运行落在 0.207–0.213 秒。）`yield from` 把外层的「继续」交给内层，`finally` 在走完或关闭时执行一次，计时覆盖的才是真正的迭代。

这个补法还留着三条缝，写在这里免得当它是个通解：

- 调用方半路 `break` 时 `gen_wrapper` 被关闭，`finally` 只记到被消费的那部分。这行为是对的，但数字会偏小，别拿它当总耗时。
- `async def` 的函数 `isgeneratorfunction` 返回 `False`。它返回的是协程对象，和生成器一样「立刻返回、没开始跑」，要另开 `iscoroutinefunction` 分支，第 17 课讲 async 时再接。
- 判断只对「原函数」有效，套在已经装饰过的函数上会漏（第 4 节那条 `True` 变 `False`）。

```python
import functools
import inspect
import time


def plain_wrapper(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


reported = []


def timed(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return fn(*args, **kwargs)
        finally:
            reported.append(time.perf_counter() - start)
    return wrapper


def make_plain(a, b=2):
    "没有装饰器的原函数"
    return a + b


def rows(n):
    for _ in range(n):
        time.sleep(0.01)
        yield 1


kept = timed(make_plain)
print("名字:", kept.__name__)
print("__wrapped__ 就是原函数:", kept.__wrapped__ is make_plain)

print("带 wraps 的签名:", inspect.signature(kept))
print("不带 wraps 的签名:", inspect.signature(plain_wrapper(make_plain)))

print("freevars:", kept.__code__.co_freevars)
print("fn 在局部变量里:", "fn" in kept.__code__.co_varnames)
print("cell 里装的就是原函数:", kept.__closure__[0].cell_contents is make_plain)
print("两个 wrapper 不共用 cell:", timed(rows).__closure__[0] is not kept.__closure__[0])

print("原函数是生成器函数:", inspect.isgeneratorfunction(rows))
print("包一层之后:", inspect.isgeneratorfunction(timed(rows)))

gen = timed(rows)(20)
start = time.perf_counter()
for _ in gen:
    pass
consumed = time.perf_counter() - start
print("计时器记下的 < 1ms:", reported[-1] < 0.001)
print("真正迭代 >= 0.2s:", consumed >= 0.2)
```

## 还差的

- **静态类型那半截没讲完**。运行时靠 `__wrapped__` 能找回签名，交给 mypy 就不行了——本机那条 `Success: no issues found` 说明装饰之后连 `add(1, "x")` 都不报。真要做标注得上 `Callable[P, R]` 加 `ParamSpec`（PEP 612），第 13 课没讲泛型，这里不硬塞。
- **async 与线程的装饰器没碰**。`async def`、`asyncio` 下怎么挂计时，重试要不要放线程池里，都没试过；等第 17 课把并发讲完再回来补。
- **类里的装饰器没验证**。装饰实例方法时 `self` 会作为第一个位置参数进 `args`，所以 `*args` 写法能跑；但自定义装饰器和 `@classmethod` / `@staticmethod` 叠在一起的顺序、描述符那一层的行为，一条都没实测。
- **重试装饰器只是个骨架**。没有退避、没有按异常类型区分该不该重试、也没讨论被装饰函数带副作用时重复执行会出什么事；`@retry(0)` 静默返回 `None` 那条我只指出来，没改成抛错。
- **`functools.wraps` 只核对了复制清单，没构造踩坑例子**。`__annotations__` 是直接搬过去的（之后改原函数的注解不会同步），`__defaults__` / `__kwdefaults__` 根本不在复制范围里；这两条我是读 `WRAPPER_ASSIGNMENTS` 和源码得到的，没有跑出会坏的具体场景。
