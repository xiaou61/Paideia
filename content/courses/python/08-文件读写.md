# 08 · 文件读写

## 一个 w 打开、立刻关掉，两行日志没了

```python
from pathlib import Path

with open(log, "w", encoding="utf-8") as f:
    f.write("启动\n")
    f.write("收款 100\n")
print("写了 2 行后:", len(log.read_text(encoding="utf-8").splitlines()))

with open(log, "w", encoding="utf-8") as f:
    pass                                  # 什么都没写
print("用 w 打开又立刻关掉:", len(log.read_text(encoding="utf-8").splitlines()))
```

```text
写了 2 行后: 2
用 w 打开又立刻关掉: 0
```

第二行是关键：**`"w"` 在打开的那一刻就截断了文件**，不是「写入时」才清。所以哪怕后面抛异常、一行都没写成功，旧内容也回不来了。

这是这一课唯一会造成不可挽回损失的坑，先把它放在第一屏。

## 四种模式

| 模式 | 文件不存在 | 文件已存在 | 危险性 |
| --- | --- | --- | --- |
| `"r"` | `FileNotFoundError` | 从头读 | 安全 |
| `"a"` | 创建 | 追加到末尾 | 安全 |
| `"x"` | 创建 | `FileExistsError` | 安全 |
| `"w"` | 创建 | **打开即清空** | 高危 |

要往日志文件里加一行，用 `"a"`；要保证「绝不覆盖已有文件」，用 `"x"`——下面 run 块里会看到它撞上已存在文件时抛的 `FileExistsError: File exists`。

`"w"` 只有一种场合该用：你确定这个文件的内容可以被丢掉，比如「重新生成整份报告」。

## 必须用 with

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
```

`with` 保证退出代码块时文件一定被关闭，哪怕中间抛了异常。不用 `with` 就得自己写 `finally: f.close()`，漏掉它在 Windows 上会看到「另一个程序正在使用此文件」——因为句柄还开着。

## 每行都带着换行符

用 `for line in f` 读，每行**保留行尾的 `\n`**。这是下一课字符串比较「莫名其妙不等」的根源：

<!-- run -->
```python
from pathlib import Path
import tempfile

folder = Path(tempfile.mkdtemp())
log = folder / "app.log"

with open(log, "w", encoding="utf-8") as f:
    f.write("启动\n")
    f.write("收款 100\n")
print("写了 2 行后:", len(log.read_text(encoding="utf-8").splitlines()))

with open(log, "w", encoding="utf-8") as f:
    pass
print("用 w 打开又立刻关掉:", len(log.read_text(encoding="utf-8").splitlines()))

with open(log, "a", encoding="utf-8") as f:
    f.write("收款 200\n")
print("追加 1 行后:", len(log.read_text(encoding="utf-8").splitlines()))

with open(log, encoding="utf-8") as f:
    for line in f:
        print("读到:", repr(line))

try:
    with open(log, "x", encoding="utf-8") as f:
        f.write("不会执行")
except FileExistsError as e:
    print("x 模式:", e.strerror)
```
```text
写了 2 行后: 2
用 w 打开又立刻关掉: 0
追加 1 行后: 1
读到: '收款 200\n'
x 模式: File exists
```

`repr(line)` 里那个 `\n` 就是证据：字符串末尾确实有换行符。所以比较前要 `line.rstrip("\n")`，或者干脆 `line.rstrip()`。

`for line in f` 比 `f.readlines()` 省内存：前者一次一行，后者把整个文件读进列表。处理 10GB 日志时这不是优化，是能不能跑起来的问题。

## 相对路径相对的是「工作目录」

`open("data.txt")` 找的是**当前工作目录**，不是脚本所在目录。所以「我明明把文件放在脚本旁边」却报错：

```text
File "C:\...\g.py", line 1, in <module>
    open("data.txt", encoding="utf-8").read()
FileNotFoundError: [Errno 2] No such file or directory: 'data.txt'
```

从别的目录敲 `python g.py`，工作目录就是那个「别的目录」，文件自然找不到。

稳妥做法是用 `__file__` 定位，跟工作目录解耦：

```python
from pathlib import Path

base = Path(__file__).parent
with open(base / "data.txt", encoding="utf-8") as f:
    text = f.read()
```

`__file__` 是脚本自己的路径（相对路径进 Python 时会被转成绝对路径），`.parent` 是它所在目录。这样不管从哪儿调用都对。

## encoding 必须写

不写 `encoding` 时，Python 用**系统默认编码**：Linux/macOS 一般是 UTF-8，中文 Windows 是 `cp936`（GBK）。三种表现，别混：

1. 读 UTF-8 文件 → `UnicodeDecodeError: 'gbk' codec can't decode byte 0xad in position 2: illegal multibyte sequence`（报错，不是乱码）；
2. 写文件 → 生成的文件在别人机器上是乱码；
3. 打印到控制台 → 输出变成 `�����`（这是控制台码页的问题，跟文件无关）。

所以规则很简单：**每个 `open` 都写 `encoding="utf-8"`**，读写两边一致。

## 写文件的两个进阶做法

**一，先写临时文件再改名。** `"w"` 截断之后如果程序崩了，文件就是半截。写盘这类操作要么完整、要么保持原样：

```python
tmp = target.with_suffix(".tmp")
with open(tmp, "w", encoding="utf-8") as f:
    f.write(content)
    f.flush()
    os.fsync(f.fileno())          # 确保落盘，不只是落到内核缓冲
tmp.replace(target)               # 同一文件系统内是原子改名
```

`Path.replace` 底层是 `os.replace`，Windows 与 POSIX 都能覆盖已存在文件。跨文件系统会失败（`OSError: [Errno 18]`），所以临时文件要放在目标旁边。

**二，结构化数据别自己拼字符串。** 存列表用 `json.dump`，比手写 `\n` 分隔稳当：

```python
import json

with open(base / "tasks.json", "w", encoding="utf-8") as f:
    json.dump(tasks, f, ensure_ascii=False, indent=2)

with open(base / "tasks.json", encoding="utf-8") as f:
    tasks = json.load(f)
```

`ensure_ascii=False` 让中文原样写入（否则是 `\u4e2d` 这种转义），`indent=2` 让它可读、可 diff。这两个参数存配置和人工编辑的文件时都该加。

## 还差的

- **编码行为只在本机 Windows（cp936）与 Linux 默认 UTF-8 上验过。** 中文 Windows 的 `cp936` 我复现过报错，其它语言区域的默认编码没测。
- **`os.fsync` 主窗口之外的东西没验。** 目录项是否也 fsync、断电后的一致性，属于文件系统层面的知识，我只知道教科书结论。
- **并发写没讲。** 两个进程同时 `"a"` 追加在什么情况下会丢行、要不要 `fcntl` 锁，这一课没覆盖。
- **二进制模式（`"rb"`/`"wb"`）一句没提。** 处理图片、压缩包、协议帧时它是必需的，但那是另一课的量。
