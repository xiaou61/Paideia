# 06 · 字典与集合

## 同一个缺失，一次崩在键上，一次崩在算式上

```python
scores = {"语文": 90, "数学": 85}
print(scores["物理"])
```

```text
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
KeyError: '物理'
```

我原来以为字典取一个不存在的键会给我一个空值（JavaScript 里是 `undefined`），拿到手再判断就行。实际是当场抛 `KeyError`，而且报错最后那行的 `'物理'` 是 `repr` 过的键本身——它把「缺的是哪个键」直接写在脸上。

崩在这一行是好事：错误发生的位置就是原因的位置。

换成 `get` 写同一件事，场面就变了：

```python
scores = {"语文": 90, "数学": 85}
scores["物理"] = scores.get("物理")
print(sum(scores.values()))
```

```text
Traceback (most recent call last):
  File "<stdin>", line 3, in <module>
TypeError: unsupported operand type(s) for +: 'int' and 'NoneType'
```

同一个缺失，报错从第 2 行挪到了第 3 行，内容从「键 `物理` 不存在」变成了「`int` 和 `NoneType` 不能相加」。而且字典里已经被悄悄塞进一条 `{'物理': None}`。

所以 `d[k]` 和 `d.get(k)` 的区别不是写法偏好，是一句话：**这个键缺失，是我该处理的业务情况，还是我代码里的 bug？**

- 缺了有意义（这门课这学期没开、用户没填这一栏）→ `d.get(k)`，**并且把默认值写出来**：`d.get(k, 0)`。
- 缺了说明我写错了（这条数据我明明存过、键名是固定的）→ `d[k]`，让它当场崩。

中间那个最不该用的是不带默认值的 `get(k)`：它既不崩，也不给出可用的值，只是把 `None` 送进后面所有算式。

## `counts[tag] += 1` 为什么在空字典上就炸

```python
counts = {}
counts["python"] += 1
```

```text
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
KeyError: 'python'
```

`+=` 不是一步：先读 `counts["python"]`（这里就崩了），加起来，再写回。空字典没有这个键，败在「读」那一步。

先给一个默认值就通了：

```python
raw = ["python", "后端", "python", "数据库", "后端"]

counts = {}
for tag in raw:
    counts[tag] = counts.get(tag, 0) + 1
print(counts)
```

```text
{'python': 2, '后端': 2, '数据库': 1}
```

注意等号左边还是用下标 `counts[tag]`，不是 `get`：写的那一侧不需要默认值，键不存在正是「第一次出现」的意思。

`counts` 打印出来的顺序是 `python`、`后端`、`数据库`——标签第一次出现的顺序，不是字母序。这不是巧合，是下面一节要用的性质。

## 字典记得你写进去的顺序

3.7 起，「字典保留插入顺序」是写进语言规范的保证（3.6 只是 CPython 的实现行为，换个实现不认这条）。所以：

```python
d = {"b": 1, "a": 2}
d["c"] = 3
print(d)
print(list(d))
```

```text
{'b': 1, 'a': 2, 'c': 3}
['b', 'a', 'c']
```

后加的 `c` 排在最后，`a` 没有因为字母小而插到 `b` 前面。要按名字排，得自己 `sorted(d)`。

这条性质在去重时最值钱。

## 同一行 `set`，六次跑出五种顺序

最顺手的去重是 `list(set(raw))`。我在本机连跑六次同一条命令（Python 3.11.5，Windows，没设 `PYTHONHASHSEED`）：

```text
['前端', '测试', 'python', '后端', '数据库']
['后端', '数据库', 'python', '前端', '测试']
['后端', '测试', '前端', 'python', '数据库']
['后端', '数据库', 'python', '前端', '测试']
['python', '数据库', '后端', '测试', '前端']
['测试', '数据库', '前端', '后端', 'python']
```

命令是 `python -c "print(list(set(['python','后端','数据库','前端','测试'])))"`，六次里只有第 2、4 次碰巧一样。

不是我把代码写错了：Python 默认给字符串的哈希加了一层随机盐（`PYTHONHASHSEED`），每个进程取一个值。同一个 `set` 在同一个进程里打印是稳定的，换个进程就换一副面孔。设 `PYTHONHASHSEED=0` 再跑三次，三次一模一样。

这条的严重程度不是「`set` 会稍微打乱顺序」，而是**同一台机器上同一条命令两次运行的结果可以不同**。任何拿 `set` 打印结果当期望输出的写法——写测试断言、比对日志、像这篇一样贴进 text 输出块——都会偶发失败。

要按原顺序去重，就拿字典当去重器：

```python
print(list(dict.fromkeys(raw)))
```

```text
['python', '后端', '数据库']
```

`dict.fromkeys` 把每个元素当一次键塞进去，重复的键只留一个位置，而字典记着第一次插入的顺序——正好等于「保序去重」。它借的就是上一节那条 3.7 的保证。

集合真正擅长的是「有没有」和交并差，那里本来就不该去读顺序：

```python
a = {"python", "后端", "数据库"}
b = {"python", "前端"}
print(a & b)   # 交集
print(a | b)   # 并集
print(a - b)   # 差集
```

顺带一个容易记反的：非字符串集合的顺序在同一个版本上是稳定的，但稳定不等于有序。

```python
print(list({3, 1, 2}))
print(list({100, 200, 300}))
```

```text
[1, 2, 3]
[200, 100, 300]
```

`{3, 1, 2}` 打印成 `[1, 2, 3]` 纯属巧合——这个规模下整数的哈希值就是它自己，落位刚好排整齐了。`{100, 200, 300}` 立刻露馅。这两行我在这台机器上连跑三次没变，但换版本不一定，别当规律背；要顺序就 `sorted`。

## `Counter` 和 `defaultdict`：先照抄 import，第 12 课才讲模块

```python
from collections import Counter

raw = ["python", "后端", "python", "数据库", "后端"]
print(Counter(raw))
print(Counter(raw).most_common(1))
```

```text
Counter({'python': 2, '后端': 2, '数据库': 1})
[('python', 2)]
```

`import` 放到脚本最上面照抄就行，第 12 课解释它是干什么的；现在不写这一行会报 `NameError: name 'Counter' is not defined`。

`Counter` 是 `dict` 的子类，缺键时读出来是 `0` 而不是抛异常。但它**不会**因为这次读就往里塞一个键——这一点要和 `defaultdict` 分开记。

`defaultdict` 要的是「缺了就先建一个空壳」：

```python
from collections import defaultdict

rows = [("a", 1), ("b", 2), ("a", 3)]
dd = defaultdict(list)
for tag, n in rows:
    dd[tag].append(n)
print(dict(dd))
print(dd["新标签"], dict(dd))
```

```text
{'a': [1, 3], 'b': [2]}
[] {'a': [1, 3], 'b': [2], '新标签': []}
```

第二行才是要记住的地方：**读一下 `dd["新标签"]`，它就被插进去了**。`defaultdict` 的缺键读取有副作用，`Counter` 没有。于是在 `defaultdict` 上做存在性判断会咬到自己：读过一次之后，`"新标签" in dd` 永远为真；而在 `Counter` 上，读过之后 `"没有的键" in c` 还是 `False`。

## `d.keys()` 不是列表，是一扇窗

```python
d = {"b": 1, "a": 2}
view = d.keys()
print(type(view).__name__, len(view))
d["c"] = 3
print(len(view), list(view))
```

```text
dict_keys 2
3 ['b', 'a', 'c']
```

`view` 不是拍下来的快照，是「看 `d` 当前状态」的窗口：后面加的 `c` 它立刻看得见。想固定住就 `list(d.keys())`。

也正因为不是列表，它没有下标：

```python
print(d.keys()[0])
```

```text
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
TypeError: 'dict_keys' object is not subscriptable
```

`d.values()`、`d.items()` 同一回事。要下标就自己套一层：`list(d.keys())`、`list(d.values())`、`list(d.items())`——键那一侧 `list(d)` 就够。

## 遍历时删键会炸，改值不会

这一条我原来记反了，以为「遍历时不能动字典」。实际上循环体里给已有键赋新值完全没问题：

```python
d = {"b": 1, "a": 2}
d["c"] = 3
for key in d:
    d[key] = d[key] * 10
print(d)
```

```text
{'b': 10, 'a': 20, 'c': 30}
```

删键才炸：

```python
d = {"b": 1, "a": 2}
for key in d:
    del d[key]
```

```text
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
RuntimeError: dictionary changed size during iteration
```

报错原文里说的是 size，不是 content。所以准确的说法是「遍历时不能让键的个数变化」：加键、删键不行，改已有键的值可以。

要把一些键筛掉，就别在原字典上删；建一个新字典放留下的：

```python
d = {"b": 1, "a": 2, "c": 3}
kept = {}
for key, value in d.items():
    if value > 1:
        kept[key] = value
print(kept)
```

```text
{'a': 2, 'c': 3}
```

## 键必须可哈希，值不必

05 课只说了元组能当键，这里把另一半补上。字典先用哈希值给键定位，查的时候用同样的键再算一次，两次必须落到同一处——所以键在待在字典里的这段时间里，内容不能变。

```python
hash([1, 2])
```

```text
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
TypeError: unhashable type: 'list'
```

`list`、`dict`、`set` 都能改，所以都不能当键，也不能放进集合。元组可以，但**要求它里面每个元素都可哈希**：

```python
hash(([1], 2))
```

```text
Traceback (most recent call last):
  File "<stdin>", line 2, in <module>
TypeError: unhashable type: 'list'
```

外面包着元组没用，报错指的仍是里面那个 `list`。

而值这一侧完全不管，可以是列表，也可以是字典：

```python
print({"科目": ["语文", "数学"]})
```

```text
{'科目': ['语文', '数学']}
```

「键不能改、值随便」这个不对称，是这一课最容易记反的一处。

## 七种症状，各自先去看哪

| 看到这个 | 先去看哪 | 为什么是它 |
| --- | --- | --- |
| `KeyError: '物理'` | 键是真不存在，还是名字写错了（大小写、前后空格、中英文括号） | 下标取不到键就抛它；报错里是键的 `repr`，可以直接跟源码里的字符串对 |
| `TypeError: unsupported operand type(s) for +: 'NoneType'` | 上游有没有人用 `get(k)` 没给默认值 | `None` 被塞进字典后一路流到算式才炸，现场已经看不到缺的是哪个键 |
| 同一条命令两次打印顺序不同 | 是不是在打印 `set` | 字符串哈希默认每进程随机加盐；要稳定就 `sorted()` 或 `dict.fromkeys` |
| `TypeError: unhashable type: 'list'` | 键里、或集合元素里有没有 `list` / `dict` / `set` | 只有键和集合元素要求可哈希，值可以是任何对象 |
| `RuntimeError: dictionary changed size during iteration` | 循环体里有没有 `del`、`pop`、或给新键赋值 | 它盯的是键的个数；改已有键的值不触发 |
| `TypeError: 'dict_keys' object is not subscriptable` | 是不是对 `d.keys()` 直接取了 `[0]` | 视图不是列表，要 `list(d.keys())` |
| 判断「键在不在」总是成立 | 前面是不是读过 `defaultdict` 的缺键 | `defaultdict` 的缺键读会插入默认值；`Counter` 不会，`in` 也就不会骗你 |

## 还差的

- 没测复杂度。全文没写字典查找是 O(1) 这类结论，因为这一课没做基准测试，哈希冲突下的退化也没测。
- 没讲 `setdefault`、`dict.update`、`frozenset`，也没讲集合的原地运算符 `|=`、`&=`、`-=`。
- 可哈希只讲了内置类型这一侧。自己写的类默认按对象身份算哈希，「内容相等但身份不同」的坑要等第 10 课讲类、第 11 课讲继承才说得清。
- `sorted(d, key=...)` 和 `Counter.most_common` 在计数并列时的次序，我只验了不并列的情况，没验并列。
- 本文所有输出来自本机 Python 3.11.5，而学习者沙箱的基线是 3.12。字典插入序、`Counter`、`defaultdict` 这几条我按官方文档判断两个版本一致，但没在 3.12 上真跑一遍；`set` 的打印顺序两版本来就不会一致。
