# 14 · 迭代器与生成器

## 这一课你要会

- 说清"可迭代对象"和"迭代器"的区别；
- 用 `yield` 写生成器，并解释它为什么省内存；
- 判断一段代码是"一次造出整个列表"还是"取一个算一个"；
- 用生成器表达式把 `[... for ...]` 改成 `(... for ...)`。

## 为什么

`for x in something` 之所以能用在列表、字典、文件、数据库游标上，靠的就是**迭代协议**。理解它之后你会发现：很多"数据太大、内存爆了"的问题，不是数据的问题，是"一次全取出来"的问题。

生成器是 Python 里最实用的一课：同样的逻辑，`return` 一个列表要占 N 份内存，`yield` 只占 1 份。

## 讲解

### 可迭代对象 vs 迭代器

- **可迭代对象（iterable）**：能被 `for` 遍历的东西。它实现 `__iter__`，返回一个迭代器。列表、字典、文件都是。
- **迭代器（iterator）**：真正"记住走到哪"的东西。它实现 `__next__`，每次给你下一个值，取完抛 `StopIteration`。

```python
nums = [1, 2, 3]      # 可迭代对象
it = iter(nums)       # 迭代器
print(next(it))       # 1
print(next(it))       # 2
print(next(it))       # 3
print(next(it))       # StopIteration
```

一个关键差别：**列表可以反复遍历，迭代器只能走一次**。

```python
it = iter([1, 2, 3])
print(list(it))   # [1, 2, 3]
print(list(it))   # [] —— 已经走完了
```

`for` 循环内部就是先 `iter()` 再反复 `next()`，遇到 `StopIteration` 结束。所以**同一个迭代器被两个循环用，第二个循环什么也拿不到**——这是排查"为什么第二次读文件是空的"的常见答案。

### `yield`：把函数变成生成器

```python
def evens(limit):
    for i in range(limit):
        if i % 2 == 0:
            yield i

for value in evens(6):
    print(value)   # 0 2 4
```

普通函数 `return` 一次就结束；带 `yield` 的函数调用时**不执行函数体**，只返回一个生成器对象。每次 `next()` 才走到下一个 `yield`，然后**暂停在那里**，局部变量原样保留。

### 跑一遍

<!-- run -->
```python
def evens(limit):
    print("开始执行")
    for i in range(limit):
        if i % 2 == 0:
            yield i


gen = evens(6)
print("拿到生成器，函数体还没跑")
print(next(gen))
print(list(gen))

it = iter([1, 2, 3])
print(list(it), list(it))
print(sum(x * x for x in range(5)))
```
```text
拿到生成器，函数体还没跑
开始执行
0
[2, 4]
[1, 2, 3] []
30
```

`开始执行` 出现在第一次 `next()` 之后，而不是 `evens(6)` 调用的那一刻——生成器函数只在取值时才运行。`gen` 已经取走了 0，所以 `list(gen)` 只剩 `[2, 4]`；`it` 第二次遍历是空的，因为迭代器只能走一次。

### 为什么省内存

```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:      # 文件本身就是迭代器，一次读一行
            yield line.strip()

for line in read_lines("big.log"):
    if "ERROR" in line:
        print(line)
```

`read_lines` 不会把文件读进内存，它一次只处理一行。换成 `f.readlines()` 则会把整个文件变成列表——1 GB 的日志就要 1 GB 内存，而且必须读完第一行才能开始处理。

**判据**：数据量可能很大、或者你只需要前几条就停，就用生成器。

### 生成器表达式：方括号换成圆括号

```python
squares = [x * x for x in range(10)]    # 列表：立刻算完 10 个
lazy    = (x * x for x in range(10))    # 生成器：一个都还没算

print(next(lazy))   # 0 —— 现在才算第一个
```

`sum(x * x for x in range(10))` 这种写法很常见：`sum` 需要一个可迭代对象，生成器正好是，而且不用先造一个列表。

### 什么时候写生成器，什么时候别写

该写：

- 逐行处理文件、逐条处理数据库结果；
- 流水线式处理（读 → 过滤 → 转换 → 写），每一步都只过一条；
- 有"找到就停"的语义。

别写：

- 调用方需要反复遍历（生成器只能走一次，第二次是空的）；
- 需要 `len()`、下标、排序——这些要求数据已经在内存里；
- 逻辑很短、数据很小，生成器反而让代码多绕一层。

## 常见误区

### 误区：生成器就是"更快的列表"

**你以为**：只是性能优化。
**其实**：它改变的是**能做什么**。生成器不能取长度、不能下标、不能回头，而且只能走一次。它省的是内存，不是 CPU。
**怎么验证**：对生成器调 `len()`，看是否抛 `TypeError`。

### 误区：函数里有 `yield` 就会立刻执行

**你以为**：调用即执行。
**其实**：调用只创建生成器对象，函数体在第一次 `next()` 时才运行。所以生成器体内的 `print`、文件打开都发生在遍历时，而不是调用时。
**怎么验证**：在 `yield` 前加一句 `print("start")`，调用函数但不遍历，看是否打印。

### 误区：`for` 里读文件两次是"又读了一遍"

**你以为**：文件会重新开始。
**其实**：文件对象是迭代器，第一次循环已经读到结尾，第二次循环直接结束。要再读一次，得 `f.seek(0)` 或重新打开文件。

## 小结

可迭代对象能被 `for`，迭代器记住进度且只能走一次。`yield` 让函数变成"取一个算一个"的生成器，处理大文件和大数据流时是默认选择。生成器表达式把方括号换成圆括号就得到了同样的懒惰求值。
