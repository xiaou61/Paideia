# 14 · 迭代器与生成器

## 第四次 next() 是一段 traceback

```python
it = iter([1, 2, 3])
print(next(it))
print(next(it))
print(next(it))
print(next(it))
```

在 Python 3.11.5 下把这段喂给 `python -`，输出是：

```text
1
2
3
Traceback (most recent call last):
  File "<stdin>", line 5, in <module>
StopIteration
```

最后一行不是 `print` 出来的字符串，是异常。`next()` 在取完元素后抛 `StopIteration`，脚本以退出码 1 结束。我原来在笔记里写过 `print(next(it))  # StopIteration`，那是错的：这一行不会打印 `StopIteration`，它会中断程序。

`for` 循环替你把 `StopIteration` 接住了。手动取的时候，要么用 `next(it, "取完了")` 给默认值，要么自己 `try/except StopIteration`：

```python
it = iter([1, 2, 3])
print(next(it, "取完了"))
print(next(it, "取完了"))
print(next(it, "取完了"))
print(next(it, "取完了"))
```

输出是 `1`、`2`、`3`、`取完了`，不会抛异常。

## 迭代器要同时有 __iter__ 和 __next__

`iter(x)` 要拿到一个迭代器；迭代器自己要被 `for` 认出来，必须实现 `__iter__`；迭代器自己的 `__iter__` 返回 `self`。只写 `__next__` 不够：

```python
class NoIter:
    def __next__(self):
        raise StopIteration


for _ in NoIter():
    pass
```

运行时最后一行是：

```text
TypeError: 'NoIter' object is not iterable
```

`for` 的第一步是 `iter(obj)`，它调用 `__iter__`；没有这个方法就直接 `TypeError`，连 `__next__` 都不会走到。

完整的迭代器长这样：

```python
class Counter:
    def __init__(self, limit):
        self.limit = limit
        self.current = 0

    def __iter__(self):
        return self

    def __next__(self):
        if self.current >= self.limit:
            raise StopIteration
        value = self.current
        self.current += 1
        return value


print(list(Counter(3)))   # [0, 1, 2]
```

`__iter__` 返回 `self`，所以 `iter(counter) is counter`；`__next__` 每次往前走一步，走到头抛 `StopIteration`。

列表可以反复遍历，迭代器只能走一次：

```python
it = iter([1, 2, 3])
print(list(it))   # [1, 2, 3]
print(list(it))   # []
```

第二行不是「重新遍历」，是同一个已经耗尽的迭代器。文件对象也是迭代器，`iter(f) is f` 是 `True`；所以第一次 `for line in f` 读到结尾后，第二次循环直接结束。这就是「第二次读文件是空的」最常见的原因：

```python
with open("demo.log", "w", encoding="utf-8") as f:
    for i in range(100_000):
        f.write(f"line {i}\n")

with open("demo.log", encoding="utf-8") as f:
    print(iter(f) is f)          # True
    print(len(list(f)))          # 100000
    print(len(list(f)))          # 0
```

要再读一遍，得重新 `open`，或者 `f.seek(0)` 把位置拨回去。

## yield 让函数在第一次 next() 时才跑

```python
def evens(limit):
    print("开始执行")
    for i in range(limit):
        if i % 2 == 0:
            yield i


gen = evens(6)
print("拿到生成器，函数体还没跑")
print(next(gen))
print(list(gen))
print(list(gen))
```

输出：

```text
拿到生成器，函数体还没跑
开始执行
0
[2, 4]
[]
```

`evens(6)` 调用时只返回一个生成器对象，函数体一行都没执行；第一次 `next(gen)` 才打印 `开始执行` 并走到第一个 `yield`，给出 `0`。`list(gen)` 从暂停处继续，取到 `[2, 4]`；再 `list(gen)` 就是 `[]`，因为生成器也只能走一次。要重新从头来，重新调用 `evens(6)` 生成一个新的。

## yield 不是「只占 1 份内存」

生成器本身不持有整个结果，但调用方一物化就全回来了：

```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip()


print(len(list(read_lines("demo.log"))))   # 100000
```

`list(read_lines("demo.log"))` 会造出 10 万个字符串，和 `readlines()` 一样占内存。生成器省内存的前提是**调用方逐条处理、不把结果攒起来**：峰值只保留在途的那几行，而不是整个文件。

`readlines()` 和逐行迭代的区别也在这里。`f.readlines()` 先把整个文件读成一个列表，再把这个列表交给你；它不可能先给你第一行再读剩下的。`for line in f` 和 `read_lines` 是读到一行交出一行，文件对象内部有缓冲区，但不是把整个文件先装进内存。

```python
with open("demo.log", encoding="utf-8") as f:
    lines = f.readlines()
```

1 GB 的日志跑这一行，就要为整个文件准备一个列表。`yield` 版本只有在调用方也逐条消费时，才把峰值压到「在途行」这个量级。

## 生成器表达式、sorted 和 len

```python
squares = [x * x for x in range(10)]    # 立刻算完 10 个
lazy = (x * x for x in range(10))       # 一个都还没算

print(next(lazy))                       # 0
print(sum(x * x for x in range(5)))     # 30
```

`sum` 接受任何可迭代对象，生成器表达式不用先造列表，所以 `sum(x * x for x in range(5))` 直接得到 `30`。

需要排序也不等于不能写生成器：

```python
print(sorted(evens(10), reverse=True))
```

输出是：

```text
开始执行
[8, 6, 4, 2, 0]
```

`sorted` 接受可迭代对象；它会把元素取完、放进列表、再排序，所以生成器在这之后耗尽。**能用** `sorted`、`list`、`sum`，代价是这些操作会把数据物化。真正做不到的是 `len(gen)`、`gen[0]` 和「回头再遍历一次」：

```python
len(evens(3))   # TypeError: object of type 'generator' has no len()
```

判断一段代码该不该用生成器，看调用方：逐条处理、找到就停、流水线式过滤，适合；需要反复遍历、随机下标、多次排序，先把数据放进列表。

## 还差的

- **生成器的双向通信没讲**。`send()`、`throw()`、`close()`、`yield from` 都没覆盖；把这套东西当协程用，和普通生成器是两种用法。
- **内存没有量化**。10 万行实验只证明了「`list(gen)` 会物化」，没测峰值 RSS；不同 Python 版本、不同操作系统、不同行长，数字都会变。
- **`itertools` 没讲**。`islice`、`chain`、`groupby` 这些现成工具能少写很多手写生成器，本文只写了最基础的形式。
- **文件迭代的边界没展开**。编码、换行、一行特别长（比如一个 500 MB 的单行 JSON）时，逐行读也会把那一行整个读进来；`readline(size)` 和按块读没讲。
