# 20 · 常见错误与调试清单

## 报错说「日期」这个键不存在，可这一列明明在

我在 `%TEMP%\budget\` 下写了个三十行的 `report.py`，读同事从 Excel 导出的 `expenses.csv`，统计 10 月每类支出。第一次运行是这样：

```python
import csv
from pathlib import Path

PATH = Path("expenses.csv")


def load_rows(path):
    with path.open(encoding="utf-8", newline="") as handle:
        return list(csv.DictReader(handle))


def summarize(rows):
    totals = {}
    for row in rows:
        if not row["日期"].startswith("2026-10"):
            continue
        category = row["分类"]
        totals[category] = totals.get(category, 0.0) + float(row["金额"])
    return totals


def main():
    rows = load_rows(PATH)
    totals = summarize(rows)
    for category, amount in sorted(totals.items()):
        print(f"{category}: {amount:.2f}")
    print(f"合计: {sum(totals.values()):.2f}")


main()
```

```text

    main()
  File "C:\Users\Lenovo\AppData\Local\Temp\budget\report.py", line 24, in main
    totals = summarize(rows)
             ^^^^^^^^^^^^^^^
  File "C:\Users\Lenovo\AppData\Local\Temp\budget\report.py", line 15, in summarize
    if not row["日期"].startswith("2026-10"):
           ~~~^^^^^^
KeyError: '日期'
```

我第一反应是：我明明写了 `row["日期"]`，表格第一列就是日期，凭什么说没有。

其实 `KeyError` 打印的是**我要求的那个键**，不是字典里实际有哪些键。所以这行只说明「`row` 里没有 `日期`」，`row` 里到底有什么，它一个字没说。

把表头打出来才看得见：

```python
import csv
import io

raw = open("expenses.csv", "rb").read()
print(raw[:3])
print(csv.DictReader(io.StringIO(raw.decode("utf-8"))).fieldnames)
```
```text
b'\xef\xbb\xbf'
['\ufeff日期', '分类', '金额']
```

`b'\xef\xbb\xbf'` 是 UTF-8 的 BOM，Excel 存「CSV UTF-8」时写在文件最前面。它解码后是一个看不见的字符 `\ufeff`，被 `csv` 当成表头的一部分，于是第一列的真名是 `\ufeff日期`——屏幕上看着和 `日期` 一模一样。

我把编码换成 `utf-8-sig` 就好了：解码时吃掉开头那个 BOM，没有 BOM 的普通 UTF-8 文件也照样读。

```python
with PATH.open(encoding="utf-8-sig", newline="") as handle:
```

这里有个我原先想反的地方：BOM 不是「文件坏了」。前三个字节是合法的 UTF-8，`open(encoding="utf-8")` 不会报错，它只是让**第一个字段名**多一个字符。所以症状是 `KeyError`，不是 `UnicodeDecodeError`。

## 先读最后一行，再往上找自己那段

这段 traceback 值得拆一遍，因为它的读法和我最初的直觉相反：

1. **最后一行**是异常类型和消息，这里是 `KeyError: '日期'`，先看它。
2. `File` 块从上到下是**从外到内**的调用顺序：`<module>` 调 `main`，`main` 调 `summarize`，`summarize` 第 15 行炸了。现场是最后一个 `File` 块，不是第一个。
3. 下面缩进的那行源码就是出错时的表达式；3.11 还会用 `^` 指到具体那一段。这里的 `~~~~^^^^^^` 圈住 `row["日期"]`，说明 `row` 在，错的是取键。
4. 最后一个块不一定在自己的文件里。上面这个还算走运，最后一块落在 `report.py`；换成 GBK 文件时，最后一块是 `csv.py` 甚至 `<frozen codecs>`——那时往上找最近一个属于自己代码的块。
5. 出现 `During handling of the above exception, another exception occurred` 是异常链：上面那段是原始异常，下面那段是处理它时又抛的。先看上面那段。

## 同一份数据的 GBK 版本，报的是另一句话

同事后来又发了一份，她那台机器上老系统导出的，同样叫 `expenses.csv`。脚本里换成 `utf-8-sig` 也救不了它，报的是：

```text
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc8 in position 0: invalid continuation byte
```

把文件当字节打开，前四个字节是 `b'\xc8\xd5\xc6\xda'`，不是任何 UTF-8 序列的开头。

`0xc8 0xd5` 在 GBK 里是「日」，在 UTF-8 里不是合法序列。这句报错的措辞值得记准确：

- `invalid continuation byte` 说的是**起始字节后面那个字节**不合法（`0xd5` 应该以 `10` 开头，它不是）；
- 位置 `0` 指的是**起始字节**的位置，不是坏的那个字节的位置；
- 如果开头就已经是 `0xff` 这种不可能作起始字节的字节，消息会变成 `invalid start byte`。

所以编码要写成参数，别靠猜：GBK 用 `gbk`，普通 UTF-8 用 `utf-8`，Excel 导出的 UTF-8 用 `utf-8-sig`。判断靠 `read_bytes()` 加看前几个字节，比在编辑器里切编码可靠。

<!-- run -->
```python
import csv
import io

TEXT = "日期,分类,金额\n2026-10-01,书籍,45.00\n"

gbk = TEXT.encode("gbk")
print(gbk[:4])
print("日".encode("utf-8"))
try:
    gbk.decode("utf-8")
except UnicodeDecodeError as error:
    print(error)

excel = TEXT.encode("utf-8-sig")
print(excel[:3])
reader = csv.DictReader(io.StringIO(excel.decode("utf-8")))
print(reader.fieldnames)

fixed = csv.DictReader(io.StringIO(excel.decode("utf-8-sig")))
print(fixed.fieldnames)
```
```text
b'\xc8\xd5\xc6\xda'
b'\xe6\x97\xa5'
'utf-8' codec can't decode byte 0xc8 in position 0: invalid continuation byte
b'\xef\xbb\xbf'
['\ufeff日期', '分类', '金额']
['日期', '分类', '金额']
```

这段里没有文件，编码是从同一串文字切出来的字节，所以能逐字对照：同一行「日期」，GBK 是 `0xc8 0xd5`，UTF-8 是 `0xe6 0x97 0xa5`，而 Excel 导出的那份前面多了三个 BOM 字节。

## 'None' 是四个字符

BOM 修好后，脚本跑起来，然后停在另一句：

```text
ValueError: could not convert string to float: 'None'
```

`float()` 收到的是字符串 `'None'`。报错消息里带引号，所以它是四个字符，不是空值 `None`。表格里那一格，导出程序把缺失的金额写成了文本。

排查时用 `!r` 能立刻把这两种东西分开：

```python
amount_text = "None"
print(repr(amount_text))
print(repr(None))
```
```text
'None'
None
```

处理不是把它变成 0。金额空着是「这笔记账没填金额」，0 是「花了 0 元」，混在一起，合计和均值都会错，而且错得很安静。沿用的是 19 课的做法：跳过，按原因计数，最后一起打印。

## 报错被我吞掉之后，报告变成了 0.00

这是这次最贵的半小时。GBK 那份文件又出现时，我不想再看到 `UnicodeDecodeError`，就给 `load_rows` 包了一层：

```python
def load_rows(path):
    try:
        with path.open(encoding="utf-8-sig", newline="") as handle:
            return list(csv.DictReader(handle))
    except Exception:
        return []
```

脚本不崩了，输出变成：

```text
书籍: 0.00
餐饮: 0.00
交通: 0.00
合计: 0.00
读取 0 行，跳过 0 行：{}
```

我当时的判断是「这个月没记账」，不是「读文件失败了」。因为异常被 `except Exception` 吞掉后，`return []` 和「文件里真的没有数据」在程序里完全等价，traceback 也不留任何痕迹。

9 课说过不要写 `except Exception`，我还是写了。现在我的规矩是：**只有知道自己能从那个异常里恢复，才捕获它**。读失败不是可恢复的情况，它意味着后面每个数字都不可信。真要让程序继续，就把异常信息打出来再决定，或者只捕获 `UnicodeDecodeError` 并明确写下「换哪个编码重试」，而不是把整段逻辑塞进 `try` 里返回空。

## 三行代码共用了一个列表

后面我想按固定的三个分类分桶，写了这行：

```python
buckets = [[]] * 3
buckets[0].append("书籍")
print(buckets)
```
```text
[['书籍'], ['书籍'], ['书籍']]
```

`[[]] * 3` 做的是把**同一个列表对象的引用**复制三份，不是新建三个空列表。要三个独立的，用推导式：

```python
buckets = [[] for _ in range(3)]
```

同一件事也解释了用 `[[0] * 3] * 3` 生成三行表格时，改一行三行一起变。

## 默认参数只在 def 那一行求值一次

分桶之后我把汇总改成带默认参数的形式，想在测试里连叫两次比较结果：

```python
def summarize(rows, totals={}):
    for row in rows:
        totals[row[1]] = totals.get(row[1], 0) + row[2]
    return totals


rows = [("2026-10-01", "书籍", 45.0)]
first = summarize(rows)
second = summarize(rows)
print(first is second)
print(second)
```
```text
True
{'书籍': 90.0}
```

两次拿到的是**同一个字典**：默认值 `{}` 在 `def` 执行时创建了一次，之后每次调用都用它。所以第二次是在第一次的结果上继续加。

修法还是老一套：默认写 `None`，函数体里判空再建。

```python
def summarize(rows, totals=None):
    if totals is None:
        totals = {}
```

不能写成 `if not totals`：调用者传进来一个空字典、想让你往里填，这么写会把他那个字典丢掉，最后他手上还是空的。

## is 比的不是内容

我在过滤里写过 `if row["分类"] is "书籍"`，以为它跟 `==` 是一回事。那一行过滤永远不成立，书全部漏掉。

```python
a = "书籍"
b = "书" + "籍"
print(a is b, a == b)
c = "".join(["书", "籍"])
print(a is c, a == c)
```
```text
True True
False True
```

`a is b` 是 `True`，因为 `"书" + "籍"` 在编译期被折叠成同一个常量对象——这是 CPython 当前实现的行为，不是语言保证。运行期拼出来的 `c` 是另一个对象，`is` 立刻变成 `False`。

从 CSV 里读出来的 `"书籍"` 属于后者，和字面量不是同一块内存。我在 3.11.5 上写 `row["分类"] is "书籍"` 时，解释器还丢了一句 `SyntaxWarning: "is" with a literal. Did you mean "=="?`。

规矩：`is` 只用于 `None`、`True`、`False` 和自己造的哨兵对象，比字符串一律 `==`。

## 计数器和 global

`main` 里加个计数，运行时报：

```text
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

函数里只要出现对 `count` 的赋值（`count += 1` 算赋值），Python 就把整个函数里的 `count` 当局部变量；`+=` 先读后写，读的时候它还没被赋过值。

三种处理：传参返回（首选）；真改模块级变量用 `global count`；改外层函数的变量用 `nonlocal count`。列表的 `append` 不触发这个问题，因为那是「读名字再调方法」，没有重新绑定。

## 什么时候别再用 print

| 调用 | 结果 |
| --- | --- |
| `print(f"amount={amount!r}")` | 当场看到值，`!r` 带引号，`'None'` 和 `None` 一眼分开 |
| `breakpoint()` | 停在那一轮，用 `p amount` 看变量，不用改代码重跑 |
| `logging.info(...)` | 程序不中断，能带级别、能落盘，事后还能翻 |

两条纪律：提交前删掉 `breakpoint()` 和调试用的 `print`；测试环境里设 `PYTHONBREAKPOINT=0`，让遗留的 `breakpoint()` 直接跳过。

## 症状 → 先看哪

| 报错或现象 | 先看什么 |
| --- | --- |
| `KeyError: '日期'`，但这一列确实存在 | 打印 `reader.fieldnames`，找 `\ufeff`、空格这类看不见的字符；UTF-8 带 BOM 就换 `utf-8-sig` |
| `UnicodeDecodeError: invalid continuation byte` | `read_bytes()[:4]` 看真实字节；起始字节像 UTF-8、后面那个不像，按 `gbk` / `gb18030` 试 |
| `UnicodeDecodeError: invalid start byte` | 开头就不是 UTF-8，直接换编码，别用 `errors="ignore"` 硬读 |
| `ValueError: could not convert string to float: 'None'` | 值是带引号的字符串，用 `repr()` / `!r` 打出来看引号 |
| 报告数字变成 0，或比预期少一截 | 搜 `except` 后面的 `pass` / `return []`；被吞的异常不会出现在 traceback 里 |
| `AttributeError: module 'csv' has no attribute ...` | `python -c "import csv; print(csv.__file__)"`，看是不是被同名文件顶了 |
| `UnboundLocalError ... where it is not associated with a value` | 函数里对这个名字有赋值；改传参返回，或用 `global` / `nonlocal` |

## 跑一遍

把上面几条都落实之后，`report.py` 长这样。数据内嵌在 `SAMPLE` 里，编码用 `utf-8-sig`，坏金额跳过并计数，最后用断言把结果钉住——断言比多打几行 `print` 更早发现问题，而且不用人眼看。

<!-- run -->
```python
import csv
import io
from collections import Counter

SAMPLE = (
    "日期,分类,金额\n"
    "2026-10-01,书籍,45.00\n"
    "2026-10-01,餐饮,32.50\n"
    "2026-10-02,书籍,None\n"
    "2026-10-02,交通,18.00\n"
)


def load_rows(raw, encoding):
    return list(csv.DictReader(io.StringIO(raw.decode(encoding))))


def summarize(rows, month="2026-10"):
    totals = {}
    skipped = Counter()
    for row in rows:
        if not (row.get("日期") or "").startswith(month):
            skipped["不是这个月"] += 1
            continue
        category = (row.get("分类") or "").strip()
        amount_text = (row.get("金额") or "").strip()
        try:
            amount = float(amount_text)
        except ValueError:
            skipped["金额不是数字"] += 1
            continue
        totals[category] = totals.get(category, 0.0) + amount
    return totals, skipped


def main():
    rows = load_rows(SAMPLE.encode("utf-8-sig"), "utf-8-sig")
    totals, skipped = summarize(rows)
    for category, amount in sorted(totals.items()):
        print(f"{category}: {amount:.2f}")
    print(f"合计: {sum(totals.values()):.2f}")
    print(f"读取 {len(rows)} 行，跳过 {sum(skipped.values())} 行：{dict(skipped)}")
    return totals, skipped


totals, skipped = main()
assert totals == {"书籍": 45.0, "餐饮": 32.5, "交通": 18.0}
assert skipped == Counter({"金额不是数字": 1})
print("断言通过")
```
```text
书籍: 45.00
交通: 18.00
餐饮: 32.50
合计: 95.50
读取 4 行，跳过 1 行：{'金额不是数字': 1}
断言通过
```

和一开始那一版比，改了三处：编码变成参数，调用时明确传 `utf-8-sig`；只捕获 `ValueError`，其它异常照原样抛；`main` 返回结果，断言写在入口下面。输出里的顺序是 `sorted` 的字符序，不是金额序。
