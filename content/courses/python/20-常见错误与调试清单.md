# 20 · 常见错误与调试清单

## 这一课你要会

- 认出可变默认参数、`is` 与 `==`、浅拷贝、闭包晚绑定这四个"看起来对"的坑；
- 处理 `UnicodeDecodeError`，分清 UTF-8、GBK 与 BOM；
- 解释模块名冲突、导入路径和循环导入分别会报什么错；
- 从上往下读 traceback，说出错在哪个文件、哪一行、哪次调用；
- 在 `print` 与 `breakpoint()` / `pdb` 之间做选择，不把异常吞掉。

## 为什么

报错不是"程序坏了"，是 Python 在告诉你它在哪一步没看懂。但新手最常做的两件事——把异常 `pass` 掉、在每一行加 `print`——都会把线索弄丢：前者让错误消失，后者让输出淹没。

这一课是一张排错清单。先认模式，再决定用眼睛看、用断言验，还是进调试器。**目标不是背下所有异常名，而是遇到报错时知道下一步查什么。**

## 讲解

### 一、可变默认参数

```python
def add_tag(tag, tags=[]):      # 错
    tags.append(tag)
    return tags

print(add_tag("python"))        # ['python']
print(add_tag("csv"))           # ['python', 'csv']
```

默认值在 `def` 执行时**只创建一次**，之后每次调用都共用同一个列表。正确写法：

```python
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
```

用 `None` 表示"没传"，在函数体里新建列表。**不要写 `tags=[]` 再 `tags = tags.copy()`**——那只是把 bug 藏起来，调用者传进来的列表仍会被意外修改。

### 二、`is` 与 `==`

```python
a = [1, 2]
b = [1, 2]
a == b      # True：值相等
a is b      # False：不是同一个对象
```

- `==` 比较**值**，调用对象的 `__eq__`；
- `is` 比较**身份**，即是不是同一块内存。

规则：`is` 只用于 `None`、`True`、`False` 和你自己定义的哨兵对象。整数和字符串的"缓存"是 CPython 的实现细节，不要依赖：

```python
x = 256
y = 256
x is y      # 这里可能是 True，但这是实现细节

x = "hello world"
y = "hello world"
x is y      # 同样不能拿来判断字符串相等
```

`x == None` 能跑，但自定义了 `__eq__` 的类可能让结果不符合预期；`is None` 没有这个问题。

### 三、浅拷贝与深拷贝

```python
grid = [[0] * 3] * 3        # 错：三行是同一个列表
grid[0][0] = 1
print(grid)                 # [[1, 0, 0], [1, 0, 0], [1, 0, 0]]

grid = [[0] * 3 for _ in range(3)]   # 对：每行新建
grid[0][0] = 1
print(grid)                 # [[1, 0, 0], [0, 0, 0], [0, 0, 0]]
```

`list(a)`、`a[:]`、`copy.copy(a)` 都是**浅拷贝**：只复制外层容器，里面的可变对象仍共享。

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

shallow[0][0] = 99
print(original)   # [[99, 2], [3, 4]]：内层被一起改了
print(deep)       # [[1, 2], [3, 4]]：深拷贝不受影响
```

判断标准：**容器里还有可变对象（list、dict、set、自定义对象）时，浅拷贝不够**。如果内层全是数字、字符串、元组这类不可变值，浅拷贝就够用，不必上 `deepcopy`。

### 四、闭包晚绑定

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])     # [2, 2, 2]，不是 [0, 1, 2]
```

闭包捕获的是**变量**，不是创建时的值。循环结束后 `i` 是 2，所以每个 lambda 看到的都是 2。三种修法：

```python
# 1) 用默认参数把当前值绑进去
funcs = [lambda i=i: i for i in range(3)]

# 2) 用 functools.partial
from functools import partial

def make(i):
    return i

funcs = [partial(make, i) for i in range(3)]

# 3) 再包一层函数，让每层有自己的变量
def make_func(i):
    return lambda: i

funcs = [make_func(i) for i in range(3)]
```

同样的问题会出现在"循环里注册回调"：如果回调在循环结束后才执行，它看到的是最后一个值。

### 五、编码：UTF-8、GBK 与 BOM

```python
open("data.txt", encoding="utf-8")
```

**永远显式写 `encoding`。** 不写时，Python 3.12 及更早版本用系统的区域编码；中文 Windows 上通常是 `cp936`（GBK 的超集）。同一份代码在你的机器上正常、在别人的机器上乱码，往往就是这里。

看到这个报错：

```text
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd6 in position 0: invalid continuation byte
```

`0xd6` 不是合法的 UTF-8 起始字节，文件很可能是 GBK/GB2312。处理顺序：

1. 先确认文件真实编码，不要靠猜；
2. 用正确的编码读：`encoding="gbk"`；
3. 读完立刻转成 UTF-8 保存，别让 GBK 在程序里继续传；
4. `errors="replace"` 只适合"先看一眼内容"，不适合数据管道——它会悄悄用 `�` 替换掉读不出来的字节。

BOM 是另一类问题。Excel 导出的 UTF-8 CSV 开头可能带 `\ufeff`，第一个列名会变成 `"\ufeffdate"`。读的时候用 `utf-8-sig` 会自动去掉 BOM；写的时候用 `utf-8`，不要主动写 BOM。

还要分清两件事：**文件编码**和**终端输出编码**是分开的。文件读对了但 `print` 乱码，问题在 stdout 的编码；设置 `PYTHONIOENCODING=utf-8` 或 `PYTHONUTF8=1` 只影响后者，不能替代 `open(..., encoding=...)`。

### 六、导入路径与模块名冲突

最常见的怪事：你写了一个 `random.py`，然后 `import random` 之后 `random.randint` 不存在。

原因是 **`sys.path[0]` 是脚本所在目录**（用 `-m` 运行时是当前目录），Python 会先在这里找模块。你的 `random.py` 把标准库的 `random` 顶掉了。

不要用这些名字命名自己的文件：

```text
random.py  csv.py  json.py  types.py  email.py  test.py
```

同样的坑还有：

- **包内相对导入**：`from .storage import load` 只能在包里用；直接 `python package/main.py` 会把 `main.py` 当顶层脚本，相对导入报 `ImportError`。正确方式是 `python -m package.main`。
- **循环导入**：`a.py` 导入 `b.py`，`b.py` 又导入 `a.py`，常见报错是 `ImportError: cannot import name 'x' from partially initialized module 'a'`。修法是把共用部分移到第三个模块，或者把导入挪进函数里（后者是权宜之计）。
- **虚拟环境不对**：`ModuleNotFoundError: No module named 'requests'` 先看 `python -c "import sys; print(sys.executable)"`，确认用的是哪个解释器，再看包是不是装到了别处。

### 七、异常被吞

```python
try:
    value = int(raw)
except Exception:
    pass                    # 错：数据坏了、代码 bug 了，全都看不见
```

正确写法是**只捕获你知道怎么处理的异常**，并且留下信息：

```python
import sys

skipped = 0
try:
    value = int(raw)
except ValueError as error:
    skipped += 1
    print(f"跳过 {raw!r}: {error}", file=sys.stderr)
```

三条规则：

1. 能写 `ValueError` 就不写 `Exception`；
2. 捕获后要么处理，要么记录并重新 `raise`，不要既不上报也不处理；
3. 裸 `except:` 还会接住 `KeyboardInterrupt` 和 `SystemExit`，几乎总是错的。

需要"记录后继续抛"时：

```python
try:
    run()
except OSError as error:
    print(f"读取失败: {error}", file=sys.stderr)
    raise
```

### 八、缩进与作用域

Python 用缩进划分代码块。**同一文件里混用 Tab 和空格会直接 `TabError`**，但"多一个空格"不会报错，只会让某行悄悄跑到别的分支里。把编辑器设成 4 个空格、显示空白字符，能省掉这类排查。

作用域更容易骗人：

```python
count = 0

def bump():
    count += 1      # UnboundLocalError

bump()
```

函数里只要出现对 `count` 的**赋值**，Python 就把 `count` 当成局部变量，`+=` 先读后写，读的时候它还不存在。修法：

- 传进去、返回出来：`def bump(count): return count + 1`（首选）；
- 真要改模块级变量，用 `global count`（少用）；
- 嵌套函数改外层函数的变量，用 `nonlocal count`。

列表的 `append` 不触发这个问题，因为它是"读变量再调方法"，没有重新绑定名字。

### 九、怎么读 traceback

```text
Traceback (most recent call last):
  File "report.py", line 42, in <module>
    main()
  File "report.py", line 36, in main
    records, skipped = load(reader)
  File "report.py", line 18, in load
    amount = float(row["amount"])
ValueError: could not convert string to float: 'None'
```

读法：

1. **最后一行**是异常类型和消息：`ValueError`，值是 `'None'`。这是"发生了什么"。
2. **从下往上看调用栈**：最下面一个 `File` 块是出错的位置（`report.py` 第 18 行，在 `load` 里），上面是"谁调用了它"。
3. 看 `line 18` 下方缩进的那行源码，就是实际执行的表达式。
4. 如果出现 `During handling of the above exception, another exception occurred` 或 `The above exception was the direct cause`，说明有异常链：先看最前面的原始异常，再看最后的异常，中间的通常是"包装时又错了"。
5. Python 3.11+ 还会用 `^` 标出具体表达式，位置比行号更细。

常见误读：只看第一行 `Traceback (most recent call last)`，或者只看最上面的 `File`。**最上面的调用栈是入口，最下面的才是现场。**

### 十、print 还是 pdb

| 场景 | 首选 | 理由 |
| --- | --- | --- |
| 确认有没有走到某一行 | `print` | 一行就够，改完即删 |
| 看一个值在几步之间怎么变 | `print` 加标签 | 比反复断点快 |
| 状态多、循环深、不知道哪次出错 | `breakpoint()` | 能停下来慢慢看 |
| 服务在跑、不能中断 | `logging` | 有级别、有时间、能落盘 |

`breakpoint()` 从 Python 3.7 起可用，等价于 `import pdb; pdb.set_trace()`。常用命令：

```text
l        列出当前位置附近的代码
n        执行下一行（不进入函数）
s        进入当前函数
c        继续运行到下一个断点
p expr   打印表达式的值
pp expr  格式化打印
b 文件:行 下断点
q        退出调试
```

也可以用 `python -m pdb script.py` 从第一行开始调试。调试器适合"状态太多、print 会刷屏"的场景；如果只是确认一个值，`print(f"amount={amount!r}")` 更快。`!r` 会显示引号和转义，能看出 `"None"` 和 `None` 的区别。

两条纪律：提交前删掉 `breakpoint()` 和调试用的 `print`；测试环境里可以设 `PYTHONBREAKPOINT=0`，让遗留的 `breakpoint()` 直接跳过。

### 完整例子：四个坑一起跑

下面把可变默认参数、闭包晚绑定、浅拷贝与深拷贝放在一段里，输出可以直接对照。

<!-- run -->
```python
import copy


def add_wrong(item, bucket=[]):
    bucket.append(item)
    return bucket


def add_right(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket


print(add_wrong("a"))
print(add_wrong("b"))
print(add_right("a"))
print(add_right("b"))

funcs = [lambda: i for i in range(3)]
print([func() for func in funcs])

fixed = [lambda i=i: i for i in range(3)]
print([func() for func in fixed])

grid = [[0] * 2] * 2
grid[0][0] = 1
print(grid)

grid_ok = [[0] * 2 for _ in range(2)]
grid_ok[0][0] = 1
print(grid_ok)

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)
shallow[0][0] = 99
print(original)
print(deep)

assert add_right("x") == ["x"]
assert add_right("y") == ["y"]
print("断言通过")
```
```text
['a']
['a', 'b']
['a']
['b']
[2, 2, 2]
[0, 1, 2]
[[1, 0], [1, 0]]
[[1, 0], [0, 0]]
[[99, 2], [3, 4]]
[[1, 2], [3, 4]]
断言通过
```

重点对照：

- 第 1、2 行：`add_wrong` 的默认列表跨调用累积；第 3、4 行 `add_right` 每次都新建。
- 第 5、6 行：闭包捕获的是循环结束后的 `i`；默认参数 `i=i` 把当时的值绑住了。
- 第 7、8 行：`[[0] * 2] * 2` 复制的是引用，改一行三行一起变；列表推导每轮新建。
- 第 9、10 行：浅拷贝后改内层，原对象跟着变；深拷贝不受影响。

没有输出 `is` 和编码的例子，因为它们的表现依赖具体对象和本机环境，不适合做逐字断言；上面用文字说明了判断标准。

## 常见误区

### 误区：`is` 比 `==` 快，所以比较都用 `is`

**你以为**：`is` 不比较内容，肯定更快，拿来判断相等没问题。
**其实**：`is` 判断的是"是不是同一个对象"。两个内容相同的列表、字符串、数字完全可能是不同对象，`is` 会给你 `False`。小整数和短字符串的缓存只是实现细节。
**怎么验证**：`a = [1, 2]; b = [1, 2]`，分别打印 `a == b` 和 `a is b`；再把字符串换成运行时拼接的结果，看 `is` 是否稳定。

### 误区：`copy.copy` 就是完全复制

**你以为**：只要用了 `copy`，改副本就不会影响原对象。
**其实**：`copy.copy` 是浅拷贝，只复制外层；内层的列表、字典仍共享。嵌套结构要么 `deepcopy`，要么显式重建。
**怎么验证**：复制一个 `[[1, 2], [3, 4]]`，改副本的 `[0][0]`，再打印原对象。

### 误区：`except Exception: pass` 让程序更稳

**你以为**：不报错就是稳。
**其实**：它把"数据有问题"和"代码写错了"一起吞掉。程序继续跑，但结果是错的，而且没有任何线索。真正的稳是**捕获预期的异常、记录原因、让不该发生的异常暴露出来**。
**怎么验证**：在 `try` 里故意写一个拼错的变量名，看 `pass` 是否把它也吞了；再换成具体异常，看它是否按预期抛出。

### 误区：报错要看第一行

**你以为**：`Traceback` 开头就是错误原因。
**其实**：第一行只是"以下是调用栈"。真正的异常类型和消息在**最后一行**，出错位置在最下面的 `File` 块。
**怎么验证**：随便制造一个 `1 / 0`，从下往上读一遍，确认 `ZeroDivisionError` 在哪一行。

### 误区：print 调试太低级，必须上调试器

**你以为**：用 `print` 不专业，`pdb` 才是正经调试。
**其实**：工具要看场景。确认"有没有走到这里""这个值是多少"，`print` 最快；状态多、循环深、要逐行看变量变化，才值得进 `pdb`。用调试器逐行跑十次，不如两行 `print` 定位。
**怎么验证**：同一个问题分别用 `print` 和 `breakpoint()` 查一次，比较花的时间。

## 小结

- 可变默认参数用 `None` 占位，函数体里再新建；
- `==` 比值，`is` 比身份，`is` 只留给 `None` / `True` / `False` / 哨兵；
- 浅拷贝只复制外层，嵌套可变结构要 `deepcopy` 或重建；
- 闭包捕获变量而非值，循环里用默认参数或 `partial` 绑定；
- 文件读写永远显式 `encoding`，BOM 用 `utf-8-sig`；
- 别用标准库名命名自己的文件，包内用 `python -m package.module` 运行；
- 只捕获具体异常，跳过要计数，不要 `pass`；
- traceback 从最后一行和最下面的 `File` 块读起；
- 简单流程用 `print`，复杂状态用 `breakpoint()`，长期运行用 `logging`。
