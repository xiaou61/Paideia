# 01 · 环境与第一行代码

## 敲 `python hello`，它说找不到文件

我在这台 Windows 上（Python 3.11.5，python.org 的安装包）建了个文件夹 `C:\py01`，里面放一个 `hello.py`：

```python
print('hello')
```

`cd C:\py01` 之后，我敲的是 `python hello`——少打了 `.py`，因为我以为解释器会替我补上。屏幕上出现的是这一整段：

```text
C:\Users\Lenovo\AppData\Local\Programs\Python\Python311\python.exe: can't open file 'C:\\py01\\hello': [Errno 2] No such file or directory
```

前面那串 `Python311\python.exe` 不是我的项目路径，是解释器自己的位置——报错格式是「谁在抱怨：抱怨什么」。抱怨的内容是：找不到 `C:\py01\hello` 这个文件（窗口里反斜杠会打成双的 `\\`，那是它把路径当字面文本输出，读的时候按单个看）。末尾的 `[Errno 2]` 是系统给的错误号，2 就是「没有这个文件」。

我的第一反应是装坏了。排除这件事只要一条命令：

```text
python --version  →  Python 3.11.5
py --version      →  Python 3.11.5
```

`py` 是 python.org 安装包一起装上的启动器，和 `python` 指向同一个解释器。两个都答得出来，说明环境是好的，问题在文件名。

## 缺的不是扩展名

补上 `.py`，`python hello.py` 就打印出了 `hello`。

但我以为的因果是错的。我当时认定「Python 要求文件必须是 .py」，验证方法很简单：把 `hello.py` 复制一份、改名成 `hello`（没有扩展名），再敲 `python hello`——它照样打印 `hello`，退出码 0。改成 `hello.txt`、内容不动，`python hello.txt` 也照样跑。

所以那条报错的意思不是「扩展名不对」，而是「这个目录里没有叫 `hello` 的文件」。至少 3.11.5 是这样：拿到什么名字就找什么名字，找不到就按这个名字报错，不会拿你打的名字去猜后缀。扩展名对 `python` 没有约束，只对你自己、编辑器和 Windows 的图标有意义。

顺带一个平台差别：Windows 的文件名不分大小写，`Hello.py` 和 `hello.py` 是同一个；macOS 和 Linux 分。在那两个系统上，明明看得见文件却报找不到，先试着把大小写改成和文件名一模一样。

## 同一个文件，换个目录就找不到

文件还在 `C:\py01\`，我 `cd C:\`，再敲同一条 `python hello.py`：

```text
C:\Users\Lenovo\AppData\Local\Programs\Python\Python311\python.exe: can't open file 'C:\\hello.py': [Errno 2] No such file or directory
```

注意报错里那段路径变了：它现在去 `C:\` 底下找这个名字，而不是在 `C:\py01\` 里。它没有「记住我上次在哪个目录」这回事——相对路径永远从终端的当前目录算。这条报错里最好用的信息就是那整段路径，先读完它，再问「这个目录里真的有这个文件吗」。

确认自己在哪：Windows 上用 `Get-Location`（PowerShell）或 `cd`（cmd，不带参数就打印当前目录），macOS 和 Linux 用 `pwd`。不想切目录也行，直接给全路径，从哪儿敲都能跑：

```text
python C:\py01\hello.py
hello
```

## 三行 print，一行一条

现在 `hello.py` 写成三行：

<!-- run -->
```python
print('hello')
print('world')
print('bye')
```
```text
hello
world
bye
```

一条 `print(...)` 打印一样东西再换行，从上到下按顺序执行；两次运行的结果一模一样。屏幕上有这三行、退出码是 0，这次就算真的跑通了——不是「没报错就算过」，而是「我预期的那三行确实出现了」。

退出码是程序结束时交给终端的那个数字，0 表示正常结束。PowerShell 里敲完命令再看一眼 `$LASTEXITCODE` 就能对上，不用靠猜。

三种结果对照一下，退出码是我在这台机器上逐个试出来的：

| 你看到的结果 | 发生了什么 | 退出码 |
| --- | --- | --- |
| 三行输出，跟你写的一致 | 跑通了 | 0 |
| `can't open file ... [Errno 2]` | 解释器根本没打开你的文件 | 2 |
| `SyntaxError` 加一段箭头 | 文件打开了，但读不懂 | 1 |

## 报错里哪一行是结论

把第 2 行的右括号删掉，再跑 `python hello.py`：

```text
  File "C:\py01\hello.py", line 2
    print('world'
         ^
SyntaxError: '(' was never closed
```

这个格式值得背下来：`File "..."` 和 `line N` 说的是位置，最后一行 `SyntaxError: ...` 说的是结论。先看最后一行，再回头看位置。`'(' was never closed` 直译是「左括号一直没被关上」，箭头指在 `(` 上——它告诉你该补的是这个括号。

有一件事跟我原本的直觉相反：**第 1 行的 `print('hello')` 一个字都没打印出来**。上面那段输出里没有 `hello` 混在前面。原因是 `SyntaxError` 发生在整份文件被翻译的阶段，翻译就没过，第一行也没机会执行。所以看到「第 2 行有问题」，不要理解成「第 1 行跑成功了」。

换个手滑方式：括号用中文输入法打，变成全角的那一对：

```text
  File "C:\py01\hello.py", line 2
    print（'world'）
         ^
SyntaxError: invalid character '（' (U+FF08)
```

两个括号在屏幕上长得几乎一样，但码位不同：全角是 `U+FF08`，半角是 `U+0028`。Python 直接把码位打出来，这已经比一句「语法错误」具体多了。这段输出是我把终端的输出编码固定成 UTF-8 之后复制的；不固定的话，报错里那个全角符号本身会显示成乱码——那是终端解码的问题，不是你代码的问题。

## 症状 → 先看哪

| 你屏幕上的样子 | 先看哪 |
| --- | --- |
| `can't open file 'C:\\py01\\hello'`，路径结尾没有 `.py` | 命令里的文件名少打了扩展名。`python` 只按名字找文件，不会补 |
| `can't open file 'C:\\hello.py'`，路径里有 `.py` 但目录不对 | 当前目录：`Get-Location` / `pwd`；不在那儿就 `cd` 过去，或者写全路径 |
| `SyntaxError: '(' was never closed` | 报错给的行号就是那个没配对的左括号所在行，去补右括号 |
| `SyntaxError: invalid character '（' (U+FF08)` | 这一行用了中文标点的括号或引号，切回英文标点重打 |
| 屏幕上出现 `>>>`，敲命令报 `File "<stdin>"` 加 `invalid syntax` | 你进的是交互模式：`>>>` 后面只收 Python 语句，不收终端命令。敲 `exit()` 退出来，回到文件模式 |
| 退出码 0，屏幕上什么都没有 | 文件跑了，但没有任何 `print` 被执行。先确认它不是空文件（我测了一个空文件：退出码 0、零输出），再确认你打开的是不是那个文件 |

空文件那条我实测过，但「退出码 0」本身只说明进程正常结束，不说明它执行了哪几行——它能帮你排除「崩了」，确认不了「跑对了」。

## 还差的

- **安装过程没走一遍**。这台机器上 Python 是现成的，我没在一台干净的 Windows 上从安装器走一遍（包括那个 `Add python.exe to PATH` 勾选框），所以「装完敲 `python` 提示命令不存在」该怎么修，得你自己看安装器的说明或另找资料。
- **编辑器一个字没提**。VS Code 右上角那个三角形、PyCharm 的绿色播放键，背后调的就是 `python xxx.py`；但它们各自要选「解释器」这一步，我没测过。
- **macOS / Linux 没实测**。文里 `pwd` 和「文件名分不分大小写」那两句是按常识写的，本机只有 Windows，没跑过。也正因为这台机器的 `python3` 指向的是另一个项目 venv 里的包装脚本，我没写「Windows 上 `python3` 一样能用」这种话。
- **输出编码没查透**。这台机器 `chcp` 是 936，Python 往管道写中文时按 GBK 编码，所以重定向到文件、或者在某些终端里会看到乱码。cmd、Windows Terminal、VS Code 内置终端各是什么行为，我只验了这一种组合。
- **虚拟环境和装包没碰**。现在跑 `pip install` 会装到全局；要不要隔离、怎么隔离，是第 12 课（模块与包）的事，这课一个包都没装。
