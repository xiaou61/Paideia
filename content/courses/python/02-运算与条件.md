# 02 · 运算与条件

## 三行都和手算不一样，却都不报错

```python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print(-7 // 2)
```

```text
0.30000000000000004
False
-4
```

第一行是精度，第二行是第一行的后果，第三行是「整除」的定义。三个都能跑通、都不警告，只是结果跟脑子里的不一样。

这一课就顺着这三行往下走。

## 三种除法，其中一种会咬人

| 写法 | 名字 | `7` 和 `2` 的结果 | 说明 |
| --- | --- | --- | --- |
| `7 / 2` | 真除法 | `3.5` | 永远返回小数 |
| `7 // 2` | 整除 | `3` | 向下取整 |
| `7 % 2` | 取余 | `1` | 7 除以 2 余 1 |

`//` 是**向下**取整，不是「截掉小数部分」：`-7 // 2` 是 `-4`，不是 `-3`。负数分页、坐标换算、时间对齐都会撞上这个差一。

`%` 跟着 `//` 一起定义，所以负数的余数也反直觉：`-7 % 2` 是 `1`，不是 `-1`。C 和 Java 里是 `-1`——**这条差异会让从 Java 转过来的人写错取模**。判断奇偶用 `x % 2 == 0` 在负数上仍然成立，这就是它设计成这样的原因。

## 小数不是精确的

计算机用二进制存小数，`0.1` 在二进制里是无限循环小数——就像 `1/3` 在十进制里是 `0.333…`。存不下，只能存近似值。两个近似值相加，误差就露出来：`0.30000000000000004`。

所以小数之间不要用 `==`。三种做法，我按推荐顺序排：

```python
abs(a - b) < 1e-9                      # 自己写容差
math.isclose(a, b)                     # 标准库
int(round(price * 100))                # 金额换成分，全程整数
```

`math.isclose` 有一个坑：**默认用的是相对容差，跟 0 比会失效**。实测 `math.isclose(1e-12, 0)` 是 `False`（相对容差乘的是 0），要比 0 附近就得显式给绝对容差：

```python
math.isclose(x, 0, abs_tol=1e-9)       # 和 0 比
```

金额场景我更倾向第三种：把元换成分、全程用整数，最后显示时再除 100。误差从根上没有，也顺手避开了浮点累加（`0.1+0.2+0.3` 得 `0.6000000000000001`，`== 0.6` 是 `False`）。

## 真值：什么算「假」

`if` 后面不一定非要跟比较。Python 把这几样当假：`0`、`0.0`、`""`、`None`、`False`、空的容器（空列表、空字典、空元组、空集合）。**其它都是真**——`1`、`"x"`、`[0]`（含一个 0 的列表）、`{"a": 1}` 全为真。

这条要记牢，因为「非空列表也是假」是很常见的误读。空容器判断用 `if items:` 是惯用写法，等价于 `if len(items) > 0:`，但少一次调用。

## 短路不是优化，是保护

- `and`：两边都真才真；左边假，右边不求值。
- `or`：有一边真就真；左边真，右边不求值。
- `not`：取反。

「左边假右边不求值」这条可以用来兜底：

```python
x = 0
if x != 0 and 10 / x > 2:      # x 是 0 时右边根本不执行，不会 ZeroDivisionError
    print("大于 2")
else:
    print("跳过")
```

```text
跳过
```

反过来说，顺序写错就会炸：`if 10 / x > 2 and x != 0:` 先算了除法，保护来不及生效。**能挡住异常的那个条件要写在前面。**

两行 `is` 的结果值得单独说：

- `a = 1000` 和 `b = 1000` 写在**同一个代码块**里，编译器把两个相同的常量复用成同一个对象，`a is b` 是 `True`；
- `c = int("1000")` 是运行时造出来的新对象，`a is c` 是 `False`。

也就是说「`a is b` 对 1000 是不是 `True`」取决于**代码怎么写**，不取决于数值。`is` 比的是「是不是同一个对象」，`==` 比的才是值。判断相等永远用 `==`；`is` 只用在 `None`、`True`、`False` 这类单例上。

## 两个容易写反的地方

**`=` 是赋值，`==` 是比较。** `if x = 1:` 在 Python 里直接 `SyntaxError`，跑不起来——这是好事。会「静默通过」的是 C/C++（`if (x = 1)` 把 1 赋给 x 再拿它当真值），Java 反而会拦你（`javac` 报 `incompatible types: int cannot be converted to boolean`）。

**`elif` 有顺序。** 如果先写 `score >= 60` 再写 `score >= 90`，90 分也落进「及格」——第一个满足的条件执行完，整条 `if` 就结束了，后面的分支连看都不看。所以条件从最严格的开始写。
