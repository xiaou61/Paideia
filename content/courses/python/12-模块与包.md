# 12 · 模块与包

## 这一课你要会

- 分清 `import x`、`from x import y`、`import x as z` 三种写法的后果；
- 知道 `if __name__ == "__main__":` 到底在防什么；
- 建一个虚拟环境、装一个依赖，并说清为什么不能直接往系统 Python 里装；
- 把一个文件夹变成一个包，让别人能 `from todo import service`。

## 为什么

前面十一课都是"一个文件从头跑到尾"。真实项目里，代码会被拆成很多文件，还会用到别人写的库。

不搞清 `import`，会遇到三类怪事：脚本在自己目录里能跑、换个目录就 `ModuleNotFoundError`；`import todo` 之后程序莫名其妙执行了一遍；装了包但 `python` 说找不到——因为装到了另一个 Python 里。

## 讲解

### 三种 import 的差别

```python
import math                 # 引入整个模块，用 math.sqrt(16)
from math import sqrt       # 只引入一个名字，用 sqrt(16)
import numpy as np          # 引入并起别名，用 np.array(...)
```

**优先用哪种**：标准库的少数函数用 `from math import sqrt` 读起来最干净；第三方大库用 `import numpy as np`，因为 `np.` 前缀能提醒你"这是外部依赖"。

避免 `from module import *`：它会把模块里所有公开名字倒进当前命名空间，两个模块有同名函数时会互相覆盖，而且你根本不知道某个名字是从哪来的。

### `if __name__ == "__main__":` 在防什么

每个 Python 文件都有一个隐藏变量 `__name__`：

- 被**直接运行**时，`__name__` 等于 `"__main__"`；
- 被**别的文件 import** 时，`__name__` 等于模块自己的名字（比如 `"service"`）。

所以这个写法：

```python
def add(a, b):
    return a + b

if __name__ == "__main__":
    print(add(1, 2))
```

意思是：**被 import 时只定义函数，不打印**；只有直接 `python service.py` 时才执行最后那行。

不写这个判断的后果很具体：测试文件 `import service` 的那一刻，`service.py` 里的测试代码、`print`、甚至 `input()` 全会跟着执行。这叫"import 有副作用"，是新手最常见的坑之一。

### 跑一遍

<!-- run -->
```python
import math
from math import sqrt
import statistics as st

print(sqrt(16))
print(math.sqrt(16))
print(st.mean([1, 2, 3]))
print(f"math.__name__ = {math.__name__}")
print(f"__name__ = {__name__}")
```
```text
4.0
4.0
2
math.__name__ = math
__name__ = __main__
```

三种写法都能拿到同一个 `sqrt`，区别只是用不用前缀、名字叫不叫别名。最后两行是 `__name__` 的取值：被 import 的模块是模块名（这里是 `math`），直接运行的脚本才是 `"__main__"`。

### 模块从哪找

`import` 时 Python 按 `sys.path` 的顺序找文件，大致是：

1. 当前脚本所在目录；
2. 环境变量 `PYTHONPATH` 列出的目录；
3. 安装目录里的 `site-packages`（第三方库就装在这）。

**"在我电脑上能跑"最常见的原因**：脚本在项目根目录，从根目录运行就能找到同级的 `service.py`；换到别的目录运行，第 1 条就不成立了。

### 包：带 `__init__.py` 的文件夹

```text
todo/
  __init__.py
  storage.py
  service.py
main.py
```

`todo/` 里放了 `__init__.py`（可以是空文件），它就成为一个**包**，于是：

```python
from todo import service
from todo.service import add
```

`__init__.py` 的作用是标记"这是一个包"，也可以在里面写包的公开接口。**不建议**在 `__init__.py` 里写大量导入——那会让 `import todo` 变慢，还容易造成循环导入。

### 虚拟环境：每个项目一套依赖

```bash
python -m venv .venv          # 创建
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install requests          # 只装进这个环境
pip freeze > requirements.txt # 记下版本
```

为什么必须这么做：不同项目可能要 `requests` 的不同版本，全装进系统 Python 会打架；系统 Python 还常被操作系统自己用，弄坏了很麻烦。

**判断有没有生效**：激活后命令行前面会出现 `(.venv)`，`pip -V` 显示的路径在 `.venv` 里。装完包仍提示找不到，八成是**装到了另一个 Python**（比如 `pip` 指向系统 Python，而 `python` 指向虚拟环境）。

## 常见误区

### 误区：`import` 只是把代码复制进来，没副作用

**你以为**：引入一个文件而已。
**其实**：被 import 的模块会整个执行一遍顶层代码。所以库里不要写 `print`、不要读文件、不要 `input()`，除非放在 `if __name__ == "__main__":` 里。
**怎么验证**：建两个文件，在 a 里 `print("hi")`，b 里 `import a`，运行 b 看是不是打印了 hi。

### 误区：虚拟环境是可选项

**你以为**：反正只有一个项目。
**其实**：项目一多、或者系统自带的工具依赖某个版本时，冲突会以"昨天还好好的"的形式出现。
**怎么验证**：`pip list` 看看系统环境里已经装了多少东西，再想想其中哪些是别的项目装的。

### 误区：包就是文件夹

**你以为**：建个目录就能 import。
**其实**：没有 `__init__.py` 的目录在旧版本里不是包；现代 Python 有"命名空间包"能勉强工作，但行为容易和预期不同。老实放一个空的 `__init__.py`。

## 小结

`import` 会用当前目录、`PYTHONPATH`、`site-packages` 依次找模块。被 import 的模块会执行顶层代码，所以入口要包在 `if __name__ == "__main__":` 里。依赖装进虚拟环境，并用 `requirements.txt` 记版本。包是带 `__init__.py` 的文件夹。
