# 13 · 类型注解

## mypy 先报了两条，脚本却照跑

本机 Python 3.11.5、mypy 2.4.1，文件叫 `demo.py`：

```python
from dataclasses import dataclass


def double(value: int) -> int:
    return value * 2


print(double("abc"))


@dataclass
class User:
    id: int
    name: str
    email: str | None = None


def find_name(users: list[User], user_id: int) -> str | None:
    for user in users:
        if user.id == user_id:
            return user.name
    return None


name = find_name([], 1)
print(name.upper())
```

`python -m mypy demo.py` 的输出：

```text
demo.py:8: error: Argument 1 to "double" has incompatible type "str"; expected "int"  [arg-type]
demo.py:26: error: Item "None" of "str | None" has no attribute "upper"  [union-attr]
Found 2 errors in 1 file (checked 1 source file)
```

但 `python demo.py` 不会在 `double("abc")` 那一行停下：它先打印 `abcabc`，走到最后一行才抛 `AttributeError: 'NoneType' object has no attribute 'upper'`。

我第一次看到这个对比时的判断是「注解只是元数据，运行时没人看」。这句话只对了一半，而且后半句是错的。解释器确实不会在函数调用时按注解做类型检查，但注解对象会留在 `__annotations__` 里，库可以在运行时读它。`@dataclass` 就是例子：它在类定义时读 `User.__annotations__`，据此生成 `__init__`、`__repr__`、`__eq__`。准确的说法是「注解不强制类型检查」，不是「运行时没人看」。

`@dataclass` 是装饰器，第 15 课才讲。这里先照抄这一行，知道它会在类定义后加工这个类就够了。

## double("abc") 为什么能跑

```python
def double(value: int) -> int:
    return value * 2


print(double("abc"))
print(double.__annotations__)
```

`double("abc")` 返回 `abcabc`，因为 `"abc" * 2` 本来就是合法的字符串重复。注解没有拦它，也没有把它转成 `int`。`double.__annotations__` 里存的是 `{'value': <class 'int'>, 'return': <class 'int'>}`——注解是真实存在的对象，只是函数调用路径不拿它做校验。

这就是为什么来自 JSON、表单、文件的数据仍要自己判断。类型检查器只能看代码里写死的类型，看不到运行时从外面进来的字符串。

## 返回 None 时，str | None 才说实话

把 `find_name` 写成真的会查：

```python
def find_name(users: list[User], user_id: int) -> str | None:
    for user in users:
        if user.id == user_id:
            return user.name
    return None


name = find_name([], 1)
print(name.upper())
```

`find_name([], 1)` 返回 `None`，下一行在运行时抛：

```text
AttributeError: 'NoneType' object has no attribute 'upper'
```

mypy 在运行前就会指出这一行：`Item "None" of "str | None" has no attribute "upper"`。修法不是把 `-> str` 改成 `-> str | None` 就完事，而是调用处真的处理 `None`：

```python
if name is not None:
    print(name.upper())
else:
    print("没找到，不调用 upper")
```

`Optional[str]` 和 `str | None` 是同一件事：值可能是 `None`。它不是「这个参数可以不传」。参数能不能省略只看默认值：

```python
def greet(name: str | None) -> str:
    return "你好" if name is None else name


greet()          # TypeError: greet() missing 1 required positional argument: 'name'
greet(None)      # 你好
```

`greet` 的注解允许 `None`，但没给默认值，所以不传参数仍然报 `TypeError`。想两者都有，写 `def greet(name: str | None = None)`。

## 常用结构和 Callable 的 import

```python
from collections.abc import Callable

name: str = "小明"
scores: list[int] = [90, 85]
by_name: dict[str, int] = {"小明": 90}
point: tuple[float, float] = (1.0, 2.0)
maybe: str | None = None


def apply(value: int, transform: Callable[[int], str]) -> str:
    return transform(value)


def show(value: int) -> str:
    return f"#{value}"


print(apply(3, show))
```

`list[int]` 从 Python 3.9 起可用，`str | None` 从 3.10 起可用。老代码里的 `typing.List[int]` 是历史写法，新代码不用再写。

`Callable` 不是内置名字，忘了 `from collections.abc import Callable` 就会得到 `NameError: name 'Callable' is not defined`。`Callable[[int], str]` 读作「收一个 `int`、返回 `str` 的可调用对象」；`apply(3, show)` 能通过，因为 `show` 符合这个形状。

## @dataclass 省的是样板，不是校验

```python
from dataclasses import dataclass


@dataclass
class User:
    id: int
    name: str
    email: str | None = None


class ManualUser:
    def __init__(self, id, name, email=None):
        self.id = id
        self.name = name
        self.email = email


first = User(1, "小明")
second = User(1, "小明")
print(first)
print(first == second)

manual_first = ManualUser(1, "小明")
manual_second = ManualUser(1, "小明")
print(manual_first == manual_second)
```

输出：

```text
User(id=1, name='小明', email=None)
True
False
```

`@dataclass` 自动生成 `__init__`、`__repr__`、`__eq__`。手写版没有 `__repr__`，`print(manual_first)` 打出来是 `<__main__.ManualUser object at 0x...>`，地址每次不同；两个手写对象也没有值相等语义，所以 `manual_first == manual_second` 是 `False`。这不是「等价于手写」，是省掉了三份样板。

字段顺序规则要单独说清：没有默认值的字段必须写在有默认值的字段前面。比如把 `email` 放到有默认值的字段后面，类定义时会报 `TypeError: non-default argument 'email' follows default argument`。它保证的是「默认参数不会挡在非默认参数前面」，**不保证你传参的语义顺序**。下面这行不报错：

```python
print(User("小明", 1))
# User(id='小明', name=1, email=None)
```

`id` 收到字符串、`name` 收到整数，运行时安静地接受。mypy 会报两条 `arg-type`，但运行时不报。所以 dataclass 不是「参数顺序保险」，只是把字段声明集中到类顶部。

什么时候用：这个类主要是一包字段，行为很少。方法多、需要维护不变量、需要封装状态时，普通类更清楚。

## 从 dict 升级到 dataclass

一开始用 `{"id": 1, "name": "小明"}` 没问题。出现下面任一情况就该换：

- 同一个 dict 在三个以上地方被拼出来；
- 你开始写 `user["nmae"]` 这种拼写错误，并且运行到一半才发现；
- 需要给这组字段加校验或默认值。

`dict[str, int]` 只约束键和值的类型，不知道你打算用哪些键。普通 dict 的键名拼写错误，类型检查器发现不了；dataclass 的属性名写错才会被 mypy 抓。想描述固定键名，需要 `TypedDict`，本文没讲。

```python
from collections.abc import Callable
from dataclasses import dataclass


def double(value: int) -> int:
    return value * 2


@dataclass
class User:
    id: int
    name: str
    email: str | None = None


def find_name(users: list[User], user_id: int) -> str | None:
    for user in users:
        if user.id == user_id:
            return user.name
    return None


print(double("abc"))
print(double.__annotations__)
print(User.__annotations__)

name = find_name([], 1)
try:
    print(name.upper())
except AttributeError as error:
    print(f"{type(error).__name__}: {error}")

if name is not None:
    print(name.upper())
else:
    print("没找到，不调用 upper")

first = User(1, "小明")
second = User(1, "小明")
print(first)
print(first == second)

swapped = User("小明", 1)
print(swapped)


class ManualUser:
    def __init__(self, id, name, email=None):
        self.id = id
        self.name = name
        self.email = email


manual_first = ManualUser(1, "小明")
manual_second = ManualUser(1, "小明")
print(manual_first == manual_second)


def apply(value: int, transform: Callable[[int], str]) -> str:
    return transform(value)


def show(value: int) -> str:
    return f"#{value}"


print(apply(3, show))


def greet(name: str | None) -> str:
    return "你好" if name is None else name


try:
    greet()
except TypeError as error:
    print(f"TypeError: {error}")
print(greet(None))
```
```text
abcabc
{'value': <class 'int'>, 'return': <class 'int'>}
{'id': <class 'int'>, 'name': <class 'str'>, 'email': str | None}
AttributeError: 'NoneType' object has no attribute 'upper'
没找到，不调用 upper
User(id=1, name='小明', email=None)
True
User(id='小明', name=1, email=None)
False
#3
TypeError: greet() missing 1 required positional argument: 'name'
你好
```

`double.__annotations__` 和 `User.__annotations__` 打印的是真实的注解对象；`User.__annotations__` 里 `email` 显示成 `str | None`。`User("小明", 1)` 没有报错，说明字段顺序规则只约束定义，不约束你传入的语义顺序。最后一段 `greet()` 的 `TypeError` 被 `try/except` 接住了，所以整段脚本正常退出。

## 还差的

- **泛型没讲**。`list[int]` 只是容器参数化；自己写 `Stack[T]`、`TypeVar`、`Protocol` 都没覆盖，遇到「这个函数接受任何有 `close()` 的对象」时还写不出来。
- **mypy 只跑了单文件默认配置**。`strict`、`ignore_missing_imports`、在 `pyproject.toml` 里固定版本、CI 里什么时机跑，都没讲；本文也没有证明 mypy 能抓住你项目里的所有问题。
- **运行时校验只到「自己写 if」**。pydantic、dataclass 的 `__post_init__` 校验、从 JSON 反序列化时怎么报错，都没展开。注解本身不会替你校验外部数据。
- **3.9 兼容没处理**。本文按 3.10+ 写 `str | None`；要兼容 3.9 得用 `Optional` 或 `from __future__ import annotations`，两种写法与运行时行为的差别没讲。
