# 13 · 类型注解

## 这一课你要会

- 给变量、函数参数、返回值写类型标注，并知道它们**运行时不起检查作用**；
- 用 `list[int]`、`dict[str, int]`、`str | None` 表达常见结构；
- 分清 `None`、`Optional` 与"这个参数可以不传"是三件不同的事；
- 用 `dataclass` 定义只装数据的类，不手写 `__init__`。

## 为什么

Python 不写类型也能跑。那为什么真实项目几乎都在写？

因为**类型标注不是给解释器看的，是给人（和你未来的自己）看的**。一个函数签名 `def parse(raw: str) -> dict[str, int]:` 一眼就说清"要字符串、还你一个字符串到整数的映射"。没有它，你得把函数体读完才知道。

更实际的好处是：编辑器能补全、能在你传错类型时标红，`mypy`/`pyright` 能在运行前抓出"这里可能返回 None"。

## 讲解

### 注解不改变运行时

```python
def double(value: int) -> int:
    return value * 2

print(double("abc"))   # abcabc —— 没报错
```

类型标注**只是元数据**，Python 运行时不会因为它拦下错误调用。真正的检查发生在两个地方：编辑器（补全与提示）和类型检查工具（`mypy` / `pyright`）在开发阶段跑。

这是一条重要认知：**不要以为写了 `-> int` 就安全了**。运行时该校验的（来自用户输入、文件、网络的数据）仍要自己 `if` 判断。

### 常见结构的写法

```python
name: str = "小明"
scores: list[int] = [90, 85]
by_name: dict[str, int] = {"小明": 90}
point: tuple[float, float] = (1.0, 2.0)
maybe: str | None = None          # Python 3.10+
callback: Callable[[int], str]    # 需要一个参数、返回字符串的函数
```

`list[int]` 这种写法（而不是 `List[int]`）从 Python 3.9 起可用。老代码里的 `typing.List` 是历史写法，新代码不必再用。

### `str | None` 的含义比你想的严格

```python
def find(user_id: int) -> str | None:
    ...
```

读法是：**调用者必须处理"可能没有"的情况**。

```python
name = find(1)
print(name.upper())      # 类型检查器会警告：None 没有 upper

if name is not None:
    print(name.upper())  # 这样才是安全的
```

`Optional[str]` 和 `str | None` 是同一件事。**别写成 `str | None = "默认值"` 就以为安全**——默认值只影响"没传参"的情况，函数体里仍可能主动返回 `None`。

### `dataclass`：只装数据的类

```python
from dataclasses import dataclass

@dataclass
class User:
    id: int
    name: str
    email: str | None = None
```

它会自动生成 `__init__`、`__repr__`、`__eq__`。等价于你手写：

```python
class User:
    def __init__(self, id, name, email=None):
        self.id = id
        self.name = name
        self.email = email
```

什么时候用：**这个类主要是"一包字段"**，行为很少。如果它有很多方法、需要封装状态，还是老老实实写普通类。

注意 `@dataclass` 的字段顺序：没有默认值的字段必须写在有默认值的字段前面，否则定义时直接报错。这其实是在帮你避免"参数顺序一错就静默赋值错"的问题。

### 跑一遍

<!-- run -->
```python
from __future__ import annotations

from dataclasses import dataclass


def double(value: int) -> int:
    return value * 2


print(double("abc"))
print(double.__annotations__)


@dataclass
class User:
    id: int
    name: str
    email: str | None = None


first = User(1, "小明")
second = User(1, "小明")
print(first)
print(first == second)
```
```text
abcabc
{'value': 'int', 'return': 'int'}
User(id=1, name='小明', email=None)
True
```

`double("abc")` 安静地返回了 `"abcabc"`，说明注解没有参与运行时检查——它只是记在 `__annotations__` 里的元数据。`@dataclass` 自动生成的 `__repr__` 与 `__eq__` 让打印和相等比较都不用自己写。第一行的 `from __future__ import annotations` 是为了让 3.9 也能写 `str | None`（3.10 起不需要）。

### 从 dict 升级到 dataclass 的时机

一开始用 `{"id": 1, "name": "小明"}` 没问题。出现下面任一情况就该换：

- 同一个 dict 在三个以上地方被拼出来；
- 你开始写 `user["nmae"]` 这种拼写错误并且运行到一半才发现；
- 需要给这组字段加校验或默认值。

类型检查器发现不了 dict 的键名拼写错误，但它能发现 dataclass 的属性名错误。

## 常见误区

### 误区：加了类型标注就等于有了运行时校验

**你以为**：传错类型会报错。
**其实**：Python 不会检查。来自外部的数据（JSON、表单、文件）仍要自己验证，或者用 pydantic 之类的库。
**怎么验证**：写 `def f(x: int): ...` 然后 `f("abc")`，看它是否安静地跑完。

### 误区：`Optional[str]` 的意思是"这个参数可以不传"

**你以为**：可选参数。
**其实**：它只表示"值可能是 None"。参数可不可以省略由**默认值**决定（`email: str | None = None` 才是两者都有）。
**怎么验证**：写一个只标了 `Optional` 但没有默认值的参数，调用时不传，看是否报 `TypeError`。

### 误区：所有函数都该写满类型

**你以为**：越全越好。
**其实**：一次性的探索脚本写满类型只是噪音。**给别人用的、要活很久的代码**才值得写；尤其是公共接口、数据模型、跨模块调用的函数。

## 小结

类型标注是给人看、给编辑器与检查器用的，运行时不管。用 `list[int]`、`dict[str, int]`、`str | None` 表达结构。`Optional` 讲的是"可能是 None"，不是"可以不传"。数据类用 `@dataclass`，省掉一堆样板。
