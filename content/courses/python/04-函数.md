# 04 · 函数

## 同一个 60 分，既及格又不及格

```python
score = 60

if score >= 60:
    print("第一次判断：及格")
else:
    print("第一次判断：不及格")

if score > 60:
    print("第二次判断：及格")
else:
    print("第二次判断：不及格")

if score >= 60:
    print("第三次判断：及格")
else:
    print("第三次判断：不及格")
```

```text
第一次判断：及格
第二次判断：不及格
第三次判断：及格
```

我盯着中间那两行看了半分钟：同一个 `60`，第一次及格，第二次不及格。Python 没算错，是我把同一套判断抄了三份，第二份的边界从 `>=` 改成了 `>`。

这种错不会抛异常。程序继续跑，报表里多一个「不及格」，你得回头翻三处代码才知道哪一处跟另外两处不一样。把它收进一个函数，边界就只有一处：

```python
def passed(score):
    return score >= 60

print(passed(60))
print(passed(59))
```

```text
True
False
```

`return` 把结果交回调用处；函数体里不再直接 `print`，这样同一个判断既能用来打印，也能用来计数、筛选、写进文件。

## 参数传进去的到底是什么

先看两个函数。它们都接收一个列表，一个往里加元素，一个给形参重新赋值：

```python
def add_bonus(scores):
    scores.append(5)

def reset(scores):
    scores = [0]

scores = [80, 90]
add_bonus(scores)
print('add_bonus 之后:', scores)

reset(scores)
print('reset 之后:', scores)
```

```text
add_bonus 之后: [80, 90, 5]
reset 之后: [80, 90, 5]
```

`add_bonus` 改了外面的列表，`reset` 没有。区别在于函数体里对形参做了什么，而不在于「参数是不是副本」：

- 调用时，形参 `scores` 和实参 `scores` 绑定到**同一个列表对象**；
- `scores.append(5)` 改的是这个对象，所以外面看得见；
- `scores = [0]` 只是把形参这个名字重新绑到一个新列表，原来的对象没动。

Python 的通行说法是**按对象引用传递**，也叫**按赋值传递**：调用发生时，形参被赋值为实参指向的那个对象。之后形参是换名字还是改对象，结果完全不同。

`reset` 如果真想改原列表，就得对同一个对象动手，比如 `scores.append(0)`；但函数偷偷改调用方传进来的列表，调用方很难判断数据是什么时候变的。更清楚的做法是返回一个新列表，让调用方决定要不要接。

## 默认参数只在定义时算一次

下面这个函数想给每个学生单独记一份成绩：

```python
def add_score(score, scores=[]):
    scores.append(score)
    return scores

print('第一次:', add_score(80))
print('第二次:', add_score(90))
print('显式传空列表:', add_score(70, []))
print('再来一次:', add_score(60, []))
```

```text
第一次: [80]
第二次: [80, 90]
显式传空列表: [70]
再来一次: [60]
```

第二次调用打印出 `[80, 90]`，但这次只传了 `90`。`80` 是上一次留下的。后两次显式传了 `[]`，结果分别是 `[70]` 和 `[60]`：这两个空列表是调用处新建的，不共用。

原因在 `def` 执行时：`[]` 这个表达式当场求值一次，结果挂在函数对象的默认值上。以后调用**省略 `scores`** 时，形参直接绑定这个已经存在的列表。它不是每次调用新建的。注意边界：只有省略该参数的调用才共用这个列表；显式传 `[]` 的调用不会。

修法是默认值用 `None`，进函数再建列表：

```python
def add_score(score, scores=None):
    if scores is None:
        scores = []
    scores.append(score)
    return scores

print('修好后第一次:', add_score(80))
print('修好后第二次:', add_score(90))
```

```text
修好后第一次: [80]
修好后第二次: [90]
```

这里必须写 `is None`，不能写 `if not scores`：调用方显式传一个空列表时，`not scores` 为真，你会把它的列表换掉，`append` 就加到了另一个对象上。

列表这样，后面会遇到的字典也一样：判断标准是「这个默认值会不会被改」，会就别直接放在 `def` 那一行。

## 函数里的名字，什么时候是局部的

函数体里赋值的名字默认是局部的：

```python
def make_total():
    total = 0
    total = total + 90
    return total

print(make_total())
```

```text
90
```

函数外面再写 `print(total)` 会得到 `NameError: name 'total' is not defined`。`total` 是函数里的局部名字，函数返回后就没了。读取外面已经存在的变量可以；要在函数里重新绑定外面的名字，得写 `global`，但优先用返回值，别让函数偷偷改外面的状态。

循环里的函数容易踩另一个坑：

```python
funcs = []
for i in range(3):
    def show():
        return i
    funcs.append(show)

for f in funcs:
    print(f())
```

```text
2
2
2
```

循环本身不产生新作用域，`i` 是模块级的名字。`show` 的函数体里写的是「去读 `i`」，不是「把当时的 `i` 存下来」。循环结束时 `i` 是 2，三个函数调用时读到的都是 2。

这里在循环体里反复定义 `show`，每次都是一个新函数对象，但函数体没有保存 `i` 的值。`show` 在模块顶层，读的是全局 `i`；如果函数里再定义函数并捕获外层变量，那就是闭包，第 15 课才讲。现在先记住这个现象：函数体读到的是变量在调用时的值。

如果你在别处看到更短的写法 `[lambda: i for i in range(3)]`，结论一样是 `[2, 2, 2]`，但作用域细节不同：3.x 里列表推导式有自己的作用域，`i` 不会泄漏到外层——在模块顶层写完推导式再 `print(i)` 是 `NameError`。普通 `for` 循环不一样：在模块顶层写，循环结束后 `i` 留在外层，值是 2。lambda 和列表推导式都在后面的课，这里不用记语法，只要别把「推导式结束后还能读到 i」当成事实。

## 什么时候该抽函数

三个判断，按顺序问：

1. 同一段逻辑是不是已经在第二个地方出现？出现第二次就该抽，不要等到第五次。
2. 这段代码是不是需要一句注释才能说清？把那句话变成函数名，注释就可以删。
3. 这段代码有没有独立的输入和输出？有，就能单独喂几组数据验证。

不必为了「每个函数都短」而拆成一堆两行的函数。拆得太碎，读代码的人要在调用链里跳来跳去，复杂度只是换了地方。

## 跑一遍

<!-- run -->
```python
def passed(score):
    return score >= 60

print(passed(60))
print(passed(59))

def add_score(score, scores=None):
    if scores is None:
        scores = []
    scores.append(score)
    return scores

print(add_score(80))
print(add_score(90))

def average(scores):
    if not scores:
        return 0
    total = 0
    for score in scores:
        total = total + score
    return total / len(scores)

print(average([80, 90, 100]))
print(average([]))

funcs = []
for i in range(3):
    def show():
        return i
    funcs.append(show)

for f in funcs:
    print(f())
```
```text
True
False
[80]
[90]
90.0
0
2
2
2
```

`average([])` 返回 `0` 而不是报错，这是一个设计决定：调用方只想要一个数字，空列表按 0 分处理。换成「空列表必须报错」也合理，但要把规则写进函数名或文档里，别让调用方猜。
