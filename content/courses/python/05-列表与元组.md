# 05 · 列表与元组

## b = a 之后，a 也多了 100

```python
a = [80, 90]
b = a
b.append(100)
print(a)
```

```text
[80, 90, 100]
```

我原来以为 `b = a` 是把 `a` 复制一份给 `b`。实际打印出来，`a` 也多了 `100`。`b` 不是副本，它只是同一个列表的第二个名字。

这类 bug 麻烦的地方是它不报错：你以为改的是 `b`，结果 `a` 跟着变，等发现时已经不知道是谁先动的手。

## 赋值、切片和 list()

先把两个动作分开：

```python
a = [80, 90]
b = a
b.append(100)
print(a)
print(b)

c = a[:]
c.append(110)
print(a)
print(c)
```

```text
[80, 90, 100]
[80, 90, 100]
[80, 90, 100]
[80, 90, 100, 110]
```

`b = a` 没有创建新列表，只是让 `b` 指向 `a` 指向的那个对象。`c = a[:]` 创建了一个新列表，`c.append(110)` 不会影响 `a`。

`a[:]` 是切片。切片的基本规则是左闭右开：

```python
items = ['a', 'b', 'c', 'd']
print(items[0], items[-1])
print(items[1:3])
print(items[:2])
print(items[2:])
```

```text
a d
['b', 'c']
['a', 'b']
['c', 'd']
```

`items[1:3]` 含下标 1 和 2，不含 3。`items[:2]` 省略起点，从 0 开始；`items[2:]` 省略终点，一直取到末尾。下标从 0 开始，`-1` 是最后一个元素。

`list(a)` 也能得到一个新列表，效果和 `a[:]` 一样：外层是新的，元素还是原来那些对象。对 `[80, 90]` 这种元素是数字的列表，两者都够用。

## 常用操作：谁返回 None，谁返回元素

```python
numbers = [3, 1, 2]

removed = numbers.pop()
print(removed)
print(numbers)

result = numbers.sort()
print(result)
print(numbers)
```

```text
2
[3, 1]
None
[1, 3]
```

`pop()` 取走最后一个元素，并把那个元素返回，所以 `removed` 是 `2`。`sort()` 原地排序，返回 `None`，所以 `result` 是 `None`。

不要把「原地修改」和「返回 None」直接画等号。`append`、`insert`、`remove`、`sort`、`reverse` 返回 `None`；`pop` 返回被取走的元素。写 `x = numbers.sort()` 会让 `x` 变成 `None`，这是 `sort` 的返回值，不是排序失败。

其余几个操作：

- `append(x)` 加到末尾；`insert(i, x)` 插到下标 `i`；
- `pop()` 取走末尾，`pop(i)` 取走下标 `i`，返回被取走的元素；
- `remove(x)` 删掉第一个等于 `x` 的元素，找不到会抛 `ValueError`；
- `sort()` 原地排序并返回 `None`；`sorted(numbers)` 返回新列表，原列表不动。

`len()`、`sum()`、`max()`、`min()` 是内置函数，不是列表方法，写法是 `sum(numbers)`，不是 `numbers.sum()`。

## 浅拷贝只复制第一层

对 `[80, 90]` 这种平面列表，`a[:]` 已经够独立。元素本身是列表时，事情变得不一样：

```python
outer = [[1], [2]]
shallow = outer[:]
shallow[0].append(9)
print(outer)
print(shallow)

shallow[1] = [8]
print(outer)
print(shallow)
```

```text
[[1, 9], [2]]
[[1, 9], [2]]
[[1, 9], [2]]
[[1, 9], [8]]
```

`shallow = outer[:]` 只新建了外层列表，两个内层列表还是 `outer` 和 `shallow` 共用的。`shallow[0].append(9)` 改的是共用的小列表，所以 `outer[0]` 也变成 `[1, 9]`。

但 `shallow[1] = [8]` 只是把 `shallow` 的第二个槽换成新列表，`outer[1]` 没动。**改内层对象**和**替换外层槽位**是两件事。

要连内层一起复制，用 `copy.deepcopy`：

```python
import copy

original = [[1], [2]]
deep = copy.deepcopy(original)
deep[0].append(9)
print(original)
print(deep)
```

```text
[[1], [2]]
[[1, 9], [2]]
```

第 12 课才讲 `import`。这里先照抄 `import copy`，把它放在脚本最上面；不写这一行，后面会报 `NameError: name 'copy' is not defined`。

什么时候需要 `deepcopy`？看两件事，不是看嵌套几层：

1. 内层有没有可变对象（列表、字典等）；
2. 你接下来会不会改内层。

两个都成立才需要。只读、或者只整体替换内层，浅拷贝就够。`deepcopy` 会把整个对象图重新走一遍，元素越多、嵌套越多，代价越大；这一课没有做基准测试，所以不给你「快多少」的数字。

## 元组：逗号才是构造，不是圆括号

```python
print(type((1)))
print(type((1,)))
print(type(()))
print(type((1, 2)))
```

```text
<class 'int'>
<class 'tuple'>
<class 'tuple'>
<class 'tuple'>
```

`(1)` 只是给 `1` 加了一对括号，类型还是 `int`。构造单元素元组要写 `(1,)`，那个逗号不能省。空元组 `()` 是特例，它确实是元组。

元组的「不可变」是浅层的：外层槽位不能换，里面的可变对象照样能改。

```python
t = ([1],)
t[0].append(2)
print(t)
```

```text
([1, 2],)
```

`t[0] = [3]` 会报 `TypeError: 'tuple' object does not support item assignment`，因为那是换外层槽位；`t[0].append(2)` 改的是内层列表，元组管不到。

可哈希就是能算出一个哈希值，能放进字典的键或集合里；列表不能哈希，因为列表能改。`hash((1, 2))` 能算，`hash(([1],))` 不能。

元组能当字典的键，但有个条件：**元组里的每个元素都必须可哈希**。元素全是数字、字符串时可以。下面用到一个字典，第 6 课才正式讲；这里只看键的位置能不能放 `(1, 2)`。

```python
scores = {(1, 2): '起点', (5, 6): '终点'}
print(scores[(1, 2)])
print(hash((1, 2)) == hash((1, 2)))
```

```text
起点
True
```

元素里只要有列表，元组本身就不可哈希：

```python
hash(([1],))
```

```text
TypeError: unhashable type: 'list'
```

所以「元组可哈希」不能单独说，得补上「元素全部可哈希」：`(状态码, 内容)` 只有在两个值都可哈希时才能当键，`([1], 2)` 不行。

元组适合表达「这几个值是一组的、顺序有意义」：`(x, y)` 坐标、`(状态码, 内容)` 返回值。想表达「这组值不打算换」时用元组；要增删改，用列表。

- 没讲字典和集合，所以「可哈希」只解释了元组这一侧，字典键的完整规则在第 6 课。
- 没讲 `copy` 模块的 `copy.copy`、自定义类的 `__deepcopy__`，也没做深拷贝的性能测试。
- 没讲排序的 `key` 参数、稳定性和混合类型比较；`sorted` 现在只能按默认顺序。
