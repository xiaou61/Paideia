# 10 · 类与对象

## 两个学生共用了一份成绩单

本机 CPython 3.11.5。下面这段是我用来复现这个问题的写法：

<!-- run -->
```python
class Student:
    scores = []

    def __init__(self, name):
        self.name = name

    def add(self, score):
        self.scores.append(score)

    def show(self):
        print(f"{self.name}: {self.scores}")


lin = Student("小林")
zhou = Student("小周")
lin.add(92)
zhou.add(55)
lin.show()
zhou.show()
print(lin.scores is zhou.scores)
```
```text
小林: [92, 55]
小周: [92, 55]
True
```

我原本以为 `scores = []` 是给每个学生准备的初始值。实际不是：在这个脚本里，执行到 `class Student:` 时，类体跑一次，`scores = []` 也只建了一个列表；之后每次 `Student(...)` 不会再执行类体里的那行赋值，而是创建新对象并调用 `__init__`。`lin.scores` 和 `zhou.scores` 都回退到类上找，读到的是同一个列表，所以 `zhou.add(55)` 也改了 `lin` 看到的成绩。

这就是类要解决的问题：把 `name`、`scores` 和对它们的操作（`add`）放在同一个对象上，不用再拿一堆散着的变量和函数手工配对。

## 把列表的创建放进 `__init__`

写在类体里、方法外面的 `scores = []` 是**类属性**：它挂在类对象上，只有一份。`Student("小林")` 创建一个**实例**（也就是对象），`lin`、`zhou` 都是 `Student` 的实例。类里定义这一组属性和方法；实例是具体创建出来的那一个。

类属性常用来放所有实例都一样、且不该改的值（例如 `MAX_SIZE = 100`）；大写只是约定，Python 不会阻止你改它。

要让每个学生有自己的成绩单，列表必须在每次创建实例时新建：

<!-- run -->
```python
class Student:
    def __init__(self, name):
        self.name = name
        self.scores = []

    def add(self, score):
        self.scores.append(score)


lin = Student("小林")
zhou = Student("小周")
lin.add(92)
zhou.add(55)
print(lin.scores)
print(zhou.scores)
print(lin.scores is zhou.scores)
```
```text
[92]
[55]
False
```

`__init__` 是初始化方法，`Student(...)` 会自动调用它；你不需要在创建对象后再手动调一次。`Student(...)` 会创建对象并自动调用 `__init__`，把新对象作为第一个参数传进去。所以 `self` 就是刚创建的那个对象，`self.scores = []` 每执行一次 `__init__` 就新建一个列表。

## 赋值和原地修改不是一回事

如果类里还留着 `scores = []`，只在某个实例上写 `self.scores = [...]`，并不会改掉类上的列表；它只是给这个实例挂了一个同名属性，把类属性遮住。下面这版还保留类属性，只给 `a` 单独赋值：

<!-- run -->
```python
class Student:
    scores = []

    def __init__(self, name):
        self.name = name

    def add(self, score):
        self.scores.append(score)


a = Student("小林")
b = Student("小周")

a.scores = [100]
a.add(60)
b.add(55)

print(a.scores)
print(b.scores)
print(Student.scores)
```
```text
[100, 60]
[55]
[55]
```

`a.scores = [100]` 和方法里写 `self.scores = [100]` 是同一条赋值规则，只是方法外用的是变量名 `a`。赋值之后，`a` 有了自己的 `scores`；`a.add(60)` 改的是这份。`b` 没有自己的 `scores`，仍然去类上找，`b.add(55)` 改的是类上的列表，所以 `Student.scores` 变成 `[55]`。

准确地说：

- **读** `self.scores`（普通属性）：先找实例自己的属性；实例没有，才去类上找。
- **赋值** `self.scores = ...`：写实例自己的属性，不会改类属性；同名类属性被遮住。
- **原地修改** `self.scores.append(...)`：先按上面的规则找到列表，再改那个列表。如果找到的是类属性，所有没有自己 `scores` 的实例都会看到这次修改。

所以「类属性是共享的」不能省成「一个改全改」。共享的是**同一个对象**；你改的是对象的内容，还是给实例换了一个新对象，结果不同。

不可变类属性也不会被复制：如果类上有 `school = "Paideia"`，实例没有自己的 `school` 时，读到的就都是 `Student.school`。只是字符串不能原地修改，所以不会出现「一个实例原地改、所有实例都变」；在实例上赋值 `school` 仍然是挂新属性，类和别的实例不变。

## `self` 是第一个参数，不是关键字

定义在类里的函数，通过实例访问时会绑定成方法。`lin.add(92)` 不是凭空多出一个 `self`：它会把 `lin` 作为第一个参数传进去，调用相当于 `Student.add(lin, 92)`。`self` 只是第一个参数的约定名字，不是关键字。

这也解释了两个写法问题：

- 方法定义成 `def add(score):`，再写 `lin.add(92)`：Python 仍然把 `lin` 和 `92` 都传进去，`add` 只收一个参数，报 `TypeError`。它不会因为少了 `self` 就变成普通函数。
- 把 `self` 全部改成 `this`：能跑。`this` 只是换了个参数名，规则没变；但别人读代码时会先愣一下，所以不这么写。

实际报错（CPython 3.11.5）：

```text
TypeError: Student.add() takes 1 positional argument but 2 were given
```

要定义不需要实例的函数，可以在类外定义；`@staticmethod` 也能做，但装饰器第 15 课才讲，这里先不展开。

## 默认打印只有类名和地址

不写 `__repr__`、也没有 `__str__` 时，`print(lin)` 的输出形状是 `<__main__.Student object at 0x...>`：模块名、类名、内存地址，没有你的字段。`0x...` 是这次运行的地址，下一次可能不同；直接运行脚本时模块名是 `__main__`（模块第 12 课讲，这里只要知道是这个名字）。这是当前 CPython 3.11.5 的 `object.__repr__` 行为，不是语言规范承诺的固定格式。

下面只验证这个形状里能固定的部分：

<!-- run -->
```python
class Student:
    def __init__(self, name):
        self.name = name


lin = Student("小林")
print(repr(lin).startswith("<__main__.Student object at 0x"))
print(type(lin))
```
```text
True
<class '__main__.Student'>
```

写 `__repr__`，让它返回一句能看出对象关键信息的字符串：

<!-- run -->
```python
class Student:
    def __init__(self, name):
        self.name = name
        self.scores = []

    def __repr__(self):
        return f"Student(name={self.name!r}, scores={self.scores})"


lin = Student("小林")
lin.scores.append(92)
print(lin)
```
```text
Student(name='小林', scores=[92])
```

`print(lin)` 会调用 `__str__`；没定义 `__str__` 时回退到 `__repr__`。所以这里写 `__repr__` 就能让 `print` 和交互式环境里都可读。`!r` 让名字带引号，字符串和数字一眼能分开。

## 跑一遍

把前面几件事放进同一版 `Student`：类属性只留不可变的学校名，成绩列表在 `__init__` 里建，方法用 `self`，`__repr__` 负责可读输出。`lin.add(92)` 和 `Student.add(lin, 78)` 两种写法都往 `lin` 的列表里加，说明 `self` 就是第一个参数。

<!-- run -->
```python
class Student:
    school = "Paideia"

    def __init__(self, name):
        self.name = name
        self.scores = []

    def add(self, score):
        self.scores.append(score)

    def average(self):
        return sum(self.scores) / len(self.scores)

    def is_passing(self):
        return self.average() >= 60

    def __repr__(self):
        return f"Student(name={self.name!r}, scores={self.scores})"


lin = Student("小林")
zhou = Student("小周")
lin.add(92)
Student.add(lin, 78)
zhou.add(55)

print(lin)
print(zhou)
print(lin.scores is zhou.scores)
print(lin.average(), zhou.average())
print(lin.is_passing(), zhou.is_passing())
print(lin.school, zhou.school)
print(Student.school)
print(type(lin).__name__)
print(isinstance(lin, Student))
```
```text
Student(name='小林', scores=[92, 78])
Student(name='小周', scores=[55])
False
85.0 55.0
True False
Paideia Paideia
Paideia
Student
True
```

`school` 是类属性，两个实例都没有自己的 `school` 属性；`lin.school` 只是回退到类上读。若写 `lin.school = "自学"`，只会给 `lin` 挂一个新属性，`zhou.school` 和 `Student.school` 仍是 `Paideia`。

`type(lin).__name__` 取到类名；`isinstance(lin, Student)` 是内置检查，问「`lin` 是不是 `Student` 的实例」，输出 `True`。`isinstance` 在继承第 11 课还会再用到。

## 还差的

- 本课最后的 `average()` 没有处理空成绩列表：`len(self.scores)` 为 0 时直接 `ZeroDivisionError`。没有成绩算多少分，这一课没有定义。
- 没讲 `__eq__`：现在两个 `Student` 用 `==` 比较，默认比的还是「是不是同一个对象」；内容相同不代表相等。
- 没讲 `__slots__`、`property` 和描述符。它们会改变「属性存在哪里、赋值时先走谁」；本课只覆盖普通属性，遇到这些写法先照抄，别按这一课的普通属性顺序硬套。
- 继承与 `super()` 留到第 11 课；类属性在子类里怎么找、子类能不能遮住父类属性，这一课没有展开。
- `__del__` 与垃圾回收时机没有碰。`__del__` 的调用时机受解释器和对象图影响，不能当成资源清理的保证；资源清理该用 `with`，第 16 课讲。
