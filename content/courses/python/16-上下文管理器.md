# 16 · 上下文管理器

## 这一课你要会

- 说清 `with open(...) as f` 里的 `f` 从哪来、关闭发生在什么时候；
- 自己写一个类，实现 `__enter__` / `__exit__`；
- 用 `@contextlib.contextmanager` 五行写一个上下文管理器；
- 解释"即使中间抛异常，收尾也会执行"是怎么做到的。

## 为什么

"打开资源 → 用它 → 关掉它"这个模式到处都有：文件、数据库连接、锁、临时目录、事务。

手写版本长这样：

```python
f = open("a.txt")
try:
    data = f.read()
finally:
    f.close()
```

问题不是写不出来，而是**每个调用点都要记得写，漏一个就泄漏**。`with` 把"收尾"绑在语法上，忘记关变得不可能——除非你根本没打开它。

## 讲解

### `with` 到底做了什么

```python
with open("a.txt", encoding="utf-8") as f:
    data = f.read()
# 到这里文件已经关了
```

等价于：

```python
f = open("a.txt", encoding="utf-8")   # __enter__ 的返回值给 as 后面的名字
try:
    data = f.read()
finally:
    f.close()                          # __exit__ 被调用
```

不管 `read()` 正常结束、抛异常、还是 `return` 离开，`__exit__` 都会执行。

### 自己写一个类版本

```python
class Timer:
    def __enter__(self):
        import time
        self.start = time.perf_counter()
        return self          # 这个返回值给 as 后面的变量

    def __exit__(self, exc_type, exc_value, traceback):
        import time
        print(f"耗时 {time.perf_counter() - self.start:.3f}s")
        return False         # False = 不吞异常，让异常继续往外抛
```

用法：

```python
with Timer():
    sum(range(1_000_000))
```

`__exit__` 的三个参数是异常信息：没异常时全是 `None`。**返回值决定异常要不要被吞掉**——`False` 或 `None` 表示继续抛，`True` 表示"我处理了，外面看不到"。

**绝大多数情况返回 `False`**。只有"这个异常在这里是预期内的、可以安全忽略"时才返回 `True`。

### 跑一遍

<!-- run -->
```python
class Resource:
    def __init__(self):
        self.closed = False

    def __enter__(self):
        print("打开资源")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        self.closed = True
        name = exc_type.__name__ if exc_type else None
        print(f"关闭资源，异常 = {name}")
        return False


with Resource() as resource:
    print("使用资源")
print(f"退出后 closed = {resource.closed}")

try:
    with Resource():
        raise ValueError("出错了")
except ValueError as error:
    print(f"异常继续抛出：{error}")
```
```text
打开资源
使用资源
关闭资源，异常 = None
退出后 closed = True
打开资源
关闭资源，异常 = ValueError
异常继续抛出：出错了
```

`__exit__` 在正常退出和抛异常两种情况下都执行了；`return False` 让 `ValueError` 继续向外抛，所以 `except` 能接住它。把 `return False` 改成 `return True`，最后一行就不会出现。

### 生成器版本：更短

```python
from contextlib import contextmanager

@contextmanager
def timer():
    import time
    start = time.perf_counter()
    try:
        yield                     # 这里之前 = __enter__，这里就是 with 块
    finally:
        print(f"耗时 {time.perf_counter() - start:.3f}s")
```

`yield` 之前是进入逻辑，`yield` 之后是退出逻辑。**必须放在 `try/finally` 里**，否则 with 块内抛异常时收尾代码不执行——这是自己写 contextmanager 最常见的 bug。

如果需要 `as` 拿到值，把值 `yield` 出去：

```python
@contextmanager
def opened(path):
    f = open(path, encoding="utf-8")
    try:
        yield f
    finally:
        f.close()
```

### 一次开多个

```python
with open("in.txt") as src, open("out.txt", "w") as dst:
    dst.write(src.read())
```

两个资源都保证关闭。也可以嵌套 `with`，效果一样，但平铺更好读。

### 真实用途

- **锁**：`with lock:` 保证出块就解锁，不会因为异常把锁一直占着；
- **数据库事务**：`with conn.begin():` 正常结束提交、异常回滚；
- **临时目录**：`with tempfile.TemporaryDirectory() as d:` 用完自动删；
- **切换工作目录**：进去换、出来换回来。

## 常见误区

### 误区：`with open(...)` 只是语法糖，没什么实际作用

**你以为**：和手动 close 一样。
**其实**：手动 close 在异常、提前 return、continue 时都可能被跳过；`with` 不可能跳过。
**怎么验证**：在 with 块里 `raise`，看文件是否仍然关闭（可以用 `f.closed` 检查）。

### 误区：`__exit__` 返回 True 是"正常结束"

**你以为**：返回 True 表示成功。
**其实**：它表示**吞掉异常**。写错这个值会让本该报错的程序安静地继续跑，错误被藏起来。
**怎么验证**：写一个返回 True 的 `__exit__`，在 with 里 `raise ValueError`，看程序是否没崩。

### 误区：contextmanager 里不用 try/finally 也行

**你以为**：`yield` 后面的代码总会执行。
**其实**：with 块抛异常时，异常会从 `yield` 那一行抛出，后面的普通语句被跳过。必须在 `finally` 里收尾。

## 小结

`with` 保证进入时 `__enter__`、退出时 `__exit__`，异常也不跳过。返回值 `False` 让异常继续抛，`True` 表示吞掉。写生成器版本时，收尾必须放 `finally`。文件、锁、事务、临时目录都该用它。
