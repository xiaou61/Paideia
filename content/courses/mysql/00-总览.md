# MySQL 从零开始

这门课写给**会用一点数据库、但没系统学过的人**。你可能已经能写 `SELECT * FROM 表`，但遇到"这条查询为什么慢""金额为什么算错了一分钱""两个人同时改同一行会怎样"时还答不上来。

不假设你会装数据库。示例全部在一个临时库里现建现跑，你看得到每一步的真实输出。

## 这门课怎么排

十二关，分五段：

1. **入门**（01–02）：建表、插数据、按条件查。先把最小闭环跑通。
2. **查询**（03–05）：排序分页、聚合分组、多表连接。这三关决定你 90% 的日常查询能力。
3. **设计**（06–08）：类型怎么选、索引怎么建、表怎么拆。这一段决定了后面会不会返工。
4. **事务与并发**（09–10）：事务边界、隔离级别、锁。这一段讲的是"两个人同时操作"时会发生什么。
5. **工程实践**（11–12）：看执行计划找慢查询，最后用一个订单系统把前面全部串起来。

每关一篇二十分钟左右，顺序是刻意排的：**先会查，再会设计，最后才谈性能和并发。**

## 为什么不用先背语法

SQL 的语法不多，真正难的是三件事：

- **知道该问数据库什么**——把业务问题翻译成一次查询；
- **知道数据库会怎么执行它**——同样的结果，写法不同代价差几十倍；
- **知道它什么时候会给你错的结果**——NULL、隐式类型转换、浮点精度、并发。

前两件靠练，第三件靠这篇线里反复出现的"陷阱"小节。所以每一关都有一节「常见误区」，那不是在凑格式，是这门课真正的内容。

## 关于示例

凡是标了「跑一遍」的 SQL，都是**真的执行过的**，下面的输出就是它当时打出来的。你可以直接复制到自己的库里跑。

想跟着做，先建一个自己的练习库：

```sql
CREATE DATABASE practice;
USE practice;
```

后面每一关的示例都假定只有它自己的那几张表，不必按顺序执行。

## 开始之前

需要一个能连上的 MySQL（8.0 及以上）。装在本地、或者用 Docker 起一个都行：

```text
docker run --name mysql-practice -e MYSQL_ROOT_PASSWORD=123456 -p 3306:3306 -d mysql:8.0
```

连进去：

```text
mysql -h 127.0.0.1 -P 3306 -u root -p
```

如果这两条命令你还不太熟，也不影响读完——每一关的 SQL 都能读懂，只是没法亲眼看输出。但**强烈建议亲手跑**：数据库这东西，看会了和跑会了差得远。

## 学完之后

你应该能做到：

- 看到一句业务描述，写出对应的 SQL，并说清它会不会返回错的数量；
- 看到一个慢查询，用 `EXPLAIN` 判断它有没有走索引；
- 设计三到五张关联的表，说清为什么这么拆；
- 说清"两个人同时买最后一件库存"时，数据库层面发生了什么。

这四条覆盖了绝大多数线上事故的成因。
