# 01 · 装库与第一张表

## 这一课你要会

- 建一个库、建一张表，说清表和库的区别；
- 用 `INSERT` 插数据、用 `SELECT` 取回来；
- 知道 `INSERT` 的两种写法，以及为什么推荐写列名。

## 为什么

数据库的一切都从"一张表"开始。表定好了，后面的查询才有东西可查；表定错了，后面所有代码都得跟着改。

## 讲解

### 库和表：两层容器

MySQL 的组织是两层：

- **库（database / schema）**：一组表的集合，同一个库里的表可以互相连接查询；
- **表（table）**：真正存数据的地方，由列（字段）和行（记录）组成。

一个 MySQL 实例里可以有很多库。工作里常见的做法是一个项目一个库，测试和生产分开。

```sql
CREATE DATABASE practice;
USE practice;
```

`USE` 是在说"接下来的语句都针对这个库"。不写 `USE` 也能工作，只要在表名前面带上库名：`practice.students`。

### 建表：每一列都要说清类型

```sql
CREATE TABLE students (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  name  VARCHAR(20) NOT NULL,
  age   INT,
  score DECIMAL(5,2)
);
```

逐项拆开：

| 部分 | 意思 |
| --- | --- |
| `INT` | 整数类型 |
| `PRIMARY KEY` | 主键：这一列能唯一标识一行，不允许重复、不允许为空 |
| `AUTO_INCREMENT` | 插入时不写这一列，数据库自动给下一个值 |
| `NOT NULL` | 不允许为空，插入时必须给值 |
| `VARCHAR(20)` | 变长字符串，最多 20 个字符 |
| `DECIMAL(5,2)` | 定点小数，总共 5 位、其中 2 位小数，范围是 -999.99 到 999.99 |

两个值得当场记住的选择：

- **名字用 `VARCHAR` 不用 `CHAR`**：`CHAR` 是定长，存 "张三" 会用空格补齐到 20 长度，取出来再裁掉。除非长度确实固定（比如国家代码），否则用变长。
- **分数用 `DECIMAL` 不用 `FLOAT`**：浮点数存不准。这一条在第 06 关会展开，现在先记住：**凡是钱和要精确的值，一律 `DECIMAL`。**

### 插入：写列名

```sql
INSERT INTO students (name, age, score) VALUES ('张三', 18, 92.5);
```

不写列名的写法是 `INSERT INTO students VALUES (1, '张三', 18, 92.5)`，它要求**每一列都按建表顺序给值**。表一加列，这种写法就全错——所以生产代码里一律写列名。

`id` 不在列名里，因为它有 `AUTO_INCREMENT`，数据库自己给。

一次插多行：

```sql
INSERT INTO students (name, age, score) VALUES
  ('李四', 19, 85.0),
  ('王五', 20, NULL);
```

批量插入比逐条插入快得多——每一条单独的 `INSERT` 都是一次独立的语句解析与提交。

### 查询：先看全表

```sql
SELECT * FROM students;
```

`*` 表示"所有列"。**生产代码里不要用 `*`**，原因不是风格：它会多读不需要的列、表结构一变返回值就变、而且可能把大字段（TEXT/BLOB）一起拉出来。练习时用着方便。

### 跑一遍

<!-- run -->
```sql
CREATE TABLE students (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  name  VARCHAR(20) NOT NULL,
  age   INT,
  score DECIMAL(5,2)
);
INSERT INTO students (name, age, score) VALUES
  ('张三', 18, 92.5),
  ('李四', 19, 85.0),
  ('王五', 20, NULL);
SELECT id, name, age, score FROM students;
SELECT id, name FROM students WHERE score IS NULL;
```
```text
id=1 | name=张三 | age=18 | score=92.50
id=2 | name=李四 | age=19 | score=85.00
id=3 | name=王五 | age=20 | score=NULL
id=3 | name=王五
```

注意 `85.00` 那两个零：`DECIMAL(5,2)` 规定两位小数，存 `85.0` 取出来就是 `85.00`。**类型决定显示，不是存进去的样子。** 而 `NULL` 表示"没有值"，它和 0、空字符串都不一样，下一关专门讲。

## 常见误区

### 误区：`SELECT *` 只是写得方便，没什么代价

**你以为**：反正结果一样，多读几列无所谓。
**其实**：多读的列要传输、要反序列化；遇到大字段（TEXT/BLOB）时可能把几十 KB 一起拉回来；表加列时接口返回值会悄悄变化。
**怎么验证**：给表加一个 `TEXT` 大字段，分别用 `SELECT *` 与只取需要的列，对比返回的数据量。

### 误区：`NULL` 和 0、空字符串是一回事

**你以为**：没填就是空，等价于 0 或 `''`。
**其实**：`NULL` 表示"未知/没有值"，它参与比较的结果是"未知"，不是真也不是假。`WHERE score = NULL` 永远匹配不到任何行。
**怎么验证**：分别查 `WHERE score = NULL` 与 `WHERE score IS NULL`，看返回行数。

### 误区：`AUTO_INCREMENT` 的 id 不会重复，所以一定连续

**你以为**：删除几行之后，新插入的 id 会补上空缺。
**其实**：自增值只增不减。删掉 id=2 之后，下一条还是 3（或者更大）。重启、并发插入、回滚都会让数字出现空洞。
**怎么验证**：插入三行、删掉中间一行、再插一行，看新行的 id。

## 小结

库是表的集合，表由列定义、按行存数据。建表时每一列都要给类型，`NOT NULL`、`PRIMARY KEY`、`AUTO_INCREMENT` 是最常用的三个约束。插入写列名，查询别用 `*`。`DECIMAL` 存精确值，`VARCHAR` 存变长字符串。
