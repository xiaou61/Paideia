# 01 · 装库与第一张表

## 一笔 1000 块的订单插不进去

第一张表是给一个小店做订单的。金额我想都没想就写成了 `DECIMAL(5,2)`——"5 位、2 位小数"，看着挺宽裕：

```sql
CREATE TABLE orders (
  id     INT PRIMARY KEY AUTO_INCREMENT,
  amount DECIMAL(5,2)
);

INSERT INTO orders (amount) VALUES (999.99);   -- Query OK
INSERT INTO orders (amount) VALUES (1000.00);  -- 挂了
```

第二条报的是：

```text
ERROR 1264 (22003): Out of range value for column 'amount' at row 1
```

`DECIMAL(5,2)` 的 5 是**总位数**，其中 2 位给了小数，整数部分只剩 3 位——最大 999.99。这个类型连一笔一千块的订单都装不下。

类型不是"格式好看"，是容量。这一课先把"建 → 插 → 查"跑通，同时把类型这个坑填掉。

## 库和表：两层容器

- **库（database / schema）**：一组表的集合，同一个库里的表可以互相 join；
- **表（table）**：真正存数据的地方，由列（字段）和行（记录）组成。

```sql
CREATE DATABASE practice;
USE practice;
```

`USE` 说的是"接下来的语句都针对这个库"。不写 `USE` 也行，把库名带上：`practice.students`。工作里常见的做法是一个项目一个库，测试和生产各一个。

## 建表：每一列都在承诺"存多大"

```sql
CREATE TABLE students (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  name  VARCHAR(20) NOT NULL,
  age   INT,
  score DECIMAL(5,2)
);
```

逐项：

| 部分 | 意思 |
| --- | --- |
| `INT` | 整数，范围 −2147483648 ~ 2147483647 |
| `PRIMARY KEY` | 主键：唯一标识一行，不允许重复、不允许为空 |
| `AUTO_INCREMENT` | 插入时不写这一列，数据库给下一个值 |
| `NOT NULL` | 不允许为空，插入必须给值 |
| `VARCHAR(20)` | 变长字符串，**最多 20 个字符**（不是字节） |
| `DECIMAL(5,2)` | 定点小数，总共 5 位、其中 2 位小数，范围 −999.99 ~ 999.99 |

三个值得当场记住的选择：

**金额用 `DECIMAL` 不用 `FLOAT`/`DOUBLE`。** 浮点是二进制表示，0.1 这类值存的是近似值，加起来会与预期差出小数。凡是钱、库存、任何要精确比较的数，一律 `DECIMAL`。

**`DECIMAL` 的位数要按业务量级算，不是随手写。** 上面那个 `DECIMAL(5,2)` 就是我踩的坑。一笔一千块需要 4 位整数 + 2 位小数，得 `DECIMAL(6,2)`；再给未来留点余量，电商系统常用 `DECIMAL(12,2)`（上限约 100 亿）。

**名字用 `VARCHAR` 不用 `CHAR`。** `CHAR` 是定长，存"张三"会补空格到指定长度，取出来再裁掉。除非长度确实固定（国家代码、状态码），否则用变长。

顺带一个很多人搞错的点：**`VARCHAR(20)` 的 20 是字符数，不是字节数**。utf8mb4 下 `VARCHAR(20)` 最多占 80 字节，能存 20 个汉字。反过来如果按"20 字节"去理解、估小了，插入时就会撞上这条：

```text
ERROR 1406 (22001): Data too long for column 'name' at row 1
```

这个报错在 MySQL 5.7 之后默认严格模式下是**直接失败**；更老的配置或手动关掉严格模式时它会截断并给一个 warning——那种"数据悄悄少了一截"的问题比报错难查得多。

## 插入：写列名

```sql
INSERT INTO students (name, age, score) VALUES ('张三', 18, 92.5);
```

不写列名的写法是 `INSERT INTO students VALUES (1, '张三', 18, 92.5)`，它要求**按建表顺序给出每一列**。表一加列、一调顺序，这种写法就全错——生产代码里一律写列名。

`id` 不在列名里，因为它有 `AUTO_INCREMENT`。

一次插多行：

```sql
INSERT INTO students (name, age, score) VALUES
  ('李四', 19, 85.0),
  ('王五', 20, NULL);
```

批量比逐条快，原因不是"DBA 技巧"：每条独立 `INSERT` 都是一次完整的语句解析、执行与提交（一次刷盘）。批量把 N 次往返压成 1 次。

## 查询：先看全表

```sql
SELECT * FROM students;
```

`*` 是"所有列"。练习时方便，进屋子的代码里要写清列名：多读的列要传输和反序列化，遇上 `TEXT`/`BLOB` 可能把几十 KB 一起拉回来，而且表加列时接口返回值会悄悄变。

## 跑一遍

<!-- run -->
```sql
CREATE TABLE students (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  name  VARCHAR(20) NOT NULL,
  age   INT,
  score DECIMAL(5,2)
);
INSERT INTO students (name, age, score) VALUES
  ('张三', 18, 92.5),
  ('李四', 19, 85.0),
  ('王五', 20, NULL);
SELECT id, name, age, score FROM students;
SELECT id, name FROM students WHERE score IS NULL;
```
```text
id=1 | name=张三 | age=18 | score=92.50
id=2 | name=李四 | age=19 | score=85.00
id=3 | name=王五 | age=20 | score=NULL
id=3 | name=王五
```

注意 `85.00` 那两个零：`DECIMAL(5,2)` 规定两位小数，存 `85.0` 取出来就是 `85.00`。**类型决定显示形态，不是存进去时的样子。**

最后一条查询用的是 `IS NULL` 而不是 `= NULL`。`NULL` 表示"没有值/未知"，它参与任何比较的结果都是"未知"，不是真也不是假，所以 `WHERE score = NULL` 一行都匹配不到——下一课专门讲这件事。

## 三件我原来以为对的事

**一、`AUTO_INCREMENT` 的 id 是连续的。** 不连续。自增值只增不减：删掉 id=2 之后，下一条还是 3（或更大），重启、并发插入、回滚都会留空洞。**不要拿 id 当"第几条记录"用**，要序号就自己数或者查窗口函数。

**二、`NULL` 和 0、空字符串差不多。** 三者完全不同：`NULL` 是"未知"，`0` 是数值零，`''` 是长度为零的字符串。`WHERE score = NULL` 永远查不到东西，必须 `IS NULL`。

**三、类型只是声明，写大了也存得下。** 类型就是容量，超了要么报错（严格模式），要么被悄悄截断/四舍五入（非严格模式）。后者更危险——错误进了库、一周后才被发现。

## 这一课之后

库是表的集合，表由列定义、按行存数据。建表就是给每一列承诺容量与规则：`NOT NULL`、`PRIMARY KEY`、`AUTO_INCREMENT` 是最常用的三个，`DECIMAL` 存精确数值，`VARCHAR(n)` 的 n 是字符数。

插入写列名、批量插更省往返；查询练习可以用 `*`，进屋子的代码写清列名。
