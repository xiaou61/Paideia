# 07 · 依赖注入与循环依赖

## 这一课你要会

- 说清构造器注入、setter 注入、字段注入三种方式的真实差别；
- 判断"依赖缺失"会在哪一步暴露（编译期 / 启动期 / 第一次调用）；
- 解释为什么循环依赖在构造器注入下是**必然失败**，在字段注入下却能绕过；
- 知道本项目为什么一律用构造器注入。

## 为什么

"注入了 null"是 Spring 项目里最高频的一类故障。它的根因几乎总是同一个：**对象被造出来了，但依赖没被填进去**。

三种注入方式的区别不在写法，而在**"对象什么时候是完整的"**：

- 构造器注入：对象构造完成的那一刻，依赖一定都在；
- setter / 字段注入：对象可以先存在、后补依赖——存在一段"半成品"的窗口。

循环依赖能不能成立，就是从这个窗口里长出来的。

## 讲解

### 三种写法的对照

```java
// 一、构造器注入（推荐）
@Service
public class TransferService {
    private final AccountRepository repository;

    public TransferService(AccountRepository repository) {
        this.repository = repository;
    }
}
```

```java
// 二、setter 注入
@Service
public class TransferService {
    private AccountRepository repository;

    @Autowired
    public void setRepository(AccountRepository repository) {
        this.repository = repository;
    }
}
```

```java
// 三、字段注入
@Service
public class TransferService {
    @Autowired
    private AccountRepository repository;
}
```

差别的实质：

| | 依赖能不能是 final | 缺依赖何时暴露 | 能不能 new 出来做单测 |
| --- | --- | --- | --- |
| 构造器 | 能 | 编译期（少传一个参数就编译不过） | 能，`new TransferService(repo)` |
| setter | 不能 | 运行期，第一次调用时 NPE | 能，但要记得手动调 setter |
| 字段 | 不能 | 运行期，第一次调用时 NPE | 难，字段是私有的且没有入口 |

第三列是最容易被忽略的收益：**构造器注入让这个类不依赖 Spring**。测试里直接 `new` 就完事，不需要 `@SpringBootTest` 起一个容器。

### 循环依赖是什么

`A` 需要 `B`，`B` 又需要 `A`：

```text
A → B → A → B → ...
```

用构造器注入时，这是一个**无解的死循环**：要造 A 必须先有 B，要造 B 必须先有 A，谁都没有第一个。

用字段注入时，它变成"两阶段"就能解开：先 `new A()`（此时 `a.b` 是 null）、再 `new B()`、然后把 `b` 塞进 `a`、把 `a` 塞进 `b`。两个对象都还没被用过，所以"半成品窗口"没有伤人。

### 手写一遍两种结果

同一对循环依赖的类，用两种容器各造一次：

<!-- run -->
```java
import java.lang.reflect.Constructor;
import java.lang.reflect.Field;
import java.util.HashMap;
import java.util.LinkedHashSet;
import java.util.Map;
import java.util.Set;

public class Main {

    // 构造器注入的版本：互相要求对方
    static class A {
        final B b;

        A(B b) {
            this.b = b;
        }
    }

    static class B {
        final A a;

        B(A a) {
            this.a = a;
        }
    }

    // 字段注入的版本：允许先存在、后填充
    static class FieldA {
        FieldB b;
    }

    static class FieldB {
        FieldA a;
    }

    static final class ConstructorContainer {
        private final Map<Class<?>, Object> instances = new HashMap<>();
        private final Set<Class<?>> creating = new LinkedHashSet<>();

        Object get(Class<?> type) {
            Object existing = instances.get(type);
            if (existing != null) {
                return existing;
            }
            if (!creating.add(type)) {
                throw new IllegalStateException("循环依赖: " + trail() + " -> " + type.getSimpleName());
            }
            try {
                for (Constructor<?> constructor : type.getDeclaredConstructors()) {
                    Class<?>[] parameters = constructor.getParameterTypes();
                    Object[] arguments = new Object[parameters.length];
                    for (int i = 0; i < parameters.length; i++) {
                        arguments[i] = get(parameters[i]);
                    }
                    constructor.setAccessible(true);
                    Object made = constructor.newInstance(arguments);
                    instances.put(type, made);
                    return made;
                }
                throw new IllegalStateException("没有可用的构造器: " + type.getSimpleName());
            } catch (ReflectiveOperationException error) {
                throw new IllegalStateException(error);
            } finally {
                creating.remove(type);
            }
        }

        private String trail() {
            StringBuilder builder = new StringBuilder();
            for (Class<?> type : creating) {
                if (builder.length() > 0) {
                    builder.append(" -> ");
                }
                builder.append(type.getSimpleName());
            }
            return builder.toString();
        }
    }

    static final class TwoPhaseContainer {
        private final Map<Class<?>, Object> instances = new HashMap<>();

        void register(Class<?>... types) {
            // 第一阶段：只造，不填
            for (Class<?> type : types) {
                try {
                    Constructor<?> constructor = type.getDeclaredConstructor();
                    constructor.setAccessible(true);
                    instances.put(type, constructor.newInstance());
                } catch (ReflectiveOperationException error) {
                    throw new IllegalStateException(error);
                }
            }
            // 第二阶段：字段注入，此时两个对象都已存在
            for (Class<?> type : types) {
                Object target = instances.get(type);
                for (Field field : type.getDeclaredFields()) {
                    Object dependency = instances.get(field.getType());
                    if (dependency == null) {
                        continue;
                    }
                    field.setAccessible(true);
                    try {
                        field.set(target, dependency);
                    } catch (IllegalAccessException error) {
                        throw new IllegalStateException(error);
                    }
                }
            }
        }

        Object get(Class<?> type) {
            return instances.get(type);
        }
    }

    public static void main(String[] args) {
        try {
            new ConstructorContainer().get(A.class);
        } catch (IllegalStateException error) {
            System.out.println("构造器注入: " + error.getMessage());
        }

        TwoPhaseContainer twoPhase = new TwoPhaseContainer();
        twoPhase.register(FieldA.class, FieldB.class);
        FieldA fieldA = (FieldA) twoPhase.get(FieldA.class);
        System.out.println("字段注入: " + (fieldA.b != null) + " / " + (fieldA.b.a == fieldA));
    }
}
```
```text
构造器注入: 循环依赖: A -> B -> A
字段注入: true / true
```

两行输出把这节课的全部讲完了：

- 构造器注入下，容器**检测到环并且拒绝**。真实 Spring 在这件事上更直接：构造器循环依赖会抛 `BeanCurrentlyInCreationException`，没有别的路；
- 字段注入下，两阶段就能解开。第二阶段的 `fieldA.b.a == fieldA` 为 `true`，说明两个对象确实互指了。

### 为什么 Spring 要用三级缓存

手写的两阶段容器只处理了"两个都没有代理"的情况。真实场景还有两个麻烦：

1. 有些对象在注入之前就要被**包装成代理**（AOP、事务都靠代理）；
2. 代理对象与原始对象的引用必须是同一个，否则你拿到的和注入进去的就不是一个东西。

Spring 用三级缓存（`singletonObjects` / `earlySingletonObjects` / `singletonFactories`）解决这件事：提前暴露一个"能生成代理的工厂"，而不只是暴露原始对象。细节在 **Spring 深入阅读线**的「循环依赖与三级缓存」一篇里——那篇读起来会容易得多，因为你现在已经知道"为什么要提前暴露"了。

**但请记住本项目的立场**：循环依赖是设计问题，不是需要在框架里解决的特性。构造器注入会让它立刻暴露，这是优点不是缺点。看到 `BeanCurrentlyInCreationException`，正确做法是拆掉环（抽第三个类、把双向改成单向通知、或者改用事件），而不是改成字段注入绕过它。

第 15 课讲完"一次请求的完整旅程"之后，你会更清楚环通常是怎么长出来的——两个 Service 互相调用，往往是因为职责边界划错了。

### 多个候选怎么办

一个接口有两个实现时，按类型注入会失败（`NoUniqueBeanDefinitionException`）：

```java
@Service("fastRepo")
public class FastRepo implements Repo { }

@Service("safeRepo")
public class SafeRepo implements Repo { }
```

三种解决方式：

```java
@Primary                     // 默认赢家
@Service
public class FastRepo implements Repo { }

@Qualifier("safeRepo")       // 按名字指定
public TransferService(@Qualifier("safeRepo") Repo repo) { }

List<Repo> repos             // 要全部
public TransferService(List<Repo> repos) { }
```

第三种值得记住：**注入 `List<T>` 会拿到该类型的所有实现**，顺序可以配合 `@Order` 控制。这是"策略列表"最省事的写法，不需要自己维护注册表。

## 常见误区

### 误区：循环依赖要靠三级缓存解决

**你以为**：遇到循环依赖，说明我需要理解三级缓存。
**其实**：三级缓存是框架为了让**字段注入**的环不炸而付出的复杂度。用构造器注入时它根本不参与——环会在启动时直接报错。把环拆掉才是解法，理解和依赖它是两回事。
**怎么验证**：把一个项目的所有注入改成构造器，启动一次；报出来的环就是真实存在的设计问题。

### 误区：`@Autowired` 放字段上和放构造器上等价

**你以为**：只是写法不同。
**其实**：字段注入让类**离不开框架**：字段私有、没有入口，测试只能起容器。构造器注入让类回归普通 Java 对象，`new` 一下就能测。
**怎么验证**：给一个有 5 个字段注入的类写单测，看你要写多少行 mock 与反射。

### 误区：`@Autowired(required = false)` 是个安全的兜底

**你以为**：设成非必需，就不会因为缺依赖启动失败了。
**其实**：它把"启动时失败"换成了"运行时 NPE"。依赖可选是真实的业务语义（比如某个功能模块没启用），但用它来绕过"我不知道为什么注入不进来"是把错误往后推。
**怎么验证**：把某个依赖设成非必需，然后调用真正用到它的那条路径。

## 小结

三种注入的实质区别是"对象什么时候是完整的"。构造器注入让依赖缺失在编译期暴露，也是唯一能让依赖是 `final` 的方式；字段注入多出一个半成品窗口，循环依赖就是从这个窗口里长出来的。本项目一律构造器注入，遇到环就拆环。多候选用 `@Primary` / `@Qualifier`，要全部实现就注入 `List<T>`。
