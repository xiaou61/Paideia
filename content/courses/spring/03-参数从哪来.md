# 03 · 参数从哪来

## 这一课你要会

- 分清路径变量、查询串、请求体、请求头四类参数各在请求的哪个位置；
- 用 `@PathVariable` / `@RequestParam` / `@RequestBody` / `@RequestHeader` 各取一次；
- 说清"参数没取到"时该怎么定位，而不是挨个注解换着试；
- 手写一个从字符串里取参数的解析器，知道这些注解底下就是字符串切分。

## 为什么

`@RequestParam` 与 `@RequestBody` 的区别不在名字上，在**它们在请求的哪一段**：

```text
POST /users/42/books?page=2&size=10 HTTP/1.1     ← 路径(/users/42/books) 查询串(?page=2&size=10)
Host: example.com                                 ← 请求头
Content-Type: application/json

{"title":"SpEL"}                                  ← 请求体
```

四个注解正好对应四段。分不清这四段，就会出现最难查的一类 bug：参数永远是 `null`，但代码看起来没错。

| 注解 | 从哪取 | 典型用法 |
| --- | --- | --- |
| `@PathVariable` | 路径里 `{}` 占的位置 | `/users/{id}` → `GET /users/42` |
| `@RequestParam` | `?` 后面的键值对 | `?page=2&size=10` |
| `@RequestBody` | 请求体（整段） | JSON / XML |
| `@RequestHeader` | 请求头 | `Authorization`、`X-Trace-Id` |

一个请求里可以同时用三种：

```java
@GetMapping("/users/{id}/books")
public List<Book> books(
        @PathVariable("id") long userId,
        @RequestParam(name = "page", defaultValue = "1") int page,
        @RequestParam(name = "size", defaultValue = "20") int size,
        @RequestHeader(name = "X-Trace-Id", required = false) String traceId) {
    return service.books(userId, page, size);
}
```

### 参数名不写会怎样

`@RequestParam` 不写名字时，Spring 用**编译后的参数名**。而 `javac` 默认会把参数名擦成 `arg0`、`arg1`——所以必须加 `-parameters`（Spring Boot 的父工程已经替你加了）。自己手写 Maven 项目时漏了这个配置，表现就是：

这段报错的意思是"你说不清这个参数叫什么，我也没从字节码里读到"。**看到它就去查编译器的 `-parameters`**，不要怀疑注解写错了。

### 手写一遍取参数

三件事：把 `/users/{id}` 与真实路径对上、把 `?a=1&b=2` 切开放进 Map、把取到的字符串转成数字并处理失败。

<!-- run -->
```java
import java.util.LinkedHashMap;
import java.util.Map;

public class Main {

    // 1. 路径变量：把 /users/{id}/books/{bookId} 与 /users/42/books/7 对上
    static Map<String, String> pathVars(String pattern, String path) {
        String[] p = pattern.split("/");
        String[] q = path.split("/");
        if (p.length != q.length) {
            return null;
        }
        Map<String, String> vars = new LinkedHashMap<>();
        for (int i = 0; i < p.length; i++) {
            if (p[i].startsWith("{") && p[i].endsWith("}")) {
                vars.put(p[i].substring(1, p[i].length() - 1), q[i]);
            } else if (!p[i].equals(q[i])) {
                return null;
            }
        }
        return vars;
    }

    // 2. 查询串：page=2&size=10 → {page=2, size=10}
    static Map<String, String> query(String raw) {
        Map<String, String> map = new LinkedHashMap<>();
        if (raw == null || raw.isEmpty()) {
            return map;
        }
        for (String pair : raw.split("&")) {
            int at = pair.indexOf('=');
            map.put(pair.substring(0, at), pair.substring(at + 1));
        }
        return map;
    }

    // 3. 类型转换：取不到或转不动，是两种不同的错
    static int toInt(String value) {
        try {
            return Integer.parseInt(value);
        } catch (NumberFormatException error) {
            throw new IllegalArgumentException("不是整数: " + value);
        }
    }

    public static void main(String[] args) {
        System.out.println(pathVars("/users/{id}/books/{bookId}", "/users/42/books/7"));
        System.out.println(pathVars("/users/{id}", "/users/42/extra"));
        System.out.println(query("page=2&size=10"));
        System.out.println(query(""));
        try {
            toInt("abc");
        } catch (IllegalArgumentException error) {
            System.out.println("400 " + error.getMessage());
        }
    }
}
```
```text
{id=42, bookId=7}
null
{page=2, size=10}
{}
400 不是整数: abc
```

四点对应四个真实行为：

- 段数不一样直接 `null`——对应"路径完全匹配不上"，就是 404；
- 空查询串返回空 Map，不是 `null`——对应 `@RequestParam(required = false)` 时拿到 `null` 值；
- 转换失败抛异常——对应 Spring 抛 `MethodArgumentTypeMismatchException`，默认转成 **400**；
- `defaultValue` 的作用就是"Map 里没有这个键时用这个值"，不是"取到空字符串时用这个值"。

### 什么时候需要 `@RequestBody`

GET 请求没有请求体（规范上可以有，但客户端与代理都会丢），所以 GET 永远用 `@PathVariable` 与 `@RequestParam`。POST / PUT / PATCH 才有请求体。

`@RequestBody` 有一个前提：**请求必须带 `Content-Type: application/json`**（或其它可识别的类型）。少了这个头，Spring 会报：

```text
org.springframework.web.HttpMediaTypeNotSupportedException: Content-Type 'application/octet-stream' is not supported
```

这**不是**参数没传对，是它不知道该用哪个转换器把一段字节变成对象。用 `curl` 调试时最容易踩：

```bash
curl -X POST http://localhost:8080/api/users \
     -H "Content-Type: application/json" \
     -d '{"name":"小林"}'
```

`-d` 默认会带上 `application/x-www-form-urlencoded`，所以必须显式 `-H` 覆盖。

### 必填与可选

```java
@RequestParam("page") int page                              // 必填，缺了 400
@RequestParam(name = "page", required = false) Integer page  // 可选，缺了是 null
@RequestParam(name = "page", defaultValue = "1") int page    // 可选，缺了是 1
```

三个写法的差别在"缺参数时"：400、`null`、默认值。`int` 不能是 `null`，所以"可选 + 基本类型"必须给 `defaultValue`，否则启动时就会报错——这是一个只有跑起来才看得见的问题。

## 常见误区

### 误区：参数取不到就是注解没写对

**你以为**：`null` 一定是注解用错了。
**其实**：先看**在哪一段**——路径、查询串、请求体、请求头。这四段有一个取错了，注解再对也没用。第二步看**名字**：注解里写的名字与客户端发出来的键是否一字不差（`userId` 与 `user_id` 是两回事）。第三步才怀疑注解。
**怎么验证**：在方法第一行打一条日志，把四个参数与 `request.getRequestURI()` 一起打出来，一眼就看出是哪一段的问题。

### 误区：`@RequestBody` 也用在 GET 上

**你以为**：查询条件复杂时，GET 带个 JSON 体更方便。
**其实**：GET 的语义是"取"，RequestBody 的语义是"提交一份内容"。不少代理、缓存、网关会直接丢掉 GET 的请求体，本地能跑、上线就空。复杂查询用 POST 定义一个 `/search` 接口，或者把条件压进查询串。
**怎么验证**：用 `curl -X GET -d '{"a":1}'` 打本地能收到，换成任何一层反向代理再试一次。

## 小结

四类参数对应请求的四段：路径、查询串、请求体、请求头。取不到时先定位是哪一段、再看名字是否一致、最后才怀疑注解。`@RequestBody` 需要正确的 `Content-Type`，GET 不该带请求体。基本类型 + 可选 必须给 `defaultValue`。
