# 03 · 路由：把路径派发到处理器

## 这一课你要会

- 把"方法 + 路径模式"建成一张表，按顺序匹配；
- 从 `/users/{id}` 里取出 `42` 并交给处理器；
- 区分 404 与 405，并说清这两种情况的判据；
- 知道为什么"路径匹配上了但方法不对"必须返回 405 而不是 404。

## 为什么

第 1 课讲过：接口返回 200 的全部工作，就是"建一张表 + 查这张表"。这一关让你把那张表亲手建出来。

404 与 405 的区别看着琐碎，但它是**排障时的关键信号**：404 说明路径写错了，405 说明路径对、方法用错了。把两者混成一个，用户在等着前端改路径，实际他该改的是用 POST。

## 讲解

### 你要交的东西

| 符号 | 语义 |
| --- | --- |
| `interface Handler { String handle(String pathVariable); }` | 处理器，接收路径变量 |
| `void register(String httpMethod, String pattern, Handler handler)` | 记下一条路由，`pattern` 形如 `/users/{id}` |
| `String dispatch(String httpMethod, String path)` | 命中返回处理器结果；方法不对返回 `405`；都没有返回 `404` |

三条硬要求：

1. **尾斜杠不容错**：`/users/42/` 必须返回 `404`（真实框架多见于配置，本关要求严格）；
2. **段数必须相等**：`/users/{id}` 匹配不了 `/users/42/books`；
3. **405 优先于 404**：只要有一条路由的路径匹配上、方法不匹配，就是 405。

### 匹配的最小内核

把 pattern 与 path 都按 `/` 切开，逐段比：`{}` 包住的段是变量，其余必须字面相等。

```java
public class Main {

    static boolean match(String pattern, String path) {
        String[] segments = pattern.split("/");
        String[] actual = path.split("/");
        if (segments.length != actual.length) {
            return false;
        }
        for (int i = 0; i < segments.length; i++) {
            boolean slot = segments[i].startsWith("{") && segments[i].endsWith("}");
            if (!slot && !segments[i].equals(actual[i])) {
                return false;
            }
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println(match("/users/{id}", "/users/42"));
        System.out.println(match("/users/{id}", "/users/42/books"));
        System.out.println(match("/users", "/users/42"));
    }
}
```

三个结果分别对应：段数与字面都对 → 命中；段数不同 → 不匹配；段数不同（1 段 vs 2 段）→ 不匹配。

### 为什么 405 要单独一个返回值

`dispatch` 只有三种返回：处理器的结果、`405`、`404`。这逼着你把"路径匹配"与"方法匹配"分成两步：

```text
第一步：有没有任何一条路由的 path 能匹配上？ 没有 → 404
第二步：匹配上的那些里，有没有 method 也对的？ 没有 → 405
```

如果合成一步（"匹配到就返回，否则 404"），方法不匹配的情况会被报成 404，排障方向就完全错了。

```java
import java.util.ArrayList;
import java.util.List;

public class Main {

    public static void main(String[] args) {
        Router router = new Router();
        router.register("GET", "/hello", id -> "hi");
        System.out.println(router.dispatch("GET", "/hello"));
    }
}

interface Handler {
    String handle(String pathVariable);
}

class Router {

    private static final class Route {
        final String method;
        final String[] segments;
        final Handler handler;

        Route(String method, String pattern, Handler handler) {
            this.method = method;
            this.segments = pattern.split("/");
            this.handler = handler;
        }

        String extract(String[] actual) {
            if (segments.length != actual.length) {
                return null;
            }
            String variable = "";
            for (int i = 0; i < segments.length; i++) {
                boolean slot = segments[i].startsWith("{") && segments[i].endsWith("}");
                if (slot) {
                    variable = actual[i];
                } else if (!segments[i].equals(actual[i])) {
                    return null;
                }
            }
            return variable;
        }
    }

    private final List<Route> routes = new ArrayList<>();

    void register(String httpMethod, String pattern, Handler handler) {
        routes.add(new Route(httpMethod, pattern, handler));
    }

    String dispatch(String httpMethod, String path) {
        // split 会丢掉尾部的空段，所以尾斜杠必须显式拒绝
        if (path.length() > 1 && path.endsWith("/")) {
            return "404";
        }
        String[] actual = path.split("/");
        boolean pathMatched = false;
        for (Route route : routes) {
            String variable = route.extract(actual);
            if (variable == null) {
                continue;
            }
            pathMatched = true;
            if (route.method.equals(httpMethod)) {
                return route.handler.handle(variable);
            }
        }
        return pathMatched ? "405" : "404";
    }
}
```

</details>

### 三个容易卡住的地方

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| `dispatch("GET","/users")` 返回 404 | `"/users".split("/")` 得到 `["", "users"]`，与 pattern 一致就没问题——但写成 `"/users/"` 会多一个空段 | 两边都按同一个 split 规则切，不要一边手工去掉首斜杠 |
| 变量取错 | 用 `indexOf("{")` 找位置，遇到多变量就错 | 按段判断，不要按字符判断 |
| 405 变成 404 | 在循环里"没匹配到就立刻 return 404" | 先遍历完所有路由，记一个 `pathMatched` 标志 |

## 常见误区

### 误区：路由表应该按"最长匹配"排优先级

**你以为**：越具体的路径越该先匹配。
**其实**：本关按注册顺序匹配，够用了。真实框架确实有优先级规则（更具体的赢），但那是为了处理 `/users/{id}` 与 `/users/me` 这种冲突。在还没有冲突的场景里引入优先级，只会让行为更难预测。
**怎么验证**：注册 `/users/{id}` 与 `/users/me`，看 `GET /users/me` 命中哪个。想让它命中后者，就得加优先级规则。

### 误区：`split("/")` 很安全

**你以为**：切分路径不会出意外。
**其实**：`"/users".split("/")` 得到 `["", "users"]`（首段是空串），而 `"/users/".split("/")` 得到 `["", "users"]`——**尾部的空串会被丢弃**。所以尾斜杠的容错行为其实来自 `split` 的这个特性，不是来自你的代码。想严格不容错，要在切分前显式检查尾斜杠。
**怎么验证**：分别打印 `"/a/".split("/").length` 与 `"/a".split("/").length`，都是 2。

## 小结

路由表的两步判断是关键：先看路径有没有匹配（→ 404），再看方法有没有匹配（→ 405）。变量按段判断，不要按字符判断。`split` 会丢掉尾部的空段，所以尾斜杠的容错要显式处理。
