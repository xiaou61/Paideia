# 03 · 路由：把路径派发到处理器

## 测试红了一个：`/users/42/` 居然命中了

我写完第一版 `Router`，跑测试，前四个用例全绿，第五个红了：

```text
FAIL trailing-slash -> dispatch(GET, /users/42/) returned user-42, expected 404: this level matches strictly
```

我第一反应是匹配逻辑写错了，盯着 `extract` 看了十分钟。后来才想明白：**错不在匹配，在我以为 `split` 会保留尾斜杠**。

我写了个小探针，打印 `split("/")` 的真实结果（JDK 25，就这几行）：

```text
"/users"         len=2  [][users]
"/users/"        len=2  [][users]
"/users/42"      len=3  [][users][42]
"/users/42/"     len=3  [][users][42]
"/"              len=0
""               len=1  []
"//users//42//"  len=5  [][][users][][42]
"/users/42/books" len=4  [][users][42][books]
```

关键在第 1、2 行和第 3、4 行：**`/users` 与 `/users/` 切出来的段完全一样，`/users/42` 与 `/users/42/` 也一样**。Java 的 `split` 会把尾部空段丢掉，所以"有没有尾斜杠"这个信息在切分之后彻底消失——你在匹配阶段永远补不回来，只能在切之前看一眼原字符串。

这条我记住了：**有些信息在某个操作之后就没了，得在那个操作之前处理**。

## 路由表要做的事

路由表把"HTTP 方法 + 路径模式"存成一张表，收到请求时查表：

| 符号 | 语义 |
| --- | --- |
| `interface Handler { String handle(String pathVariable); }` | 处理器，接收路径变量 |
| `void register(String httpMethod, String pattern, Handler handler)` | 记下一条路由，`pattern` 形如 `/users/{id}` |
| `String dispatch(String httpMethod, String path)` | 命中调处理器；路径在但方法不对返回 `405`；都没有返回 `404` |

这一关有三条硬要求（也就是你的测试会验的）：

1. **尾斜杠不容错**：`/users/42/` 返回 `404`；
2. **段数必须相等**：`/users/{id}` 匹配不了 `/users/42/books`；
3. **405 优先于 404**：只要有一条路由路径匹配上、方法不匹配，就是 405。

## 为什么 405 不能合并进 404

这两条路的排障方向完全相反：

- **404** = 路径不对。前端要改 URL，或者后端漏注册了。
- **405** = 路径对、方法不对。前端拿着 POST 打 GET 接口，改的是方法不是地址。

我在真实项目里被这个坑过一次：接口加了 `PUT`，前端还在发 `POST`，服务端一路返回 404，前端同学花了一下午在改路径拼接规则。如果当时返回 405，问题五分钟就定位了。

所以 `dispatch` 必须先把所有路由走完，记住"有没有路径匹配上"，再决定返回值：

```text
第一步：有没有任何一条路由的路径能匹配上？   没有 → 404
第二步：匹配上的那些里，有没有方法也对的？   没有 → 405
```

合成一步（"匹配到就返回，否则 404"）就会把 405 误报成 404——这是本节最容易写错的地方，测试里专门有一个用例盯着它。

## 先把匹配内核跑通

这一关的匹配内核就三段：切段、比段数、逐段比。先把它跑出来：

<!-- run -->
```java
public class Main {

    static boolean match(String pattern, String path) {
        String[] segments = pattern.split("/");
        String[] actual = path.split("/");
        if (segments.length != actual.length) {
            return false;
        }
        for (int i = 0; i < segments.length; i++) {
            boolean slot = segments[i].startsWith("{") && segments[i].endsWith("}");
            if (!slot && !segments[i].equals(actual[i])) {
                return false;
            }
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println(match("/users/{id}", "/users/42"));
        System.out.println(match("/users/{id}", "/users/42/books"));
        System.out.println(match("/users", "/users/42"));
    }
}
```

注意这段代码**故意没有尾斜杠检查**——所以它会把 `/users/42/` 也判成命中。这就是我上面那个 FAIL 的来源，加上检查才能满足第 1 条要求。

```java
import java.util.ArrayList;
import java.util.List;

public class Main {

    public static void main(String[] args) {
        Router router = new Router();
        router.register("GET", "/hello", id -> "hi");
        System.out.println(router.dispatch("GET", "/hello"));
    }
}

interface Handler {
    String handle(String pathVariable);
}

class Router {

    private static final class Route {
        final String method;
        final String[] segments;
        final Handler handler;

        Route(String method, String pattern, Handler handler) {
            this.method = method;
            this.segments = pattern.split("/");
            this.handler = handler;
        }

        String extract(String[] actual) {
            if (segments.length != actual.length) {
                return null;
            }
            String variable = "";
            for (int i = 0; i < segments.length; i++) {
                boolean slot = segments[i].startsWith("{") && segments[i].endsWith("}");
                if (slot) {
                    variable = actual[i];
                } else if (!segments[i].equals(actual[i])) {
                    return null;
                }
            }
            return variable;
        }
    }

    private final List<Route> routes = new ArrayList<>();

    void register(String httpMethod, String pattern, Handler handler) {
        routes.add(new Route(httpMethod, pattern, handler));
    }

    String dispatch(String httpMethod, String path) {
        // split 会丢掉尾部的空段，所以尾斜杠必须在切段前显式拒绝
        if (path.length() > 1 && path.endsWith("/")) {
            return "404";
        }
        String[] actual = path.split("/");
        boolean pathMatched = false;
        for (Route route : routes) {
            String variable = route.extract(actual);
            if (variable == null) {
                continue;
            }
            pathMatched = true;
            if (route.method.equals(httpMethod)) {
                return route.handler.handle(variable);
            }
        }
        return pathMatched ? "405" : "404";
    }
}
```

## 这一版还差什么

写完这一关，`Router` 有几个我明确没做的东西——知道差什么比以为写完了更重要：

- **多个路径变量**：`Handler.handle` 只收一个 `String`，所以 `/users/{id}/books/{bookId}` 这种模式，`extract` 只会留下最后一个变量（`bookId`）。要支持多变量，签名得改成 `handle(Map<String, String> vars)`。
- **尾部斜杠的真实框架行为**：Spring Framework 6 起默认不再做尾斜杠容错（`setUseTrailingSlashMatch` 已被标记废弃），所以本关的严格匹配其实跟现在的 Spring 一致；老教程里"加不加斜杠都行"的说法已经过时。
- **路由优先级**：本关按注册顺序匹配。真实框架有优先级规则来处理 `/users/{id}` 与 `/users/me` 的冲突——你想让 `/users/me` 命中静态路由，就得让更具体的先匹配。这一关不引入优先级，是因为在还没有冲突的场景里，优先级只会让行为更难预测。
- **路径参数解析**：`dispatch` 只返回字符串，不解析查询串、不做 URL 解码。
