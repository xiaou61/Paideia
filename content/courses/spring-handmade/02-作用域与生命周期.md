# 02 · 作用域与生命周期

## 这一课你要会

- 给容器加两种作用域：单例（一个类型一个实例）与原型（每次新造）；
- 在对象创建后、销毁前各插入一个回调，并让销毁按创建逆序进行；
- 说清"逆序销毁"为什么是必须的，而不是为了日志好看；
- 看懂固定测试入口在断言哪四次事件。

## 为什么

作用域决定了"这个对象被几个调用方共享"。放错了会出现最隐蔽的一类 bug：单例里的可变状态被并发请求互相覆盖。

销毁顺序则是资源正确释放的前提。这一关的四个断言会把"顺序"变成可见的东西——你不可能靠猜通过。

## 讲解

### 你要交的东西

| 符号 | 语义 |
| --- | --- |
| `interface InitializingBean { void afterCreate(); }` | 创建完成后回调 |
| `interface DisposableBean { void destroy(); }` | 关闭时回调 |
| `void singleton(Class<?>... types)` | 每个类型一个实例，创建后若实现 `InitializingBean` 就回调 |
| `void prototype(Class<?>... types)` | 只登记类型；每次 `get` 新造一个（也回调） |
| `<T> T get(Class<T> type)` | 单例返回表里那个；原型新造一个 |
| `void close()` | 对所有单例按创建**逆序**调 `destroy()` |

四个接口/类名写死，`TestMain` 直接用它们。

### 逆序为什么是必须的

`Beta` 可能在创建时依赖了 `Alpha`（哪怕是间接的）。关闭时如果先销毁 `Alpha`，`Beta` 的收尾代码就可能访问一个已经关闭的资源——连接池已关、线程池已 shutdown、文件句柄已释放。

**逆序保证被依赖者活得更久。** 这条规则在栈、`try-with-resources`、`useEffect` 的清理函数里都是同一个道理。

下面这段是最小示意：

<!-- run -->
```java
import java.util.ArrayList;
import java.util.List;

public class Main {

    static final List<String> events = new ArrayList<>();

    public static void main(String[] args) {
        open("a");
        open("b");
        closeAll("b", "a");
        System.out.println(events);
    }

    static void open(String name) {
        events.add("create-" + name);
    }

    static void closeAll(String... order) {
        for (String name : order) {
            events.add("destroy-" + name);
        }
    }
}
```
```text
[create-a, create-b, destroy-b, destroy-a]
```

### 原型与单例共用一个表会怎样

如果把原型也放进 `singletons`，第二次 `get` 就会返回第一次那个——原型退化成单例。所以两者必须分开记：一个 Map 存实例，一个 List 存"哪些类型是原型"。

`creationOrder` 只记单例。原型不进销毁序列——容器没有强引用它们，它们的生命周期到调用方用完为止（这是"原型"的固有代价：销毁责任转移给了使用者）。

```java
import java.lang.reflect.Constructor;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class Main {

    public static void main(String[] args) {
        Container container = new Container();
        container.singleton(String.class);
        System.out.println(container.get(String.class).getClass().getSimpleName());
        container.close();
    }
}

interface InitializingBean {
    void afterCreate();
}

interface DisposableBean {
    void destroy();
}

class Container {

    private final Map<Class<?>, Object> singletons = new LinkedHashMap<>();
    private final List<Class<?>> creationOrder = new ArrayList<>();
    private final List<Class<?>> prototypes = new ArrayList<>();

    void singleton(Class<?>... types) {
        for (Class<?> type : types) {
            singletons.put(type, instantiate(type));
            creationOrder.add(type);
        }
    }

    void prototype(Class<?>... types) {
        for (Class<?> type : types) {
            prototypes.add(type);
        }
    }

    private Object instantiate(Class<?> type) {
        try {
            Constructor<?> constructor = type.getDeclaredConstructor();
            constructor.setAccessible(true);
            Object made = constructor.newInstance();
            if (made instanceof InitializingBean bean) {
                bean.afterCreate();
            }
            return made;
        } catch (ReflectiveOperationException error) {
            throw new IllegalStateException("实例化失败: " + type.getSimpleName(), error);
        }
    }

    @SuppressWarnings("unchecked")
    <T> T get(Class<T> type) {
        Object singleton = singletons.get(type);
        if (singleton != null) {
            return (T) singleton;
        }
        if (prototypes.contains(type)) {
            return (T) instantiate(type);
        }
        return null;
    }

    void close() {
        for (int i = creationOrder.size() - 1; i >= 0; i--) {
            Object instance = singletons.get(creationOrder.get(i));
            if (instance instanceof DisposableBean bean) {
                bean.destroy();
            }
        }
    }
}
```

</details>

### 三个容易卡住的地方

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 第一次断言就红（事件只有 0 条） | `singleton` 里造了对象但没调 `afterCreate` | 造完立即判 `instanceof InitializingBean` |
| 原型断言红 | 原型也被塞进了单例表 | 只用 `prototypes` 这个 List 记类型 |
| 销毁顺序反了 | `close` 正向遍历 | 从 `creationOrder.size() - 1` 倒着走 |

## 常见误区

### 误区：初始化回调可以在构造器里做

**你以为**：构造函数最后一行就等于 `afterCreate`。
**其实**：构造器执行时依赖可能还没注入（本关的容器是构造器注入，所以恰好没这个问题；但 Spring 里字段注入就发生在构造器之后）。把"需要依赖"的初始化放进 `afterCreate`，语义在任何注入方式下都成立。
**怎么验证**：在构造器里读一个字段注入的依赖，看是否为 null。

### 误区：`close()` 里遍历 Map 就够

**你以为**：Map 的遍历顺序无所谓。
**其实**：`HashMap` 的顺序是哈希顺序，与创建顺序无关；即使换成 `LinkedHashMap`，你也需要**反向**遍历才符合逆序销毁。用两个结构（一个 Map 存实例、一个 List 存顺序）比依赖 Map 的迭代顺序可靠。
**怎么验证**：把 `creationOrder` 换成直接遍历 `singletons.keySet()`，看事件顺序断言是否还过。

## 小结

作用域的实质是"实例被几个调用方共享"。单例与原型要分开记录，否则原型退化成单例。初始化回调放在"依赖都已就位"之后，销毁必须逆序。克隆一个对象很简单，把顺序做对才难。
