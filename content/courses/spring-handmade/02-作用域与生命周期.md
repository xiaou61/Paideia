# 02 · 作用域与生命周期

## 加完 close() 之后，TestMain 只剩一条红

```text
FAIL destroy-reverse-order -> events were [create-a, create-b, destroy-a, destroy-b], expected destroy-b before destroy-a
1 check(s) failed
```

这是我在 01 的容器上补完 `singleton` / `prototype` / `get` / `close` 之后，跑「动手」里那个 `TestMain` 的完整输出：前三个断言过了，销毁顺序这条红。原因很直白，我把 `close()` 写成了顺着 `creationOrder` 从前往后走——Alpha 先登记就先销毁，Beta 后进就后关，正好把「后进先出」反过来。

红一条断言看起来只是日志不好看。把 Alpha 换成持有连接池、Beta 的收尾要从池里读一行，同一版代码就不是难看了，是直接崩在 `close()` 里面：

```text
create-a
create-b
create-gamma
destroy-a
destroy-b
Exception in thread "main" java.lang.IllegalStateException: pool already closed
	at Pool.query(Main.java:29)
	at Beta.destroy(Main.java:65)
	at Container.close(Main.java:152)
	at Main.main(Main.java:12)
```

栈帧从下往上读：`Main.main` 调 `close()`，`close()` 在循环里调到了 `Beta.destroy()`，`Beta.destroy()` 里的 `alpha.pool.query()` 撞上已经关掉的池。这段输出里还有第二件事：`create-gamma` 有，`destroy-gamma` 没有。Gamma 排在创建顺序的最后，正向遍历走到 Beta 就抛出去了，Gamma 一条清理都没做，也没有任何人知道。

这两件事都不需要更聪明的容器，`close()` 里改三处就够：方向、per-bean 的 `try`、异常的收尾。下面这段可以存成 `Main.java` 直接跑（JDK 21 以上；我这边是 JDK 25，Temurin），五段探针把上面几种情况各打一次。

## 跑一遍：把顺序、异常、原型摆在同一段里

`Container` 就是 01 那个容器：登记即实例化，构造器参数从已登记的实例里找，填不上就换下一个构造器，全填不上当场抛。这一课在它上面加了 `prototype()`、`get()` 的两个分支和 `close()`。`instantiate` 沿用 01 改好的那版（遍历所有构造器、参数用 `resolve` 填、填不上就换下一个），只多了一步「造完判 `instanceof InitializingBean` 就回调 `afterCreate()`」——所以 Beta 的构造器要一个 Alpha，Alpha 就必须先登记。

```java
import java.lang.reflect.Constructor;
import java.util.ArrayList;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

public class Main {

    static final List<String> EVENTS = new ArrayList<>();

    public static void main(String[] args) {
        order();
        prototype();
        duplicate();
        bothScopes();
        lateDependency();
    }

    static void order() {
        System.out.println("=== 1. 倒序销毁，并且每个 bean 单独兜住 ===");
        EVENTS.clear();
        Container container = new Container();
        container.singleton(Alpha.class, Beta.class, Gamma.class);
        System.out.println("创建后: " + EVENTS);
        try {
            container.close();
        } catch (RuntimeException error) {
            System.out.println("close 抛出了: " + error);
        }
    }

    static void prototype() {
        System.out.println("=== 2. 原型不进销毁序列 ===");
        EVENTS.clear();
        Container container = new Container();
        container.singleton(Alpha.class);
        container.prototype(Task.class);
        System.out.println("两次 get(Task.class) 是同一个: "
                + (container.get(Task.class) == container.get(Task.class)));
        System.out.println("销毁前: " + EVENTS);
        container.close();
        System.out.println("销毁后: " + EVENTS);
        System.out.println("close 之后还能 get 到实例: "
                + (container.get(Alpha.class) != null && container.get(Task.class) != null));
    }

    static void duplicate() {
        System.out.println("=== 3. 同一类型登记两次 ===");
        EVENTS.clear();
        Container container = new Container();
        container.singleton(Alpha.class, Alpha.class);
        System.out.println("创建时: " + EVENTS);
        container.close();
        System.out.println("销毁后: " + EVENTS);
    }

    static void bothScopes() {
        System.out.println("=== 4. 同一类型既登记原型又登记单例 ===");
        EVENTS.clear();
        Container container = new Container();
        container.prototype(Task.class);
        container.singleton(Task.class);
        System.out.println("登记完: " + EVENTS);
        System.out.println("两次 get 是同一个: "
                + (container.get(Task.class) == container.get(Task.class)));
        System.out.println("拿完之后: " + EVENTS);
        container.close();
        System.out.println("销毁后: " + EVENTS);
    }

    static void lateDependency() {
        System.out.println("=== 5. 依赖登记在依赖者后面 ===");
        Container container = new Container();
        try {
            container.singleton(Beta.class, Alpha.class);
        } catch (RuntimeException error) {
            System.out.println("启动就断了: " + error);
        }
    }
}

interface InitializingBean {
    void afterCreate();
}

interface DisposableBean {
    void destroy();
}

class Pool {
    private boolean open = true;

    String query() {
        if (!open) {
            throw new IllegalStateException("pool already closed");
        }
        return "row-1";
    }

    void close() {
        open = false;
    }
}

class Alpha implements InitializingBean, DisposableBean {
    final Pool pool = new Pool();

    public void afterCreate() {
        Main.EVENTS.add("create-a");
    }

    public void destroy() {
        pool.close();
        System.out.println("destroy-a（关池）");
    }
}

class Beta implements InitializingBean, DisposableBean {
    private final Alpha alpha;

    Beta(Alpha alpha) {
        this.alpha = alpha;
    }

    public void afterCreate() {
        Main.EVENTS.add("create-b");
    }

    public void destroy() {
        System.out.println("destroy-b，还能读到: " + alpha.pool.query());
    }
}

class Gamma implements InitializingBean, DisposableBean {
    public void afterCreate() {
        Main.EVENTS.add("create-gamma");
    }

    public void destroy() {
        System.out.println("destroy-gamma（自己炸）");
        throw new IllegalStateException("gamma cleanup failed");
    }
}

class Task implements InitializingBean, DisposableBean {
    public void afterCreate() {
        Main.EVENTS.add("create-task");
    }

    public void destroy() {
        Main.EVENTS.add("destroy-task");
    }
}

class Container {

    private final Map<Class<?>, Object> singletons = new LinkedHashMap<>();
    private final List<Class<?>> creationOrder = new ArrayList<>();
    private final List<Class<?>> prototypes = new ArrayList<>();

    void singleton(Class<?>... types) {
        for (Class<?> type : types) {
            singletons.put(type, instantiate(type));
            creationOrder.add(type);
        }
    }

    void prototype(Class<?>... types) {
        for (Class<?> type : types) {
            prototypes.add(type);
        }
    }

    private Object instantiate(Class<?> type) {
        for (Constructor<?> constructor : type.getDeclaredConstructors()) {
            Class<?>[] parameters = constructor.getParameterTypes();
            Object[] arguments = new Object[parameters.length];
            boolean satisfiable = true;
            for (int i = 0; i < parameters.length; i++) {
                arguments[i] = resolve(parameters[i]);
                if (arguments[i] == null) {
                    satisfiable = false;
                    break;
                }
            }
            if (!satisfiable) {
                continue;
            }
            try {
                constructor.setAccessible(true);
                Object made = constructor.newInstance(arguments);
                if (made instanceof InitializingBean bean) {
                    bean.afterCreate();
                }
                return made;
            } catch (ReflectiveOperationException error) {
                throw new IllegalStateException("实例化失败: " + type.getSimpleName(), error);
            }
        }
        throw new IllegalStateException("找不到可满足的构造器: " + type.getSimpleName());
    }

    private Object resolve(Class<?> wanted) {
        for (Object candidate : singletons.values()) {
            if (wanted.isAssignableFrom(candidate.getClass())) {
                return candidate;
            }
        }
        return null;
    }

    @SuppressWarnings("unchecked")
    <T> T get(Class<T> type) {
        if (prototypes.contains(type)) {
            return (T) instantiate(type);
        }
        return (T) singletons.get(type);
    }

    void close() {
        RuntimeException first = null;
        for (int i = creationOrder.size() - 1; i >= 0; i--) {
            Object instance = singletons.get(creationOrder.get(i));
            if (instance instanceof DisposableBean bean) {
                try {
                    bean.destroy();
                } catch (RuntimeException error) {
                    if (first == null) {
                        first = error;
                    } else {
                        first.addSuppressed(error);
                    }
                }
            }
        }
        if (first != null) {
            throw first;
        }
    }
}
```

## 从输出读五件事

### 一、倒序，并且每个 bean 单独兜住

第 1 段的顺序是 `destroy-gamma` → `destroy-b`（打印了 `还能读到: row-1`）→ `destroy-a`（关池）：从 `creationOrder.size() - 1` 往回走到 0。Beta 收尾时它依赖的 Alpha 还没关，池是开的。

Gamma 的 `destroy()` 自己抛了 `IllegalStateException`，可 `destroy-b`、`destroy-a` 照跑，`close()` 到最后才把那个异常抛出来。这就是第一幕里「Gamma 消失」的解法：不是给 Gamma 补个 `try`，而是让 `close()` 对每个 bean 单独兜住，第一个异常留到最后抛，其余用 `addSuppressed` 挂上去。`close()` 的语义是尽力关完，不是遇到第一个错就停。

### 二、原型：容器手里没有它的引用

第 2 段两次 `get(Task.class)` 拿到不同对象；`销毁前` 和 `销毁后` 的 `EVENTS` 一模一样，都是 `[create-a, create-task, create-task]`。Task 实现了 `DisposableBean`，它的 `destroy()` 会往 `EVENTS` 里塞一条 `destroy-task`；`close()` 确实跑了（`destroy-a（关池）` 那行），`destroy-task` 一条都没有。

原因不是「容器对原型只有弱引用」——这个说法让人以为问题出在 GC 上。实际是容器根本不记录原型实例：`prototype()` 只把 `Class` 塞进 `prototypes` 这个 List，`get()` 每次新造一个就直接返回，既不进 `singletons`，也不进 `creationOrder`。`close()` 遍历的是后两者，手上没有任何一个原型对象，所以「对它调 destroy」这句代码根本写不出来。

Spring 文档在 prototype 作用域那一节写的是同一个语义：初始化回调对所有作用域都调用，销毁回调对原型不调用，原型由客户端自己清理。本课只是照这段语义写的最小版，没有额外机制。

### 三、同一类型登记两次：两份实例，一份被挤出表

第 3 段 `singleton(Alpha.class, Alpha.class)` 打出 `创建时: [create-a, create-a]`，`close()` 又打出两行 `destroy-a`。

两行 `destroy-a` 不是两个实例各销毁一次。`singletons.put(type, instantiate(type))` 的第二个实参先求值——又造了一个 Alpha——再把第一个键的值覆盖掉。所以表里只剩第二份实例，`creationOrder` 里却有两条 Alpha；`close()` 逆序走两遍，两遍都从表里取到同一份，同一份被 `destroy()` 两次。第一份实例被挤出表之后，永远收不到销毁。

这跟「原型退化成单例」是同一类问题：容器的两张表（实例表、顺序表）靠类型这一个键对齐，类型重复就没有对齐可言。Spring 里 bean 有名字，重名是覆盖或报错；本课只有 `Class`，没有名字。

### 四、同一类型既登记原型又登记单例

第 4 段先 `prototype(Task.class)` 再 `singleton(Task.class)`：`登记完: [create-task]`，`两次 get 是同一个: false`，`拿完之后` 三条 `create-task`，`销毁后` 多出一条 `destroy-task`——表里那份单例被关掉了，而 `get()` 永远拿不到它。

这条决定了 `get()` 的写法：`prototypes` 的判断必须放在 `singletons` 前面。反过来写（先查表再判原型）就是原型退化成单例——表里那一份被两次 `get` 拿走，新对象永远不会被造出来。

### 五、倒序照着登记顺序来，不是照着依赖关系来

把顺序反过来本身是三行代码；容易出错的是顺带给它一个它给不了的保证。

第 5 段 `singleton(Beta.class, Alpha.class)`（Beta 的构造器要 Alpha）的输出是一行：`启动就断了: java.lang.IllegalStateException: 找不到可满足的构造器: Beta`。`resolve(Alpha.class)` 执行的那一刻 `singletons` 还是空的，Beta 唯一的构造器被判为不满足，容器当场抛。

反过来推：这个容器能启动，就说明依赖一定排在依赖者前面（否则造不出来）。所以「登记顺序等于依赖顺序」是 `resolve` 逼出来的结果，不是容器维护的约束。于是 `close()` 倒着遍历登记顺序，在这门课里才恰好等于「先关依赖者、后关被依赖者」。

容器自己不知道谁依赖谁：`creationOrder` 就是一个 `List<Class<?>>`，没有任何一条边。它没有依赖图，也没有 `@DependsOn` 这种显式声明。只要出现「A 在 `destroy()` 里用到 B，但 A 的构造器没有依赖 B」——比如 B 是后来用 setter 塞进 A 的，或者从静态字段取的——登记顺序就不再等于依赖顺序，倒着遍历也救不了。

## 症状 → 先看哪

| 症状 | 先看哪 |
| --- | --- |
| `close()` 输出里 `destroy-a` 排在 `destroy-b` 前面 | `close()` 的循环方向：`for (int i = 0; i < creationOrder.size(); i++)` 是正向；要从 `creationOrder.size() - 1` 开始 `i--` |
| 同一个 bean 的 `destroy()` 被调用两次 | 同一类型被 `singleton(...)` 登记了两次，`creationOrder` 里就有两条；容器不去重，也不报错 |
| 只有排在后面的 bean 没收到 `destroy()` | 循环体里缺 per-bean `try/catch`：前一个 bean 抛出，后面的全跳过 |
| 原型两次 `get` 拿到同一个对象 | `get()` 里先查了 `singletons`；`prototypes` 的分支要放前面 |
| `close()` 之后 `get()` 还能拿到实例 | 本课没有 closed 标志。第 2 段末尾那行 `close 之后还能 get 到实例: true` 就是它 |

## 还差的

- 没有依赖图，也没有 `@DependsOn`：销毁顺序只是登记顺序的倒序。任何「销毁时才用到、但构造器没依赖」的关系都会让这个倒序失效，而这个容器不做拓扑排序，也不会告警。
- 没有作用域冲突检测，也没有 bean 名字：同一类型既登记原型又登记单例不报错（第 4 段，那份单例白造、还会被销毁一次）；同一类型登记两次也不去重（第 3 段，第一份实例收不到销毁）。
- 没有 early reference：`singleton()` 里 `singletons.put(type, instantiate(type))` 的实参先求值，`afterCreate()` 跑完对象才进表，所以初始化回调里 `get(自己)` 拿到的是 null。Spring 用创建期提前暴露的引用解决这件事，本课没有那一层。
- `close()` 之后容器照样能用：没有 closed 状态位，`get()` 继续返回单例、继续新造原型（第 2 段末尾那行 `close 之后还能 get 到实例: true`）。
- 没有并发安全：`LinkedHashMap` 和 `ArrayList` 都没同步，运行期一个线程 `singleton()`、另一个线程 `get()`，`ConcurrentModificationException` 就从这里来。本课所有输出都是单线程跑的。
