# 04 · 代理：前后置通知与自调用

## 我期待 6 条日志，只拿到 2 条

这一关的测试里有一条断言，是把 `twice()` 期间的日志打出来看一眼。它长这样：

```text
[before:twice, after:twice]
```

我第一次做的时候盯着这两行看了很久。`twice()` 里面明明调了两次 `hello()`，为什么一条 `before:hello` 都没有？

答案只有一句话：**`twice()` 里的那个 `hello(name)`，`this` 是原始对象，不是代理**。代理是套在对象外面的一层壳，进了壳里之后，对象调自己就是纯粹的方法调用，没有任何东西经过壳。

这一关值得亲手做一遍，因为 `@Transactional`、`@Async`、`@Cacheable`、`@PreAuthorize` 全都建立在"代理能拦到方法调用"这个前提上，而它们失效的场景有很大一部分源于同一个事实：**那次调用没经过代理**。自己写一遍，你会知道这不是"框架的怪癖"，而是一个只有一条出路的必然。

## 你要交的东西

`Main.java` 里已经给出两样东西，你只需要实现 `ProxyFactory.timed`：

| 符号 | 语义 |
| --- | --- |
| `interface Greeting { String hello(String name); String twice(String name); }` | 目标接口。**`twice` 必须在这个接口上**，否则代理暴露不出来 |
| `class GreetingImpl implements Greeting` | 目标实现，`twice` 内部调用 `hello` |
| `static Greeting timed(Greeting target, List<String> log)` | 返回代理：每次经过代理的方法调用，先 `log.add("before:" + 方法名)`，返回后 `log.add("after:" + 方法名)` |

日志格式写死：`before:hello` / `after:hello`。

## 代理只拦「从外面进来的那一次」

`Proxy.newProxyInstance` 的三段参数：类加载器、要实现的接口列表、调用处理器。处理器里 `method.invoke(target, args)` 调的是**原始对象**。

原始对象的 `twice()` 里写的是 `hello(name)`，等价于 `this.hello(name)`——`this` 是原始对象，不是代理。所以那两次调用根本不经过处理器。

先跑一遍最小的代理，确认"外面进来的调用确实被拦住了"：

<!-- run -->
```java
import java.lang.reflect.Proxy;

public class Main {

    interface Greeting {
        String hello(String name);
    }

    static class Impl implements Greeting {
        public String hello(String name) {
            return "hello, " + name;
        }
    }

    public static void main(String[] args) {
        Greeting proxy = (Greeting) Proxy.newProxyInstance(
                Greeting.class.getClassLoader(),
                new Class<?>[]{Greeting.class},
                (p, method, a) -> {
                    System.out.println("经过代理: " + method.getName());
                    return method.invoke(new Impl(), a);
                });
        System.out.println(proxy.hello("world"));
    }
}
```
```text
经过代理: hello
hello, world
```

注意这段代码里 `method.invoke(new Impl(), a)` 每次新建一个实例——只是为了演示代理能拦住调用，真实实现必须 `invoke` 传进来的那个 `target`，否则目标对象的状态全丢了。

## 为什么这个"缺陷"没法在代理层修

代理是在**对象外面**加的一层。原始对象内部的方法调用根本不跨出对象，外面那层没有任何机会插入逻辑。

能想到的替代方案只有一个：改写字节码，把对象里所有 `this.x()` 变成"先查有没有切面"。那就不叫代理了——Spring 的 AOP 里另一个选项（AspectJ 编译期/加载期织入）就是干这个的，代价是要改构建或加 `-javaagent`。**代理方案选的就是"不碰字节码"这条代价更小的路，自调用拦不到是它的代价，不是它的 bug。**

```java
import java.lang.reflect.Proxy;
import java.util.List;

public class Main {

    public static void main(String[] args) {
        List<String> log = new java.util.ArrayList<>();
        Greeting proxy = ProxyFactory.timed(new GreetingImpl(), log);
        System.out.println(proxy.hello("world"));
        System.out.println(log);
    }
}

interface Greeting {
    String hello(String name);

    String twice(String name);
}

class GreetingImpl implements Greeting {

    public String hello(String name) {
        return "hello, " + name;
    }

    public String twice(String name) {
        return hello(name) + hello(name);
    }
}

class ProxyFactory {

    static Greeting timed(Greeting target, List<String> log) {
        return (Greeting) Proxy.newProxyInstance(
                Greeting.class.getClassLoader(),
                new Class<?>[]{Greeting.class},
                (proxy, method, args) -> {
                    log.add("before:" + method.getName());
                    Object result = method.invoke(target, args);
                    log.add("after:" + method.getName());
                    return result;
                });
    }
}
```

</details>

三个我卡过的点：

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 编译报 `twice` 找不到 | 把 `twice` 从接口里删了 | 它必须在接口上，代理才能暴露它 |
| 自调用断言红（日志里有 4 条） | 处理器里调了代理自己的方法，而不是 `target` | `method.invoke(target, args)` 必须是原始对象 |
| 编译警告 `unchecked` | 强转 `(Greeting)` 没加注解 | 方法上加 `@SuppressWarnings("unchecked")`，或用局部变量接 |

第一个坑值得多说一句：`Proxy.newProxyInstance` 只能代理**接口**上的方法。目标类里如果有接口没有的 public 方法，代理对象上根本不存在这个方法，编译器直接报找不到。这也是为什么 Spring 有两种代理方式——基于接口的 JDK 代理（就是本关这个）和基于继承的 CGLIB。

## 三类失效，全是这一条推出来的

`@Transactional`（以及所有基于代理的注解）失效，追根到底只有三条路，而且全是"那次调用没经过代理"的变体：

**一、自调用。** 就是本关这条：`this.x()` 不经过代理。修法是把事务方法拆到另一个类，或者用 `AopContext.currentProxy()`（需要 `@EnableAspectJAutoProxy(exposeProxy = true)`）。**拆类是最省事、最可靠的**，注入自己（`@Lazy` 自注入）虽然能工作，但它把一个设计问题藏了起来。

**二、private / final 方法。** 代理是"实现接口"或"继承父类"——两种方式都覆盖不到 `private` 方法，也覆盖不到 `final` 方法（不能被重写）。加在上面的 `@Transactional` 完全不生效，而且**不报错**。这条最阴，因为代码看起来完全正常。

**三、类没有被 Spring 管。** 自己 `new` 出来的对象不是代理，注解当然没人读。这个最好查——看一眼调用方是不是从容器里拿的。

验这三点有个共同方法：**看日志里有没有代理类的名字**。Spring 的代理对象在 `getClass()` 上会带 `$Proxy`（JDK 代理）或 `$Cglib$`/`$$SpringCGLIB$$`（CGLIB），原样打印一下就知道自己拿到的是不是壳。

## 结尾：这一关之后你该认得出什么

下次看到"事务没回滚"、"缓存没生效"、"异步没异步"，先别怀疑注解写错了，先问：**这次调用经过代理了吗？** 这一问能省掉大半排查时间。

最后一关：把事务模板 + 服务写出来，并让"异常被吞掉不回滚"与"自调用没有事务"变成四条可执行的断言。
