# 04 · 代理：前后置通知与自调用

## 这一课你要会

- 用 `java.lang.reflect.Proxy` 生成一个"调用前后各做一件事"的代理；
- 说清为什么 `twice()` 内部调 `hello()` 时，代理**看不到**那两次调用；
- 知道"自调用不经过代理"是代理模式的固有结果，不是 bug；
- 把这条结论对照到 `@Transactional` 的失效场景上。

## 为什么

这是整个平台里最值得亲手做一遍的一关。`@Transactional`、`@Async`、`@Cacheable`、`@PreAuthorize` 全部建立在"代理能拦到方法调用"这个前提上，而它们的失效场景有九成都源于同一个事实：**那次调用没经过代理**。

自己写一遍代理之后，你会知道这句话不是"框架的一个怪癖"，而是一个只有一条出路的必然。

## 讲解

### 你要交的东西

`Main.java` 里已给出三样东西，你只需实现 `ProxyFactory.timed`：

| 符号 | 语义 |
| --- | --- |
| `interface Greeting { String hello(String name); String twice(String name); }` | 目标接口。**`twice` 必须在这个接口上**，否则代理暴露不出来 |
| `class GreetingImpl implements Greeting` | 目标实现，`twice` 内部调用 `hello` |
| `static Greeting timed(Greeting target, List<String> log)` | 返回代理：每次经过代理的方法调用，先 `log.add("before:" + 方法名)`，返回后 `log.add("after:" + 方法名)` |

日志格式写死：`before:hello` / `after:hello`。

### 代理只拦"从外面进来的那一次"

`Proxy.newProxyInstance` 的三段参数：类加载器、要实现的接口列表、调用处理器。处理器里 `method.invoke(target, args)` 调的是**原始对象**。

原始对象的 `twice()` 里写的是 `hello(name)`，等价于 `this.hello(name)`——`this` 是原始对象，不是代理。所以那两次调用根本不经过处理器。

<!-- run -->
```java
import java.lang.reflect.Proxy;

public class Main {

    interface Greeting {
        String hello(String name);
    }

    static class Impl implements Greeting {
        public String hello(String name) {
            return "hello, " + name;
        }
    }

    public static void main(String[] args) {
        Greeting proxy = (Greeting) Proxy.newProxyInstance(
                Greeting.class.getClassLoader(),
                new Class<?>[]{Greeting.class},
                (p, method, a) -> {
                    System.out.println("经过代理: " + method.getName());
                    return method.invoke(new Impl(), a);
                });
        System.out.println(proxy.hello("world"));
    }
}
```
```text
经过代理: hello
hello, world
```

### 为什么这个"缺陷"无法在代理层修复

代理是在**对象外面**加的一层。原始对象内部的方法调用根本不跨出对象，外面那层没有任何机会插入逻辑。

唯一的替代方案是改写字节码（让你对象的所有 `this.x()` 变成"先查有没有切面"）——那就不叫代理了，代价也完全不同。

```java
import java.lang.reflect.Proxy;
import java.util.List;

public class Main {

    public static void main(String[] args) {
        List<String> log = new java.util.ArrayList<>();
        Greeting proxy = ProxyFactory.timed(new GreetingImpl(), log);
        System.out.println(proxy.hello("world"));
        System.out.println(log);
    }
}

interface Greeting {
    String hello(String name);

    String twice(String name);
}

class GreetingImpl implements Greeting {

    public String hello(String name) {
        return "hello, " + name;
    }

    public String twice(String name) {
        return hello(name) + hello(name);
    }
}

class ProxyFactory {

    static Greeting timed(Greeting target, List<String> log) {
        return (Greeting) Proxy.newProxyInstance(
                Greeting.class.getClassLoader(),
                new Class<?>[]{Greeting.class},
                (proxy, method, args) -> {
                    log.add("before:" + method.getName());
                    Object result = method.invoke(target, args);
                    log.add("after:" + method.getName());
                    return result;
                });
    }
}
```

</details>

### 三个容易卡住的地方

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 编译报 `twice` 找不到 | 把 `twice` 从接口里删了 | 它必须在接口上，代理才能暴露它 |
| 自调用断言红（日志里有 4 条） | 处理器里调了代理自己的方法，而不是 `target` | `method.invoke(target, args)` 必须是原始对象 |
| 编译警告 `unchecked` | 强转 `(Greeting)` 没加注解 | 方法上加 `@SuppressWarnings("unchecked")`，或用局部变量接 |

## 常见误区

### 误区：只要实现了接口，代理就能拦到所有方法调用

**你以为**：代理实现同一接口，所有调用都会被看见。
**其实**：只拦"通过代理引用发起"的调用。对象内部任何 `this.x()` 都绕过它。这也是为什么"把事务方法拆到另一个类"是最省事、最可靠的修法。
**怎么验证**：本关第四条断言就是它的可执行证明。

### 误区：`@Transactional` 加在 private 方法上也能生效

**你以为**：注解写了就该生效。
**其实**：代理是"实现接口"或"继承父类"——两种方式都覆盖不到 `private` 方法。加在 `private` 方法上的 `@Transactional` 完全不生效，而且不报错。
**怎么验证**：把第 1 关的 `Container` 改一改，只代理 public 方法，然后给一个 private 方法加日志，看是否会打印。

## 小结

代理就是"外套一层"，靠实现同一接口或继承父类来覆盖方法。它只拦从外面进来的调用，所以对象内部的 `this.x()` 一定绕过。`@Transactional` 的三类失效（自调用、private、final）全从这一条推出来。

最后一关：把事务模板 + 服务写出来，并让"异常被吞掉不回滚"与"自调用没有事务"变成四条可执行的断言。
