# 01 · 容器：反射造对象并填参数

## 先跑坏的那一版：Greeter 注册在 RepoImpl 前面

<!-- run -->
```java
import java.lang.reflect.Constructor;
import java.util.HashMap;
import java.util.Map;

public class Main {

    interface Repo {
        String name();
    }

    static class RepoImpl implements Repo {
        public String name() {
            return "in-memory";
        }
    }

    static class Greeter {
        private final Repo repo;

        Greeter(Repo repo) {
            this.repo = repo;
        }

        String hello() {
            return "hello, " + repo.name();
        }
    }

    public static void main(String[] args) {
        Container container = new Container();
        container.register(Greeter.class, RepoImpl.class);
        try {
            System.out.println(container.get(Greeter.class).hello());
        } catch (RuntimeException error) {
            System.out.println(error);
        }
    }
}

class Container {

    private final Map<Class<?>, Object> instances = new HashMap<>();

    void register(Class<?>... types) {
        for (Class<?> type : types) {
            instances.put(type, instantiate(type));
        }
    }

    private Object instantiate(Class<?> type) {
        try {
            Constructor<?> constructor = type.getDeclaredConstructors()[0];
            Class<?>[] parameters = constructor.getParameterTypes();
            Object[] arguments = new Object[parameters.length];
            for (int i = 0; i < parameters.length; i++) {
                arguments[i] = resolve(parameters[i]);
            }
            return constructor.newInstance(arguments);
        } catch (ReflectiveOperationException error) {
            throw new IllegalStateException("实例化失败: " + type.getSimpleName(), error);
        }
    }

    private Object resolve(Class<?> wanted) {
        for (Object candidate : instances.values()) {
            if (wanted.isAssignableFrom(candidate.getClass())) {
                return candidate;
            }
        }
        return null;
    }

    @SuppressWarnings("unchecked")
    <T> T get(Class<T> type) {
        return (T) instances.get(type);
    }
}
```

```text
java.lang.NullPointerException: Cannot invoke "Main$Repo.name()" because "this.repo" is null
```

输出里没有「缺依赖」三个字，只有 `Greeter.hello()` 里的 `repo.name()`。`resolve(Repo.class)` 扫了一遍 `instances`，当时表是空的，返回 `null`；`instantiate` 没检查这个 `null`，直接把它当构造器实参传了进去。对象造出来了，`repo` 是 `null`，错误拖到第一次调用才出现。

我原以为 `register` 会在这个顺序上立刻拒绝；实际它先造了一个坏对象。这个差别很重要：报错点不在缺依赖的地方，而在使用依赖的地方。

这版还有第二个问题：`getDeclaredConstructors()[0]` 只取第一个构造器；类有多个构造器时，选哪个没有保证。

## 让容器在造对象前就拒绝

修法不是「把 null 换成默认值」，而是在调用 `newInstance` 之前检查每个参数是否都解析到了；只要有一个是 `null`，这个构造器就不满足，换下一个。所有构造器都不满足时，抛 `IllegalStateException`，消息里带类型名。

下面这段把 `Greeter`、`A`/`B`、`FieldGreeter` 几个探针放在一个 `main` 里，一次跑完：

<!-- run -->
```java
import java.lang.reflect.Constructor;
import java.util.HashMap;
import java.util.Map;

public class Main {

    interface Repo {
        String name();
    }

    static class RepoImpl implements Repo {
        public String name() {
            return "in-memory";
        }
    }

    static class MirrorRepo implements Repo {
        public String name() {
            return "mirror-repo";
        }
    }

    static class Greeter {
        private final Repo repo;

        Greeter(Repo repo) {
            this.repo = repo;
        }

        String hello() {
            return "hello, " + repo.name();
        }
    }

    static class FieldGreeter {
        private Repo repo;

        FieldGreeter() {
        }

        String hello() {
            return "hello, " + repo.name();
        }
    }

    static class A {
        A(B b) {
        }
    }

    static class B {
        B(A a) {
        }
    }

    public static void main(String[] args) {
        Container wrongOrder = new Container();
        try {
            wrongOrder.register(Greeter.class, RepoImpl.class);
        } catch (IllegalStateException error) {
            System.out.println("wrong order: " + error.getMessage());
        }

        Container rightOrder = new Container();
        rightOrder.register(RepoImpl.class, Greeter.class);
        System.out.println("right order: " + rightOrder.get(Greeter.class).hello());
        System.out.println("get(Repo.class): " + rightOrder.get(Repo.class));

        try {
            new Container().register(A.class, B.class);
        } catch (IllegalStateException error) {
            System.out.println("cycle: " + error.getMessage());
        }

        Container fields = new Container();
        fields.register(RepoImpl.class, FieldGreeter.class);
        try {
            System.out.println("field: " + fields.get(FieldGreeter.class).hello());
        } catch (NullPointerException error) {
            System.out.println("field: " + error.getClass().getSimpleName());
        }
    }
}

class Container {

    private final Map<Class<?>, Object> instances = new HashMap<>();

    void register(Class<?>... types) {
        for (Class<?> type : types) {
            instances.put(type, instantiate(type));
        }
    }

    private Object instantiate(Class<?> type) {
        for (Constructor<?> constructor : type.getDeclaredConstructors()) {
            Class<?>[] parameters = constructor.getParameterTypes();
            Object[] arguments = new Object[parameters.length];
            boolean satisfiable = true;
            for (int i = 0; i < parameters.length; i++) {
                arguments[i] = resolve(parameters[i]);
                if (arguments[i] == null) {
                    satisfiable = false;
                    break;
                }
            }
            if (!satisfiable) {
                continue;
            }
            try {
                constructor.setAccessible(true);
                return constructor.newInstance(arguments);
            } catch (ReflectiveOperationException error) {
                throw new IllegalStateException("实例化失败: " + type.getSimpleName(), error);
            }
        }
        throw new IllegalStateException("找不到可满足的构造器: " + type.getSimpleName());
    }

    private Object resolve(Class<?> wanted) {
        for (Object candidate : instances.values()) {
            if (wanted.isAssignableFrom(candidate.getClass())) {
                return candidate;
            }
        }
        return null;
    }

    @SuppressWarnings("unchecked")
    <T> T get(Class<T> type) {
        return (T) instances.get(type);
    }
}
```
```text
wrong order: 找不到可满足的构造器: Greeter
right order: hello, in-memory
get(Repo.class): null
cycle: 找不到可满足的构造器: A
field: NullPointerException
```

这五条输出分别说明：

- `wrong order`：`register` 是边登记边造，造 `Greeter` 的时候 `RepoImpl` 还没进表。容器没有「先把所有类型收完再统一装配」这一步。
- `right order`：把依赖放在前面，`Repo` 参数就能拿到 `RepoImpl`。
- `get(Repo.class): null`：`get` 只按 `Class` 精确查表，不做 `isAssignableFrom`。`RepoImpl` 能赋给 `Repo`，但表里的键是 `RepoImpl.class`，不是 `Repo.class`。按接口取实例是另一件事，本课没写。
- `cycle`：A 的构造器要 B、B 的构造器要 A，先造 A 时 B 还不在表里，于是 A 被判定为「没有可满足的构造器」。它没有进入「正在创建」的状态，也没有环检测。
- `field`：`FieldGreeter` 的无参构造器被调用了，但 `repo` 字段没人填；NPE 在 `hello()` 里才出现。

`resolve` 的关键判断是 `wanted.isAssignableFrom(candidate.getClass())`：`Repo.class.isAssignableFrom(RepoImpl.class)` 为 true，所以构造器参数 `Repo` 能拿到 `RepoImpl`。`get` 里没有这句，它只有 `instances.get(type)`。

### 缺 Bean 不是编译期错误

有一句常见说法是「构造器注入让依赖缺失在编译期暴露」。这句不成立。编译期能查的只有你手写 `new Greeter()` 少传参数；`container.register(Greeter.class, RepoImpl.class)` 收的是 `Class<?>`，编译器不知道注册表里有什么。缺 Bean 是 `register` 执行时的运行期失败——如果 `register` 在 `main` 里，它看起来像启动失败，但不是编译失败。

构造器注入真正的好处是另外两条：构造器返回时对象已经完整，不会出现「先 new 出来、过一会儿再被填字段」的半成品；依赖字段可以写成 `final`，构造完就不能再换。`FieldGreeter` 那种无参构造器 + 字段等待填充的写法，本课容器不会替它补。

## 这个容器不做什么

它只有 `register`、`instantiate`、`resolve`、`get` 四个动作。下面这些能力都没有，读的时候不要按 Spring 的默认行为去猜。

### 没有依赖图解析：登记顺序就是创建顺序

`register` 不是先记下类型、最后统一装配；它每收到一个类型就立刻 `instantiate`。`instantiate` 里的 `resolve` 只能看到 `instances` 里已经有的对象。所以 `register(Greeter.class, RepoImpl.class)` 一定失败，`register(RepoImpl.class, Greeter.class)` 才行。

真实 Spring 不是这样：它先把 bean 定义收集起来，`getBean` 时再按依赖递归创建。它不需要你手写顺序，代价是要维护一张定义表和一套解析流程——本课没有这张表。

### 没有环检测

A 的构造器要 B，B 的构造器要 A。你先注册 A，`resolve(B.class)` 看不到 B；先注册 B，`resolve(A.class)` 看不到 A。两种顺序都只会得到：

```text
找不到可满足的构造器: A
```

或者 `找不到可满足的构造器: B`。它不会说「A 正在创建中」。`BeanCurrentlyInCreationException` 是 Spring 的异常名，不是本课容器的；本课也没有三级缓存。

### 只有构造器注入

`instantiate` 只读构造器参数，构造完就返回。字段注入、setter 注入、`@Autowired` 标注的字段都不会被处理。上面 `FieldGreeter` 就是证据：无参构造器成功了，`repo` 仍是 `null`，NPE 要等到 `hello()`。这也是为什么本课的类要把依赖放进构造器、字段写成 `final`。

多个构造器都能满足时，它取 `getDeclaredConstructors()` 返回的第一个，顺序同样没有保证；它不会像 Spring 那样做候选构造器排序，`@Autowired` 在这里也不读。

### 多候选按 HashMap 迭代到的第一个

`resolve` 是 `for (Object candidate : instances.values())`，谁先被遍历到就用谁。两个实现类都注册时，没有 `@Primary`、没有 `@Qualifier`、没有按名字或登记顺序的优先级。

`instances` 是 `HashMap`，它的迭代顺序不是登记顺序，也不保证跨 JVM 稳定；`Class` 没有重写 `hashCode`，用的是对象身份哈希，换个类名或换台机器，顺序都可能变。我在本机 JDK 25 上把 `register(RepoImpl.class, MirrorRepo.class, Greeter.class)` 和 `register(MirrorRepo.class, RepoImpl.class, Greeter.class)` 各跑 10 次，10 次都打印 `repo-impl`——这只是这台机器上 `HashMap` 的当前顺序，不是承诺。

### 不认 @Primary / @Qualifier / @Lazy

容器只接收 `Class<?>`，没有注解扫描。`@Primary`、`@Qualifier` 不会改变上面那个「第一个」；`@Lazy` 也不会让对象晚点创建——本课没有代理、没有作用域工厂，`register` 时就把对象造了。下一课加作用域，仍然不会自动读这些注解。

### setAccessible 不是万能钥匙

第一段代码没写 `setAccessible`，`Greeter` 的包级私有构造器照样被调用了。原因是 `Container`、`Greeter`、`Main` 都在默认包，反射调用方与 `Greeter` 同包，包级私有构造器可见。`setAccessible(true)` 不是「反射调用构造器的必填项」。

只有构造器对 `Container` 不可见时才需要它——比如跨包的非 public 构造器，或同包的 private 构造器。我建了 `app`、`pkg` 两个包，`app.Main` 反射 `pkg.Widget` 的包级私有构造器，第一次不调 `setAccessible`：

```text
java.lang.IllegalAccessException: class app.Main cannot access a member of class pkg.Widget with package access
```

调了之后能造。参考实现里的 `Container` 仍然保留 `setAccessible(true)`，因为它想支持跨包的非 public 构造器；你如果只在自己的默认包里用，可以删掉这一行。但对非 open 模块，`setAccessible` 自己会抛 `InaccessibleObjectException`：

<!-- run -->
```java
import java.lang.reflect.Constructor;

public class Main {

    public static void main(String[] args) {
        try {
            Constructor<?> constructor = java.util.Collections.emptyList()
                    .getClass()
                    .getDeclaredConstructor();
            constructor.setAccessible(true);
        } catch (Exception error) {
            System.out.println(error.getClass().getName());
            System.out.println("is ReflectiveOperationException: "
                    + (error instanceof ReflectiveOperationException));
            System.out.println(error.getMessage().replaceAll(" @[0-9a-f]+$", ""));
        }
    }
}
```
```text
java.lang.reflect.InaccessibleObjectException
is ReflectiveOperationException: false
Unable to make private java.util.Collections$EmptyList() accessible: module java.base does not "opens java.util" to unnamed module
```

那段 `replaceAll` 只是把消息末尾每次不同的模块哈希去掉；异常类名和前半句是原样。`InaccessibleObjectException` 是 `RuntimeException`，不是 `ReflectiveOperationException`；上面 `instantiate` 的 `catch` 包不住它。常规做法是加 JVM 启动参数 `--add-opens java.base/java.util=ALL-UNNAMED`，这不是容器能自己解决的。

## 动手

固定入口 `TestMain.java` 已经给你了；你只改 `Main.java`。`starter` 里的 `main` 只是占位，真正跑的是 `TestMain`；`Container` 的两个方法才是你要补的。它断言两件事：`get(Greeter.class)` 能打印 `hello, in-memory`，两次 `get(RepoImpl.class)` 拿到同一个引用。如果容器把 `null` 塞进 `Greeter`，`TestMain` 会在 `hello()` 这行直接 NPE，不会打印 FAIL；先让容器拒绝缺依赖。

## 还差的

- 没有依赖图解析：`register` 的顺序错了就起不来；先收集定义、再按依赖递归创建的两阶段没做。
- 没有环检测：A↔B 只会得到「找不到可满足的构造器」；Spring 的 `BeanCurrentlyInCreationException` 和三级缓存都没有。
- 只有构造器注入：字段/setter 注入、`@Autowired` 扫描、`@Primary`/`@Qualifier`/`@Lazy` 都没做，多候选只能靠 `HashMap` 的顺序碰运气。
- 没有作用域和生命周期：只有「登记即单例」，没有原型、初始化回调、逆序销毁，也没有 `close()`；这些在下一课。
- 没有并发安全：`HashMap` 没有同步；并发 `register` 可能丢更新，`resolve` 遍历时撞上修改会抛 `ConcurrentModificationException`。
