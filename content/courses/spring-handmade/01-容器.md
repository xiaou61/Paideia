# 01 · 容器：反射造对象并填参数

## 这一课你要会

- 用反射读一个类的构造器，并按参数类型找到已经造好的依赖；
- 实现"登记若干类型 → 按类型取出实例"，且同一类型只造一次；
- 看懂固定测试入口 `TestMain` 在断言什么，以及它为什么改不了；
- 知道"按接口注入"需要的是 `isAssignableFrom`，不是类型相等。

## 为什么

后面四关都建在这一关之上：路由表要先能拿到 handler 对象，事务模板要先能注入到 Service 里。如果容器这一步是"抄一段看不太懂"，后面每一关都会卡在同一处。

所以这一关的判据很硬：**不看你的代码像不像 Spring，只看同一个入口能不能全部通过**。

## 讲解

### 你要交的东西

`Main.java` 里必须有一个**包级私有**的顶层类 `Container`，签名写死：

| 方法 | 语义 |
| --- | --- |
| `void register(Class<?>... types)` | 按顺序登记这些类型，每个都造一个实例并记住 |
| `<T> T get(Class<T> type)` | 按类型返回同一个实例；没有就返回 null |

登记顺序就是实例化顺序：一个类型在登记时只能用到**它之前已经登记好的**依赖。

### 测试入口在断言什么

`TestMain`（只读）自己声明了三个类型：`Repo` 接口、`RepoImpl` 实现、`Greeter`（构造器收一个 `Repo`）。它做两件事：

1. `register(RepoImpl.class, Greeter.class)`，然后 `get(Greeter.class)` 调 `hello()`——如果构造器参数没被填，`hello()` 会抛空指针；
2. 两次 `get(RepoImpl.class)` 必须拿到同一个引用。

它**不会**读你的源码，也不会看你有没有写注释。它只调那两个方法。

### 关键只有一句：按"能不能赋值"找依赖

`Greeter` 的构造器参数类型是 `Repo`（接口），而你登记的是 `RepoImpl`（实现类）。两者不是同一个 `Class` 对象，所以：

正确的找法是遍历已登记的实例，用 `wanted.isAssignableFrom(candidate.getClass())` 判断。下面这段是这一步的最小内核：

<!-- run -->
```java
import java.lang.reflect.Constructor;

public class Main {

    interface Repo {
        String name();
    }

    static class RepoImpl implements Repo {
        public String name() {
            return "in-memory";
        }
    }

    static class Greeter {
        private final Repo repo;

        Greeter(Repo repo) {
            this.repo = repo;
        }

        String hello() {
            return "hello, " + repo.name();
        }
    }

    public static void main(String[] args) throws Exception {
        Object repo = new RepoImpl();
        Constructor<?> constructor = Greeter.class.getDeclaredConstructors()[0];
        constructor.setAccessible(true);
        Greeter greeter = (Greeter) constructor.newInstance(repo);
        System.out.println(greeter.hello());
    }
}
```
```text
hello, in-memory
```

`constructor.setAccessible(true)` 是必须的：`Greeter` 的构造器是包级私有，反射调用前要显式打开。

<summary>展开答案（改坏一次也要自己改回来）</summary>

```java
import java.lang.reflect.Constructor;
import java.util.HashMap;
import java.util.Map;

public class Main {

    public static void main(String[] args) {
        Container container = new Container();
        container.register(String.class);
        System.out.println(container.get(String.class).getClass().getSimpleName());
    }
}

class Container {

    private final Map<Class<?>, Object> instances = new HashMap<>();

    void register(Class<?>... types) {
        for (Class<?> type : types) {
            instances.put(type, instantiate(type));
        }
    }

    private Object instantiate(Class<?> type) {
        for (Constructor<?> constructor : type.getDeclaredConstructors()) {
            Class<?>[] parameters = constructor.getParameterTypes();
            Object[] arguments = new Object[parameters.length];
            boolean satisfiable = true;
            for (int i = 0; i < parameters.length; i++) {
                Object dependency = resolve(parameters[i]);
                if (dependency == null) {
                    satisfiable = false;
                    break;
                }
                arguments[i] = dependency;
            }
            if (!satisfiable) {
                continue;
            }
            try {
                constructor.setAccessible(true);
                return constructor.newInstance(arguments);
            } catch (ReflectiveOperationException error) {
                throw new IllegalStateException("实例化失败: " + type.getSimpleName(), error);
            }
        }
        throw new IllegalStateException("找不到可满足的构造器: " + type.getSimpleName());
    }

    private Object resolve(Class<?> wanted) {
        Object direct = instances.get(wanted);
        if (direct != null) {
            return direct;
        }
        for (Object candidate : instances.values()) {
            if (wanted.isAssignableFrom(candidate.getClass())) {
                return candidate;
            }
        }
        return null;
    }

    @SuppressWarnings("unchecked")
    <T> T get(Class<T> type) {
        return (T) instances.get(type);
    }
}
```

</details>

### 三个容易卡住的地方

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 编译报"找不到符号 Container" | `Container` 被写成了 `public class Container`，与文件名 `Main.java` 不匹配 | 改成包级私有（不加 `public`） |
| `greeter` 是 null | `register` 里没把实例放进表，或 `get` 用了新造的对象 | 注册时造一次并缓存，`get` 只查表 |
| `hello()` 抛空指针 | 构造器参数没被填（`repo` 为 null） | 用 `isAssignableFrom` 找依赖，而不是 `Map.get` |

## 常见误区

### 误区：容器必须一次把整张依赖图算出来

**你以为**：要先把所有类的关系分析清楚，再统一实例化。
**其实**：本关的容器是"边登记边造"的朴素实现——登记 A 时 A 的依赖必须已经在表里。这够用，也让顺序问题暴露得很直接。真实的 Spring 用两阶段（先建定义、再按拓扑序实例化），正是因为不想要求你手写顺序。
**怎么验证**：把 `register(Greeter.class, RepoImpl.class)` 反过来写，看第一个断言是否失败。

### 误区：`get` 每次都可以新造一个对象

**你以为**：反正调用方只用一次，新造也没关系。
**其实**：`get` 的语义是"给我那个实例"。每次新造会让"单例"这个前提失效——第 2 关的作用域正是从这条语义的两种做法里长出来的。
**怎么验证**：在 `get` 里加一行打印，看同一个类型被造了几次。

## 小结

容器的核心只有两件事：登记时把实例造出来并存进表，取用时按类型查表。构造器注入靠反射，依赖查找靠 `isAssignableFrom`。`Container` 必须是包级私有，因为文件名是 `Main.java`。
